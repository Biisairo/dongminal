# SRS: 파괴적 동작의 확인을 한 걸음으로 — IEEE 29148

## 1. 개요

### 1.1 목적

접수한 말은 한 줄이다.

> **"git 에서 브랜치를 지우거나 할 때 확인을 두 번 누르게 하는데 한 번만 확인하도록 해.
> git branch 제외하고도 이런 곳이 많으니 모두 찾아서 수정해."**

찾을 곳은 많지 않다 — **자리가 하나이기 때문이다.** Git 의 파괴적 동작은 전부
`GitConfirm.open` 을 지나며, 두 걸음을 강제하는 것은 그 함수의 한 줄이다
(`confirm.js:50`). 이 SRS 는 그 한 줄을 바꾸고, **두 걸음이 나눠 들고 있던 정보를 한
화면에 합친다.**

### 1.2 범위

**포함**
- `GitConfirm` 의 단계 수와 한 화면의 구성
- 두 걸음을 전제로 쓰인 e2e 단정의 갱신
- GIT_SRS 의 관련 조항 개정

**미포함**
- 무엇이 파괴적인가의 판정 — `GET /api/git/policy` 가 계속 정한다 (§6 비목표 #1)
- 기본 선택지·키 규약 (FR-GIT-97·176) — 그대로다 (§6 비목표 #2)
- Git 밖의 확인창 (§2.4, §6 비목표 #3)

## 2. 현재 상태

### 2.1 두 걸음의 출처는 한 줄이다

`confirm.js:47~57`:

```js
static async open({action,title,targets,hint,mobile,run,stages}){
  if(GitConfirm._cur) return false;
  const n=await GitConfirm.destructive(action)?2:(stages===2?2:(stages===1?1:0));
  …
}
```

`n` 이 단계 수다. 파괴적 목록에 든 action 이면 호출자가 무엇을 넘기든 **2** 이고,
`stages:2` 를 명시한 호출부(`branches.js:458`, `worktrees.js:263`, `panel-write.js:245`,
`console.js:235`)도 2 다. 브랜치 삭제는 앞의 경로로, worktree 삭제는 뒤의 경로로 같은
곳에 온다 — **"이런 곳이 많다"의 실체는 호출부 여럿이 아니라 이 한 줄이다.**

### 2.2 두 걸음이 나눠 든 것

| 걸음 | 보이는 것 | 근거 |
|---|---|---|
| 1 | 대상 목록 + 개수 | FR-GIT-91 |
| 2 | recovery hint (되돌리는 명령) | FR-GIT-92 |

`_paint()` 가 그것을 단계로 가른다 (`confirm.js:219`):

```js
hint.classList.toggle('vis',this.stage===this.stages&&(this.stages>1||!!this.hint));
```

`stages>1` 이라는 항이 있어 **2단계 확인에서는 hint 가 없어도 "복구 힌트 없음"을
말하고**, 1단계 확인에서는 hint 가 있을 때만 그 자리가 열린다. 걸음을 하나로 줄이면 이
항이 뜻을 잃는다 — 판정의 근거가 "몇 번째 걸음인가"에서 **"파괴적인가"**로 옮겨야 한다.

### 2.3 두 걸음을 전제로 쓰인 e2e

`gc-go` 를 누르는 자리가 19개 파일에 73곳, `data-stage` 단정이 30곳이다. 대부분은 같은
모양이다:

```ts
await confirm(page).locator('.gc-go').click();   // 1 → 2
await confirm(page).locator('.gc-go').click();   // 실행
```

걸음을 줄이면 **두 번째 클릭이 사라진 다이얼로그를 기다리다 타임아웃**한다. 기계적이지만
빠짐없이 손봐야 하는 자리다.

### 2.4 Git 밖에는 두 걸음이 없다

파일 탐색기의 영구 삭제(`file-tree-edit.js:188` → `_edConfirmDelete`)는 한 걸음이며,
지워지는 것·개수·미저장 탭을 한 화면에 적는다 (FR-EDT-83·84). 그 뒤 탭을 닫을 때 다시
묻지 않는 것도 명시되어 있다 (`app-layout.js:334`). **이미 이 SRS 가 만들려는 모양이다** —
바꿀 것이 없다.

## 3. 요구사항

### 3.1 묶음 N — 한 걸음 (FR-COS)

**FR-COS-1** 파괴적 동작의 확인은 **한 걸음**이다. `GitConfirm` 이 만드는 단계 수는
언제나 1 이며, 호출자가 `stages:2` 를 넘겨도 1 이다.

**FR-COS-2** 그 한 화면이 **영향 범위와 recovery hint 를 함께** 보인다 — 두 걸음이
나눠 들던 것(§2.2)을 하나도 잃지 않는다.

**FR-COS-3** hint 자리의 표시 여부는 **파괴적인가**로 정한다. 파괴적이면 hint 가 없어도
그 사실(`GIT_CONFIRM_NO_HINT`)을 말한다 — 되돌릴 길이 없다는 것 역시 사용자가 알아야
할 사실이다. 파괴적이 아닌 확인(`stages:1`)은 hint 가 있을 때만 그 자리를 연다.

**FR-COS-4** 실행 버튼의 글자는 언제나 실행(`GIT_CONFIRM_RUN`)이다 — 넘어갈 다음 걸음이
없으므로 `GIT_CONFIRM_CONTINUE` 가 나올 자리가 없다.

**FR-COS-5** `data-stage` 는 남으며 언제나 `"1"` 이다. 없애면 그 값을 읽는 e2e 가 무엇을
보고 있었는지 함께 사라진다.

**FR-COS-6** 다음은 **바뀌지 않는다**: 초기 포커스는 취소 (FR-GIT-97), `Enter` 는 실행이
아니라 취소 (FR-GIT-176), `Esc` 는 취소, 실행 중 두 버튼 비활성 (FR-GIT-174), 실패 시
사유·stderr tail 유지 (FR-GIT-96·175), 폴링 중 변경 알림 (FR-GIT-178), 파괴적 판정의
출처는 `/api/git/policy` (FR-GIT-89).

**FR-COS-7** 확인이 한 걸음이 되어도 **실행은 클릭 또는 Space 로만** 된다 (FR-GIT-176).
걸음이 줄어든 만큼 오발의 값이 커지므로 이 규약은 더 중요해진다.

### 3.2 묶음 O — 문서와 검증 (FR-COS)

**FR-COS-8** GIT_SRS 의 FR-GIT-90 을 개정한다. "2단계 확인"이라는 말이 남아 있으면
다음 사람이 그것을 복원한다.

**FR-COS-9** 두 걸음을 전제한 e2e 단정을 전부 갱신한다 (§2.3). 클릭을 하나 지우는 것으로
끝나지 않는 자리 — 1단계에서 hint 가 없음을 단정하던 곳 — 은 **뜻을 뒤집어** 다시 쓴다.

## 4. 설계 결정

**D-1. 호출부를 고치지 않는다.** `stages:2` 를 넘기는 네 곳을 지우는 대신 `open` 이
그것을 무시하게 한다. 호출부는 "이것은 파괴적이다"라는 **사실**을 말하고 있고, 그 사실을
몇 걸음으로 표현할지는 `GitConfirm` 의 몫이다 — 정책을 한 자리에 두면 되돌리기도 한
자리다.

**D-2. hint 판정을 `stages` 에서 떼어낸다.** §2.2 의 `stages>1` 은 "파괴적"을 단계 수로
에둘러 말한 것이었다. 걸음이 하나가 되면 그 에두름이 거짓이 되므로, 판정하려던 것
(`destructive`)을 그대로 들고 있게 한다.

**D-3. `data-stage` 를 남긴다.** 속성을 지우면 그것을 읽던 30곳이 조용히 통과하게 된다 —
단정이 사라지는 것이 아니라 **무의미해지는** 것이 더 나쁘다. 값이 `"1"` 로 고정되면
"걸음이 하나"라는 사실 자체가 검증 대상이 된다.

**D-4. 안전을 잃지 않는 이유.** 두 걸음의 값어치는 "실수로 한 번 누르는 것"을 막는
데 있었다. 그 방어는 걸음 수가 아니라 **기본 선택지가 취소이고 `Enter` 가 실행이 아닌
것**(FR-GIT-97·176)에서 나오며, 그것은 그대로 남는다. 또한 한 화면이 영향 범위와 되돌릴
길을 **함께** 보이므로, 판단에 필요한 정보는 오히려 한자리에 모인다.

## 6. 비목표

1. 무엇이 파괴적인가의 목록을 바꾸지 않는다 — 서버가 정한다.
2. 기본 선택지·키 규약을 바꾸지 않는다.
3. Git 밖의 확인창(탐색기 삭제 등)을 바꾸지 않는다 — 이미 한 걸음이다 (§2.4).
4. 확인 없이 실행되는 동작을 만들지 않는다.
