# 2.2 데몬 화면 상태 모듈 (FR-TRM-1·7)

## 목표

alacritty_terminal `=0.26.0` 을 새 crate(가칭 `otter-shared-termstate`) 하나에 가두고, 도구마다 화면 상태 한 벌을 둔다. `Tool::handle_chunk` 의 `cmu` 잠금 안에서 링과 함께 에뮬레이터에 넣고, `resize_inner` 에서 크기를 바꾼다. 에뮬레이터 기록 상한은 작게(초기 1,000줄) 두고, 답장 사건(`PtyWrite`)은 PTY 에 쓰지 않는다. 비교 시험 자료(2.1 스파이크의 녹화·경계 벡터)와 `@xterm/headless 5.5.0` 기준 셀 격자 JSON·생성 스크립트를 저장소로 옮긴다.

설계: `perf/M2_DESIGN.md` §2.2. 결정: D-13, D-18. 2.3 이 쓸 줄 읽기 표면은 착수 때 먼저 정해 조정자를 거쳐 2.3 에 알린다.

## 완료 조건

- RED: 경계 벡터·vim·less·top·agent-sim 의 모든 셀·커서·대체 화면이 xterm 기준과 같다(OSC 8 밑줄 4셀은 2.4 뒤 0).
- RED: 크기 바꾸기 전후 화면이 xterm 의 재흐름 결과와 같다. 대체 화면 왕복, 스크롤 영역(DECSTBM) 스크롤.
- RED: 도구 하나에 에뮬레이터 하나 — 구독자 둘이어도 `feed` 는 한 번(FR-TRM-7).
- RED: 에뮬레이터가 답장을 PTY 에 쓰지 않는다.
- `deny.toml`·RustSec·Windows 타입 검사 통과.
- 바꾼 부분의 시험(단위·관련 e2e 한두 개)·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.

## 진행 기록


### 2026-11-24 agent-pf-2-2

**바꾼 것**

- 새 crate `otter-shared-termstate`(`rust/crates/shared/termstate`). `alacritty_terminal =0.26.0`(기본 기능 끔)을 `src/emu.rs` 한 모듈에만 쓴다. 바깥 표면: `Screen::{new, feed, resize, size, history_len, row, drop_oldest, cursor, modes}` 와 값 타입 `Row`·`Cell`·`Color`·`Attrs`·`Link`·`Cursor`·`Modes`·`MouseMode`. alacritty 타입은 밖으로 나가지 않는다.
  - 사건 수신자 `Quiet` 는 모든 사건(`PtyWrite`·제목·클립보드)을 버린다 — 답장을 PTY 에 쓰지 않는다.
  - 동기 갱신(DECSET 2026)이 바이트를 붙잡지 않게 `Timeout` 을 늘 만료로 둔다(`NoSync`). 화면은 언제나 넣은 바이트 끝(`end`)까지의 상태다.
  - 크기 0 은 1 로 올린다(alacritty 가 0 열을 받지 않는다).
- `toolhub::Tool`: `cmu: Mutex<bool>` → `Mutex<Cmu{exited, screen}>`. `feed` 가 같은 잠금 안에서 화면 상태와 링에 넣는다. `resize_inner` 가 같은 잠금 안에서 PTY 와 화면 크기를 바꾼다(SIGWINCH 뒤 다시 그린 바이트가 옛 크기에 들어가지 않게). 읽기는 `Tool::with_screen(|screen, end| ..)` — 화면과 그 화면의 오프셋을 한 잠금에서 준다. 에뮬레이터 기록 상한 `SCREEN_HISTORY = 1_000`(비공개 상수). 터미널 없는 도구(`new_detached`)는 화면 상태가 없다.
- 비교 시험 자료를 저장소로: `termstate/testdata/corpus/*.bin`(2.1 스파이크의 vectors·vim·less·top·agent-sim 녹화 + 새 벡터 unicode·emoji-new·alt-roundtrip·decstbm·wrap), `cases.json`(입력·크기·크기 바꾸기·뒤이은 입력), `ref/*.json`(xterm 기준 셀 격자), 생성 스크립트 `gen-ref.mjs`(`@xterm/headless 5.5.0` + unicode11 0.8.0, 인자로 node_modules 경로). cargo 시험은 node 없이 JSON 과 견준다. 7 MB·13 MB 짜리 big-*.bin 은 옮기지 않았다(성능 측정용, 2.3·2.10 몫).
- 의존: 루트 `Cargo.toml` `[workspace.dependencies]`·`DEPENDENCIES.md` 에 alacritty_terminal 줄, `architecture.md` 패키지 표에 `termstate/`(②③).

**지운 것**: 없다.

**동작 변경**

- 사용자에게 보이는 동작은 없다(화면 상태를 읽는 곳은 2.4·2.8.1 부터).
- 데몬 자원 — 이전: 도구마다 1 MB 링만. 새: 링 + 에뮬레이터(화면 + 기록 1,000줄, 120열 기준 최대 약 3 MB), PTY 출력 바이트마다 에뮬레이터 파싱(스파이크 측정 175~214 MB/초). 이유: FR-TRM-1·7.
- `resize_inner` 가 PTY 크기 바꾸기 동안 `cmu` 를 잡는다. 그동안 읽기 스레드의 `feed` 가 기다린다(ioctl 한 번).

**시험 (RED → GREEN)**

- `cargo test -p otter-shared-termstate --lib` 26 통과: 경계 벡터(OSC 8 밑줄 4셀만 따로 세어 `==4` 로 고정 — 2.4 직렬화 뒤 0), unicode, vim·vim-live, less·less-live, top·top-live, agent-sim 줄·TUI(+기록 40줄), 대체 화면 왕복, DECSTBM(RI·SU·SD·IL·DL), 크기 바꾸기 재흐름(넓히기·좁히기·agent-sim 120×40→80×30), 대체 화면 중 크기 바꾸기, 크기 바꾼 뒤 출력 — 모든 셀(글자·폭·색·속성)·`wrapped`·커서·커서 보임·대체 화면·모드(앱 커서·키패드·괄호 붙여넣기·삽입·마우스·원점·포커스·자동 줄바꿈)가 xterm 과 같다. 표면 시험: 기록 상한·번호, `drop_oldest` 가 가장 오래된 줄부터 지움, 범위 밖 `None`, 넓은 글자 뒤칸, OSC 8, 색·속성, 질의가 화면을 바꾸지 않음, 동기 갱신, 크기 0.
- `cargo test -p otter-shared-toolhub --lib` 104 통과. 새 시험: 구독자 둘이어도 화면은 한 번만 먹음(FR-TRM-7), 화면과 오프셋을 함께 읽음, DA·DSR·CPR·OSC 11·XTWINOPS·OSC 52 질의에 PTY 쓰기 0, PTY 크기를 따름, detached 도구는 화면 없음.

**2.4 가 알아야 할 것**

- 스냅숏은 `Tool::with_screen(|s, end| ..)` 안에서 만들면 "오프셋 `end` 의 화면"이 된다.
- alacritty 0.26 은 대체 화면일 때 주 화면 격자(`inactive_grid`)를 공개하지 않는다. "대체 화면(주 화면 내용도)" 직렬화는 이 표면으로 못 한다 — 2.4 가 방법을 정해야 한다(예: 대체 화면 들어가는 시퀀스를 보면 그 전에 주 화면을 복사해 둠).
- 스크롤 영역·문자 집합·커서 모양·창 제목은 아직 `Screen` 에 없다. 스크롤 영역은 alacritty 비공개 필드다. 제목은 `Quiet` 가 버리는 `Event::Title` 로만 온다. 2.4 가 `emu.rs` 안에서 더한다.
- 2.3 과의 공용 타입: 2.3 은 `Row{cells, wrapped}`·`Cell{text, width, fg, bg, attrs, link}` 을 읽고 `drop_oldest(n)` 을 부른다(조정자 경유로 알림). 대체 화면 동안 `history_len()` 은 0 이다(alacritty 가 기록을 주 화면에만 둔다).
- 데몬 교체(`adopt_handover`)는 빈 화면 상태로 시작한다. 링 바이트를 먹이는 것(D-27)은 2.9 몫이다.

**남은 위험**

- **Unicode 12 이후 이모지 폭 (사용자 판단 필요)**: 🥲🫀(13)·🫠🫡(14)·🫨🩷(15)를 alacritty(unicode-width 0.2)는 폭 2, 앱의 xterm.js(unicode11)는 폭 1 로 본다. 글자 하나마다 그 줄 뒤쪽이 한 칸씩 어긋난다. 시험 `newer_emoji_width_differs_from_xterm_unicode11` 이 차이(15셀)를 고정해 둔다. 국기·ZWJ·피부색·VS15/16·한글·자모·전각은 같다.
- 쓰지 않는 PTY 의존(rustix-openpty·polling·signal-hook·miow)이 빌드에 들어온다(EMULATOR §8, 받아들임).

**코드와 어긋난 문서 (고치지 않음)**

- `EMULATOR_2026-11-24.md` §8 "이번 자료에서는 차이 0" — Unicode 12 이후 이모지를 넣으면 차이가 난다(위 위험).
- `M2_DESIGN.md` §2.2 "바깥에는 feed·resize·화면 셀 읽기·모드 읽기만 낸다" — 2.3 을 위해 `history_len`·`drop_oldest` 도 냈다.
- `M2_DESIGN.md` §2.4 "대체 화면(주 화면 내용도)" — alacritty 0.26 공개 API 로는 주 화면을 읽을 수 없다.
- `M2_DESIGN.md` §1.1 의 `tool.rs` 줄 번호(`:300`·`:338`·`:368~383`)는 이번 변경으로 밀렸다.

**2.3 요청 반영 (pf-2-3)**: 넓은 글자가 다음 행으로 넘어가 비운 행 끝 칸(alacritty `LEADING_WIDE_CHAR_SPACER`)을 `width 0`(버릴 칸)으로 낸다. 이전에는 `" "` 폭 1 로 냈다 — 논리 줄을 합칠 때 가짜 빈칸이 낀다. xterm 비교는 "wrapped 행의 마지막 칸이 우리 0 / xterm 빈칸 폭 1" 을 같은 것으로 본다(unicode 벡터 edge 줄이 이 경우를 잰다). 시험 `wide_char_pushed_to_next_row_leaves_dropped_cell` 은 구현과 함께 썼다(RED 미확인). 밑줄 색·종류는 내지 않았다 — 필요하면 2.4 에서 `emu.rs` 에 더한다.
