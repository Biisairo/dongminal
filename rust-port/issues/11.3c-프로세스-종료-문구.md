# 11.3c 프로세스 종료 문구를 Go ProcessState.String 과 같게

## 목표

조정자 지시(2026-11-24): 11.3b 에서 플래그한 신호 문구 차이를 고친다. Go `syscall.Signal.String()`(darwin·linux 각각)과 같은 문구를 내고, OS 별 표를 Go 1.27.2 표준 라이브러리 `zerrors_*.go` 의 `signals` 표에서 옮겨 시험으로 고정한다.

## 진행 기록

- 2026-11-24 시작. prod-pids.sh(시작): `38173 start --foreground` / `58470 d --handover-fd`
- 2026-11-24 끝. 커밋 `cbca9e3e`, rust-port 병합 `9db8e995`(충돌 없음). prod-pids.sh(끝): 시작과 같다.

### 한 것

- `dm-shared-platform` 에 `pub mod gowait` 를 더했다. 공개 API: `WaitOs::{Darwin, Linux}`, `signal_name(os, sig)`, `wait_status_text(os, raw)`, `windows_exit_text(code)`. Go 1.27.2 의 `syscall.WaitStatus`(syscall_bsd.go·syscall_linux.go) 해석과 `os.ProcessState.String()` 을 그대로 옮겼다: `exit status N`, `signal: <이름>`, ` (core dumped)`, `stop signal: <이름>`(linux 는 ` (trap N)`), `continued`, Windows 는 코드가 1<<16 이상이면 `exit status 0x…`.
- 신호 이름 표는 darwin·linux 각 31개다. arm64·amd64 표는 같다(확인함). 표는 OS 와 무관하게 컴파일해 어느 호스트에서도 시험한다.
- `platform::exit_status_text` 가 Unix 에서는 wait 상태 원값(`into_raw`)을, Windows 에서는 종료 코드를 위 함수로 넘긴다.
- 같은 문구를 따로 만들던 사본을 모두 이 함수로 바꿨다: git core `exit_status_string`(git jobs 도 이것을 씀), ext `install.rs`, swap `validate.rs`, privhelper, platform 의 handover·junction·procinfo/darwin. toolhub·sandbox 는 11.3b 에서 이미 이것을 부른다. secrets 의 `signal: killed` 는 기한 초과로 직접 죽인 경우의 고정 문구라 그대로 뒀다.

### 이전 동작 / 새 동작 / 이유

| 자리 | 이전 | 새 |
|---|---|---|
| toolhub·sandbox(도구 종료 로그, 샌드박스 실행 오류) | HUP·INT·KILL·TERM 밖은 `signal: signal 11` | Go 와 같은 `signal: segmentation fault` 등, 코어 덤프 표시 |
| ext 설치 | 아홉 개 밖은 `signal N`, darwin·linux 구분 일부만 | Go 표 전량 |
| swap 검증 | HUP·INT·KILL·TERM 밖은 `signal N` | Go 표 전량 |
| privhelper | 신호로 끝나면 Rust 기본 문구(`signal: 11 (SIGSEGV)`) | Go 문구 |
| platform handover·procinfo/darwin | 신호로 끝나면 늘 `signal: killed` | 실제 신호 이름 |
| junction(Windows) | 큰 코드가 음수 10진수 | Go 처럼 `exit status 0xc0000005` |

이유: 사용자에게 보이는 프로세스 종료 안내를 Go 판과 같게 한다(FR-RSP-3).

### 시험

- `gowait` 시험 8개: Go 원본 표 파일(`testdata/go_signals_{darwin,linux}.txt`, zerrors 에서 그대로 옮김)을 읽어 31개 전량 대조, 표 밖(0·32·64·-1), 종료, OS 별 신호 문구, 코어 덤프, 멈춤·계속·trap, Windows 16진.
- 실제 프로세스 대조 `real_process_matches_go`: `/bin/sh -c 'kill -SEGV $$'` 등 아홉 경우의 문구를 Go 1.27.2 `exec.Command(...).Run()` 의 실제 출력과 맞춘다. 이 Mac 에서 Go 로 떠서 확인했다(darwin). linux 쪽 기대값은 Go 표에서 왔고, `scripts/linux-test.sh` 는 podman 이 꺼져 있어 돌리지 못했다.
- 바뀐 crate 시험 656 통과(platform·git core·git jobs·ext·swap·privhelper·toolhub·sandbox), platform 254+1, 게이트 13개, fmt, check-cross 다섯 대상 ✅.

### 남은 위험

- linux 의 실제 프로세스 시험은 linux 에서 아직 돌지 않았다(CI 나 linux-test.sh 에서 돈다).
