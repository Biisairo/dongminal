# 4.2 생성 명령 응답과 워크스페이스 uuid 등록 경합

## 배경 (2026-11-25 조사, scenario 실패 원인)

- `otterctl new-window`(·`new-tab`) 응답에 실린 새 탭 uuid 로 곧바로 `--at` 명령을 보내면, 부하가 있을 때 서버가 400 "location 은 list-workspace 의 uuid 만 허용" 으로 거절한다. 3.4.12 전부터 있던 경합(3.4.12.5 직전 바이너리도 같은 조건에서 실패).
- 경로: 브라우저 `layout-controller.js:183` `_mkWindow` 가 `wsSave.save()` 를 기다리지 않고 결과를 돌려주고, `tool-cmd-remote.js:150-154` `_remoteNewWindow` 가 곧바로 `cmd.result` echo → 서버 `httpapi/src/commands.rs:170-176` 이 echo 를 받자마자 응답. uuid 확인 `commands.rs:57` `is_known_tab_id` → `shared/workspace/src/resolve.rs:107` 색인은 `PUT /api/workspace`(`shared/workspace/src/lib.rs:298-322` `save()`)에서만 갱신.
- 재현 스크립트: `/private/tmp/pfscn/repro.mjs`, `repro-slow.mjs`(페이지 `_savePut` 지연).

## 목표 (사용자 결정 2026-11-25: 서버가 기다림)

- 서버가 생성 명령(new-window·new-tab·split-* 등 `newTabs` 를 돌려주는 명령)의 echo 를 받은 뒤, 결과의 새 탭 uuid 가 모두 워크스페이스 색인에 들어올 때까지(`Manager::changes()` 구독 등 사건 기반, 주기 폴링 금지) 짧게 기다렸다가 otterctl 에 답한다. 기다림 상한은 이름 있는 상수(하드코딩 금지). 상한을 넘으면 지금처럼 답하되 그 사실을 로그로 남긴다.
