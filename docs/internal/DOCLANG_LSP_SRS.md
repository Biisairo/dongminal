## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 한 줄이다.

> **"svg, md 등 다른 문서들도 lsp 를 이용해서 하이라이트 및 다양한 동작을 하도록"**

지금 언어 서버가 서는 파일은 **셋뿐이다** — Go · TypeScript/JavaScript · Python
(`descriptor.go:68`). `.md` 를 열면 세션이 서지 않고, `F12` 도 호버도 진단도
아무 일이 일어나지 않는다.

### 1.2 접수한 말의 분해

**"하이라이트" 는 이 요구에서 두 가지를 가리킬 수 있고, 둘 중 하나는 이미 되어 있다.**

| 읽는 법 | 지금 상태 | 이 SRS 의 대상 |
|---|---|---|
| 문법 색칠 (구문 강조) | **이미 된다.** `LANG_MAP` 이 `.md→markdown`·`.svg→xml`·`.json`·`.yaml`·`.html`·`.css` 를 Monaco 언어로 매핑하고 Monaco 의 기본 문법이 칠한다 (`file-editor.js:9~44`) | 아니다 (§2.1) |
| 의미 기반 강조 (semantic tokens) | 없다. LSP 의 `textDocument/semanticTokens` 를 받아 Monaco 에 얹어야 한다 | **조건부** — §8 Q-2 |

그러므로 이 요구가 실제로 여는 것은 **"다양한 동작"** 쪽이다: 진단(깨진 링크·스키마
위반), 호버, 정의/참조 이동, 그리고 지금 우리에게 **없는** 동작인 문서 심볼.

### 1.3 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 서술자 | 문서 언어의 서버를 기본 서술자에 더한다 |
| **B** 설정 표 | EDITOR_LSP_SRS **FR-LSP-3 의 미구현분** — 사용자가 확장자↔실행 명령을 직접 적는다 |
| **C** 한 자리 | 언어 목록이 서버·화면 **두 곳에 적히는 것**을 접는다 |
| **D** 새 동작 | 문서 심볼(아웃라인)·문서 링크 — 문서 언어에서 이득의 절반이 여기 있다 |

**미포함:** §6 비목표. 렌더 미리보기는 [`./DOC_RENDER_VIEW_SRS.md`](./DOC_RENDER_VIEW_SRS.md) 의 것이다.

### 1.4 참조 (References)

- [`./EDITOR_LSP_SRS.md`](./EDITOR_LSP_SRS.md) — **이 문서의 모체다.** FR-LSP-1~53,
  D-1~D-10 이 전부 그대로 걸린다. 여기서는 그 위에 얹는 것만 적는다
- [`./DOC_RENDER_VIEW_SRS.md`](./DOC_RENDER_VIEW_SRS.md) — 같은 접수의 다른 절반

### 1.5 착수 전 확정된 결정

|---|---|---|

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 문법 색칠은 이미 되어 있다

`LANG_MAP` 은 `.md`·`.svg`(→`xml`)·`.json`·`.yaml`·`.html`·`.css`·`.scss`·`.xml` 을
전부 Monaco 언어로 매핑한다. 색칠은 Monaco 의 기본 문법이 하며 **LSP 와 무관하다.**

**이 사실이 요구의 절반을 이미 만족시킨다.** 남은 것은 §1.2 의 아래 칸이다.

### 2.2 서술자는 Go 코드에 하드코딩된 셋이다

`descriptor.go:68` 의 `defaults` — `gopls` · `typescript-language-server` ·
`pyright`. `DescriptorForExt(ext)` 가 이 표에 없는 확장자를 풀지 못하므로
(`descriptor.go:117`), `.md` 는 **세션을 세우지 않는다** (V-LSP-1 이 그것을 명세한다).

### 2.3 FR-LSP-3 은 미구현이다

EDITOR_LSP_SRS 는 *"사용자는 서술자를 설정으로 더하거나 덮을 수 있다"* 를 적었지만,
지금 화면이 실어 보내는 것은 `overrides`(서술자 id → 절대경로) 하나뿐이다
(`app-lsp.js:33`, `handlers_lsp.go:40`). **없는 서술자를 더하는 길은 없다.**

### 2.4 언어 목록이 두 곳에 적혀 있다

| 자리 | 내용 |
|---|---|
| `descriptor.go:68` `defaults[].Langs` | 서버가 아는 언어 |
| `constants-editor.js:170` `LSP_HOVER_LANGS` | 화면이 호버 provider 를 등록하는 언어 |

**언어 하나를 더하려면 두 곳을 고쳐야 한다.** 한쪽만 고치면 서버는 서는데 호버가
붙지 않거나(후자 누락), 붙었는데 세션이 없다(전자 누락). 서버가 이미 상태 조회에
`langs` 를 싣고 있으므로(`app-lsp.js:77`) 화면이 그것에서 파생할 수 있다.

### 2.5 설치 격리는 이미 npm 을 알고 있다

FR-LSP-7b 가 `npm --prefix <lsp>` 와 `<lsp>/node_modules/.bin/` 을 이미 다룬다
(`install.go`·`locate.go`). **문서 언어 서버는 전부 npm 패키지이므로 새 설치 도구가
필요 없다** — 표에 줄을 더하는 일이다.

### 2.6 조달 가능성 (npm 레지스트리 실측, 2026-09-06)

| 패키지 | 판 | 실행 파일 | 덮는 것 |
|---|---|---|---|
| `vscode-langservers-extracted` | 4.10.0 | `vscode-markdown-language-server` · `vscode-html-language-server` · `vscode-css-language-server` · `vscode-json-language-server` · `vscode-eslint-language-server` | **다섯 서버가 한 패키지** |
| `yaml-language-server` | 1.24.0 | `yaml-language-server` | YAML(+ 스키마) |
| `svg-language-server` | 0.2.0 (2026-08 갱신) | `svg-language-server` · `svg-ls` | SVG 진단·완성·호버·포매팅·참조 |

**함정 하나를 적어 둔다.** npm 의 `marksman` 은 마크다운 언어 서버가 **아니다** —
gun.js 유틸리티이며 2022년에 멈춰 있다(`description = 'gun.js replacement function
for .path().'`). 이름만 보고 서술자에 적으면 설치는 성공하고 서버는 서지 않는다.
진짜 marksman 은 .NET 바이너리이며 npm 으로 오지 않는다.

### 2.7 우리 클라이언트가 쓰는 LSP 동작은 넷이다

정의 이동 · 참조 찾기 · 호버 · 진단 (`app-lsp.js`). 문서 언어에 이 넷을 그대로
얹었을 때 실제로 보이는 것은 이렇다.

| 서버 | 진단 | 호버 | 정의 이동 | 참조 |
|---|---|---|---|---|
| markdown | 깨진 링크·없는 헤딩 참조 | 링크 대상 | **링크 → 그 파일·헤딩** | 그 헤딩을 가리키는 링크들 |
| yaml | 스키마 위반 | 스키마의 설명 | 앵커 | — |
| json | 스키마 위반·구문 | 스키마의 설명 | — | — |
| css | 구문·알 수 없는 속성 | 속성 문서 | 변수·심볼 | 같은 파일 안 |
| html | 구문 | 태그·속성 문서 | — | — |
| svg | 구문·속성 | 속성 문서 | `url(#id)` → 그 정의 | `id` 참조들 |

**Markdown 의 이득이 가장 크고, 그 이득의 절반은 우리에게 없는 동작에 있다** —
문서 심볼(헤딩 아웃라인)과 문서 링크다 (§3.4).

### 2.8 설치 제안 배너는 확장자 표로 판정한다

`lspOfferFor` 가 서버가 준 `exts` 로 서술자를 찾는다 (`app-lsp.js:352`). 서술자에
문서 언어가 들어오면 **`.md` 를 여는 순간 배너가 뜬다** — 그것이 기본 동작이며,
"다시 보지 않기" 는 그 언어에 대해 기억된다 (FR-LSP-45).

## 3. 기능 요구사항 (Functional Requirements)

EDITOR_LSP_SRS 의 FR-LSP-* 는 **모두 그대로 걸린다.** 여기서는 얹는 것만 센다.

### 3.1 묶음 A — 서술자 확장 (FR-DLS-1~5)

- **FR-DLS-1** 기본 서술자에 문서 언어가 더해진다. **한 패키지가 여러 서버를 낼 때
  서술자는 서버마다 하나다** — 단위가 서버라는 FR-LSP-1 의 규칙이 그대로다.
- **FR-DLS-2** 설치 도구는 `npm` 이며 전용 디렉터리로 격리된다 (FR-LSP-7·7b). §2.5 가
  이미 그 길을 냈다.
- **FR-DLS-3** 한 패키지가 여러 서술자를 덮을 때, 그중 하나를 받으면 나머지도 함께
  받아진다. **상태 조회가 그 사실을 반영해야 한다** — 하나를 설치했는데 나머지가
  "없음" 으로 남으면 사용자는 설치가 실패한 줄로 읽는다.
- **FR-DLS-4** 어떤 서술자를 기본에 넣을지는 §8 Q-1 의 답이 정한다. **성숙도가 낮은
  의존을 기본 셋에 넣는 것은 대가가 있다** (§2.6 의 `svg-language-server`).
- **FR-DLS-5** 서술자 이름으로 패키지를 고를 때 **레지스트리에서 실물을 확인한다** —
  §2.6 의 `marksman` 함정이 그 근거다.

### 3.2 묶음 B — 설정 표 (FR-DLS-6~10) — FR-LSP-3 의 미구현분

- **FR-DLS-6** 사용자는 설정에서 **서술자를 더할 수 있다**: 확장자들 · Monaco 언어
  id 들 · 실행 파일(절대경로 또는 이름) · 인자.
- **FR-DLS-7** 사용자가 적은 서술자는 **기본 셋을 덮을 수 있다.** 같은 확장자를
  가리키면 사용자의 것이 이긴다.
- **FR-DLS-8** 그 표는 `overrides` 와 같은 길로 간다 — **요청이 싣는다** (FR-LSP-4b).
  설정 블롭을 서버가 해석하지 않는 규약(PAGE_TITLE_SRS §2.2)이 그대로다.
- **FR-DLS-9** 사용자가 적은 서술자에는 **설치 방법이 없다.** 그것은 사용자가 이미
  가진 실행 파일을 가리키는 표이며, 우리가 받아 줄 대상이 아니다 — 그 사실이 상태
  화면에 보인다 (FR-LSP-6 과 같은 어휘로).
- **FR-DLS-10** 표가 잘못 적혀 있으면(없는 실행 파일 등) **그 사실이 보인다.** 조용히
  세션이 서지 않으면 사용자는 우리 버그로 읽는다 (D-9).

### 3.3 묶음 C — 언어 목록을 한 자리로 (FR-DLS-11~12)

- **FR-DLS-11** 화면의 호버 provider 등록 언어는 **서버 상태에서 파생한다**
  (§2.4). 상수 목록을 손으로 늘리지 않는다.
- **FR-DLS-12** 파생이 늦게 도착해도(상태 조회는 비동기다) 그때 세워진 편집기에
  provider 가 붙는다. 붙지 않으면 첫 파일에서만 호버가 죽는다.

### 3.4 묶음 D — 새 동작 (FR-DLS-13~16)

문서 언어의 이득 절반이 여기 있다 (§2.7).

- **FR-DLS-13** **문서 심볼**(`textDocument/documentSymbol`) 을 받는다. Markdown 은
  헤딩 트리, YAML·JSON 은 키 트리, CSS 는 선택자다.
- **FR-DLS-14** 그것을 보이는 자리는 **이미 있는 목록 껍데기**다 — 찾기 패널·참조
  목록이 쓰는 그것 (EDITOR_LSP_SRS §2.11 / D-8b). 새 사이드바를 만들지 않는다.
- **FR-DLS-15** **문서 링크**(`textDocument/documentLink`) 는 §8 Q-3 의 답이 정한다.
  Markdown 에서 링크를 눌러 그 파일로 가는 일은 **렌더 뷰가 이미 하기로 한 것이므로**
  (DOC_RENDER_VIEW_SRS FR-DRV-28) 두 벌이 되지 않게 조율해야 한다.
- **FR-DLS-16** 자동완성은 **여전히 넣지 않는다** (EDITOR_LSP_SRS D-7 / I-2). YAML·
  JSON 스키마 완성이 탐나 보이지만, 그것을 열면 타이핑마다 왕복이 나는 경로가
  열리고 그 실패는 "편집기가 느리다" 로 보인다.

## 5. 확정 결정 (Decisions)

- **D-1 '하이라이트' 를 LSP 로 만들지 않는다.** 문법 색칠은 이미 Monaco 가 하고
  있으며(§2.1), 그것을 LSP 로 옮기는 것은 되던 일을 서버 유무에 매다는 일이다.
- **D-2 서술자 표를 늘리는 것이 이 요구의 본문이다.** 언어를 아는 자리는 그
  표 하나이며 나머지 계층(탐색·설치·세션·종단)은 이미 언어를 모른다.
- **D-3 설정 표(FR-LSP-3)를 함께 구현한다.** 기본 셋만 늘리면 다음 언어에서 같은
  대화를 다시 하게 되고, 그때마다 Go 코드를 고친다.
- **D-4 문서 심볼을 더한다 — 목록 껍데기를 다시 쓴다.** 새 UI 를 만들지 않는 것이
  이 저장소의 관용이다 (D-8b).
- **D-5 실물 확인 없이 패키지 이름을 적지 않는다** (§2.6).

## 6. 비목표 (Non-goals)

1. **자동완성** — EDITOR_LSP_SRS D-7 이 그대로 걸린다.
2. 서식 정리(formatting)·코드 액션 — 그 SRS 의 비목표 2 와 같다.
3. 렌더 미리보기. 다른 문서의 것이다.
4. Semantic tokens — §8 Q-2 의 답이 나오기 전에는 하지 않는다.
5. 언어 서버의 스키마 설정(YAML/JSON 스키마 연결)을 우리 UI 로 편집하기 — 그 SRS 의
   비목표 5 와 같은 근거.

## 7. 다른 세션과의 조율 (Handoff)

**이 문서는 구현 지시가 아니다.** LSP 영역은 지금 다른 세션의 손에 있다 (I-3).

### 7.1 겹치는 파일

| 파일 | 이 SRS 가 요구하는 변경 |
|---|---|
| `internal/webserver/domain/lsp/descriptor.go` | `defaults` 에 서술자 추가, 사용자 서술자 병합 |
| `internal/webserver/domain/lsp/locate.go` · `install.go` | (변경 없음 예상 — §2.5) |
| `internal/webserver/httpapi/handlers_lsp.go` | 요청에 사용자 서술자 표를 싣는 자리 |
| `web/js/core/app-lsp.js` | 서술자 표 전송 · 호버 언어 파생 · 문서 심볼 |
| `web/js/core/constants-editor.js` | `LSP_HOVER_LANGS` 제거(파생으로) |

### 7.2 조율 규약

1. **착수 전에 그 세션의 진행 상태를 확인한다.** 이 문서의 FR 이 그쪽이 이미 하고
   있는 일과 겹치면, 겹치는 쪽을 지운다.
2. **먼저 할 수 있는 것은 묶음 A 다.** 서술자 표에 줄을 더하는 일은 다른 계층을
   건드리지 않는다.
3. **묶음 B·C 는 그 세션의 작업이 멎은 뒤에 한다.** `app-lsp.js` 와
   `handlers_lsp.go` 를 함께 고치는 일이기 때문이다.
4. 렌더 뷰 작업(`DOC_RENDER_VIEW_SRS` M1·M2)은 **브라우저 안에서 끝나며 이 파일들에
   닿지 않는다** — 두 작업을 나란히 돌릴 수 있다.

## 8. 미해결 질문 (사용자·조율 결정 필요)

| # | 물음 | 권장 |
|---|---|---|
| **Q-1** | 기본 서술자에 무엇까지 넣는가 (FR-DLS-4) | **`vscode-langservers-extracted`(markdown·html·css·json) + `yaml-language-server`.** `svg-language-server` 는 성숙도가 낮으므로 **설정 표(묶음 B)로 붙이게 두고 기본에는 넣지 않는다** |
| **Q-2** | Semantic tokens 를 하는가 (§1.2) | **하지 않는다.** 문서 언어에서 얻는 것이 적고(색이 이미 있다), Monaco 에 provider 를 하나 더 여는 값이 크다. 사용자가 실제로 겪은 불만이 "색이 밋밋하다" 였다면 그때 다시 연다 |
| **Q-3** | 문서 링크를 LSP 로 다루는가 (FR-DLS-15) | **렌더 뷰에 맡긴다.** 소스에서 링크를 따라가는 일은 정의 이동(`F12`)이 이미 덮는다 |
| **Q-4** | 배너가 `.md` 를 열 때마다 뜨는 것을 받아들이는가 (§2.8) | **받아들인다.** "다시 보지 않기" 가 언어별로 기억되므로 한 번이다 (FR-LSP-45) |
