# SRS: 접근성 기준 — 목표·범위·검사 방법·완료 조건 (IEEE 29148)

> **문서 상태**: 승인·구현중

- 접수: 2026-09-12 (로드맵 M7 선행 SRS ① · 사용자 결정 2)
- 마일스톤: M7 — 이 문서가 **먼저다**. M7 DoD 의 첫 두 항목이 여기서 정의되고,
  M9 의 `UX-11`(CSS `content` → DOM 텍스트) 검증 방법도 여기에 달렸다.
- 짝: [DESIGN_TOKENS_SRS](./DESIGN_TOKENS_SRS.md)(선행 SRS ②) — 대비의 **보장

## 1. 개요

### 1.1 목적

`07 §7` 이 적은 사실은 결함 목록이 아니라 **부재**다.

> **목표 기준 선언: 없음.** `docs/`·`README` 에서 `WCAG`·`a11y`·`접근성` grep
> 결과는 `UX_REVISION_SRS.md:290` FR-BLP-21 의 "접근성 하한(30px)" 한 줄과 보관
> SRS 의 `aria-label` 언급뿐.

갭 `G7-1` 이 지적하는 실질 문제가 그것이다. 기준이 없으면 `UX-4`(L)·`UX-6`(M) 을
**"어디까지 하면 끝인가"** 로 판정할 수 없고, 판정할 수 없으면 마일스톤이 닫히지
않는다. 이 문서는 그 완료 조건을 만든다.

**이 문서가 하지 않는 것도 분명하다.** 개별 결함(`UX-3`·`UX-4`·`UX-6`·`UX-8`·
`UX-10`·`UX-12`·`UX-13`)의 조치 설계는 그 항목들의 몫이다. 여기서는 **그 조치가
언제 끝났다고 말할 수 있는가**만 정한다.

### 1.2 사용자 결정 (2026-09-12)

로드맵 §3-B 미결정 2 에 대한 답이다.

> **(a) WCAG 2.1 Level AA 를 목표로 선언한다. xterm 캔버스는 명시적 범위 밖.**

선택지 (b)(핵심 화면에만)를 택하지 않은 이유는 **"핵심 화면"의 경계가 그 자체로
또 하나의 미결정**이기 때문이다 — 새 화면이 생길 때마다 그것이 핵심인지 물어야
하고, 그 물음에 답하는 자리가 없으면 게이트의 판정이 흔들린다. (c)(기준 없이
개별 결함만)는 로드맵이 이미 비권장으로 판정했다: `G7-1` 이 M7 에서 빠지고 axe
스모크·대비 게이트가 DoD 에서 빠져 **마일스톤 완료 판정이 불가능**해진다.

### 1.3 범위

**포함 — 이 앱이 스스로 그리는 DOM 전부**

- 상단바·사이드바(창 목록·git·에이전트)·분할 칸 탭·상태바·모바일 키바·드로어
- 설정 모달·`UIKit.modal` 위에 서는 모든 상자·git 확인창(`GitConfirm`)
- 탐색기(파일 트리)·git 뷰(변경·이력·diff)·Runs·Agents·알림 센터
- 토스트·라이브 리전·컨텍스트 메뉴
- 테마 54종 전부에서의 색 대비 (계산 방법은 `DESIGN_TOKENS_SRS` 가 소유)

**비포함 — 벤더 표면 (§2.4)**

- **xterm 캔버스 안** — 터미널 출력은 캔버스 픽셀이고 DOM 이 아니다. 접근성은
  xterm 자신의 screen-reader 모드가 소유한다 (`07 §7` 기준선이 그대로 제안).
- **Monaco 편집기 안** — 같은 이유. 편집기 위젯 내부의 역할·포커스 규약은
  Monaco 가 소유한다. 우리가 그리는 **편집기 탭 줄·찾기 줄·상태 표시**는 포함.
- 터미널이 출력하는 문자열의 내용 — 그것은 도구가 쓴다.

**비포함 — 다른 문서의 몫**

- 문구·언어·`lang` 속성 → **M9**(`UX-9`·`UX-11`·`UX-20`·`UX-21`). 단, `UX-11` 의
  *검증 방법* 은 이 문서가 정의한다 (FR-A11Y-21).
- 토큰의 값·파생·하드코딩 금지 게이트 → `DESIGN_TOKENS_SRS`.

### 1.4 정의

| 용어 | 정의 |
|------|------|
| **AA** | WCAG 2.1 Level AA. A 를 포함한다 — AA 는 A 위에 선다 |
| **검사 표면** | axe 스모크가 DOM 을 읽는 하나의 화면 상태. "설정 모달이 열린 상태" 가 하나다 |

| **예외** | AA 를 적용하지 않기로 **등록한** 자리. 미적용이 아니라 **기록된 미적용**이다 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 선언과 자동 검사

| 항목 | 실측 (2026-09-12) |
|---|---|
| 목표 기준 선언 | **없음** |
| a11y 자동 검사 | **없음** — `package.json` devDependency 에 axe 계열 0 |

### 2.2 ARIA 실측

`web/index.html` 과 `web/js` 전체를 센 값이다.

| 속성 | `index.html` | `web/js` | 합 |
|---|---|---|---|
| `aria-hidden` | 22 | 7 | 29 |
| `aria-label` | 14 | 12 | 26 |
| `role=` | 1 | 2 | **3** |
| `aria-modal` | 0 | 2 | 2 |
| `aria-selected` | 0 | 2 | 2 |
| `tabindex` | 0 | 1 | **1** |
| `aria-live` | 0 | 0 | **0** |
| `aria-expanded` | 0 | 0 | **0** |
| `aria-labelledby` | 0 | 0 | **0** |
| `aria-describedby` | 0 | 0 | **0** |

읽는 방법: **`aria-hidden` 29 가 가장 많다.** 장식 SVG 를 숨기는 일은 이미 규약이
됐다(`UIKit.icon` 이 붙인다). 그 반대편 — **이름을 주고 역할을 말하고 상태를
알리는 쪽이 비어 있다.** `role=` 3 · `tabindex` 1 · `aria-live` 0 이 `UX-4`(목록·
탭·카드가 전부 `div`)와 `UX-8`(라이브 리전 0개)의 수치적 실체다.

### 2.3 포커스

| 항목 | 실측 |
|---|---|
| `outline:none` 선언 | **17** |
| `:focus-visible` 선언 | **9** |

차이 8 이 `UX-13`(포커스 표시가 키트 밖 컨트롤에 없다)이다. `outline:none` 은
포커스를 **지우는** 선언이고, 그것을 되돌리는 `:focus-visible` 이 그보다 적다는
것은 지운 채로 남은 자리가 있다는 뜻이다.

### 2.4 벤더 표면의 현재 접근성

- **xterm**: 자체 screen-reader 모드를 갖는다. 캔버스 렌더러를 쓰는 한 터미널
  출력은 DOM 에 없다 — axe 가 볼 것이 없고, 봐도 판정할 근거가 없다.
- **Monaco**: 자체 접근성 도움말(`Alt+F1`)과 스크린리더 모드를 갖는다. 위젯
  내부의 `role`·`aria-*` 는 Monaco 가 붙인다. 우리가 고칠 수 있는 표면이 아니고,
  고치면 벤더 갱신에서 사라진다.

**그래서 범위 밖이라는 말의 뜻은 "무시한다" 가 아니라 "그 벤더의 기준을 따르고
그 사실을 기록한다" 다** (FR-A11Y-5).

### 2.5 대비 — 이 조사가 로드맵의 전제를 뒤집었다

로드맵 §M7 DoD 는 *"44개 테마 전부 … `--text-hint`·`--text-muted`·버튼 기본
글자 대비 … 전부 ≥ 4.5:1"* 을 적으면서 `--text-dim` 1.91:1 · `--text-muted`
2.76:1 · `--text` 8.10:1 · `--accent` 6.79:1 을 근거로 들었다.

**그 넷은 Tokyo Night 한 테마의 값이다.** 실제 팔레트는 **54종**(dark 43 ·
light 11)이고, 전부를 계산하면 이렇다 (배경 `--bg` 대비, WCAG 2.1 상대휘도).

| 토큰 | 최소 | 중앙값 | 최대 | ≥ 4.5:1 | ≥ 3.0:1 |
|---|---|---|---|---|---|
| `--text` | 4.13 | 9.84 | 19.03 | **53/54** | 54/54 |
| `--text-bright` | 4.99 | 13.24 | 19.03 | 54/54 | 54/54 |
| `--text-muted` | 1.69 | 3.21 | 6.15 | **10/54** | 31/54 |
| `--text-dim` | 1.09 | 1.28 | 1.91 | **0/54** | **0/54** |
| `--accent` | 2.69 | 5.90 | 15.89 | **45/54** | 52/54 |
| `--danger` | 2.80 | 4.77 | 7.84 | **33/54** | 53/54 |

그리고 이 토큰들이 **글자로 쓰인다**:

| 토큰 | `color:` 선언 | `background:` | `border*:` |
|---|---|---|---|
| `--text-muted` | **149** | 2 | 0 |
| `--text-dim` | **99** | 3 | 2 |
| `--accent` | 96 | 20 | 71 |
| `--danger` | 57 | 1 | 24 |

**248개 글자 선언이 AA 에 못 미치는 두 토큰 위에 서 있다.** `--text-dim` 은 54종
어디서도 3:1 조차 넘지 않는다.

**여기서 로드맵의 DoD 문장을 그대로 따를 수 없다.** 그 값들은 각 테마의 **정본
팔레트 값**이다 — Nord 의 `#4c566a` 는 Nord 그 자체이고, 54벌을 손으로 올리면
테마의 정체성이 바뀐다. 보장 방법은 `DESIGN_TOKENS_SRS` 가 **파생**으로 푼다
(사용자 결정 2026-09-12). 이 문서는 **임계치와 판정 대상**만 정한다 (§3.2).

### 2.6 우리가 이미 갖고 있는 강제 하나

`ui-kit.js:72` 가 이름 없는 아이콘 버튼을 **만들 수 없게** 한다.

```js
if (!s.label && !s.title) throw new Error('[ui-kit] 이름 없는 버튼은 만들 수 없다 (label 또는 title 필요)');
…
if (s.title) { b.title = s.title; b.setAttribute('aria-label', s.title) }
```

`03 §4-2` 가 양호 판정한 자리다. **이 문서의 방법론이 여기서 나온다** — 접근성을
"나중에 검사해서 고치는 것" 이 아니라 **만들 수 없게 하는 것**으로 옮긴다.

## 4. 설계 결정

**D-A11Y-1: 목표는 WCAG 2.1 AA 전면이다.**

  핵심 화면 한정(선택지 b)을 택하지
  않은 이유는 "핵심"의 경계가 **또 하나의 미결정**이어서다. 화면이 늘 때마다
  그것이 핵심인지 물어야 하고, 묻는 자리가 없으면 게이트의 판정이 흔들린다.
  전면 선언은 그 물음을 없앤다 — 대신 **예외를 등록하는 자리**(§3.5)를 연다.
  경계는 화면 목록이 아니라 **등록된 예외 목록**이 진다.

**D-A11Y-2: 큰 글자 예외(3:1)를 쓰지 않는다.**

  WCAG 1.4.3 은 18pt(또는 14pt
  bold) 이상에 3:1 을 허용한다. 쓰지 않는 이유는 관대함이 아니라 **게이트의
  판정 가능성**이다: 예외를 열면 토큰 하나가 큰 글자에도 작은 글자에도 쓰일 수
  있고, 그러면 게이트가 "이 토큰은 어디에 쓰였나" 를 알아야 한다. §2.5 가 보인
  대로 `--text-muted` 는 149곳에 쓰인다 — 149곳의 크기를 아는 게이트는 만들 수
  없다. 단일 임계치 4.5 가 계산 가능한 유일한 형태다.

**D-A11Y-3: 검사 표면 목록은 파생시킨다.**

  M6 이 두 번 배웠다: 손으로 적은
  목록은 새 항목을 놓치고(§3-2), 고친 방법은 **이미 있는 순서에서 파생**시키는
  것이었다(§4-A-3, 하네스의 파일 목록을 `index.html` 에서 파생). 설정 모달 탭이
  늘면 axe 도 그 탭을 봐야 하는데, 스펙에 탭 이름을 적어 두면 보지 않는다.

**D-A11Y-4: 라이브 리전은 "있다" 가 아니라 "들어왔다" 로 검증한다.**

  리전의
  존재는 axe 도 보지만, 그것이 **실제로 통지에 쓰이는지**는 보지 못한다. M6
  §4-A-1 이 정확히 그 함정을 만났다 — `window.App._modKbd` 를 읽던 단정이
  **아무것도 재고 있지 않았다**. 리전만 만들고 토스트가 그리로 가지 않으면 같은
  일이 된다.

**D-A11Y-5: 벤더 표면은 제외(exclude)하지 숨기지(hide) 않는다.**

  xterm·Monaco
  컨테이너를 `aria-hidden` 으로 덮으면 그 **안에 우리가 그린 DOM**(편집기 탭 줄·
  찾기 줄·터미널 검색 줄)까지 접근성 트리에서 사라진다. axe 의 `exclude` 는 그
  셀렉터 아래만 스캔에서 빼고 트리는 건드리지 않는다.

**D-A11Y-6: 대비는 axe 가 아니라 계산 게이트가 판정한다.**

  axe 의
  `color-contrast` 는 렌더된 픽셀을 읽으므로 **활성 테마 하나**만 본다. 54종을
  axe 로 보려면 스모크가 54배가 된다. 팔레트에서 직접 계산하면 브라우저 없이
  밀리초 안에 끝나고, `themes.js` 를 고치는 커밋에서 즉시 빨개진다.

## 7. 비목표

1. **WCAG AAA.** 대비 7:1 은 54종 팔레트 전부를 다시 그리는 일이다.
2. **스크린리더 호환성 표.** 특정 리더의 특정 판에서의 동작은 우리가 고정할 수
   없다. 우리가 지키는 것은 표준이고, 리더의 해석은 리더의 몫이다.
3. **접근성 전용 테마**(고대비 모드). 54종 전부가 AA 를 만족하면 필요가 없다.
4. **자동 검사만으로 AA 를 주장하는 것.** FR-A11Y-15 가 그것을 명시적으로 막는다.
5. **터미널 안의 도구 출력.** 도구가 쓰는 문자열이다.
6. **문구·언어**(M9) · **토큰 값·파생**(`DESIGN_TOKENS_SRS`).
