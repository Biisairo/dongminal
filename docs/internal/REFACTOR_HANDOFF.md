# 인수인계 — 리팩터 브랜치 (`refactor`)

> 세션 종료 시점의 상태. 근거 SRS 넷은 §6 에 있다.
> **모든 변경이 커밋·푸시돼 있다.** 워킹 트리는 비어 있어야 한다.

## 0. 한 줄 상태

**네 단계가 끝났다** — 통짜 파일 분할, e2e 헬퍼 회수, flaky 수정, `RunsPanel` 추출.
**남은 일은 `App` 상태 추출의 나머지 후보를 재검토하는 것**이며, 그 후보들은
**현재 측정으로는 전부 "하지 말 것" 으로 판정돼 있다** (§3).

## 2. 다음 세션이 반드시 먼저 읽을 것

**`APP_STATE_EXTRACT_SRS.md` §7 전체.** 특히:

- **§7.2 — 앞 세션의 측정이 틀렸다.** `this.<이름>` 을 전부 필드로 셌는데 상당수가
  **다른 파일이 정의한 메서드 호출**이었다. "필드 107개 중 60개 전용" 은 과장이고

  무엇을 정의하는지 먼저 매핑**하고 세야 한다.
- **§7.3 — 추출의 세 조건.** `RunsPanel` 이 잘 떨어진 것은 예외였다.
- **§2.3 — 바깥이 붙잡는 것은 메서드만이 아니다.** 이것이 이번 세션 최대의 함정이다.

## 3. 이번 세션의 일 — 남은 후보 재검토

사용자의 지시는 **"완벽하게 분석해서 확실한 경우에만 진행하고 아니면 패스"** 다.

### 3.1 판정 기준 (셋을 **모두** 만족해야 추출한다)

| # | 조건 | `RunsPanel` 의 값 |
|---|---|---|
| 1 | 상태가 전부 그 파일 전용 | 11 / 11 |
| 2 | 바깥이 부르는 메서드가 적다 | 34개 중 **6** |
| 3 | 앱으로 나가는 편집이 좁다 | **6줄** |

하나라도 크게 어긋나면 **패스하고 사유를 SRS 에 남긴다.** 이득 없는 추출은 위임
계층만 늘린다.

### 3.2 현재 측정과 잠정 판정

| 대상 | 정의 메서드 | 바깥이 부름 | 전용 필드 | 잠정 |
|---|---|---|---|---|
| `app-editor.js` | 50 | **35** | 5 | 부적합 (`_isEditorWin` 만 14곳) |
| `app-attn.js` | 26 | **14** | 6 | 부적합 + 주제 혼재 |
| `app-reload.js` | 6 | 2 | **3** | 이득 없음 |
| `app-statusbar.js` | ? | ? | **7** | **미조사** — 전용 필드가 가장 많다 |

**`app-statusbar.js` 를 조사하지 않았다.** 전용 필드 7개로 남은 것 중 가장 많으므로
먼저 재야 한다.

### 3.3 추출보다 값이 큰 것 — `app-attn.js` 의 주제 혼재

`_findToolLocation`·`_jumpToTool`·`_toolName` 은 **알림과 무관한 공용 유틸**인데
알림 파일에 얹혀 있다. 외부 호출이 많은 것이 여기서는 **공용임의 증거**다.

객체로 뽑을 것이 아니라 **제자리로 돌려보내는** 것이며, `App` 의 메서드로 남으므로
**위임 껍데기가 필요 없다** — 파일만 옮기면 된다. 별도 SRS 가 필요하다.

## 4. 반드시 지킬 절차

### 4.1 추출 대상 조사 — 세 가지를 **모두** 센다

```
① 바깥이 부르는 메서드     grep '\.<이름>\('
② 바깥이 app. 으로 읽는 필드  grep 'app)\?\.<이름>'
③ 형제 파일이 this. 로 만지는 필드   grep 'this\.<이름>'     ← 최대 함정
```

**③ 이 함정인 이유**: `app-slots.js` 는 `App` 의 메서드 안이라 `app.` 이 아니라
`this._runViews` 로 접근한다. `app\._run` 으로 찾으면 **걸리지 않는다.** 파일은
갈렸어도 **`this` 는 하나다.** 이번 세션에서 이것을 놓쳐 e2e 3건이 깨졌다.

### 4.2 옮기기는 `Object.assign` 증강으로

원본이 이미 `Object.assign(App.prototype, { … })` 의 객체 리터럴이므로, 받는 쪽을
`Object.assign(NewClass.prototype, { … })` 로 두면 **쉼표까지 그대로**다. 클래스
본문에 넣으면 메서드마다 쉼표를 떼야 하고 그 편집이 diff 를 덮는다.

**메서드 이름도 바꾸지 않는다.** 이름을 다듬으면 내부 호출 전부가 diff 에 섞인다.

### 4.3 검증

```bash
go build ./... && go vet ./... && go test ./...
npx playwright test --reporter=line          # 13~14분
```

**e2e 실패 1건은 회귀가 아닐 수 있다.** 이 저장소는 전량 실행에서 927개 중 1개
정도가 산발로 흔들리며 **실행마다 다른 스펙이 걸린다** (관측된 것: `git-commit` E11,
`git-repo-missing` M3, `sidebar-tabs` T9). 실패가 나면 **반드시 단독 재실행으로
가른다** — 단독에서 통과하면 산발 흔들림이고, 재현되면 회귀다.

자산을 고쳤으면 `index.html` 의 `?v=` 와 `web/assets.lock` 을 함께 올린다
(`go test ./web/` 가 새 해시를 알려준다).

## 5. 손대지 않기로 한 것과 사유

| 대상 | 사유 |
|---|---|
| `GitPanel` 객체 분해 | 주제 그룹끼리 필드를 **10~21개** 공유한다. 떼면 참조만 늘어난다 (`APP_STATE_EXTRACT_SRS` §5 N2) |

| SA4000 2건 | `Render() != Render()` 는 결정성 테스트다 |
| ST1005 1건 | `dmctl` 이 사용자에게 내보내는 안내문. 고치면 CLI 출력이 바뀐다 |
| `_activityRestore`·`_bgRefresh`·`_focusRestore` 의 복원 경쟁 | `_fgRestore` 와 같은 자리에서 불린다. **같은 결함이 있는지 확인하지 않았다** (`FG_RESTORE_RACE_SRS` §7.4) |
