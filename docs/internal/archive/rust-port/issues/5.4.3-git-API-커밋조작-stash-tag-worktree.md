### 5.4.2 에서 값을 치르고 배운 것
- 도메인 오류의 `is` 는 inherent 메서드(WriteKind/QueryKind 인자)가 Classify::is 를 가린다 — Go errors.Is 는 `Classify::is(&e, &Sentinel::Core(Kind::X))` 로 명시 호출한다.
- Go `map[string]any` 응답은 `obj!{}`(BTreeMap, 키 정렬 = Go 와 같음). action.Answer args 에 구조체를 실을 땐 `serde_json::to_value`(preserve_order 켜짐 → 필드 순서 유지).
- 요청 구조체: `#[derive(Default, Deserialize)] #[serde(default, rename = "gitapi.<goType>")]`, nil 될 수 있는 slice 는 Option<Vec>.
- Go 에서 핸들러가 `gitError(w, err)` 로 직접 쓰고 return 하는 곳은 `t.reject(&e)` 또는 응답을 그대로 return 한다.
- stage·unstage·discard·resolve·clean 의 argv 는 `:(literal)<경로>`(DIFF-14) — Go 테스트의 기대 argv 를 Rust 에 맞추고 주석을 단다.
- SSE·잡: 잡 실행기는 테스트에서 늘 fake(`job_runner`). Go `after, _ := ParseUint` 처럼 버리는 값도 Go 의 반환값(범위 오류=최댓값)을 따진다.
- 테스트 이식은 파일 묶음별로 하위 에이전트 4개를 병렬로 돌리니 빨랐다(겹치지 않는 test 파일만 쓰게, 프로덕션·하네스 수정 금지, 의심 버그는 #[ignore] + 보고). `cargo fmt --all` 은 마지막에 한 번.
- 교차 clippy 는 ring 의존이라 건너뛴다(8.3).

### 5.5 httpapi 배선 참고
- 만들기: `let mut g = GitServer::default();` 뒤 pub 필드를 채운다 — `git: Some(Arc<Store>)`, `work: Some(Arc<dyn WorkspaceStore>)`(wsentry 트레이트), `commands: Some(Arc<dyn Broadcaster>)`, `tools: Some(Arc<dyn ToolLocator>)`(cwd 하나), `images: Some(Arc<core::Service>)`(WithMaxOutput 큰 그림 전용 실행기, 없으면 blob 503), `repo_guard: None`(Go 운영도 주입하지 않는다), `watch: Some(Arc<dyn RepoWatcher>)`(hub GitWatcher), `exclusion: Some(Exclusion)`(Run 격리와 같은 것), `job_runner: None`(운영은 실제 git), `user_worktrees: Some(Arc::new(worktree::Manager::new($DONGMINAL_HOME/git-worktrees)...))`, `submodules: Some(Arc::new(submodule::Manager::new(runner)))`, `run_worktree_root: <Run 격리 Manager 의 root>`. 그 뒤 `Arc::new(g)`.
- 요청: `GitServer::handle(self: &Arc<Self>, req: http::Request<B>, req_id: Option<String>) -> Option<Response>` — `None` 이면 호출자가 404. 경로가 `/api/git/` 로 시작하지 않거나 라우트가 없으면 None. 핸들러는 tokio::spawn 으로 돌고 패닉은 다시 던진다(5.5 가 recover 규칙을 진다 — NFR-RSP-2).
- **경로 퍼센트 디코드 실패는 handle 이 None 을 준다** — Go 서버는 핸들러 전에 400 을 내므로 5.5 가 먼저 `neturl::path_unescape` 로 걸러 400 을 내야 한다.
- `/api/stats?jobs=1`: `GitServer::active_jobs() -> Option<Vec<Job>>`(git 없으면 None).

### Go 와 다르게 한 결정
- **FR-RSP-6 (보안 강화, DIFF 후보)** file-head 의 HEAD 사본 쓰기(`$TMPDIR/dongminal-git-head/<hash>/<rel>`): Go 는 공유 임시 디렉터리에서 경로를 따라 chmod·WriteFile 하므로, 다른 로컬 사용자가 미리 디렉터리나 심링크를 심으면 남의 파일을 덮거나 권한을 바꿀 수 있다(유닉스 `/tmp` 공유 시). Rust 는 ① `dongminal-git-head` 가 심링크 아닌 디렉터리이고 내 uid 소유이며 group/other 쓰기가 없을 때만 쓰고(아니면 `mkdir <top>: operation not permitted` 500) ② 끝 성분을 `O_NOFOLLOW` 로 열고(심링크면 `open …: too many levels of symbolic links`) ③ 읽기 전용 전환은 열린 핸들로 한다. 정상 사용자에게는 경로·권한·응답이 Go 와 같다. SRS 3.7 표 등재를 조정자에게 요청한다.
- submodule 오류는 apierr 에 Classify 구현이 없어 gitapi 안 newtype(SubErr)이 원인 core 오류로 분류한다(Go errors.Is 사슬과 같은 결과).
- 오류 문구 근사: file-head·worktree 생성의 MkdirAll 실패는 `mkdir <요청 디렉터리>` 로 감싼다(Go 는 실패한 조상 성분 경로를 싣는다 — 권한 오류 같은 드문 경우의 문구 차이).
- worktree 생성의 Go defer(잡 등록 실패 시 잠금 반납·만든 디렉터리 삭제)는 Drop 가드(CreateGuard)로 옮겼다.
