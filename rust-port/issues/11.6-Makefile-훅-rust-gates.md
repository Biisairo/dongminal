**자리별 처리**
- G-9: `make gates` 머리 세 단계를 `── cargo fmt`(`cargo fmt --all -- --check -l`, 위반이면 저장소 기준 상대 경로 목록과 `cargo fmt --all 로 고치세요`, 레시피 종료 1) · `── cargo clippy`(`-q --workspace --all-targets -- -D warnings`) · `── cargo build`(`-q --workspace`)로 바꿨다. `-q` 는 Go 판의 `go vet`·`go build` 처럼 성공하면 아무것도 찍지 않게 하려는 것이다.
- G-10: 제목 둘을 바꿨다: `활동 상태 어휘 (Rust 와 JS 의 …)`, `프로세스 축 경계 · crate 표 (축을 넘는 의존이 없는가 · 표가 cargo metadata 와 같은가)`. 나머지 63단계는 그대로다.
- G-11: `test:  ## 단위 테스트 (cargo test --workspace)`, 레시피는 `cd rust && scripts/hermetic.sh cargo test --workspace`. **결정**: 격리 실행으로 돌린다 — 탭에서 물려받은 `DONGMINAL_*` 가 운영 서버를 겨누지 않게 한다(C-RSP-1). `-race -shuffle=on` 이 없는 것은 DIFF-GRM-5.
- G-12: `lint` 의 golangci-lint 자리를 `cargo deny check`·`cargo audit` 로 바꿨다. 없으면 `!! cargo-deny 가 없어 건너뜁니다 — CI 는 이것을 돌립니다.` + `   설치: cargo install --locked cargo-deny`(audit 도 같은 형식). eslint 부분은 그대로다. 도움말은 `cargo deny + cargo audit + eslint (없으면 건너뛰고 알린다)`.
- G-13·G-14: 목표 이름·의존 순서·`.githooks/pre-commit` 은 그대로다.
- G-67: `rust/scripts/gates.sh` 에서 `--go` 를 지웠다. Q-GRM-12 의 "deny·audit·교차 clippy 전용" 대로 `fmt` 단계와 `--test` 도 지웠다(fmt 는 `make gates`, test 는 `make test` 가 돈다). `--go` 를 주면 `알 수 없는 옵션: --go` 와 종료 2. `-h` 가 `cd` 뒤에 상대 경로 `$0` 를 읽어 실패하던 원래 버그도 고쳤다.

**검증**(PATH 에서 go·gofmt·golangci-lint 를 뺀 격리 실행)
- `make help`: 목표 이름 집합이 Go 판과 같다. `test`·`lint` 도움말 두 줄만 다르다.
- `make gates`: 66단계가 Go 판과 같은 순서이고 G-9·G-10 의 세 곳만 다르다. `gates ok`, 종료 0. rust-port 병합 뒤 다시 돌려도 같다. (node 게이트가 espree 를 읽으므로 실행하는 동안만 다른 worktree 의 node_modules 를 링크했다 — 이 worktree 에는 node_modules 가 없다.)
- fmt 위반 한 건을 심으면 `── cargo fmt` → 파일 목록 → `cargo fmt --all 로 고치세요`, make 종료 2(Go 판도 레시피 exit 1 → make 종료 2).
- `make test`: 3882 통과·실패 0·무시 2.
- `make lint`: 도구가 있으면 `advisories ok, bans ok, licenses ok, sources ok` 와 audit 통과, 종료 0. 도구가 없으면 위의 `!!` 네 줄과 eslint 안내, 종료 0.
- `rust/scripts/gates.sh`: 다섯 대상 clippy·deny·audit 통과, `gates: 통과`.
- `make all` 은 따로 돌리지 않았다. 구성 목표(gates·lint·test)는 각각 통과했다. typecheck·unit 은 이 묶음에서 바꾸지 않았다(unit 의 실패 9건은 원래부터 있다 — 11.2 기록 참고).
