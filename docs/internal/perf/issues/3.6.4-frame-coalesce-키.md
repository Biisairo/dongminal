# 3.6.4 frame coalesce 키 충돌

## 목표

3.6.3 에서 발견(3.6.1 이전부터 있던 결함): `frame` 의 coalesce 키가 `'frame:'+owner+':'+이름` 이라 주인이 객체면 모두 "[object Object]" 로 같아진다. 서로 다른 DiffView·문서 뷰가 같은 coalesce 이름(예: diff-fold)을 한 프레임에 쓰면 뒤의 것이 버려진다. 주인별로 구별되게 고친다(예: 주인 객체별 키 공간). 기존 호출 동작은 같은 주인 안에서 그대로.

## 완료 조건

- RED: 두 주인이 같은 이름으로 같은 프레임에 걸면 둘 다 돈다. 같은 주인은 여전히 하나로 합쳐진다. 프론트 단위 전체·tsc·check-timers. 전체 시험 금지.

**바꾼 것**: `TimerHub.frame` 의 coalesce id 를 `'frame:'+_ownerKey(owner)+':'+이름` 으로 바꿨다. 주인 객체(함수 포함)는 `WeakMap` 으로 번호(`o:<n>`)를 받고, 문자열·없는 주인은 `s:<값>` 이다. `timer-hub.js` 가 500줄을 넘지 않게(499) frame·`_flushFrame` 주석을 줄였다.

**동작 변경**

| 이전 | 새 | 이유 |
|---|---|---|
| 주인이 객체면 키가 모두 `frame:[object Object]:<이름>` 이었다. 다른 DiffView(`diff-fold`)·문서 뷰(`doc-scroll`, `view`)·터미널 터치(`wheel`)가 같은 프레임에 걸면 먼저 잡힌 하나만 돌았다. 그 레코드의 주인도 먼저 건 쪽이라 `disposeOwner` 가 어긋났다 | 주인마다 따로 접는다. 같은 주인 안에서는 종전처럼 먼저 잡힌 예약이 이긴다 | 결함 수정 |
