# 11.9c architecture.md 본문의 Go 심볼을 Rust 심볼로

## 목표

조정자 결정(2026-11-24): `docs/internal/architecture.md` 본문의 Go 심볼 이름을 대응하는 Rust 심볼로 바꾸고, Go 언어를 전제로 한 설명 문단은 Rust 구조에 맞게 고친다. 대응이 없으면 "Go 기준선(main)" 으로 표기한다.

## 진행 기록

- 바꾼 것(서버 쪽 Go 심볼 → Rust 심볼, 모두 rust/crates 에서 정의를 확인했다): 오류 방언(`http_err`·`httpresp::json`·`CODE_HEADER`·`fail`·`fail_code`·`httpreq::decode_json`·`apierr::Table::lookup`), `GitWrite`, `dm_shared_runtime::install`·`dmenv::helper_names`, `safe_resolve`, `run::path_slug`, 커맨드 허브(`CMD_SUB_QUEUE`·`clear_all_attention`·`TOOL_CAP`·`is_allowed_cmd_action`·`CMD_ACTIONS`·`FocusRegistry::executor`·`SUB_CAP`·`presence_subs`), toolipc(`PROTOCOL_VERSION`·`DAEMON_FEATURES`·`CODE_NOT_FOUND`), git core(`Service::exec`·`exec_write`·`guard_args`·`READ_COMMANDS`·`guard_write_args`), seam(trait·`adapters::Tool/Workspace/Client`), ws(`hold_miss`·`OP_EXIT`), 종료(`ToolClient::close`·`save_all`·`load_all`).
- Go 를 전제로 한 문단을 Rust 구조로 다시 썼다: "자유 함수" 문단(Rust 의 고유 impl 은 정의한 crate 에만 — `status_of(s: &Service, …)`), gitapi 의 trait 넷(Rust 는 `RepoWatcher` 가 더 있어 "메서드 네 개" 를 뺐다), `workspace::Manager::save`(writer 스레드 + 대기 칸 하나 + `Condvar`, `close()` 는 flush 뒤 join), 동시성 절 8항목(각 struct 의 실제 필드: `RwLock<State>`·`Mutex<Table>`·`PaneState` atomic·`State.generation`·`OUTPUT_QUEUE` 등), "모드 판별은 `ToolHub.Daemon()`" → Rust 는 `ToolHub` trait 하나와 composition root, 종료 경로(`serve/signals.rs` 의 `CancellationToken`·`run(ctx)`), `go list` → crate 의존 그래프, upgrade 뒤 취소 문장, git 실행 계층의 "패키지" → crate 묶음.
- "Go 기준선(main)" 으로 적은 것: `http.Error`, `throttleMiss`, `adapters.Command`·`toolaccess.CommandBroadcaster`(지운 것), `Proto`·`ParseHistory`·`fakeagent`(지운 것), `ToolHub.Daemon()`, workspace 저장 측정치(Go 에서 잰 값).
- 일부러 둔 것: 프런트엔드(JS) 심볼 전부(`GitPanel`·`FileTree`·`_execRemote` 등 — Go 가 아니다), `StartTool`·`installAgentHooks` 는 Rust 에 한 이름의 대응이 없어 "도구 시작 함수"·"런타임 설치" 로 풀어 썼다. 진단 로그 예시 줄(`goroutines=18 allocMB=1`)은 실제 출력 키 이름이라 두었다(DIFF-27). "패키지 레이아웃" 제목과 표 안의 "패키지" 는 pkg-axis 가 읽는 자리라 두었다.
