# SRS: 내부 새로고침 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 한 줄이다.

> **"새로고침말고 내부적으로 새로고침이있으면 좋겠어. 다시 가져오고 다시
> 로딩하고..."**

페이지를 다시 여는 것(`location.reload`)은 **가진 것을 전부 버리고 처음부터
세우는 일**이다. 터미널의 xterm 인스턴스와 스크롤백, 열린 편집기 탭의 미저장
내용, 펼친 트리와 스크롤 위치가 함께 사라진다. 사용자가 원하는 것은 그것이
아니라 **서버의 사실을 다시 받아 화면을 맞추는 것**이다.

이 요구는 접속 불가 건과 이어져 있다. 연결이 한동안 끊겼다 붙으면 화면은 서버의
사실을 더는 따라가지 않는데, 지금 그 상태를 벗어나는 수단이 **페이지 새로고침
하나뿐**이다.

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 다시 가져오기 | 워크스페이스·부가 상태·목록·패널을 서버에서 다시 받아 적용한다 |
| **B** 터미널 재연결 | 모든 터미널을 끊고 다시 붙여 서버의 스크롤백을 받는다 |
| **C** 진입점 | 사이드바 버튼과 단축키. 도는 동안과 끝났을 때를 보인다 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **내부 새로고침** | 문서를 다시 열지 않고 서버 상태를 다시 받아 적용하는 것 |
| **페이지 새로고침** | `location.reload`. 문서와 그 안의 모든 것을 버린다 |
| **부가 상태** | 워크스페이스에 없는 것들 — 주의·활동·백그라운드·포커스·전경 이름 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 조각은 이미 다 있다 — 부르는 자리가 없을 뿐이다

| 하는 일 | 있는 자리 |
|---|---|
| 워크스페이스 재적용 | `_onWorkspaceChanged(rev)` (`app-cmd.js:106`) |
| 주의·활동·백그라운드·포커스·전경 | `_attnRestore` · `_activityRestore` · `_bgRefresh` · `_focusRestore` · `_fgRestore` |
| 죽은 도구 정리 | `_applyRemoteWorkspace` (`app-cmd.js:210`) |
| 탐색기 갱신 | `FileTree.refresh()` |

그리고 **`_onWorkspaceChanged` 는 인자 없이 부르면 무조건 다시 가져온다** —
`typeof rev==='number'` 가 거짓이라 rev 비교를 건너뛴다 (`:114`). 강제 재적용의
경로가 이미 열려 있다.

지금 이것들이 함께 도는 자리는 SSE 의 `onopen` 하나뿐이다 (`app-cmd.js:25`).
**즉 "다시 가져오기" 는 SSE 가 끊겼다 붙을 때만 일어난다.**

### 2.2 SSE 가 살아 있으면 회복의 계기가 없다

FR-RCS-6 이 "포기하지 않는다" 를 보장하지만, 그것은 **끊긴 뒤 다시 붙는** 경우의
이야기다. 구독이 형식상 살아 있는데 그 사이의 브로드캐스트를 놓친 경우 — 네트워크가
잠깐 멎었다 돌아온 뒤가 그렇다 — 화면은 옛 사실을 붙들고 있고 `onopen` 은 다시
오지 않는다.

사용자가 페이지를 새로고침해 온 이유가 이것이다.

### 2.3 페이지 새로고침이 버리는 것

| 잃는 것 | 왜 |
|---|---|
| 터미널 스크롤백과 xterm 상태 | 인스턴스를 새로 만든다 |
| 편집기 탭의 미저장 내용 | Monaco 모델이 사라진다 |
| 탐색기의 펼침·선택·스크롤 | 창별 런타임 상태다 (FR-EDT-62·66) |
| Git 패널의 열린 탭·diff 위치 | 같은 이유 |

내부 새로고침은 이 중 **터미널만 의도적으로 버린다** (묶음 B, D-2).

### 2.4 오버레이를 지우는 자리가 한 곳뿐이다 (구현 중 실측)

`_hideOverlay()` 를 부르는 곳은 `_reconnect()` 의 `onopen` **하나뿐이다**
(`term-pane.js:434`). `connect()` 의 `onopen` 에는 없다 — 그 함수는 최초 연결
전용이라 지울 오버레이가 애초에 없었기 때문이다.

`reconnectNow()` 가 오버레이를 띄운 채 `connect()` 를 부르면서 그 사실이 결함이
됐다. 실측:

```
T+6000  {"ws":1, "ovVisible":true, "ovText":"다시 연결내부 새로고침..."}
```

`ws:1` 은 소켓이 **OPEN** 이라는 뜻이다 — 연결은 붙었는데 화면만 "다시 연결" 에
멈춰 있다. 사용자에게는 이것이 곧 "연결 안 됨" 이다.

> **검사가 이것을 놓쳤던 경위도 함께 적는다.** 처음 쓴 e2e 는 `expect.poll(…)
> .toBe(0)` 으로 오버레이 수를 재는데, 그것이 **클릭 직후 오버레이가 뜨기도 전에**
> 평가돼 0 을 받고 그대로 통과했다. 사라짐을 재려면 **먼저 붙기를 기다린 뒤**
> 봐야 한다 (V-SRL-5b).

## 3. 요구사항 (Requirements)

### 3.1 묶음 A — 다시 가져오기

**FR-SRL-1.** `App.softReload()` 를 신설한다. 순서는 아래이며, **워크스페이스가
가장 먼저다** — 창·탭·도구의 구성이 나머지 전부의 전제이기 때문이다.

1. SSE 구독이 살아 있는지 보고, 아니면 다시 연결한다 (FR-SRL-3)
2. 워크스페이스를 강제로 다시 받아 적용한다 (`_onWorkspaceChanged()`)
3. 부가 상태 다섯을 복원한다
4. 목록과 패널을 갱신한다 — Editor 목록 · Git 리포 · Git 패널 · 탐색기
5. 터미널을 전부 다시 붙인다 (묶음 B)
6. 다시 그린다

**FR-SRL-2.** 한 번에 하나만 돈다. 도는 중에 다시 부르면 **무시한다** — 겹쳐
돌면 낡은 응답이 새 것을 덮는다 (FR-GRR-4 와 같은 근거).

**FR-SRL-3.** SSE 구독의 상태를 볼 수 있어야 한다. `EventSource.readyState` 가
`CLOSED` 면 즉시 다시 연결한다. 지금은 구독 객체가 클로저 안에 갇혀 밖에서 볼 수
없으므로, 인스턴스에 보관하고 강제 재연결 수단을 연다.

**FR-SRL-4.** 한 단계가 실패해도 나머지는 계속한다. 부분적으로라도 최신에 가까워
지는 것이 전부 포기하는 것보다 낫다 — 실패한 것은 콘솔에 남긴다.

### 3.2 묶음 B — 터미널 재연결

**FR-SRL-5.** **모든** 터미널 pane 을 끊고 다시 붙인다. 살아 있는 것도 포함이다.
사용자가 내부 새로고침을 부르는 상황은 "화면이 서버와 어긋난 것 같다" 이며, 그때
살아 있어 **보이는** 연결이 실제로는 옛 것일 수 있다.

**FR-SRL-6.** 재연결은 pane 을 다시 만들지 않는다 — 소켓만 다시 연다. xterm
인스턴스가 새로 서면 페이지 새로고침과 다를 것이 없어진다 (§2.3).

**FR-SRL-6b.** 재연결이 끝나면 **오버레이가 사라진다.** 연결이 붙었는데 "다시
연결" 화면이 남으면, 사용자에게 그것은 성공이 아니라 **연결 실패**다.

> 이것을 조항으로 세우는 이유는 실제로 그렇게 나갔기 때문이다 (§2.4).

**FR-SRL-7.** 도구가 사라졌다고 판정된 pane(`_exited`)은 **다시 붙이지 않는다.**
그 판정은 서버의 통보로 선 것이며(FR-RCS-1), 뒤집으면 폭주가 되살아난다.

### 3.3 묶음 C — 진입점

**FR-SRL-8.** 사이드바 최하단, 설정(⚙) 옆에 버튼을 둔다. 어느 탭에서나 보이는
자리다 (FR-SBT-4 와 같은 근거).

**FR-SRL-9.** 단축키는 **앱의 기존 단축키 체계에 편입한다** —
`SHORTCUT_DEFAULTS` 에 기본값을 두고 `executeAction` 이 실행한다. 기본값은
`Ctrl+Shift+K` 이며, `Cmd+R`·`Cmd+Shift+R` 은 브라우저가 가져가므로 쓸 수 없다.

> 별도 리스너를 달지 않는 이유: 그 체계가 이미 **설정에서의 변경**과 **터미널·
> 브라우저보다 앞서는 우선순위**를 정한다 (`shortcuts.md`). 우회하면 사용자가 키를
> 바꿀 수도, 충돌을 풀 수도 없다.

**FR-SRL-10.** 설정의 Shortcuts 목록에 나타나 다른 동작들처럼 바꿀 수 있다.

**FR-SRL-11.** 도는 동안 버튼이 그 사실을 보이고, 끝나면 되돌아온다. 아무 표시가
없으면 사용자는 눌린 줄 모르고 다시 누른다.

## 4. 설계 결정 (Design Decisions)

| # | 결정 | 근거 |
|---|---|---|
| **D-1** | 있는 조각을 부를 뿐 새로 만들지 않는다 | 복원 경로 다섯은 이미 SSE `onopen` 이 쓰고 있다 (§2.1). 두 벌이 되면 한쪽만 고쳐진다 |
| **D-2** | 터미널은 **전부** 다시 붙인다 | 사용자 결정. 화면이 어긋난 것 같을 때 부르는 기능이므로, 살아 보이는 연결도 믿지 않는다 |
| **D-3** | pane 을 다시 만들지 않는다 | 만들면 페이지 새로고침과 같아진다. 소켓만 다시 여는 것이 이 기능의 전부다 (FR-SRL-6) |
| **D-4** | `_exited` 는 되살리지 않는다 | 그 판정은 서버의 통보로 섰다. 뒤집으면 RECONNECT_STORM 이 고친 폭주가 되살아난다 |
| **D-5** | 실패해도 계속한다 | 다섯 갈래 중 하나가 실패했다고 나머지를 버리면, 가장 필요한 순간(부분 장애)에 아무것도 못 한다 |
| **D-6** | 단축키는 `Cmd/Ctrl+Shift+K` | `R` 계열은 브라우저가 가져간다. `Shift` 조합이라 터미널의 일반 입력과 겹치지 않는다 |

## 6. 비목표 (Non-goals)

- **편집기 탭의 내용 재로드.** 미저장 내용을 덮어쓰게 된다. 파일 다시 읽기는
  편집기 자신의 일이다.
- **자동 주기 실행.** 이 기능은 사용자가 부르는 것이다. 주기적으로 돌면 그것은
  폴링이며, 그 비용은 SSE 를 둔 이유와 어긋난다.
- **페이지 새로고침의 대체.** 자산(JS·CSS)이 바뀌면 문서를 다시 열어야 한다 —
  그것은 `version-watch` 의 배너가 맡는다.
- **끊김 자동 감지 후 실행.** 사용자가 이번 범위에서 고르지 않았다.
