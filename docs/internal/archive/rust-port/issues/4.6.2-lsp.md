## 진행 기록
- 2026-11-23 **review** (owner 117bca6d). 커밋 `a961a194` port(4.6.2) (rp/4.6).
  - prod-pids.sh 출력(시작과 끝이 같다): `38173 start --foreground`, `58470 d --handover-fd`.
  - **공개 API** (`dm-webserver-domain-lsp`)
    - 프레이밍: `write_frame(&mut dyn Write, &[u8])`, `read_frame(&mut dyn BufRead) -> io::Result<Vec<u8>>`, `ERR_HEADER_TOO_LARGE`. 오류 문구는 Go 와 같다(`EOF`, `unexpected EOF`, `lsp: bad Content-Length " x": strconv.Atoi: …`, `lsp: frame too large (…)`).
    - 프로세스: `Conn{reader, writer, stop}`, `Starter = Arc<dyn Fn(exe, args, dir) -> io::Result<Conn>>`, `start_process`(platform 의 Group 으로 자손까지 묶는다. 시작 실패 문구는 `fork/exec <exe>: …`).
    - `Service{ext: Option<Arc<ext::Service>>, start, now: Option<NowFn>, idle_after, max_sessions, watch_max}`. `new(ext)`, `status()`, `install(ctx, id).await`, `open_tunnel(root, desc) -> Result<Arc<dyn Tunnel>, OpenError>`(`OpenError::Limit` 은 Go `ErrLimit`), `sweep()`, `run_sweeper(self: Arc<Self>, CancellationToken).await`, `shutdown()`, `load_paths(file) -> Result<(), String>`, `paths()`, `set_paths(&HashMap) -> Result<HashMap, PathsError>`(`NotAbsolute`·`Save` 는 Go 의 두 sentinel 이다).
    - `Tunnel` trait: `send`·`recv`·`close`·`last_use`. 블로킹이다 — WS 처리부(5.5)는 읽기·쓰기를 각각 스레드나 spawn_blocking 에서 돌린다. `close` 는 다른 스레드에서 막힌 `recv` 를 서버 종료(EOF)로 풀어 준다.
    - 변경 알림: `FileEvent{path, typ}`, `WATCH_CREATED/CHANGED/DELETED`, `DEFAULT_WATCH_MAX`, `FileNotifier` trait(Service 가 구현한다), `RepoView` trait(`snapshot`, `name_status` — Go 의 ctx 인자는 뺐다), `RepoSnap`, `NameStatus`, `RepoWatch::{new, seen, changed}`, `ExistsFn`.
    - 상수: `IDLE_AFTER`(20m), `MAX_SESSIONS`(6), `MAX_TEXT_BYTES`(= editorlimit FILE_MAX_BYTES), `SWEEP_EVERY`(2m). 끼워 넣기 줄은 16 이다.
  - **시험**: Go 시험을 모두 옮겼다(codec 6·attic 6·limit 1·tunnel 10·paths 2·process 1·watch 14). 실패 문구·경로 표 파일 바이트(MarshalIndent 모양)·시작 실패가 자리를 쥐지 않는 것도 더했다. 모두 41개이고 격리 실행에서 통과한다. fmt·darwin clippy `-D warnings` 가 통과한다.
  - **Go 와 다르게 한 내부 결정**
    - Go 의 goroutine+chan 끼워 넣기는 `sync_channel(16)` + 전용 스레드다. 터널을 닫으면 보내는 쪽을 떨어뜨려 스레드가 끝난다.
    - 시각은 `SystemTime` 이고 `now` 를 주입한다. Go `time.Time` 과 같은 쓰임이다.
    - Go 는 rwc.Close 로 읽기 끝을 닫는다. Rust 는 쓰기 끝만 떨어뜨리고 `stop`(묶음 kill+wait)으로 stdout 이 EOF 가 되게 한다. 다른 스레드가 읽는 fd 를 닫지 않기 위해서다. 그래서 닫힌 터널의 recv 오류는 `EOF` 이고, send 오류는 `file already closed` 다.
    - `load_paths` 의 오류는 String(Go `error` 문구)이다.
  - **교차 검사**: 이 crate 는 ext→reqwest→ring 을 끌어오므로, 조정자 결정에 따라 windows·linux `cargo check` 를 건너뛰었다(8.3 에서 푼다). OS 분기 코드는 이 crate 에 없고, process 의 묶음은 platform 이 맡는다.
  - **남은 위험**: Windows 에서 Job Object 를 kill 했을 때 stdout EOF 가 오는지는 실기 검증 전이다(LOW). NFR-5 시험(중앙값 25ms)은 부하가 큰 CI 에서 흔들릴 수 있다(Go 와 같은 기준).
