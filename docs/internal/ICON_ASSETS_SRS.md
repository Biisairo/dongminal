# Dongminal 아이콘·파비콘 자산 SRS

- 문서 상태: 승인 대기
- 준수 표준: IEEE/ISO/IEC 29148:2018
- 작성일: 2026-08-25
- 관련 브랜치: `feat/icon-favicon`

---

## 1. 서론

### 1.1 목적

dongminal 웹 UI에 브랜드 아이콘과 파비콘 자산을 도입한다. 현재 `web/index.html` 에는
아이콘 관련 선언이 전혀 없어 브라우저가 기본 아이콘(빈 문서)을 표시한다. 본 문서는 도입할
자산의 형태·색·규격·배선 요구사항과 검증 방법을 정의한다.

### 1.2 범위

포함:

- 아이콘 마크의 형태·색 정의
- SVG 원본 및 래스터(PNG) 파생 자산
- `web/index.html` `<head>` 배선
- `web/embed.go` 임베드 대상 확장

제외 (비목표):

- PWA 매니페스트(`manifest.webmanifest`)·서비스워커 — 설치형 앱 동작을 유발하므로 별도 결정 사항
- macOS `.icns` / Windows `.ico` 등 데스크톱 번들용 자산 — 현재 배포 형태(단일 Go 바이너리 + 브라우저)에 불필요
- 기존 44종 테마와의 연동(테마별 아이콘 교체)
- 로고타입(워드마크) 확정

### 1.3 용어

| 용어 | 정의 |
|---|---|
| 마크 | 아이콘의 도형 부분. 대문자 D 형태의 프레임과 그 내부의 `>` 프롬프트 |
| 타일 | 마크를 담는 둥근 사각 배경 |
| 카운터 | 글자 내부의 빈 공간. 본 마크에서는 터미널 화면에 해당 |
| 잉크 | 마크 획의 색. 타일과 대비되는 어두운 색 |

## 3. 전체 설명

### 3.1 제품 관점

정적 자산 추가와 HTML `<head>` 선언 추가만으로 구성된다. 서버 라우팅은 이미
`web/` 전체를 `/` 에 서빙하므로 신규 핸들러가 필요 없다.

### 3.2 설계 근거 (형태)

대문자 D 의 바깥선을 터미널 창 프레임으로, 카운터를 화면으로, 내부의 `>` 를 프롬프트로
사용한다. 창과 글자가 같은 도형이므로 요소 수가 늘지 않는다.

- 왼쪽 모서리는 작은 곡률(R3.5), 오른쪽은 큰 곡률(R17) — D 로도 창으로도 읽힌다.
- 프레임 획 7.5, 프롬프트 획 4.0 (64 단위 기준). 프레임이 굵어 창으로, 프롬프트가 가늘어
  화면 위 텍스트로 읽힌다.

### 3.3 설계 근거 (색)

터미널 인광 그린 계열에서 채도·명도를 낮춘 "더 어둡게" 톤을 사용한다.

| 역할 | 값 |
|---|---|
| 타일 그러데이션 시작 | `#4F8461` |
| 타일 그러데이션 끝 | `#356146` |
| 잉크(마크 획) | `#08110D` |

잉크는 순수 검정이 아니라 녹색이 미량 섞인 값으로, 타일과 같은 계열을 유지한다.

### 3.4 제약

- 자산은 `go:embed` 로 바이너리에 포함되어야 한다 (단일 실행 파일 배포 원칙).
- 외부 CDN·네트워크 요청을 발생시키지 않는다.
- 런타임 테마 전환(44종)과 무관하게 아이콘 색은 고정이다.

---

### 3.5 구현 노트

작업 중 확인된 사항 두 가지를 기록한다.

1. **그러데이션 벡터는 타일 전체를 덮어야 한다.** `gradientUnits="userSpaceOnUse"` 에서 벡터를
   `(6,6)→(58,58)` 로 두면 벡터 바깥 영역이 `spreadMethod="pad"` 로 단색 처리되어 타일 위에
   대각선 경계가 보인다. `(0,0)→(64,64)` 로 타일 전체를 덮어 해결했다.
2. **래스터 자산에 색상 양자화(PNG-8)를 적용하지 않는다.** 팔레트 양자화 시 그러데이션에
   디더 노이즈가 발생한다(인접 픽셀 채널 차 최대 10). 무손실 재압축만으로 512px 자산이
   40 KB 로 줄어 NFR-ICON-2 를 만족하므로 양자화가 불필요하다.

## 4. 요구사항

### 4.1 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-ICON-1 | `web/assets/favicon.svg` 를 제공한다. viewBox `0 0 64 64`, 타일 모서리 반경 15, 타일 밖은 투명이어야 한다. | 필수 |
| FR-ICON-2 | `web/assets/favicon-16.png`, `favicon-32.png` 를 제공한다. 각각 16×16, 32×32 이며 타일 밖은 투명이어야 한다. | 필수 |
| FR-ICON-3 | `web/assets/apple-touch-icon.png` 를 180×180 으로 제공한다. iOS 가 자체 마스킹을 적용하므로 모서리를 둥글리지 않고 전면을 채운다(투명 영역 없음). | 필수 |
| FR-ICON-4 | `web/assets/icon-192.png`, `icon-512.png` 를 제공한다. 둥근 타일, 투명 배경. | 필수 |
| FR-ICON-5 | `web/index.html` `<head>` 에 SVG 파비콘, PNG 파비콘(16·32), apple-touch-icon 선언을 추가한다. 경로는 기존 자산과 동일하게 상대 경로를 사용한다. | 필수 |
| FR-ICON-6 | `web/embed.go` 의 `go:embed` 패턴에 `assets/*` 를 추가해 신규 자산이 바이너리에 포함되게 한다. | 필수 |
| FR-ICON-7 | 모든 래스터 자산은 동일한 SVG 원본에서 파생되어 형태·색이 일치해야 한다. | 필수 |

### 4.2 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-ICON-1 | 16×16 에서 프레임과 프롬프트가 모두 판별 가능해야 한다(형태가 단색 덩어리로 뭉개지지 않을 것). |
| NFR-ICON-2 | 개별 자산 파일 크기는 64 KB 이하여야 한다. |
| NFR-ICON-3 | 어두운 브라우저 탭 바와 밝은 탭 바 양쪽에서 타일 경계가 식별되어야 한다. |
| NFR-ICON-4 | 자산 추가로 인한 기존 기능의 동작 변경이 없어야 한다. |

### 4.3 인터페이스 요구사항

- 자산 URL: `/assets/<파일명>` — `internal/server/server.go:100` 의 기존 파일 서버로 서빙된다.
- 신규 서버 라우트를 추가하지 않는다.

## 5. 검증

| 요구사항 | 검증 방법 |
|---|---|
| FR-ICON-1..4 | 파일 존재 및 규격 확인 (`sips -g pixelWidth -g pixelHeight`), SVG 는 viewBox 문자열 확인 |

| NFR-ICON-1 | 16px 렌더 육안 확인 (시안 리뷰 Artifact 의 탭 목업) |

| NFR-ICON-3 | 어두운/밝은 배경 위 렌더 육안 확인 |
| NFR-ICON-4 | 기존 e2e 스위트 통과 |
