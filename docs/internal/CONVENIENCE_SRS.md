## 2. 전체 설명 (Overall Description)

### 2.1 현재 상태 — 조사로 확정한 사실

**(a) 탭 이름은 만들어질 때 정해지고 그대로다.** `app-layout.js:28`·`:177`:

```js
tabs:[{id:t, name:'Shell', type:'terminal', toolId:p.id}]
```

모든 터미널 탭이 `Shell` 이다. 다섯 개를 띄우면 `Shell` 이 다섯 개다. `vim` 을 열든
`claude` 를 띄우든 이름은 변하지 않는다.

**(b) 현재 서버는 전경 프로세스를 보지 않는다.** busy 판정은
`tool.go:166` 이다:

```go
var toolBusyProbe = func(pid int) bool {
	out, err := exec.Command("pgrep", "-P", strconv.Itoa(pid)).Output()
	...
	return len(strings.TrimSpace(string(out))) > 0
}
```

**직접 자식이 하나라도 있는가**만 본다. 주석은 "foreground process" 라 부르지만
실제로는 아니다. 이름도, 어느 것이 전경인지도 모른다.

**(c) 전경 프로세스를 알려면 PTY fd 가 필요하다.** 표준 방법은 PTY 마스터에
`TIOCGPGRP`(=`tcgetpgrp`)를 걸어 전경 프로세스 그룹 id 를 얻고, 그 pgid 를 리더 pid
로 삼아 프로세스 이름을 읽는 것이다. 터미널 에뮬레이터가 탭 제목을 정하는 방식이다.

`Tool.PTMX()` 가 이미 마스터를 노출한다 (`tool.go:578`). **그러나 데몬 모드에서는
쓸 수 없다** — `seam/adapters/tool.go:116` 이 명시한다:

```go
// Daemon mode: ToolHub doesn't expose PTMX; use List for cols/rows.
```

PTY 를 소유한 것은 **데몬 프로세스**다. 따라서 이름 취득은 **데몬 안에서 수행하고
IPC 로 실어 나른다.** 웹 서버가 직접 `tcgetpgrp` 를 부를 수 있다고 가정하면 direct
모드에서만 동작하는 기능이 된다.

**(d) 백그라운드 모달은 이미 있고, 복귀만 한다.** `app-statusbar.js` 의
`_bgModalRender` 가 행을 그리며, 행 클릭은 복귀다:

```js
row.title='클릭하면 현재 분할 칸의 새 탭으로 복귀';
```

**종료하는 길이 없다.** 백그라운드 도구를 죽이려면 복귀시킨 뒤 탭을 닫아야 한다 —
두 단계다. 그리고 복귀는 화면을 바꾼다. "그냥 없애고 싶다"는 요구에 비해 비싸다.

**(e) 도구 삭제 경로는 이미 있다.** `ToolManager.Delete(id)` (`tool.go:948`)가
`background` 맵에서도 함께 제거한다 (`tool.go:952`). 종료 버튼은 **새 경로가 아니라
기존 경로에 UI 를 다는 일**이다.

### 2.2 설계 결정 — 수동 이름이 이긴다

사용자 결정(2026-08-28): **"수동 이름이 이긴다."**

근거가 둘이다.

1. **팀 역할명이 사라지면 안 된다.** `dmctl rename-tab --at <탭> "비평가"` 는
   오케스트레이션의 관전성을 지탱한다. 그 탭에서 `claude` 가 돌고 있다고 해서
   `claude` 로 덮이면 팀 전체가 `claude` 다섯 개가 된다.
2. **명시가 추론을 이긴다.** 사람이 이름을 준 것은 의도이고, 프로세스 이름은 추정이다.

따라서 탭은 **이름의 출처**를 기억해야 한다. 지금 탭에는 `name` 만 있고 그것이 기본값
`'Shell'` 인지 사용자가 준 것인지 **구분할 수 없다.** 이 구분을 새로 도입한다.

### 2.3 제약 (Constraints)

- **C-1** 전경 프로세스 조회는 **데몬 프로세스에서** 수행한다 (§2.1(c)). 두 모드에서
  동일하게 동작해야 한다.
- **C-2** 새 Go 의존을 더하지 않는다. `TIOCGPGRP` 는 표준 `syscall` 로 부른다.
- **C-3** 조회는 **핫패스가 아니다.** 이름 갱신을 위해 초당 수십 번 syscall 을 돌리지
  않는다.
- **C-4** POSIX 전제 코드가 된다. cross-platform 후속 트랙이 갈아낄 수 있도록
  **한 함수 뒤에 격리**한다 (§3.1.7).
- **C-5** 다시 그리기는 `repaint.js` 경유 (기존 여섯 자리 회귀 금지).

## 3. 요구사항 (Specific Requirements)

### 3.1 묶음 N — 전경 프로세스 기반 탭 이름 (FR-TAN-*)

#### 3.1.1 이름의 출처 구분

**FR-TAN-1** 탭에 `nameSource` 를 도입한다. 값은 둘이다.

| 값 | 의미 |
|---|---|
| `auto` (기본) | 이름이 파생 이름이거나 최초 기본값(`Shell`)이다. 자동 갱신 대상 |
| `manual` | 사용자·에이전트가 명시적으로 준 이름이다. **자동 갱신하지 않는다** |

**FR-TAN-2** 다음 경로는 `nameSource` 를 `manual` 로 만든다.

- 사이드바/탭 바에서 더블클릭 후 이름 입력
- `dmctl rename-tab --at <uuid> <이름>`
- `dmctl new-tab --name <이름>` / `dmctl new-window --name <이름>`
- 워크플로우·team 스킬이 부여하는 역할명 (위 경로를 지나므로 자동으로 만족)

**FR-TAN-3** 편집기 탭(`type==='editor'`)과 Run 대시보드 탭(`type==='run'`)은 이름이
콘텐츠에서 파생되므로 본 묶음의 대상이 아니다. `nameSource` 는 `manual` 로 고정한다.

**FR-TAN-4** 기존 워크스페이스에는 `nameSource` 가 없다. 없으면 **`auto` 로 읽는다**
— 다만 이름이 `'Shell'` 이 아니면 `manual` 로 읽는다. 사용자가 예전에 준 이름을
업그레이드가 지워버리면 안 된다.

> 이 규칙은 완전하지 않다 — 예전에 사용자가 탭 이름을 `Shell` 로 직접 지정했다면
> `auto` 로 강등된다. 그 경우 다음 갱신에서 이름이 바뀌고, 사용자는 다시 지정할 수
> 있다. 손실이 회복 가능하고 발생 확률이 낮으므로 수용한다.

#### 3.1.2 전경 프로세스 조회

**FR-TAN-5** 도구마다 전경 프로세스 이름을 조회한다. 절차는 다음과 같다.

1. PTY 마스터 fd 에 `TIOCGPGRP` → 전경 프로세스 그룹 id (`pgid`)
2. `pgid` 를 pid 로 삼아 프로세스 이름을 읽는다
   - Linux: `/proc/<pid>/comm` (즉시)
   - macOS: `ps -p <pid> -o comm=` 폴백. **이 값은 이름이 아니라 실행 경로다**
     (`/bin/zsh`). 반드시 basename 을 취한 뒤 `-` 접두를 뗀다 — 그러지 않으면
     FR-TAN-11 의 셸 판정이 통째로 빗나가 프롬프트 대기 중인 탭이 전부
     `/bin/zsh` 가 되고, 16자 절단(FR-TAN-13)이 경로 앞부분을 남긴다
     (2026-08-28 실측, WS-7)
3. 실패하면 **이름 없음**을 반환한다. 추측하지 않는다

**FR-TAN-6** 전경 pgid 가 **셸 자신의 pgid 와 같으면** 전경 프로그램이 없는 것이다
(프롬프트 대기 상태). 이 경우 이름 없음을 반환한다.

**FR-TAN-7** 조회는 **데몬 프로세스에서** 수행하고, 기존 도구 목록 IPC 응답에 필드를
실어 웹 서버로 전달한다 (C-1). direct 모드는 같은 함수를 자기 프로세스에서 부른다.

**FR-TAN-8** 조회 주기는 **2초**이며, 이름만을 위한 새 **요청**을 만들지 않는다 (C-3).

> **정정 (2026-08-28, 조정자 판정 — 최종 확정, 뒤집기 0회).** 원문은 "기존 도구 상태
> 폴링에 편승한다" 였으나 **편승할 대상이 실재하지 않는다.** 주기 폴링은
> `/api/tools/activity` 뿐이고 거기엔 도구 목록이 없으며, 그것마저 에이전트 패널이
> 열려 있을 때만 돈다. `/api/state` 는 init 1회와 `workspace_changed` 수신 시뿐이다.
> (2026-08-28 실측 2회 — 조정자·WS-7 이 독립적으로 같은 결론에 도달했다.)
>
> **서버측 2초 티커를 허용한다.** 근거는 C-3 의 문면이다 — C-3 이 금하는 것은
> **빈도**("초당 수십 번 syscall")이지 타이머의 존재가 아니다. 원문의 "새 타이머를
> 만들지 않는다 (C-3)" 는 C-3 을 과하게 읽은 것이며, 2초 티커는 C-3 이 세운 상한을
> 정확히 지킨다. V-TAN-18 의 "새 요청 0" 은 **브라우저 HTTP 요청**을 뜻하고 그것은
> 그대로 지켜진다.
>
> **`AttnTracker.StartSweeper` 에 편승하지 않는다.** 그것이 유일한 서버측 주기 루프
> 이지만 `idleThreshold > 0` 일 때만 뜬다 — 편승하면 주의 기능을 끄는 순간 탭 이름이
> **조용히 죽는다.** 무관한 두 기능을 결합시키는 대가가 티커 하나를 아끼는 이득보다
> 크다.

**FR-TAN-9** 조회 결과는 도구 단위로 캐시하고, 값이 바뀌었을 때만 SSE 로 브라우저에
알린다. 같은 값을 반복 전송하지 않는다.

#### 3.1.3 이름 파생 규칙

**FR-TAN-10** 파생 이름은 프로세스 이름을 **그대로** 쓴다. `vim`·`claude`·`node`·
`go`·`ssh`. 꾸미거나 매핑 표를 두지 않는다.

**FR-TAN-11** 다음은 **셸로 간주**하여 전경 프로그램으로 취급하지 않는다:
`sh`·`bash`·`zsh`·`fish`·`dash`·`-zsh`·`-bash` (로그인 셸의 `-` 접두 포함).

**FR-TAN-12** 전경 프로그램이 없으면 탭 이름은 **기본값 `Shell`** 로 돌아간다.
프로그램이 끝나면 이름도 돌아간다 — 이름은 **현재 상태의 표시**이지 이력이 아니다.

**FR-TAN-13** 파생 이름은 **16자**로 자른다. 사이드바 최소 폭에서 읽혀야 한다.

**FR-TAN-14** 래퍼를 벗기지 않는다. `dmctl`·`claude` 투명 래퍼가 전경에 있으면 그
이름이 나온다. 래퍼 인식은 매핑 표를 낳고, 매핑 표는 낡는다.

> **실측 완료 (2026-08-28, WS-7 · V-TAN-20). 예외는 필요 없다.** 전경 프로세스 이름은
> `claude` 로 그대로 보인다.
>
> 근거: 훅의 `claude()` 셸 함수는 `command claude … "$@"` 로 실제 바이너리를 exec 하며
> **함수 자신은 프로세스를 만들지 않는다.** 그리고 `claude` 는 Mach-O 네이티브
> 바이너리라 `ps comm` 이 `claude` 를 그대로 낸다 (node 셸 래퍼가 아니다). 살아 있는
> 프로세스 트리에서 셸 pgid ≠ 전경 pgid 이고 전경 pgid 의 리더가 `claude` 임을
> 확인했다 — FR-TAN-6 도 올바르게 "전경 있음"을 낸다.
>
> 같은 실측이 FR-TAN-5 의 macOS 주석도 재확인했다 — 셸의 `comm` 은 `/bin/zsh` 로
> **경로**가 나오므로 basename 과 `-` 접두 제거가 필수다.

#### 3.1.4 적용

**FR-TAN-15** `nameSource === 'auto'` 인 탭만 파생 이름을 받는다. `manual` 은 어떤
경우에도 덮이지 않는다 (§2.2).

**FR-TAN-16** 이름 변경은 **워크스페이스 영속에 쓰지 않는다.** 파생 이름은 휘발성
표시이며, `workspace.json` 에 저장되는 것은 `nameSource` 와 **사용자가 준 이름**뿐이다.

> 근거: 파생 이름을 저장하면 서버 재시작 후 죽은 프로세스의 이름이 남는다. 그리고
> 이름이 2초마다 바뀌는 값이면 워크스페이스 쓰기가 폭증한다.

**FR-TAN-17** 파생 이름이 보이는 자리는 **탭 바**이며, 그것을 내는 모든 표면이 같은
값을 보여야 한다.

> **정정 (2026-08-28, 조정자 판정 — 최종 확정, 뒤집기 0회).** 원문은 "탭 바와 사이드바
> 창 목록" 이었으나 **사이드바는 탭 이름을 내지 않는다.** `renderer.js:_siEl` 이 그리는
> 것은 창 이름(`s.name`)뿐이고, 탭 이름이 보이는 자리는 pane 탭 바 하나다 (실측).
>
> 사이드바에 활성 탭 이름을 **새로** 붙이는 것은 요구되지 않은 UI 추가이므로 하지
> 않는다. 이 요구의 실질은 "표시 자리가 여럿이면 일관돼야 한다" 이고, 실재하는 짝은
> **탭 바 ↔ `dmctl list-workspace`**(FR-TAN-18)다. **V-TAN-15 는 그 짝으로 읽는다.**

**FR-TAN-18** `dmctl list-workspace` 의 `tab="..."` 컬럼은 **표시되는 이름**을 낸다.
에이전트가 화면과 다른 것을 보면 안 된다.

#### 3.1.5 사용자 제어

**FR-TAN-19** 이 기능은 **설정으로 끌 수 있다** — Settings ▸ Display 에 `프로세스
이름을 탭 이름으로` 체크박스. 기본값은 **켬**.

**FR-TAN-20** 끄면 모든 탭이 즉시 `Shell`(또는 수동 이름)로 돌아간다. 켜면 다음
조회에서 다시 파생된다.

#### 3.1.6 이름 되돌리기

**FR-TAN-21** `manual` 탭을 다시 자동으로 돌리는 길을 둔다 — 이름 편집에서 **빈
문자열을 넣으면** `nameSource` 가 `auto` 로 돌아간다. 현재 빈 이름은 거부되므로
동작이 비어 있고, 여기에 의미를 준다.

**FR-TAN-22** `dmctl rename-tab --at <uuid> --auto` — 같은 일을 에이전트가 한다.

#### 3.1.7 이식 경계

**FR-TAN-23** 전경 프로세스 조회는 **단일 함수 뒤에 격리**한다.

```go
// foregroundName reports the name of the tool's foreground process, or "" when
// there is none (shell at prompt) or it cannot be determined.
func foregroundName(ptmx *os.File, shellPid int) string
```

**FR-TAN-24** 이 함수는 POSIX 전용 파일(`_unix.go` 등 build tag)에 둔다. 미지원
플랫폼의 스텁은 `""` 를 반환하며, 기능은 조용히 비활성된다 — **오류를 내지 않는다.**
cross-platform 후속 트랙이 이 자리 하나만 채우면 된다 (C-4).

> `sysstat` 이 이미 `reader_darwin.go`/`reader_other.go` 로 같은 패턴을 쓴다. 그
> 관례를 따른다.

### 3.2 묶음 X — 백그라운드 도구 즉시 종료 (FR-BGK-*)

**FR-BGK-1** 백그라운드 도구 모달의 각 행에 **종료 버튼**을 둔다. 행 클릭(복귀)과
별개의 목표여야 한다 — 클릭이 겹치면 복귀하려다 죽인다.

**FR-BGK-2** 종료 버튼은 **항상 보인다.** hover 게이팅하지 않는다. 이는 기존 규약
이다 — git 리포 행에서 hover 게이팅을 걷어낸 결정(`GIT_REMAINING.md` §1.2 I4 주변)과
같은 이유이며, hover 는 터치 기기에서 존재하지 않는다.

**FR-BGK-3** 종료는 **확인을 요구한다.** 백그라운드 도구는 화면에 없어 무엇을 잃는지
보이지 않으므로, 되돌릴 수 없는 동작에 확인을 붙인다.

**FR-BGK-4** 확인은 **모달 위의 모달을 띄우지 않는다.** 행 안에서 `종료?` `[예]
[아니오]` 로 바뀌는 인라인 확인을 쓴다. 중첩 모달은 Escape 처리와 포커스 관리를
복잡하게 만든다.

**FR-BGK-5** 인라인 확인은 다른 행을 건드리거나 모달 밖을 클릭하면 **취소**된다.

**FR-BGK-6** 종료는 `POST /api/tools/kill` (신설) 또는 기존 도구 삭제 종단을 쓴다.
서버는 `ToolManager.Delete(id)` 를 부르며, 그 함수가 `background` 맵에서도 제거한다
(§2.1(e)).

**FR-BGK-7** 종료는 **SIGTERM 후 유예, 그 다음 SIGKILL** 이다. `tool.go:644` 가 이미
SIGTERM 경로를 갖고 있다. 유예는 3초.

**FR-BGK-8** 종료 후 모달은 그 행만 제거하고 **열린 채로 남는다.** 여러 개를 정리하는
것이 이 화면의 목적이다.

**FR-BGK-9** 마지막 도구를 종료하면 모달은 "없음" 을 표시하고, 상태바 배지는 사라진다
(`FR-BGU-5` 보존).

**FR-BGK-10** 종료 실패 시 행은 남고 오류를 인라인으로 표시한다. 모달을 닫지 않는다.

**FR-BGK-11** **전체 종료 버튼은 두지 않는다.** 한 번의 오조작으로 전부 잃는 동작을
만들지 않는다.

**FR-BGK-12** Run 의 헤드리스 멤버가 백그라운드 목록에 나타나는 경우, 행에 **소속
Run 을 표시**한다 (`ORCHESTRATION_V2_SRS` 묶음 H 연계). 종료는 여전히 가능하되,
확인 문구가 그 사실을 알린다 — "이 도구는 Run `<short>` 의 멤버 `<역할>` 이다".

> 묶음 H 가 아직 없으면 이 요구는 무동작이다. 두 트랙의 유일한 접점이며, 순서 의존이
> 아니다 (H 가 나중에 와도 표시가 늘 뿐이다).

## 5. 비기능 요구사항

**NFR-CNV-1 (부하).** 전경 프로세스 조회가 도구 100개에서 폴링 주기(2초) 안에 끝난다.
`/proc` 읽기는 즉시이고, macOS `ps` 폴백은 **한 번의 호출로 전부** 조회한다 —
도구마다 프로세스를 띄우지 않는다.

**NFR-CNV-2 (요청 증가 없음).** 이름 기능이 새 HTTP 요청·새 타이머를 만들지 않는다.

**NFR-CNV-3 (영속 무오염).** 파생 이름이 `workspace.json` 에 저장되지 않는다.

**NFR-CNV-4 (이름 보존).** 어떤 경로로도 수동 이름이 자동으로 덮이지 않는다. 이를
고정하는 테스트를 둔다.

**NFR-CNV-5 (이식 격리).** POSIX 의존이 `foregroundName` 한 함수와 그 build tag 파일
안에만 있다.

**NFR-CNV-6 (재렌더 안전).** 이름 갱신·모달 갱신이 진행 중인 이름 편집·드래그·선택을
깨지 않는다 (C-5).

**NFR-CNV-7 (되돌릴 수 없는 동작).** 도구 종료는 확인 없이 일어나지 않는다.

## 6. 비목표 (Non-Goals)

- **`--expose` 접근 제어** — 독립 후속 트랙 (사용자 결정)
- **cross-platform 이식** — 독립 후속 트랙 (사용자 결정). 본 SRS 는 이식 지점을
  격리해 **두는 것**까지만 한다 (FR-TAN-23/24)
- **프로세스 이름 매핑 표** — `node` 를 `Node.js` 로 예쁘게 바꾸지 않는다 (FR-TAN-10)
- **래퍼 벗기기** — FR-TAN-14
- **창 이름의 자동 파생** — 탭만 대상
- **프로세스 인자까지 표시** (`vim foo.go`) — 이름만. 인자는 길고 폭이 없다
- **파생 이름의 영속** — FR-TAN-16
- **백그라운드 도구 전체 종료** — FR-BGK-11
- **종료 취소(undo)** — 프로세스는 되살릴 수 없다. 확인이 그 자리를 대신한다

## 8. 구현 순서

```
묶음 X (백그라운드 종료)  — 독립. 프론트 + 얇은 종단. 먼저 끝난다
   └ 1. POST /api/tools/kill
     2. 모달 행 버튼 + 인라인 확인
     3. Run 소속 표시 (묶음 H 도착 후 또는 무동작)

묶음 N (탭 이름)          — 데몬 경로가 있어 더 길다
   └ 1. foregroundName() + build tag 격리 + 유닛 테스트
     2. 데몬 IPC 필드 + 웹서버 전달 (두 모드 동일 확인)
     3. nameSource 도입 + 구 workspace 추론
     4. 프론트 적용 (탭 바·사이드바·list-workspace)
     5. 설정 토글 + 되돌리기(--auto·빈 문자열)
     6. 실측: claude 래퍼의 전경 이름 (V-TAN-20)
```

두 묶음은 **서로 독립**이다. 병렬로 진행해도 충돌하지 않는다 — 묶음 X 는
`app-statusbar.js`, 묶음 N 은 `toolhub`·`renderer.js`·`app-layout.js` 를 만진다.
