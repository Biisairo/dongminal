  - Go 와 다르게 한 내부 결정:
    ① 개발 빌드(`version == "dev"`)의 헬퍼 교차 빌드는 `go build` 대신 `cargo build --release -p dongminal --target <arch>-unknown-linux-gnu` 다(Rust 바이너리를 넣어야 하므로). 실패 문구의 안내 줄(`GOOS=linux … go build …`)은 Go 와 바이트가 같게 두었다 — 8.x 에서 Rust 안내로 바꿀지 사용자 결정 필요.
    ② `ParseConfig` 는 Go map 순회(무작위) 대신 키 이름순으로 본다. 오류가 둘 이상인 입력에서 어느 오류가 먼저 나오는지만 다를 수 있다(Go 도 매번 다르다).
    ③ `HomeFn`(`Fn() -> Option<String>`)·`stat`(`Fn(&str) -> bool`) 은 Go 의 `(string, error)`·`error` 를 필요한 만큼으로 줄였다(오류 내용을 쓰는 자리가 없다).
    ④ 헬퍼 내려받기는 reqwest 를 전용 스레드의 current-thread 런타임에서 돌린다(Go 동기 호출과 같은 모양, FR-RSP-36). 임시 파일 이름은 `.dmctl-<pid>` 다(Go `CreateTemp` 의 무작위 꼬리).
    ⑤ `LoadProfiles` 는 홈 함수를 인자로 받는다(Go 는 `os.UserHomeDir` 고정).
  - 남은 위험: windows·linux 교차 clippy 는 reqwest→ring 의 C 교차 컴파일러가 없어 못 했다(2.3·2.6 과 같은 이유, 8.3). OS 분기는 exec 의 unix 신호 이름, 디렉터리 권한(0700·0755) 정도다. 헬퍼 HTTP 오류 문구(`응답 404 Not Found`, `Get "url": …`)는 실측하지 않았다.
  - 게이트: fmt, clippy(macOS), 격리 cargo test(sandbox 22 + sandboxplace 7) 통과.
