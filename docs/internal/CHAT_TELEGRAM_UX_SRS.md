# SRS: 채팅·텔레그램 사용성 묶음 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 다섯 줄이다. 위에서부터 차례로 진행한다.

> 1. 채팅방에서 다른 것을 하다가 다시 오면 읽던 곳에서 스크롤을 시작한다.
> 2. 채팅방 글이 md 렌더를 지원한다. 에이전트가 채팅할 때 md 로 보내게 해서 가독성을 챙긴다.
> 3. 텔레그램에서 방 만들기, 접속한 이용자 보기, 개인채팅 보내기.
> 4. 텔레그램 켜기 / 알람만 끄고 켜기 설정을 나눈다.
> 5. 토픽을 만들 때 고정 메시지를 하지 않는다.
>
> 추가 접수(같은 날):
>
> 6. 채팅방 글씨 크기 설정을 더한다.
> 7. 글 입력칸의 높이가 내용에 따라 늘고 준다. 화면의 반을 가릴 때까지 늘어난다.
> 8. 텔레그램 토픽에서 그 방에 들어와 있는 참가자 목록을 본다.

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 채팅 뷰는 가려지면 문서에서 떨어진다

- `renderer-pane.js` `_hideOthers` 는 보이지 않는 탭 본문을 `remove()` 한다. 다시 보일 때 `appendChild` 로 붙인다.
- 떨어졌다 다시 붙은 요소의 `scrollTop` 은 0 이다.
- 편집기·Doc·Diff 는 `keepView`/`restoreView`, 터미널은 `_keepTermScroll`/`_restoreScrollOf` 로 자리를 지킨다. 채팅 뷰에는 그런 장치가 없다.

### 2.2 그래서 지금은 돌아오면 맨 위가 보인다

- `chatViewEl` 은 뷰를 붙이기 **전에** `_chatViewPaint` 를 부른다. 떨어진 요소는 `scrollHeight`·`clientHeight` 가 0 이라 맨 아래로 보내는 대입도 효과가 없다.
- 결과: 채팅 탭으로 돌아오면 대화칸이 맨 위(가장 오래된 글)에 있다. 처음 여는 탭도 같다.

### 2.3 뷰는 탭보다 오래 살지 않는다

- 탭을 닫으면 `_chatViewsPaint` 가 뷰를 거둔다. 뷰에 자리를 두면 탭을 닫을 때 사라진다.
- 대화는 `ChatStore` 에 방마다 있다. 새로고침하면 대화도 사라진다 (FR-PCH-85).

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 R — 읽던 자리

- **FR-CTU-1** 읽던 자리는 **방마다** `ChatStore` 에 둔다. 탭을 닫고 같은 방을 다시 열어도 남는다 (D-CTU-2).
- **FR-CTU-2** 읽던 자리는 렌더러가 탭 본문을 떼기 전의 공통 시점(`_keepScrollAll`)에 적는다. 문서에 붙어 보이는(`isConnected` + `.vis`) 뷰만 적는다.
- **FR-CTU-3** 읽던 자리는 픽셀이 아니라 **글**로 적는다: 대화칸 맨 위에 걸친 글(아래변이 대화칸 윗변보다 아래인 첫 글)과 그 글 안의 거리.
- **FR-CTU-4** 뷰가 붙은 뒤(`_mountTabBody` 에서 이동한 경우) 읽던 자리로 되돌린다. 적힌 글이 대화칸 맨 위에 오고, 적힌 거리만큼 더 내려간다.
- **FR-CTU-5** 떠날 때 맨 아래였고 그 사이 새 글이 왔어도 FR-CTU-4 를 따른다. 읽던 글이 그대로 보이고 새 글은 그 아래에 있다 (D-CTU-1).
- **FR-CTU-6** 읽던 자리가 없으면(그 방을 처음 연다) 맨 아래에서 시작한다.
- **FR-CTU-7** 적힌 글이 방별 상한(`CHAT_KEEP`)으로 버려졌으면 맨 위에서 시작한다. 읽던 글보다 뒤의 글 가운데 남은 가장 오래된 글이다.
- **FR-CTU-8** 방금 붙은 요소에 크기가 없어 대입이 잘리면 다음 프레임에 한 번 더 놓는다 (`doc-render.js` `restoreView` 와 같은 규약).
- **FR-CTU-9** 탭이 보이는 동안의 동작은 바꾸지 않는다: 맨 아래에 있으면 새 글을 따라 내려가고, 위를 읽고 있으면 그대로 둔다.

### 3.2 묶음 M — 마크다운 안내

조사로 확정한 사실:

- 채팅 화면은 글 본문을 마크다운으로 그린다(`web/js/core/chat-md.js`, ISSUE_TREE_CHAT_SRS FR-CUX-8).
- 텔레그램은 채팅 글의 마크다운을 Telegram HTML 로 옮긴다(`render.rs` `chat_md_html`, FR-TGT-7). 제목·목록·인용·굵게·인라인 코드·코드 블록을 옮기고, 표는 행마다 한 줄로 푼다.
- 에이전트는 이 사실을 모른다. 채팅 MCP 의 안내(`CHAT_INSTRUCTIONS`)와 `chat_send` 설명에 형식 이야기가 없다.

- **FR-CTU-10** 채팅 MCP 의 안내(`CHAT_INSTRUCTIONS`)에 "글은 Markdown 으로 쓴다" 는 줄을 둔다. 줄은 쓸 수 있는 문법(제목·목록·굵게·인라인 코드·코드 블록)과, 원시 HTML 은 글자로 나온다는 것을 말한다.
- **FR-CTU-11** `chat_send` 의 설명과 `text` 인자 설명도 Markdown 이라고 말한다.
- **FR-CTU-12** 화면·텔레그램의 그리기는 바꾸지 않는다.

### 3.3 묶음 T — 텔레그램 메뉴

조사로 확정한 사실:

- 봇은 일반 대화(토픽 밖)에서 `/pair` 만 받는다. 그 밖의 글에는 "이 봇은 알림만 보냅니다." 라고 답한다 (`bridge.rs` `on_message`).
- 데몬에는 방 만들기(`create`), 개인채팅 열기(`direct`), 접속자(`online`) 연산이 있다. 텔레그램 `Host` 에는 `chat_view`·`chat_join`·`chat_send` 만 있다.
- 방이 생기면 거울이 그 방의 토픽을 만든다 (ISSUE_TREE_CHAT_SRS FR-TGT-3).

요구:

- **FR-CTU-20** 이 묶음은 채팅 토픽이 켜져 있을 때(`topics_active`)만 있다. 꺼져 있으면 일반 대화의 동작은 지금과 같다.
- **FR-CTU-21** 허용 계정이 일반 대화에 메뉴 단추가 아닌 글을 쓰고 진행 중인 입력이 없으면, 봇은 안내 글과 함께 늘 보이는 키보드(reply keyboard)를 보낸다. 단추는 `방 만들기`·`접속자` 둘이다. 짝맞춤이 끝났을 때도 같은 키보드를 단다.
- **FR-CTU-22** `방 만들기` 를 누르면 봇이 방 이름을 묻는다(force_reply). 다음 글이 이름이다. 이어서 목적을 묻고, 그 글에 `[건너뛰기]` 단추(inline)를 단다. 다음 글이 목적이다. `[건너뛰기]` 는 목적을 비운다.
- **FR-CTU-23** 이름과 목적을 받으면 사람 참가자로 방을 만든다(`create`). 성공하면 "방을 만들었다, 토픽에서 대화하라" 고 답하고 거울 맞추기를 넣는다. 실패하면 실패와 오류 코드를 답한다.
- **FR-CTU-24** 진행 중인 입력은 하나다. 마지막 물음에서 `MENU_PENDING_TTL`(10분)이 지나면 버린다. 메뉴 단추를 누르면 진행 중인 입력을 버리고 그 단추를 처리한다. 서버를 다시 시작하면 사라진다.
- **FR-CTU-25** `접속자` 를 누르면 지금 접속한 참가자(나 제외)를 노드별로 보낸다. 행은 표시 이름(FR-CUX-9)과 종류(사람·에이전트)다. 참가자마다 inline 단추 `[개인채팅: <이름>]` 을 단다. 단추는 `MENU_WHO_MAX`(50)개까지다. 없으면 "접속한 참가자가 없습니다." 라고 답한다.
- **FR-CTU-26** 개인채팅 단추를 누르면 그 참가자와의 개인채팅을 연다(`direct`). 성공하면 버튼에 "개인채팅을 열었습니다" 로 답하고 거울 맞추기를 넣는다. 단추의 목록이 마지막으로 보낸 목록이 아니면 "목록이 바뀌었습니다. 다시 [접속자] 를 누르세요." 로 답하고 아무것도 하지 않는다.
- **FR-CTU-27** 허용 계정이 아닌 글·단추는 지금처럼 무시한다 (FR-TGB-12·13).
- **FR-CTU-28** 밖으로 나가는 데이터 목록(`TELEGRAM_BRIDGE_SRS` §8)에 접속자의 표시 이름·종류·노드 이름을 더한다.

동작 변경: 토픽이 켜져 있을 때 일반 대화의 글에 대한 답이 "이 봇은 알림만 보냅니다." 에서 메뉴 안내와 키보드로 바뀐다. 모르는 토픽의 글과 토픽이 꺼진 때의 답은 그대로다.

### 3.4 묶음 N — 텔레그램 켜기와 알림 나누기

조사로 확정한 사실:

- 설정 ▸ Telegram 의 스위치 하나(`enabled`, 이름 "Telegram 알림")가 에이전트 알림·메시지 받기·채팅 토픽을 함께 켜고 끈다.
- 에이전트 알림은 작업자 큐의 `Item::Attention` 을 `alarm` 이 보낸다 (`bridge.rs` `process`).

요구:

- **FR-CTU-30** `telegram.json` 에 `alarmsOff` 를 더한다. 기본은 거짓이고, 거짓이면 파일에 싣지 않는다(옛 파일 형식 그대로).
- **FR-CTU-31** `alarmsOff` 가 참이면 에이전트 알림(`Item::Attention`)을 보내지 않는다. 메시지 받기·짝맞춤·채팅 토픽·메뉴·안내 글(`Item::Notice`)은 그대로다.
- **FR-CTU-32** `PUT /api/telegram/alarms` `{"alarms": bool}` 가 값을 바꾼다. 전제는 없다(Telegram 이 꺼져 있어도 저장한다). 화면 값(`GET /api/telegram`)은 `alarmsOff` 가 참일 때만 싣는다.
- **FR-CTU-33** 설정 ▸ Telegram 의 첫 스위치 이름을 "Telegram 사용" 으로 바꾸고, 그 아래에 "에이전트 알림" 스위치를 둔다. 켜져 있으면 알림을 보낸다.

동작 변경: 첫 스위치의 이름만 바뀐다. 동작은 같다(끄면 Telegram 전체가 꺼진다).

### 3.5 묶음 P — 토픽 안내 글을 고정하지 않는다

조사로 확정한 사실:

- 토픽을 만들면 안내 글(목적·참가자 수·`[들어가기]`/`[나가기]`)을 올리고 `pinChatMessage` 로 고정한다 (`mirror.rs` `post_pin`, ISSUE_TREE_CHAT_SRS FR-TGT-5).
- 사용자는 Telegram 의 토픽 사이드바로 토픽을 보므로 고정이 필요 없다고 했다.

- **FR-CTU-40** 안내 글은 토픽의 첫 글로 올리되 고정하지 않는다(`pinChatMessage` 를 부르지 않는다). 글의 내용·단추·고치기는 그대로다.
- **FR-CTU-41** ISSUE_TREE_CHAT_SRS FR-TGT-5 의 "고정" 을 이 요구로 고친다. 짝 파일의 `pinId`·`pinText` 이름은 저장 형식이므로 그대로 둔다.

동작 변경: 이전에는 토픽을 만들 때 안내 글을 고정해 "봇이 메시지를 고정했습니다" 알림과 고정 띠가 생겼다. 이제 고정하지 않는다. 이유: 토픽은 사이드바에 보이므로 고정이 쓸모없고 알림만 남긴다.

### 3.6 묶음 F — 채팅 글자 크기

조사로 확정한 사실:

- 글자 크기 토큰 다섯(`--fs-xs`~`--fs-xl`)은 `:root` 에서 `--fs-scale` 을 곱해 정한다. `--fs-scale` 은 `uiFontSize / UI_FONT_BASE_PX`(14)다 (FONT_SIZE_SETTING_SRS).
- 채팅 화면(`.chat-view`)의 글자는 모두 이 토큰을 쓴다. 동그라미 크기는 `--chat-avatar`·`--chat-avatar-sm`(px)이다.
- 커스텀 프로퍼티의 `var()` 는 선언한 요소에서 계산되므로, `.chat-view` 에서 토큰을 다시 선언해야 그 안의 배율이 바뀐다.

요구:

- **FR-CTU-50** 설정 블롭에 `chatFontSize`(int, px, 8~32, 기본 14)를 더한다. 자리는 Display ▸ 채팅 글자 크기다. 다른 글자 크기 키와 같이 서버에 저장한다.
- **FR-CTU-51** 설정 ▸ Display 의 `UI 글자 크기` 아래에 숫자 칸(`ds-chatfs`)을 둔다. 입력 중에는 덮지 않고(가드), 확정하면 곧바로 화면에 얹는다.
- **FR-CTU-52** 채팅 화면 전체가 `chatFontSize / UI_FONT_BASE_PX` 배율을 쓴다: `.chat-view` 안에서 다섯 토큰과 동그라미 크기를 그 배율로 다시 정한다. 값은 `:root` 의 `--chat-fs-scale` 로 건넨다.
- **FR-CTU-53** 채팅 화면의 글자는 UI 글자 크기를 따르지 않는다. 기본 14 는 UI 글자 크기가 기본(14)일 때의 지금 화면과 같다.

동작 변경: UI 글자 크기를 14 가 아닌 값으로 둔 사용자는, 채팅 화면이 UI 글자 크기 대신 채팅 글자 크기(기본 14)를 따른다. 이유: 채팅 글자를 따로 정하라는 요구다.

### 3.7 묶음 H — 입력칸 높이

조사로 확정한 사실:

- 입력칸(`.chat-input`)은 `rows=2`, `min-height:36px`, `resize:vertical` 이다. 내용이 길어도 높이가 그대로이고 안에서 스크롤한다.

요구:

- **FR-CTU-60** 입력칸의 높이는 내용에 맞춰 늘고 준다. 아래 한계는 지금의 높이(CSS `min-height` 와 두 줄)이고, 위 한계는 그 채팅 탭(`.chat-view`) 높이의 반이다.
- **FR-CTU-61** 위 한계를 넘는 내용은 입력칸 안에서 스크롤한다. 한계 아래에서는 스크롤 막대를 두지 않는다.
- **FR-CTU-62** 높이는 글을 칠 때, 그리고 코드가 입력칸 값을 바꿀 때(보낸 뒤 비우기, `@` 고르기, 답장) 다시 잰다.

### 3.8 묶음 V — 토픽의 참가자 목록

조사로 확정한 사실:

- 토픽 안내 글의 단추는 `[들어가기]` 또는 `[나가기]` 하나다 (`mirror.rs` `pin_keyboard`).
- 브리지가 읽는 방 보기(`ChatRoom.people`)에는 참가자의 id 와 표시 이름만 있다. 사람인지는 없다. 서버는 데몬의 `kind` 를 안다.

요구:

- **FR-CTU-70** 안내 글의 단추 줄에 `[참가자]` 를 더한다. 새로 올리는 안내 글과, 내용이 바뀌어 고치는 안내 글에 달린다.
- **FR-CTU-71** `[참가자]` 를 누르면 그 토픽에 방의 참가자 목록을 보낸다(소리 없이). 머리는 `참가자 N명`, 행은 `• <표시 이름> · <사람|에이전트>` 이고 나는 이름 뒤에 `(나)` 를 붙인다. 차례는 내 노드 먼저, 그 안에서 사람 먼저, 이름 차례다. 목록은 누른 순간의 방 보기다.
- **FR-CTU-72** 방 보기를 읽지 못하거나 그 토픽의 방을 모르면 단추에 실패로 답하고 글을 보내지 않는다.
- **FR-CTU-73** 방 보기의 참가자에 사람인지(`human`)를 더한다. 서버는 데몬 참가자의 `kind` 가 `user` 이면 참으로 옮긴다.
- **FR-CTU-74** 밖으로 나가는 데이터 목록(`TELEGRAM_BRIDGE_SRS` §8)에 방 참가자의 종류를 더한다.

동작 변경: 안내 글 단추가 하나에서 둘이 된다. 이미 올린 안내 글은 다음에 내용(참가자 수·들어가 있는지 등)이 바뀌어 고칠 때 새 단추를 받는다.

## 5. 확정 결정 (Decisions)

- **D-CTU-1 돌아오면 읽던 글 그대로 둔다.** 맨 아래에서 떠났어도 새 글 끝으로 뛰지 않는다. 사용자가 고른 답이다. 떠난 사이의 글을 건너뛰지 않는다.
- **D-CTU-2 방 단위로 기억한다.** 사용자가 고른 답이다. 뷰는 탭과 함께 사라지므로(§2.3) 자리는 `ChatStore` 에 둔다.
- **D-CTU-3 자리는 글로 적는다.** 픽셀은 새 글·폭 변화·글 버림에 흔들린다. 글과 그 안의 거리는 그 사이의 변화에 영향을 받지 않는다.
- **D-CTU-5 형식 안내는 MCP 안내와 `chat_send` 설명 두 곳에 둔다.** 안내는 연결할 때 한 번 읽히고, 도구 설명은 글을 쓰는 그 순간 보인다. 화면·텔레그램이 이미 그리므로 안내만 더한다.
- **D-CTU-6 텔레그램 기능은 늘 보이는 키보드의 단추로 쓴다.** 사용자가 고른 답이다(명령 없이 메뉴 단추만, 늘 보이는 키보드). 글을 받아야 하는 단계는 봇이 물은 뒤의 다음 글로 받는다.
- **D-CTU-7 개인채팅은 접속자 목록의 행 단추로 연다.** 사용자가 고른 답이다. 사람과 에이전트 모두 대상이다.
- **D-CTU-8 방 만들기는 이름 → 목적 차례로 묻는다.** 사용자가 고른 답이다. 목적은 `[건너뛰기]` 로 비울 수 있다.
- **D-CTU-9 알림을 끄면 에이전트 알림만 보내지 않는다.** 사용자가 고른 답이다. 소리만 끄는 방식은 고르지 않았다.
- **D-CTU-10 값은 꺼짐을 적는다(`alarmsOff`).** 기본(켬)을 파일에 싣지 않아 옛 파일과 골든이 그대로다. `chatTopics` 와 같은 규약이다.
- **D-CTU-11 안내 글은 남기고 고정만 뺀다.** 사용자는 "사이드바에 보이니 고정이 없어도 된다" 고 했다. 안내 글에는 `[들어가기]`/`[나가기]` 단추가 있으므로 글은 남긴다.
- **D-CTU-12 채팅 글자 크기는 채팅 화면 전체에 걸고, 설정 ▸ Display 에 둔다.** 사용자가 고른 답이다.
- **D-CTU-13 배율은 `.chat-view` 에서 토큰을 다시 선언해 건다.** `zoom` 은 스크롤·상자 좌표를 바꿔 읽던 자리(묶음 R) 계산을 흔든다.
- **D-CTU-14 입력칸의 위 한계는 채팅 탭 높이의 반이다.** 사용자가 고른 답이다. 칸을 나눈 작은 탭에서도 대화가 반은 보인다.
- **D-CTU-15 토픽의 참가자 목록은 안내 글의 단추로 본다.** 사용자가 고른 답이다. 누른 순간의 목록이라 낡지 않는다.
- **D-CTU-4 적는 시점은 `_keepScrollAll` 하나다.** 떼는 자리가 셋이므로 각 자리에 훅을 걸지 않는다 (FR-VSR-2 의 규약).

2. "새 글 N개" 표시나 첫 안 읽은 글 구분선.
