# 1.4.2 platform 뼈대·파일·경로

## 목표

platform crate 의 lib.rs(모든 모듈 선언과 Platform 구조체 필드 전부, current())를 먼저 세워 1.4.3~1.4.6 이 각자 모듈만 고치게 한다. 그리고 OS 종류·경로·원자적 쓰기·상태 파일 세대·파일 락·디렉터리 fsync·junction·크래시 마커를 옮긴다. testdata/file_uri_vectors.json 벡터를 그대로 쓴다. 공개 API 는 부모 이슈 1.4 의 진행 기록 "공개 API 안" 을 따른다. 바꿔야 하면 조정자에게 먼저 알린다.

## 대상 Go 코드

- `internal/shared/platform/platform*.go`, `oskind.go`, `paths.go`, `statefile.go`, `filelock*.go`, `dirsync_*.go`, `junction_*.go`, `lastexit.go` (약 1000줄)

## 완료 조건

- 대상 Go 코드의 관측 동작을 Rust 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

    - `lib.rs` 는 모든 모듈 선언·재수출과 `Platform` 필드 전부를 갖는다. 하위 이슈는 `lib.rs` 를 고치지 않는다.

    - `Pending` 은 실패를 "모름" 으로 낸다. 오류는 Unsupported, alive 는 true, 조회는 빈 값/None 이다.
    - 모듈과 이슈의 대응: shell.rs·browser.rs·secrets.rs 는 1.4.3, process.rs·procinfo.rs 는 1.4.4, ipc.rs 는 1.4.5, pty.rs·handover.rs 는 1.4.6 이다.
    - secrets 는 linux·windows 용 `NoSecrets` 를 이미 구현했다. darwin 키체인만 1.4.3 이 채운다.
  - **공개 API**: `Platform { os, process, info, pty, shell, ipc, paths, browser, opener, secrets }`(필드는 `&'static dyn Trait`), `current() -> &'static Platform`, `OsKind::{Darwin, Linux, Wsl, Windows}`(`as_str`·Display), `build_target()`(Go `GOOS/GOARCH` 이름), `Paths { default_log_file, exe_suffix, file_uri(&str), path_from_file_uri(&str) -> io::Result<String>, is_executable(&Path), link_or_copy }`, `write_file_atomic(&Path, &[u8], perm: u32)`, `write_file_if_changed`, `copy_executable`, `write_state_file`, `STATE_FILE_GENERATIONS`, `RETAIN_QUARANTINED`, `lock_file(&Path, Duration) -> Result<FileLock, LockError>`(`FileLock` 은 drop 하면 놓는다, `LockError::Timeout` 의 문구는 "락을 잡지 못했습니다"), `junction(target, link)`, `LAST_EXIT_FILE`, `LastExit { crashed, first, raw }`, `read_last_exit/mark_running/mark_clean_exit(&Path)`. trait 시그니처(`Process`·`Group`·`ProcInfo`·`Pty`·`Terminal`·`Handover`·`Frozen`·`is_frozen`·`Ipc`·`IpcListener`·`IpcStream`·`SOCKET_FILE_NAME`·`sibling_socket`·`ShellProvider`·`ShellSpec`·훅 상수·`Browser`·`Opener`·`Secrets`·`SecretsError`)는 각 모듈 파일에 있다.
  - **테스트**: 61개 통과. Go 의 paths·atomic·link·ifchanged·dirsync·statefile·filelock·lastexit·oskind 테스트를 옮겼다. 다음 두 가지는 go1.27.2 로 직접 돌려 얻은 값과 대조했다: `file_uri_vectors.json`(Go testdata 를 include_str 로 그대로 읽는다), `url.URL.String()`·`url.Parse` 의 경계값.
  - **게이트**: fmt·clippy(-D warnings) 를 aarch64-darwin·x86_64-darwin·x86_64/aarch64-linux·x86_64-windows-msvc 에서 모두 통과했다. 격리 테스트도 통과했다.
  - **Go 와 다르게 한 내부 결정**
    1. `Terminal` 의 메서드는 모두 `&self` 다(`Send + Sync`). Go 처럼 읽기·쓰기·크기 조절이 서로 다른 스레드에서 일어나기 때문이다.
    2. pid 타입은 `i32` 다.
    3. 파일 락은 std `File::try_lock` 을 쓴다(unix flock, Windows LockFileEx). Windows 에서 Go 는 1바이트만 잠그고 Rust 는 전 범위를 잠근다. 두 범위가 겹치므로 Go 판과 Rust 판이 서로를 막는다.
    4. `StateFileGenerations` 는 Go 에서는 var 였지만 상수로 바꿨다. 외부에서 값을 바꾸는 곳이 없다. 세대 수는 테스트에서만 내부 매개변수로 바꾼다.
    5. 크래시 마커의 `raw` 는 UTF-8 이 아닌 바이트를 lossy 로 읽는다.
  - **남은 위험**
    1. **FR-RSP-35 대기:** Go 형식 파일 오류(`open /x: no such file or directory`)는 내부 `goerr::{path_err, link_err}` 가 임시로 만든다. unix 는 std 문구의 첫 글자를 낮춰 Go 문구에 가깝게 만든다. 하지만 errno 문구가 libc 와 Go 표에서 다른 경우는 다르게 나온다. gocompat 이 공개되면 그 두 함수만 바꾼다.
    2. Go 는 `f.Close()` 오류를 검사하지만, Rust 는 drop 할 때 닫으므로 close 오류를 놓친다.
    3. `path_from_file_uri` 는 Go url.Parse 의 호스트 검증을 하지 않는다. 운영 코드에서 쓰는 곳이 없어 관측되지 않는다.
    4. Go 는 UTF-8 이 아닌 경로를 바이트 그대로 돌려주지만, Rust 는 오류로 돌려준다.
