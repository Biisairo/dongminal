### Go 와 다르게 한 내부 결정
- multipart 를 직접 옮겼다(`multipart.rs`·`mediatype.rs`, 허용 목록에 multipart crate 가 없다). go1.27.2 `mime/multipart`·`net/http` 의 판정 순서·상한(부분 1000·헤더 10000·메모리 32MiB+10MiB·`peekBufferSize` 4096·경계 `matchAfterPrefix`)과 `FormValue` 의 쿼리 우선을 따랐다. 관측은 성공·413·400 세 갈래다. 파일은 32MiB 까지 메모리, 넘으면 `$TMPDIR/multipart-*` 임시 파일이고 응답 뒤에 지운다.
- 패키지 변수 `fileReadMaxBytes` 는 `ServerLimits::file_read_max` 로 옮겼다(시험이 전역을 바꾸지 않게, Go `limits` 와 같은 이유).
- 큰 파일 일(읽기·쓰기·probe·raw·목록·업로드 복사)은 `spawn_blocking` 에서 한다. 다운로드는 `tokio::fs` + `ReaderStream` 으로 흘려보낸다. 경로 잠금(`PathLocks`)은 `await` 를 넘어 쥐므로 tokio Mutex 다.
- Go `os.Open` 은 Windows 에서도 디렉터리를 연다 — Rust 는 열기 실패 뒤 디렉터리면 `not a file` 로 같은 답을 낸다.
- `/api/cwd` 의 서버 cwd 폴백은 Go `os.Getwd` 처럼 `$PWD` 가 같은 디렉터리를 가리키면 그것을 쓴다(unix).
- Go `fsEntries`(`Entries == nil`) 갈래는 없다 — Go `New` 도 언제나 세워 닿지 않는다.

### 남은 위험
- multipart: `Content-Transfer-Encoding: quoted-printable` 부분의 자동 해독(Go `NextPart`)은 옮기지 않았다(브라우저·curl 은 보내지 않는다). 파일 이름·값의 잘못된 UTF-8 은 U+FFFD 로 바뀐다(Go 는 바이트 그대로 디스크 이름이 된다).
- 업로드 임시 파일은 async 문맥에서 std 쓰기로 쓴다(조각 단위라 짧다).
- wsentry 의 `Error::Io`(메모 자리 만들기 실패)는 문구만 들어 `permission_denied` 로 가르지 못한다 — Go 는 `*os.PathError` 라 권한이면 403 이다(`/api/editors` 는 그 키만 빠지므로 관측 없음, `fs_root_of` 는 `roots()` 가 그 자리를 빈 값으로 넘겨 관측 없음).
- 탐색기 목록 정렬의 대소문자 무시 비교는 글자마다 첫 소문자 하나를 쓴다(Go `unicode.ToLower` 와 같다 — İ 포함).
- Go `ToolCwdIsRoot`(실제 데몬으로 도구를 만드는 시험)는 옮기지 않았다 — 경계가 없으므로 "절대경로면 쓴다" 시험과 같은 것을 본다.
