**해석**

- 목표 미달 항목은 없다. NFR-PRF-12 는 D-42 의 1.55 MB 로 충족하고, 옛 목표 1.5 MB 로는 43,787 B 넘는다. 1.55 MB 까지 남은 여유는 6,213 B 다.
- 유휴 메인 스레드: 줄 실행의 0.72% 는 load average 12~17 일 때 잰 값이다. 유휴 단계는 에이전트가 돌기 전이라 줄·TUI 조건이 같다. 부하 7 에서 새 인스턴스로 다시 재니 0.33%(idle-after 0.30%)였다. 그래서 0.72% 는 기계 부하 영향으로 추정한다. 같은 줄 실행의 idle-after 는 0.40% 였다.
- 서버·데몬 CPU 0.03% 는 `ps` 의 CPU 시간 단위(0.01초)를 30초로 나눈 한 칸이다. 0.07% 는 두 칸이다.
- NFR-PRF-9 는 시나리오가 10분만 돌아 "60분, 마지막 30분 증가 5 MB 이하" 를 판정할 수 없다. 10분 동안 힙은 10~22 MB 사이를 오르내리며 늘지 않았다.

**이상한 점**

- 데몬 RSS 가 M1 보다 크다. M1 은 27.6~28.7 MB 였고, 지금은 줄 104.8 → 116.4 MB(10분 동안 30초에 약 0.6 MB 증가)·TUI 105.5 MB 다. 터미널 16개로 나누면 약 7.3 MB 이고 NFR-PRF-10(터미널당 8 MB, 이후 증가 없음) 범위에 가깝다. 원인은 M2 의 에뮬레이터·줄 저장소(D-14)로 추정한다. 시나리오는 NFR-PRF-10(5만 줄이 찬 뒤 증가 없음)을 재지 않으므로 이 값으로 판정하지 않는다.
- 위의 "같은 인스턴스에서 boot 를 거듭 재면 작업 공간이 커진다" 는 도구의 성질이다(도구는 고치지 않았다).
