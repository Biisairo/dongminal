# SRS: 설정 내보내기·가져오기 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 한 줄이다.

> **"설정 export, import 기능 추가. 모든 설정을 export, import 할 수 있는 기능."**

지금 설정을 옮기는 길이 없다. 새 기계에 dongminal 을 띄우면 테마·단축키·상태바
항목·레이아웃 프리셋을 **손으로 다시 짜야 한다.** 값이 세 저장소(서버 블롭 ·
`localStorage` · `sessionStorage`)에 흩어져 있어 사용자가 직접 복제할 수도 없다.
요구는 그 전부를 파일 하나로 내보내고, 그 파일로 되돌리는 것이다.

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 대상 | **Settings 창에서 설정 가능한 값 전부** (§3.1 이식 표) — 세 저장소에 걸쳐 있다 |
| **B** 내보내기 | 봉투 JSON 파일 하나를 브라우저가 내려받는다 |
| **C** 가져오기 | 파일을 골라 **전체 교체**한 뒤 페이지를 다시 연다 |
| **D** 자리 | Settings 모달의 새 탭 `Backup` |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **설정 블롭** | `/api/settings` 가 주고받는 JSON. 서버는 해석하지 않고 `<dataDir>/settings.json` 에 그대로 쓴다 |
| **이식 표** | §3.1 의 키 목록. 무엇이 파일에 실리는지의 단일 진실 |
| **봉투** | 내보낸 파일의 최상위 구조. `kind`·`version` 과 세 계층(`server`·`local`·`session`) |
| **전체 교체** | 파일에 있는 그대로 복원한다. 이식 표에 있으나 파일에 없는 키는 **지워** 기본값으로 되돌린다 |
| **기기별 값** | `localStorage` 에 사는 값. 브라우저(기기)마다 다르다 |
| **탭별 값** | `sessionStorage` 에 사는 값. 같은 기기의 브라우저 탭마다 다르다 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 설정은 세 저장소에 흩어져 있다

| 저장소 | 자리 | 성격 |
|---|---|---|
| 서버 블롭 | `/api/settings` → `<dataDir>/settings.json` | 서버의 값. 어느 브라우저로 붙어도 같다 |
| `localStorage` | 브라우저 | 기기별 취향 |
| `sessionStorage` | 브라우저 탭 | 탭별 자리 |

Settings 모달 6개 탭이 만지는 값이 이 셋에 나뉘어 있다 — 사용자에게는 한 창의
설정이지만, 저장소는 하나가 아니다. **내보내기가 한 계층만 담으면 "설정을
옮겼는데 알림이 꺼져 있다" 가 된다.**

### 2.2 서버는 블롭을 해석하지 않는다

`internal/webserver/httpapi/handlers_settings.go` 는 받은 바이트를 그대로 쓰고
그대로 돌려준다. 따라서 블롭 계층의 내보내기는 `GET /api/settings` 응답을 **그대로
담는 것**이고, 가져오기는 `PUT /api/settings` 로 **그대로 보내는 것**이다. 키를
하나씩 세지 않아도 되고, 서버 변경도 필요 없다.

### 2.3 블롭의 PUT 은 전체를 갈아치운다

`_saveSettings`(`web/js/core/app-settings.js:11`)가 읽어 쓰는 값을 매번 전부 실어
보낸다. 이 성질이 이번 작업에는 **유리하다** — 가져오기가 블롭을 통째로 PUT 하면
그것이 곧 전체 교체다. 반대로 위험도 같은 자리에 있다: 가져온 직후 사용자가 설정을
하나라도 건드리면 `_saveSettings` 가 **그 순간 메모리에 있는 전역값**으로 블롭을
다시 덮는다. 방금 가져온 값이 전역에 올라와 있지 않으면 조용히 되돌아간다.

### 2.4 내부 새로고침은 설정 전역을 다시 읽지 않는다

`softReload`(`web/js/core/app-reload.js`)가 다시 가져오는 것은 워크스페이스·주의·
활동·편집기·Git 이다. 설정 블롭을 읽는 곳은 `main.js:12` 의 부트스트랩 IIFE 와
`app-settings.js:314` 의 IIFE 둘뿐이고, 둘 다 **페이지가 열릴 때 한 번** 돈다.
`shortcuts`·`statusBar`·`statsInterval` 같은 값은 전역 변수(`helpers.js`)라
`softReload` 로는 갱신되지 않는다.

→ **가져오기 뒤에 화면을 맞추는 확실한 길은 페이지를 다시 여는 것뿐이다.**

### 2.5 이탈 가드가 걸려 있다

`main.js:62` 의 `beforeunload` 가 도구가 하나라도 있으면 되묻는다. 단
`window.__dmReloading` 이 참이면 지나간다 (FR-RLC-5a). 앱이 스스로 여는
새로고침은 사용자의 실수가 아니기 때문이다.

### 2.6 자산 버전은 잠겨 있다

`web/version_test.go` 가 `web/js`·`web/*.css` 의 해시를 `web/assets.lock` 과 맞춘다.
자산을 고치면 `index.html` 의 `?v=` 를 올리고 잠금 파일을 새 해시로 바꿔야 한다.

## 3. 요구사항 (Requirements)

### 3.1 이식 표 — 무엇이 실리는가

**FR-SPT-1.** 파일에 실리는 것은 아래 표가 전부다. Settings 창의 6개 탭이 만지는
값과 정확히 일치한다.

| 계층 | 키 | Settings 자리 |
|---|---|---|
| `server` | 설정 블롭 **전체** | Theme · Shortcuts · Status Bar · Presets · Display(제목·탭이름) |
| `local` | `attnDesktop` | Notifications ▸ 데스크톱 알림 |
| `local` | `attnSound` | Notifications ▸ 사운드 |
| `local` | `agentsPollMs` | Notifications ▸ 에이전트 패널 새로고침 주기 |
| `local` | `slotDir` | Display ▸ 슬롯 방향 |
| `session` | `displayMode` | Display ▸ Display Mode |
| `session` | `mobileBreakpoint` | Display ▸ Mobile Breakpoint |

**FR-SPT-2.** 블롭 계층은 키를 세지 않고 **통째로** 담는다 (§2.2). UI 가 아직 없는
설정(`gitSignatureInterval`·`gitStatusInterval`)도 그래서 함께 실린다 — 값이 설정인
것과 화면에 칸이 있는 것은 다른 문제다.

**FR-SPT-3.** 이식 표 밖의 `localStorage`·`sessionStorage` 키(`sidebarWidth`·
`agentsWidth`·`sidebarTab`·`gitFileView`·리포별 마지막 ref·활성 창·포커스 pane …)는
**담지도 않고 건드리지도 않는다.** 화면 크기에 딸린 치수와 리포별 자리는 다른
기계로 옮기면 뜻을 잃는다.

### 3.2 내보내기

**FR-SPT-4.** `Backup` 탭의 `설정 내보내기` 를 누르면 봉투 JSON 파일이 내려받아진다.

**FR-SPT-5.** 봉투의 형태는 이렇다.

```json
{
  "kind": "dongminal-settings",
  "version": 1,
  "exportedAt": "2026-09-02T04:05:06.000Z",
  "server": { "…설정 블롭 전체…" },
  "local":  { "attnDesktop": "1", "agentsPollMs": "5000" },
  "session": { "displayMode": "desktop" }
}
```

- `server` 는 `GET /api/settings` 응답 그대로다.
- `local`·`session` 은 **저장된 키만** 담는다. 없는 키를 기본값으로 채우지 않는다 —
  "정한 적 없음" 과 "기본값으로 정함" 은 다르고, 그 차이가 복원 뒤에도 남아야 한다.
- 값은 저장소에 있던 **문자열 그대로** 담는다. 저장소가 문자열만 갖기 때문이다.

**FR-SPT-6.** 파일 이름은 `dongminal-settings-YYYYMMDD-HHMMSS.json` 이다 (내려받는
기계의 지역 시각). 여러 번 내보내도 서로 덮지 않는다.

**FR-SPT-7.** 서버 블롭을 못 읽으면(응답 실패) 내보내기는 **파일을 만들지 않고**
실패를 알린다. 반쪽 백업이 온전한 백업처럼 보이는 것이 가장 나쁘다.

### 3.3 가져오기

**FR-SPT-8.** `Backup` 탭의 `설정 가져오기` 는 파일 선택기를 연다. 고른 파일은
브라우저가 읽는다 — 서버로 올라가지 않는다.

**FR-SPT-9.** 아래 중 하나라도 어긋나면 **아무것도 바꾸지 않고** 거부한다.

| 검사 | 거부 사유 문구 |
|---|---|
| JSON 파싱 실패 | `JSON 파일이 아닙니다` |
| `kind !== 'dongminal-settings'` | `dongminal 설정 파일이 아닙니다` |
| `version` 이 아는 판(1)보다 큼 | `더 새로운 판의 설정 파일입니다 (v<n>)` |
| `server` 가 객체가 아님 | `설정 내용이 없습니다` |

**FR-SPT-10.** 검사를 지나면 무엇이 덮이는지 알리고 **확인을 받는다.** 되돌릴 수
없는 교체이기 때문이다.

**FR-SPT-11.** 확인하면 **전체 교체**한다.

1. `server` 를 `PUT /api/settings` 로 통째로 보낸다.
2. 이식 표의 `local` 키: 파일에 있으면 그 값으로 쓰고, **없으면 지운다.**
3. 이식 표의 `session` 키: 같은 규칙.

이식 표 밖의 키는 이 절차가 읽지도 쓰지도 않는다 (FR-SPT-3).

**FR-SPT-12.** 서버 PUT 이 실패하면 거기서 멈춘다 — 브라우저 저장소는 손대지
않는다. 서버는 옛 설정, 브라우저는 새 설정인 상태를 만들지 않는다.

**FR-SPT-13.** 교체가 끝나면 페이지를 다시 연다. 이유는 §2.4 다 — 설정 전역을
다시 읽는 길이 그것뿐이고, 다시 열지 않으면 §2.3 의 덮어쓰기로 방금 가져온 값이
조용히 사라진다. 이탈 가드는 `window.__dmReloading=true` 로 지난다 (§2.5).

### 3.4 UI

**FR-SPT-14.** Settings 모달에 7번째 탭 `Backup` 을 둔다. 기존 6개 탭 뒤다.

**FR-SPT-15.** 패널에는 버튼 둘과, **무엇이 실리고 무엇이 실리지 않는지**를 적은
안내가 있다. 기기별·탭별 값이 함께 옮겨진다는 사실은 사용자가 알아야 한다.

**FR-SPT-16.** 내보내기·가져오기의 결과(성공·거부 사유)는 패널 안에서 보인다.

## 4. 비기능 요구 (Non-functional)

| 항목 | 요구 |
|---|---|
| 서버 변경 | 없다. 기존 `GET`·`PUT /api/settings` 만 쓴다 (§2.2) |
| 자산 버전 | `?v=` 를 올리고 `web/assets.lock` 을 갱신한다 (§2.6) |
| 파일 크기 | 레이아웃 프리셋을 포함해 수십 KB 규모. 별도 제한을 두지 않는다 |
| 비밀 | 설정 블롭에 자격증명이 없다. 파일은 평문 JSON 이다 |

## 5. 설계 결정 (Design decisions)

**D-1. 순수 클라이언트로 만든다.** 내보낼 값이 브라우저 저장소에 걸쳐 있어
서버 혼자서는 전체를 볼 수 없다. 서버에 종단을 새로 파도 `local`·`session` 계층은
브라우저가 실어 줘야 하므로, 종단이 하는 일이 없다.

**D-2. 봉투가 계층을 나눠 담는다.** 한 덩어리로 평평하게 담으면 복원할 때 어느
키를 어느 저장소에 써야 하는지 알 수 없다. 파일에 계층이 적혀 있으면 그 판단이
파일 안에 있다.

**D-3. 이식 표를 서술자 배열 하나로 둔다.** 내보내기와 가져오기가 같은 배열을
읽는다. 두 벌로 적으면 설정이 늘 때 한쪽만 고쳐지고, 그 실패는 **복원해 보기
전까지 아무도 모른다.**

**D-4. 가져오기 뒤에는 다시 연다.** 부분 재적용(테마만 다시 칠하고 단축키만 다시
배선…)은 설정이 늘 때마다 재적용 경로도 함께 늘려야 하고, 빠뜨리면 §2.3 이
조용히 되돌린다. 다시 여는 길은 하나뿐이라 늘어나지 않는다.

**D-5. `sessionStorage` 값도 담는다.** `displayMode`·`mobileBreakpoint` 는 탭별
값이지만 **Settings 창에서 설정하는 값**이다. 사용자가 "모든 설정" 이라고 할 때
그 창에 있는 칸은 전부 포함된다. 탭별이라는 성질은 안내로 밝힌다 (FR-SPT-15).

**D-6. 없는 키는 채우지 않고, 복원할 때는 지운다.** 저장소에 키가 없다는 것은
"기본값을 쓴다" 는 뜻이다. 내보낼 때 기본값을 박아 넣으면 나중에 기본값이 바뀌어도
옛 값이 따라온다. 복원할 때 지우면 그 뜻이 그대로 옮겨진다.

## 6. 비목표 (Non-goals)

| 하지 않는 것 | 이유 |
|---|---|
| 부분 가져오기(단축키만·테마만) | 사용자가 정한 것은 전체 교체다 |
| 병합 | 같은 이유. "복원했는데 옛 값이 남아 있다" 를 만들지 않는다 |
| 워크스페이스(창·탭·도구) 내보내기 | 설정이 아니다. 실행 중인 프로세스에 딸린 상태다 |
| 기기별 치수·리포별 취향 이식 | FR-SPT-3 |
| `dmctl` 하위 명령 | 요구에 없다. 필요해지면 봉투 형식이 이미 있다 |
| 자동 백업·판 관리 | 요구에 없다 |
| 서버 종단 신설 | D-1 |
