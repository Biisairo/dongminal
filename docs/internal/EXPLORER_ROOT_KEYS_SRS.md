# SRS: 탐색기의 루트 자리·생성 직후·키보드 길, 그리고 탭 바 여백 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

사용자 보고 여섯(`U-4`·`U-11`·`U-12`·`U-13`·`U-14`·`U-16`)을 한 묶음으로 닫는다.
접수한 문장은 여섯이다.

> · **"탐색기의 빈 공간을 클릭하면 커서가 root 로 간다"** — 최상위에 파일·폴더를
>   만들 자리가 없다 (`U-4`)
> · **"탭 바의 빈 공간을 더블클릭하면 새 탭이 열린다"** (`U-11`)
> · **"탐색기의 빈 공간을 더블클릭하면 새 파일을 만든다"** (`U-12`)
> · **"파일이 만들어지면 그 파일을 즉시 연다"** (`U-13`)
> · **"탐색기를 클릭하면 편집기로부터 키보드 주도권을 가져오고, 탐색기에서
>   키보드로 삭제·복사·붙여넣기를 한다"** (`U-14`)
> · **"메모장(Notes)에서는 폴더를 만들 수 없고 파일만 만들어지게 한다"** (`U-16`)

추가 접수 (2026-09-10): **루트 머리(`.ed-head`)도 클릭할 수 있어야 하고, 클릭하면
루트가 선택된다.**

### 1.2 범위 (Scope)

여섯을 **한 스펙**으로 둔다. 따로 하면 "빈 여백은 무엇인가"·"선택을 무엇이
소비하는가" 두 규약이 여러 벌로 갈린다. 근거는 §2.6 이다.

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 말 | 뜻 |
|---|---|
| **빈 여백** | `.ed-tree` 안에서 `.ed-row` 가 아닌 자리. `_dropDirAt` 이 이미 이 뜻으로 쓴다 |
| **머리** | `.ed-head` — 루트 이름과 버튼 셋을 든 줄. 루트에는 행이 없으므로 머리가 루트의 시각적 대표다 |
| **루트 선택** | `_sel === this.root`. `_kindOf(root)` 는 이미 `'dir'` 을 돌려준다 |
| **조작 4종** | 삭제 · 복사 · 붙여넣기 · 이름 변경. 전부 이미 있다 (§2.4) |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 "빈 여백 = 루트" 규약은 이미 있다 — **드롭에만** 있다

```
file-tree-xfer.js:305  _dropDirAt(target)
  "드롭이 향하는 폴더. 폴더 행이면 그 폴더, 파일·링크 행이면 그 부모,
   헤더와 빈 여백이면 루트다 (FR-FTR-20)."
```

드롭은 이미 그렇게 판정하고, `file-tree.js:57` 의 주석도 **"헤더는 루트 드롭
존이다"** 라고 적고 있다. **클릭·더블클릭만 그 규약 밖에 있다.**

```
file-tree-paint.js:134  _onClick(e)   const row=…; if(!row||…) return;   ← 즉시 나간다
file-tree-paint.js:160  _onDbl(e)     const row=…; if(!row||…) return;   ← 즉시 나간다
```

`U-4` 가 결함으로 느껴지는 이유가 이 비대칭이다 — 같은 자리에 **놓을 수는 있는데
고를 수는 없다.**

### 2.2 루트에는 행이 없다

```
file-tree-paint.js:524
  "뿌리에는 행이 없으므로(이름은 머리가 보인다) 뿌리의 실패는 여기 실어 보인다"
```

`_items()` 의 `walk(this.root,0)` 는 루트의 **자식들**부터 만든다. 그래서 루트
선택을 "행에 `sel` 클래스" 로 보일 방법이 없다. 머리에는 이미 루트를 뜻하는 표시
자리가 하나 있다 — `style-editor.css:223 .ed-head.ed-drop-root`.

머리는 **생성자에서 한 번** 만들어지고 인스턴스 수명 내내 같은 요소다
(`file-tree.js:60 this.head=this._head()`). 루트가 바뀌면 인스턴스 자체가
버려진다 (`app-editor.js:535 if(t&&t.root!==…){t.destroy()}`). 따라서 머리의
리스너는 **하나면 되고**, 루트에 따라 갈리는 것은 생성 시점에 결정해도 된다.

### 2.3 `startCreate` 는 이미 `at` 을 받는다 — 진입점이 넷이다

```
file-tree-edit.js:12   startCreate(isDir,at){ const d=at||this._targetDir(); … }
file-tree.js:127                 툴바 새 파일   startCreate(false)
file-tree.js:129                 툴바 새 폴더   startCreate(true)
file-tree-xfer.js:185            메뉴 newFile   startCreate(false,dir)
file-tree-xfer.js:186            메뉴 newDir    startCreate(true,dir)
```

`U-12` 는 다섯 번째 진입점을 더하는 일이고, `U-16` 은 그 넷(앞으로 다섯) **전부**를
막아야 하는 일이다. 진입점마다 각자 막으면 한쪽만 고쳐지는 부류가 된다.

`/api/fs/create` 를 부르는 자리는 **`doCreate` 하나뿐**이다 (`FS_CREATE_API` 전량
검색). 폴더 업로드는 `/api/upload` 로 따로 간다 — 이 사실이 §6 비목표 3 의 근거다.

### 2.4 조작은 전부 있다. 없는 것은 포커스와 키 경로다

컨텍스트 메뉴(`file-tree-xfer.js:198-210`)가 이미 다섯을 다 갖고 있다.

| 조작 | 있는 것 | 확인 |
|---|---|---|
| 복사 | `app.edClipSet(this.root,p)` | `app-editor.js:871` |
| 붙여넣기 | `doPasteInto(dir)` | `file-tree-edit.js:224`. 빈 클립보드는 `EDITOR_PASTE_NONE` 로 막혀 있다 |
| 복제 | `doDuplicate(p)` | `file-tree-edit.js:243` |
| 삭제 | `doDelete(p)` | `file-tree-edit.js:193`. **확인창까지 자기가 든다** (`FR-EDT-83`·`84`) |
| 이름 변경 | `startRename(p)` | `file-tree-edit.js:25`. `p===this.root` 를 **이미 막는다** |

없는 것은 둘이다.

1. **탐색기가 포커스를 받지 못한다.** `.ed-explorer`·`.ed-tree` 에 `tabindex` 가
   없다. 지금 탐색기의 `keydown` 은 `file-tree-paint.js:628` 하나뿐이고 그것은
   **인라인 편집 입력**의 것이다.
2. **키 → 조작의 사상이 없다.**

붙여넣는 자리 규칙도 이미 있다 — `_targetDir()`(`file-tree-paint.js:654`)이
"폴더면 그 폴더, 아니면 그 부모, 선택이 없으면 루트" 이며 이것이 `FR-WBR-70` 이다.

### 2.5 전역 `keydown` 과의 충돌은 **없다** (실측)

`M2_PROGRESS` §3.4 는 이 규약이 `PANEL_SHORTCUTS_SRS` 영역이라고 적었으나 **틀렸다**
— 그 문서는 `Background`·`Runs` 버튼의 단축키만 다룬다. 실제 규약은
`EDITOR_GIT_UX_SRS` `FR-EKB-1`·`4` 이며, 전역 `keydown`(`input-binding.js:114`,
**capture** 단계)이 "Monaco **밖**(탐색기·탭바)에서 누른 경우" 를 의도적으로
담당한다.

그 전역이 이 스펙의 키를 삼키는지 자리마다 확인했다.

| 자리 | 판정 |
|---|---|
| `activeElement` 게이트 (`:131`) | `INPUT`/`TEXTAREA` 면 나간다. 탐색기 컨테이너는 `div` 라 **나가지 않는다** |
| `edTrySearchKey` (`:139`) | `Mod+F` 계열만 본다 |
| `BUILTIN_HOTKEYS` (`constants.js:240`) | `Mod+F` 하나뿐 |
| `SHORTCUT_DEFAULTS` (`helpers.js`) | `Delete`·`Mod+C`·`Mod+V`·`F2`·맨 방향키가 **하나도 없다**. 방향키는 `Ctrl+Shift+Arrow` 로만 쓰인다 |
| `_blockBrowserDefault` (`:157`) | 수식키 없는 키는 대상이 아니다 → `Delete`·`F2`·방향키 통과. `KeyC`·`KeyV`·`KeyX` 는 `KEY_BLOCK_EXEMPT_MOD`(`constants.js:234`)로 면제 |

**결론: `U-14` 는 전역 규약을 뒤집지 않고 트리 로컬 `keydown` 을 얹는 일이다.**
그래서 `FR-EKB-1`·`4` 는 **개정하지 않는다.**

### 2.6 여섯이 한 묶음인 이유

| 얽힘 | 내용 |
|---|---|
| `U-4` → `U-14` | 루트를 **선택 가능**하게 만들면 `Delete`·`F2`·복사가 루트를 겨눈다. `startRename` 만 루트를 막고 `doDelete`·`edClipSet` 은 막지 않는다 |
| `U-12` → `U-16` | `U-12` 가 부르는 `startCreate` 를 `U-16` 이 막는다 |
| `U-12` → `U-13` | `U-13` 은 `U-12`(와 나머지 넷)가 만든 파일의 후속이다 |
| `U-4` → `U-12` | 같은 "빈 여백" 판정을 클릭과 더블클릭이 나눠 쓴다 |
| `U-11` | 같은 착상("여백에도 뜻이 있다")의 탭 바 적용. `e.target` 함정이 `U-4` 의 머리 버튼과 **같은 형태**다 |

### 2.7 서버는 메모 루트를 이미 안다 — 부작용도 이미 일어난다

`s.Entries.Notes()`(`wsentry.go:93`)가 정규화된 메모 루트를 준다. 이 함수는
`MkdirAll` 을 **한다**. 그러나 `fsRoot`(`handlers_fs.go:118`)가 부르는
`Roots()`(`wsentry.go:146`)가 **이미 `Notes()` 를 부른다** — 따라서
`apiFSCreate` 에서 다시 부르는 것은 **새 부작용이 아니다.** 새 메서드를 만들 필요가
없다.

거부에 쓸 코드도 이미 있다 — `fsErrBadRequest`(`handlers_fs.go:39`). 새 코드를
등록부(`apierr`)에 더하지 않는다.

## 3. 요구사항 (Requirements)

### 3.1 묶음 A — 빈 여백과 머리는 루트다 (`U-4`)

**FR-EXR-1** `.ed-tree` 의 **빈 여백** 클릭은 루트를 선택한다 (`_sel=this.root`).
판정은 `_dropDirAt`(`FR-FTR-20`)과 **같은 뜻**이어야 하며, 그 판정을 두 벌로
적지 않는다.

**FR-EXR-2** **머리(`.ed-head`)** 클릭도 같은 결과를 낸다. 단 `e.target` 이
`.ed-head-btn`(또는 그 자손)이면 **아무 일도 하지 않는다** — 그 버튼은 자기 동작을
갖는다.

**FR-EXR-3** 루트가 선택된 것은 **머리에 보인다** — `.ed-head` 가 `sel` 클래스를
갖고, 행의 선택(`.ed-row.sel`)과 같은 색을 쓴다. 루트에는 행이 없다 (§2.2).

**FR-EXR-4** 빈 여백·머리 클릭도 행 클릭과 **같은 뒷정리**를 한다 — 쓰다 만 인라인
입력을 버리고(`cancelEdit`) 마지막 실패 메시지를 지운다(`_clearErr`).
근거는 `FR-WBR-2`·`FR-GIT-97` 과 같다.

**FR-EXR-5** 루트가 선택된 동안 `_targetDir()` 은 루트를 돌려준다 — 따라서 툴바의
새 파일·새 폴더가 **최상위**에 만든다 (`FR-EDT-81`). `_kindOf(root)==='dir'` 이
이미 그렇게 만들므로 **새 갈래를 만들지 않는다.**

**FR-EXR-6** 루트 선택은 **워크스페이스에 저장하지 않는다** — `_sel` 의 기존 규약
(`FR-EDT-62`·`FR-SVS-21`)을 그대로 따른다.

### 3.2 묶음 B — 빈 여백 더블클릭은 루트에 파일을 만든다 (`U-12`)

**FR-EXR-10** `.ed-tree` 의 빈 여백 더블클릭은 **루트에 새 파일**의 인라인 입력을
연다 — `startCreate(false, this.root)`.

**FR-EXR-11** 폴더가 아니라 **파일**이다. 폴더는 툴바·메뉴로만 만든다.

**FR-EXR-12** 머리의 더블클릭은 이 갈래에 **들어오지 않는다** — 머리에는 이미
새 파일 버튼이 있고, 클릭 두 번이 그 버튼을 두 번 누르는 일과 겹친다.

### 3.3 묶음 C — 만든 파일은 즉시 연다 (`U-13`)

**FR-EXR-20** `doCreate` 가 **성공한 뒤** 만든 것이 **파일이면 연다.**

**FR-EXR-21** **실패하면 열지 않는다.** `doCreate` 는 서버 응답 **전에** 먼저
그리고(`_optimAdd`) 실패하면 되돌린다(`_restore`) — 열기는 `r.ok` 를 확인한
**뒤**여야 한다. 없는 파일을 연 탭이 남으면 그것이 결함이다.

**FR-EXR-22** **폴더는 열지 않는다.** 폴더 생성은 그 자리를 펼치는 일로 끝난다.

**FR-EXR-23** 여는 방식은 **고정(pin)** 이다 — 미리보기가 아니다 (D-3).

**FR-EXR-24** 진입점을 가리지 않는다 — 툴바·메뉴·빈 여백 더블클릭이 모두 같다.
`doCreate` **한 자리**에 둔다.

### 3.4 묶음 D — 메모장에서는 폴더를 만들 수 없다 (`U-16`)

**FR-EXR-30** 루트가 메모 루트일 때 `startCreate(true, …)` 는 **아무 일도 하지
않는다.** 진입점마다 막지 않고 **`startCreate` 안에서 한 번** 막는다 — 그러면
앞으로 생길 진입점도 자동으로 덮인다.

**FR-EXR-31** 메모 루트에서는 툴바의 **새 폴더 버튼이 없다.** 눌러도 아무 일이
없는 버튼은 고장으로 읽힌다. 루트는 인스턴스 수명 동안 불변이므로(§2.2) `_head()`
가 만들 때 가른다.

**FR-EXR-32** 메모 루트에서는 컨텍스트 메뉴의 **`newDir` 항목이 없다.**

**FR-EXR-33** 서버 `apiFSCreate` 는 `dir:true` 이고 확정된 root 가 메모 루트일 때
**거부한다.** 코드는 `fsErrBadRequest` 이고 본문은 `fs` 방언(`{code,message}`)이다.
클라이언트만 막으면 API 직접 호출로는 만들어진다.

**FR-EXR-34** 메모 루트에서 **파일 생성은 그대로 된다** — 막는 것은 `dir:true`
하나뿐이다.

**FR-EXR-35** 메모 루트를 얻지 못하면(`ErrUnavailable`) 막지 않는다 — 그때는
메모장 표면 자체가 없다 (`FR-NOT-11` 과 같은 근거).

### 3.5 묶음 E — 탭 바 여백 더블클릭 (`U-11`)

**FR-EXR-40** `.pn-tabs` 의 **빈 여백** 더블클릭은 그 pane 에 **새 탭**을 연다.

**FR-EXR-41** `e.target` 이 `.pn-tab`(또는 그 자손)이면 **돌지 않는다.**
`renderer.js:914`(탭 고정)·`:922`(라벨 이름 변경)가 이미 그 자리의 더블클릭을
쓰고 있다 — 탭에서 올라온 이벤트를 여백으로 읽으면 **이름을 고치려다 새 탭이
열린다.**

**FR-EXR-42** 새 탭이 서는 곳은 **그 여백이 속한 pane** 이다. `addTabFocused()`
(`app-layout.js:815`)는 `this.focused` 를 쓰므로 **그것을 그대로 쓰지 않는다** —
활성이 아닌 pane 의 여백을 더블클릭했을 때 다른 pane 에 탭이 생기면 그것이 결함이다.
`.pn-tabs` 는 `el._ctx.node` 로 자기 pane 을 이미 안다.

**FR-EXR-43** 탭의 종류는 기존 새 탭과 **같다**(`'terminal'`) — 이 요구는 진입점을
더하는 일이고 새 종류를 만드는 일이 아니다.

**FR-EXR-44** **Editor·Git 창의 탭 바에서는 아무 일도 하지 않는다.** 그 창에는
`+` 자리 자체가 없다 — `renderer.js:884` 가 `FR-GIT-180`·`FR-EDT-54` 를 근거로
"눌리지만 아무 일도 하지 않는 버튼은 고장으로 읽힌다" 며 빼 두었다. 여백
더블클릭이 그 창에서 터미널 탭을 만들면 그 결정을 조용히 뒤집는다. 판정은
`+` 를 두는 조건과 **같은 것**을 써야 한다 — 두 벌이 되면 한쪽만 고쳐진다.

### 3.6 묶음 F — 탐색기의 키보드 길 (`U-14`)

**FR-EXR-50** 탐색기 컨테이너(`.ed-explorer`)는 **포커스를 받는다**(`tabindex="0"`).
빈 여백·머리·행을 클릭하면 그 포커스를 갖는다 — 이것이 사용자가 말한 "편집기로부터
키보드 주도권을 가져온다" 다. **포커스를 옮기는 일이며 전역 핸들러를 바꾸는 일이
아니다** (§2.5).

**FR-EXR-51** 포커스를 가진 동안 아래 키가 돈다.

| 키 | 동작 | 부르는 것 |
|---|---|---|
| `Delete` · `Backspace` | 선택을 지운다 | `doDelete(sel)` |
| `Mod+C` | 선택을 복사한다 | `app.edClipSet(this.root, sel)` |
| `Mod+V` | 붙여넣는다 | `doPasteInto(this._targetDir())` |
| `F2` | 이름을 고친다 | `startRename(sel)` |
| `ArrowDown` · `ArrowUp` | 선택을 **보이는 순서**로 옮긴다 | — |
| `ArrowRight` | 닫힌 폴더를 펼친다 | `toggle(sel)` |
| `ArrowLeft` | 열린 폴더를 접는다 | `toggle(sel)` |
| `Enter` | 파일이면 고정해 열고, 폴더면 토글한다 | `edPinTabFor` / `toggle` |

`Backspace` 를 함께 받는 것은 macOS 의 삭제 관용이 그것이기 때문이다.

**FR-EXR-52** `ArrowDown`·`ArrowUp` 의 순서는 `_items()` 의 `t:'row'` 항목 순서다 —
**보이는 그대로**이며 펼침 상태를 따른다. 별도의 순서 계산을 만들지 않는다.
선택이 없으면 `ArrowDown` 은 첫 행, `ArrowUp` 은 마지막 행을 고른다.

**FR-EXR-53** **삭제는 확인창을 거친다.** `doDelete` 를 그대로 부르므로 재귀 여부·
항목 수·dirty 탭을 밝히는 확인이 유지된다 (`FR-EDT-83`·`84`). 키보드라는 이유로
확인을 빼는 갈래를 **만들지 않는다** — `U-10` 이 정확히 그 부류의 결함이었다.

**FR-EXR-54** **루트가 선택된 동안** `Delete`·`F2`·`Mod+C` 는 아무 일도 하지
않는다. 루트는 지울 수도 이름을 고칠 수도 복사할 수도 없다. `Mod+V` 는 **된다** —
붙여넣는 자리가 루트라는 뜻이다 (`FR-EXR-5`).

**FR-EXR-55** **인라인 입력이 열려 있는 동안** 이 키들은 돌지 않는다 — 그 키는
그 입력의 것이다. 판정은 `e.target` 이 `.ed-edit` 인지로 한다.

**FR-EXR-56** 처리한 키만 `preventDefault`·`stopPropagation` 한다. **처리하지 않은
키는 그대로 올려보낸다** — 전역 단축키(`FR-EKB-1`·`4`)를 삼키면 탐색기에 포커스가
있는 동안 앱의 키가 죽는다.

**FR-EXR-57** `e.target` 이 `button` 이면 돌지 않는다 — 머리 버튼에 포커스가 있는
동안 `Delete` 가 파일을 지우면 그것이 놀람이다.

**FR-EXR-58** **렌더가 탐색기의 포커스를 빼앗지 않는다.** `renderer.js:447` 의
렌더 후 재포커스는 `document.activeElement` 가 탐색기 안이면 아무 일도 하지
않는다.

- 이전 동작: **매 렌더**가 활성 탭(편집기·터미널)으로 포커스를 되돌렸다. 행을
  클릭하면 미리보기가 열리고 그 렌더가 포커스를 편집기로 가져갔다
- 새 동작: 탐색기가 포커스를 쥐고 있으면 그대로 둔다
- 이유: **이것이 `U-14` 의 본체다.** 이 자리가 없으면 `tabindex`(FR-EXR-50)만으로는
  포커스가 한 프레임도 유지되지 않는다. `FR-EFP-5` 가 이미 "포커스를 편집기로
  되돌리는 **모든 자리**" 를 가리키고 있으며, 이 자리가 그 목록의 하나다
  (`EDITOR_FIND_PANEL_SRS` §2.4b 와 같은 부류의 결함)

**FR-EXR-59** **명시적으로 여는 손짓은 편집기가 포커스를 갖는다.** 더블클릭·
`Enter`·생성 직후 열기(FR-EXR-20)는 "이 파일에서 일하겠다" 이므로 FR-EXR-58 의
예외다. 한 번 클릭의 **미리보기는 예외가 아니다** — 그것은 훑어보는 손짓이고,
그래서 방향키가 이어서 돌아야 한다.

판정은 렌더 후 재포커스 **한 자리**가 소유한다 — 여는 자리마다 `focus()` 를 부르면
그 자리가 여러 벌이 되고, 그것이 `FR-EFP-5` 가 겪은 형태다.

## 4. 설계 결정 (Design Decisions)

**D-1 판정 함수를 하나로 둔다.** `_dropDirAt` 이 이미 "행이면 그 폴더/부모, 아니면
루트" 를 판정한다. 클릭·더블클릭이 각자 같은 판정을 적으면 두 벌이 되고, 그것이
이 저장소가 반복해 겪은 형태다. → **`_dropDirAt` 과 같은 판정을 쓴다.**

**D-2 루트 행을 만들지 않는다.** 일반 탐색기처럼 맨 위에 루트 행을 두는 쪽이
직관적이지만, `_items()`·`reconcile`·`_kindOf`·`doDelete`·`doRename`·드롭 표시가
모두 "루트 행" 을 알아야 하고 삭제·이름 변경을 개별로 막아야 한다. 머리가 이미
루트의 대표이며(§2.2) 이미 루트 드롭 존이다. → **머리에 표시를 얹는다**
(사용자 결정 2026-09-10).

**D-3 만든 파일은 고정해 연다.** `FR-RTU-42` 의 근거는 "목록에서 더블클릭하는
손짓은 '이것을 열어 둔다' 이지 '잠깐 본다' 가 아니다" 다. **만드는 손짓은 그보다
더 강하다** — 방금 이름까지 지어 준 파일이 다음 클릭에 대체되는 미리보기 탭이면
사용자는 만들기가 실패한 것으로 읽는다.

**D-4 `U-16` 을 서버에도 넣는다** (사용자 결정 2026-09-10). 클라이언트만 막으면
API 직접 호출로는 만들어진다. 서버는 메모 루트를 이미 알고 부작용도 이미
일어나므로(§2.7) 추가 비용이 없고, `/api/fs/create` 를 부르는 자리가 `doCreate`
하나뿐이라 회귀 면이 좁다.

**D-5 `startCreate` 안에서 한 번 막는다.** 진입점 넷에 각자 두면 한쪽만 고쳐진다.
툴바 버튼을 **감추는 것은 그와 별개**다 — 막힌 것과 없는 것은 사용자에게 다른
사실이다.

**D-6 `FR-EKB-1`·`4` 를 개정하지 않는다.** 전역 `keydown` 은 탐색기를 의도적으로
담당하며, 이 스펙의 키는 그와 **하나도 겹치지 않는다**(§2.5 실측). 겹치지 않는
것을 규약 변경으로 다루면 다음 사람이 뒤집을 근거를 잃는다.

**D-7 방향키의 부모 이동은 넣지 않는다.** 일반 탐색기는 닫힌 폴더에서 `←` 를
부모로 읽지만, 그것은 선택 이동 규칙을 하나 더 만드는 일이다. 접기/펼치기만으로
요구("방향키 탐색")를 만족한다 → §6 비목표 4.

## 6. 비목표 (Non-goals)

1. **다중 선택** (`U-5`). 선택 모델을 집합으로 넓히는 일이며 그것을 소비하는 자리
   전부가 함께 바뀐다. 이 스펙은 **단일 선택**을 전제한다.
2. **루트 행의 도입** (D-2).
3. **업로드 경유의 폴더 생성을 메모장에서 막는 것.** 폴더 업로드는
   `/api/upload` 로 가고 `/api/fs/create` 를 지나지 않는다(§2.3). 사용자가 가진
   구조를 그대로 옮기는 일을 거부하면 드롭이 조용히 실패한다. 필요해지면 그때
   `FILE_API_BOUNDARY_SRS` 쪽에서 판정한다.
4. **방향키의 부모 이동·`Home`/`End`·타이핑 점프** (D-7).
5. **`Mod+X`(잘라내기).** 클립보드(`edClipSet`)에 cut/copy 구분이 없어 그 모델을
   넓히는 일이 된다.
6. **탐색기의 포커스 링 디자인.** `tabindex` 가 만드는 기본 표시를 쓴다.
7. **탭 바 여백의 **한 번** 클릭.** 뜻을 정하지 않는다 — 더블클릭만 더한다.

### 7.1 구현 중에 실제로 걸린 것 — `tabindex` 만으로는 한 프레임도 못 버틴다

`FR-EXR-50`(`tabindex="0"`)을 넣고 e2e 를 돌렸을 때 **묶음 F 여섯이 전부 실패했다.**
전부 한 뿌리였다 — 행을 클릭한 직후 `document.activeElement` 가 탐색기 안이 아니다.

처음 의심한 것은 `renderer.js` 의 렌더 후 재포커스가 **빼앗는다**는 것이었고
`FR-EXR-58` 의 가드를 넣었다. **그것으로도 실패했다.** 원인은 그 위였다.

```
renderer.js `_rLayout` 이 매 render 마다 `.ed-win` 을 떼었다 붙인다
  → 요소가 문서에서 떨어지는 순간 포커스가 사라진다 (activeElement === body)
  → 재포커스 블록이 도달할 때 탐색기는 이미 포커스를 쥐고 있지 않다
```

**이 함정은 이 저장소에 이미 기록돼 있었다** — `FR-EDT-66` 과 `_restoreEditFocus`
가 인라인 입력에 대해 똑같은 일을 한다("SSE 한 번이면 충분하다"). 컨테이너에도
같은 것이 필요했다: 소유를 플래그로 들고(`_focusOwn`) `mount()` 에서 되돌린다
(`_restoreOwnFocus`).

`focusout` 으로 소유를 지우는 판정도 같은 주석이 미리 답해 두었다 — 떨어져
나가며 잃은 blur 는 **요소가 다시 붙은 뒤에** 도착하므로, `relatedTarget` 이
바깥일 때만 지운다.

**교훈: 렌더가 요소를 떼는 앱에서 `tabindex` 는 포커스의 절반이다.** 나머지 절반은
"누가 쥐고 있었나" 를 기억하는 자리이며, 이 저장소에는 그 선례가 이미 둘 있었다
(`_restoreEditFocus` · `_restoreScrollOf`).

### 7.2 프레임 순서에 기대는 자리가 하나 생겼다

`_restoreOwnFocus` 는 렌더러의 재포커스보다 **먼저** 돌아야 한다 — 그래야
`FR-EXR-59`(명시적으로 여는 손짓)가 우리를 덮어쓸 수 있다. 성립하는 근거는
`TIMERS.frame` 이 `requestAnimationFrame` 을 그대로 쓰고(`timer-hub.js:261`)
rAF 가 등록 순서로 도는 것이며, `mount()` 는 렌더 중에 불리므로 렌더러의
`TIMERS.frame`(그 뒤 `_domGC()` 다음)보다 먼저 등록된다.

**그 순서가 깨지면 더블클릭이 편집기로 가지 않는다.** `V-EXR-59b` 가 그 자리의
회귀 넷이다.
