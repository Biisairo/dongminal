# 1.3 설정·HTTP 보조 묶음

## 목표

JSON·HTTP 응답 보조 패키지를 옮긴다. httpresp·httpreq·sse·httproute 는 HTTP 프레임워크(hyper/axum) 선택의 기준이 되므로, 고른 타입(요청·응답·바디 타입)을 진행 기록에 분명히 적는다. 이후 webserver 이슈들이 그 결정을 따른다.

## 대상 Go 코드

- `internal/shared/runfile`
- `internal/shared/release`
- `internal/shared/httpresp`
- `internal/shared/httpreq`
- `internal/shared/statusline`
- `internal/shared/settingsschema`
- `internal/webserver/sse`
- `internal/webserver/httproute`

프로덕션 코드 약 1197줄.

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)

- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

    - 요청: `http::Request<B>`, 본문 `B: hyper::body::Body` (운영은 `hyper::body::Incoming`, 테스트는 `http_body_util::Full<Bytes>`).
    - 응답: `dm_shared_httpresp::Response = http::Response<Body>`, `Body = BoxBody<Bytes, BoxError>`, `BoxError = Box<dyn Error + Send + Sync>`. 핸들러는 Go 처럼 `w` 에 쓰지 않고 `Response` 를 **돌려준다**. 미들웨어(CORS·보안 헤더 등)는 돌려받은 응답에 헤더를 더한다.
    - 한 번에 쓰는 본문은 `httpresp::full(bytes)`, 스트림은 자기 `Body` 를 `.boxed()` 한다(sse 참고).
  - 공개 API 요약
    - `dm-shared-httpresp`: `CODE_HEADER`, `CONTENT_TYPE_JSON`, `CONTENT_TYPE_TEXT`, `full`, `empty`, `json(status,&v)`(Go Encoder 바이트, 끝 개행), `http_error(status,msg)`(Go `http.Error` 바이트·헤더), `fail_text`/`fail_raw`/`fail_json`(Go `Fail` 의 Text/Raw/그 밖 갈래), `fail_code`.
    - `dm-shared-httpreq`: `DEFAULT_LIMIT`·`WORKSPACE_LIMIT`·`SMALL_LIMIT`(i64), `TOO_LARGE_MSG`, `enum ReadError { TooLarge, Other(BoxError) }`, `async read(body, limit) -> Result<Bytes, ReadError>`, `status(&err)`, `mark_response(&err, &mut res)`.
    - `dm-webserver-sse`: `WRITE_TIMEOUT`, `MAX_BATCH_BYTES`, `start(timeout) -> (Response, Stream)`, `Stream::{comment, data, event, full, drain_data(|| rx.try_recv().ok()), async flush() -> bool}`, `payload(action, Option<&T>)`, `workspace_changed(rev)`.
    - `dm-webserver-httproute`: `Matcher::{Exact, Under, UnderWith, Func}`, `Route<H>{method, matcher, handle}`, `get/post/put/delete/any/at/when`, `dispatch(&routes, method, path) -> Option<&H>`.
    - `dm-shared-release`: `REPO`, `API`, `TIMEOUT`, `newer`, `comparable`. (`latest` 는 아직)
  - Go 와 다르게 한 내부 결정
    - httproute: Go `Dispatch` 는 핸들러를 부르지만, Rust `dispatch` 는 첫 매칭 핸들러를 돌려주고 부르기는 호출자가 한다(핸들러 모양을 표가 정하지 않게). `path` 는 Go `r.URL.Path`(퍼센트 디코딩한 값)를 넘겨야 한다.
    - httpreq: Go `MaxBytesReader` 는 상한 초과 시 응답에 `Connection: close` 를 세우고 연결을 닫는다. Rust 는 `read` 가 응답을 모르므로 응답을 만든 쪽이 `mark_response` 를 부른다. `ReadError::Other` 의 문구(로그 전용)는 Go net/http 문구와 다를 수 있다.
    - sse: Go `Supported` 는 옮기지 않았다(hyper 응답은 늘 스트리밍된다). 본문은 용량 1 채널이고, `flush` 가 시한(`timeout`) 안에 보내지 못하면 false 를 돌려주고 본문을 오류로 끝내 연결을 끊는다. `drain_data` 는 채널 대신 "쌓인 것 꺼내기" 클로저를 받는다.
    - httpresp: Go `Fail(body any)` 의 타입 스위치를 함수 셋(`fail_text`/`fail_raw`/`fail_json`)으로 나눴다.
  - 옮긴 테스트: httpresp 10, httpreq 8, sse 8(멎은 클라이언트 시한 검사는 포트 없이 메모리 파이프 위 hyper 로), httproute 5, release 4.
  - 남은 위험: ① Go 는 핸들러가 넣은 `Connection: keep-alive`(sse) 를 그대로 내보내는데, hyper 도 그대로 내보내는지 Go 와 바이트 비교는 하지 않았다(차분 실행 대상). ② Go 서버는 `Content-Type` 이 없으면 본문을 보고 정한다(DetectContentType). Rust 응답은 그러지 않으므로 Content-Type 없이 쓰는 핸들러는 5.5 에서 직접 정해야 한다. ③ 시한에 걸린 sse 연결은 hyper 가 막힌 소켓 쓰기를 마칠 때까지 남는다 — 연결 단위 쓰기 시한은 서버 계층(5.5/7)의 일이다.
