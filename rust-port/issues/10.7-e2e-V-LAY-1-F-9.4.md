### FR-RDF-6 V-LAY-1

- **판정**: 의도한 프런트 변경도, 의도하지 않은 프런트 변경도 아니다. 8.1 트리와 지금 트리의 `web/`·`e2e/` 는 같다(`git log rp/8.1..HEAD -- e2e web` 비어 있음). 그래서 기준선을 다시 뜨지 않았고 프런트도 고치지 않았다. SRS 요구 동작 2 의 두 갈래 밖이다.
- **원인**: 워커의 서버는 시험끼리 공유된다. 같은 워커의 앞 시험이 열린 Run 이나 작업 중(`working`·바쁜 전경) 도구를 남기면, 작업 패널 탭 배지(`.ag-tab-n`)가 켜진다. 그러면 열 화면 모두에 `span.ag-tab-n.ui-tab-badge` 키(숨김 아님)가 새로 생기고, 드리프트가 50 이 되어 기준선 40 을 넘는다. 8.1 증상과 숫자까지 같다.
  - 실험: 열린 Run 하나로 runs 배지가, `sleep 600` 에 `working` 을 보고한 도구 하나로 agents 배지가 켜진다.
- **고침**:
  - fixture `stubEmptyActivityCounts(page)` 를 더했다. 시험 화면이 받는 활동(`activities`·`limits`)·백그라운드 도구·Run 목록을 비운다. 종단과 스냅샷 조각 두 길 모두 막는다.
  - 같은 갈래의 선례는 FR-FLK-12 `stubEmptyLimits` 다. 제품에 시험용 입구는 두지 않았다.
  - 회귀 V-LAY-1b 를 더했다(열린 Run 을 남기고 같은 대조). 고치기 전 RED 는 `지금에만 10 · 면제 40 → 50 > 40`, 고친 뒤 GREEN 이다. `working` 갈래는 임시 실험으로 확인했다(막기 전: 배지 보임, 막은 뒤: 숨김). 백그라운드 도구 갈래는 같은 모양의 응답을 비우는 것이라 따로 시드하지 않았다.
- **전량 회차에서 하나 더 드러난 것**: history 뷰에 `vis` 가 선 그 프레임에는 `ResizeObserver` 가 아직 돌지 않았다. 그때 찍으면 `hide-hash` 가 없는 `git:history|div.git-hist-list.ui-scroll` 이 「지금에만」 키가 된다(드리프트 41).
  - 고침: 행(`.git-hist-row.head`)이 선 뒤 두 프레임을 기다린다.
  - RED 를 결정적으로 만들지 못했다. `/api/git/log` 를 8초 늦춰도 재현되지 않았다. 한 프레임 경합이다. 근거는 전량 회차의 실패 산출물이다.
