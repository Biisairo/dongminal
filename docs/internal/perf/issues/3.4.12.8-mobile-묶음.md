**껍데기와 본체의 동작이 다른 곳**(본체가 서기 전 = 데스크톱에서 한 번도 모바일이 된 적 없는 탭)
1. `#drawer-close` 단추를 사이드바 머리에 넣지 않는다(이전: 데스크톱에도 숨은 채 있었다).
2. `#mobile-keybar` 에 `.mkb-btn` 을 그리지 않는다(이전: 숨은 채 18개+). 설정의 키바 바꿈(`_keybarApply`)도 다시 그리지 않는다 — 본체가 설 때 그 값으로 그린다.
3. `visualViewport` resize·scroll 리스너를 걸지 않는다. 이전에는 데스크톱에서도 vv resize 마다 `_scheduleFit` 했다 — 핀치 확대처럼 창 resize 없이 vv 만 바뀌는 경우 맞춤을 다시 예약하지 않는다(창 resize 는 main.js 가 그대로 한다).
4. 길게 누르기 → `contextmenu` 합성 리스너(document 캡처 넷)를 걸지 않는다(이전에도 데스크톱에서는 곧바로 물러섰다).
5. 서랍(`DrawerSheet`)을 만들지 않고, 렌더마다 하던 `drawerSheet().close()`·`body.mobile`/`keyboard-up` 걷기를 하지 않는다(그 표식은 본체만 붙인다).
6. 설정 탭을 누를 때 `#modal[data-mview]` 를 `detail` 로 바꾸지 않는다 — 열 때 `list` 만 적는다. 설정 창 MutationObserver(→ `mobileChromeSync`)도 걸지 않는다. CSS 는 `body.mobile` 아래에서만 이 값을 읽는다.
7. 위 모든 모바일 전용 이름(`mTopPaint`·`mkbRefresh`·`_kbSuppressAll`·`_mobileVvApply`·`_toggleDrawer`·`nav.*`·`sheets.mobileChromeSync`)은 아무 일도 하지 않는다. 이전에는 `isMobile` 이 거짓이면 대개 곧바로 물러섰고, `_toggleDrawer` 는 데스크톱에서 `mobileChromeSync` 를 불렀다(데스크톱에선 바꿀 표식이 없다). `_mobileVvApply` 는 이전에 데스크톱에서 패딩을 걷고 `_scheduleFit` 했다 — 지금은 하지 않는다(걷을 패딩이 없다).
8. `ui-layout` 기준선(V-LAY-1)의 `button.drawer-close…`·`button.mkb-btn` 키는 데스크톱에서 "기준선에만" 쪽으로 간다(게이트가 세지 않는 쪽, 값 대조 대상 아님).

**설계와 다르게 한 것**
- keybar.js 를 `[mobile]` 이 아니라 따로 `[keybar]` 라이브러리 묶음으로 뒀다 — `[settings]` 의 settings-terminal.js 가 같은 함수를 쓰므로 `mobile`·`settings` 가 needs 로 나눠 싣는다(설정을 열 때 모바일 본체 23 KB 를 받지 않게).
- 껍데기를 `app.mobile` 에 계속 두고 위임하지 않고, 본체를 실으면 `app.mobile` 자체를 바꾼다. `isMobile` 을 본체 유무로 가렸다(위 동작 변경 셋째).

**남은 위험**
- 모바일 부팅의 첫 렌더가 `b/keybar.js`→`b/mobile.js` 두 요청을 기다린다(워크스페이스 요청과 나란히). 요청이 멎으면(onload·onerror 둘 다 없음) 첫 렌더도 멎는다 — 워크스페이스 요청이 멎을 때와 같은 성질이다.
- 묶음 싣기가 실패한 채 모바일이어야 하면 렌더마다 다시 시도한다(등록부가 실패를 기억하지 않음). 망이 끊긴 동안 렌더가 잦으면 요청이 그만큼 난다.
- 3.4.12.10 이 같은 줄 `Screens.register('settings', …)` 에 `needs:['chat']` 를 더한다 — 병합 때 `needs:['keybar','chat']` 처럼 합쳐야 한다.
- 3.4.12.9(언어 조각): 모바일 파일의 문자열은 부팅 상수(TIP_*)라 조각 대상이 거의 없다. keybar 는 키 없음.
- 터치 데스크톱·태블릿: `wantsMobile` 은 이전 `isMobile` 판정 그대로다(폭 < 기준, 또는 높이 < `MOBILE_LANDSCAPE_MAX_H` 이고 `pointer:coarse`). 높이가 넉넉한 태블릿·터치 데스크톱은 묶음을 받지 않는다. 터미널 터치 스크롤(`_tsTouch`)은 `pointer:coarse` 만으로도 서므로 묶음과 무관하다. 세로 태블릿(폭 < 768)은 이전처럼 모바일이고 묶음을 받는다.
