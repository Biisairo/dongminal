# SRS: 헬퍼 설치의 안정성 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 사용자가 겪은 증상이다.

> **"Stop hook error: `/Users/dykim/.dongminal/bin/dmctl: No such file or directory`
> — 이런 버그 여전히 나는데 확인해줘."**

조사로 원인을 확정했다. `~/.dongminal/bin/` 의 헬퍼 넷(`dmctl`·`detach`·
`download`·`edit`)이 **존재하지 않는 파일을 가리키는 심볼릭 링크**였다.

```
dmctl -> /private/var/folders/.../T/go-build3179988942/b001/exe/dongminal
```

`go-build3179988942` 은 **`go run` 이 만들고 끝나면서 지우는 임시 빌드 디렉터리**다.

### 1.2 범위 (Scope)

| 묶음 | 내용 |
|---|---|
| **I** 설치 | 사라질 경로를 링크 대상으로 삼지 않는다 |
| **D** 진단 | `doctor` 가 운영 홈의 `bin` 을 다시 쓰지 않는다 — 검사만 한다 |
| **H** 점검 | `health` 와 `doctor` 가 설치된 헬퍼가 실제로 실행 가능한지 본다 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **헬퍼** | `bin/` 에 multi-call 로 설치되는 이름들 — `dmctl`·`detach`·`download`·`edit`·`mdview` |
| **덧없는 자기 자신** | `go run` 이 만든 임시 빌드 산출물. 프로세스가 끝나면 지워진다 |
| **운영 홈** | `$DONGMINAL_HOME`. 격리 홈(`--isolated`·`verify`)이 아닌, 사용자가 실제로 쓰는 홈 |

  Windows 는 심볼릭 링크를 시도하지 않는다)

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 설치는 `os.Executable()` 을 그대로 가리킨다

`runtime.Install(binDir)`(`internal/shared/runtime/install.go:41`)은
`os.Executable()` 을 `EvalSymlinks` 로 편 뒤, 헬퍼 이름마다
`paths.LinkOrCopy(self, dst)` 를 부른다. POSIX 의 `LinkOrCopy` 는 **심볼릭
링크를 먼저 시도**하고 실패할 때만 복사한다.

`go run` 아래에서 `os.Executable()` 은 임시 빌드 산출물이다. 그래서 설치는
성공하고, **`go run` 이 끝나는 순간 다섯 링크가 한꺼번에 죽는다.**

### 2.2 그 명령은 문서가 권하는 명령이다

- `.github/workflows/release.yml` 의 게이트: `go run ./cmd/dongminal doctor`
- `docs/external/getting-started.md` 의 "안 될 때 — `doctor`"

CI 러너는 홈이 매번 새것이라 아무 일도 없다. **개발 기계에서 `DONGMINAL_HOME` 이
운영 홈을 가리키면 `go run` 한 번이 살아 있는 설치본을 조용히 망가뜨린다.**

### 2.3 증상은 나중에 나타난다

설치 시점에는 링크가 유효하다. 죽는 것은 `go run` 이 **끝난 뒤**다. 그래서
`doctor` 는 "전부 통과" 를 찍고, 사용자는 한참 뒤 훅이 실패할 때 알게 된다 —
실제로 이번이 그랬다.

### 2.4 부팅은 이미 다시 설치한다

`boot.go:49` 와 `cmd/dongminal/main.go:354` 가 기동마다 `Install` 을 부른다.
**서버를 다시 띄우면 저절로 낫는다** — 다만 그때까지 터미널 세션을 잃지 않고는
알 길도, 고칠 길도 없었다.

### 2.5 진단이 운영 상태를 바꾼다

`doctorInstall`(`doctor.go:119`)은 검사를 위해 **운영 홈의 `bin` 에 실제로
설치한다.** 진단 명령이 진단 대상을 바꾸는 구조이고, §2.1 의 사고가 퍼진 경로가
바로 이것이다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 I — 설치

- **FR-HLI-1** `Install` 은 **사라질 경로를 링크 대상으로 삼지 않는다.** 자기
  자신이 덧없으면, `binDir` 안에 안정된 복사본을 만들고 헬퍼들이 그것을 가리키게
  한다.
- **FR-HLI-2** 덧없음의 판정은 두 조건을 **모두** 만족할 때다 — 경로가 OS 임시
  디렉터리 아래이고, 경로 요소에 `go-build` 가 있다. 하나만으로는 판정하지
  않는다 (D-2).
- **FR-HLI-3** 덧없지 않으면 동작은 종전과 같다 — `LinkOrCopy` 그대로다.
- **FR-HLI-4** 복사본은 헬퍼 이름이 아니어야 한다. multi-call 디스패치가 보는
  이름과 겹치면 그 이름으로 불렸을 때의 동작이 달라진다.

### 3.2 묶음 D — 진단

- **FR-HLI-5** `doctor` 는 **운영 홈의 `bin` 에 설치하지 않는다.** 설치 계층
  검사는 임시 디렉터리에서 하고, 끝나면 지운다.
- **FR-HLI-6** 설치 계층 뒤의 검사들(셸·터미널)은 그 임시 `bin` 을 쓴다 —
  "이 호스트에서 계층이 도는가" 라는 질문에 운영 홈은 필요하지 않다.

### 3.3 묶음 H — 점검

- **FR-HLI-7** `runtime.CheckHelpers(binDir)` 는 설치된 헬퍼마다 **가리키는 것이
  실제로 존재하는지** 본다. 없거나, 죽은 링크이거나, 실행 권한이 없으면 그 이름과
  사유를 돌려준다.
- **FR-HLI-8** `doctor` 는 **운영 홈**의 헬퍼를 이 검사로 본다 (설치는 하지 않고,
  §3.2 와 짝이다). 깨져 있으면 실패로 세고 고치는 방법을 알린다.
- **FR-HLI-9** `health` 도 같은 검사를 하고, 깨져 있으면 실패로 센다 —
  터미널 세션을 잃지 않고 상태를 아는 유일한 길이다 (§2.4).
- **FR-HLI-10** 두 곳의 안내는 같아야 한다: 서버를 다시 띄우면 낫는다.

## 4. 검증 (Verification)

| ID | 검증 | 수단 |
|---|---|---|
| **V-HLI-1** | 덧없는 exe 로 설치하면 링크가 `binDir` 안을 가리키고, 원본을 지워도 헬퍼가 살아 있다 | 단위 |
| **V-HLI-2** | 덧없지 않은 exe 는 종전대로 그 경로를 가리킨다 | 단위 |
| **V-HLI-3** | 임시 디렉터리 밖의 `go-build`, `go-build` 없는 임시 경로는 덧없지 않다 | 단위 |
| **V-HLI-4** | `CheckHelpers` 가 죽은 링크·없는 파일을 찾아낸다 | 단위 |
| **V-HLI-5** | 정상 설치에서는 아무것도 보고하지 않는다 | 단위 |
| **V-HLI-6** | `doctor` 실행이 운영 홈의 `bin` 을 바꾸지 않는다 | 단위 |
| **V-HLI-7** | `health` 가 깨진 헬퍼를 실패로 센다 | 단위 |

## 5. 확정 결정 (Decisions)

- **D-1 거절이 아니라 복사다.** `go run` 을 막는 길(설치 실패)도 있지만, 릴리스
  게이트가 바로 그 명령을 쓴다(§2.2). 게이트를 깨지 않으면서 사고도 막는 길은
  **사라지지 않을 것을 가리키게 하는 것**이다.
- **D-2 판정은 두 조건을 모두 만족할 때만.** 임시 디렉터리 아래라는 것만으로
  판정하면, 임시 홈에 정식 설치한 경우(`--isolated`·`verify`)까지 복사로 바뀐다.
  `go-build` 만으로 판정하면 그 이름의 실제 설치 자리를 오인한다.
- **D-3 복사본은 `binDir` 안에 둔다.** 밖에 두면 그 자리를 누가 지우는지가 다시
  문제가 된다. `bin` 은 이미 이 프로그램이 소유하는 자리다.
- **D-4 `doctor` 는 고치지 않고 알린다.** 진단이 대상을 바꾸면 무엇이 원래
  상태였는지 알 수 없게 된다(§2.5 가 그 사고다). 고치는 것은 기동의 몫이고
  (§2.4), `doctor` 는 그 사실을 알린다.
- **D-5 `health` 에 넣는다.** 서버를 다시 띄우면 낫지만, **다시 띄우기 전에**
  깨진 것을 아는 수단이 필요하다. `health` 가 그 자리다.

## 6. 비목표 (Non-goals)

1. 헬퍼가 깨졌을 때 `health`·`doctor` 가 스스로 다시 설치하는 것 (D-4).
2. `go run` 으로 도는 것을 막는 것 (D-1).
3. 헬퍼 판번호 검사 — 설치된 것이 지금 서버와 같은 판인지는 별개의 질문이다.
4. Windows 의 복사 정책 변경 (FR-XPA-3 그대로).
