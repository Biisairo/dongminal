# 2.4.1 스냅숏 직렬화기와 분할점 연속성 (FR-TRM-4, A-2)

## 목표

termstate 에 `Screen::snapshot(history) -> Snapshot{bytes, back, first_line}` 을 만든다. 화면 + 에뮬레이터 기록 + 대체 화면일 때 가려진 주 화면 + 커서(줄바꿈 대기)·저장 커서·펜(SGR·밑줄 종류·밑줄 색·OSC 8)·문자 집합·SO·스크롤 영역·원점·모드·커서 모양·제목을 최소 재그리기 ANSI 로 낸다. 분할점이 시퀀스·UTF-8 한가운데이면 오프셋을 물린다(`back`). 스캐너(vte 표)는 termstate 안에 둔다.

설계: `perf/M2_DESIGN.md` §2.4. 상위: `2.4-스냅숏-직렬화와-오프셋-연속성.md`(분할 2026-11-24, 조정자 승인).

## 완료 조건

- RED: 모든 분할점(녹화·경계 벡터·모드·문자 집합·펜·커서·대체 화면)에서 스냅숏(k) + 바이트[k-back..] = 바이트 전체.
- RED: 대체 화면 안팎의 DECSC·DECRC, 대체 화면 안에서 크기를 바꾼 뒤(조정자 요청).
- RED: 스캐너가 alacritty 와 어긋날 수 있는 자리를 시험 이름으로 드러낸다(`scanner_*`, `known_gap_*`).
- xterm.js 확인 스크립트(`testdata/check-snap.mjs`).
- 바꾼 부분의 시험·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.

## 진행 기록

### 2026-11-24 agent-pf-2-4

- 분할 승인보다 먼저 2.4.1~2.4.3 을 한 커밋(`25aabebf`, pf/2.4)으로 냈다. 상세 진행 기록은 상위 2.4 파일에 있다.
- 조정자 요청으로 시험을 더했다(후속 커밋): 대체 화면 안팎의 DECSC·DECRC(`alt_screen_round_trip_keeps_saved_cursors`), 대체 화면 안에서 크기 바꾼 뒤(`alt_screen_after_resize`), 스캐너 어긋남(`scanner_follows_decstbm_with_subparams`, `scanner_resets_title_on_ris`), 알려진 빈틈(`known_gap_custom_tab_stops_are_not_carried`, `known_gap_alt_saved_cursor_from_previous_alt_session`, `known_gap_main_saved_cursor_after_resize_in_alt`, `known_gap_scroll_region_below_screen`).
- 이 시험이 찾아 고친 것:
  - DECSTBM 하위 인자(`2:1;4r`): vte 는 첫 하위 인자를 쓰는데 스캐너는 그 시퀀스를 버렸다 → 같게 맞춤.
  - RIS 뒤 제목 사본이 남음(alacritty 가 제목 사건을 안 보냄) → RIS 를 보면 설정을 다시 걸어 지금 제목을 받는다.
- 알게 된 것: alacritty 의 1049h/l 은 `swap_alt` 뿐이다(DECSC·DECRC 없음). 대체 화면 안에서 크기를 바꿔 주 화면 커서가 재흐름으로 옮겨지면, 스냅숏을 만들 때 주 화면 저장 커서가 지금 커서로 바뀐다(원본도 같이). 나간 뒤 화면은 같고 주 화면 DECRC 에서만 다르다 — `known_gap_main_saved_cursor_after_resize_in_alt` 로 고정. 원본 상태를 바꾸는 유일한 경우다.
- 시험: termstate `--lib` 57 통과(+ignored 2), toolhub 105, fmt·clippy 통과.
