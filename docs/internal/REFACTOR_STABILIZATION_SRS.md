# SRS: 중복을 접고 구조를 안정화한다 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요

### 1.1 목적

접수한 말은 한 줄이다.

> **"전체 리팩터링 진행하면서 중복 제거하고 오류 수정, 구조 안정화 진행"**

계기는 e2e 였다. 전체 실행마다 **서로 다른** 2~3개가 무작위로 실패했고, 하나를
고치면 다음 실행에서 다른 파일이 같은 이유로 무너졌다.

| 회차 | 통과 | 실패한 것 |
|---|---|---|
| 1차 | 1191/1194 | T6 · BR13 · G11 |
| 2차 | 1192/1194 | T6 · TC-SVS-50 |
| 3차 | 1191/1194 | B11 · S2 · V100 |
| 4차 | 진행 중 | B8 · H15 |

**개별 대응이 수렴하지 않는 이유는 중복이었다.** 같은 일을 하는 헬퍼가 파일마다
복제돼 있고 그중 일부만 견고했다. 견고한 판을 한 곳에 두지 않는 한, 고치는 속도가
깨지는 속도를 넘지 못한다.

같은 물음을 앱 코드에 던지자 **이미 일어난 결함**이 나왔다 (§2.2) — 뷰 하나를
더하려면 여섯 자리를 고쳐야 하는 구조가, 실제로 네 자리를 빠뜨린 채로 있었다.

이 SRS 는 세 영역에서 **중복을 접고, 그 중복이 만든 결함을 고치고, 재발을 구조로
막는다.**

### 1.2 범위

**포함**
- e2e 하네스 (`e2e/`, 114파일 35k줄)
- 프론트엔드 (`web/js`, 68파일 28.5k줄)
- 백엔드 (`internal/`·`cmd/`, 245파일 45k줄)

**미포함**
- 사용자에게 보이는 동작의 변경 — 이 작업은 **동작을 보존한다** (§6 비목표 #1).
  예외는 §2.2 의 결함 넷이며, 그것은 "원래 그랬어야 하는 동작" 으로 되돌리는 것이다
- 이미 근거가 유효한 의도적 중복 (§3.1 의 보존 목록)
- 새 기능 (§6 비목표 #2)

## 2. 현재 상태

### 2.1 e2e — 견고한 판이 한 곳에 없다

`fixtures.ts` 는 이미 부분 공용화돼 있고 **114개 파일 전부가 그것을 import 한다.**
그러므로 남은 일은 배선이 아니라 치환이다.

| 헬퍼 | fixtures | 로컬 복제 | 복제본의 상태 |
|---|---|---|---|
| `waitForInit` | ✓ (`:174`) | **27벌** | 21벌은 `waitSettled` 한 줄이 빠진 옛 판 |
| `openGit` | ✓ (`:227`) | **16벌** | **공용판이 오히려 약하다** — 사이드 visible 단언 없음 |
| `open<View>` | ✗ | 16벌 | 전부 `openGit 몸통 + clickGitView + 단언` |
| git fixture 루트 | ✗ | **40파일 ×8줄** | 같은 원본 트리를 40번 만들고 40번 지운다 |
| `resetWorkspace` | ✓ (`:49`) | 4벌 | **전부 409 를 다루지 않는다** |

**두 뿌리가 여기서 나온다.**

**뿌리 1 — 재렌더 경쟁.** 클릭 893회 중 재시도(`toPass`)를 가진 것은 **9회, 6개
파일**뿐이다. raw `page.click` 120회(33파일), 우클릭 메뉴 58회(17파일)는 무방비다.
`fixtures.ts:91-98` 이 이미 이 진단을 적어 두었으나, 그 처방(`clickGitView`)은
**뷰 탭 하나에만** 적용됐다.

**뿌리 2 — 워크스페이스가 안 비워진 채 다음 테스트가 시작된다.**
`resetWorkspace`(`fixtures.ts:49-61`)가 GET 으로 etag 를 읽고 PUT 을 **한 번** 한다.
응답 상태를 확인하지 않고 `catch` 가 통째로 삼킨다. 앞 테스트의 마지막 저장이 아직
날고 있으면 이 PUT 이 409 로 밀리고 — **아무도 모르게** 리셋이 실패한다. 세 단계
(`resetWorkspace`→`reapOrphanTools`→`clearAttention`)가 첫 단계에 직렬 의존하므로,
"참조됨" 판정까지 앞 테스트 기준으로 빗나간다.

### 2.2 web/js — 구조가 이미 결함을 냈다

Git 패널의 **뷰 집합이 다섯 자리에서 손으로 열거된다.** 여덟 번째 탭
(`Submodules`)이 그중 넷에서 빠져 있다 (실측).

| 자리 | Submodules |
|---|---|
| `panel.js:68-78` 필드 선언 | **없음** — 게터가 미선언 필드를 만든다 |
| `panel-life.js:103` 탭 활성화 시 재조회 | **없음** — 열어도 낡은 목록을 본다 |
| `panel-life.js:124` `dropView` 언마운트 맵 | **없음** — **탭을 닫아도 언마운트되지 않는다** |
| `panel-life.js:148-153` `detach()` | **없음** — 창을 닫아도 남는다 |
| `panel-poll.js:160` `_reloadViews` | 있음 |

부수 결함: `detach()` 가 부르는 게터들은 **없으면 생성한다.** 그래서 창을 닫는
경로가 한 번도 열지 않은 뷰 여섯 개를 새로 만든 뒤 언마운트한다 — `panel-views.js`
가 표방한 지연 생성이 그 자리에서 깨진다.

**이것은 부주의가 아니라 구조의 산출물이다.** 뷰 하나를 더하는 비용이 여섯 자리이고,
빠뜨림을 잡아 주는 것이 아무것도 없다.

같은 형태의 중복이 더 있다.

- **뷰 생명주기 6벌** — `_adopt` 는 여섯 곳이 한 글자도 다르지 않고, `_load` 는
  worktrees 와 submodules 가 주석까지 바이트 동일하다 (URL·상수 3토큰만 다름).
- **그룹 개념이 표 7개 + if-chain 에 흩어져 있다** — `GIT_GROUPS`·`GIT_GROUP_AXIS`·
  `GIT_ROW_ACTS`·`GIT_DIR_ACTS`… 그리고 상태문자 규칙은 `panel-changes.js:700` 과
  `file-tree-paint.js:347` 에 **따로** 있다. 둘은 "같아야 한다" 고 주석이 밝히지만
  같은 자리에서 나오지 않는다.
- **폴링 5벌** — `document.hidden` 스킵과 복귀 시 갱신의 조합이 자리마다 다르다.
  가장 정확한 판정(`console.js:78`)이 나머지 넷에 전파되지 않았다.
- **확인창 5벌** — 그중 `_confirmClose`(`app-tool.js:332`)는 여전히 `innerHTML`
  경로다. `app-tool.js:14-16` 이 그 위험을 적어 두었고, `_edConfirm` 은 그것을
  피하려고 **또 하나를 만들었다**.
- **`try{fetch}catch{null}` 60여 곳** — `git/api.js` 가 이 패턴을 "버그 부류 하나의
  제거" 로 없앴는데 그 처방이 `git/` 안에만 있다. `file-tree-paint.js:269` 는
  **git 종단을 raw fetch 로** 부르며 stale/echo 보호를 못 받는다.

### 2.3 Go — 한쪽에서 푼 문제가 다른 쪽에 안 퍼졌다

백엔드는 대부분 이미 깊다. `domain/submodule` 이 별도 패키지인 이유는 화이트리스트
판정 단위이고(`status` 와 `update` 의 argv[0] 이 같아 합치면 교집합-금지 불변식이
깨진다), `wsentry` 는 read-modify-write 원자성을 소유한다. 둘 다 삭제 테스트에서
복잡도가 **곱해진다** — 손댈 것이 없다.

마찰은 **비대칭**에 있다.

| 문제 | gitapi | httpapi |
|---|---|---|
| 쓰기 전처리 | `gitWrite` 하나, 11파일 38회 | **없음** — 4단계가 핸들러마다 손으로 |
| `http.Error` 직접 호출 | 0곳 | **55곳** |
| 오류 봉투 | `{error,message}` | `{code,message}` · `{error,detail}` · `{error}` · text/plain |
| 배선 가드 | — | **4벌**, 그중 하나는 503 이 아니라 **500** 을 낸다 |

봉투가 넷이라는 것이 실제 비용이 되는 자리: CLI 에 **`{"code","message"}` 를 읽는
코드가 하나도 없다**(`dmctl_toolio.go:387`, `dmctl_run.go:779`). 지금은 CLI 가
`/api/fs/*` 를 부르지 않아 드러나지 않을 뿐이다.

그 밖에:
- `handlers_git_remote.go`(732줄)에 sync 체인 상태기계가 섞여 있고 **그 부작용 층에
  테스트가 0건**이다 (판정은 이미 순수 함수로 뽑혀 있는데도).
- `toolhub/tool.go`(706줄)의 주목 상태기계가 PTY 에 묶여, 그것만 시험하려고 **패키지
  전역 훅 두 개**(`SetAttnBusyProbe`·`toolBusyProbe`)가 생겼다. 전역 변수 교체는
  병렬 테스트에서 되돌릴 수 없는 자리다.
- `sandbox/runtime.go` 의 `StartCommand(goos)`(`:119`)와 `splitCommand(goos)`(`:159`)가
  OS 분기를 **각각 독립적으로** 한다 — 표시한 명령과 실행한 argv 가 갈라질 수 있다.
- 라우터 골격(`route` 타입·`exactPath`·디스패치 루프)이 두 패키지에 그대로 복제돼
  있다 (`handlers_api.go:60`, `gitapi/routes.go:8`; 후자의 주석이 스스로 인정한다).

### 2.4 JS 단위 테스트가 0개다

`package.json` 의 devDependency 는 `@playwright/test` 하나다. 순수 로직 하나를
확인하려면 서버를 띄우고 브라우저를 연다. 이미 순수한데 묶여 있는 것들:
`relTime`(1057줄 DOM 클래스의 static 인데 밖에서 두 곳이 부른다)·`_rollup`·
`_inherit`·`_viewFp`·`gitEchoOk`.

## 3. 요구사항

### 3.1 공통

**FR-RST-1** **동작을 보존한다.** 이 작업의 성공은 "전체 e2e 가 통과한다" 로 재고,
사용자에게 보이는 것은 바뀌지 않는다. 예외는 §2.2 의 결함 넷이며 그것은 원래
의도된 동작으로 되돌리는 것이다 (FR-RST-20).

**FR-RST-2** **의도적 중복은 보존한다.** 근거가 코드에 남아 있고 그 근거가 여전히
유효한 것은 건드리지 않는다.

| 보존 대상 | 근거 |
|---|---|
| `fixtures.ts` 의 `plainWindows`·`GIT_BODY_VIEWS` | 앱 함수를 쓰지 않는 것이 검사의 독립성이다 — 없애면 검사가 검사를 멈춘다 |
| `app-runs.js` 의 파사드 6개 | 삭제하면 복잡도가 15곳으로 **흩어진다** |
| `panel-views.js` 의 branch/tag 파사드 22개 | 메뉴가 패널만 알면 되게 하는 자리 |
| `git/api.js` 의 3중 반환(`ok`/`stale`/`fail`) | 세 상태가 실제로 다르다 |
| `domain/submodule`·`wsentry`·`git/store` | 삭제 시 불변식이 사라지거나 복잡도가 곱해진다 |

**FR-RST-3** 각 단계는 **독립적으로 검증 가능**하고 독립적으로 커밋된다. 한 단계가
막히면 앞 단계는 그대로 남는다.

### 3.2 묶음 E — e2e 하네스

**FR-RST-10** `resetWorkspace` 는 409 를 재시도하고 **결과를 확인한다.** PUT 이
밀리면 최신 etag 로 다시 하고, 워크스페이스가 실제로 비었는지 GET 으로 본다.
조용한 실패를 남기지 않는다. *(뿌리 2 직격, 114파일 즉시 효과)*

**FR-RST-11** 로컬 `waitForInit` 27벌을 공용판으로 치환한다. 21벌은 그대로 들어가고,
6벌은 옵션(`mode`·`beforeGoto`·`readyFor`·`clearOnFirstLoad`)으로 흡수한다.
`waitSettled` 가 따라 들어가며 **초기 저장 2건이 비행 중인 상태에서 단언을 시작하는
문제**가 닫힌다.

**FR-RST-12** 재렌더 경쟁에 공용 방어를 세운다 — `clickGitView` 의 검증된 골격
(눌러 보고, 원한 상태가 됐는지 보고, 아니면 다시)을 `clickRow`·`openRowMenu`·
`waitRows` 로 넓힌다. *(뿌리 1 직격)*

**FR-RST-13** `openGit` 을 **강한 쪽으로** 통합한다 — 공용판이 로컬 16벌보다 약하다
(§2.1). `openGitView(page, repo, view)` 하나가 16개 정의를 흡수한다.

**FR-RST-14** git fixture 원본을 워커 스코프로 한 번만 만든다. 40파일 ×8줄이
한 줄이 된다.

**FR-RST-15** 파일별로 남아야 하는 것은 남긴다: `tab-names` 의 stub 주입,
`git-confirm`/`git-dialog` 의 준비 판정 대상, sidebar 두 스펙의 first-load-only 지우기
(**키는 파일별**이어야 한다 — 자기 검증 대상을 지우지 않기 위한 장치다),
`git-hunk` 의 `openDiff`, `workspace-save-conflict` 의 두 번째 컨텍스트.

### 3.3 묶음 W — web/js

**FR-RST-20** **결함 넷을 고친다** (§2.2): `_submodulesView` 필드 선언, 탭 활성화 시
재조회, `dropView` 언마운트, `detach()`. 그리고 `detach()` 가 **열린 적 없는 뷰를
만들지 않게** 한다.

**FR-RST-21** 뷰 집합을 **서술자 하나**로 접는다. `sidebar-list.js` 의 `SidebarList`
가 이 저장소에서 같은 문제를 이미 그렇게 풀었다 — 창 목록과 Git 핀 목록이 각자
reconcile 을 구현하다 한쪽만 뒤처졌던 문제다. 뷰를 더하는 비용이 **배열 한 줄**이
되고, FR-RST-20 의 누락은 구조적으로 재발 불가능해진다.

**FR-RST-22** 그룹 개념을 서술자로 접는다. 상태문자 규칙(`_stateChar`)이 두 화면의
**한 출처**가 된다. `GIT_DIR_ACTS` 가 이미 같은 사고의 절반을 했다(`GIT_ROW_ACTS`
에서 파생) — 그 방향을 끝까지 민다.

**FR-RST-23** `visiblePoll(ms, fn, opts)` 하나로 폴링 5벌을 접는다. `console.js` 가
발견한 `isConnected`/`vis` 판정이 `opts.when` 으로 모두에게 간다.

**FR-RST-24** `_confirmClose`·`_notify`·`_edConfirm` 을 `GitDialog` 위로 옮긴다.
`innerHTML` 경로 하나가 사라진다. 파일 이름은 `ui/dialog.js` 로 옮겨 이름이 자리를
배신하지 않게 한다.

**FR-RST-25** `panel.js:86-107` 의 관측 접근자 44개를 제거한다. 그것을 만든 근거
("옮기면 하위 뷰 일곱이 한 줄도 안 바뀐다")는 **이미 소비됐다.** 제거하면
"칸마다 다른 것" 과 "저장소마다 하나인 것" 이 코드 표면에서 갈린다.

**FR-RST-26** `file-tree-paint.js:269` 의 raw fetch 를 `gitFetch` 로 옮긴다 — git
종단인데 stale/echo 보호를 못 받고 있다.

### 3.4 묶음 G — Go

**FR-RST-30** httpapi 에 gitapi 와 같은 모양의 쓰기 트랜잭션을 세우고 `fs`·`runs`·
`attention` 세 표면을 그 위로 올린다. **옳은 설계가 옆 패키지에서 38회 검증됐다.**

**FR-RST-31** 오류 봉투를 하나로 정하고 `apierr` 가 응답까지 쓴다. 지금 `apierr` 는
조회만 하고, 나머지 절반을 각 표면이 자기 방식으로 채운다.

**FR-RST-32** 배선 가드를 하나로 모은다 — 같은 사실이 503 과 500 으로 갈리는 것이
구조적으로 불가능해진다.

**FR-RST-33** sync 체인(`gitSyncHolder`·`runSyncChain`)을 gitapi 밖으로 내린다.
HTTP 없이 체인 전이를 시험할 수 있게 된다 — 지금 그 층의 테스트는 0건이다.

**FR-RST-34** 주목 상태기계를 값 타입으로 세운다. **성과 지표는 전역 훅 두 개가
사라지는 것이다.**

**FR-RST-35** `sandbox` 의 OS→명령 매핑을 한 자리로 모은다 (표시 문자열은 거기서
파생). 라우터 매처를 공용 타입으로 올리되 **테이블 둘은 그대로 둔다** (소유가 다르다).

### 3.5 묶음 T — 안전망

**FR-RST-40** JS 단위 테스트 러너를 세우고, 이미 순수한 로직(`lanes`·`relTime`·
`_rollup`·`_inherit`·`gitEchoOk`·`_viewFp`)을 그 아래 둔다. 새 추상화보다 **러너가
먼저다** — 묶음 W 의 안전망이 곧 이것이다.

### 3.6 비기능

**NFR-RST-1** 각 단계 뒤 전체 e2e 가 이전 회차보다 **나빠지지 않는다.**

**NFR-RST-2** 주석의 근거를 보존한다. 이 저장소의 주석은 결정의 이유를 담으며,
합치는 과정에서 그것이 사라지면 다음 사람이 같은 논쟁을 다시 한다.

## 4. 단계와 순서

근거가 강한 것, 그리고 **다음 단계의 안전망이 되는 것**이 먼저다.

| 단계 | 내용 | 왜 이 순서인가 |
|---|---|---|
| **E1** | FR-RST-10 (`resetWorkspace` 409) | 함수 하나, 114파일 즉시 효과. 뿌리 2 직격 |
| **E2** | FR-RST-11 (`waitForInit` 치환) | 기계적. `waitSettled` 가 따라 들어간다 |
| **E3** | FR-RST-12 (`clickRow`·`openRowMenu`·`waitRows`) | 뿌리 1 직격 |
| **E4** | FR-RST-13·14 (`openGit`·fixture 루트) | 줄 수는 가장 많이 줄지만 안정성 효과는 뒤 |
| **W1** | FR-RST-20 (결함 넷) | **이미 일어난 오류.** 서술자화 전에 고쳐 두어야 회귀를 잰다 |
| **W2** | FR-RST-21 (뷰 서술자) | W1 의 재발을 구조로 막는다 |
| **T1** | FR-RST-40 (JS 러너) | W3~W5 의 안전망 |
| **W3~W5** | FR-RST-22·23·24·25·26 | 그룹 서술자 → 폴링 → 확인창 → 접근자 → fetch |
| **G1** | FR-RST-30·31·32 | 한 묶음. 근거가 가장 강하다 |
| **G2** | FR-RST-33·34 | 테스트 0건인 층, 전역 훅 제거 |
| **G3** | FR-RST-35 | 작고 명확 |

E1~E3 만으로 실측된 두 뿌리가 모두 닫힌다. 나머지는 유지보수 비용과 재발 방지다.

## 6. 비목표

1. **동작 변경** — 사용자에게 보이는 것은 바뀌지 않는다. 예외는 §2.2 의 결함 넷뿐이며
   그것은 되돌리는 것이지 바꾸는 것이 아니다.
2. **새 기능** — 이 작업에서 늘어나는 사용자 기능은 없다.
3. **문자열 파일 분할** — `constants-git.js` 를 로케일별로 쪼개는 것은 부차적이다.
   먼저 접어야 하는 것은 **개념**(그룹·뷰)이지 문자열이 아니다.
4. **`run/store.go` 의 결정/지속 분리** — 비결정성이 이미 주입돼 있어 지금 아프지
   않다. 아파지면 그때 한다.
5. **테스트 재시도(retries) 설정으로 flaky 를 덮는 것** — 이 SRS 는 원인을 없앤다.
