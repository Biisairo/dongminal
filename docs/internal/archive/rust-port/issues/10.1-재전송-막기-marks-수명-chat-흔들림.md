**FR-RDF-1 — reached 번호의 수명**
- `dm-shared-edgemesh` 공개 API 추가: `MARK_REACHED_TTL`(= `REDIAL_MAX.saturating_mul(3)` = 180초), `mark_expendable(reached, at, now) -> bool`(닿은 적 없거나 `now - at >= TTL`). chat(`upper.rs` `junk_mark`)과 edgemesh(`net.rs` `junk_mark`)가 이 함수 하나를 함께 쓴다.
- 밀어내기는 기억이 가득 찼을 때만 한다(바뀌지 않음). 고를 때 닿은 적 없는 번호를 먼저, 그 안에서 가장 오래된 것을 고른다. 처음 커밋은 `at` 만으로 골라 오래된 reached 를 닿은 적 없는 번호보다 먼저 밀어낼 수 있었다. 자동 보안 검토의 지적을 받아 `6df190d3` 에서 고쳤다.
- `Mark.at` 은 잊은 시각이다. 거절한 재전송으로는 바꾸지 않는다.
- 시험(두 crate 에 같은 것, 시계 주입): `expired_reached_marks_pushed_out`(가득 차도 180초 뒤 새 노드를 받음), `live_reached_marks_not_pushed_out`(179초면 밀어내지 않음), `old_reached_mark_kept_when_not_full`(가득 차지 않으면 오래된 reached 도 남고 옛 상태를 막으며, 거절한 재전송은 `at` 을 바꾸지 않음), `unreached_marks_pushed_out_first`, edgemesh 에 `mark_reached_ttl_is_three_redials`. 기존 DIFF-19·21 시험은 그대로 통과한다. edgemesh 시험 도우미에 `Hooks.clock`(주입 시계)을 더했다.

**FR-RDF-8 — `reachability_follows_links`**
- RED: 고치기 전, `yes` ×3 부하에서 crate 전체 20회 중 2회 실패했다.
- 원인: 시간이 모자란 것이 아니었다. 시한을 60초로 늘려도 멈췄다. C 가 옛 연결의 EOF 를 처리하기 전에 시험이 `link(&c, &b)` 를 부르면, C 의 동시 걸기 판정(`prefer_new`)이 새 연결을 버린다. 옛 연결을 작은 지문 쪽(B)이 걸었으면 이렇게 된다. 시험은 한 번만 이으므로 C 가 돌아오지 않는다. 제품은 다시 걸기로 복구하므로 제품 결함은 아니다.
- 수정: 시험 노드에 `changed` 알림(`tokio::sync::Notify`)을 달았다. 도우미 `on_change` 는 알림이 올 때마다 조건을 본다. 다시 잇기 전에 C 도 B 를 끊김으로 보았는지 기다린다. 60초 `HANG` 은 멈춤을 진단하는 데만 쓰고, 퍼지는 속도는 재지 않는다. 제품 코드의 시간 상수는 바꾸지 않았다.
- GREEN: 이 시험만 `yes` ×6 부하에서 100회 연속 통과했다. crate 전체는 `yes` ×3 부하에서 20회 연속 통과했다.

**게이트**: fmt·clippy(-D warnings)·hermetic test 통과(chat 59, edgemesh 39). 두 crate 에 OS 의존 코드가 없어 교차 clippy 는 돌리지 않았다.
