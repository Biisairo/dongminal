# SRS: 탐색기의 다중 선택 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요

### 1.1 목적

사용자 요구 `U-5`: **"탐색기에 다중 선택을 더한다 (`Cmd`+클릭 · `Shift`+클릭)."**

지금 선택은 문자열 하나다(`FileTree._sel`). 그것을 **집합**으로 넓히되,
**넓히는 것과 소비하는 것을 가른다** — 선택을 읽는 자리가 열 곳이 넘고 그 전부를
한 번에 다중으로 만들면 각 자리의 확인창·되돌림·낙관적 반영이 함께 흔들린다.

### 1.2 범위

- `web/js/ui/file-tree.js` · `file-tree-paint.js` · `file-tree-edit.js` ·
  `file-tree-xfer.js` — 선택 모델과 그 소비.
- 신규·변경 e2e.

비포함:

- 서버 종단. 다중은 **클라이언트가 여러 번 부르는 것**이며 새 API 를 만들지 않는다.
- 이름 변경·새 파일·새 폴더·붙여넣기·복제 — **본질적으로 단일**이다 (`FR-EMS-20`).
- 키보드로 범위를 넓히는 일(`Shift`+↑↓). 마우스의 둘만 요구됐다.

### 1.3 정의

- **앵커(anchor)**: `_sel`. 지금 기준이 되는 하나이며 `Shift` 범위의 시작점이다.
  **기존 코드가 읽던 그 값 그대로다** — 이름도 뜻도 바꾸지 않는다.
- **집합(set)**: `_selSet`. 앵커를 **포함한** 선택 전부.
- **보이는 순서**: `_items()` 의 행 순서. 펼침 상태를 그대로 따른다 (`FR-EXR-52`).

## 2. 현재 상태 (조사)

| 자리 | 읽는 것 |
|---|---|
| 그리기 (`file-tree-paint.js:605`) | `sel:this._sel===p` — 행마다 하나 |
| 머리 (`:643`) | 루트가 앵커인가 |
| 키보드 이동 (`_moveSel`) | 앵커의 인덱스 |
| 조작 대상 폴더 (`_selTargetDir`) | 앵커의 종류 |
| 삭제·이름변경·이동·복사 (`file-tree-edit.js`) | 인자로 받은 경로 하나 |
| 드래그 (`file-tree-xfer.js:232`) | `this.drag` — 끌기 시작한 행 하나 |

**조작 함수들은 이미 경로를 인자로 받는다.** 그래서 다중은 "집합을 만들고 그것을
순회하는" 일이며, 함수들의 계약을 바꾸지 않는다.

## 3. 요구사항

### 3.1 묶음 A — 선택 모델

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| FR-EMS-1 | 선택은 **앵커 하나 + 집합**이다. 집합은 언제나 앵커를 포함하고, 앵커가 빈 문자열이면 집합도 비어 있다 | 필수 |
| FR-EMS-2 | 평범한 클릭은 **집합을 그 하나로 되돌린다.** 기존 동작이 한 글자도 바뀌지 않아야 한다 — 미리보기 열기·폴더 펼침도 그대로다 | 필수 |
| FR-EMS-3 | `Mod`+클릭(Ctrl 과 Meta 중 **정확히 하나** — `helpers.js` 규약)은 그 행을 집합에서 **토글**한다. 토글로 들어온 행이 새 앵커다. 마지막 하나를 빼면 선택은 비어 있게 된다 | 필수 |
| FR-EMS-4 | `Shift`+클릭은 **앵커부터 그 행까지 보이는 순서의 범위**를 집합으로 만든다. 앵커는 움직이지 않는다 — 그래야 범위를 다시 잡을 수 있다 | 필수 |
| FR-EMS-5 | `Mod`·`Shift` 클릭은 **파일을 열지 않고 폴더를 펼치지도 않는다.** 그 클릭의 뜻은 "고른다" 이지 "본다" 가 아니다 | 필수 |
| FR-EMS-6 | 루트는 집합에 들지 않는다 (`FR-EXR-54` 의 정신 — 루트는 지울 수도 옮길 수도 없다) | 필수 |
| FR-EMS-7 | 집합은 트리가 바뀌면 따라간다 — 이름이 바뀐 경로는 새 이름으로, 사라진 경로는 집합에서 빠진다 (`rename`·`_forget` 이 앵커에 하는 일과 같다) | 필수 |
| FR-EMS-8 | 키보드 이동(↑↓)·`revealPath`·루트 선택은 집합을 **하나로 되돌린다.** 두 손짓이 같은 상태를 다르게 남기면 사용자가 무엇이 선택됐는지 셀 수 없다 | 필수 |

## 4. 설계 결정

- **D-1. 앵커를 남긴다.** `_sel` 을 집합으로 **대체**하면 그것을 읽는 열 곳이 전부
  바뀌고, 그중 하나라도 놓치면 "선택이 없다" 로 읽혀 조용히 아무 일도 하지 않는다.
  앵커는 그대로 두고 집합을 **더한다** — 기존 자리는 계속 옳다.
- **D-2. 다중을 받는 자리를 둘로 못 박는다.** 요구는 "다중 선택" 이지 "모든 조작의
  다중화" 가 아니다. 이름 변경에 다중이 무슨 뜻인지는 아무도 답하지 않았고, 답이
  없는 것을 구현하면 그 자리가 다음 사람의 함정이 된다.
- **D-3. 확인창은 하나다.** 열 개를 지우는데 창이 열 번 뜨면 사용자는 읽지 않고
  누른다 — 그 순간 확인창은 방어가 아니라 관문 통과 의식이 된다.
- **D-4. 조상·자손 겹침은 조상만 남긴다** (`FR-EMS-22`). 서버에 두 번 묻지 않는
  것이 목적이 아니라, **두 번째 요청의 실패가 사용자에게 거짓말을 하기 때문**이다.
