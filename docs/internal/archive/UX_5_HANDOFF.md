## 4. 값을 치르고 배운 것 (이번 세션)

- **e2e 전량 중에는 `web/` 과 `e2e/` 를 고치지 않는다** — 서버가 디스크의 웹 파일을 그대로 읽고, 샤드가 시험 파일을 늦게 읽을 수 있다. 전량 중에는 문서만 쓴다
- 전량이 끝나기 전에 사용자에게 다른 일을 받으면 `TaskStop` 으로 멈추고 다시 돌린다. 끝나면 알림이 오므로 기다리며 폴링하지 않는다
- 전량은 머신 부하에 따라 9분~25분이다. 샤드 하나만 늦을 수 있다 — 로그의 샤드별 마지막 줄로 진행을 본다(`LC_ALL=C sed $'s/\x1b\\[[0-9;]*[A-Za-z]//g' 로그 | LC_ALL=C grep -a "샤드 8/8" | tail -1`)
- 로그의 ANSI·한글 때문에 BSD `sed`·`grep` 이 "illegal byte sequence" 를 낸다 — `LC_ALL=C` 와 `grep -a` 를 쓴다
- **화면 확인은 임시 spec 으로 한다**: `e2e/zz-tmp-shot.spec.ts` 를 만들어 `page.screenshot({path:'/tmp/…'})` 하고 돌린 뒤 바로 지운다. 이번에 이렇게 두 결함을 잡았다(모바일 지문 복사 단추가 줄 아래로 떨어짐, 레일의 작업 중 점이 글자를 덮음)
- **CSS 우선순위 함정**: `.ds-row>:not(span:first-child)` 는 (0,2,1)이다. 컨테이너 쿼리 안의 규칙이 지려면 `.display-settings .ds-row>…` 처럼 올려야 한다. `#id` 규칙(예: 옛 `#pf-fp{flex:…}`)은 클래스 규칙을 이기므로 클래스로 바꾼다
- 단위 하네스의 vm 배열은 원형이 달라 `assert.deepEqual` 이 거절한다 — `JSON.parse(JSON.stringify(x))` 로 옮겨 비교한다
- 단위 하네스는 파일 일부만 읽는다 — 다른 모듈의 함수를 부를 때는 `if(this.x)` / `app.x?…:…` 처럼 있는지 먼저 본다(코드베이스 관례). 새 모듈을 부르는 기존 함수가 하네스에서 깨지면 이것이다
- 프로필 패널 단위 시험의 가짜 DOM 에는 `createElement`·`replaceChildren` 이 없었다 — 더했다(`profile-panel.test.mjs`)
- 모바일 설정은 목록→상세다 — 상세에서 다른 섹션으로 갈 때 `.mtab` 이 가려져 클릭이 안 된다. `el.click()` 을 `evaluate` 로 부른다
- 결정 표를 바꾸면 `go run ./scripts/gen-decisions` — 안 하면 `make gates` 가 진다
- V-LAY-1 실패가 "재지 않는 자리 N (지금에만 …)" 이면 키가 늘어난 것이다 → `LAYOUT_BASELINE=write npx playwright test e2e/ui-layout-defaults.spec.ts -g "V-LAY-1 "` 로 다시 뜨고 `UI_LAYOUT_DEFAULTS_SRS.md` §9 끝에 이전/새/이유를 적는다. 푸시 뒤 linux·win32 는 사용자에게 `layout-baseline` 워크플로를 부탁한다
- **서버 값의 뜻을 바꿀 때는 그 값을 읽는 모든 자리를 추적한다.** 4묶음에서 전경 이름(`fgName`)이 "프로그램이 돈다"에서 "탭을 부르는 이름"으로 바뀌었다. 읽는 자리 다섯(탭·작업 패널·Telegram 위치·`dmctl list-workspace`·화면 Map)을 확인했고, 틀린 주석 2곳과 `RUN_RECOVERY_SRS` §2.4 를 고쳤다
- **성능 함정**: darwin 의 `CWDs` 는 `lsof` 를 띄운다. 2초 주기 경로에 넣지 않는다 — 셸 훅 보고값(`reportedCwd`)이 먼저다(결정 D-21)
- 상시 경로에 외부 명령을 더하는 변경은 사용자에게 성능·정확도 맞바꿈을 쉽게 설명하고 고르게 한다(사용자가 "뭐가 더 정확하고 안전하냐"고 물었다)
- 4묶음의 새 모듈은 `web/js/core/app-work.js`(작업 중 표식). 모듈 500줄 한도 근처 파일: `app-attn.js` 488, `app-agents.js` 456, `sidebar-tabs.js` 474, `renderer-pane.js` 449

## 5. 변하지 않는 규약

- 순서: 스펙 → 테스트 RED → 구현 → 게이트·단위·타입·관련 e2e → 화면 확인 → 문서 개정 → **사용자 확인 뒤** 커밋·푸시
- 동작이 바뀌면 SRS·코드 주석에 이전/새/이유. 기존 e2e 단정을 바꿀 때도 `// UX_AUDIT_FIX_SRS FR-UXF-NN 로 개정: 이전 … / 지금 … / 이유 …`
- 커밋 메시지에 AI 서명 금지. `git checkout <파일>` 류 되돌리기는 분류기가 막는다 — 직접 편집하거나 백업 복사로 되돌린다
- 문서와 코드가 어긋나면 코드가 진실. 어긋남은 끝에 보고하고 사용자가 고르면 고친다
- 문서 개정 관례: 역사 서술은 지우지 않고 아래에 `> **<SRS> FR-… 으로 개정 (날짜)**: 이전 … / 지금 … / 이유 …`. `docs/external/features.md`·CHANGELOG `[Unreleased]` 도 고친다
- 툴팁(`title`)·`aria-label` 은 영어(FR-TIP-2), 보이는 글자는 로케일(FR-UXF-40). ko 카탈로그에 영어 값을 더하면 TC-UXF-40 허용 목록도 고친다
- 모서리는 `--radius-sm·md·lg·pill` 만(게이트 `check-radius.mjs`). 글자는 `--fs-*`, `--fs-xs` 는 기호 자리만(TC-UXF-44 단위 시험)
