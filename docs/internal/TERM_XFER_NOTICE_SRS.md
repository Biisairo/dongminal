# SRS: 터미널 전송 알림 — 화면 밖 팝업 — IEEE 29148

> **문서 상태**: 승인·구현완료

| 항목 | 값 |
|---|---|
| 문서 | TERM_XFER_NOTICE_SRS |
| 상태 | 구현 (e2e 는 다른 세션에서 실행) |
| 선행 | FILE_TRANSFER_SRS (FR-FTR-9·10·11) |
| 개정 | **FR-FTR-9·10 의 "터미널에 쓰는 줄" 을 이 문서가 대체한다.** FR-FTR-10 의 **금지**(엔터 미주입)는 그대로 살아 있다 |
| 후속 | 없음 |

## 1. 개요

### 1.1 목적

접수한 말은 이렇다.

> **"tab 에 드레그드롭하여 업로드 시 다른 키를 누르기전까지 프로세스가 남아있는
> 것 같다."** → 증상 확인: 업로드 줄만 찍히고 **셸 프롬프트가 다시 그려지지
> 않아, 명령이 실행 중인 것처럼 보인다.** 아무 키를 누르면 프롬프트가 돌아온다.
>
> 처방 확정: **"화면에 쓰지않고 하단 알림 팝업으로 성공함을 알린다."**

```
$ ↑ Uploading: a.txt
  ✓ a.txt (1.2KB)
█                     ← 프롬프트 없음, 커서만
(키 입력 후) $ █
```

### 1.2 원인 (조사로 확정한 사실)

`_say` 는 `this.term.write` 로 xterm 에 **직접** 쓴다 (`term-pane.js:532`). 그
글자는 pty 를 거치지 않으므로 셸은 그것을 모른다 — zle 은 자기 프롬프트가 여전히
원래 줄·열에 있다고 믿고, 그 믿음이 깨지는 것은 다음 키 입력이 라인을 다시 그릴
때다. 그래서 그 사이의 화면에는 프롬프트가 없다.

FR-FTR-10 이 엔터 주입을 금지했으므로(그 순간 돌고 있는 것이 셸이 아니면 그
프로그램이 엔터를 받는다) 프롬프트를 되돌릴 수단이 코드에 없었다. **금지가 옳고,
알림의 자리가 틀렸다** — 셸이 소유한 화면에 남이 쓰면 그 화면은 어긋난다.

### 1.3 정의

| 용어 | 정의 |
|---|---|
| **전송 알림** | 터미널 pane 의 업로드·다운로드가 사용자에게 알리는 한 줄 |
| **팝업** | 창 하단에 뜨고 스스로 사라지는 알림 요소 (`.toast`) |
| **진행 팝업** | 업로드가 끝나기를 기다리는 동안 떠 있는 팝업 — 완료 시 같은 요소가 성공 문구로 바뀐다 |

### 1.4 참조

- `web/js/ui/term-pane.js:532`(`_say`)·`:534`(`_downloadFile`)·`:540`(`_uploadFiles`)
- `web/style-git.css:360`(`.git-undo-toast` — 자리와 그림자의 선례)
- `web/js/core/constants.js:339`(`TERM_UPLOAD_NO_CWD`)
- `e2e/file-transfer.spec.ts:283~334` (FT11·FT12)

## 2. 현재 상태

```js
// term-pane.js:532
_say(s){ if(this.term) try{this.term.write(s)}catch{} }
```

`_say` 의 호출자는 **전송 넷뿐**이다 (`:538`·`:546`·`:554`·`:558`·`:561`·`:565`) —
다운로드 시작 한 줄, 업로드 시작·성공·실패, cwd 미확정 사유 둘. 터미널 화면에
쓰는 다른 알림은 없다. 그래서 이 함수를 지우면 셸의 화면에 남이 쓰는 자리가
사라진다.

---

## 3. 기능 요구사항

**FR-TXN-1** 터미널 전송 알림은 **터미널 화면에 쓰지 않는다.** `_say` 와 그 호출
여섯을 없앤다. 셸이 소유한 화면에는 pty 가 보낸 것만 남는다.

**FR-TXN-2** 알림은 **창 하단의 팝업**으로 뜬다. 자리는 **오른쪽 아래**, 상태바
위다 — `.git-undo-toast`(하단 **가운데**)와 자리를 다투지 않는다 (D-2).

**FR-TXN-3** 업로드는 **파일 하나마다 팝업 하나**다. 시작할 때 진행 팝업이 뜨고,
완료하면 **같은 팝업이** 성공 문구(이름 + 크기)로 바뀐다. 새 팝업을 겹쳐 띄우지
않는다 — 파일 하나의 일은 한 자리에서 끝난다.

**FR-TXN-4** 성공 팝업은 **3초** 뒤 사라진다. 실패와 사유는 **8초**다 — 읽고
판단할 것이 있는 알림은 더 오래 남는다.

**FR-TXN-5** **진행 팝업은 스스로 사라지지 않는다.** 큰 파일의 전송이 3초보다
길면 알림이 먼저 사라져, 사용자는 시작한 일이 없어진 것으로 읽는다 (D-3).

**FR-TXN-6** 팝업을 **누르면 곧바로 닫힌다.** 자동 소멸을 기다리는 것 말고 출구를
준다.

**FR-TXN-7** 팝업은 **여러 개가 쌓인다.** 파일 여럿을 떨어뜨리면 그 수만큼 서고,
최신이 아래에 온다.

**FR-TXN-8** 다운로드 알림(`_downloadFile`)도 같은 팝업이다. FR-FTR-9 의 불변은
유지된다 — **term 이 없어도 다운로드는 일어나고**, 알림이 실패해도 전송을 막지
않는다 (FR-TXN-10).

**FR-TXN-9** cwd 가 `tool` 이 아닐 때의 사유(FR-FTR-11)도 팝업이다. **업로드하지
않는다는 판정 자체는 불변이다.**

**FR-TXN-10** 팝업을 만들다 실패해도 **전송은 계속된다.** 알림은 전송의 조건이
아니다.

**FR-TXN-11 (FR-FTR-10 의 금지 존속)** 업로드가 끝난 뒤에도 **셸에 엔터를 보내지
않는다.** 이 문서는 알림의 자리를 옮길 뿐, 그 금지를 풀지 않는다.

## 4. 비기능 요구사항

**NFR-TXN-1** 팝업은 **모듈 하나**(`web/js/ui/toast.js`)에 산다. 호출자는
`Toast.show(text, kind, ms)` 하나만 안다.

**NFR-TXN-2** 컨테이너는 **처음 부를 때 만든다.** `index.html` 에 빈 자리를 두지
않는다 — 그 자리는 알림이 없을 때도 레이아웃에 참여하고, 소프트 리로드
(SOFT_RELOAD_SRS)가 본문을 다시 만드는 경로마다 그 자리를 지켜야 한다.

**NFR-TXN-3** 컨테이너는 **클릭을 통과시킨다** (`pointer-events:none`). 팝업 자신만
받는다 — 알림이 떠 있는 동안 그 아래의 터미널을 누를 수 없으면 알림이 방해가 된다.

## 5. 설계 결정

**D-1** 프롬프트를 되돌리는 두 길(**셸에 SIGWINCH 를 보내 zle 을 다시 그리게 하기**,
**`ESC[L` 로 프롬프트 줄 위에 알림을 끼워 넣기**)을 택하지 않았다 — 처방이 "화면에
쓰지 않는다" 로 확정되었다. 둘은 어느 쪽이든 셸의 화면을 우리가 계속 만지는
설계이고, 그러면 프롬프트가 여러 줄인 경우·입력 중인 줄이 있는 경우가 전부 우리의
문제가 된다. 화면 밖으로 나가면 그 문제 집합이 사라진다.

**D-2** 팝업의 자리를 pane 안이 아니라 **창 하단**으로 둔다. pane 안에 두면 좁은
분할 칸에서 터미널을 가리고, 칸마다 자리를 계산해야 한다. 창 하단은 한 곳이며,
`.git-undo-toast` 가 이미 쓰는 관용구다 — 다만 그것과 겹치지 않게 **오른쪽**이다.

**D-3** 진행 팝업에 자동 소멸을 주지 않는다 (FR-TXN-5). 진행이 끝나면 성공·실패로
**바뀌고**, 그때부터 시간이 흐른다. 시작과 끝을 두 팝업으로 나누면 끝나지 않은
전송의 알림이 사라져, 화면이 "아무 일도 없었다" 를 말하게 된다.

**D-4** `_say` 를 남겨 두고 팝업을 **덧붙이지** 않는다. 남기면 셸 화면 훼손이 그대로
남고, 이 문서가 고치려는 것이 고쳐지지 않는다.

## 6. 검증

e2e 는 **다른 세션에서 실행한다** (접수 시 지시).

| 요구 | 방법 | 자리 |
|---|---|---|
| FR-TXN-1 | e2e — 업로드·다운로드 동안 `term.write` 가 불리지 않는다 | `e2e/file-transfer.spec.ts` |
| FR-TXN-2·3 | e2e — 업로드 뒤 `.toast` 가 뜨고 성공 문구를 담는다 | 같음 (FT13 신설) |
| FR-TXN-4 | e2e — 성공 팝업이 3초 뒤 사라진다 | 같음 |
| FR-TXN-6 | e2e — 누르면 곧바로 사라진다 | 같음 |
| FR-TXN-9 | e2e — cwd 가 `server` 면 업로드하지 않고 사유가 **팝업**에 뜬다 | 같음 (FT12 개정) |
| FR-TXN-11 | e2e — 엔터(0x0d)가 가지 않는다 | 같음 (FT11, 불변) |

## 7. 비목표

1. **전송 밖의 알림을 팝업으로 이관하는 일** — Git·편집기의 오류 표시는 각자의
   자리를 갖고 있다.
2. **진행률(%)·취소 버튼** — 접수한 말 밖이다. 진행 팝업은 "하고 있다" 만 말한다.
3. **알림 이력·모아 보기.**
4. **탐색기 업로드**(`file-tree-xfer.js`) — 그쪽은 트리 안에 `_busy`·`_err` 로
   알리며, 셸 화면을 건드리지 않으므로 이 문서의 문제가 없다.
5. **셸 프롬프트를 되돌리는 일** — D-1 에서 버렸다. 프롬프트는 사용자의 다음 입력이
   되돌린다.
