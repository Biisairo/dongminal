### 교차 검사 — 다섯 대상 워크스페이스 clippy 통과 (커밋 rp/8.3 `b6596698`·`5dd07b26`)
- `rust/scripts/cross-check.sh [<triple>…]`: 다섯 대상에서 `cargo clippy --workspace --all-targets --keep-going -D warnings` 를 돈다. ring 의 C 는 check 에서 **컴파일만** 되면 되므로 대상별 C 툴체인 없이 돈다: C 컴파일러는 clang(`CC_<t>`), 헤더는 `-ffreestanding` + `rust/scripts/cross-check-include`(assert.h·string.h·stdlib.h 최소 선언, MSVC `_byteswap_*` 는 clang 내장으로), 아카이버는 rustup `llvm-tools` 의 llvm-ar(MSVC 는 `llvm-lib` 이름으로 불러 lib 형식). 이 C 산출물은 쓸 수 없다 — 검사 게이트일 뿐 빌드가 아니다. 필요 도구: clang, `rustup component add llvm-tools`(이 기계에 설치했다).
- 결과: aarch64/x86_64-apple-darwin, x86_64/aarch64-unknown-linux-gnu 는 그대로 통과. x86_64-pc-windows-msvc 는 경고 23건을 고친 뒤 통과. 모두 unix 전용 시험에서만 쓰는 import·상수·함수(`#[cfg(unix)]`), unix 에서만 바꾸는 `let mut`(`cfg_attr(not(unix), expect(unused_mut))`), gitapi ignore.rs 의 `set_readonly(false)`(Go os.Chmod 의 Windows 갈래와 같은 의도 — `expect(clippy::permissions_set_readonly_false)`)였다. 동작 변경은 없다. 고친 crate: ext, runtimebin(시험), daemon-ipc, claudeacct(시험), git-jobs(시험), ctl-cli, gitapi, httpapi, dongminal(시험). 고친 crate 의 호스트 격리 시험은 모두 통과했다.
- 이로써 "ring 때문에 교차 clippy 를 8.3 으로 미룸" 으로 적힌 crate 전부(1.6 reqwest 기능, 2.3·2.4.x 간선, 2.5, 2.6, 3.1·3.2·3.3 데몬, 4.5.x claudeacct, 4.6.x ext·lsp, 4.7 telegram, 5.4.x gitapi, 5.5.x httpapi, 6.1.x cli, 6.3.x runtimebin, 7.x dongminal)의 windows·linux 컴파일 검사가 끝났다. 3.3·3.2 의 "windows 분기가 컴파일 검사를 받지 않았다" 도 이것으로 닫힌다.

### 공급망 — cargo deny·audit 통과 (커밋 `d6a908f1`)
- deny.toml: `allow-wildcard-paths = true`(워크스페이스 path 의존, 모든 crate publish = false). 라이선스 예외를 crate 에만 열었다: notify `CC0-1.0`, xxhash-rust `BSL-1.0`(둘 다 허용적, 전역 허용 목록은 그대로). 권고 RUSTSEC-2026-0543(chrono 유지보수 중단 — 취약점이 아니다)은 사유를 달아 ignore. `cargo deny check` → advisories·bans·licenses·sources ok. `cargo audit` → 허용 경고 1건(chrono)만, 통과.
- **결정 후보(조정자·사용자)**: chrono 대체. DEPENDENCIES.md 가 로컬 시간대를 unsafe 없이 얻으려고 chrono::Local 을 골랐다(gocompat time zone, workspace recover, claudeacct alerts). 대체 후보는 `jiff`(허용 목록 밖) 또는 platform 의 unsafe localtime_r. 유지보수 중단만으로는 막을 이유가 없어 ignore 로 두었다.

### CI 게이트 스크립트 (커밋 `d6a908f1`)
- `rust/scripts/gates.sh [--test] [--go]`: fmt → 다섯 대상 clippy → cargo deny → cargo audit → [격리 `cargo test --workspace`] → [격리 Go `make gates`]. 전부 돌려 확인: Rust 단계 전부 통과, 격리 test 실패 0.
- Go `make gates` 는 rust-port 에서 **한 곳만** 실패한다: `docs/internal/RUST_PORT_SRS.md` 에 `> **문서 상태**: …` 머리줄이 없다(SRS 상태 필드 검사). 임시로 넣어 돌리면 나머지가 모두 통과한다("gates ok") — 되돌렸다. SRS 는 조정자 문서라 이 브랜치에서 고치지 않는다. 또 `--go` 는 저장소 루트 `node_modules`(espree 등)가 필요하다(`npm ci --ignore-scripts`, 8.3 worktree 에 깔았다).
- 2026-11-23 조정자 결정: chrono 는 사유 달린 ignore 로 두고 대체하지 않는다. chrono 를 직접 쓰는 crate(목록만):
  - `dm-gocompat` — `time/zone.rs:607` 로컬 시간대 오프셋(`chrono::Local`).
  - `dm-shared-workspace` — `recover.rs:75` 격리 파일 이름의 UTC 시각(`chrono::Utc::now().format`).
  - `dm-webserver-domain-claudeacct` — `alerts.rs:49·51` 유닉스 시각 → 로컬 시각(`DateTime::from_timestamp`·`with_timezone(&Local)`).

### linux 실기 (podman, linux/arm64 네이티브)
- `rust/scripts/linux-test.sh [--platform linux/amd64] [cargo test 인자…]`: 저장소를 읽기 전용으로 마운트하고, 산출물·레지스트리는 컨테이너 볼륨에 둔다. 컨테이너는 네트워크·PID·HOME 이 따로라 운영 인스턴스에 닿지 않는다. 조건: `--init`, ripgrep, `TZ=Asia/Seoul`, 병렬 1·디버그 정보 없음(2GiB VM 에서 httpapi 컴파일이 OOM 으로 죽었다).
- 첫 실행에서 실패 9건을 갈랐다.
  1. 좀비 6건(platform group_kills_descendants, git-core spawn 둘, git-jobs exec_stream 둘, lsp tunnel stop): init 이 없어 죽은 자식이 거둬지지 않았다. `--init` 으로 모두 통과. 제품 결함이 아니다.
  2. platform `real_pty_masters_and_child_ttys`: 시험이 `sh -c "sleep 30"` 의 sh 가 sleep 으로 exec 한다고 가정했다. Debian dash 는 그러지 않는다. `exec sleep 30` 으로 고쳤다(`4adb0528`).
  3. git-query `signature_ref_add_survives_stale_dir_mtime`: git 2.39 는 느슨한 ref 를 지울 때 빈 packed-refs(46바이트)를 새로 쓴다. 시험의 전제("mtime 근거가 그대로다")가 깨진다. Go 시험도 같은 전제라 git 2.39 linux 에서는 Go 판도 실패한다. 처음에 `git pack-refs --all` 로 packed-refs 를 만들고 그 mtime 도 고정하게 고쳤다(`4adb0528`). 서명 값이 바뀌는 제품 동작은 옳다.
  4. httpapi `golden_5572`: ① rg 가 없으면 `engine:"go"` — 골든은 rg 가 있는 환경에서 뽑았다. ② zip DOS 시각은 지역 시각이고 Go 정답을 KST 에서 뽑았다. Mac 에서도 `TZ=UTC` 면 같은 이유로 실패한다. 이 골든은 **rg 와 TZ=Asia/Seoul 을 요구한다**(환경 요구로 기록, 스크립트가 맞춘다).

### Windows — 실기 수단이 없으면 남는 것
컴파일·clippy(다섯 대상)로는 닫혔지만 실행으로 확인하지 못한 것들(이슈 기록에서 모음):
- **platform**: ConPTY(1.4.6), AF_UNIX IPC·소유자 전용 DACL(1.4.5, DIFF-1), Job Object·Ctrl+Break·toolhelp·iphlpapi(1.4.4), 셸·브라우저 선택과 PowerShell 인용(1.4.3, DIFF-2), `hostname` 의 GetComputerNameExW(3.3), handover 는 Unsupported(1.4.6·2.2.3).
- **gocompat**: Windows errno 문구 표와 로컬 시간대(1.1), FormatMessageW.
- **sysstat**(1.2): WinAPI CPU·메모리 지표.
- **데몬**: `listen_signal`(ctrl_c·ctrl_break), swap 의 Windows 갈래(perm·file_owner·listener_files·inherit_listeners)(3.2·3.3).
- **파일 경로**: 정션·대소문자 접기·canonicalize 머리(4.5.2), `same_file` 이 canonicalize 비교(Go 는 볼륨+인덱스), 링크 복사가 `symlink_file` 하나(5.5.7.1), gitapi `set_readonly(false)`.
- **lsp**: Job Object 를 kill 했을 때 stdout EOF(4.6.2).
- **ctl**: `%userprofile%`·`%PATH%` 문구(6.1.1), 서비스 설치 갈래, 런타임 헬퍼의 .exe·.cmd 이름 처리.
- **시험 자체**: Windows 에서는 `cargo test` 를 한 번도 돌리지 못했다. `#[cfg(unix)]` 로 빠지는 시험이 많아, Windows 의 시험 덮개는 unix 보다 얇다.
- 실기 수단 후보(사용자 결정): ① GitHub Actions `windows-latest` 러너에서 `cargo test --workspace`(push 가 필요하다 — 이 작업에서는 금지) ② Windows VM(UTM/Parallels, Windows 11 ARM 에서 x86_64 에뮬레이션 또는 aarch64-pc-windows-msvc 추가) ③ SSH 로 닿는 Windows PC. 어느 것이든 MSVC 툴체인(또는 cargo-xwin)이 있으면 `cargo test --workspace` 와 `dongminal verify` 를 돌리면 된다.
- linux/arm64 최종(`linux-test.sh`, rp/8.3 `b42d844b` 기준): 테스트 바이너리 184개, **3820 통과 / 실패 0**. aarch64, rustc 1.95.0, git 2.39.5, ripgrep 13.0.0. linux/amd64(에뮬레이션)는 돌리지 않았다 — 2GiB VM 에서 qemu 로 워크스페이스 전체를 빌드하면 몇 시간이 걸린다. `--platform linux/amd64` 로 같은 스크립트를 쓸 수 있다. amd64 는 다섯 대상 clippy 로 컴파일만 확인했다.
- 컨테이너 볼륨 `dm-rust-target-native`·`dm-rust-cargo-native` 는 다음 실행의 캐시로 남겼다. 내가 켠 podman VM 은 다시 껐다.
