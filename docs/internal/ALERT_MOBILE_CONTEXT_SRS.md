## 1. 개요

### 1.1 목적

접수한 말은 셋이다.

> ② **"알림 시 격하게 확인 가능하도록 browser unfocuse 처럼 태두리 점멸을
> 추가한다. 색상은 실제 알람 색과 같은 색으로 한다. 이 조절값은 browser unfocus
> 처럼 조절할 수 있도록 0~10 으로 조절되도록 한다. 기본은 5 이며 0 은 꺼짐이다."**
>
> ③ **"모바일모드에서 키보드는 키보드 버튼을 누를때만 올라오도록 수정. 터미널을
> 터치했을 시에는 올라오지 않는다. 하단 바에서 키보드 버튼을 제일 왼쪽으로 올린다.
> 추가로 ctrl+c 단축키도 추가한다."**
>
> ⑩ **"run 에서 context size 및 사용량 퍼센트 표기를 추가한다. (조정자 스스로의
> context 사용량은 확인 못하나?)"**

### 1.2 범위

**포함**
- ② 알림이 있는 동안의 화면 가장자리 점멸과 그 세기 설정(0~10)
- ③ 모바일에서 소프트 키보드가 올라오는 **유일한 계기**를 키바의 `⌨` 로 만드는 것,
  `⌨` 의 자리 이동, `^C` 키 추가
- ⑩ Run 패널의 컨텍스트 수치 표기 확대와 **조정자 자신의 컨텍스트 관측**
- (추가 접수) 설정값의 **창 사이 전파** — §3.4

**비포함**
- 알람의 **판정과 수명** — 무엇이 알람인지는 ATTENTION_LIFECYCLE 이 갖는다
- 기존 `#focus-edge`(포커스 잃은 창 표시)의 규약. 이 문서는 그것과의 **우선순위**만
  정한다
- 데스크톱의 키보드 동작. ③ 은 `body.mobile` 안의 일이다
- 컨텍스트 **정책**(임계·환산·창 넓히기) — UX_BATCH6_SRS FR-CTX-* 가 갖는다
- 승계(`run succeed`)·자동 교체 — 서버는 판단하지 않는다

### 1.3 정의

| 용어 | 정의 |
|------|------|
| **알림(주의)** | `app._attn` 에 실린 도구. 표시는 `.attn` (ATTENTION_PULSE_SRS §2.1) |
| **가장자리 표시** | 화면 네 변에서 안쪽으로 페이드아웃하는 오버레이 (UNFOCUSED_EDGE_SRS) |

| **조정자** | Run 을 여는 에이전트. **멤버 레코드가 아니다** (§2.5) |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 ② 가 본뜨려는 구조는 이미 완성돼 있다

`#focus-edge` 는 **정적 마크업**(`index.html`)이고, `--ufe-alpha`·`--ufe-alpha-mid` 를
JS 가 세우며, 보임은 `html.win-unfocused` 클래스가 정하고, 세기는 설정의 0~10
레인지(`focusEdgeLevel`, 기본 5, 0=끔)가 `/api/settings` blob 에 실린다. 조작 중
미리보기(`ufe-preview`)까지 있다.

**② 는 이 구조의 두 번째 사례다.** 다른 것은 셋뿐이다 — 계기(포커스 → 알림), 색
(반전 혼합 → `--attn`), 움직임(정지 → 2초 맥박).

### 2.2 알림의 전역 상태는 하나다

`app._attn`(Map, `app-attn.js`)이 알림 걸린 도구 전체를 든다. `_attnRefresh()`
(`:267`)가 `this._attn.size` 로 상단바 배지를 칠한다. **"워크스페이스 어디든 알림이
있는가" 는 이미 한 줄로 답이 나온다** — `app._attn.size > 0`.

색은 `--attn`(`#e0af68` 기본, 테마마다 다름)·`--attn-subtle`·`--attn-glow` 셋이며
`style.css:23` 에서 나온다. 맥박 애니메이션 6종이 이미 2초 주기로 돈다
(`attn-pulse-ring`·`-tab`·`-bar`·`-dot`·`-badge`·`-chip`).

### 2.3 모바일에서 키보드를 올리는 계기는 터치다

- `term-pane.js:754`(renderer) / xterm 자신이 터미널 요소의 클릭·터치에서
  `.xterm-helper-textarea` 에 포커스를 준다 → 소프트 키보드가 올라온다.
- 내리는 길은 둘이다: 스크롤 제스처가 판정되면 `_blurInput()`(`term-pane.js:352`),
  그리고 키바의 `⌨`(`act:'hidekb'`, `app-mobile.js`)다.
- `⌨` 는 키 배열의 **마지막**(맨 오른쪽)에 있다 — 열일곱 개 중 열일곱 번째다.
- `Ctrl` 은 sticky/lock 모디파이어이며, `Ctrl` 을 켠 뒤 `c` 를 **소프트 키보드로**
  쳐야 SIGINT 가 간다. 소프트 키보드를 올리지 않기로 하면(③) **지금 구조에서는
  Ctrl+C 를 낼 방법이 사라진다** — 그래서 접수한 말이 그 둘을 한 문장에 담고 있다.

### 2.4 ⑩ 의 절반은 이미 있다

멤버 카드는 `ctx ~13%` 와 등급 색을 보이고(`runs-panel.js:665~673`), 실측 토큰은
**툴팁에만** 있다(`128,000 / 1,000,000 토큰`). 그래프 노드는 4px 게이지 막대만
그린다(`:632~640`). 서버는 실측 토큰·모델·창 넓히기까지 이미 한다 (UX_BATCH6).

### 2.5 조정자의 컨텍스트는 **버려지고 있다**

접수한 물음("조정자 스스로의 context 사용량은 확인 못하나?")의 답이다.

1. 훅은 조정자에게도 붙는다 — `dmctl activity` 가 `toolId` 와 함께 실측 토큰·모델을
   `POST /api/runs/context` 로 보낸다 (`dmctl_activity.go:106`).
2. 서버는 그 `toolId` 를 **멤버 목록에서만** 찾는다 —
   `s.findByTool(toolID)`(`store_context.go:153`). 못 찾으면 `found=false` 로 **그대로
   버린다.**
3. 조정자는 멤버가 아니다. Run 레코드가 `CoordinatorToolID` 로 **따로** 든다
   (`store.go:189`). 프론트의 조정자 노드도 멤버가 아니라 합성된 가상 노드다
   (`runs-panel.js:594`), 그래서 게이지 조건이 `!m.coord` 다 (`:632`).

**즉, 신호는 이미 도착해 있고 저장할 자리만 없다.** 자리를 만들면 조정자의 사용량이
보인다.

### 2.6 사용자 결정 (2026-09-08 인터뷰)

- **D-1** ② 는 **워크스페이스 어디든 알림이 하나라도 있으면** 켜진다 (상단바 배지와
  같은 근거).
- **D-2** ② 와 `#focus-edge` 가 동시에 성립하면 **알림이 이긴다** — 그동안 포커스
  표시는 물러난다.
- **D-3** ③ 은 `inputmode=none` 을 걸고 **`⌨` 를 누를 때만 푼다.**
- **D-4** ③ 의 `^C` 는 **`Ctrl` 모디파이어와 같은 자리에 묶는다.**
- **D-5** ⑩ 은 셋 다 한다: 조정자 자신의 사용량, 숫자를 툴팁 밖으로, 그래프 노드에도
  숫자.

### 2.7 설계 결정

- **D-6 오버레이를 하나 더 둔다** (`#attn-edge`). `#focus-edge` 에 색만 바꿔 얹지
  않는 이유는 둘의 **계기와 움직임이 다르기** 때문이다 — 하나는 정지·반전 혼합,
  하나는 맥박·`--attn`. 한 요소에 두 규칙을 걸면 전이가 서로를 자른다.
- **D-7 우선순위는 클래스 하나로 정한다.** 알림이 있으면 `documentElement` 에
  `attn-edge-on` 이 붙고, CSS 가 그때 `#focus-edge` 의 `opacity` 를 0 으로 만든다.
  JS 가 두 오버레이를 각각 끄고 켜면 두 진실이 생긴다.
- **D-8 맥박은 CSS 애니메이션이다.** 주기·곡선은 `attn-pulse-*` 6종과 **같은 값**을
  쓴다 — 가장자리만 다른 박자로 뛰면 화면에 두 박자가 생긴다.
- **D-9 세기의 저장 키는 `attnEdgeLevel`** 이며 `focusEdgeLevel` 과 나란히 산다.
  하나의 값으로 둘을 조절하지 않는다 — 취향이 다르다(포커스 표시는 상시, 알림은
  드물게·강하게).
- **D-10 `inputmode` 의 진실은 하나다.** `TerminalTool` 이 `.xterm-helper-textarea` 의
  `inputmode` 를 소유하고, 키바는 그 메서드를 부른다. 두 곳이 직접 속성을 쓰면
  "올라와 있는데 none" 같은 상태가 생긴다.
- **D-11 키보드가 내려가면 `inputmode` 는 자동으로 `none` 으로 돌아간다.**
  `visualViewport` 가 이미 오르내림을 알고 있으므로(`_mobileVvApply`) 그 자리에서
  되돌린다 — 되돌리지 않으면 다음 터치가 다시 키보드를 올린다.
- **D-12 `^C` 는 모디파이어를 거치지 않는다.** 누르면 곧바로 `0x03` 을 보낸다.
  중단은 급할 때 누르는 것이고, 두 번 눌러야 하는 중단은 중단이 아니다. `Ctrl` 의
  sticky 상태와 무관하게 동작하며, 보낸 뒤 sticky 를 건드리지 않는다.
- **D-13 조정자 관측은 Run 레코드에 산다.** 멤버 배열에 가짜 멤버를 넣지 않는다 —
  멤버 수·목록·승계·메시지 라우팅이 전부 그 배열을 딛고 있다.
- **D-14 조정자에게 등급 통지를 보내지 않는다.** 멤버가 critical 이면 서버가 조정자에게
  한 번 알리는데(FR-CBG-7), **조정자 자신의 등급을 조정자에게 알리면** 그 통지가
  조정자의 컨텍스트를 더 먹는다. 관측은 기록하고 화면에만 보인다.

### 3.4 설정의 전파 (2026-09-08 추가 접수)

> **"설정값이 바뀌었을 때 다른 브라우저창은 바로 갱신이 안된다. 갱신되도록"**

원인은 설정에 **갱신 경로가 없었다**는 것이다. 값은 `/api/settings` blob 에 있고
브라우저는 부팅에서 한 번 읽는다. 게다가 그 "읽고 얹는" 일이 **두 곳**에 흩어져
키를 각자 나열하고 있었다 — `main.js` 의 부팅 로더(테마·단축키·상태바·주기·
프리셋·제목)와 `app-settings.js` 끝의 IIFE(브라우저 키·떠날 때 확인·가장자리·
줄바꿈·탭 너비·프로세스 이름). 그래서 "다시 얹을" 함수 자체가 없었다.

| ID | 요구사항 | 우선 |
|----|---------|------|
| FR-SYN-1 | 설정 blob 을 화면에 얹는 일은 **함수 하나**다 (`_settingsApply`). 부팅·SSE 방송·소프트 리로드가 같은 길을 지난다. | 필수 |
| FR-SYN-2 | `PUT /api/settings` 가 성공하면 서버가 `settings_changed` 를 SSE 로 방송한다. **저장이 끝난 뒤에** 알린다 — 먼저 알리면 받은 창의 `GET` 이 옛 값을 읽는다. | 필수 |
| FR-SYN-3 | 방송에 **본문을 싣지 않는다.** 이 blob 은 서버가 해석하지 않는 것이며, 실으면 그 순간부터 서버가 그 모양을 아는 셈이 된다. 받는 쪽이 `GET /api/settings` 로 읽는다 (`tools_background_changed` 와 같은 규약). | 필수 |
| FR-SYN-4 | 클라이언트에서 이 상태는 `STATE_REGISTRY` 의 항목 하나다 — `merge:'latest'`, 재검증 계기는 `sse:open` 과 `softreload`. 증분이 없으므로 `touched` 가 아니다. | 필수 |

### 3.5 비기능

- **NFR-1** ② 의 오버레이는 합성 레이어 하나다. 맥박은 CSS 가 돌리며 스크립트가
  프레임마다 도는 일이 없다.
- **NFR-2** ② 가 켜져 있어도 터미널 글자는 흐려지지 않는다 (blur 금지 — D-6 of
  UNFOCUSED_EDGE 와 같은 근거).
- **NFR-3** ③ 은 키 입력 지연을 늘리지 않는다. `inputmode` 는 속성 하나이며 전환은
  버튼을 누를 때만 일어난다.
- **NFR-4** ③ 이후에도 `visualViewport` 이벤트 처리는 프레임당 1회로 묶인 채다
  (FR-MTI-12·20).
- **NFR-5** ⑩ 은 훅의 핫패스를 늘리지 않는다. 보내는 것은 지금과 같은 페이로드이고,
  **transcript 내용은 어떤 형태로도 서버에 가지 않는다** (NFR-4 of ORCHESTRATION_V2).
- **NFR-6** 기존 e2e 통과. `attention-pulse`·`git-head-mobile`·`runs-*` 계열은 화면이
  더해지므로 **추가**가 있을 뿐 기존 단언이 깨지지 않아야 한다.

## 5. 리스크

- **MEDIUM — ③ 이 실기기에서만 드러나는 문제를 건드린다.** `inputmode` 에 대한 반응은
  엔진마다 다르다(WebKit 은 즉시, 일부 Android WebView 는 다음 포커스에서). 완화:
  `⌨` 가 `inputmode` 를 풀고 **blur 후 재포커스**하는 순서를 쓴다. 실기기 확인이
  검증의 일부다(`?diag=1` 오버레이가 이미 있다).
- **MEDIUM — ③ 이 붙여넣기·선택을 해칠 수 있다.** `inputmode=none` 은 IME 를 부르지
  않을 뿐 포커스와 클립보드 경로는 그대로여야 한다. V-7 이 포커스 유지를 못 박고,
  기존 `term-clipboard` e2e 가 나머지를 지킨다.
- **LOW — ② 의 시각 피로.** 전 화면 가장자리가 2초마다 뛴다. 완화: 기본 5(옅은 쪽),
  0 으로 완전히 끌 수 있음, 알림 해제와 동시에 멈춤.
- **LOW — ⑩ 의 서버 변경.** 도메인·핸들러·투영 세 곳이 늘지만 전부 **덧붙임**이며
  기존 멤버 경로를 고치지 않는다.
- **잔여** — 조정자가 여러 Run 을 동시에 열고 있으면 하나의 `toolId` 가 여러 Run 의
  조정자다. 그때는 **열린 Run 전부**에 같은 관측을 기록한다 (조정자는 하나의 대화이고
  그 컨텍스트도 하나다).

### 7.1 ③ 의 구현이 남긴 자리

- **`⌨` 의 뜻이 바뀌었다** — 내리기만 하던 버튼이 **두 방향**을 갖는다. `act` 도
  `hidekb` 에서 `kb` 가 됐고, 이름표는 `Dismiss keyboard` → `Toggle keyboard` 다.
  기존 e2e 둘이 그 위에 서 있어 함께 고쳤다 (`mobile-keybar` 의 이름표 표,
  `mobile-android-touch` 의 TC-MTI-21). 후자는 **출발 상태를 세워야 했다**:
  FR-MKB-1 이후 `inputmode` 는 `none` 이고 그 상태의 버튼은 *올리는* 쪽이므로,
  내리는 쪽을 재려면 먼저 `_kbAllow()` 로 풀어 둔다.
- **되돌림은 전이에서만 한다** (FR-MKB-7). `_mobileVvApply` 가 매 회차 되돌리면
  `⌨` 로 방금 푼 것을 — 키보드가 아직 올라오는 중이라 `isUp` 이 거짓인 그
  순간에 — 다시 잠근다. `keyboard-up` 이 참에서 거짓이 되는 순간만 본다.
- **되돌림의 대상은 터미널 전부다.** 포커스된 하나만 되돌리면 다른 칸의 터미널이
  풀린 채 남고, 그 칸을 터치하는 순간 키보드가 올라온다 — `inputmode` 는 요소마다
  걸리므로 대상도 요소 전부다.
- **모드 전환에도 다시 건다** (FR-MKB-13). 폭이 바뀌어 데스크톱이 되면 속성을
  걷는다 — 남겨 두면 물리 키보드 사용자가 IME 를 잃는다.
- **`Esc` 는 소스에 리터럴 제어문자로 들어 있다.** `^C` 도 같은 관례로 리터럴
  `0x03` 을 넣었다 (`'\x03'` 이스케이프가 아니다).

### 7.2 ⑩ 의 구현이 남긴 자리

- **어휘를 구조체로 뽑았다** (FR-RCX-8). `Member` 의 컨텍스트 필드 여덟이
  `ContextState` 가 되고 멤버에는 **임베드**된다 — Go 의 임베디드 구조체는 필드가
  승격되므로 `cur.ContextTokens` 같은 참조도, JSON 모양도 그대로다. 그래서 프론트·
  e2e·`runs.json` 이 한 줄도 바뀌지 않았다.
- **판정도 한 함수가 됐다.** 창 넓히기(FR-CTX-6)·추정 폴백(FR-CTX-4)·등급
  판정(FR-CBG-4)이 멤버 경로 안에만 있었다. `applyContextObservation` 으로 뽑아야
  조정자가 **같은 규칙**을 지난다 — 두 벌이면 화면의 두 자리가 다른 규칙으로
  색을 고른다.
- **`entered` 를 내지 않는 것이 통지를 막는 유일한 장치다** (FR-RCX-10 / D-14).
  호출자는 `entered != ""` 일 때만 통지하므로, 조정자 경로가 빈 값을 내면 통지
  경로 자체를 지나지 않는다. **기록은 남는다** — 알리지 않는 것과 재지 않는
  것은 다르다.
- **조정자는 멤버가 아니라는 사실을 빈 멤버 id 가 말한다.** 핸들러는 그것으로
  응답을 가르고 `coordinator:true` 와 `runId` 를 낸다 — 받는 쪽이 "멤버를 못
  찾았다"(`observed:false`)와 구분할 수 있어야 한다.
- **프론트에서는 `!m.coord` 제약 하나가 사라졌다.** 조정자에게 관측이 없어서
  뺐던 조건이고 이제 있다. 값이 없으면 `contextLevel` 이 비므로 남은 조건
  하나가 두 경우를 다 가른다.
- **`_runTokens` 는 M 단위에 소수 한 자리를 쓴다** (`1.0M`). 카드 본문의 기대값을
  쓸 때 그 표기를 확인해야 한다 (실측으로 알았다).

**②를 하며 확정된 것** — 가장자리 표시의 모양은 두 스펙이 공유한다. `--edge-fade`
하나가 둘의 액자를 정하고, 다른 것은 색(반전 vs `--attn`)과 움직임(정지 vs 맥박)뿐이다.
그 과정의 실측과 기각된 두 안은 [`UNFOCUSED_EDGE_SRS`](./UNFOCUSED_EDGE_SRS.md) D-5e 에 있다.
