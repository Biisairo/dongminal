# 4.1.1 git 실행 계층: core

## 목표

git 실행 계층(exec·spawn·guard·write·unguarded·record·recovery·exclusion·errors·oid·redact 등)을 옮긴다. git 명령 인자·환경변수·타임아웃·오류 분류 문구가 Go 와 같아야 한다. 프로세스 그룹(spawn.go 의 `platform.Current().Process.NewGroup`)은 1.4.4 의 Process trait 에 맞춰 쓰고, 그 구현이 필요한 시험만 1.4.4 완료 뒤로 남긴다. 시험 보조 `gittest`·`testpath` 는 1.5 가 dev 용으로 옮긴다 — 아직 없으면 같은 동작의 시험 전용 보조를 이 crate 의 tests 안에 두고, 1.5 완료 뒤 바꾼다.

### Go 와 다르게 한 내부 결정

- `Output.stdout` 은 `Vec<u8>`(Go string 은 바이트열 — `show` 로 연 바이너리·비 UTF-8 내용을 보존). stderr 는 lossy String(문구·JSON 에서 Go 와 같아진다)
- Ctx 의 사유는 처음 관측된 것으로 고정한다. `from_token` 토큰을 바깥에서 취소한 뒤 마감이 지나 처음 읽으면 DeadlineExceeded 로 보일 수 있다(드묾). 토큰은 마감에 스스로 취소되지 않는다 — `done()` 을 쓴다
- spawn 은 std::process + spawn_blocking 대기. 시한 A 에서 TERM 무시 리더에 Go 는 리더만 KILL, Rust 는 그룹 KILL(어차피 직후 그룹 KILL). 회수 시한을 넘긴 읽기는 읽기단을 닫지 못하고 스레드를 버린다(관측 차이 없음, 스레드 하나가 남을 수 있음)
- `ExecUnguardedText` 의 `missing` 인자를 뺐다 — git 부재면 `text=""` 와 감싸지 않은 오류를 돌려 호출자가 자기 사유로 바꾼다
- PATH 를 바꾸는 시험은 `Builder::path_env`(cfg(test))·`look_git(Some(path))` 로 우회(unsafe set_var 금지). kill grace·drain 시험은 내부 `spawn_with(grace, &Activity)` 로 전역 상태를 쓰지 않는다
- 신호로 죽은 git 의 문구(`signal: killed`)용 Go `ProcessState.String()`·`Signal.String()`(darwin·linux 표)를 core 안에 두었다 — gocompat 으로 옮길지 조정자 판단
- 기동 실패 문구는 `fork/exec <bin>: <go errno 문구>`(Go PathError 와 같음)
- gittest·testpath 는 아직 골격이라 `src/tests/support.rs` 에 임시 보조를 두었다(1.5 완료 뒤 바꾼다). Init 에 `commit.gpgsign=false` 를 더했다(GIT_CONFIG_GLOBAL 을 프로세스 전역으로 못 바꾸므로)

### 남은 위험

- 오류 문구는 Go 소스의 형식 문자열을 따라 썼고 시험으로 일부(ExecError·ctx_err·git_missing·repo_missing·signal) 확인했다. guard 계열 문구 전부를 go1.27.2 실측과 대조하지는 않았다
- 정적 게이트 V13(죽은 예외 없음)은 대상 crate 가 아직 없어 옮기지 않았다. httpapi fs-ignored 파일 이름(`handlers_fs_ignored*`)은 짐작이다
- exclusion_key·심링크 시험은 unix 만, spawn 시험은 POSIX 만(Go 와 같음)
- 4.1.2·4.1.3 은 시작하지 않았다(조정자 중단 공지)
