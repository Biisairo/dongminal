섰다. 서버 로그가 그 계기를 찍는다:

```
[ws-daemon] replay tool=… len=1784 end=1784 full=true since=-1   ← 데스크톱이 되찾으며
[ws-daemon] replay tool=… len=1894 end=1894 full=true since=-1   ← 모바일이 따라가며
```

**두 줄인 것이 정상이다** — 폭이 바뀐 클라이언트가 둘이므로 각자 한 번씩 다시 받는다.
그리고 여기서 멈춘다: 따라가는 쪽은 PTY 를 바꾸지 않으므로 되울림이 없다 (수렴 확인).

## 2. 배운 것

### 2-1. 사용자의 "원래는 됐었다" 가 두 번 다 맞았다

접수는 증상 둘이었고 첫 진단은 **둘 다 원리상 불가**로 기울었다. 사용자가 두 번 되물었다 —
*"다 다시그릴수는 없나?"* · *"위쪽 스크롤백도 원래 다시 터미널을 갱신하면서 모양이
회복되었었어. 초기엔 그랬어."* 두 번 다 실측이 사용자 쪽을 지지했다.

- 첫 되물음은 **회귀**를 찾게 했다. `git worktree` 로 `b2095a4`(FR-M9-3 직전)를 세워 재 보니
  옛 판은 되찾을 때 `tput cols` 가 151 로 돌아왔다
- 둘째 되물음은 **내 오진을 뒤집었다.** 나는 xterm 버퍼의 리플로우만 보고 "스크롤백은 다시
  그릴 원본이 없다" 고 단정했는데, 원본은 서버의 바이트 tail 이었고 그것을 새 폭으로 다시
  파싱하는 길(`full=true` 전량 재생)이 **이미 구현돼 있었다**

**교훈은 "사용자를 믿어라" 가 아니다.** 사용자의 증언은 *과거의 실측 기록*이라는 것이다.
코드에 없는 사실을 사용자는 겪어서 알고 있고, 그 시점을 `git worktree` 로 되세우면 그것이
재현 가능한 증거가 된다. 가설을 코드에서만 세우면 "지금 없는 것" 을 "원래 없던 것" 으로 읽는다.

### 2-2. 한 칸에 두 진실을 담으면 나중 것이 앞 것을 먹는다

`term.cols` 하나가 두 가지를 뜻하고 있었다 — 소유자에게는 **자기 폭**, 비소유자에게는
**PTY 폭**. FR-M9-3 이 후자를 더할 때 전자를 덮어썼고, 그래서 소유를 되찾는 순간 되보낼
자기 폭이 남아 있지 않았다. 고친 모양은 판정을 더한 것이 아니라 **칸을 하나 더 둔 것**이다
(`_ownCols`). 판정을 더했으면 "지금 어느 뜻인가" 를 묻는 자리가 호출부마다 생겼을 것이다.

### 2-3. 고친 기능이 만든 회귀는 그 기능의 검사에 걸리지 않는다

`term-size.spec.ts`(V-M9-3b)는 수정 전에도 초록이었고 지금도 초록이다. 그 검사가 재는 것은
"비소유자가 따라가는가" 이고, M10-B1 은 "따라가기가 **끝날 때**" 의 결함이라 재는 대상 밖이다.
기능을 더할 때 **그 기능이 끝나는 자리**를 함께 재지 않으면, 시작만 지키는 검사가 초록을 주고
그 사이로 회귀가 지나간다. `term-reclaim.test.mjs` 의 마지막 두 건이 그 경계를 양쪽에서 못박는다 —
"따라가기를 되돌리지 않는다" 와 "되찾으면 자기 폭이 나간다" 는 한 쌍이다.

### 2-4. 다시 그리는 길이 이미 있는지부터 물었어야 했다

`full=true` 재생은 `\x1b[3J` 로 스크롤백까지 지우고 tail 을 되뿌린다. 이 길은 M6 부터 있었고
지금도 새로고침마다 돈다 — 서버 로그 한 줄(`full=true since=-1`)이면 5초에 확인됐을 사실이다.
그것을 모르고 "원리상 불가" 로 결론을 냈다. `M9_PROGRESS` §2-31·§2-24 가 같은 것을 적었는데
(*"버리고 있던 것을 또 찾았다"* · *"없는 줄 알았던 것이 이미 있었다"*) 또 밟았다.
**응답·로그를 먼저 덤프하고 세는 규약**은 프로토콜에만 적용되는 것이 아니다.

## 3. 실측 방법

### 3-1. 회귀의 시점을 `git worktree` 로 되세우기

```
git worktree add --detach /tmp/dm-<sha> <sha>
cd /tmp/dm-<sha> && go build -o /tmp/dm-<이름> ./cmd/dongminal
DONGMINAL_HOST=127.0.0.1 /tmp/dm-<이름> start --isolated --port <다른 포트>
```

**포트를 판마다 다르게** 준다 — 같은 포트로 갈아타면 브라우저 탭이 어느 판을 보는지 흐려진다.
정지는 기동 출력이 찍어 준 줄 그대로이고, `--port` 를 빼면 운영 서버가 내려간다
(`M9_PROGRESS` §2-11). 끝나면 `git worktree remove --force` · `git worktree prune`.

### 3-2. 폭 의존성을 재는 한 줄

```sh
printf 'MARK'; printf '\033[%dGR\n' $(tput cols)
```

`\033[<W>G` 는 **절대 좌표**다. 줄바꿈과 달리 xterm 의 리플로우로 되돌아가지 않으므로,
"다시 그려졌는가" 와 "리플로우됐을 뿐인가" 를 가른다 — 그 줄의 **길이**가 답이다.
논리 줄 길이가 지금 폭과 같으면 다시 그려진 것이고, 옛 폭과 같으면 남은 것이다.

### 3-3. 재생이 델타인지 전량인지는 서버 로그가 답한다

```
LC_ALL=C grep -a 'ws-daemon\] replay' <격리홈>/server.log | tail
```

`full=true since=-1` 이면 전량(hard clear 포함), `full=false` 면 델타다. 클라이언트에서
추론하지 말고 이 줄을 읽어라 — `_seq` 가 무엇이었는지가 그대로 찍힌다.
