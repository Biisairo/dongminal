## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

**배포된 제품에서 들어온 문제를 받을 수 있어야 한다.** 지금은 세 가지가 없다.

1. 로그에 **수준이 없다.** 전부 같은 무게로 쏟아지고 걸러낼 수 없다.
2. 로그 줄끼리 **이어지지 않는다.** 한 요청이 남긴 세 줄을 사람이 시각으로
   짐작해 묶는다 — 동시 요청이 둘이면 그 짐작이 틀린다.
3. **죽은 사실이 남지 않는다.** 비정상 종료와 브라우저의 예외는 흔적 없이 사라진다.

### 1.2 범위 (Scope)

| 묶음 | 내용 |
|---|---|
| **L** 로그 | `log/slog` 전환 + `DONGMINAL_LOG_LEVEL`. **의존성 추가 0** |
| **R** 요청 ID | 미들웨어가 부여하고 접근 로그·핸들러 로그·데몬 RPC 로그가 함께 싣는다 |
| **D** 진단 | `GET /api/diag` — 집계 수치만 |
| **C** 크래시 | `.lastexit` 마커 + 프론트 `window.onerror`·`unhandledrejection` |
| **G** 게이트 | 새 `log.Printf` 금지 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|---|---|
| **요청 ID** | HTTP 요청 하나의 수명 동안 유일한 짧은 식별자. 응답 헤더와 로그에 함께 실린다 |
| **접근 로그** | `loggingMiddleware` 가 요청 끝에 남기는 한 줄 |
| **집계 수치** | 개별 요청·기기를 식별하지 않는 수. 세는 것이지 기록하는 것이 아니다 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 `log.Printf` 가 172곳이다

> **로드맵은 146곳이라 적었다.** 실측은 **172** 다 — 그사이 늘었다. 문서는
> 조용히 낡는다는 이 마일스톤의 전제가 로그 축에서도 참이다.

가장 많은 곳은 `internal/webserver/httpapi`(19파일)이고, 데몬·도구 허브·워크스페이스가
그 뒤다. 표준 `log` 는 **수준이 없다** — `dongminald accept: …` 같은 치명과
`settings loaded 1234 bytes` 같은 잡음이 같은 무게로 한 파일에 섞인다.

### 2.2 접근 로그와 핸들러 로그가 이어지지 않는다

`loggingMiddlewareFor` 는 `http METHOD PATH STATUS DUR addr=…` 한 줄을 남긴다.
핸들러가 그 요청 안에서 남긴 줄에는 **그 요청을 가리키는 것이 하나도 없다.**
동시 요청이 둘이면 어느 줄이 어느 요청인지 시각으로 짐작해야 하고, 그 짐작은
자주 틀린다.

데몬 RPC 는 더 멀다. `PanedRequest` 의 `ID` 는 **연결 안의 순번**이라 요청과 무관하다.

### 2.3 `/api/health` 는 있고 메트릭은 없다

M3 이 `GET /api/health` 를 만들었고 그것이 **어긋남을 답하는 자리**다.
`VERSION_HEALTH_SRS §6-5` 가 메트릭을 비목표로 갈라 두었다 — 헬스는 사람이 읽고
메트릭은 기계가 읽으며, **형식도 수명도 다르다.**

그래서 새 종단을 만든다. 다만 **헬스를 먼저 보고** 겹치는 것을 늘리지 않는다.

### 2.4 죽은 사실이 남지 않는다

기동이 정상 종료였는지 강제 종료였는지 알 방법이 없다. 브라우저의
`window.onerror`·`unhandledrejection` 훅은 **grep 0건**이다 — 프론트의 예외는
콘솔에만 남고 사용자가 그것을 신고에 붙이지 않는다.

## 3. 요구사항 (Requirements)

### 3.1 묶음 L — 구조화 로그

**FR-OBS-1** 로그는 `log/slog` 를 지난다. **의존성을 더하지 않는다**(표준 라이브러리).

**FR-OBS-2** 수준은 넷이다 — `debug`·`info`·`warn`·`error`.
`DONGMINAL_LOG_LEVEL` 이 하한을 정하고 기본은 `info` 다.
**알 수 없는 값은 `info` 로 떨어지고 경고하지 않는다** — 로그 설정 하나가 기동을
시끄럽게 만들 이유가 없다.

**FR-OBS-3** 전환은 `internal/shared/dmlog` 한 자리를 지난다. 각 파일이
`slog.Default()` 를 직접 부르지 않는다 — 요청 ID 를 붙이는 자리가 거기이기 때문이다.

**FR-OBS-4** 서식 있는 호출(`Warnf`)을 남긴다. 172곳을 전부 키-값으로 바꾸는 것은
**이 마일스톤의 위험 대비 이득이 없다** — 얻는 것은 수준·시각·요청 ID 이고, 그 셋은
서식을 유지한 채로 얻는다. 새로 쓰는 곳은 키-값(`Info(ctx, msg, "k", v)`)을 쓴다.

**FR-OBS-5** `log.Printf`·`log.Println` 은 **제품 코드에서 0곳**이 되고
`scripts/check-logging.sh` 가 재발을 막는다. 예외는 `dmlog` 자신뿐이다.

### 3.2 묶음 R — 요청 ID

**FR-OBS-6** 미들웨어가 요청마다 짧은 ID 를 부여한다. 게이트 **앞**에 선다 —
거절된 요청도 ID 를 갖는다. 거절이야말로 사용자가 묻는 자리다.

**FR-OBS-7** 클라이언트가 `X-Request-Id` 를 보내면 **그것을 쓴다.** 단
길이·문자를 제한한다(최대 64, `[A-Za-z0-9_-]`) — 로그에 실리는 값이므로
줄바꿈이 섞이면 로그가 위조된다.

**FR-OBS-8** 응답에 `X-Request-Id` 가 실린다. 사용자가 화면에서 그 값을 집어
로그를 찾는다.

**FR-OBS-9** 접근 로그·핸들러 로그·데몬 RPC 로그가 **같은 ID** 를 싣는다.

**FR-OBS-10** 데몬 RPC 는 **그 호출 자리에서** 기록되며 그 줄이 요청 ID 를 든다.
`httpapi` 가 `ToolHub` 를 요청에 매인 겹(`reqHub`)으로 감싸고, 상태를 바꾸는
호출(`create`·`delete`·`resize`·`paste`·`background`)이 한 줄을 남긴다.

읽기 호출은 남기지 않는다 — 요청당 수십 번 나므로, 남기면 이 줄이 로그를 덮어
정작 쫓으려던 것을 가린다.

**FR-OBS-11** **와이어를 바꾸지 않는다.** `PanedRequest` 에 필드를 더하지 않는다.

> **처음 설계를 실물이 뒤집었다.** `ToolClient` 자신이 요청 ID 를 들게 하려면
> 손잡이를 요청마다 얕게 베껴야 하는데, 그 구조체 안에는 `sync.Mutex`·`sync.Once`
> 와 **연결·대기 표가 함께 있다** — 베끼면 복사본이 제 뮤텍스를 갖고 같은 map 을
> 만지는 **경합**이 된다. 공유 상태를 포인터 뒤로 옮기는 재구성은 700줄짜리 연결
> 관리 파일을 통째로 흔들고, 이 마일스톤이 사려는 것보다 비싸다.
>
> 기록을 경계로 올리면 **얻는 것은 같다** — RPC 가 자기를 부른 요청을 가리킨다.
> 얻지 못하는 것은 **데몬 프로세스 쪽 로그**의 상관관계이고, 그것은 비목표 7 이다.
>
> 쓰는 사람이 없는 와이어 필드를 남기지 않는 것도 같은 규칙이다 — 채울 계획이
> 없는 자리는 다음 사람에게 "예정" 으로 읽힌다 (`authGate` 에서 배운 것).

### 3.3 묶음 D — `GET /api/diag`

**FR-OBS-12** `GET /api/diag` 가 JSON 으로 낸다.

| 필드 | 뜻 |
|---|---|
| `tools` | 살아 있는 도구 수 |
| `ws` | 열린 WebSocket 수 |
| `goroutines` | `runtime.NumGoroutine()` |
| `allocMB` | 힙 할당(MiB) |
| `persistErr` | 마지막 영속 실패 (없으면 빈 문자열) |
| `gate.access` · `gate.request` | 게이트별 **거절 수** |
| `reconnects` | 데몬 재연결 수 |
| `uptime` · `version` | 기동 시각으로부터의 초 · 빌드 판 |

**FR-OBS-13** **개별 식별 정보를 싣지 않는다** (집계 수치만). 인증이 없으므로
이 종단도 ACL·출처 게이트 뒤에 있을 뿐이며, 거기까지 온 요청은 이미 허용된
기기다 — 그렇더라도 **세는 것과 기록하는 것은 다르다.** 주소·경로·도구 이름을
싣지 않는다.

**FR-OBS-14** 헬스와 겹치지 않는다. 판 불일치·워크스페이스 rev 는 `/api/health`
의 것이고 여기 두지 않는다 (`VERSION_HEALTH_SRS §6-5`).

### 3.4 묶음 C — 크래시 마커와 프론트 훅

**FR-OBS-15** 서버는 기동 시 `<home>/.lastexit` 를 읽어 **마지막 종료가
정상이었는지** 판정하고 로그에 남긴다. 그 뒤 `running` 으로 덮고, 정상 종료
경로에서 `clean` 으로 쓴다.

**FR-OBS-16** 파일이 없으면 **첫 기동**이며 비정상이 아니다.

**FR-OBS-17** `doctor --bundle` 이 이 마커를 담는다. **새 수집기를 만들지 않는다**
— 번들은 이미 있고 마스킹도 `SanitizeRemote` 한 벌이다.

**FR-OBS-18** 브라우저가 `window.onerror` 와 `unhandledrejection` 을 건다.
**서버로 보내지 않는다** — 종단을 새로 파면 그 종단이 오류 폭주의 증폭기가 된다.
대신 **마지막 N건을 메모리에 쥐고** 진단 패널이 보여 준다.

**FR-OBS-19** 훅은 기존 오류 표시를 **바꾸지 않는다.** 관측이지 처리가 아니다.

### 3.5 묶음 G — 게이트

**FR-OBS-20** `scripts/check-logging.sh` 가 제품 코드의 `log.Printf`·`log.Println`·
`log.Fatal*` 을 잡는다. 검사 파일은 지나간다 — 검사의 출력은 제품의 로그가 아니다.

## 5. 결정 (Decisions)

| ID | 결정 | 근거 |
|---|---|---|
| **D-OBS-1** | 서식 있는 호출을 남긴다 | 172곳을 키-값으로 바꾸는 위험 대비 이득이 없다. 얻으려던 수준·시각·요청 ID 는 서식을 유지한 채 얻는다 |
| **D-OBS-2** | 요청 ID 는 **게이트 앞**이다 | 거절된 요청이야말로 사용자가 묻는 자리다. 뒤에 두면 그 물음에 답할 수 없다 |
| **D-OBS-3** | RPC 기록을 **`httpapi` 경계**에 둔다 | `ToolClient` 를 요청마다 베끼면 뮤텍스와 연결 표가 함께 복사되어 **경합**이 된다. 얻는 것은 같고 흔드는 범위가 훨씬 작다 |
| **D-OBS-3a** | 와이어에 `reqId` 필드를 **더하지 않는다** | 채울 계획이 없는 자리는 "예정" 으로 읽힌다. `authGate` 에서 배운 것 |
| **D-OBS-4** | 프론트 오류를 **서버로 보내지 않는다** | 종단을 새로 파면 오류 폭주의 증폭기가 된다. 메모리에 쥐고 진단 패널이 보인다 |
| **D-OBS-5** | 진단은 **집계만** 싣는다 | 세는 것과 기록하는 것은 다르다. 인증이 없다는 사실이 이 선을 더 굵게 만든다 |
| **D-OBS-6** | 크래시 마커는 `doctor --bundle` 에 **얹는다** | 새 수집기를 만들기 전에 이미 있는 것을 본다 — `G4-3`·`G2-6` 이 번들과 겹친다 |

## 6. 비목표 (Non-goals)

1. **원격 로그 전송·집계 백엔드.** 단일 사용자 제품이다.
2. **Prometheus 등 노출 형식.** `/api/diag` 는 JSON 이고 그 소비자는 `doctor` 다.
3. **분산 추적(span).** 프로세스가 둘(서버·데몬)이고 ID 하나로 충분하다.
4. **172곳의 키-값 전면 전환.** D-OBS-1.
5. **프론트 오류의 서버 수집 종단.** D-OBS-4.
6. **로그 회전 정책 변경.** `FR-LOG-1`(`capHomeLogs`)이 이미 있다.
7. **데몬 프로세스 쪽 로그의 상관관계.** 데몬은 여러 호출자의 RPC 를 한 스트림에
   섞어 쓰므로 그쪽을 묶으려면 와이어 판을 올려야 한다. 서버 쪽 줄만으로 "어느
   요청이 어떤 RPC 를 불렀는가" 에 답할 수 있고, 그것이 사람이 묻는 물음이다.
