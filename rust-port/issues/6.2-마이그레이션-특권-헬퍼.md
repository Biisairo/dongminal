# 6.2 마이그레이션·특권 헬퍼

## 목표

홈 마이그레이션과 특권 헬퍼 클라이언트·OTP 를 옮긴다. 실제 특권 헬퍼(`/Library/PrivilegedHelperTools/com.dongminal.helper`)는 호출하지 않는다.

## 대상 Go 코드

- `internal/ctl/migrate`
- `internal/ctl/privhelper`

프로덕션 코드 약 1590줄.

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  - 한 것: rp/6.2 에 `port(1.5): humancmd Client`(a31ae0ff) 커밋 — `Client{path, timeout}::info·sign`, IPC dial + 왕복 전체 절대 마감, 가짜 소켓 서버 시험 5개(humancmd 시험 18개 통과). 6.2 crate(dm-ctl-migrate, dm-ctl-privhelper) 코드는 아직 쓰지 않았다(커밋할 미완 코드 없음). Go 코드·시험은 모두 읽었다(프로덕션 1590줄, 나누지 않아도 되는 규모).
  - 다음에 할 일(설계 메모)
    - migrate: 값은 `serde_json::Value`/`Map` 으로 다루고 출력은 `dm_gocompat::json::marshal`(키 정렬). 맨 위 디코딩은 `json::GoTyped` 로 Go 타입 이름(`map[string]interface {}`, `[]interface {}`)을 맞춘다 — 오류가 `workspace 파싱: …` 으로 CLI 에 나간다. schemaVersionOf 는 float64 단언 뒤 int 절삭. 파일 오류 문구는 gocompat `path_error`(`open`/`write`/`remove`). 데몬 생존은 `platform::current().process.alive`. uuid 생성기는 `dm_shared_uuid::new_string`.
    - privhelper: TOTP 는 hmac+sha1, base32 는 data-encoding(Go NoPadding 디코딩처럼 \r\n 무시·남는 비트 허용 설정), 키는 base64 비엄격 디코딩. Secret.recovery 는 null 왕복을 위해 `Option<Vec<String>>`, 저장은 `marshal_indent("", "  ")`(끝 줄바꿈 없음) + write_file_atomic 0600, 폴더 0700 chmod. peer uid 는 macOS 에서 nix `sockopt::LocalPeerCred`(unsafe 없음), 다른 OS 는 모두 거부. geteuid·chown 은 nix. 서버의 읽기는 humancmd 의 줄 읽기·마감 래퍼를 공개해(지금은 private) 재사용한다. `status` 는 시험에서 실제 소켓에 닿지 않게 경로를 받는 내부 함수로 나눈다. 시간 표시는 gocompat `format_rfc3339(to local)`.
    - 시험은 Go 시험(migrate 4개 파일·privhelper 3개 파일)을 그대로 옮기고, 실제 /var/run/com.dongminal.helper.sock 이나 /Library 경로에는 닿지 않는다.
  - 찾은 문제(고칠 후보, 조정자 확인 필요)
    - FR-RSP-7 결함: migrate.Run 에서 workspace.json 이 `null` 이면 Go 는 nil map 에 쓰다가 패닉한다. Rust 판은 빈 객체로 다루는 것을 제안(산출 `{"schemaVersion":2}`).
    - FR-RSP-6 후보: privhelper Server 는 연결마다 고루틴을 만들고 동시 연결 수 상한이 없다. 같은 uid 의 에이전트가 연결을 쌓으면 fd 가 바닥나 Accept 오류로 Serve 가 끝나고 도우미가 죽는다(launchd 가 다시 띄운다). 동시 연결 상한(예: 32)과 초과 연결 즉시 닫기를 제안. 정상 사용(한 번에 한 연결)에는 차이가 없다.
  - 남은 위험: 위 두 결정이 아직 없다. Go 의 per-connection 5초 마감은 절대 마감이므로 Rust 에서도 humancmd 와 같은 절대 마감 래퍼로 해야 한다(읽기마다 다시 거는 시간 제한이면 느린 송신으로 연결을 오래 붙들 수 있다).
