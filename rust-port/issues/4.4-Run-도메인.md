**공개 API 요약 (`dm-webserver-domain-run`)**
- 타입: `Record`·`Member`·`ContextState`·`Worktree`·`MsgEvent`·`Assignment`. JSON 은 Go 와 같다. `Member` 는 Go 의 ContextState 임베드를 `context` 필드로 두되, 직렬화는 평탄화한다(직접 짠 Serialize/Deserialize). Go 의 문자열 타입(Projection·Isolation·State·MemberState·Outcome)은 `String` 과 상수(`INLINE`·`OPEN`·`STARTING`·`OUTCOME_SUCCEEDED` 등)로 두었고, 검사는 `valid_projection`·`valid_isolation` 이 한다.
- `Error` 는 enum 이다. `code()` 는 Go sentinel 문구를 낸다. `Display` 는 Go `err.Error()` 와 같다(`invalid_argument: …`). `TreeOpen{run_id}`·`NodeTaken{member_id}`·`Write(문구)` 가 있다.
- `Store::new(dir).with_clock(..).with_id_gen(..).with_writer(..)`, `load()`. 조회: `get`·`list`·`changes()`(pollwait)·`has_open`·`member_by_tool`·`find_member`. 쓰기: `start`·`add_member`·`report`·`close(id, force) -> (Result<Record>, Vec<Member>)`·`sweep`·`delete`·`reap_targets(Option<&dyn Fn(&str)->bool>)`·`mark_worktrees`·`move_coordinator`·`append_message`·`attach`·`detach`·`update_assign`·`has_open_child`·`observe_context -> Option<(Member, entered)>`·`succeed -> (prev, next)`·`handoff`·`handoff_waiting`·`give_up_handoff`.
- 함수: `preamble`·`tree_preamble(&Record, &Member, &TreeContext)`·`handoff_clause`·`check_close -> Result<Vec<Member>, (Error, Vec<Member>)>`·`short`·`path_slug`·`headless_tool_ids`·`window_for_model -> Option<f64>`·`widen_window`·`ContextPolicy{..}::{default_policy, ratio, estimate_tokens, grade, level}`.

**테스트**: `tests/go_parity.rs` 는 `testdata/goref`(Go 참조 시나리오)를 빌드해 돌린다. 출력 355줄(반환 JSON·오류 문구 39개·프리앰블·트리 프리앰블·인수인계 절·runs.json 원문·다시 읽은 목록)을 Rust 같은 시나리오와 바이트 단위로 비교하며 같다. `tests/store.rs` 11개는 쓰기 실패와 되돌림, 첫 저장 실패, 깨진·없는 파일, compact 파일, 메시지 500개 상한, 관측 시각만 바뀌면 쓰지 않기, 정책 등급, 창 크기, 어휘, headless 도구, 옛 필드(epoch·aborted) 읽기를 본다. Go 테스트 약 130개의 관측 동작은 이 둘이 함께 덮는다. 시나리오 하나에 묶은 것은 토큰 절약을 위한 결정이다.

**Go 와 다르게 한 내부 결정**
- 저장: Go 는 runs.json 쓰기 동안 store 잠금을 풀고, 세대 번호로 나중 저장의 성공·실패를 맞춘다. Rust 는 쓰기 동안 잠금을 쥔다. 저장이 직렬화되므로 "나중 저장이 앞 실패를 덮는다"는 경우가 생기지 않는다. 실패하면 마지막으로 쓴 스냅숏으로 되돌린다. 파일 결과와 반환값은 같고, 쓰기 중 읽기가 기다린다는 점만 다르다(Go `TestSave_WriteDoesNotHoldStoreLock`·동시 저장 순서 시험은 옮기지 않았다).
- `short`·`path_slug` 는 Go 처럼 바이트로 자른다. 글자 경계가 아니면 손실 변환(U+FFFD)한다(Go 는 깨진 바이트를 그대로 둔다. uuid 에서는 생기지 않는다).

**남은 위험**
- 위 저장 잠금 결정으로, 느린 디스크에서 쓰기 동안 조회가 기다린다(성능 차이, 관측 결과는 같다).
- `dm-shared-platform` 의 `ipc::tests::stream_errors_match_go` 가 전체 실행에서 가끔 실패한다(이 이슈와 무관, 2.1 후속에서 보고).
- 2026-11-23 조정자: rust-port 에 병합(51e1bec3). 저장 중 잠금을 쥐는 결정은 NFR-RSP-3(핫패스 지연이 Go 보다 나쁘지 않을 것)에 어긋나므로 Go 처럼 잠금을 풀고 세대로 맞추는 후속 커밋을 요청했다.
