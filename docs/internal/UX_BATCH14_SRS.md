# SRS: 작업 화면 다듬기 — 레일 상태 · 사용량 머리 · 슬롯 흐림 · 이슈트리 원천 — IEEE 29148

> **문서 상태**: 승인·구현중
> **승인**: 2026-11-26 사용자 승인(§10 가정 포함)
> **남은 것**: 묶음 H · S · I 구현 (R 끝남)
> **접수**: 2026-11-26 대화(인터뷰). 원본은 사용자 메모장 `memo` 46~60줄이다. 사용자 결정은 §4, 사용자가 아직 확인하지 않은 가정은 §10 이다.
> **구현 순서(사용자 결정)**: 묶음 R(레일 상태) → H(사용량 머리) → S(슬롯 흐림·배경) → I(이슈트리 원천).
> **개정 대상**: `UX_BATCH12_SRS` FR-ACF(레일 카드), `CLAUDE_ACCOUNTS_SRS` FR-CAC-90~93(칸 라벨), `WINDOW_SLOTS_SRS`(포커스 표시), `ISSUE_AGENT_TREE_SRS` 묶음 D(트리 노드). 자세한 것은 §8 이다.

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

사용자 메모(2026-11-26)는 다음과 같다.

> 패널에 마우스 올라갔을 때 연결된 슬롯 화면 빼고 전체 블러 — 다른 창, 다른 기기에서도 가능? 안 되면 그 창에서 다른 슬롯 있을 때만이라도. 포커스 없는 슬롯 배경 색 다르게 — 슬롯뿐 아니라 다른 pane 도?
>
> issue tree 에서 어차피 gh 를 사용하니 gh 로 이슈들을 가져와서 그리는 방식. 이슈가 추가, 제거, 변경되면 알아서 tree 도 업데이트해야 한다. 거기에서 에이전트가 연결된 트리는 다르게 보여주면 된다.
>
> 사용량에서 폴더 헤더에 남은 초기화 시간 보여주기. 사용량에서 접은 계정들 폴더 헤더와 같은 모양으로 만들기. 세션, 주간 대신 5h, 7d 로 표시.
>
> agents 에서 레일모드일 때 각 에이전트에 상태 표시.

## 2. 현황 (Identified Facts, 2026-11-26 코드 조사)

### 2.1 레일 상태
- 펼친 카드는 상태 점 `.ag-dot.<state>`(`AGENT_STATE_ICON`)과 `.ag-state`(`AGENT_STATE_LABEL` · 도구)를 그린다(`agents-controller.js` `_agCardEl`).
- 레일은 `.ag-state`·`.ag-detail`·`.ag-usage`·`.ag-sub`·`.ag-dot` 을 모두 숨긴다(`style-activity.css` 38~60). 그 주석은 「상태 띠가 대신한다」 고 적지만, 카드에 상태 class 가 없고 띠 CSS 도 없다. **레일에는 상태 표시가 없다.**

### 2.2 사용량
- 요약 줄의 칸은 남은 시간(`.cacct-cell-left`)을 이미 그리지만 CSS 가 숨긴다(`style-activity.css` 368 주석, 레일은 65~66).
- 접힌 계정 행은 `_actCellsEl` 로 칸 두 개를 그린다. 값은 `claudeAcctView` 의 `mini` 다.
- 칸 라벨은 `usage.sl.*`(ko `세션`/`주간`, en `Session`/`Week`), 레일 라벨은 `usage.rail.*`(`5h`/`7d`), 막대 블록 제목은 `usage.win.*`(`현재 세션`/`이번 주`)이다.
- 시험 `ux-wording-ko.test.mjs` 의 `LATIN_KEYS`, `claude-accounts-foot.test.mjs` 가 라벨 키에 묶여 있다.

### 2.3 슬롯
- 에이전트 카드에 hover 동작이 없다(`.ag-card:hover` 는 카드 바탕만 바꾼다).
- 포커스 없는 슬롯은 바탕이 같다. 포커스 슬롯만 머리 글자색·밑줄이 강조색이다(`style-workspace.css` 112~118). 그 주석은 `.pn-dimmed`(소유권 없음)의 뜻 때문에 흐리게 하는 방식을 쓰지 않는다고 적는다.
- 슬롯 구성은 브라우저마다 로컬이다(FR-WSL-72). hover 를 창·기기 사이에 나누는 수단은 없다.

### 2.4 이슈트리
- `GET /api/runs/tree?ref=` 는 같은 트리의 열린 Run 멤버만 노드로 낸다. 부모는 역할 이름의 `›` 사슬이다. 응답 모양은 Go 골든이다.
- 서버는 gh 를 부르지 않는다. gh 는 `/otterminal:issue-tree` 명령 문서가 에이전트에게 쓰게 한다(GraphQL `subIssues(first:100)`).
- 대시보드는 채널 토픽 `run:<id>` push 때 `/api/runs/tree` 를 다시 읽는다. 이슈 원천의 변경을 보는 계기는 없다.
- 로컬 트리는 Run 의 `issueDir` 로 판정한다(`storage_of`).
- 배치(`runTreeLayout`)는 위에서 아래로 내려가는 모양이다(FR-ITC-6). 잎 노드는 모두 가로로 나란히 서고, 노드 하나가 가로 `RUN_TREE_NODE_W`(184) + `RUN_TREE_GAP_X`(24) 를 차지한다. 잎 20 개면 폭이 4,000px 을 넘어, 맞춤 보기에서 글자를 읽을 수 없다(사용자 지적 2026-11-26).

## 3. 요구 (Requirements)

### 3.1 묶음 R — 레일 상태

- **FR-RAS-1** — 레일 모드의 에이전트 카드는 펼친 카드와 같은 상태 점(`.ag-dot.<state>`, 같은 색·아이콘)을 카드 위쪽 가운데에 보인다.
- **FR-RAS-2** — 레일 카드에 마우스를 올리면 `<상태 이름> · <도구>`(도구가 없으면 상태 이름만)를 title 로 보인다.
- **FR-RAS-3** — 상태가 바뀌면(`tool_activity`) 레일 카드의 점도 바뀐다. 펼친 모드는 바뀌지 않는다.
- **FR-RAS-4** — `style-activity.css` 의 「상태 띠가 대신한다」 주석은 실제 동작에 맞게 고친다.

### 3.2 묶음 H — 사용량 머리

- **FR-UHD-1** — 요약 줄의 칸은 남은 초기화 시간(`limitShortLeft` 꼴, 예: `2h`·`4d`)을 보인다. 레일의 요약 줄은 폭이 좁아 지금처럼 숨긴다.
- **FR-UHD-2** — 접힌 계정 행은 요약 줄과 같은 모양이다: 같은 칸 구성(라벨 · % · 막대 · 남은 시간), 같은 DOM class 와 같은 CSS 규칙을 쓴다. 계정 이름·색 바·접기 동작은 지금 그대로다.
- **FR-UHD-3** — 칸 라벨 `usage.sl.*` 은 ko·en 모두 `5h`·`7d` 다.
- **FR-UHD-4** — 펼친 계정의 막대 블록 제목 `usage.win.*` 도 ko·en 모두 `5h`·`7d` 다.
- **FR-UHD-5** — 바뀐 라벨 키는 `LATIN_KEYS` 등 문구 시험의 허용 목록에 이유와 함께 넣는다.

### 3.3 묶음 S — 슬롯 흐림·배경

- **FR-SFX-1** — 에이전트 카드에 마우스를 올리면, 그 카드의 탭을 가진 슬롯(슬롯의 창에 그 탭이 있다)을 뺀 나머지 슬롯을 흐리게 한다(CSS `filter: blur`, 값은 디자인 토큰).
- **FR-SFX-2** — 다음이면 아무것도 하지 않는다: 슬롯이 하나다, 이 화면의 어느 슬롯에도 그 탭이 없다, 모든 슬롯이 그 탭을 가진다.
- **FR-SFX-3** — 마우스가 카드를 떠나면 곧바로 흐림을 푼다. 카드가 다시 그려지거나 사라질 때, 슬롯 구성이 바뀔 때, 끌기(drag)가 시작될 때도 푼다. 흐림이 남는 경로가 없어야 한다.
- **FR-SFX-4** — 흐림은 이 브라우저 화면에서만 한다. 서버·다른 창·다른 기기에 알리지 않는다. 모바일 화면에서는 하지 않는다.
- **FR-SFX-5** — 슬롯이 둘 이상이면 포커스 없는 슬롯 위에 옅은 막을 덮는다. 막의 색은 테마에서 파생하고(디자인 토큰), 클릭·스크롤은 그대로 통과한다(`pointer-events: none`). `.pn-dimmed` 와 다른 class 와 색을 쓴다.
- **FR-SFX-6** — 포커스가 다른 슬롯으로 옮겨 가면 막도 곧바로 옮겨 간다. 슬롯 안의 pane 에는 막을 덮지 않는다.
- **FR-SFX-7** — 흐림(FR-SFX-1)과 막(FR-SFX-5)이 겹치면 둘 다 적용한다.

### 3.4 묶음 I — 이슈트리 원천

- **FR-ITV-1** — 새 종단 `GET /api/runs/issue-tree?ref=<트리>[&refresh=1]` 은 그 트리의 이슈를 낸다: `storage`(`github`|`local`), 이슈마다 `key`·번호 또는 ID·제목·상태·부모 key·자식 차례·열 곳(GitHub URL 또는 로컬 파일 경로), 마지막으로 읽은 시각, 실패면 오류 코드. `/api/runs/tree` 의 응답은 바꾸지 않는다(Go 골든).
- **FR-ITV-2** — GitHub 트리(`owner/repo#N`)는 서버가 `gh api graphql` 의 `subIssues` 로 루트부터 하위 끝까지 읽는다. gh 는 `command_path` 로 찾는다. 깊이와 한 번에 읽는 수의 상한은 crate 상수다.
- **FR-ITV-3** — GitHub 트리의 gh 호출은 **사건 때만** 한다: ① 대시보드가 그 트리를 처음 그릴 때, ② Run push 로 멤버 구성·멤버 상태·배정 이슈가 바뀌었을 때, ③ 사용자가 대시보드의 새로고침 단추를 누를 때. 주기 호출은 없다. 아무도 보지 않으면 gh 호출은 0 이다.
- **FR-ITV-4** — 같은 트리의 gh 호출이 겹치면 하나로 합친다. 서버는 트리마다 마지막 결과를 메모리에 두고, `refresh` 가 없는 GET 은 그것을 돌려준다. 짧은 시간에 몰린 요청은 최소 간격(cadence 상수)으로 합친다.
- **FR-ITV-5** — 로컬 트리는 이슈 폴더를 `shared/issuefile` 로 읽는다(외부 프로세스 없음). 열린 로컬 트리 Run 이 있는 동안 이슈 폴더를 파일 감시 사건으로 보고, 바뀌면 그 Run 의 토픽에 push 해 화면이 다시 읽게 한다. 주기 검사는 없다.
- **FR-ITV-6** — 대시보드는 이슈 원천의 구조(부모·자식, 자식 차례 = GitHub sub-issues 차례 · 로컬 ID 차례)로 트리를 그린다. 배정 이슈가 같은 Run 멤버를 그 이슈 노드에 붙인다.
- **FR-ITV-7** — 에이전트 노드는 지금의 멤버 노드 모양 그대로다(상태·맥락 %·복구·누르면 탭으로 이동)이고, 강조 테두리를 더한다. 끝난 멤버는 지금처럼 `inactive` 다.
- **FR-ITV-8** — 이슈 노드는 옅은 모양으로 `#번호`(로컬은 ID)·제목·상태(GitHub 열림/닫힘, 로컬 todo·ready·in-progress·review·blocked·done)를 보인다. 누르면 GitHub 이슈는 브라우저로, 로컬 이슈는 편집기로 연다.
- **FR-ITV-9** — 이슈가 없는 멤버(예: 조율 에이전트)와 이슈 원천에 없는 이슈의 멤버는 지금 규칙(역할 사슬)대로 붙인다. 이슈 원천에서 사라진 이슈의 노드는 다음 갱신에서 사라진다.
- **FR-ITV-10** — gh 가 없거나 실패하면(인증·권한·망) 대시보드는 지금처럼 멤버만 그리고, 실패 사유와 새로고침 단추를 보인다. 실패는 재시도 루프를 돌리지 않는다.

- **FR-ITV-11** — 트리는 왼쪽에서 오른쪽으로 배치한다: 깊이가 오른쪽(x)으로 가고, 형제는 위아래(y)로 쌓는다. 부모는 자식들의 세로 가운데에 선다. 폭은 깊이에만 비례한다.
- **FR-ITV-12** — 선은 부모 상자 오른쪽 → 두 열 사이 → 자식 상자 왼쪽으로 꺾인다. 상자 크기는 노드마다다(끝난 노드는 작다, FR-RIN-4 그대로).
- **FR-ITV-13** — 줌·패닝·미니맵·맞춤 보기(FR-ITC-11·12·17)는 새 배치에서도 그대로 동작한다. 배치 간격은 상수다.

### 3.5 비기능 (Non-functional)

- **NFR-UB14-1** — 유휴 상태(대시보드를 아무도 보지 않음)에서 서버는 이 기능으로 외부 프로세스를 띄우지 않고 주기 작업을 돌리지 않는다(FR-SRV-3). 시간 값은 `cadence` 또는 crate 상수다.
- **NFR-UB14-2** — 부팅 JS 는 1,150,000 B 이하다. 이슈트리 그리기는 지연 묶음에 둔다.
- **NFR-UB14-3** — 색·크기·흐림 값은 디자인 토큰이다. 하드코딩하지 않는다.

## 4. 결정 (Decisions)

| # | 결정 | 근거 |
|---|---|---|
| D-UB14-1 | 네 기능을 SRS 하나에 두고, 레일 상태 → 사용량 → 슬롯 → 이슈트리 순서로 구현한다 | 사용자 결정. 작고 분명한 것부터 끝낸다 |
