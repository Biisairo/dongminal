# 6.3.1 헬퍼 기반과 워크스페이스 명령

## 목표

multi-call 분기(Dispatch·HelperName), dmctl 공통 동작(도움말·배치 인자 파서·raw 인자 파서·/api/commands 전송·서버 주소·시간 예산·보고 소켓), 워크스페이스 하위 명령(send·list-workspace·who-am-i·notify·read-screen·read-output·send-input·msg·open-editor·open-url·status·wait·move-*·*-group·list-groups·split·focus·rename-*·close-*·new-*·이동 명령)과 argv0 헬퍼 edit·download·detach·open-url 을 옮긴다. run·edge·account·훅·chat-mcp·claude 셈은 분기만 두고 6.3.2·6.3.3 이 채운다. 차분 시나리오 helper-dmctl·helper-misc 를 맞춘다.

## 완료 조건

- 대상 Go 코드의 관측 동작을 Rust 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다
