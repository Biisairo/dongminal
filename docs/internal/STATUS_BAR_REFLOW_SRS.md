# SRS: 상태바 줄바꿈과 백그라운드 진입점 이전 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 둘이다.

> **"하단 상태바 창 크기를 줄이면 깨지는 문제가 있어. 창 크기 따라서 알아서 2줄
> 3줄로 표시되게해줘."**
>
> **"백그라운드버튼은 split run bg agents 순서로 위치 바꿔줘. 항상 떠있게하고
> bg 가 있는경우 하이라이트하는걸로."**

앞의 것은 결함이고 뒤의 것은 배치 변경이다. 두 요구가 같은 요소(상태바)를
건드리므로 한 스펙에서 다룬다 — 진입점이 상태바를 떠나는 것이 줄바꿈 설계의
전제이기도 하다(§3.1 은 상태바에 지표만 남는다고 가정한다).

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **W** 줄바꿈 | 상태바가 폭에 맞춰 여러 줄로 늘어난다. 잘라내지 않는다 |
| **B** 진입점 이전 | 백그라운드 버튼이 상단바의 `Split H · Split V · Runs · **BG** · Agents` 자리로 간다. 항상 보이고, 도구가 있을 때만 하이라이트된다 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **지표** | 상태바에 뜨는 `.sb-item` 하나 — 연결·지연·위치·CWD·메모리… |
| **진입점** | 백그라운드 도구 목록 모달을 여는 버튼 (구 `#sb-bg-btn`) |

## 2. 현재 상태 (실측으로 확정한 사실)

### 2.1 상태바는 줄일 수 없는 것을 줄이고 있었다

지표 9개를 모두 켜고 뷰포트를 좁혀 가며 잰 값이다 (`#sb-items` 기준).

| 뷰포트 | 지표가 요구하는 폭 | 실제 폭 | 잘린 지표 |
|---|---|---|---|
| 1280px | 774px | 774px | 0 |
| 900px | 727px | 727px | 0 |
| 700px | **527px** | 527px | 0 |
| 560px | 474px | **387px** | **3** |
| 420px | 474px | **247px** | **5** |

두 가지가 동시에 일어난다.

1. **`.sb-item` 에 `flex-shrink` 가 없다.** 폭이 모자라면 항목 자체가 눌린다 —
   1280px 에서 774px 이던 것이 700px 에서 527px 로 줄었는데, 글자가 준 것이
   아니라 **상자가 글자보다 좁아진 것**이다. 글자는 상자 밖으로 흘러 이웃과 겹치고,
   `height:22px` 안에서 두 줄이 되려다 아래가 잘린다.
2. **`#sb-items{overflow:hidden}` 이 나머지를 잘라낸다.** 560px 에서 3개, 420px
   에서 5개가 통째로 사라진다 — 접혔다는 표시도 없이 사라진다.

700px 에서 찍은 상태바가 그 결과다: `연`(잘린 `연결됨`) · 겹쳐 쓰인 호스트명 ·
22px 안에서 두 줄로 눌린 `MEM 22.6GB/32.0GB` · 정체를 알 수 없는 꼬리.

### 2.2 고정 높이가 전제로 박혀 있다

`.status-bar{height:22px}` 다. `#content` 는 세로 flex 이고 `#area` 가 `flex:1`
이므로, **상태바가 커지면 터미널 영역이 그만큼 줄어든다.** 지금은 높이가 변하지
않아 아무도 이 사실을 다루지 않는다 — 줄바꿈을 허용하는 순간 터미널의 `cols/rows`
가 어긋나므로 다시 맞출 계기가 필요하다.

`_scheduleFit()`(`app-mobile.js:254`)이 그 수단이고, 지금은 `window.resize` 와
visualViewport 만 그것을 부른다. **상태바가 스스로 커지는 경우**(지표가 늘거나
Git 작업 chip 이 붙는 경우)는 `window.resize` 를 내지 않는다.

### 2.3 구분선 규칙이 줄바꿈과 부딪힌다

`.sb-item+.sb-item{border-left:1px solid}` 다. 여러 줄이 되면 **둘째 줄 첫 항목이
앞에 세로선을 달고 시작한다** — 앞에 아무것도 없는 자리의 구분선이다.

### 2.4 진입점은 상태바 우측 끝에 산다

`#sb-bg-btn` 은 `#sb-items` **밖**의 형제이고 `margin-left:auto` 로 오른쪽 끝에
붙는다(FR-BGU-3). 0개면 `display:none` 이다(FR-BGU-5). 리스너는 `_initStatusBar`
가 한 번만 붙이고, 표시와 개수만 `_updateBgBtn` 이 갱신한다(FR-RPT-3 의 이유).

### 2.5 진입점은 모바일에서도 유일한 통로다

`bg-kill-touch.spec.ts` 가 `body.mobile` 에서 이 버튼을 탭한다. 상단바의 이웃
버튼들(`Split H`·`Split V`·`Runs`·`Agents`)은 전부 `desktop-only` 라 모바일에서
사라지므로, **진입점을 그 관행대로 옮기면 모바일에서 백그라운드 도구에 닿을 길이
없어진다.**

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 W — 줄바꿈

- **FR-SBR-1** 상태바는 폭이 모자라면 지표를 다음 줄로 넘긴다. 줄 수는 내용과 폭이
  정한다 — 2줄·3줄을 코드가 정하지 않는다.
- **FR-SBR-2** 지표는 눌리지 않는다(`flex-shrink:0`). 폭이 모자라는 것은 줄을
  넘기는 사유이지 글자를 겹치는 사유가 아니다 (§2.1-1).
- **FR-SBR-3** 지표는 잘리지 않는다. 어떤 폭에서도 켜 둔 지표는 전부 화면에 있다
  (§2.1-2).
- **FR-SBR-4** 상태바 높이는 내용이 정한다(`height:auto`). 한 줄일 때의 높이는
  지금과 같은 22px 이다 — 대다수 상황에서 화면이 달라지지 않아야 한다.
- **FR-SBR-5** 줄의 첫 지표는 앞에 구분선을 달지 않는다 (§2.3).
- **FR-SBR-6** 한 지표가 한 줄보다 넓으면 그 지표만 잘린다. 그 때문에 다른 지표가
  사라지지는 않는다.
- **FR-SBR-7** 상태바 높이가 바뀌면 터미널을 다시 맞춘다(`_scheduleFit`). 계기는
  상태바 자신의 크기 변화이고 `window.resize` 에 기대지 않는다 (§2.2).

### 3.2 묶음 B — 진입점 이전

- **FR-SBR-8** 진입점은 상단바로 옮겨 `Split H · Split V · Runs · **BG** ·
  Agents` 순서에 선다. 상태바에는 지표만 남는다.
- **FR-SBR-9** 진입점은 **항상 보인다.** 백그라운드 도구가 0개여도 자리를 지킨다.
  (FR-BGU-5 폐기 — §5 D-3)
- **FR-SBR-10** 백그라운드 도구가 1개 이상이면 진입점이 하이라이트된다(`.on`).
  하이라이트는 테마 팔레트(`--accent`)를 쓴다 — 리터럴 색을 넣지 않는다.
- **FR-SBR-11** 이름은 `BG` 이고, 도구가 있으면 개수를 붙여 `BG 2` 가 된다.
  이웃(`Split H`·`Runs`·`Agents`)과 같은 낱말 표기다.
- **FR-SBR-12** 진입점은 모바일에서도 보인다 — 이웃과 달리 `desktop-only` 가
  아니다 (§2.5).
- **FR-SBR-13** 진입점의 식별자는 상태바를 떠났으므로 `#sb-bg-btn` → `#bg-btn`
  이다. 클릭 동작·모달·리스너 부착 시점(FR-RPT-3)은 그대로다.

## 5. 확정 결정 (Decisions)

- **D-1 접기(`…` 더보기)를 하지 않는다.** 요구가 "2줄 3줄로 표시" 다. 접으면 켜 둔
  지표를 다시 숨기는 것이라 요구와 반대다.
- **D-2 줄 수를 코드가 정하지 않는다.** 미디어 쿼리로 "600px 이하면 2줄" 을 박으면
  지표 구성(사용자가 켜고 끄는 10개)마다 어긋난다. `flex-wrap` 이 내용과 폭에서
  스스로 정하게 둔다.
- **D-3 FR-BGU-5(0개면 UI 에 흔적이 없다)를 폐기한다.** 사용자의 지시다. 그 요구의
  뜻은 "쓰지 않는 기능이 자리를 차지하지 않는다" 였는데, 자리가 상단바의 버튼 줄로
  바뀌면서 **버튼이 나타났다 사라지는 쪽이 이웃 버튼의 위치를 흔들어 더 해롭다.**
  대신 하이라이트가 "지금 있는가" 를 말한다(FR-SBR-10).
- **D-4 모바일에서도 보인다.** 이웃 관행(`desktop-only`)을 따르면 모바일에서
  백그라운드 도구에 닿을 길이 없어진다 (§2.5).
- **D-5 구분선은 음수 마진 + 클리핑으로 지운다.** 줄의 첫 항목을 CSS 선택자로는
  고를 수 없다(`:first-child` 는 줄이 아니라 부모 기준이다). 모든 항목을 1px 왼쪽으로
  밀고 컨테이너가 그 1px 을 잘라내면, 각 줄의 첫 항목 구분선만 화면 밖으로 나간다.
- **D-6 식별자를 바꾼다.** `sb-` 는 상태바를 뜻한다. 상단바에 사는 요소가 그 이름을
  달고 있으면 다음 사람이 상태바에서 찾는다. e2e 6개 파일의 기계적 치환이 비용 전부다.
