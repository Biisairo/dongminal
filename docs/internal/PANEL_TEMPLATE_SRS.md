## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 말:

> **"정렬이나 행 두께, 나타나는 동작 같은 걸 말하는 거야. 메인 패널은 홈 화면과 정렬도 잘 되고 애니메이션으로 잘
> 나타나는데 에이전트는 모바일에서 그게 없어. 이와 비슷한 내용으로 데스크톱 모드에서도 UI 통일성을 확인해 봐. 두 패널이
> 같은 패널 템플릿을 사용하도록 해서 나중에 패널 확장성도 키우고 통일성 있는 UI 를 가지도록 하자"**

메인 패널(사이드바·모바일 서랍)과 Activity 패널이 **하나의 패널 템플릿**을 쓰게 한다. 템플릿은 골격(머리·몸통·바닥),
머리의 높이와 정렬, 탭의 모양, 모바일에서 나타나는 동작을 정한다. 새 패널은 이 템플릿을 쓰면 같은 규칙을 받는다.

### 1.2 범위 (Scope)

**포함:** `#sidebar`·`#agents-panel` 의 골격 DOM, 머리(탭 줄·끝 단추), 탭의 모양, 데스크톱 레일의 머리, 모바일 시트의 크기와
나타나는 동작, 이것들을 정하는 공통 CSS 클래스.

**미포함:** §6 비목표. 패널 안의 목록 행(창 목록·에이전트 카드)의 내용과 모양은 바꾸지 않는다.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|---|---|
| **패널** | 화면 옆에 서는 전역 목록 표면. 지금은 메인 패널(`#sidebar`)과 Activity(`#agents-panel`) 둘이다 |
| **패널 템플릿** | 패널이 공유하는 골격과 CSS 클래스(`ui-panel`·`ui-panel-head`·`ui-panel-tabs`·`ui-panel-tab`·`ui-panel-acts`) |
| **머리** | 패널 맨 위의 한 줄. 탭 줄과 끝 단추로 이루어진다 |
| **끝 단추** | 머리 오른쪽 끝의 아이콘 단추들(`ui-panel-acts`) |
| **시트** | 모바일에서 화면 전체를 덮는 패널 |
| **레일** | 데스크톱에서 접힌 40px 패널 |

### 2.3 제약 (Constraints)

| # | 제약 |
|---|---|
| C-1 | 패널의 id(`#sidebar`·`#sb-tabs`·`#agents-panel`·`#agents-body`·`#agents-foot`)와 기존 클래스(`sb-tab`·`ag-tab`·`ag-head`·`ag-refresh`·`ag-collapse`)는 남긴다 — 다른 모듈과 e2e 가 그 이름 위에 서 있다. 템플릿 클래스는 **함께** 붙인다 |
| C-2 | 템플릿 규칙은 id 가 아니라 템플릿 클래스에 건다 (FR-PNT-20) |

## 3. 요구사항 (Specific Requirements)

### 3.1 골격

**FR-PNT-1** — 패널은 `.ui-panel` 이고, 자식은 위에서부터 머리(`.ui-panel-head`), 몸통, 바닥(있으면)이다. 머리는 몸통의
스크롤 밖에 있어 몸통이 굴러도 움직이지 않는다.

**FR-PNT-2** — 머리는 탭 줄(`.ui-panel-tabs`, `role="tablist"`)과 끝 단추(`.ui-panel-acts`) 둘로 이루어진다. 끝 단추는 머리
오른쪽 끝에 선다. 탭 줄은 남는 폭을 다 쓴다.

**FR-PNT-3** — 메인 패널: 탭 줄은 `#sb-tabs`, 끝 단추는 닫기(`#drawer-close`, 모바일에서만 보인다).
Activity: 탭 줄은 `.ag-tabs`, 끝 단추는 새로고침(`.ag-refresh`)과 접기(`.ag-collapse`, 모바일에서는 닫기 `×`)다.

**FR-PNT-4** — Activity 의 제목 줄(`Activity`)을 없앤다.

> 이전 동작: 머리가 제목 줄(`Activity` + 새로고침·접기)과 그 아래 탭 줄 두 줄이었고, 둘 다 몸통 스크롤 안의 항목이었다.
> 새 동작: 탭 줄 한 줄이고 새로고침·접기는 그 끝 단추다. 머리는 몸통 밖이다.
> 이유: 두 패널의 머리가 같은 선에 서야 한다 (D-3). 패널의 이름은 상단바의 Activity 단추와 탭 아이콘이 말한다.

### 3.2 머리의 높이와 정렬

**FR-PNT-5** — 머리의 높이는 상단바의 높이와 같다 — 데스크톱 `--panel-head-h`(32px), 모바일 `--touch-min`(44px). 머리의 아래
선은 상단바의 아래 경계와 같은 y 에 선다. 아래 선은 안쪽 그림자로 그린다 — 경계(border)로 그리면 탭이 1px 낮아져 모바일
터치 하한(44px)에 못 미친다(실측 43px, FR-A11Y-27).

**FR-PNT-6** — 탭(`.ui-panel-tab`)은 두 패널에서 같다: 높이(머리 높이에서 경계를 뺀 값), 바탕(패널 바탕), 글자 크기·굵기,
hover(바탕 `--accent-hover`), 활성(밑줄 2px `--accent` + 바탕 `--accent-active` + 밝은 글자). 탭의 **내용**은 패널의 서술자가
정한다 — 메인 패널은 글자, Activity 는 아이콘과 배지다.

**FR-PNT-7** — 끝 단추는 아이콘 단추(`ui-btn-icon ui-btn-ghost`)이고 높이는 머리 높이에 맞춘다.

### 3.3 데스크톱 레일

**FR-PNT-8** — 레일에서 머리는 세로로 눕는다. 고른 탭의 띠는 패널의 **바깥 가장자리**에 선다(왼쪽에 선 패널은 왼쪽, 오른쪽에 선 패널은 오른쪽). 탭이 맨 위(y = 0)부터 세로로 서고, 끝 단추는 그 아래에 선다. 두 패널의 레일에서
첫 탭은 같은 y 에 선다. Activity 레일의 끝 단추는 펼치기 하나만 보인다(새로고침은 감춘다).

> 이전 동작: Activity 레일은 접기 단추가 맨 위에 서고 탭이 그 아래에서 시작했다.
> 새 동작: 탭이 맨 위다. Activity(오른쪽) 레일의 띠는 왼쪽(안쪽)에서 오른쪽(바깥쪽)으로 옮긴다.
> 이유: 두 레일의 탭이 같은 선에 서고, 띠가 같은 규칙(바깥 가장자리)을 따른다 (D-1).

### 3.4 모바일 시트 (D-2)

**FR-PNT-10** — 모바일에서 두 패널은 시트다. 화면 전체(안전 영역 안쪽 여백 포함)를 덮는다.

**FR-PNT-11** — 시트는 닫힌 동안 화면 밖에 있고 보이지 않는다(`visibility:hidden`). 열리면 제자리로 **미끄러져** 들어오고 닫히면
같은 방향으로 나간다. 방향은 패널의 `data-sheet` 값이다 — 메인 패널 `left`, Activity `right`. 전환은 `transform` 하나이고 시간은
`--dur-slow`, 곡선은 두 패널이 같다.

**FR-PNT-12** — 시트의 끝 단추 `×` 는 누를 수 있다. 다른 원소가 그 위를 덮지 않는다.

> 이전 동작: 서랍의 `×`(`#drawer-close`)는 서랍 오른쪽 위에 겹쳐 섰고, 탭 줄이 그 위를 덮어 눌리지 않았다 (P10).
> 새 동작: `×` 는 머리의 끝 단추 자리에 선다.

**FR-PNT-13** — 시트가 열리고 닫히는 길은 종전과 같다: 상단바의 ☰·Activity 단추, 머리의 `×`, Escape(FR-MUX-14). 시트가 열린 동안
키바·상태바를 감추는 규칙(FR-MUX-13)도 그대로다.

**FR-PNT-14** — 메인 패널 시트의 배경 막(`#drawer-backdrop`)은 쓰지 않는다 — 시트가 화면 전체를 덮어 막이 보일 자리가 없다.

> FR-MUX-10 개정: 이전 폭 `min(86vw, 360px)` + 배경 막 / 지금 화면 전체 / 이유 D-2.

### 3.6 모바일 Activity — 누른 뒤 유지·닫힘 (D-5)

원칙: **다른 화면을 보여 주는 누름은 시트를 닫는다. 패널 안에서 끝나는 조작은 시트를 유지한다.** 시트가 화면 전체를 덮으므로,
이동한 곳은 시트를 닫아야 보인다. 데스크톱 패널은 화면을 덮지 않으므로 이 규칙과 상관없이 종전대로다.

**FR-PNT-15** — 다음 누름은 이동을 마친 뒤 시트를 닫는다(`actSheetLeave`):

| 자리 | 누름 | 이동 |
|---|---|---|
| Agents | 에이전트 카드(서브에이전트 줄 포함) | 그 에이전트의 탭으로 간다 (`jumpToTool`) |
| Background | 행 | 그 도구를 탭으로 되살린다 (`_restoreTool`) |
| Runs | 행 | Run 탭을 연다 |
| Chats | 방 행, 참가자 메뉴의 `개인 대화`, 새 그룹 대화 만들기(확인 뒤) | 채팅 탭을 연다 (`_chatOpenTab`) |

**FR-PNT-16** — 다음 누름은 시트를 유지한다:

| 자리 | 누름 |
|---|---|
| 머리 | 탭 전환, 새로고침 (`×` 는 닫는 단추다) |
| Agents | 창 그룹 머리 접기·펴기 |
| Background·Runs | 종료·삭제 단추, 확인·취소, 확인이 열린 행 누름(취소일 뿐이다) |
| Chats | 참가자 줄(메뉴만 연다), 다중 선택 중의 방 행, 새 그룹 대화 단추(대화상자를 연다), 대화상자의 취소 |
| 바닥(사용량) | 요약 줄 펼치기·접기, 계정 묶음·색 막대, 전환 메뉴, 계정 전환·새로 고침·초기화 사용 |

**FR-PNT-17** — 닫힘의 판단은 이동을 일으킨 자리 한 곳에서 한다 — 행의 처리기가 이동을 실제로 했을 때만 닫는다. 취소·무시로 끝난
누름(확인이 열린 행, 진행 중인 종료)은 닫지 않는다.

### 3.5 확장성

**FR-PNT-20** — 템플릿 규칙(FR-PNT-1·2·5~8·10·11)은 id 가 아니라 템플릿 클래스와 `data-sheet` 에 건다. 새 패널은 그 클래스와
속성을 붙이면 같은 머리·탭·레일·시트를 받는다. 패널별 규칙은 패널 고유의 내용(목록 행·배지 색)에만 남는다.

## 6. 비목표 (Non-goals)

- 패널 안 목록 행(창 목록·에이전트 카드)의 내용·모양 변경
- 탭 내용 통일(메인 패널은 글자, Activity 는 아이콘으로 둔다)
- 데스크톱 패널이 나타나는 동작(레일 ↔ 펼침)의 애니메이션 — 지금 두 패널 모두 전환 없이 같다
- 패널을 셋 이상으로 늘리는 일 (FR-PNT-20 은 그 길만 연다)
