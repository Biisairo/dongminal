## 남은 것 — 착수 순서

**UX-4 — 닫혔다.** 세 팩토리에 역할이 섰고 키 계약은 `UIKit.roving`(목록·탭)
하나와 트리의 `aria-activedescendant` 다. **알아 둘 것 셋**:
  - `×`(`.sbl-x`·`.pn-tab-x`)는 `UIKit.button` 이 **아니다** — `option`·`tab`
    안의 버튼은 axe `nested-interactive` 위반이라 `aria-hidden` 포인터 표식으로
    남겼고 키보드는 `Delete`/`Backspace` 다 (사용자 결정, D-A11Y-10). 그래서
    `touch-targets` 의 손 목록은 `POINTER_ONLY` 둘로 남았다
  - `.pn-tabs > .pn-tablist[role=tablist]` 로 한 겹 늘었다 — `+` 가 tablist 의
    자식일 수 없어서다. `.pn-tabs .pn-tab` 류 후손 선택자는 그대로 산다
  - `render()` 의 재포커스가 **키보드 포커스**(`:focus-visible`)를 `.kb-nav` 안에서
    빼앗지 않는다. `edFocusWanted` 는 `focusHandoff` 로 이름이 바뀌었다 — 탐색기만의
    규칙이 아니었다 (D-A11Y-12)

## 이 세션이 비싸게 배운 것 (M6 의 열둘 + M7 의 열여섯에 더해 셋)

29. **인계서의 처방을 스펙(ARIA)과 대조해라 — `④` 가 올릴 것을 `③` 이 만들지
    마라.** "`×` 를 `UIKit.button` 으로" 는 `03` 과 인계서가 두 번 적은 처방인데,
    `option`·`tab` 안의 버튼은 axe `nested-interactive` 다. 역할을 주는 일과 그
    역할이 자식에게 무엇을 요구하는지는 한 몸이다 — `tablist` 의 `+` 도 같은
    부류였다. 결정은 사용자에게 물었다 (D-A11Y-10)

30. **컨테이너에 키를 걸면 그 안의 입력도 듣는다.** roving 리스너가 이름 변경
    `<input>` 의 `Enter`·`Backspace` 를 먹었다 — `Backspace` 가 글자가 아니라
    **행을 지운다.** 전량 ①이 `V-TAN-6` 으로 잡았고 탐색기는 이미 같은 가드를
    갖고 있었다(FR-EXR-55). 컨테이너 리스너의 첫 줄은 "이 키가 누구 것인가" 다

31. **"포커스를 지킨다" 는 규칙에는 마우스가 반례다.** 행·탭에 `tabindex` 가
    생기면 **클릭도** 거기 포커스를 두므로 "우리 위젯 안의 포커스는 빼앗지 않는다"
    를 그대로 쓰면 창을 고른 뒤 터미널에 글자를 칠 수 없다. `:focus-visible` 가
    브라우저의 답이다 — 키보드에서 온 포커스만 지킨다. **잡으면 안 되는 것**의
    검사(`TC-A11Y-6e`)를 함께 두지 않았으면 이 반례는 사람이 처음 클릭할 때 나왔다

21. **흔들림을 집계할 단위는 검사 이름이 아니라 그 검사가 기다리는 것이다.**
    §5-4 는 "이름이 회차마다 통째로 바뀐다 → 얇게 퍼진 시간 민감성" 이라고 적었다.
    이름으로 보면 사실이다. **파일로 묶으니** 19건 중 16건이 두 부류였다 —
    칸별 상태(`slot-view-state` 계열)와 git 관측 주기(`git-worktrees`·`git-history`·
    `git-refresh-lifecycle`·`git-observe-revive` 계열). 이전 세션들의 이름도 같은
    파일에 떨어진다(`V151`·`V168`·`V169` 는 전부 `git-worktrees`). **남은 작업은
    스무 개의 검사가 아니라 두 헬퍼일 가능성이 높다** (§5-5)

22. **게이트를 느슨하게 하는 대신 지역 토큰을 줘라.** 테마 미리보기(`.pv-*`)는
    높이 14px 안에 7px 로 들어가야 해서 눈금 바닥(9px)으로는 넘친다. 예외로
    등록하는 대신 `.theme-preview-panel{--pv-fs-xs:7px…}` 지역 토큰을 줬다 —
    FR-TOK-28 이 "선택자에 매인 정의" 를 정의 자리로 인정하므로 **게이트는 그대로
    통과하고 뜻은 이름에 남는다.** 문서의 종이색(`--doc-paper`)·부팅 브랜드색
    (`--boot-glow`)도 같은 방식이다. 이 세션의 토큰 예외 등록부가 **0건**인 이유다

23. **"게이트가 지킨다" 는 문장은 게이트를 읽어야 참이 된다.** 인계서가
    *"토큰을 더하면 `:root` 와 `applyThemeObj` 둘 다에 넣어야 하고 게이트가 그것을
    지킨다"* 고 적었는데 `check-css-vars` 는 네 자리 중 **하나만** 있으면 통과하는
    **OR** 다. 그러면 파생을 잊어도 초록인데 54종 전부에서 기본 테마 색이 나온다 —
    `UX-14` 가 보고한 결함의 정확한 모양이다. `TC-TOK-16`(e2e)으로 막았고
    FR-TOK-28b 로 그 한계를 문서에 적었다

24. **로드맵의 문장을 근거로 들 때는 그 문장을 다시 읽어라.** "§3-A-1 에 따라 모달
    골격 수렴이 `UX-3` 보다 먼저다" 라고 적었는데 그렇게 쓰여 있지 않았다 — 셋을
    **M9 앞이어야 하는 근거**로 묶은 것이고 셋 사이 순서는 정하지 않았다. 내 추론이
    로드맵의 말로 문서에 들어갈 뻔했다

25. **탐침이 통과하면 그 검사는 아무것도 재지 않는다.** 회귀를 하나 **계산으로**
    찾았고(토스트 흡수로 버튼이 잘린다) CSS 를 고치고 검사를 넣었고 통과했다.
    탐침으로 되돌려도 통과했다 — 검사가 공허했다. 실측하니 문구가 6자(`커밋했습니다`)
    라 애초에 잘리지 않았다. **회귀는 없었다.** 추측 코드와 공허한 검사를 둘 다
    되돌리고 실측값만 주석으로 남겼다. M6 §4-A-1 이 게이트에 세운 규칙이 **e2e
    단정에도 그대로 걸린다**

26. **탐침의 되돌림은 `git checkout` 이 아니다.** 그 파일에 커밋되지 않은 작업이
    있으면 되돌림이 작업을 먹는다(실제로 먹혔다). **파일 끝에 덧붙이고 길이로
    잘라 내거나 사본으로** 되돌려라. 게이트 탐침 열은 그 방식이어서 안전했고,
    위험은 **파일 중간을 고치는 탐침**에 있다

27. **상자를 들어올리지 말고 팝오버를 팝오버 층에 둬라.** `.git-commit{z-index:5}`
    는 메뉴를 형제들 위로 올리려고 **상자**에 걸린 값이었고, 그 방식은 **메뉴의 층을
    상자의 층에 가둔다** — 상자보다 위로 가는 형제가 하나 생기면 메뉴가 즉시 묻힌다
    (실측: `.git-files-bar` 가 `--z-sticky` 로 가자 클릭이 먹지 않았다). 상자의
    `z-index` 를 지우고 메뉴가 `--z-popover` 를 직접 쓰게 하면 선언이 하나 줄고
    형제들과의 결속이 끊어진다

28. **목록을 대조하는 정규식도 표본이다.** 게이트가 Makefile·CI 양쪽에 있는지

## e2e — 무엇을 신호로 쓰나

**샤드를 시간으로 가른다.** `make e2e` 가 `scripts/e2e-shard.mjs` 로 목록을

    벽시계 ~4.5분 · 항목 1,615 · 스펙 153 (넷째 세션 뒤 `make e2e-rebalance` 로 다시 맞췄다)

**새 스펙을 더하면 그 회차의 분배가 크게 흔들린다** — 시간을 모르는 파일은 **가장
무겁게** 쳐서 배치하므로 샤드가 165~259항목으로 갈렸다(실측). 스펙을 더한 뒤에는
`make e2e-rebalance` 를 돌려라. **그 명령은 직전 전량의 JSON 리포트를 읽는다** —
표적 실행(`npx playwright test <일부>`)이 그것을 덮으면 "먼저 `make e2e` 를 돌리세요"
로 멎는다 (이 세션이 한 번 겪었다)

**flaky 는 0 이 아니다** (회차당 0~8건). **판정은 `unexpected 0` 으로 한다.**
흔들린 것은 **단독 반복(`--repeat-each=2`)으로 확인**해라. 같은 이름이 두 회차
연속 흔들리면 그때는 그 검사를 본다 — 그리고 **파일로 묶어서 봐라** (배운 것 21)

**새 스펙은 목록에 손으로 넣지 않는다** — `e2e-shard.mjs` 가 `e2e/` 에서 파생한다.

## 변하지 않는 규약

- **로컬 전량은 `make e2e`** (CI 와 같은 8샤드 병렬, ~4.5분)

## 열려 있는 것

**전량 3회 연속 flaky 0** (로드맵 §M6 DoD). **한 회차를 처음으로 달성했다**
(`UX-3` 뒤, 1,607항목). 그러나 같은 코드에서 다음 세 회차가 8 → 3 → 4 로 흔들렸다 —
**전량을 반복해 0 을 쫓는 것으로는 수렴하지 않는다.**

§5-5 가 대상을 좁혔다: 19건 중 16건이 **두 부류**이고 둘 다 주기적으로 도는 것을
기다린다 — 칸별 상태(`slot-view-state`·`slot-live-refresh`)와 git 관측 주기
(`git-worktrees`·`git-history`·`git-refresh-lifecycle`·`git-observe-revive`·
`git-head-mobile`). 스무 개의 검사가 아니라 **두 헬퍼**를 보는 일일 가능성이
높다 (예: `expect.poll` 의 대상이 "요청이 왔는가" 인지 "화면이 그것을 반영했는가"
인지 — M6 `TEST-16` 의 판정이 여기 다시 걸린다). 그 자체로 하나의 작업이다.

**`UX-16` 의 나머지 절반** — 모달 골격 7벌. 접근성의 선행이 아니므로(D-A11Y-7)
급하지 않지만, `⑤`(과도기 클래스)와 같은 부류이므로 **함께 하는 것이 싸다.**

**`index.html` 의 이름 없는 컨트롤 18개** (`<input>` 17 + `<select>` 1).
`label[for=]` 가 **0개**라 연결 기제 자체가 없다. `④`(axe)가 증거와 함께 몰고 올
일이고 위 ④ 항목에 적어 두었다.

**`Tab` 이 벤더 표면에 갇힌다.** xterm 과 Monaco 는 `Tab` 을 먹는다 — 키보드
사용자가 터미널에 들어가면 **나올 길이 없다** (`a11y-keyboard` 의 `tabTo` 가 그
자리에서 멎는 것으로 실측). E-1·E-2 의 범위 안이지만 "벤더의 접근성 모드를 따른다"
가 탈출 키까지 주지는 않는다. 사용자 결정이 필요한 자리다 — 예: `Ctrl+M`(Monaco 의
관용) 류의 탈출 키를 둘 것인가.

**`.git-repo-xslot`** — CSS `style-git-views.css:396·398` 에 남아 있으나 JS 어디서도
만들지 않는 죽은 선택자다 (같은 파일 `:760` 의 주석이 이미 "사라졌다" 고 적는다).
