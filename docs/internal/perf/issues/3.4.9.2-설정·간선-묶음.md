# 3.4.9.2 설정·간선 묶음

3.4.9 에서 나눴다. Run·채팅은 3.4.9.1 이 했다.

## 목표

- `SettingsController` 를 "부팅에 남는 껍데기(값의 길 `SettingsApply`·등록부/사건 처리·부팅 부수효과) + 묶음 본체(모달·섹션)" 로 나눈다.
- 설정 창 섹션(`initModal`)은 처음 열 때 세운다. `settings-*` 섹션과 간선 화면(설정 ▸ Edges 의 망 그림)을 `settings` 묶음으로.

## 완료 조건

- RED e2e: 부팅 때 `b/settings.js` 요청이 없다 → 설정을 처음 열 때 실리고 그려진다. 설정 값의 부팅 적용(`_settingsApply`)은 묶음 없이 돈다.
- 부팅·소프트 리로드 e2e 한두 개, 게이트 통과. 전체 시험 금지.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.

## 3.4.9 에서 조사한 것 (2026-11-25 agent-pf-3-4-9)

**정적 경계.** 섹션 파일 21개(`settings-section`·`settings-row`·섹션 17개·`settings-claude-rows`·`settings-backup`·`settings-presets`)와 `edges-mesh.js` 를 `[settings]` 로 옮겨 `check-lazy-boundary` 를 돌리면, 위반은 셋뿐이다.

- `settings-controller.js` 의 `SETTINGS_INIT` 표(섹션 클래스 17개).
- `edges-controller.js:95~160` 의 망 그림(`meshLayout`·`MESH_*`·`meshNodeMarks`·`meshNodeAction`).
- `chat-views.js:135` 의 `meshDirectPeer`. 채팅(3.4.9.1 의 `[chat]`)도 쓰므로 이 함수는 부팅에 남긴다.

크기: 옮길 JS 약 140 KB(압축 전).

**게이트가 보지 못하는 런타임 결합 (껍데기로 옮겨야 동작이 그대로다).**

1. 순서 계약 — `SETTINGS_INIT` 이 섹션 사이에 다른 주제의 init 을 끼운다: `settings.paint`, `settings.saveState.initSaveButtons`(패널이 선 뒤, FR-UXF-72), `statusbar.initStatusBar`, `mobile.initMobile`·`initMobileKeybar`(모달 리스너 뒤, FR-MUX-20), `attn.initAttn`. 모달을 늦게 세우면 부팅 몫과 열기 몫으로 표를 나눠야 한다.
2. 섹션 `init()` 의 부팅 부수효과
   - `ThemeSection`: OS 색 구성표(`prefers-color-scheme`)를 따라가는 리스너.
   - `DisplaySection`: `applyTabWidth`·`applyUiFontScale`, `_initSlotDir` 의 `_slotDirPaint`.
   - `TerminalSection`: `_initTermGpu`·`_initKeybar`. `CodeSection`: `_initLsp`.
   - `NotifySection`: `attn._attnSecurityNotice`(보안 문맥이 아니면 데스크톱 알림을 끈다)·`_initUpdateCheck`.
3. 등록부·사건이 섹션을 부른다(`state-registry.js:235~250`): `telegram` 토픽 → `section(telegram)._tgTopic`, `access_changed`·`sandbox_changed` → 섹션, `server_moving` → `section(server)._onServerMoving`(서버가 포트를 옮기면 새 주소로 가는 전역 동작). 섹션이 없으면 빠진다.
4. `?.` 로 섹션을 부르는 자리: `edges-controller.js:54~61`, `main.js:112~113`(테마 편집기), `claude-accounts-controller.js:47`, `settings-save-state.js:22`(`_sectionCall`). 열 때 칠하면 되는지 하나씩 확인한다.
5. e2e: 설정 창을 여는 스펙 48개 파일. 버튼 클릭으로 여는 것은 진입점이 `await Screens.load('settings')` 하면 그대로다. 계약 `settings.section(presets)._savePreset`·`settings.section(theme).themeSlots` 등을 열기 전에 부르는 스펙은 `app.testing.loadScreen('settings')` 가 먼저다.

## 결정할 것 (권장안)

- D1 경계: 모달·섹션 전부와 간선 망 그림을 `[settings]` 로 옮긴다. 2·3 의 부팅 부수효과와 등록부·사건 처리는 부팅 쪽(`SettingsApply` 또는 그 주제의 컨트롤러)으로 옮긴다. 대안: 섹션은 부팅에 두고 행 세우기·칠하기만 늦춘다 — 줄어드는 바이트가 작다.
- D2 순서 계약: `SETTINGS_INIT` 을 부팅 몫과 열기 몫 둘로 나눈다. 모바일의 설정 탭 리스너(FR-MUX-20)는 모달을 세운 뒤 건다.
- D3 간선: 간선 화면은 설정 ▸ Edges 탭 하나이므로 따로 묶지 않고 `[settings]` 에 넣는다. `EdgesController` 의 읽기·알림·`edgeHandle` 등은 부팅에 남는다.
