# SRS: 나가기 확인 토글 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 한 줄이다.

> **"나가시겠습니까? 질문 하지 않기"**

지금 도구가 하나라도 열려 있으면 탭을 닫거나 새로고침할 때 브라우저의 떠남 확인이
반드시 뜬다. 그 가드는 **끌 수 없다.** 요구는 그것을 묻지 않게 하는 것이다.

가드를 지우지 않고 **스위치로 두기로 확정했다** (D-4). 지우면 실수로 세션을 잃는
경로가 되돌릴 수 없이 열리고, 그 판단은 사용자마다 다르다.

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 스위치 | Settings ▸ Display 의 체크박스 한 칸 |
| **B** 저장 | 설정 블롭의 `confirmLeave` 키. 서버가 가지므로 브라우저를 가리지 않는다 |
| **C** 적용 | `beforeunload` 가드의 단일 판정 지점 |
| **D** 전제 | 가드를 재던 앞선 검증 셋이 스위치를 켜고 재게 한다 (§2.7) |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **떠남 확인** | `beforeunload` 에서 `preventDefault()` 했을 때 브라우저가 띄우는 확인 대화 |
| **가드** | `web/js/core/main.js` 의 `beforeunload` 리스너 |
| **자기 새로고침** | 앱이 새 판을 받으려 스스로 여는 재적재. `__dmReloading` 로 표시된다 (FR-RLC-5a) |
| **설정 블롭** | `/api/settings` 가 주고받는 JSON. 서버는 해석하지 않는다 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 가드는 한 자리에 있고 조건이 하나다

`web/js/core/main.js:92`:

```js
window.addEventListener('beforeunload',e=>{
  if(window.__dmReloading) return;
  if(app.tools.size>0) e.preventDefault();
});
```

도구가 하나라도 있으면 묻는다. **끄는 길이 없다** — 그것이 접수한 요구의 대상이다.

### 2.2 자기 새로고침은 이미 예외다

`__dmReloading` 가 그 표시이며 근거는 FR-RLC-5a 다. 이번 작업은 그 예외를 건드리지
않는다 — 조건을 하나 **더** 얹는 것이지 기존 조건을 바꾸는 것이 아니다.

### 2.3 설정 블롭은 서버가 해석하지 않는다

`internal/webserver/httpapi/handlers_settings.go:74` 는 받은 바이트를 그대로 저장하고
그대로 돌려준다. 키를 하나 늘리는 데 **서버 변경이 필요 없다.**

### 2.4 블롭은 PUT 이 전체를 갈아치운다

`_saveSettings`(`web/js/core/app-settings.js:11`)가 싣는 키 목록에 새 키를 넣지 않으면,
다른 설정을 건드리는 순간 이 값이 조용히 사라진다.

### 2.5 `blockBrowserKeys` 가 배선의 본이다

같은 성격의 값이 이미 다섯 자리를 지난다 — 전역 선언(`helpers.js:205`), PUT 목록
(`app-settings.js:11`), 초기화(`_initBlockKeys`), 모달 열 때 재칠(`app-settings.js:95`),
서버에서 읽기(`app-settings.js:325`). 새 값도 **같은 다섯 자리**를 지난다.

### 2.6 문구는 우리 것이 아니다

브라우저는 `beforeunload` 의 커스텀 문구를 오래전에 폐기했다. 우리가 정할 수 있는
것은 **묻는지 여부**뿐이다.

### 2.7 가드를 재는 검증이 이미 셋 있다

`e2e/version-autoreload.spec.ts` 의 셋이 FR-RLC-5a 를 잰다.

| 검증 | 재는 것 |
|---|---|
| TC-RLC-10 | 자동 새로고침에는 확인이 걸리지 **않는다** |
| TC-RLC-10b | 만진 적 있는 페이지에서도 대화가 뜨지 **않는다** |
| TC-RLC-11 | 사용자가 떠나는 경로에서는 확인이 **걸린다** (앞 둘의 대조군) |

기본값이 끔이 되면 **앞의 둘은 가드가 어떻게 망가져도 통과한다** — 아무것도
묻지 않으므로 "묻지 않았다" 가 언제나 참이다. 그러면 FR-RLC-5a 를 지키는 검사가
셋에서 영이 된다. 뒤의 하나는 반대로 언제나 실패한다.

셋을 **스위치를 켠 상태로** 재도록 고쳐야 한다 (FR-LVC-11). 그것이 그 셋이 애초에
재려던 것이며, 이번 변경은 그 물음의 답을 바꾸지 않는다.

### 2.8 판(`?v=`)은 서버가 계산한다

`index.html` 은 `?v=__ASSETV__` 자리표시자만 적고 서버가 내용에서 채운다
(ASSET_VERSION_SINGLE_SOURCE_SRS FR-AVS-1·5). **손으로 올릴 값이 없다** —
`web/version_test.go` 는 반대로 "손으로 적은 판이 있으면" 실패한다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 A — 스위치

- **FR-LVC-1** Settings ▸ Display 패널에 `떠날 때 확인` 체크박스(`#ds-confirmleave`)가
  있다. 무엇을 위한 값인지 알리는 안내문(`.ds-hint`)이 뒤따른다.
- **FR-LVC-2** 안내문은 **꺼져 있을 때 무엇을 잃는지** 밝힌다 — 실수로 탭을 닫으면
  터미널 세션과의 연결을 되묻지 않고 잃는다. 그리고 문구는 브라우저의 것이라
  우리가 정하지 못한다는 사실도 함께 밝힌다 (§2.6).
- **FR-LVC-3** 모달을 열 때 체크박스는 현재 설정값으로 다시 칠해진다 (§2.5 의 본).

### 3.2 묶음 B — 저장

- **FR-LVC-4** 값은 설정 블롭의 `confirmLeave` 키로 서버에 저장된다. 브라우저·기기를
  가리지 않고 같은 서버에 붙은 모든 화면이 같은 판단을 쓴다.
- **FR-LVC-5** `_saveSettings` 가 싣는 키 목록에 `confirmLeave` 가 들어간다 (§2.4).
- **FR-LVC-6** 저장된 적 없으면 **끔**이다 (D-1). `blockBrowserKeys` 와 달리 기본값이
  거짓이며, 그것이 접수한 요구다.

### 3.3 묶음 C — 적용

- **FR-LVC-7** 스위치가 꺼져 있으면 가드는 `preventDefault()` 를 부르지 않는다 —
  도구가 몇 개든, 저장되지 않은 것이 있든 묻지 않는다.
- **FR-LVC-8** 스위치가 켜져 있으면 종전 동작 그대로다: 자기 새로고침이 아니고
  (§2.2) 도구가 하나라도 있으면 묻는다.
- **FR-LVC-9** 판정은 **한 자리**(`main.js` 의 그 리스너)에서만 일어난다. 스위치를
  읽는 자리를 늘리지 않는다 — 두 벌로 두면 한쪽만 고쳐진다.
- **FR-LVC-10** 스위치를 바꾸면 **다시 적재하지 않아도** 곧바로 듣는다. 전역 변수를
  가드가 그때그때 읽으므로 리스너를 다시 걸 일이 없다.

### 3.4 묶음 D — 앞선 검증의 전제

- **FR-LVC-11** 가드를 재는 **기존 검증들은 스위치를 켠 상태로 재야 한다.**
  `version-autoreload.spec.ts` 의 TC-RLC-10·10b·11 이 그것이며, 셋 다 자기 안에서
  스위치를 켠다.

  이것이 요구사항인 이유는 §2.8 이다 — 고치지 않으면 그 셋이 **검사를 멈춘다.**

## 4. 검증 (Verification)

| ID | 검증 | 수단 |
|---|---|---|
| **V-LVC-1** | 저장된 적 없는 새 브라우저에서 `beforeunload` 가 취소되지 않는다 (FR-LVC-6·7) | e2e |
| **V-LVC-2** | Display 패널에 체크박스가 있고, 켜면 `beforeunload` 가 취소된다 (FR-LVC-8) | e2e |
| **V-LVC-3** | 켠 뒤 새로고침해도 켜진 채이고 가드가 그대로 듣는다 (FR-LVC-4) | e2e |
| **V-LVC-4** | 다시 끄면 그 즉시 취소되지 않는다 — 재적재 없이 듣는다 (FR-LVC-10) | e2e |
| **V-LVC-5** | 다른 설정(테마)을 바꿔도 이 값이 살아남는다 (§2.4) | e2e |
| **V-LVC-6** | 켠 상태에서 자기 새로고침(`__dmReloading`)은 여전히 묻지 않는다 (FR-LVC-8) | e2e |
| **V-LVC-7** | 문서가 판을 손으로 적지 않았다 (§2.8) | `go test ./web` |
| **V-LVC-8** | TC-RLC-10·10b·11 이 스위치를 켠 상태로 재고 통과한다 (FR-LVC-11) | e2e |

검증 수단은 `beforeunload` 를 **직접 발화시켜 `defaultPrevented` 를 읽는다**:

```js
const ev = new Event('beforeunload', { cancelable: true });
window.dispatchEvent(ev);
return ev.defaultPrevented;
```

실제 대화창을 띄우는 경로(`page.close({runBeforeUnload:true})`)는 headless 에서
결정론적이지 않다. 우리가 정하는 것은 `preventDefault` 를 부르는지 여부이고
(§2.6), 위 발화가 바로 그것을 관측한다.

## 5. 확정 결정 (Decisions)

- **D-1 기본값은 끔이다.** 접수한 요구가 "묻지 않기" 다. 켬을 기본으로 두면 요구는
  이뤄지지 않은 채 설정 항목만 하나 늘어난다 — 사용자가 스스로 찾아 꺼야 하는
  기능은 그 요구의 답이 아니다.
- **D-2 서버 저장이다 (브라우저별 아님).** 선례가 둘 있다(FR-KEY-6·FR-TAN-19).
  기기를 옮겨도 같은 판단이 서야 한다.
- **D-3 자리는 Display 다.** `blockBrowserKeys` 는 Shortcuts 에 사는데 그 값은 **키**를
  다루기 때문이다. 이 값은 키가 아니라 떠남의 동작이므로 표시·동작 취향이 모인
  Display 가 맞다.
- **D-4 가드를 지우지 않고 토글로 둔다.** 사용자가 고른 답이다. 지우면 실수로 세션을
  잃는 경로가 되돌릴 수 없이 열린다.
- **D-5 문구는 정하지 않는다.** 브라우저가 자기 문구를 쓴다 (§2.6).
- **D-6 서버는 건드리지 않는다.** 블롭은 불투명하다 (§2.3).

## 6. 비목표 (Non-goals)

1. 확인 문구를 우리 말로 바꾸기 — 브라우저가 폐기했다 (§2.6).
2. "저장되지 않은 편집이 있을 때만 묻기" — 조건을 정교하게 하는 일은 이 요구의
   대상이 아니다. 요구는 묻지 않는 길을 여는 것이다.
3. 도구별·창별로 다른 판단.
4. 앱 자신의 확인창으로 브라우저 대화를 대신하기 — `beforeunload` 는 비동기 UI 를
   기다려 주지 않는다.
