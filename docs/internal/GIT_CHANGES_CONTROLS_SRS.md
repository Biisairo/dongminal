# SRS: Changes 사이드의 손잡이 정리 (IEEE 29148 준수)

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)
`Changes` 사이드에 손잡이가 너무 많고 생김새가 제각각이다. 쓰이지 않는 둘을 걷어내고,
남는 것을 **한 벌의 아이콘 언어**로 모으며, 새로고침을 눈이 먼저 닿는 자리로 올린다.

### 1.2 범위 (Scope)
- 포함: `Sync`·`Push preview` 제거(화면·클라이언트·**서버 API**), 원격 버튼 3종의 아이콘화,
  파일 목록 보기 방식(`Tree`/`Flat`) 아이콘화, 새로고침 버튼의 이동.
- 비포함: `Commit` 버튼(글자 유지 — D-3), 파일 행의 아이콘(`✎`·`+`·`↺`, 이미 아이콘이다),
  섹션 머리의 아이콘, 원격 동작 자체의 동작·정책(`▾` 다이얼로그의 내용), 상태바.

### 1.3 정의 (Definitions)
- **원격 버튼**: `.git-head-remote` 안의 `fetch`·`pull`·`push` 세 쌍(본 버튼 + `▾`).
- **진입점 줄**: 사이드 최상단의 아이콘 줄(`.ed-side-acts`, REPO_TAB_UNIFY_SRS FR-RTU-21).

## 2. 현황 (Current State)
실측(캡처)한 `Changes` 사이드의 세로 순서와 그 손잡이들:

| 자리 | 손잡이 | 생김새 |
|---|---|---|
| 1 진입점 줄 | History·Branches·Stash·Console·Worktrees·Submodules | **아이콘** |
| 2 커밋 | `amend` 체크박스 · `Commit` · `▾` | 글자 |
| 3 브랜치 줄 | 저장소·브랜치·배지 · **새로고침** | 아이콘(`⟳`) |
| 4 원격 1행 | `Sync` · `Preview` | **글자** |
| 5 원격 2행 | `Fetch ▾` · `Pull ▾` · `Push ▾` | **글자** |
| 6 보기 | `Tree` · `Flat` | **글자** |
| 7 목록 | 섹션 `+`·`↺`, 행 `✎`·`+`·`↺` | 아이콘 |

세 가지가 겹쳐 어수선하다.
1. 같은 패널에서 글자 버튼과 아이콘 버튼이 번갈아 선다 — 무엇이 눌리는 것인지 매번 다시 읽어야 한다.
2. 원격 버튼 여섯 개가 **두 줄**을 먹고, 사이드가 좁아 `Push` 의 `▾` 가 줄을 넘긴다(실측).
3. 새로고침이 브랜치 줄 **안**에 있어, 목록을 다시 읽고 싶을 때 눈이 세 번째 줄까지 내려가야 한다.

### 2.1 사용자 결정 (2026-09-06)
- **D-1** `Sync` 와 `Push preview` 를 지운다 — **서버 API 까지 전부**. ("뭔지도 모르고 안 써봤다")
- **D-2** 원격 버튼의 아이콘은 `⤓`(fetch) · `↓`(pull) · `↑`(push) 다.
- **D-3** `Commit` 은 글자로 남긴다. `Tree`/`Flat` 은 아이콘이 된다.
- **D-4** 새로고침은 **Changes 창의 최상단**으로 올린다.
- **D-5** 버튼이므로 **툴팁을 반드시 둔다.**
- **D-6a** 사이드 탭의 순서를 바꾼다: `Changes` 가 왼쪽, `Explorer` 가 오른쪽.

### 2.2 설계 결정
- **D-6** 아이콘 문자열을 `GIT_REMOTE_LABEL` 에 덮어쓰지 않는다. 그 상수는 **작업 진행 표시**에도
  쓰이므로(`remote.js:211·549` — 상태바와 작업 로그의 이름) 아이콘이 되면 "⤓ 중" 이 된다.
  버튼용 `GIT_REMOTE_ICON` 을 따로 세운다.
- **D-7** 새로고침은 진입점 줄의 **오른쪽 끝**에 선다. 그 줄의 나머지는 "뷰를 여는 것" 이고 이것은
  "지금 것을 다시 읽는 것" 이라 성질이 다르다 — 여백으로 갈라 같은 줄에 두되 섞이지 않게 한다.
- **D-7a 정정 (구현 실측).** 진입점 줄에 넣어 보니 그쪽은 여섯 칸이 폭을 나눠 갖는 자리라 일곱
  번째가 **다음 줄로 밀렸다.** 그래서 자리는 **사이드 탭 줄**(`.ed-side-tabs`)의 오른쪽 끝이다 —
  탭 둘뿐이라 오른쪽이 비어 있고, "창의 최상단" 이라는 D-4 의 뜻에도 그쪽이 더 맞는다.
  `Changes` 탭에서만 서는 조건(FR-GCC-12)은 그대로다.
- **D-8** 클래스 이름(`.git-head-refresh`)은 **바꾸지 않는다.** 자리가 바뀌었을 뿐 같은 버튼이고,
  이름까지 바꾸면 이 변경과 무관한 스펙·문서가 함께 흔들린다.

### 3.2 비기능 요구사항 (Non-functional)
- NFR-1 원격 동작(fetch·pull·push)의 **동작**은 한 줄도 바뀌지 않는다 — 바뀌는 것은 버튼의 얼굴이다.
- NFR-2 `▾` 다이얼로그의 내용·정책은 그대로다.
- NFR-3 아이콘만 남는 버튼은 전부 `title` 을 가진다 (FR-TIP-2 와 같은 규약).
- NFR-4 서버에서 지운 종단 셋 외의 git API 는 손대지 않는다.

### 3.3 이전 동작 / 새 동작 / 이유
| 항목 | 이전 | 새 | 이유 |
|------|------|-----|------|
| `Sync`·`Preview` | 브랜치 줄 아래 글자 버튼 둘 | 없음 | 쓰이지 않았다 (D-1) |
| 원격 버튼 | `Fetch`·`Pull`·`Push` 글자 | `⤓`·`↓`·`↑` + 툴팁 | 좁은 사이드에서 두 줄을 먹고 `▾` 가 줄을 넘겼다 |
| `Tree`·`Flat` | 글자 | 아이콘 + 툴팁 | 같은 패널의 언어를 하나로 |
| 새로고침 | 브랜치 줄 안 | 진입점 줄 오른쪽 끝 | 목록을 다시 읽는 손이 가장 먼저 닿는 자리 (D-4) |
| 사이드 탭 순서 | `Explorer` · `Changes` | `Changes` · `Explorer` | 이 창을 여는 이유가 대개 변경을 보는 것이다 (D-6a) |

## 5. 리스크
- MEDIUM: 서버 종단 제거는 되돌리기 비용이 있다. 클라이언트가 유일한 소비자임을 확인했다(전수 grep).
- MEDIUM: 새로고침의 자리가 바뀌면 그 버튼을 `.git-view.git-changes` 안에서 찾던 e2e 가 전부 어긋난다 —
  스코프를 사이드로 올려야 한다(실측 대상: git-improve · git-polling · git-view-refresh · git-worktrees).
  **전량 실행에서 드러난 것은 그 넷이 아니었다** — `git-head-mobile` 도 같은 이유로 무너졌고, 그
  파일은 `Sync`·`Preview` 가 머리에 **서는 것**까지 단정하고 있었다 (V1·V2·V3·V5·V6·V7).
- LOW: 아이콘 오독. `⤓`(fetch)와 `↓`(pull)은 방향이 같아 헷갈릴 수 있다 — 툴팁이 그 자리를 메운다 (D-5).
