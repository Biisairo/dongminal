## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

**사용자의 워크스페이스가 조용히 사라지지 않게 한다.**

세 구멍이 한 뿌리다 — 상태 파일이 깨졌을 때 **돌아갈 곳이 없고**(`G4-1`),
깨진 것을 **알아채는 자리가 없고**(`G4-2`), 그 상태에서 브라우저가 **빈 판을
덮어쓴다**(`FE-2`). 셋을 함께 닫아야 "덮어쓰지 않는다" 가 불변식이 된다.

### 1.2 왜 M4 앞인가

M4 가 인증을 넣으면 **401 이 프론트 부팅 실패의 새 트리거**가 된다. 지금 부팅이
실패하면 빈 판을 저장하는 경로가 열려 있으므로(§2.3), 인증을 먼저 넣으면 그
트리거가 손실로 이어진다. 로드맵 §M3 의 내부 순서가 그 이유를 적고 있다.

## 2. 현재 상태 (조사로 확정한 사실, 2026-09-11)

### 2.1 `WriteFileAtomic` 호출부는 일곱이고, 그중 **여섯**이 상태 파일이다

| # | 자리 | 파일 | 세대 대상 |
|---|---|---|---|
| 1 | `workspace/fs.go:22` | `workspace.json` | ✅ |
| 2 | `sandboxplace/place.go:89` | 샌드박스 배치 | ✅ |
| 3 | `toolhub/persist.go:87` | `tools.json` | ✅ |
| 4 | `httpapi/access.go:174` | `access.json` | ✅ |
| 5 | `httpapi/handlers_settings.go:58` | `settings.json` | ✅ |
| 6 | `run/store.go:149` | `runs.json` | ✅ |
| 7 | `httpapi/handlers_files.go:441` | **사용자가 편집기로 저장하는 파일** | ❌ |

**일곱째는 대상이 아니다.** 그것은 우리 상태가 아니라 사용자의 원본이고, 거기에
`.bak.1`~`.bak.3` 을 만들면 사용자의 작업 디렉터리가 우리 파일로 더럽혀진다.
사용자 파일의 보존은 git 과 편집기 자신의 일이다.

**쓰기는 이미 원자적이다** — `WriteFileAtomic` 은 임시 형제 파일에 쓰고
`fsync` 후 `rename` 한다(`paths.go:297`). 이 문서가 더하는 것은 **원자성이 아니라
되돌아갈 곳**이다.

### 2.2 손상은 **감지되지만 아무 일도 일어나지 않는다**

```go
// manager.go:113-122
ix, perr := buildIndex(buf)
if perr != nil {
    if errors.Is(perr, ErrSchemaTooOld) { return nil, perr }
    ix = emptyIndex()      // ← 파싱 불가는 빈 인덱스로 지나간다
}
```

격리도, 복원도, 알림도 없다. 그리고 **인덱스만 비고 raw 는 그대로 남으므로**,
브라우저가 그 raw 를 읽지 못해 빈 판을 만든 뒤 저장하면 그것이 곧 덮어쓰기다.

### 2.3 워크스페이스 PUT 은 `If-Match` 를 **요구하지 않는다**

```go
// manager.go:211
if ifMatch != "" { ... }   // 비어 있으면 검사하지 않는다
```

`GET /api/state` 는 `ETag` 를 주는데(`handlers_api.go:230`) 쓰기는 그것을 요구하지
않는다. 그래서 **아무것도 읽지 않은 클라이언트가 빈 판을 올릴 수 있다.**

### 2.4 상위 스키마를 **조용히 읽는다**

```go
// manager.go:541
if s.SchemaVersion < SchemaVersion { return nil, ErrSchemaTooOld }
```

`<` 만 본다. `schemaVersion: 3` 인 파일은 이 코드가 모르는 필드를 담고 있는데도
**통과한다** — 읽고, 모르는 것을 버리고, 저장하면 그 순간 **다운그레이드 손실**이다.

### 2.5 프론트의 부팅 실패 갈래가 저장으로 이어진다

`app.js:218-221` 의 `catch` 는 창이 없으면 새로 만든다. 그 뒤의 정상 흐름이
`_save()` 를 부르면 방금 만든 **빈 판**이 PUT 된다. 서버가 `If-Match` 를 요구하지
않으므로(§2.3) 그 PUT 은 성공한다.

## 3. 요구사항 (Requirements)

### 3.1 묶음 B — 백업 세대

**FR-SFD-1** 상태 파일을 덮어쓰기 전에 **직전 내용을 세대로 남긴다.**

**FR-SFD-2** 세대는 **3** 이다 (사용자 결정). `<파일>.bak.1` 이 가장 최근이고
`.bak.3` 이 가장 오래됐다. 회전은 `3→버림 · 2→3 · 1→2 · 현재→1` 이다.

> 셋인 이유: 손상은 보통 마지막 쓰기에서 오고 그때는 직전 하나면 된다. 나머지
> 둘은 **손상된 채로 몇 번 저장된 뒤에 알아채는** 경우의 여유다. 비용은
> 상태 파일 크기×3 이며 수십 KB 급이다.

**FR-SFD-3** **사용자 파일은 대상이 아니다** (§2.1 의 일곱째). 그 자리의 보존은
git 과 편집기의 일이며, 우리 파일을 사용자의 작업 디렉터리에 만들지 않는다.

**FR-SFD-4** 세대를 남기다 실패해도 **쓰기는 진행한다.** 세대는 여유이지 조건이
아니다 — 백업을 못 만든다고 저장을 막으면 디스크가 찬 순간 제품이 멈춘다.
실패는 기록하고 지나간다.

**FR-SFD-5** 원자성은 유지된다. 세대 회전은 **쓰기 전에** 끝나고, 실제 쓰기는
종전의 `WriteFileAtomic` 그대로다 (`fsync`+`rename`).

**FR-SFD-6** 대상 파일이 **없으면** 세대를 만들지 않는다. 첫 쓰기에 빈 `.bak` 을
만들면 그것이 나중에 "복원할 것이 있다" 는 거짓 신호가 된다.

### 3.2 묶음 Q — 손상 감지·격리·복구

**FR-SFD-10** `workspace.json` 이 **읽히지 않으면 격리한다** — `<파일>.corrupt-<ts>`
로 옮긴다. 덮어쓰지 않고 옮기는 이유는 그것이 **신고의 증거**이기 때문이다.

**FR-SFD-11** 격리본은 **자동으로 지우지 않는다** (사용자 결정). 지우는 것은
사용자가 판단한다. `doctor --bundle`(`G2-3`, M3 ⑤)이 그것을 모아 붙인다.

**FR-SFD-12** 격리 뒤 **최근 세대부터 차례로 복원을 시도한다** (`.bak.1`→`.bak.3`).
읽히는 첫 세대가 현재 판이 된다.

**FR-SFD-13** 복원할 세대가 하나도 없으면 **빈 상태로 시작한다.** 그것이 지금
동작이며 이 문서가 바꾸지 않는다 — 다만 그 사실이 헬스에 실린다.

**FR-SFD-14** 무슨 일이 있었는지 **헬스에 싣는다** (`VERSION_HEALTH_SRS FR-VHL-10`
의 자리). `workspace.lastLoadErr` 는 **분류 문자열**이며 경로를 담지 않는다
(`FR-VHL-14`): `""`(정상) · `"parse"` · `"restored"` · `"empty"`.

**FR-SFD-15** **상위 스키마는 거부한다.** `s.SchemaVersion > SchemaVersion` 이면
읽지 않고 오류를 낸다. 모르는 필드를 버리고 저장하면 그것이 다운그레이드 손실이다.

  - 이전 동작: `<` 만 봤다 — 상위 판이 조용히 통과했다
  - 새 동작: 위아래 모두 거부한다. 아래는 `migrate` 안내, 위는 **판 갱신** 안내
  - 이유: §2.4

### 3.3 묶음 W — 빈 판 덮어쓰기 방지

**FR-SFD-20** 워크스페이스 PUT 은 **`If-Match` 를 요구한다.** 없으면 **428**
(Precondition Required) 이다. 클라이언트는 그때 **재조회부터** 다시 한다.

> 428 을 고른 이유: 409 는 "경합했다", 412 는 "조건이 틀렸다" 이고, 여기서 일어난
> 일은 **조건을 아예 보내지 않았다** 이다. 그 셋을 같은 코드로 답하면 클라이언트가
> 무엇을 해야 할지 가릴 수 없다.

**FR-SFD-21** 관대함의 경계를 여기 적는다. `Save(blob, "")` 를 **서버 내부**에서
부르는 자리는 그대로 둔다 — 이 요구는 **HTTP 표면**의 계약이다. 내부 호출자는
자기가 방금 읽은 것을 쓰는 쪽이라 경합 대상이 아니다.

**FR-SFD-22** 프론트는 **부팅에 실패한 판을 저장하지 않는다.** `app.js` 의
`catch` 갈래가 만든 판은 화면을 세우기 위한 것이지 디스크에 쓸 것이 아니다.

### 3.4 비기능

| ID | 요구사항 |
|---|---|
| NFR-SFD-1 | 세대 회전이 저장 지연을 눈에 띄게 늘리지 않는다 — 상태 파일은 수십 KB 이고 회전은 `rename` 셋이다 |

## 4. 설계 결정 (Design Decisions)

- **D-1. 세대는 `WriteFileAtomic` 의 **호출부**가 아니라 그 **곁**에 둔다.** 일곱
  호출부 중 여섯만 대상이므로, 함수 자체를 바꾸면 일곱째까지 딸려 온다.
  세대를 남기는 새 함수(`WriteStateFile`)를 두고 여섯을 그쪽으로 옮긴다.
- **D-2. 격리는 워크스페이스만 한다** (이번 범위). 나머지 다섯도 같은 기계가
  필요하지만, 손실의 크기가 다르다 — 워크스페이스가 사용자의 작업 그 자체다.
  나머지는 §6 비목표 2.
- **D-3. `If-Match` 를 **요구**로 바꾼다.** 관대함을 남기면 그 길로 빈 판이 들어온다.
- **D-4. 격리본을 지우지 않는다** (사용자 결정). 증거를 자동으로 없애지 않는다.
