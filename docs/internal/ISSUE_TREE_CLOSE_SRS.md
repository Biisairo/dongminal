# SRS: issue-tree 종료 — 조율 에이전트 · 종료 요청 · 단계별 준비 · 병합 확인 뒤 정리 — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: 실제 트리로 중간 종료와 정상 완료를 한 번씩 시범한다(절차 FR-ITX-10~37 은 에이전트가 따르는 문서라 시험이 문장만 확인한다). 묶음 G·프리앰블은 Go 시험으로 닫혔다.

## 2. 현황 (Identified Issue)

### 2.1 루트가 자기 Run 을 닫다가 멈춘다

`issue-tree.md` 「루트 노드의 끝」 은 ① 병합 확인 → ② `run close --run <루트 Run>` → ③ `delete-group` → ④ 최종 보고 순서다.

- 루트 노드는 루트 Run 의 멤버다. 끝내기 절차에 `run report` 가 없다. 그래서 ②는 보고하지 않은 멤버 때문에 `ErrUnreportedMembers` 로 거절된다 (`domain/run/store_write.go:310`).
- `--force` 로 통과시키면 서버가 살아 있는 멤버 전부에게 `/exit` 를 보내고 탭을 닫는다 (`httpapi/handlers_runs_cleanup.go:60-101`). 그 대상에 루트 자신도 들어간다. 그래서 ③·④가 실행되지 않는다.

### 2.2 window 가 남는다

`delete-group` 은 window 를 닫지 않고 그룹에서 풀기만 한다 (`dmctl_order.go:23`). 루트 window 와 그 안의 탭이 화면에 남는다.

### 2.3 도중에 끝내는 길이 없다

절차는 「루트 이슈의 하위가 모두 닫혔을 때」 만 다룬다. 사용자가 노드에서 「닫자」 고 하면 따를 절차가 없다. 병렬 가지 Run 이 여럿 열려 있으면 그것을 닫는 순서도 없다.

### 2.4 발사대가 빠진다

발사대는 루트를 띄운 뒤 보고하고 빠진다(「발사대 절차」 6). 루트 Run 의 `coordinatorToolId` 는 발사대지만, 루트의 트리 프리앰블은 「부모: 없음」 이다 (`domain/run/preamble_tree.go:41-45`). 트리 밖에서 트리 전체를 볼 자리가 없다.

### 2.5 worktree 정리는 병합을 보지 않는다

`run close` 의 worktree 정리 (`worktree/remove.go`)는 다음과 같다.

- 커밋하지 않은 변경이 있으면(dirty) 지우지 않는다(`dirty` 잔여물).
- 깨끗하면 worktree 를 지우고, 브랜치는 `git branch -d` 로 지운다. 메인 worktree 의 HEAD 에 병합되지 않은 브랜치는 지워지지 않는다(`branch-retained`).

그래서 **커밋은 했지만 병합하지 않은 worktree 도 지운다.** 커밋은 브랜치에 남지만, 사용자의 요구(병합되지 않았으면 정리하지 않는다)와 어긋난다. 또 Run 기록에는 시작 commit(`Base`)만 있고 「어느 브랜치에 병합돼야 하는가」 는 없다.

| FR-ITX-35 | 정상 완료(FR-ITX-4)에서는 FR-ITX-12~19 를 건너뛰고 FR-ITX-31 부터 한다 | 필수 |
| FR-ITX-36 | **대신 조율.** 조율이 없으면 루트가 조율의 일(FR-ITX-12~18 · 31~34)을 자기 탭에서 맡는다. 조율이 없다는 것은 셋 중 하나다: 프리앰블이 「부모: 없음」 · 조율에게 보낸 `msg` 가 전송되지 않음 · `dmctl status --at <조율>` 이 `live=false` 이거나 `state=unknown`(에이전트가 끝나면 활동 기록이 지워진다). 루트는 조율에게 보내기 전에 늘 `status` 를 본다 | 필수 |
| FR-ITX-37 | 대신 조율하는 루트는 ① `종료 준비` 를 자기에게 보내지 않고 바로 하위에 내린다 ② 가지 Run 을 닫은 뒤 자기 window 의 다른 노드 탭을 `close-tab --force` 로 닫는다(`--keep-tools` 는 탭을 하나도 닫지 않는다) ③ 자기 window 는 닫지 않고 그룹을 지운다 ④ 자기 `run report` 뒤 루트 Run 을 `--keep-tools` 로 **맨 마지막 명령**으로 닫는다(자기 worktree 가 지워질 수 있다) ⑤ 최종 보고에 「이 탭과 window 는 직접 닫는다」 를 적는다 | 필수 |

### 3.4 묶음 G — 서버 가드 (FR-ITX-40~49)

| ID | 요구 | 우선 |
|---|---|---|
| FR-ITX-40 | 격리 Run 을 열 때(`run start --isolation …`) 서버는 cwd 저장소의 현재 브랜치 이름(`git symbolic-ref --short HEAD`)을 Run 기록의 `mergeInto` 에 남긴다. HEAD 가 분리돼 있으면 비운다 | 필수 |
| FR-ITX-41 | 트리 Run(`tree` 가 있는 Run)을 닫을 때 서버는 worktree 하나마다 그 브랜치가 `mergeInto` 의 조상인지(`git merge-base --is-ancestor <branch> <mergeInto>`) 본다. 조상이 아니면 그 worktree 와 브랜치를 지우지 않고 잔여물 `unmerged` 로 보고한다. `mergeInto` 가 비었거나 판정이 실패해도 `unmerged` 다 | 필수 |
| FR-ITX-42 | FR-ITX-41 의 판정을 통과한 트리 Run 의 브랜치는 `git branch -D` 로 지운다. 그 커밋은 모두 `mergeInto` 에서 닿기 때문이다 | 필수 |
| FR-ITX-43 | 판정과 제거는 같은 저장소 잠금 안에서 한다. 잠금을 쥔 뒤 판정한다 | 필수 |
| FR-ITX-44 | 서버는 병합 · rebase · reset 같은 쓰기 git 명령을 하지 않는다. 판정은 읽기 전용이다 | 필수 |
| FR-ITX-45 | 트리가 아닌 Run 의 정리 규칙은 바뀌지 않는다 | 필수 |
| FR-ITX-47 | 격리 Run 의 `repo` 는 **메인 worktree 경로**다. cwd 가 연결된 worktree(가지 Run 은 부모 worktree 에서 연다)여도 그렇다. 메인 경로를 구하지 못하면 cwd 의 toplevel 이다 | 필수 |
| FR-ITX-48 | 정리할 때 기록의 `repo` 경로가 없으면(옛 가지 Run 의 기록이 지워진 부모 worktree 를 가리킨다) 대상 worktree 에서 메인 worktree 경로를 구해 쓴다 | 필수 |
| FR-ITX-46 | `unmerged` 잔여물이 있으면 Run 기록은 지우지 않는다(FR-DEL-9a 와 같다). 나중에 병합한 뒤 `dmctl run close --run <id> --force`(정리 전용 진입, FR-WKT-8a)를 부르면 다시 판정한다 | 필수 |

## 4. 결정 (Decisions)

| ID | 결정 | 근거 |
|---|---|---|
| D-ITX-1 | 트리 종료는 그룹 밖의 조율 에이전트가 한다. 종료 의사는 한 단계씩 위로 올린다 | 사용자 결정(2026-11-08). 안전 판정(하위 병합 · 커밋하지 않은 변경 · 일하는 하위)은 각 노드만 자기 범위에서 할 수 있다. 조율은 그룹 밖에 있어 그룹을 모두 닫아도 보고할 자리가 남는다. 루트가 자기 Run 을 닫다가 멈추는 문제(§2.1)도 함께 풀린다 |
| D-ITX-2 | 서버에 「트리 통째로 닫기」 명령을 두지 않는다. 조율은 기존 명령(`run close` · `close-window` · `delete-group`)을 순서대로 부른다 | 안전 판정이 노드에 있으므로, 서버가 한 번에 닫으면 판정을 건너뛴다. 사용자 지시: 서버가 임의로 git 정리를 해서는 안 된다 |
| D-ITX-3 | 미완료 노드는 조율이 사용자에게 노드마다 보존·버림을 묻는다 | 사용자 결정(2026-11-08). 묻는 자리를 조율 한 곳으로 모아 사용자가 탭을 옮겨 다니지 않게 한다 |
| D-ITX-4 | 조율이 없으면 루트가 대신 조율한다. 같은 트리로 발사대를 다시 불러 자리를 이어받는 장치는 두지 않는다 | 사용자 결정(2026-11-08). 대가로 루트의 탭과 window 는 남는다(FR-ITX-37) |
| D-ITX-5 | 서버는 트리 Run 의 worktree 를 병합 대상에 병합된 뒤에만 지운다 | 사용자 결정(2026-11-08): 「병합되지 않은 worktree 는 정리하면 안 되고, 마음대로 병합해서도 안 된다」 |
| D-ITX-6 | 병합 대상은 `run start` 시점 cwd 의 현재 브랜치다 | 루트 Run 은 발사대가 사용자 저장소에서 연다(사용자 브랜치). 가지 Run 은 부모 worktree 에서 연다(부모 브랜치). 규칙 하나로 둘 다 맞는다 |
| D-ITX-7 | 미완료 노드는 `run report --outcome failed` 로 보고한다. 새 결과 값을 만들지 않는다 | 결과 값은 `succeeded` · `failed` 둘이다. 이유는 `--summary` 에 「트리 종료로 중단」 으로 남긴다. 값을 더하면 Run 화면·집계를 모두 고쳐야 한다 |

## 6. 비목표 (Non-goals)

- 트리 일부(가지 하나)만 닫는 것. 종료는 트리 전체다

- 조율이 사라진 뒤 새 조율이 자리를 이어받는 것 (D-ITX-4). 조율이 살아 있을 때 넘기는 것(migration)은 FR-ITX-7~9 다
