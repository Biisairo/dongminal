# SRS: 포커스를 잃은 창의 가장자리 표시 (IEEE 29148 준수)

> **문서 상태**: 승인·구현완료

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)
이 브라우저 창이 **OS 포커스를 갖지 않은 상태**임을 화면 가장자리에서 알린다. 여러 창·여러 기기에
같은 워크스페이스를 띄웠을 때, 지금 키를 받는 창이 어느 것인지 화면만 보고 알 수 있어야 한다.

### 1.2 범위 (Scope)
- 포함: `web/index.html`(오버레이 마크업 · 설정 행), `web/style.css`(가장자리 그라데이션),
  `web/js/core/app-focus.js`(클래스 토글), `web/js/core/app.js`(초기 반영),
  `web/js/core/helpers.js`(전역 기본값), `web/js/core/app-settings.js`(설정 배선·복원),
  `web/js/core/constants.js`(상수), `web/js/core/main.js`(복원 시 반영), `e2e/unfocused-edge.spec.ts`(신규).
- 비포함: 창별(dongminal window) 포커스 소유권 표시(`applyFocusOverlay`, 기존 `.pn` dim), 알람 링(`.pn.attn`),
  펄스·애니메이션, 서버측 변경(`/api/settings` 는 해석하지 않는 blob 이다).

### 1.3 정의 (Definitions)
- **OS 포커스**: `document.hasFocus()` 가 참인 상태. 앱은 이것을 `app.windowFocused` 로 들고 있다.
- **가장자리 표시(edge indicator)**: 화면 네 변에서 안쪽으로 지정 거리만큼 페이드아웃하는 오버레이.
- **반전 혼합**: `mix-blend-mode:difference` 로 아래 픽셀의 보색을 그리는 것. 어떤 테마·어떤 화면
  내용 위에서도 대비가 보장된다.

## 2. 현황 (Current State)
1. `app.windowFocused` 는 이미 있다 — 초기값은 `document.hasFocus()`(`app.js:20`), 유지는
   `_initFocusSync()` 의 `focus`/`blur` 리스너(`app-focus.js:110-116`)다.
2. 그 값은 **동작**에만 쓰인다: 리사이즈 전송 허가(`resizeCheck`), 재연결 시 소유권 재주장
   (`_focusRestore`), 렌더러의 분기(`renderer.js:312`). 화면에는 아무 표시도 없다.
3. 화면에 있는 dim 은 다른 것이다 — `applyFocusOverlay` 의 `.pn` dim 은 "이 **창**을 다른
   클라이언트가 소유한다" 는 뜻이며(FR-XDF), 이 브라우저 창의 OS 포커스와 무관하다.
4. 결과: 창 두 개를 나란히 띄우면 둘 다 같아 보인다. 어느 쪽에 키가 가는지 눌러 봐야 안다.

### 2.1 사용자 결정 (2026-09-06)
- **D-1** 표시는 **가장자리에서 안쪽으로 페이드아웃**하는 형태다(에이전트 작업 표시의 관용구).
- **D-2** 투명도를 써서 **글을 읽는 데 불편하지 않아야** 한다. 화면 중앙은 손대지 않는다.
- **D-3** 색은 "확 대비되고 잘 쓰지 않는 색" 이거나 **겹치는 영역의 반대값(색상 반전)** 이다.
- **D-4** 설정에서 켜고 끌 수 있고 **기본은 켬**이다.
- **D-4a**(개정) on/off 와 세기를 **하나의 0~10 레인지**로 합친다. 기본은 5이고 **0 이 곧 끔**이다.
  스위치와 정도를 따로 두면 "켜져 있는데 0" 같은 뜻 없는 상태가 생기고, 손잡이도 둘이 된다.

### 2.2 설계 결정
- **D-5a**(2026-09-08 개정) 반전은 유지하되 **채도를 얹는다**. 접수한 말은 "보색으로
  해달라고 했는데 그냥 흰색같아서" 였고, 조사는 그 관찰이 옳음을 확인했다 — 흰 소스의
  `difference` 는 수학적으로 `invert(1)` 과 같고, 어두운 테마(`#1a1b26`·`#282a36`)의
  반전값은 채도가 낮아 밝은 회색이다. 고정색을 쓰지 않는다는 D-3·D-5 는 그대로 두고
  (색은 여전히 아래 픽셀에서 파생한다) 결과에 `saturate(10)` 을 얹는다. 같은 자리를
  실측하면 배경 h≈230° 에 대해 가장자리가 h 55°·s 41% 로 선다.
  수단도 함께 바뀐다: `mix-blend-mode` 대신 **`backdrop-filter` + 마스크**이며,
  네 변이 각자의 겹이다 — 필터를 화면 전체가 아니라 띠에만 걸기 위해서다.
- **D-5b**(같은 개정) 세기 곡선을 레벨당 `.04` → `.1` 로 올린다. 반전이 20% 만 섞이면
  무엇을 하든 옅은 빛 하나로 수렴한다. 안쪽 감쇠(`UFE_ALPHA_MID_RATIO`)는 그대로이므로
  글자 위의 영향은 종전과 거의 같다.
- **D-5e**(2026-09-08, 최종) 표시는 **겹 하나**이고 액자는 **마스크**가 만든다 —
  전체(L1)에서 안쪽 사각형(L2~L5 의 교집합)을 뺀다(`mask-composite:exclude,intersect…`).
  안쪽 사각형의 경계가 `--edge-fade`(64px)에 걸쳐 부드러우므로 색은 가장자리에서
  가장 진하고 안쪽으로 갈수록 옅어진다 (접수: "색상이 안쪽으로 들어갈수록
  흐려지는거지?"). 실측 프로파일: y=0 (154,149,93) → y=25 (127,123,82) →
  y=45 (83,81,64) → y=70 배경. 같은 깊이에서 변과 모서리가 58~60% 로 같다.

  **버린 두 안과 그 이유** (둘 다 실측으로 기각):
  ① 네 변을 각자의 요소로 두기 — 모서리에서 겹쳐 `invert` 가 두 번 걸린다
     (접수한 관찰: "보색의보색으로 나오는거같은데").
  ② 각 변을 사다리꼴로 잘라 45° 로 맞물리기 (접수: "액자처럼 대각으로") —
     **같은 요소의 `clip-path` 가 `mask-image` 를 무효로 만든다.** 페이드가 죽고
     균일한 색만 남았다(상단 프로파일 y=0~60 이 같은 값, y=70 에서 뚝 끊김).
     대각 자르기와 "안쪽으로 흐려짐" 은 한 요소에서 공존하지 못한다.

  세기(`--ufe-alpha`)는 요소의 `opacity` 다. **자식에 두지 않는다**: 부모에
  `opacity:<1` 을 두면 그것이 backdrop root 를 만들어 자식의 `backdrop-filter` 가
  바깥 화면을 보지 못한다(실측: 표시가 통째로 사라졌다) — 겹이 하나이므로 이
  함정도 함께 사라졌다.
- **D-5** D-3 의 두 안 중 **반전 혼합**을 택한다. 고정색은 테마마다 대비가 달라지고(어떤 테마에서는
  그 색이 이미 팔레트에 있다), 반전은 아래 픽셀에서 파생하므로 43개 테마 어디서도 반드시 대비된다.
- **D-6a**(2026-09-08, 확인) "블러" 는 **색이 안쪽으로 옅어지는 것**이었다. 접수한
  말이 "왜 블러는 안해" → "그냥 대각으로 하고 블러만 해봐" → "아니 색상이 안쪽으로
  들어갈수록 흐려지는거지?" 로 이어지며 그 뜻이 확정됐다. 중간에 `blur(5px)` 를
  실제로 얹어 봤고(그 자리의 글자가 함께 뭉개졌다) 걷어냈다 — **D-6 은 그대로다.**
  흐려지는 것은 마스크의 알파이지 화면의 픽셀이 아니다.
- **D-6** blur 는 쓰지 않는다. 터미널은 1px 획의 텍스트라 약한 blur 로도 글자가 뭉개져 D-2 와 정면으로
  충돌하고, 전체 화면 blur 는 터미널이 출력할 때마다 그 영역을 다시 합성한다.
- **D-7** 값은 `/api/settings` blob 에 실린다 — `confirmLeave`·`blockBrowserKeys` 와 같은 근거(D-2 of
  LEAVE_CONFIRM_TOGGLE_SRS): 취향 스위치가 기기마다 어긋나면 같은 사람이 기기를 옮길 때마다 다시 끈다.
- **D-8a** 깊이(`--ufe-depth`)와 전이 시간은 **CSS 에만** 산다 — 조절 대상이 아니다.
- **D-8e** 저장하는 값은 **레벨(정수 0~10)** 이다. 알파(`level × UFE_ALPHA_PER_LEVEL`)를 저장하면
  눈금과 저장값이 두 벌이 되고, 손으로 고친 설정 파일이 눈금 사이에 앉는다.
- **D-8b** 세기(`--ufe-alpha`)는 사용자 값이 되었으므로 **JS 가 진실**이다. `:root` 에 리터럴을 함께
  두지 않는다: 그러면 같은 값이 두 벌이 되고 한쪽만 고쳐진다. 오버레이가 보이는 것 자체가
  `win-unfocused` 클래스(JS 소관)에 달려 있으므로, 변수도 JS 가 세우는 편이 경계가 맞다.
- **D-8c** 중간 정지점(`--ufe-alpha-mid`)은 세기에서 **파생**한다(`UFE_ALPHA_MID_RATIO`). 둘을 따로
  받으면 사용자가 두 값의 관계를 직접 맞춰야 하고, 그 관계는 취향이 아니라 곡선의 성질이다.
- **D-8d** 세기를 조절하는 동안에는 표시를 **강제로 보인다**. 이 표시는 포커스를 잃었을 때만 뜨는데,
  슬라이더를 만지는 동안 창은 반드시 포커스를 가지고 있다 — 미리보기가 없으면 눈을 감고 고르는 셈이다.
- **D-8** 오버레이는 **정적 마크업**이다. 표시 여부는 `documentElement` 의 클래스 하나로 정한다 —
  포커스는 초당 여러 번 오갈 수 있고, 그때마다 DOM 을 만들고 지울 이유가 없다.

## 3. 요구사항 (Requirements)

### 3.1 기능 요구사항 (Functional)
| ID | 요구사항 | 우선 |
|----|---------|------|
| FR-UFE-1 | `index.html` 은 `#focus-edge` 오버레이를 정적 마크업으로 가진다. 안에는 네 변의 겹 넷뿐이다 (D-5a) — 필터를 화면 전체가 아니라 띠에만 걸기 위한 자리다. | 필수 |
| FR-UFE-2 | `#focus-edge` 는 포인터 이벤트를 받지 않는다 — 화면 위의 어떤 조작도 가로채지 않는다. | 필수 |
| FR-UFE-3 | 표시는 화면 가장자리를 두르는 **균일한 액자 하나**다 (D-5c 개정). 두께는 `--ufe-band` 이고 그 안쪽은 완전히 투명하다 (D-2). | 필수 |
| FR-UFE-4 | 색은 아래 픽셀에서 파생한다 (D-5) — `backdrop-filter:invert(1) saturate(--ufe-sat)` (D-5a 개정). 팔레트의 특정 색을 쓰지 않는다. | 필수 |
| FR-UFE-5 | 세기는 `--ufe-alpha`(= 요소의 opacity)다. 기본값에서 1 미만이므로 그 자리의 글자도 형태를 유지한다. | 필수 |
| FR-UFE-6 | OS 포커스를 잃으면 `documentElement` 에 `win-unfocused` 클래스가 붙고, 얻으면 떨어진다. | 필수 |
| FR-UFE-7 | 클래스는 `_initFocusSync()` 의 `focus`/`blur` 와 **같은 자리**에서 토글된다 — `windowFocused` 와 다른 진실을 만들지 않는다. | 필수 |
| FR-UFE-8 | 첫 화면도 실제 포커스 상태를 반영한다 — 배경 탭에서 연 창은 처음부터 표시가 켜져 있다. | 필수 |
| FR-UFE-9 | 나타남과 사라짐은 0.2초 동안 opacity 로 전이한다 — 창을 오갈 때 깜빡이지 않는다. | 필수 |
| FR-UFE-10 | Settings ▸ Display 에 `포커스 잃은 창 표시` 레인지(0~10)가 있다. 손잡이는 그 하나뿐이다 (D-4a). | 필수 |
| FR-UFE-11 | 값을 바꾸면 즉시 화면에 닿는다 — 새로고침을 요구하지 않는다. 0 으로 내리면 표시가 사라진다. | 필수 |
| FR-UFE-12 | 값은 `focusEdgeLevel`(정수)로 `/api/settings` blob 에 저장되고 다음 로드에서 복원된다 (D-7·D-8e). | 필수 |
| FR-UFE-13 | 저장된 값이 없으면 `UFE_LEVEL_DEFAULT`(5)다 — 기존 사용자도 이 기능을 보게 된다. 범위 밖의 값은 기본값으로 떨어진다. | 필수 |
| FR-UFE-14 | 설정 모달을 열 때마다 레인지는 현재 값으로 다시 칠해진다 (FR-LVC-3 과 같은 근거). | 필수 |
| FR-UFE-15 | 레인지 옆에 현재 값이 보인다. 0 은 `끔`, 그 외는 숫자다 (SETTINGS_CONTROLS_SRS D-7). | 필수 |
| FR-UFE-16 | 레인지를 움직이면 `--ufe-alpha` 가 **즉시** 바뀐다. 저장은 조작이 멎은 뒤 한 번만 한다 (`tabWidthPx` 와 같은 근거). | 필수 |

| FR-UFE-20 | 레인지의 생김새는 `SETTINGS_CONTROLS_SRS` 의 `.ds-range` 를 따른다. | 필수 |

### 3.2 비기능 요구사항 (Non-functional)
- NFR-1 표시가 켜져 있어도 터미널 텍스트의 글자꼴은 흐려지지 않는다 (D-6: blur 금지).
- NFR-2 오버레이는 합성 레이어 하나다. 포커스 전환 외에는 어떤 스크립트도 돌지 않는다.
- NFR-3 기존 `.pn` dim(`applyFocusOverlay`)·알람 링(`.pn.attn`)과 겹쳐도 서로를 가리지 않는다 —
  이 표시는 화면 **가장자리**에, 그것들은 칸 **경계**에 산다.
- NFR-4 기존 e2e 는 수정 없이 통과한다. 헤드리스 브라우저는 포커스를 가진 상태로 뜨므로 평상시 이 표시는 없다.

### 3.3 이전 동작 / 새 동작 / 이유
| 항목 | 이전 | 새 | 이유 |
|------|------|-----|------|
| 포커스를 잃은 창 | 화면상 구분 없음 | 가장자리에 반전 그라데이션 | 어느 창이 키를 받는지 눌러 보지 않고 알아야 한다 |
| `windowFocused` | 동작 판단에만 쓰임 | 화면 표시의 근거이기도 함 | 진실을 하나로 둔다 (FR-UFE-7) |
| `/api/settings` | `focusEdge` 없음 | `focusEdge:boolean` | 취향 스위치는 기기를 옮겨도 같아야 한다 (D-7) |

## 4. 검증 (Verification)
| ID | 대상 | 검증 방법 |
|----|------|----------|
| V-1 (FR-UFE-6·8·9) | e2e: 새 창(혹은 `blur` 디스패치)으로 포커스를 뺏고 `documentElement` 에 `win-unfocused` 가 붙는지, 되돌리면 떨어지는지 확인한다. |
| V-2 (FR-UFE-1·2·3) | e2e: `#focus-edge` 의 `pointer-events` 가 `none` 이고, 화면 중앙 좌표의 최상위 요소가 오버레이가 아님을 확인한다. |
| V-3 (FR-UFE-4·5) | e2e: 계산된 `mix-blend-mode` 가 `difference` 이고 배경 그라데이션의 최대 알파가 1 미만이다. |
| V-4 (FR-UFE-10·11) | e2e: 레인지를 0 으로 내리면 포커스를 잃어도 오버레이가 보이지 않고, 올리면 보인다. |

## 5. 리스크
- LOW: 표시 계층 하나가 는다. 실패 경로는 "표시가 없다" 이며 그것은 종전 동작이다.

  그려지는지는 실측으로 확인한다 — 문제가 나오면 오버레이를 `#app` 밖 최상단에 두는 것으로 격리한다.
