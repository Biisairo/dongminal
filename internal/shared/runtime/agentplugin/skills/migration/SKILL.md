# migration

이 세션이 하던 일을 **다음 세션이 그대로 잇게** 한다. 하는 일은 하나다 —
지금 pane 에 새 탭을 열고, 에이전트를 띄우고, 이어갈 일을 넘기고, 자기 탭을 닫는다.

## 언제 쓰나

- 컨텍스트가 차 간다 — 지금 세션으로는 남은 일을 끝까지 못 간다
- 한 단계가 끝났고 다음 단계를 새 세션이 맡는다
- "인수인계해줘", "다음 세션에 넘겨", "새 탭에서 이어가"

**안 쓰는 경우**: 여러 에이전트를 동시에 돌리는 일 (`/dongminal:team`) · 저장된 팀 구성의 반복 실행 (`/dongminal:workflow`).

---

## 절대 원칙 (넷)

1. **인계는 두 벌이다.** 긴 맥락은 **문서**가, "그 문서를 읽어라" 는 짧은 지시는 **엔벨로프**가 나른다. 엔벨로프 하나에 다 담으면 메시지 길이에 매이고 인계 기록이 남지 않는다.
2. **문서의 경로는 이 스킬이 정하지 않는다.** 진행 중인 작업에 규약이 있으면 **그것**을 쓴다. 없을 때만 이 스킬이 한 장을 만든다.
3. **새 탭은 지금 pane 에 선다.** `--at` 없이 `dmctl new-tab -n` 이다. 전용 창을 만들지 않는다 — 인계는 자리를 옮기는 일이 아니라 **자리를 물려주는** 일이다.
4. **넘기기 전에 준비완료를 확인한다.** `dmctl wait --for ready` 뒤에만 엔벨로프를 보낸다. 기동 프롬프트에 지시를 끼워 넣지 않는다.

---

## 절차

### 0. 넘길 것을 정한다

넘기는 것은 **지금까지의 서술**이 아니라 **다음 세션이 할 일**이다. 최소한 이 여섯이 문서에 있어야 한다.

- 어디까지 왔나 (끝난 것 · 그 근거가 되는 커밋 해시)
- 남은 일과 **순서**
- 먼저 읽을 것 (경로와 절 번호까지)
- 이 세션이 값을 치르고 배운 것 — 다음 세션이 같은 값을 다시 치르지 않게
- 변하지 않는 규약 (전량 검사·게이트·금지 사항)
- 사용자 결정 중 아직 유효한 것

### 1. 문서 한 장

진행 중인 작업의 규약을 먼저 본다.

- 규약이 있으면 그 파일을 **다음 세션의 착수 문서로 다시 쓴다** (예: 단계별 진행 문서를 다음 단계의 착수 프롬프트로)
- 없으면 한 장을 만든다. 자리는 저장소 안이고, 이름은 이어갈 일을 말한다

### 2. 새 탭과 에이전트

```
dmctl new-tab -n                      # --at 없이 — 지금 pane 이다
                                      # 응답의 newTabs[0] 의 uuid·toolId 를 그대로 쓴다
dmctl rename-tab --at <탭 uuid> "<이어갈 일의 이름>"
dmctl send-input --at <탭 uuid> --execute "cd '<작업 디렉터리>' && <이 세션을 띄운 에이전트 명령>"
dmctl wait --at <탭 uuid> --for ready --timeout-ms 180000
```

- 에이전트 명령은 **이 세션을 띄운 그 명령**이다. 이름을 짐작하지 않는다
- `new-tab` 과 `close-tab` 은 `--help` 를 받지 않는다
- `wait` 가 `rc=5` 면 준비되지 않은 것이다 — **3의 갈래**로 간다

### 3. 엔벨로프

```
dmctl msg --to <toolId> -
```

본문은 짧다. 문서를 가리키고, 어디서부터인지 말하고, 근거 해시를 준다.

```
[HANDOFF <이 세션의 이름> → <다음 세션의 이름>]
<문서 경로> 를 읽고 진행하라. 그 안의 착수 블록이 이번 세션의 지시 전부다.
직전 커밋: <해시>. 작업 트리는 깨끗하다 — `git status` 로 확인하라.
먼저 <남은 일의 첫 항목> 부터 시작하라.
[/HANDOFF]
```

`--to` 에 넣는 것은 **toolId** 다. `W?.P?.T?` 좌표 라벨은 거절된다.

#### `wait` 가 실패했을 때

```
dmctl read-screen --at <탭 uuid>
```

화면이 **무엇을 묻는지** 보고 처리한다. 흔한 갈래 셋:

- 신뢰·권한 확인을 묻는다 → `dmctl send-input --at <탭> --execute "<답>"` 뒤 `wait` 를 다시 건다
- 셸이 아직 프롬프트를 내지 않았다 → `wait` 를 한 번 더, 상한을 늘려서
- 명령을 찾지 못했다 → 에이전트 명령이 틀렸다. 이 세션을 띄운 명령을 다시 확인한다

**준비되지 않은 탭에 엔벨로프를 보내지 않는다.** 보낸 메시지는 셸의 입력줄에 문자열로 남고, 그 뒤 에이전트가 뜨면 그것을 보지 못한다.

### 4. 확인하고, 자기 탭을 닫는다

```
dmctl status --at <탭 uuid>
```

`working` 이어야 한다. `idle` 이면 엔벨로프가 닿았으나 착수하지 않은 것이다 — `dmctl send-input --at <탭> --execute ""` 로 한 번 깨운다.

```
dmctl who-am-i                        # 출력의 uuid= 가 자기 탭이다
dmctl close-tab --at <자기 탭 uuid> --force
```

**`--force` 를 빼지 마라.** 그 탭에는 방금까지 에이전트가 돌고 있었으므로 확인창("프로세스가 있습니다")이 뜨고, **그 창에 답할 사람이 이미 없다** — 인계가 거기서 멎는다. 도구를 살려 두고 싶으면 `--background` 를 쓴다(둘은 함께 쓸 수 없다).

**이것이 이 세션의 마지막 명령이다.** 닫기 전에 사용자에게 보고할 것이 있으면 먼저 보고한다.

---

## 이 스킬이 하지 않는 것

- **팀을 만들지 않는다.** 여럿을 동시에 돌리는 일은 `/dongminal:team` 이다
- **일을 대신 하지 않는다.** 인계는 다음 세션이 무엇을 할지 정하는 것까지다
- **문서를 대신 요약하지 않는다.** 줄인 인계는 다음 세션이 같은 조사를 다시 하게 만든다 — 값을 치르고 안 것은 길어도 그대로 넘긴다
