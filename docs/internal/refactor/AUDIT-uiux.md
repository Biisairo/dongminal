# 감사: UI/UX — 실제 화면을 눌러 본 기록

> 작성: 2026-09-20 · 브랜치 `refactor` · 격리 인스턴스(`start --isolated`)를
> Playwright 로 1440×900 과 390×844 에서 직접 조작하며 관찰했다.
> 화면은 `tmp/design-audit/audit-*.png` 에 있다.

이 문서는 **코드를 읽어서 나온 것이 아니라 화면을 눌러서 나온 것**이다. 정적
분석이 잡지 못하는 것 — 같은 역할이 화면마다 다르게 생긴 것, 말이 자리마다
달라지는 것, 손이 닿지 않는 것 — 만 적는다. 토큰·CSS 중복은
`AUDIT-design.md`, JS 컴포넌트 중복은 `AUDIT-fe-ui.md` 가 맡는다.

---

## 0. 요약

| 등급 | 건수 | 성격 |
|---|---:|---|
| HIGH | 13 | 손이 닿지 않거나, 같은 역할이 3가지 이상으로 갈라졌거나, 말이 틀렸다 |
| MED | 12 | 배우기 어렵거나, 정보가 조용히 사라지거나, 빈 화면이 아무것도 안 한다 |
| LOW | 5 | 다듬을 것 |

**가장 중요한 다섯.**

1. **스크롤 표면 49개 중 33개가 브라우저 기본 스크롤바다** (§5A.1). 폭은 네
   가지, 손잡이 색은 두 가지, hover 는 킷에만 있다 (§5A.2). macOS 는 오버레이
   스크롤바라 안 보이지만 이 제품이 1급으로 내세우는 **Linux · WSL · Windows**
   에서는 밝은 회색 네이티브 스크롤바가 54종 다크 테마 위에 그대로 뜬다.
2. **킷을 안 단 버튼 98개**가 있고, 그중 네 종은 `DESIGN_TOKENS_SRS` §7.6
   잔여표에 **아예 없다** (§5A.5). 표가 "탭 넷만 남았다" 고 말하는 동안 실제로는
   여섯 종이 남아 있다 — 표의 세는 방법이 한 번도 병기되지 않은 것을 못 본다.
3. 불리언 설정 하나가 **세 가지 컨트롤**로 갈라져 있다 (§1.1). 킷에 토글
   컴포넌트가 **없는 것**이 원인이다.
4. 모바일에서 `#drawer-close` 가 **visible·enabled 인데 뷰포트 밖**에 있다 —
   닿을 수 없는 컨트롤이다 (§3.1).
5. 같은 대상을 **네 가지 이름**으로 부른다 (§2.1), 조사가 고정돼 **"markdown 를"**
   처럼 틀린 한국어가 나온다 (§2.4), `t()` 를 건너뛴 영어 리터럴 8개가 i18n
   게이트를 통과한다 (§2.3).

**근본 원인 한 줄.** `style-kit.css` 는 잘 설계됐고 버튼·모달·메뉴는 이미
수렴했다(`DESIGN_TOKENS_SRS` §7.1~7.5 전부 "끝났다"). 갈라진 것은 전부 **킷이
가지고 있지 않은 종류**다 — 토글, 빈 상태, 섹션 머리글, 세그먼트 컨트롤, 분할
버튼, 인라인 알림, 개수 표시. 화면마다 없는 것을 스스로 발명했다. 그러므로
고칠 자리는 각 화면이 아니라 **킷**이다.

## 1. 같은 역할, 다른 모양

### [HIGH] 1.1 불리언 설정이 세 가지 컨트롤로 갈라졌다

- 위치:
  - 설정 ▸ Theme — "시스템 다크/라이트 따르기": **맨 사각 체크박스**, 라벨 없음
    (`audit-02-settings.png`)
  - 설정 ▸ Status Bar — 항목 10개: **알약형 토글 스위치**
    (`audit-04-statusbar.png`)
  - 설정 ▸ Access — "허용 목록 적용": **체크박스 + "켜기" 글자**
    (`audit-05-access.png`)
- 현상: 한 모달 안에서 탭을 옮길 때마다 같은 뜻의 컨트롤이 다른 모양이 된다.
- 비용: 사용자가 "이건 눌리는 것인가"를 탭마다 다시 배운다. 셋의 켜짐 상태
  표현도 달라서(파란 채움 / 파란 알약 / 체크 표시) 훑어볼 때 상태를 못 읽는다.
- 제안: 킷에 `.ui-switch` **하나**를 세우고 셋을 옮긴다. 이미 `.ui-field` 가
  라벨+컨트롤 행을 갖고 있으므로 컨트롤 쪽만 비어 있다. 색은
  `--accent`/`--border`/`--text-dim` 파생으로 — 새 색을 넣지 않는다.
- 위험도: LOW (외형만, 상태 읽기/쓰기 경로는 그대로)
- 공수: M

### [HIGH] 1.2 섹션 머리글이 다섯 가지로 갈라졌다

- 위치 (한 화면에 네 가지가 동시에 보인다 — `audit-11-history.png`):

  | 자리 | 표기 | 언어 | 대소문자 |
  |---|---|---|---|
  | git 패널 | `STAGED` · `CHANGES` | 영 | 전부 대문자 |
  | 히스토리 ref 목록 | `LOCAL` · `REMOTE` · `TAGS` | 영 | 전부 대문자 |
  | 히스토리 본문 | `미커밋 변경 (10)` | 한 | — |
  | 설정 ▸ Theme | `DARK` | 영 | 전부 대문자 |
  | 설정 ▸ Shortcuts | `창`·`보던 자리`·`탭` 인데 `PANE` 만 영어 대문자 | 섞임 | 섞임 |
  | Agents 드로어 | `AGENTS` | 영 | 전부 대문자 |

- 현상: 같은 층위의 머리글이 자리마다 언어도 대소문자도 다르다. Shortcuts
  탭은 **한 목록 안에서** 섞인다.
- 비용: 대문자 영문 머리글은 한글 본문 옆에서 다른 층위처럼 읽힌다. 실제로는
  같은 층위다. 훑을 때 구조가 잡히지 않는다.
- 제안: 킷에 `.ui-section-head` 를 세우고 **한글 문장형 한 가지**로 통일한다
  (`스테이지됨` · `변경` · `로컬` · `원격` · `태그` · `에이전트`). 전부 대문자는
  쓰지 않는다 — 한글에는 대소문자가 없어서 영문에만 걸리는 장식이 된다.
  `PANE` 이 영어로 남은 것은 i18n 사전 누락이므로 §2.3 과 같이 고친다.
- 위험도: LOW
- 공수: M

### [HIGH] 1.3 "지금 선택된 것" 표시가 세 가지다

- 위치:
  - 사이드바 탭 `Windows`/`Repo`, git 패널 탭 `Changes`/`Explorer`: **아래 밑줄**
  - git 보기 모드(폴더/목록) 두 버튼: **강조색 테두리 + 배경**
    (`audit-09-git.png`)
  - 히스토리 ref 목록의 현재 브랜치 `refactor`: **글자색만 강조색**
- 현상: 선택 상태를 밑줄로도, 테두리로도, 글자색으로도 나타낸다.
- 비용: 글자색만인 `refactor` 는 선택이 아니라 링크로 읽힌다. 실제로 링크가
  아니다.
- 제안: 킷의 `.ui-tabs-underline`/`.ui-tabs-side` 가 이미 축 두 개를 갖고 있다.
  보기 모드 두 버튼은 **세그먼트 컨트롤**이므로 킷에 `.ui-segment` 를 세워
  옮긴다. ref 목록은 `.ui-tabs-side` 의 왼쪽 레일 표시를 쓴다.
- 위험도: LOW
- 공수: M

### [MED] 1.4 개수 표시가 두 가지다

- 위치: 사이드바 저장소 항목은 알약 배지 `8`, git 패널 머리글은 괄호 `(8)`,
  Runs 모달 제목은 `Run 0개`, Background 모달 제목은 `백그라운드 도구 0개`.
- 비용: 같은 수치가 네 가지 서식으로 나온다. 제목에 수를 넣으면 0 일 때
  "Run 0개" 라는 어색한 제목이 된다.
- 제안: 킷의 `.ui-badge` 로 통일하고 **제목에는 수를 넣지 않는다** — 제목은
  `실행` · `백그라운드 도구`, 수는 그 옆 배지.
- 위험도: LOW
- 공수: S

### [MED] 1.5 분할 버튼(주동작+더보기)이 자기 방식으로 그려졌다

- 위치: git 패널 원격 줄 — 가져오기/당기기/올리기 각각에 별도 화살표 버튼이
  붙어 **버튼 6개**가 늘어선다. 커밋 줄도 `Commit` + 화살표 (`audit-09-git.png`).
- 현상: 화살표 쪽이 자기 테두리를 가져서 독립 버튼으로 보인다. 게다가 커밋
  줄에서는 **비활성 `Commit` 옆의 화살표가 강조색으로 채워져** 부차 동작이 주
  동작보다 시끄럽다.
- 비용: 시각 계층이 뒤집혔다. 6개 아이콘 버튼은 무엇이 무엇인지 학습이 필요하다
  (가져오기와 당기기가 둘 다 아래 화살표다).
- 제안: 킷에 `.ui-split` 을 세운다 — 주버튼과 더보기가 한 테두리를 공유하고
  사이에 1px 구분선만. 더보기는 주버튼의 등급을 따라간다(주버튼이 비활성이면
  더보기도 시끄럽지 않게). `DESIGN_TOKENS_SRS` §7.5 가 "붙은 한 쌍 모서리" 를
  이미 자리 규칙으로 갖고 있으므로 그 규칙을 킷으로 올린다.
- 위험도: MED (git 동작 버튼은 e2e 가 짚는다)
- 공수: M

### [MED] 1.6 인라인 알림 한 줄에 버튼 세 가지 모양이 들어 있다

- 위치: 편집기 상단 LSP 안내 줄 (`audit-17-editor.png`) — `받기`(작은 강조색
  테두리) + `다시 보지 않기`(큰 중립 테두리) + `X`(맨 아이콘). 높이도 셋 다
  다르다.
- 비용: 한 줄 안에서 세 버튼의 무게가 제각각이라 무엇을 눌러야 하는지 안 보인다.
- 제안: 킷에 `.ui-notice` 를 세운다 — 본문 + 동작 영역, 동작은 `ui-btn-sm` 한
  크기로 맞추고 주동작만 `ui-btn-primary`, 닫기는 `ui-btn-ghost ui-btn-icon`.
- 위험도: LOW
- 공수: S

## 2. 말이 자리마다 다르다

### [HIGH] 2.1 같은 대상을 네 가지 이름으로 부른다

- 위치 (`audit-06-repo-empty.png` → `audit-07-repo-add.png`):

  | 자리 | 표기 |
  |---|---|
  | 사이드바 탭 | `Repo` |
  | 버튼 | `Add` |
  | 버튼 툴팁 | `Add a repository or folder` |
  | 빈 상태 문구 | `+ Add 로 경로를 추가하세요` |
  | 눌렀을 때 뜨는 대화상자 제목 | **`Editor 추가`** |

- 현상: 탭 이름·버튼·툴팁·빈 상태·대화상자가 전부 다른 낱말을 쓴다. 특히
  대화상자만 `Editor` 라고 부른다 — 사용자는 저장소를 추가하려 했다.
- 비용: 인터페이스의 낱말은 길 안내다. 같은 길에 표지판이 네 개 서 있고 넷 다
  다른 지명을 가리킨다.
- 제안: **하나로 정한다.** 이 자리의 대상은 "작업할 폴더나 저장소" 이므로
  `저장소` 로 부르고 전부 맞춘다 — 탭 `저장소`, 버튼 `저장소 추가`, 대화상자
  제목 `저장소 추가`, 빈 상태 `아직 저장소가 없습니다`. 동작 이름은 흐름 끝까지
  같은 말을 쓴다.
- 위험도: LOW (e2e 가 텍스트를 짚는다면 함께 고친다)
- 공수: S

### [HIGH] 2.2 한 대화상자 안에 영어 버튼과 한글 버튼이 나란히 있다

- 위치: 저장소 추가 대화상자 — `Cancel` 과 `추가` (`audit-07-repo-add.png`).
  같은 현상이 앱 전체에 있다: 상단바 `Split H`·`Split V`·`Runs`·`Background`·
  `Agents`·`Slot`·`New`·`Box`·`Preset` 는 영어인데 상태바는 `연결됨`, 설정 본문은
  한글이다.
- 원인 (코드 확인): `web/index.html` 이 이 버튼들에 `data-i18n-title` 만 달고
  **보이는 글자는 하드코딩**했다. 예: `<button id="split-h" data-i18n-title=
  "html.split_h_title">Split H</button>` — 툴팁만 번역되고 라벨은 안 된다.
- 비용: 한국어로 쓰는 사용자에게 앱이 반쯤만 한국어다. 영어로 쓰는 사용자에게는
  상태바가 반쯤 한국어다. 어느 쪽에게도 완성돼 보이지 않는다.
- 제안: 보이는 글자 전부에 `data-i18n` 을 달고 `ko.js`/`en.js` 에 키를 채운다.
  게이트로 막는다 — `index.html` 안에서 `data-i18n` 없는 버튼 텍스트 노드를
  세는 검사를 `make gates` 에 넣는다 (저장소 규약 3-3 에 맞다).
- 위험도: LOW
- 공수: M

### [HIGH] 2.3 `t()` 를 건너뛴 영어 리터럴 8개가 i18n 게이트를 통과한다

> 이 항목은 코드로 검증했다. 처음에 "사전에 키가 없다" 로 적었으나 **틀렸다** —
> `make gates` 의 `i18n` 검사가 `ko`·`en` 의 키 짝을 이미 강제하고 통과한다
> (`카탈로그 958 키`). 진짜 원인은 아래다.

- 위치 — `t()` 를 거치지 않고 영어 문자열을 **직접** 든 자리 8곳:

  | 파일:라인 | 리터럴 | 주변 |
  |---|---|---|
  | `web/js/core/app-settings-keys.js:15` | `{label:'Pane', …}` | 같은 배열의 나머지 그룹 12개는 전부 `t('keys.group_*')` |
  | `web/js/core/helpers.js:391` | `paneUp:'Pane ↑'` `paneDown:'Pane ↓'` `paneLeft:'Pane ←'` `paneRight:'Pane →'` | `SHORTCUT_LABELS` 의 나머지 ~35개는 전부 `t('shortcut.*')` |
  | `web/js/core/constants-git-history.js:124-126` | `{kind:'local',name:'Local'}` `'Remote'` `'Tags'` | **바로 다음 줄** `:128` 이 `GIT_REF_ALL=t('git.ref_all')` |

- 현상: 각 자리에서 **자기 이웃만 예외적으로** `t()` 를 건너뛴다. 게다가
  `git.br_groups.local`·`.remote`·`.tag` 로 **번역이 이미 사전에 있다**
  (`로컬`·`원격`·`태그`) — 브랜치 대화상자가 쓰고 히스토리 ref 목록만 안 쓴다.
- 왜 게이트가 못 잡았나: `i18n` 검사는 *"한글 리터럴이 카탈로그 밖에 없는가"* 를
  본다. 이 8개는 **영어**라서 검사 대상이 아니다. 검사가 막는 것은 "한글을
  코드에 박는 것" 이고, "번역해야 할 것을 영어로 박는 것" 은 막지 않는다.
- 화면에 나타나는 모습: `.sc-group-title` 과 `.git-ref-sec` 에
  `text-transform:uppercase` 가 걸려 있어 `Pane`→**`PANE`**,
  `Local`→**`LOCAL`** 로 커진다. 한글 머리글은 대문자가 없어 그대로이므로,
  결과적으로 **번역을 건너뛴 것만 대문자로 튀어 보인다** (`audit-03-shortcuts.png`,
  `audit-11-history.png`). 증상이 원인을 정확히 가리키고 있었던 셈이다.
- 비용: 한국어 사용자에게 다섯 그룹 중 한 그룹, 세 섹션 전부가 영어로 남는다.
  같은 낱말의 번역이 사전에 있는데도 그렇다.
- 제안:
  1. 8곳을 `t()` 로 바꾼다. 히스토리 ref 는 **이미 있는 키**
     `git.br_groups.{local,remote,tag}` 를 그대로 쓴다 (새 키를 만들지 않는다).

## 3. 손이 닿지 않거나 정보가 사라진다

### [HIGH] 3.1 모바일에서 사이드바 닫기 버튼이 뷰포트 밖에 있다

- 위치: `#drawer-close` (`web/index.html`), 390×844 에서 재현.
- 현상: Playwright 가 `element is visible, enabled and stable` 로 판정하면서도
  `element is outside of the viewport` 로 클릭에 실패한다. 즉 **접근성 트리에는
  있는데 화면 밖에 있다.**
- 비용: 키보드/스크린리더 사용자는 도달할 수 있다고 안내받지만 실제로는 누를 수
  없다. 터치 사용자는 보이지도 않는다.
- 제안: 드로어가 닫혀 있는 동안 `#drawer-close` 를 `hidden` 으로 두거나
  `inert` 를 건다. 저장소가 이미 `[hidden]` 을 가시성 어휘로 쓰고 있다
  (`DESIGN_TOKENS_SRS` §7.5 의 FR-LAY-30).
- 위험도: LOW
- 공수: S

### [HIGH] 3.2 탭·목록 항목의 닫기 버튼이 `aria-hidden` 이다

- 위치: 접근성 트리에서 확인 — 터미널 탭 `Shell` 안, 창 목록 `Window` 안:
  ```
  tab "Shell" [selected]:
    generic [aria-hidden] [cursor=pointer]     ← 닫기 affordance
  option "Window" [selected]:
    generic [aria-hidden] [cursor=pointer]
  ```
- 현상: 누를 수 있는 요소인데 `aria-hidden` 이고 `button` 도 아니라서 키보드
  탭 이동과 스크린리더 양쪽에서 사라진다.
- 비용: 탭을 키보드로 닫을 수 없다. 저장소에 `@axe-core/playwright` 가 있는데도
  이 종류는 자동 검출이 안 된다(클릭 핸들러 유무를 axe 가 모른다).
- 제안: `<button class="ui-btn ui-btn-icon ui-btn-ghost ui-btn-sm"
  aria-label="탭 닫기">` 로 바꾼다. 닫기는 `i-x` 스프라이트가 이미 있다.
- 위험도: MED (탭 DOM 구조를 e2e 가 짚는다)
- 공수: M

### [HIGH] 3.3 `--touch-min:44px` 를 앱 자신이 어긴다

- 위치: 390px 폭에서 (`audit-16-mobile-git.png`) — 원격 줄의 화살표(더보기)

  않았다.
- 비용: 손가락으로 누르기 어렵다. 게다가 분할 버튼의 화살표는 주버튼 바로 옆에
  있어 오탭이 파괴적 동작으로 이어질 수 있다.
- 제안: `body.mobile` 에서 `.ui-btn`/`.ui-btn-icon` 이 이미 44px 하한을 갖는다

- 공수: S

### [HIGH] 3.4 API 오류가 사용자에게 뜨지 않는다

## 5-A. 스크롤바 — 킷이 닿지 않은 가장 큰 표면 (사용자 지적)

> 사용자 지적: *"잘 안 보이는 버튼이나 스크롤 같은 곳에서 UI 적용 누락이 많이
> 보이고, 스크롤이 보이지 말아야 할 곳에 내부 엘리먼트 크기 때문에 보이는 등
> 오류가 있다."*
>
> 살아 있는 화면(Playwright)과 CSS 전수 파싱 두 가지로 측정했다. 수치는 모두
> 재현 가능하다.

### [HIGH] 5A.1 스크롤 표면 49개 중 34개가 브라우저 기본 스크롤바다

  | `.ui-scroll` 을 다는 표면 | **1** (`doc-render.js:254` 의 `.dr-body`) |
  | **아무 것도 없어 브라우저 기본으로 뜨는 표면** | **33** |

- 기본으로 뜨는 표면(일부): `#agents-panel` · `.bg-box` · `.runs-box` ·

  선언한 선택자는 `.ui-scroll` 을 달거나 자기 `::-webkit-scrollbar` 를
  가져야 한다"* 를 `make gates` 에 넣는다 (`css-vars`·`focus`·`z-index` 검사와

- 공수: M

### [HIGH] 5A.2 스크롤바 폭이 네 가지, 손잡이 색이 두 가지, hover 는 킷에만 있다

  킷만 `--text-dim` + hover 를 쓴다. 즉 **킷이 정한 스크롤바와 앱의 스크롤바가
  서로 다른 색이다.**
- 비용: 같은 창 안에서 스크롤바가 4px·6px·8px 로 갈리고 색도 갈린다. 한 화면에

- 제안: 폭은 **두 눈금**으로 줄인다 — 본문 표면 8px(`--ui-scroll-w`), 좁은

  `.ed-tree`·`.sbl-list`·`.theme-list` 가 쓰게 한다
  (`style-kit.css:234` 가 이미 *"좁은 목록의 4px 은 뜻이 다르다"* 고 적었으므로
  그 판단을 **토큰으로 세운다**). 손잡이 색·hover 는 킷 한 벌로.
- 위험도: LOW
- 공수: M

### [HIGH] 5A.3 킷의 `.ui-modal-body` 가 그것이 대체하는 `.modal-body` 보다 못하다

- 위치: `web/style-kit.css:116` (`.ui-modal-body{…overflow:auto…}`) vs
  `web/style.css:570` (`.modal-body{…overflow-x:hidden}` + `:571` 에
  `::-webkit-scrollbar{width:6px}`).
- 현상: 옛 `.modal-body` 는 스크롤바를 그리는데, 그것을 대체하려고 세운 킷의
  `.ui-modal-body` 는 **안 그린다**.
- 비용: `DESIGN_TOKENS_SRS` §3.9 가 모달 골격 여섯을 킷으로 모으는 중이다. 그
  이주가 진행될수록 **스크롤바가 사라진다** — 개선 작업이 회귀를 만든다.
  지금 이미 `.runs-box`·`.bg-box`·`.git-dialog-body` 가 그 상태다.
- 제안: `.ui-modal-body` 에 `.ui-scroll` 의 규칙을 합치거나
  (`.ui-modal-body,.ui-scroll{…}`), 모달을 만드는 자리에서 클래스를 함께 단다.
  **킷을 먼저 고치고 이주를 잇는다** — 순서가 반대면 이주할 때마다 이 회귀가 는다.
- 위험도: LOW
- 공수: S

### [MED] 5A.4 "보이지 말아야 할 스크롤바" — 내용이 몇 px 넘쳐 생긴다

- 측정 (1440×900, 탐색기 열린 상태):

  | 표면 | 보이는 높이 | 내용 높이 | 넘침 |
  |---|---:|---:|---:|
  | `.ed-tree` | 789px | 798px | **9px** |
  | `.modal-body` (설정 ▸ Code) | 626px | 667px | **41px** |

- `.ed-tree` 의 산수: 행 36개 × 22px = 792px, `padding-bottom:6px`
  (`style-editor.css:90`) → 798px. 쓸 수 있는 높이는 789px. **마지막 행이 3px
  잘리고, 거기에 패딩 6px 이 더해져 9px 스크롤바가 선다.**
- 현상: 내용이 "거의 맞는데 조금 넘치는" 상태에서 스크롤바가 서고, 스크롤해도
  9px 만 움직인다. 사용자는 더 볼 것이 있다고 읽지만 실제로는 없다.
- 비용: 스크롤바가 정보가 아니라 잡음이 된다. `.ed-tree` 는 4px 폭이라 더
  희미하게 서서 "왜 여기 선이 있지" 로 읽힌다.
- 제안: 두 가지를 구분해서 고친다.
  1. **`padding-bottom:6px` 이 넘침을 만드는 부분** — 목록 끝의 숨 쉴 자리는
     패딩이 아니라 마지막 행의 `margin-bottom` 이나 `scroll-padding-block-end`
     로 준다. 패딩은 `scrollHeight` 에 들어가 스스로 스크롤을 만든다.
  2. **행 높이의 나머지** — 컨테이너 높이가 행 높이의 배수가 아니면 항상 조금
     남는다. 근본 해법은 마지막 행을 자르지 않는 것이므로, 컨테이너에
     `scroll-snap-type` 이나 행 높이 토큰(`--ed-row-h`)에서 파생한
     `max-height:calc(...)` 를 주는 대신, **잘린 행이 있음을 페이드로 알린다**
     (§4.2 의 제안과 같은 장치를 쓴다).
- 위험도: LOW
- 공수: M

## 6. 성능으로 넘길 것

여기서 관찰한 것 중 성능 항목은 `AUDIT-fe-ui.md` 의 성능 절로 넘긴다. 육안으로
확인된 것만 적는다.

1. **히스토리 목록 비가상화** — `300개 로드` 로 300행을 한 번에 DOM 에 올린다.
   전체 이력이 수천 건인 저장소에서 더 불러오면 선형으로 는다.
2. **파일 트리 비가상화** — 홈 디렉터리를 열면 수백 행이 한 번에 올라간다.
3. **드로어 개폐가 레이아웃을 다시 계산한다** — 밀어내기 방식이라 히스토리
   목록 전체가 재배치된다(열 하나가 사라질 만큼). 오버레이로 덮으면 사라진다.

## 7. 이 감사가 제안하는 작업 순서

각 화면을 따로 고치지 않는다. **킷을 먼저 채우고 옮긴다.**

| 순서 | 내용 | 여기의 항목 |
|---|---|---|
| ⓪ | **킷이 이미 가진 것을 끝까지 적용한다** — `.ui-scroll` 33곳, 스크롤바 폭 두 눈금 토큰화, `.ui-modal-body` 의 스크롤바 결손, 킷 없는 버튼 98개. 새 컴포넌트보다 **먼저** 한다: 지금 진행 중인 모달 이주가 스크롤바를 지우고 있다 | 5A.1~5A.5 |
| ① | 킷에 없는 컴포넌트 8종을 세운다 — `.ui-switch` · `.ui-section-head` · `.ui-segment` · `.ui-split` · `.ui-notice` · `.ui-empty` · `.ui-key` · 개수 배지 배치 규칙 | 1.1~1.6, 4.1, 5A.5 |
| ② | 말을 고친다 — 낱말 통일, `data-i18n` 전면 적용, 사전 키 일치 검사, 조사 헬퍼, 존댓말 등급 두 가지 | 2.1~2.6 |
| ③ | 닿지 않는 것을 고친다 — `drawer-close`, 탭 닫기 버튼, 44px 하한, API 오류 표시 | 3.1~3.4 |
| ④ | 모달 골격과 빈 상태를 옮긴다 | 4.1~4.4 |
| ⑤ | 배우기 어려운 자리를 고친다 | 5.1~5.6 |

**색에 관한 제약을 다시 적는다.** `DESIGN_TOKENS_SRS` FR-TOK-16 이 팔레트 값
변경을 이미 금지했고, 테마는 54종이다. 위 작업 전부는 **기존 토큰의 조합**으로만
한다 — `--accent`·`--border`·`--text-*`·`--danger`·`--attn` 과 그 파생
(`color-mix`/`--accent-subtle` 류). 새 hex 를 넣지 않는다.
