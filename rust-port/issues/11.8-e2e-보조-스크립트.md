## 목표

docs/internal/GO_REMOVAL_SRS.md 의 G-34~G-36·G-53 를 요구 동작·수락 시험대로 바꾼다. 4절 조정자 결정과 3.10 묶음 순서를 따른다. Go 판과 사용자가 보는 동작(명령·인자·출력·산출물 이름·위치·종료 코드)이 같아야 한다.

## 진행 기록

- 시작 prod-pids: `38173 start --foreground/58470 d --handover-fd`
- 07:47 운영 보호 사고: Go 기준 캡처 중 `verify-isolated.sh --repo /nonexistent/x` 가 격리 인스턴스를 임시 포트 57008(60147 미만)에 띄워 전체 검사를 돌았다(격리 홈만 씀, 스스로 정리, prod-pids 변화 없음). 조정자에게 보고하고 답을 기다리며 멈춤.

- 커밋: `e1dd82cb` (변경), `08540d55` (rust-port 병합, 충돌 없음).
- G-34 `scripts/verify-isolated.sh`: `go build` → `BINARY="$BIN" scripts/build.sh >/dev/null`. build.sh 의 빌드 줄과 `health --daemon` 줄은 버린다. Go 판 `go build` 는 성공하면 아무것도 찍지 않았으므로 출력이 verify 보고뿐인 것이 같다. 실패하면 cargo 오류(stderr)가 그대로 보이고 `set -e` 로 멈춘다.
- G-35 `scripts/perf-probe.sh`: 빌드 줄을 `BINARY=dongminal scripts/build.sh >/dev/null || exit 1` 로 바꿨다. `allocMB` 줄은 `allocMB:측정 안 됨`, 예산 줄은 `allocMB 100 (유휴, 측정 안 됨)` 으로 찍는다(DIFF-27).
- G-36 `scripts/shots/shoot.sh`: 바꿀 것이 없다(SRS 대로). 포트 58199 를 쓰므로 실행하지 않았다.
- G-53 `e2e/global-setup.ts`: `DM_E2E_PREBUILT_BIN` 이 없으면 `cargo build --quiet --release --locked -p dongminal --manifest-path rust/Cargo.toml` 을 실행하고, `${CARGO_TARGET_DIR:-rust/target}/release/dongminal[.exe]` 를 `E2E_BIN` 으로 복사한다. 바깥의 `DONGMINAL_BUILD_*` 는 지운다(Go 판처럼 `dev`). build.sh 를 거치지 않은 이유: e2e 는 Windows 러너에서도 돌고 TS 에서 bash 를 부를 수 없다. FR-GRM-8: 샤드가 동시에 불러도 cargo 의 빌드 잠금이 직렬화하고, 뒤의 샤드는 이미 최신인 산출물을 쓴다. 그래서 `make e2e`(11.6 담당)는 고치지 않았다.
- 대조(Go 기준 = 같은 worktree 의 Go 판 / Rust = PATH 에서 go 를 뺀 격리 실행, 11.1 의 진행 중 `build.sh`·`daemon-fingerprint.sh` 를 커밋하지 않고 잠시 가져와 씀):
  - verify-isolated: 전체 실행 종료 0·0이고 항목 34줄(26건 통과)이 같다. `--repo /nonexistent/x` 는 1·1, 항목 목록이 같다. `--bogus` 는 2·2, stdout·stderr 바이트가 같다. 실행 전후 prod-pids 를 확인했다(7.4 결정 (가)).
