## 진행 기록

### 2026-11-26 원인·수정 (review)

- **원인**: 회귀가 아니고 낡은 시험이다. perf(3.2) `51ed845f` 부터 Diff 뷰가 줄 단위로 먼저 비교한다(`gitDiffBounded`).
  시험의 입력(-7행, +9b행)은 vendor 글자 단위 diff 에서는 `[7,9]` 한 덩어리로 칠해졌다. 줄 단위 diff 에서는
  `[7,7]`·`[9,9]` 두 덩어리로 칠해진다(node 하네스에서 `Chunk.build` 로 확인). 그래서 8행이 칠해지지 않고
  `paintedSpan(8)` 이 null 이다. `paintedSpan`·`gitHunkSpanAt` 의 논리(FR-UIP-25)는 그대로 맞다.
- **RED**: 고치기 전 `--grep TC-UIP-14` 가 실패했다(재시도 포함 2회, `Received: null`).
- **수정(시험만)**: `e2e/git-hunk.spec.ts` TC-UIP-14. 줄 비교의 편집 수가 `GIT_DIFF_LINE_MAX_EDITS` 를 넘는 변경을
  만든다(7행 삭제, 10행부터 한 줄 건너 고침, 끝에 추가). 상한은 화면에서 읽는다. 이때 화면은 공통 앞뒤 줄을 뺀 구간
  하나로 칠하고 git 은 블록 여럿으로 나눈다. 검증 내용(문맥 줄 8행에서 툴바가 뜨고 Revert 가 전체를 되돌린다)은 같다.
- **동작 변경**: 제품 동작 변경은 없다. 시험 전제만 바뀌었다.
  - 이전: 닮은 글자의 삭제·추가를 화면이 한 덩어리로 칠한다고 전제했다.
  - 새: 줄 비교 상한을 넘는 변경을 화면이 한 덩어리로 칠한다고 전제한다.
  - 이유: perf(3.2) 의 줄 단위 diff 가 의도된 변경이다.
- **시험**: TC-UIP-14 e2e 를 빈 폴더로 3회 통과(각 6.7~6.8 s, 공용 바이너리 `otterminal-pfbase`).
  단위(diff-bounded·diff-cm·hunk-coords·git-hunk-fresh, 44개) 통과. `npm run -s typecheck`·`npx eslint web/js`·
  check-*.mjs/sh(check-cross 제외) 모두 통과. Rust 는 고치지 않았다.
- **남은 위험**: 시험 파일이 약 4천 줄이다(실행 6.8 s). 줄 단위 diff 에서는 화면 덩어리가 git 블록 여럿에 걸치는 경우가
  상한 초과(또는 정렬 차이)뿐이다. 그래서 FR-UIP-25 가 실제로 쓰이는 일은 드물다.
- **코드와 어긋난 문서(고치지 않음)**: `docs/internal/UI_POLISH_SRS.md` TC-UIP-14 행은 "삭제와 추가 사이의 칠해진 줄"이라고
