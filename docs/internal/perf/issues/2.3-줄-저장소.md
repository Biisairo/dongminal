# 2.3 줄 저장소 (FR-TRM-2, NFR-PRF-10)

## 목표

에뮬레이터 기록 상한을 넘은 줄을 줄 단위 압축 저장소로 옮긴다. 줄 = 글자 + 속성 구간 + OSC 8 링크 구간, 블록마다 deflate, 최근 블록은 풀린 채로. 줄 단위는 감싼 행을 합친 논리 줄이고 꺼낼 때 지금 폭으로 다시 감싼다(D-28). 줄마다 절대 줄 번호를 붙인다. 상한(기본 50,000줄)을 넘으면 오래된 블록부터 버리고, ED3 를 받으면 비우되 번호는 이어 간다. 넣기 전에 줄바꿈 수로 나눠 넣어 줄을 잃지 않는다. 구간 읽기 `lines(from, count)` 를 낸다.

저장소 자체는 2.2 없이 만들고, 에뮬레이터에서 옮기는 연결은 2.2 의 표면을 쓴다. 설계: `perf/M2_DESIGN.md` §2.3, `perf/EMULATOR_2026-11-24.md` §6. 결정: D-14, D-28.

## 완료 조건

- RED: 넣은 줄을 꺼내면 글자·속성·링크가 같다(왕복). 다른 폭으로 꺼내면 xterm 재흐름과 같다.
- RED: 64 KB 청크 하나로 수천 줄을 밀어도 줄을 잃지 않는다 — 에뮬레이터 기록 + 저장소 = xterm 기준 기록.
- RED: 상한을 넘으면 오래된 줄부터 사라지고 번호는 단조 증가한다. ED3 뒤 비고 번호가 이어진다.
- 측정 시험(`--ignored`): 터미널 12개 × 5만 줄 뒤 데몬 RSS 증가분이 터미널당 8 MB 이하.
- 바꾼 부분의 시험(단위·관련 e2e 한두 개)·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.

**완료 조건 중 남은 것 — 2.4 로 넘김**

- "64 KB 청크 하나로 수천 줄을 밀어도 줄을 잃지 않는다 — 에뮬레이터 기록 + 저장소 = xterm 기준" 은 에뮬레이터(2.2)가 있어야 잴 수 있다. 2.2 가 아직 착수 전이라 이번에는 나누기 함수의 성질(이어 붙이면 원본, 조각마다 상한 이하, 긴 줄·VT·FF)만 시험했다. 연결 시험은 2.4 에서 한다.
- 데몬 RSS 전체(링 + 에뮬레이터 + 저장소) 측정은 연결 뒤(2.4/2.10).

**2.4 가 알아야 할 것(연결 계약)**

1. 에뮬레이터 행 → `Line`: 감싼 행(`WRAPLINE`)을 이어 한 논리 줄로 `LineBuilder::push(text, width, style, link)` 한다. 넓은 글자의 뒤 칸(`WIDE_CHAR_SPACER`)과 감싼 행 끝의 빈 칸(`LEADING_WIDE_CHAR_SPACER`)은 넣지 않는다. 결합 문자는 `text` 에 함께 넣는다. 색은 `Color::{Default, Indexed, Rgb}` 로 옮긴다 — alacritty `NamedColor` 의 Foreground/Background 는 `Default`, 0~15 는 `Indexed`. 밑줄 색은 `Style::underline`.
2. 논리 줄이 옮기는 경계에 걸리면(앞 행만 기록 밖으로 나감) 저장소는 조각을 이어 붙이는 API 가 없다. 연결 쪽이 완결된 논리 줄만 옮기거나, 기록 여유를 넘는 아주 긴 줄은 끊어 넣어야 한다 — 2.4 에서 정한다.
3. `split_for_rows` 는 CSI S·IND·NEL·화면 지우기(alacritty 는 ED2 때 화면을 기록으로 밀어 올린다)로 미는 행은 세지 않는다. 연결 쪽이 에뮬레이터 기록 상한을 "남길 줄 + 조각 여유 + 화면 행 수" 로 두고 조각마다 넘친 줄을 옮기면 이 틈이 막힌다.
4. 절대 줄 번호는 저장소에 들어온 줄 기준이다. 에뮬레이터 기록 줄의 번호는 `store.end() + 기록 안 위치` 로 이어 셀 수 있다.
5. 인계(2.9, D-M2-13)로 블록을 넘기려면 블록 바이트를 꺼내고 되넣는 표면이 더 필요하다 — 지금은 없다.

**남은 위험**

- 뒤쪽 빈칸: alacritty 는 지운 칸과 쓴 빈칸을 가리지 않아 "끝에 쓴 공백"은 잘린다. xterm 은 쓴 공백을 내용으로 친다 — 그 줄을 좁히면 빈 행 수가 xterm 과 다를 수 있다(드묾).
- 기준 자료의 폭 판정은 시험의 작은 표(한글·CJK·결합 문자)로 만든다. 이모지·ZWJ 폭은 2.2 비교 시험 몫이다.
- xterm 은 OSC 8 링크 칸을 밑줄로 보고한다 — 시험이 이를 반영한다(2.2 의 "OSC 8 밑줄 4셀" 과 같은 원인).

**코드와 어긋난 문서**: 없음.

### 2026-11-24 agent-pf-2-3 — 2.2 표면 대조

- 2.2 가 제안한 `otter-shared-termstate` 의 `Row{cells, wrapped}`·`Cell{text, width, fg, bg, attrs, link}` 와 저장소 입력(`LineBuilder::push(text, width, Style, Option<&Link>)`)은 2.4 에서 그대로 변환된다. 저장소 코드는 바꾸지 않았다(2.2 crate 에 의존하지 않음).
