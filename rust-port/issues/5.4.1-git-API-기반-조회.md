### Go 와 다르게 한 내부 결정
- 핸들러는 `tokio::spawn` 으로 돈다 — 응답을 기다리던 쪽이 future 를 버려도 핸들러는 끝까지 가고 요청 ctx 만 취소된다(Go 의 r.Context 취소와 같은 관측). 핸들러 패닉은 `handle` 로 다시 던진다(5.5 가 recover 규칙을 진다).
- Go `map[string]any` 응답은 `BTreeMap<String, RawMessage>`(Go 처럼 키 정렬). 임베드 구조체 응답은 `reply::embed` 로 JSON 을 이어 붙여 필드 순서를 지킨다(serde flatten 은 gocompat 가 map 으로 정렬해 순서가 깨진다).
- `Req` 의 본문은 `Mutex<Option<UnsyncBoxBody<Bytes, BodyError>>>` — 본문 오류를 구체 타입으로 둬야 rustc 고차 수명 추론이 핸들러 future 를 Send 로 본다. 요청 ID 는 `handle` 인자로 받는다.
- `gitUndoStore`·`managerWrite` 는 쓰는 종단(5.4.2·5.4.3)이 더한다. Go 테스트 전용 `gitPinsMutate` 는 옮기지 않았다.
