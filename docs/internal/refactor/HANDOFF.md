## 3. 이 세션이 값을 치르고 안 것

### 3-1. "손으로 센 수는 표본" 이 **일곱 번째**다 — 이번엔 내 수였다

| 센 사람 | 무엇 | 적은 수 | 실측 |
|---|---|---:|---:|
| 감사 | 보이는 영어 | "상단바 9" | **18** (+ 선언된 영어 15) |
| **인계서** | 보이는 영어 | 20 | **18 + 15** |
| **인계서** | 해라체 | **2** | **17** |
| 감사 | `t()` 건너뛴 자리 | 8 | **79** |
| **이 세션의 SRS §2.3** | 같은 것 | **13** | **79** |

마지막 줄이 요점이다. 나는 §2.3 을 *"같은 그릇에 `t()` 가 섞인 자리"* 라는
**내가 고른 규칙**으로 세고 13이라 적었다. 그 규칙은 **그릇에 `t()` 가 하나도
없는 자리**(`constants*.js` 의 문구 상수 65개)를 보지 못한다. 감사가 적은
"영문 리터럴 113개" 가 가리키던 집합이 그쪽이었다.

**교훈은 "감사를 믿지 마라" 가 아니라 "세는 규칙이 곧 수다" 이다.** 규칙을
적어 두면 다음 사람이 그 규칙의 사각지대를 볼 수 있다. 그래서 이 세션의 SRS 는
절마다 "세는 방법" 을 적었다 — B5 도 그렇게 해라.

### 3-2. 감사의 제안 셋이 **기존 요구를 뒤집고 있었다** — 착수 전에 잡았다

B3 이 `FR-CMP-83`(모달 높이)에서 **전량 e2e 로** 겪은 일을(§3-7 of 이전 인계서)
이번에는 **SRS 를 쓰는 동안** 잡았다. 방법은 하나다 — 제안마다 *"이 낱말·값을
못박은 요구가 있는가"* 를 grep 으로 물었다.

| 감사의 제안 | 뒤집는 것 | 결말 |
|---|---|---|
| 설정 탭 12개를 번역해라 | `FR-B-5`·`FR-B-9` + `index.html:251` 의 `lang="en"` 선언 | **범위에서 뺐다** (D-WRD-2) |
| 툴팁 낱말이 갈린다 | `UX_BATCH5_SRS` FR-TIP-2 (*"`title` 의 언어는 영어다"*) | 뜻만 맞춘다 (D-WRD-3) |
| 상단바를 한글로 | `FR-SBR-11`(`Background 2` 까지 글자로) · `FR-RVZ-1` · V70 | 구조만 세우고 낱말은 유지 (D-WRD-5) |

**뒤집어야 할 때는 뒤집되 같은 변경에서 요구를 고친다.** `FR-RTU-1`(탭 이름)과
`FR-SCT-4`(슬롯 방향 이름)는 사용자가 승인한 낱말표에 있었으므로 **그 두 SRS 를
같은 커밋에서 개정**했다 (이전/새/이유 + e2e 넷).

### 3-3. 감사의 **값** 하나가 틀렸다 — 실측이 뒤집었다

`AUDIT-design.md` §1-4 는 라이트 테마의 그늘 색으로 `ui.textDim` 을 제안했다.
이 저장소의 `textDim` 은 **글자가 아니라 경계·채움**이고(FR-TOK-3 / D-TOK-2)
라이트 11종의 상대휘도가 **0.562~0.807** 이다 — 거의 흰색이라 그늘이 되지 못한다.
같은 11종의 `ui.text` 는 0.016~0.186 이다. `ui.text` 로 바꿨다 (D-WRD-9a).

**감사가 토큰의 이름만 보고 뜻을 짐작한 자리다.** 값을 재면 3분이다.

### 3-4. 게이트를 넷 세웠고, 넷 다 **탐침으로 양쪽을 확인했다**

| 게이트 | 잡아야 하는 것 | **잡으면 안 되는 것** |
|---|---|---|
| `check-hardcoded-color`(확장) | JS·HTML·`:root` 의 새 색 | `#add-window` 선택자 · `mask-image` 의 `#000` 60건 · 등록된 파일 12 |
| `check-i18n-html` | `data-i18n` 없는 보이는 글자 | `lang` 이 선언된 서브트리 16자리 |
| `check-i18n-literal` | 이웃이 `t()` 인데 자기만 영어 | `'Enter'`(키 이름) · `Shell`·`Run <short>`(엔티티 이름) · `title` |
| `check-josa` · `check-honorific` | 회피형·고정 조사 · 해라체 | 명사형 라벨(`조정자`) |

**`check-i18n-literal` 은 첫 판이 무너졌다.** 그릇의 형제가 번역되는지 보는데,
`App.prototype` 처럼 **메서드를 담은 큰 객체**는 어딘가에 `t()` 가 있어서 파일
전체가 "번역되는 그릇" 이 됐다. 함수 본문까지 파고들지 않도록 **직접 값만** 보게
좁혔다 (`directLiterals`). 좁히기 전 16건 중 절반이 오탐이었다.

### 3-5. 조사 마커는 **치환 시점**이 전부다

`constants*.js` 는 **로드 시점에** `t()` 를 부른다. 그래서 `t()` 안에서 마커를
곧바로 풀면 `'%s {을를}'` 의 `%s` 를 보고 `s`(에스)의 받침으로 확정해 버린다 —
모든 상수가 그 순간 잘못 굳는다. 해법은 한 줄이다: **앞이 자리표시자면 풀지
않는다.** 치환하는 5자리가 치환 뒤에 `josa()` 를 한 번 더 부른다.

### 3-6. 예외는 **등록부에 사유와 함께** 살아야 게이트가 남는다

`check-hardcoded-color` 를 `:root` 안까지 넓히면 팔레트 41개가 전부 걸린다.
손으로 목록을 적으면 주입 맵이 자랄 때 조용히 갈린다 — 그래서 **`themeVarsOf` 와
`deriveShade` 에서 이름을 파생**했다. 스프레드(`...deriveShade(…)`)로 들어가는
이름도 함께 읽는다.

`diag.js` 는 **면제로 닫았다** (D-WRD-8). 진단 화면이 테마 파생에 기대면 파생이
깨졌을 때 못 읽는다 — 파일 머리와 등록부 양쪽에 사유를 적었다.

### 3-7. **파생으로 이어진 단정은 원본을 grep 해도 안 나온다**

이 세션은 묶음마다 **관련 스펙만** 돌리고(빠르다) 글자를 바꾼 묶음(E·G·H)에서
넓게 돌았다. 그렇게 고친 문구 단정이 `slot-title-boundary`(8) · `runs`(3) ·
`git-*`(38) · `window-slots`(2) 다 — **전부 낱말을 직접 적은 자리**였고 grep 으로
찾았다.

**전량 e2e 가 잡은 것은 그 방법이 못 보는 자리였다.** `sidebar-tabs` T15 는
단축키 행의 라벨을 `'사이드바 탭: Windows'` 로 단정하는데, 그 문자열은 코드
어디에도 없다 — `사이드바 탭: ` + **서술자의 label** 로 조립된다(FR-SBT-30).
바꾼 낱말(`Windows`)을 grep 해도 이 자리는 나오지 않는다.

**그래서 전량은 묶음 끝이 아니라 판정의 일부다.** 회차를 세 번 돌았고,
1·2회차의 실패 셋 중 하나가 이 회귀였다. 나머지 둘은 단독 3회 초록이었고
그중 `git-menu` N3 는 **이 세션 이전부터** 기록된 부하 flake 다.
*"회차마다 다른 스펙이 걸리면 부하, 같은 것이 반복되면 결함"* — 이 규칙으로
가른 뒤에도 **반복된 것 하나(N3)는 먼저 이전 인계서에서 확인**하고 넘겼다.

### 3-8. `make e2e` 의 종료 코드는 여전히 함정이다

이전 인계서 §3-8 그대로다. **샤드별 요약을 직접 세어라:**

```
for i in 1 2 3 4 5 6 7 8; do echo -n "샤드 $i: "; \
  LC_ALL=C grep -a "샤드 $i/8" <로그> | LC_ALL=C grep -aoE '[0-9]+ (passed|failed|flaky)' | tr '\n' ' '; echo; done
```

`✘` 로 grep 하면 **안 잡힌다** (색 코드가 섞인다). `N failed` 를 세라.

## 4. 변하지 않는 규약

`CONTRIBUTING.md` 가 원본이다.

1. **SRS → 테스트 → 코드.** RED 를 **실제로** 보고 나서 구현한다. 이미 구현했다면
   `git stash push web/` 로 코드만 되돌려 확인한다
2. **게이트를 느슨하게 만들어 통과시키지 않는다.** 다만 **재는 대상이 달라진 것**은
   느슨하게 만드는 것이 아니다
3. **새 게이트를 세우면 탐침으로 검출을 확인하고 지운다.** 잡아야 하는 것과
   **잡으면 안 되는 것**을 둘 다
4. **동작을 바꾸면 근거 문서를 같은 변경에서 고친다.** 이전 / 새 / 이유 셋
5. **커밋 메시지에 FR 번호를 단다. AI 서명 금지**
6. **생성물을 직접 고치지 않는다** — `docs/external/errors.md` · `docs/internal/decisions.md`
7. **색은 팔레트를 바꾸지 않는다** (FR-TOK-16). 새 hex 를 넣지 마라
8. **낱말·값을 바꾸기 전에 그것을 못박은 요구를 grep 으로 찾는다** (§3-2)
