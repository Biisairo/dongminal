# 5.3 데몬 클라이언트

## 목표

웹 서버 → 데몬 클라이언트(재연결 감독 포함)를 옮긴다. 재연결 간격·횟수가 같아야 한다 (FR-RSP-4).

## 대상 Go 코드

- `internal/webserver/toolclient`

프로덕션 코드 약 1510줄.

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  **다음 세션이 할 일 (순서)**
  1. (끝남) 조정자에게 두 커밋을 알렸다. 5.3 이 끝나면 `dmctl msg --to 37787b76-bd93-43c8-871c-f8c89c66afec` 로 알린다.
  2. 공통 규칙 `int/rust-port/AGENT_RULES.md` 와 이 이슈를 읽는다. 시작 prod-pids 는 이미 적었다(위).
  3. Go `internal/webserver/toolclient` 를 읽는다. 이미 파악한 것:
     - 상수: toolCallTimeout 5s, toolCreateTimeout 60s, toolDialTimeout 2s, toolReconnectBackoff 1s(두 배씩, 상한 toolMaxBackoff 30s), toolRespawnEvery 3(실패 3·6·9…번째마다 spawnDaemon), toolHeartbeatEvery 15s(ping 은 pending 이 있으면 건너뜀, ping 시한=toolCallTimeout), listCacheTTL 200ms.
     - 연결: `platform::current().ipc.dial(sock, 2s)` → readLoop 시작 → `hello`(params `HelloParams{features: SERVER_FEATURES}`) → `version`(없으면 PROTOCOL_VERSION) 이 다르면 "hello: protocol mismatch: daemon=%d server=%d". 실패 시 "dial dongminald: %w".
     - RPC: 줄 단위 JSON(Go json.Encoder = 끝에 \n). 요청 `{"id","method","params"}`, 알림 `{"method","params"}`. 오류 문구: "toolclient not connected", "paned connection lost", "paned call %q timed out"(시한이면 지금 연결을 끊는다), "toolclient closed". RPC 오류는 `RpcError{code,message}`.
     - readLoop: wireMsg 하나로 응답·push 를 함께 푼다. 값 오류(UnmarshalTypeError·base64)는 연결을 끊지 않는다(응답이면 그 오류를 돌려줌, push 면 버림). 그 밖의 읽기 오류는 로그 "toolclient read: %v"(닫는 중이 아니면) 뒤 connLost(대기 중 호출 모두 "paned connection lost").
     - supervise: 연결이 죽으면 Warn "toolclient: connection lost, reconnecting...", backoff 뒤 connect, 성공하면 reconnects+1, Info "toolclient: reconnected", 그리고 resyncAfterReconnect·resyncRecords·resyncEdge·resyncChat 순서. 실패 n 번째가 3 의 배수면 Error "toolclient: respawning dongminald after %d failed dials" 뒤 spawnDaemon.
     - push(event): output(onOutput 콜백 + 구독 채널, 가득 차면 버리고 dropped==1 또는 256 의 배수일 때 Warn), fg(목록 캐시 무효화, fgSeen 기록, onForeground), exit(구독자 exit 채널 닫기, onExit 없으면 earlyPushes 에 쌓았다가 SetOnExit 때 흘림), size(cols·rows 0 이면 무시), report·attn·edges·chat.
     - ToolHub 메서드(client_toolhub.go): Subscribe, Connected, List/ListOK(200ms 캐시·세대), Create(60s, CODE_TOOL_CAP → ErrToolCap 감쌈), Get, Delete(kill), Terminate(시한 5s+grace), Restore, IsLive, Write/SendPaste(nil 데이터는 빈 배열), Resize, InputNotify/ResizeNotify(FEATURE_NOTIFY 없으면 RPC 로 대체), Cwd, Busy, BusyMany(FEATURE_BUSY_MANY 없으면 하나씩), ShellProbe(FEATURE_SHELL_PROBE, 알 수 없는 값은 Unknown), SetBackground, BackgroundList, SnapshotTool/Since(CODE_NOT_FOUND → ErrToolNotFound), Reconnects.
     - 아직 안 읽은 파일: client_resync.go, client_records.go, client_edge.go, client_chat.go, client_attention.go, 그리고 시험 전부(client_test.go 867줄이 가장 크다 — 가짜 IPC 서버 패턴을 거기서 옮긴다).
  4. Rust 쪽 확인할 것: `rust/crates/shared/toolhub/src/hub.rs` 에서 `ToolHub` trait 이 있는지·모양(ToolInfo·OutChunk·DaemonInfo·ToolSnapshot 은 있다. trait 은 grep 에 안 걸렸다 — 없으면 조정자에게 묻는다), `toolipc` 의 wire.rs·protocol.rs(PanedErrObj·RpcError·HelloParams·*Params/*Result), `platform::current().ipc`(1.4.5, 동기 API — IpcStream: Read+Write).   5. 설계 결정(권장): platform 이 동기 API 이므로 toolclient 도 스레드 기반 동기 구현(readLoop·supervise 전용 스레드, 응답은 채널, 시한은 recv_timeout). 소비자(웹서버 async)는 spawn_blocking 으로 감싼다. 구독 채널은 크기 있는 채널(try_send 실패 = 드롭).
