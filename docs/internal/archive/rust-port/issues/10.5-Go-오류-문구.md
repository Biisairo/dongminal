**기대 문구 실측(go1.27.2 darwin/arm64, hermetic)**: `mkdir $ROOT/f: not a directory`(조상이 파일·끝이 파일), `mkdir $ROOT/f/: not a directory`(끝 `/`), `mkdir $ROOT/ro/a: permission denied`(권한 없는 조상), `mkdir : no such file or directory`(빈 경로), `open $ROOT/p.md: permission denied`, `exec: "dmx": cannot run executable found relative to current directory`(PATH=`.`·PATH=`bin`), `exec: "x": executable file not found in $PATH`.

**공개 API**
- `dm_gocompat::oserr::mkdir_all(path: &str, perm: u32) -> io::Result<()>`: Go `os.MkdirAll`(go1.27.2 os/path.go) 그대로다. 부모 판정은 `len(parent) > len(VolumeName(path))`. 오류는 `path_error("mkdir", 막힌 칸, e)` 이고 ENOTDIR 은 unix errno 20, Windows 는 `NotADirectory` + `not a directory`.
- `dm_shared_platform::{LookPathError{NotFound, Dot}, exec_error(file, err), try_look_path(file), try_look_path_in(file, path_env)}`. 기존 `look_path`·`look_path_in`(Option)은 그대로 두고 `try_*().ok()` 로 바꿨다. `exec_error` 는 Go `exec.Error.Error()` 이고, NotFound 문구는 unix `$PATH`, Windows `%PATH%` 다.

**FR-RDF-9 고친 자리(RED→GREEN, 자리마다 문구 시험 하나)**
- serverconf `fsx::mkdir_all` → `write_addr_mkdir_error_matches_go`
- worktree `Manager::create`(권한 0o755 상수화, 전에는 `create_dir_all` 이라 0o777&umask) → `create_mkdir_error_matches_go`. 쓰지 않게 된 `Error::io` 를 지웠다.
- gitapi `worktree::mkdir_parents`·`ignore::write_head_temp`. 이중 감쌈을 없앴다 → `mkdir_parents_error_matches_go`·`head_temp_mkdir_error_matches_go`
- httpapi `fs_upload_target`: 부모가 파일이면 Go 는 ENOTDIR 이므로 코드가 `io_failed` 다(전에는 EEXIST 라서 `exists` 409 가 나갔다) → `fs_upload_rel_path_guards` 에 추가
- ctl-cli `start::mkdir_all` 은 gocompat 을 다시 내보낸다(doctor·backup 이 같이 쓴다. 이미 Go 알고리즘이라 RED 없이 회귀 시험만 둔다). `service --out`(stderr) → `out_mkdir_error_matches_go`
- runtime·agentadapter `mkdir_all`: 전에는 `Path::parent` 였다. `x/new/.` 에서 Go 는 성공하는데 Rust 는 실패했다 → `mkdir_all_matches_go` ×2
- toolhub 히스토리 디렉터리 로그 → `hist_dir_mkdir_error_matches_go`, cmd/dongminal `resolve_home` → `home_mkdir_error_matches_go`
- platform `lock_file`(SRS 목록 밖이지만 내 crate 다. 이중 감쌈이었다) → `mkdir_error_matches_go`

**FR-RDF-10**: decidx `collect` 가 Go `os.ReadFile` 처럼 `open`·`read` PathError 로 감싼다(dm-gocompat 의존 추가) → `collect_unreadable_file_carries_path`.

**FR-RDF-11**: platform `look_path_unix`·`look_path_windows` 가 `Result<_, LookPathError>` 다. Windows 는 루프가 끝난 뒤 dotf 가 있으면 Dot 이다(Go `lookPathExts` 와 같다). 문구를 만드는 호출자: platform pty `resolve`, sandbox `look_path`, ext `HostExec`(`host_exe_in` 으로 뺐다), git core `look_git`(ErrDot 도 GitMissing 이다. Go 는 모든 lookGit 오류를 ErrGitMissing 으로 감싼다). 시험: `windows_rules`·`unix_rules`(Dot 기대), `try_look_path_in_tells_dot_from_not_found`, `exec_error_matches_go`, `resolve_reports_err_dot`, `look_path_reports_err_dot`, `host_exe_reports_err_dot`, `exec_git_err_dot`. ErrDot 이면 지금처럼 실행하지 않는다.

**게이트**: `cargo fmt --all --check` OK. 고친 16 crate 의 `clippy --all-targets -D warnings` OK. `rust/scripts/cross-check.sh` 다섯 대상 ✓. `hermetic.sh cargo test` 16 crate 모두 OK(병합 뒤 다시 돌렸다). 시험 수: 새 시험 19개, 기대값을 바꾼 기존 시험 3개(unix_rules·windows_rules·fs_upload_rel_path_guards).

**Go 와 다르게 한 내부 결정**: 없다. 관측 동작은 모두 Go 와 같게 했다. 프로세스 PATH 를 바꾸지 않고 시험하려고 `resolve_in`·`look_path_in`(sandbox)·`host_exe_in` 이음매를 두었다.

**남은 위험(조정자 판단 요청)**
1. Go 알고리즘을 따로 흉내 내는 자리가 남아 있다: ext `goos::mkdir_all`(go1.27 이전의 fixRootDirectory 판), wsentry `fsx::mkdir_all`, claudeacct `fsutil::mkdir_all`(`Path::parent` 라서 `x/.` 에서 Go 와 갈린다). SRS 3번 목록 밖이라 손대지 않았다.
2. `DirBuilder::recursive` 를 쓰는 자리가 남아 있다: sandbox `helper.rs:135`, sandboxplace(오류를 버린다), daemon chatsock `lib.rs:339`, daemon ipc `server.rs:173`·`report.rs:55`, privhelper `secret.rs:130`·`lib.rs:246`. 문구가 밖으로 나가는지는 확인하지 않았다.
3. platform `procinfo/darwin.rs` 는 `Command::new("ps")` 로 std 의 PATH 검색을 쓴다. 상대 PATH 항목만 있으면 Go 는 ErrDot 으로 거절하는데, Rust 는 그 파일을 실행할 수 있다. look_path 를 거치지 않는 자리라 FR-RDF-11 범위 밖으로 두었다.
4. 명시 경로(`/`·`\` 포함)를 찾지 못했을 때 Go 는 `findExecutable` 의 원인(`permission denied`, `is a directory`, `file does not exist` 등)을 싣지만, Rust 는 NotFound 문구를 낸다. 이 차이는 전부터 있었고 ErrDot 과는 무관하다.
5. `envset::tests::thread_count_sees_new_thread` 가 전체 실행에서 한 번 흔들렸다. 다시 세 번 돌려 모두 통과했다. 이번 변경과 무관하다.
