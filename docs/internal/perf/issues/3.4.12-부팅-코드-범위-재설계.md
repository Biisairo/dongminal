# 3.4.12 부팅 코드 범위 재설계

## 목표

- 부팅 JS 를 원래 목표 1.5 MB 이하로 줄인다. 지금 NFR-PRF-12 는 D-42 로 1.55 MB 이고 3.4.10(주석·줄 끝 공백 걷기)으로 1,543,764 B 다 — 여유 6.2 KB.
- 방법은 코드 양 줄이기(주석 걷기·압축)가 아니다. 부팅 때 넘기는 코드의 범위를 새로 정하거나 부팅 로직을 새로 짠다(사용자 결정 2026-11-25).
- 중·대 규모다. 설계(무엇을 부팅에 남기고 무엇을 처음 쓸 때 싣는가)는 사용자 확인을 받은 뒤 구현한다.

## 배경

3.4.10 판정 측정(perf-m1 `4f41422b`, 3.4.6~3.4.9 병합 뒤): 부팅 JS **2,505,579 B**. 요청 45, Script 14.

| 파일 | 바이트 | 주석 | 비고 |
|---|---|---|---|
| `b/boot.js` | 1,796,724 | 949,135 | 서버 묶음 |
| `b/pre.js` | 21,036 | 11,276 | 서버 묶음 |
| `js/i18n/ko.js` | 114,439 | 3,319 | 묶음 밖, 언어 카탈로그 |
| vendor 8개 | 563,478 | 거의 없음 | xterm 289,441 · markdown-it 114,905 · addon-webgl 100,856 · purify 29,369 · addon-search·unicode11·web-links·fit |
| head `js/core/*` 3개 | 9,902 | 3,073 | server-move·storage-rename·panel-layout |

- 묶음 밖에서 부팅 때 실리는 양이 약 0.69 MB 다.
- markdown-it·DOMPurify(144 KB)는 3.4.8 결정으로 부팅에 남았다. 터미널 맨 도메인 링크(`bare-link.js`)·편집기 링크(`cm-link.js`)가 markdown-it 을, LSP hover(`lsp-client.js`)가 DOMPurify 를 쓴다.
- 위 표는 주석 걷기 전이다. 3.4.10 A안(주석·줄 끝 공백 걷기)이 병합되어 지금 부팅 JS 는 1,543,764 B(`b/boot.js` 845,965 · `b/pre.js` 9,980)다. 더 줄이는 일은 코드 양이 아니라 범위·로직 재설계로 한다(사용자 결정 2026-11-25).

**이미 나왔던 선택지 (참고, 결정 아님)**

- B. 목표를 고친다(예: 1.55 MB, 또는 "주석을 뺀 바이트").
- C. `js/core` 를 더 쪼갠다(메뉴·원격·도움말 등), 또는 언어 카탈로그·vendor 를 처음 쓸 때 싣는다.

## 완료 조건

- 설계(부팅 범위의 새 정의)를 사용자가 확인한다.
- `scenario.mjs --only boot` 의 `jsBytes` 가 1,500,000 B 이하다. 이전·새 숫자를 진행 기록에 적는다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다. 전체 시험 금지.
