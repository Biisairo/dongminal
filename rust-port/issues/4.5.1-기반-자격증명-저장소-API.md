  - **Go 와 다르게 한 내부 결정**
    - HTTP 는 async(reqwest + ring)다. Go 의 ctx 는 받지 않는다 — 취소는 future 를 drop 하는 것으로, 시한은 내부 tokio timeout 으로 한다(시한 초과 문구 `Get "<url>": context deadline exceeded`). 전송 오류 꼬리는 reqwest 문구다.
    - `ClaimReset` 은 Go 처럼 (본문, 오류) 두 값을 함께 돌려준다. 상태 오류여도 본문을 쓴다.
    - Go 의 함수 반환 release(`func()`)는 drop 가드(`DirLock`·`ClaudeLock`·`FileLock`)다. 시험 훅 전역 `dirLockTouch` 는 내부 인자(`acquire_dir_lock_with`)로 바꿨다. `readStoreFile` 이음매는 읽기 횟수 카운터(`Store::reads`)로 바꿨다.
    - Go `ReadOAuthAccount`/`Read` 의 `(값, ok, err)` 는 `Result<Option<_>>` 다.
    - waker 는 tokio 다. Go 는 음수 시간을 받지만 Rust 는 `Duration` 이므로 0 으로 본다(하한과의 max 결과는 같다).
    - `ScopedWindow` 는 임베드 대신 필드를 펼쳤다(JSON 키·순서 같다).
    - `ACCOUNT_RANGES` 는 BTreeMap 이다(Go map 의 JSON 출력도 키 정렬이라 같다).
    - NFC 는 `icu_normalizer` 다(워크스페이스 의존 추가, DEPENDENCIES.md 기록. url→idna 가 이미 끌어오는 crate). 유니코드 판의 차이(x/text 와 ICU4X)는 새로 배정된 글자에서만 드러난다.
    - 4.5.2~4.5.4 가 쓸 내부 API 가 아직 쓰이지 않아 lib.rs 에 `#![allow(dead_code)]` 를 임시로 달았다. 4.5.4 에서 지운다.
  - **남은 위험**
    - `State.accounts` 는 `Vec` 이라, Go 에서 계정을 한 번도 넣지 않은 상태를 update 하면 `"accounts": null` 이 쓰이는 경우가 Rust 에서는 `[]` 다(LOW. 읽기 쪽은 둘 다 빈 목록이다). 4.5.2 의 Service 가 그 경로를 쓰는지 보고 필요하면 맞춘다.
    - dirlock·Store 락·키체인 호출은 블로킹이다. async 호출부(4.5.2~)는 `spawn_blocking` 이나 블로킹 허용 구간에서 불러야 한다(MEDIUM, 4.5.2 에서 정한다).
