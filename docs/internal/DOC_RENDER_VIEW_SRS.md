# SRS: 문서의 렌더 뷰 (Markdown · SVG · HTML · 표) — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 두 문장이다.

> **"editor 에서 지금 image 만 이미지로 보이고 다른건 다 텍스트로 보인다."**
> **"vsc 처럼 버튼을 통해 해당 문서가 랜더되는 모습을 볼 수 있도록."**

지금 편집기가 그림으로 그리는 것은 **이미지 파일 하나뿐이다**. `README.md` 도
`icon.svg` 도 `data.csv` 도 전부 소스 텍스트다 — 그것들이 사람에게 보이려고 만들어진
문서인데도 그렇다.

요구는 편집기가 그 문서를 **결과로도 보여주는 것**이다.

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 판정·진입 | 어떤 파일이 렌더 가능한가. 버튼은 어디에 서는가 |
| **B** 자리 | 옆 칸에 렌더 탭을 연다 (VS Code 의 "Open Preview to the Side") |
| **C** 렌더링 | Markdown · SVG · HTML · CSV/TSV 넷 |
| **D** 살아 있음 | 저장 전 편집을 따라가고, 스크롤 자리를 지킨다 |
| **E** 경계 | 정화·샌드박스·경로·상한 |
| **F** 수명 | 저장·복원·닫기·이동·테마 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **렌더 뷰** | 문서를 사람이 보는 모습으로 그린 화면. 이 SRS 가 만드는 것 |
| **렌더 탭** | 렌더 뷰를 담은 탭. `type:'editor'` 이며 `render:true` 로 갈린다 |
| **소스 탭** | 지금까지의 편집기 탭 (Monaco) |
| **미리보기 탭** | **이미 있는 어휘다** — REPO_TAB_UNIFY_SRS FR-RTU-40 의 *임시 탭*(기울임, 다음 클릭에 대체). **렌더 뷰와 다른 것이며 이름을 겹쳐 쓰지 않는다** (D-6) |
| **문서(document)** | 파일 하나에 하나인 Monaco 모델과 dirty (FR-SVS-50). 칸마다 뷰가 그것을 공유한다 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 편집기 탭의 본문은 `FileEditor` 하나뿐이다

`renderer.js:547` 의 `_mountTabBody`:

```js
if(at.type==='editor'){
  const key=this.app._slotKey(at.id,slot);
  let editor=this.app.fileEditors.get(key);
  if(!editor){editor=new FileEditor(at.id,at.name,at.filePath);...}
```

타입이 `editor` 면 실체는 언제나 Monaco 다. 렌더 뷰가 설 자리는 **이 분기 안**이거나
새 타입인데, 새 타입의 대가는 §2.7·2.8 에 있다.

### 2.2 이미지만 그려지는 기계적 이유

`file-editor.js:225` 가 `probe.kind === FILE_KIND_IMAGE` 일 때만 `<img>` 를 세운다.
그리고 그 판정은 `handlers_file_probe.go:36` 의 `http.DetectContentType` 이다.

**Go 의 sniffer 는 SVG 를 모른다.** `<svg …>` 로 시작하는 파일은 `text/xml` 로
판정되어 kind 는 `text` 가 되고, 편집기는 그것을 소스로 연다. 사용자가 든 예가 바로
그 자리다.

### 2.3 `/api/file/raw` 는 이미지만 내보낸다 — 그것이 방어선이다

그 종단의 주석이 이유를 적고 있다.

> **이미지만 내보낸다.** 임의의 파일을 추론된 MIME 으로 같은 출처에서 인라인
> 제공하면 저장형 XSS 가 된다 — HTML 하나면 족하다.

SVG 를 그리려면 이 벽에 문을 내야 한다. **문을 내는 방법이 이 SRS 의 가장 중요한
결정이다** (FR-DRV-24).

### 2.4 응답에 CSP 헤더가 없다

`internal/webserver` 전체에 `Content-Security-Policy` 가 한 번도 나오지 않는다.
그러므로 "브라우저가 알아서 막아 준다" 는 전제를 쓸 수 없다 — 렌더가 스크립트를
만나는 자리는 **우리가 막는다**.

### 2.5 문서는 파일마다 하나이고, 뷰는 칸마다다

`app._edDoc(filePath)` 가 (모델, dirty, views) 를 쥐고 `FileEditor` 들이 그것을
공유한다 (FR-SVS-50~55). 그러므로 **렌더 뷰가 그 문서를 구독하면 저장하지 않은
편집을 그릴 수 있다** — 디스크를 읽으면 방금 쓴 문장이 보이지 않는다.

### 2.6 뷰의 수명은 `renderer` 가 하나의 루프로 관리한다

`renderer.js:233`:

```js
for(const[k,v] of app.fileEditors){
  const tid=app._slotBase(k);
  if(!allTabIds.has(tid)){v.destroy();app.fileEditors.delete(k)}
}
```

키는 `(탭 id, 슬롯)` 복합키다 (FR-WSL-75). 렌더 뷰를 **다른 Map** 에 두면 이 루프와
`app-slots.js:514`·`app-layout.js:527` 의 회수를 전부 한 벌 더 써야 한다.

### 2.7 Editor 창은 탭 타입을 둘로 제한한다

`app-layout.js:344`:

```js
if (this._isEditorWin(s) && type !== 'editor' && type !== TAB_TYPE_GIT) return;
```

새 타입은 이 가드를 지나야 한다.

### 2.8 타입을 **열거하는 자리**가 여럿이다

| 자리 | 하는 일 |
|---|---|
| `helpers.js:483` `clean()` | `editor`·`run`·git 탭만 `toolId` 검사에서 면제한다. 빠지면 **로드마다 사라진다** |
| `helpers.js:520` `tabNameSource()` | 그 셋의 이름을 `manual` 로 고정한다 |
| `app-layout.js:344·418·513` | 창 가드·생성·닫기 |
| `app-editor.js:318·338` | 일반 창에 남은 `editor` 탭 제거 |
| `renderer.js:306·547·681` | 포커스·본문·모바일 분기 |

**새 타입 하나의 값이 이 여섯 자리다.** 그것이 D-1 의 근거다.

### 2.9 같은 경로의 탭은 하나로 재사용된다

`_findEditorTab(filePath)` 이 워크스페이스 전체에서 `type==='editor' && filePath===`
를 찾고, 있으면 그 탭으로 옮긴다 (FR-EDT-101). 소스와 렌더가 **함께 열려 있어야
하므로** 이 판정은 갈려야 한다 (FR-DRV-10).

### 2.10 옛 md 뷰어는 제거됐다

`MdViewer`·`/api/md-file` 은 이 저장소에 흔적이 없다(전수 grep). 아카이브 문서
(`archive/MD_VIEWER_REGRESSION_FIX_SRS.md`, `archive/MD_SCROLL_SYNC_SRS.md`)에 그
기능이 있었던 사실과 **그때 났던 회귀**가 남아 있다: 비활성 창의 뷰 인스턴스가 매
렌더마다 파괴되던 것, 세션 전환 뒤 포커스가 옛 자리로 복원되던 것.

지금은 그 두 결함의 자리가 다르다 — 수명은 `renderer` 의 한 루프가, 포커스는 슬롯
체계가 정한다. **되살리는 것이 아니라 지금 구조 위에 새로 세우는 일이다.**

### 2.11 오프라인 자산의 선례는 `web/vendor/` 다

`xterm.js`·애드온 넷이 거기 있고 `index.html:374` 가 그것을 로컬에서 읽는다. Monaco
만 CDN 이다 (`file-editor.js:5`).

### 2.12 칸을 나눠 탭을 넣는 길이 이미 있다

`app-dnd.js:98` 의 `_splitPaneWithTab(srcRid, tabId, targetRid, zone)` — 드래그
드롭이 쓰는 것이며, "옆 칸에 연다" 가 딛을 바닥이다.

### 2.13 알림·오버레이의 규약이 이미 있다

`FileEditor` 는 자기 `el` 안에 `fe-find`(찾기)·`fe-note`(알림)·`fe-offer`(제안)를
얹는다. `.file-editor` 가 `position:absolute` 이므로 새 좌표계를 만들 필요가 없다
(FR-EFP-8 / D-3).

### 2.14 렌더는 언어 서버(LSP)와 무관하다

같은 접수 안에 두 요구가 함께 들어 있었으므로 **여기서 경계를 못박아 둔다.**

LSP 는 편집기에 **의미 정보**를 주는 프로토콜이다 — 타입·정의 자리·진단. **문서를
그려 주지 않는다.** `vscode-markdown-language-server` 에게 `README.md` 를 줘도 HTML 은
나오지 않으며, 나오는 것은 깨진 링크 목록과 헤딩 심볼이다.

VS Code 도 같다. 그쪽의 마크다운 미리보기는 LSP 가 아니라 **번들된 렌더러가 웹뷰
안에서** 그리며, 마크다운 언어 서버를 꺼도 미리보기는 그대로 뜬다.

| 하는 일 | 누가 | 언어 서버가 필요한가 |
|---|---|---|
| 렌더 뷰 (md → 화면) | 우리가 `vendor/` 에 담는 렌더러 | **아니다** |
| SVG 그리기 | 브라우저의 `<img>` | **아니다** |
| 소스 편집기의 문법 색칠 | Monaco 내장 문법 (이미 된다) | **아니다** |
| 렌더 안 코드 블록 색칠 | `vendor/` 의 정적 하이라이터 (FR-DRV-13b) | **아니다** |
| 진단·호버·정의 이동 | 언어 서버 | 예 — 이 문서의 것이 아니다 |

**그러므로 이 SRS 의 전 범위는 언어 서버가 하나도 없어도 동작한다.** 두 작업은 같은
파일을 대상으로 삼을 뿐 코드가 겹치지 않으며, 나란히 진행할 수 있다 (I-6).

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 A — 판정과 진입 (FR-DRV-1~6)

- **FR-DRV-1** 렌더 가능 여부는 **확장자**가 정한다. 표는 **한 자리**에 산다.

  | 종류 | 확장자 |
  |---|---|
  | `markdown` | `.md` · `.markdown` · `.mdown` |
  | `svg` | `.svg` |
  | `html` | `.html` · `.htm` |
  | `table` | `.csv` · `.tsv` |

  **내용 판정(§2.2 의 sniff)을 쓰지 않는다.** Markdown 과 평문은 내용으로 갈리지
  않는다 — 확장자가 근거인 유일한 자리다.
- **FR-DRV-2** 렌더 가능한 파일의 편집기에만 진입 버튼이 선다. 그렇지 않으면
  **자리를 만들지 않는다** — 눌리지만 아무 일도 하지 않는 버튼은 고장으로 읽힌다
  (FR-GIT-180 과 같은 근거).
- **FR-DRV-3** 버튼은 편집기 **우상단 오버레이**다 (§2.13 의 규약). 탭바에 두지
  않는다 — 그것은 모든 탭 타입이 지나는 렌더 경로이며, 편집기 하나의 사정으로
  건드릴 자리가 아니다.
  > **개정 (UX_BATCH8_SRS FR-DRB-1·2·3, 2026-09-08).** 편집기 오버레이라는 규약은
  > 그대로이나 자리가 **좌상단**이고, 버튼의 이름은 기호가 아니라 낱말이다
  > (`미리보기`). 기호 하나에 `opacity:.65`·`--text-dim` 의 22px 정사각은 미니맵
  > 위에서 배경에 잠겼고, 그것이 "미리보기 버튼이 없음" 으로 접수됐다. 라벨을 붙인
  > 뒤에는 그 폭이 미니맵·스크롤바를 덮어 자리를 왼쪽으로 옮겼다.
- **FR-DRV-4** 버튼은 자기가 하는 일을 말한다 (툴팁). 문구는 상수에서 온다 —
  화면에 문장을 박으면 그 문장이 두 자리에 산다.
- **FR-DRV-5** 렌더 탭이 이미 열려 있으면 **새로 만들지 않고 그 탭으로 옮긴다.**
- **FR-DRV-6** 렌더 탭에서 같은 버튼은 **소스 탭으로 돌아간다.** 렌더를 켠 손이
  끄는 법을 따로 배우지 않는다.

### 3.2 묶음 B — 자리 (FR-DRV-7~12)

- **FR-DRV-7** 렌더 탭은 **옆 칸**에 선다 (I-2). 지금 칸의 오른쪽(세로 분할이면
  아래) 형제 칸이 그 자리다.
- **FR-DRV-8** 형제 칸이 없으면 지금 칸을 **가로로 나눠** 만든다. 그 일은 이미 있는
  `_splitPaneWithTab` 의 경로를 딛는다 (§2.12) — 분할 규칙을 두 벌로 쓰지 않는다.
- **FR-DRV-9** 렌더 탭은 `type:'editor'` 를 유지하고 **`render:true`** 로 갈린다
  (D-1). 새 탭 타입을 만들지 않는다.
- **FR-DRV-10** `_findEditorTab` 은 **소스 탭만** 찾는다 (§2.9). 갈리지 않으면
  탐색기에서 파일을 열었을 때 소스가 아니라 렌더가 뜬다.
- **FR-DRV-11** 두 탭의 이름이 같으면 어느 것이 렌더인지 알 수 없다. 렌더 탭의
  이름에는 **표시가 붙는다**, 그리고 그 표시는 `_tabDisplayName` 한 자리에서 붙는다.
- **FR-DRV-12** 렌더 탭은 소스 탭과 **같은 자격**이다 (FR-RTU-33): 닫기·드래그·분할·
  칸 이동이 같다. 이름 변경만 없다 — 이름이 파일에서 파생하기 때문이다.

### 3.3 묶음 C — 렌더링 (FR-DRV-13~19)

- **FR-DRV-13** **Markdown**: CommonMark + GFM(표·작업 목록·펜스 코드·자동 링크).
  결과는 정화를 지나 DOM 에 들어간다 (FR-DRV-20).
- **FR-DRV-13b** 펜스 코드 블록은 **문법 색칠된다** (I-5). 색칠은 `vendor/` 에 담은
  **정적 하이라이터**가 한다 (D-8) — **VS Code 와 같은 방식이다** (I-7).

  **이것은 LSP 가 하는 일이 아니다** (§2.14). 문서 안의 코드 블록을 언어 서버로
  칠하려면 그 블록만 떼어 가상 파일로 만들어 그 언어의 서버에 물어야 하는데(embedded
  language), 마크다운 언어 서버는 그것을 하지 않는다. VS Code 의 미리보기도 웹뷰에
  번들한 정적 하이라이터를 쓴다.
- **FR-DRV-13c** 언어를 적지 않았거나 하이라이터가 모르는 언어의 블록은 **색 없이
  그대로 낸다.** 모르는 것을 짐작해 칠하지 않는다.
- **FR-DRV-13d** 하이라이터의 색은 **CSS 변수에서 파생한다** (FR-DRV-18). 하이라이터가
  들고 오는 기성 테마(그 라이브러리의 `*.css`)를 그대로 쓰지 않는다 — 쓰면 그 색만
  테마를 따라오지 않아, 밝은 테마에서 코드 블록 하나가 어두운 섬으로 남는다.
- **FR-DRV-13e** 하이라이터는 **전체 언어 묶음을 담지 않는다.** highlight.js 는
  190종이 넘는 문법을 내는데, 배포물이 쓰이지 않는 문법을 지고 갈 이유가 없다.

  **실제로 담은 것은 `common` 빌드다** (11.12.0 · 128 KB · 45종). 언어를 하나씩
  골라 담는 길도 있으나 그 경로에는 **UMD core 빌드가 없다** — 개별 언어 파일은
  전역 `hljs` 를 전제하므로 core 를 ESM 으로 받아 조립해야 하고, 그것은 이
  저장소에 없는 프론트 빌드 단계를 만드는 일이다. `common` 은 이 저장소의 문서가
  쓰는 것(`go`·`js`·`ts`·`bash`·`json`·`yaml`·`sql`·`css`·`xml`·`diff`)을 모두
  덮으며, 비교 대상인 `xterm.js`(289 KB)의 절반이 안 된다.
- **FR-DRV-14** **SVG**: `<img>` 로 그린다 (FR-DRV-23). 원본 비율을 지키고 칸보다
  크면 줄여 맞춘다 — 이미지 뷰(FR-EVW-4)와 같은 규약이다. 크기와 바이트를 함께
  적는다.
- **FR-DRV-15** **HTML**: `sandbox` iframe 의 `srcdoc` 으로 그린다. **스크립트는
  돌지 않으며 그 사실이 화면에 적힌다** (FR-DRV-22).
- **FR-DRV-16** **CSV/TSV**: 표로 그린다. 구분자는 확장자가 정하고, 첫 줄을 머리글로
  본다. 따옴표로 감싼 칸과 그 안의 구분자·줄바꿈을 지킨다.
- **FR-DRV-17** 그리지 못하면 **사유를 말한다** — 빈 화면은 고장과 구별되지 않는다
  (EDITOR_LSP_SRS D-9 와 같은 근거).
- **FR-DRV-18** 렌더 뷰의 색은 **CSS 변수에서 파생한다.** 색을 하드코딩하지 않는다
  (FR-GIT-119 와 같은 근거) — 테마를 바꾸면 따라온다.
- **FR-DRV-19** 렌더 뷰는 **읽는 화면이다.** 거기서 문서를 고칠 수 없고, 그 사실이
  화면과 어긋나지 않아야 한다(커서·입력 자리를 만들지 않는다).

### 3.4 묶음 D — 살아 있음 (FR-DRV-40~44)

- **FR-DRV-40** 렌더 뷰는 **문서(모델)를 읽는다** — 디스크가 아니다 (§2.5). 저장하지
  않은 편집이 그대로 보인다.
- **FR-DRV-41** 문서가 없으면(소스 탭이 닫힌 뒤에도 렌더 탭이 살아 있는 경우) 파일을
  읽는다. 그때도 화면은 비지 않는다.
- **FR-DRV-42** 편집하면 따라온다. 다시 그리는 일에는 **지연(디바운스)이 있다** —
  타이핑마다 큰 문서를 다시 그리면 그 지연이 편집기의 지연으로 느껴진다
  (EDITOR_LSP_SRS 비목표 8 과 같은 근거).
- **FR-DRV-44** 소스를 스크롤하면 **렌더가 그 자리를 따라간다** (Markdown).
  방향은 **소스 → 렌더 한쪽뿐이다** — 양쪽이 서로를 밀면 두 뷰가 마주 보고 튀는
  되먹임이 생기고, 그것을 막는 장치가 다시 이 기능만큼 커진다.

  매핑은 **렌더된 블록이 자기 줄 번호를 들고 있는 것**으로 한다. 비율로 맞추면
  코드 블록이나 표가 있는 문서에서 어긋나며, 어긋난 동기화는 없는 것보다 나쁘다.
- **FR-DRV-43** 다시 그려도 **스크롤 자리를 지킨다.** 한 글자를 고칠 때마다 문서
  처음으로 튀면 그것은 미리보기가 아니다.

### 3.5 묶음 E — 경계 (FR-DRV-20~29)

이 묶음이 이 SRS 의 무게중심이다. §2.3 의 벽에 문을 내는 일이기 때문이다.

- **FR-DRV-20** Markdown 렌더 결과는 **정화를 지난다.** `<script>`·`on*` 이벤트
  핸들러·`javascript:`·`data:text/html` URL 이 남지 않는다.
- **FR-DRV-21** 렌더러·정화기·하이라이터는 **우리 배포물에 담긴다** (`web/vendor/`, §2.11).
  CDN 에서 받지 않는다 — **정화기를 남의 서버에서 받아 오는 것은 그 서버가 우리
  화면의 보안을 정하게 하는 일이다.** Monaco 가 CDN 인 것은 그것이 편집기이기
  때문이고, 이것은 방어선이다.
- **FR-DRV-22** HTML 렌더의 iframe 은 `sandbox` 이며 **`allow-scripts` 도
  `allow-same-origin` 도 주지 않는다.** 그러므로 문서의 스크립트는 돌지 않고, 그
  프레임은 우리 출처의 쿠키·저장소에 닿지 못한다. **그 사실을 화면에 적는다** —
  적지 않으면 "왜 내 스크립트가 안 도는가" 가 우리 버그로 읽힌다.
- **FR-DRV-23** SVG 는 **`<img>` 로만** 그린다. 인라인 `<svg>` 로 넣지 않는다 —
  인라인은 그 안의 스크립트가 **우리 문서 컨텍스트에서** 돈다.
- **FR-DRV-24** `/api/file/raw` 가 SVG 를 내보내려면 셋을 함께 지킨다.

  **이것은 EDITOR_GIT_UX_SRS FR-EVW-5 를 그만큼 개정한다.**

  | | |
  |---|---|
  | 이전 동작 | `.svg` 는 415 였다 — 내보낼 길이 없었다 |
  | 새 동작 | 내용이 SVG 면 `image/svg+xml` 로 나간다 |
  | 이유 | Markdown 문서 **안에서** 참조된 `.svg` 이미지가 이 길로 와야 그려진다. 여는 대신 잠금장치를 함께 달았다 |

  개정의 **경계**도 재어 둔다: SVG 가 통과한다고 XML 이 통과하지는 않는다
  (`TestFileRawRefusesNonImage` 가 그 자리를 지킨다).

  1. **내용으로 SVG 임을 판정한다** — 확장자를 믿지 않는다 (FR-EVW-2 와 같은 근거).
  2. `Content-Type: image/svg+xml` 과 `X-Content-Type-Options: nosniff`.
  3. **`Content-Security-Policy: sandbox`** — 이 헤더가 없으면 사용자가 그 URL 을
     주소창에 직접 열었을 때 문서의 스크립트가 **우리 출처에서** 돈다. 그것이
     §2.3 이 막고 있던 바로 그 함정이며, 문을 내면서 잠금장치를 함께 다는 일이다.
- **FR-DRV-25** 문서 안의 **상대 이미지 참조**는 `/api/file/raw?path=<절대경로>` 로
  바뀐다. 경로는 그 문서의 디렉터리에서 푼다.
- **FR-DRV-26** 모든 경로는 **`fsRoot` 가드를 딛는다.** 루트 밖을 가리키는 참조는
  그리지 않는다. 가드를 새로 쓰지 않는다 — 두 벌이 되면 한쪽만 고쳐진다 (FR-EDT-108).
- **FR-DRV-27** **원격 이미지**(`http:`·`https:`)는 **그린다** (I-4). VS Code 와 같은
  어휘이며, 배지와 외부 다이어그램이 빈 자리로 남으면 사용자는 렌더가 깨진 것으로
  읽는다.

  **대가를 적어 둔다:** 그 문서를 여는 것만으로 그 서버들에 요청이 나가고, 우리 IP 와
  "지금 이 문서를 보고 있다" 가 알려진다. 사내 저장소의 README 를 여는 일이 배지
  서버에 기록되는 것이 그것이다. 사용자가 그 대가를 알고 고른 값이다.
- **FR-DRV-27b** 그리는 것은 **이미지뿐이다.** 원격 스크립트·스타일시트·폰트·프레임은
  렌더 결과에 남지 않는다 (FR-DRV-20 의 정화가 그것을 걷는다) — "외부 이미지를
  그린다" 가 "외부 코드를 실행한다" 로 넓어지지 않는다.
- **FR-DRV-28** 링크의 대상에 따라 다르게 움직인다.
  - 문서 안 앵커(`#heading`) → 렌더 뷰 안에서 스크롤
  - 저장소 안 상대 링크(`./other.md`) → **그 파일을 탭으로 연다** (`_edOpenFile`)
  - 외부 링크 → 새 창. `rel="noopener noreferrer"` 를 붙인다
- **FR-DRV-29** 상한이 있다: 파일 바이트, 표의 행·열 수. 넘으면 그리지 않고 그
  사실을 말한다 (FR-DRV-17).

### 3.6 묶음 F — 수명과 연속성 (FR-DRV-30~36)

- **FR-DRV-30** 렌더 탭은 **워크스페이스에 남는다.** 새로고침 뒤 되살아난다.
  `clean()` 이 그것을 버리지 않아야 한다 (§2.8).
- **FR-DRV-31** 렌더 뷰 인스턴스는 **(탭, 슬롯)마다**이며 `fileEditors` 의 복합키
  규약을 그대로 쓴다 (§2.6). 회수 루프를 두 벌로 만들지 않는다.
- **FR-DRV-32** 렌더 뷰는 `FileEditor` 와 **같은 뷰 계약**을 만족한다:
  `el` · `focus()` · `refresh()` · `destroy()` · `_dirty`(항상 거짓) ·
  `applyWordWrap()`(무동작). 근거는 `app-settings.js:231`·`app-layout.js:450`·
  `renderer.js:169` 이 `fileEditors` 의 값에 대고 이것들을 부르기 때문이다.
- **FR-DRV-33** 소스 탭을 닫아도 렌더 탭은 산다. 반대도 같다.
- **FR-DRV-34** 파일이 탐색기에서 옮겨지면 렌더 탭의 경로도 따라간다
  (`app-editor.js:804` 의 선례를 딛는다).
- **FR-DRV-35** 렌더 탭은 `dirty` 가 되지 않는다 — 저장할 것이 없다. 창을 닫을 때의
  확인(FR-WBR-40)에 걸리지 않아야 한다.
- **FR-DRV-36** 판(`?v=`)은 서버가 계산한다. 새 자산을 더해도 손으로 적는 값이 없다.

## 5. 확정 결정 (Decisions)

- **D-1 새 탭 타입을 만들지 않는다.** 렌더 탭은 `type:'editor'` 에 `render:true` 다.
  근거는 §2.8 이다 — 새 타입 하나의 값은 여섯 자리의 열거를 고치는 일이고, 그중
  `clean()` 을 빠뜨리면 **탭이 새로고침마다 조용히 사라진다.** 이미 있는 타입에
  기대면 저장·복원·회수·창 가드가 그대로 온다.
- **D-2 렌더는 디스크가 아니라 문서를 읽는다.** 저장을 강제하면 "결과를 보려면
  저장하라" 가 되어 요구를 이루지 못한다 (EDITOR_LSP_SRS D-3 과 같은 판단).
- **D-3 렌더는 브라우저의 일이다 — 서버가 HTML 을 만들지 않는다.**
  `go.mod` 에는 지금 의존이 둘뿐이고(`pty`·`websocket`) 마크다운 파서를 그 자리에
  더할 이유가 없다. 그리고 더 중요한 이유: **서버가 만든 HTML 은 우리가 신뢰하게
  된다.** 방어선이 브라우저 한 곳에 있어야 정화를 빠뜨린 경로가 생기지 않는다.
- **D-4 종류마다 그리는 법이 다르다.** Markdown 은 정화 후 DOM, SVG 는 `<img>`,
  HTML 은 sandbox iframe, 표는 우리가 만든다. **하나의 길로 통일하지 않는다** —
  통일하려면 가장 위험한 것(HTML)의 방식으로 나머지를 끌어와야 한다.
- **D-5 렌더러·정화기는 `vendor/` 에 담는다** (FR-DRV-21).
- **D-6 어휘를 겹치지 않는다.** '미리보기 탭' 은 이미 임시 탭의 뜻이다 (FR-RTU-40).
  이 기능은 **렌더 뷰**이며 코드의 필드도 `render` 다. `preview` 를 쓰면 두 개념이
  한 이름을 나눠 갖고, 그 뒤로는 어느 쪽 이야기인지 주석으로도 갈리지 않는다.
- **D-7 진입 버튼은 편집기 오버레이다** (FR-DRV-3). 탭바는 모든 타입이 지나는 자리다.
- **D-8 코드 블록은 `vendor/` 의 정적 하이라이터가 칠한다 — VS Code 와 같은 방식이다**
  (I-7). Monaco 의 `colorize` 를 빌리는 길도 있었고 그편이 소스와 색이 정확히 같아지는
  이점이 있었으나, 그 값으로 **렌더 경로 전체가 Monaco(CDN) 로드에 매인다.** 지금
  렌더는 브라우저 안에서 자족적이며 — 그래서 Monaco 가 못 떠도 문서는 보인다 — 그
  성질을 코드 블록의 색과 바꾸지 않는다.

  **대가는 문법 엔진이 둘이 되는 것이다.** 같은 코드가 소스 편집기와 렌더 뷰에서
  미묘하게 다른 색을 받을 수 있다. VS Code 도 같은 대가를 지고 있다(본체는 TextMate,
  미리보기는 번들 하이라이터). 그 차이를 줄이는 자리가 FR-DRV-13d 다 — 색을
  라이브러리의 기성 테마가 아니라 **우리 CSS 변수에서** 파생한다.
- **D-9 렌더는 언어 서버에 기대지 않는다** (§2.14). 이었다면 언어 서버가 없는
  기계에서 문서가 그려지지 않았을 것이고, 문서를 보는 일이 툴체인 설치를 전제하게
  된다. 그리고 애초에 언어 서버는 문서를 그려 주지 않는다.

## 6. 비목표 (Non-goals)

1. **렌더 뷰에서 편집하기**(WYSIWYG). 렌더는 읽는 화면이다 (FR-DRV-19).
2. Mermaid · 수식(KaTeX) · PlantUML. 각각이 자산 하나와 렌더 경로 하나를 더한다 —
   1차의 대상이 아니며, 표가 한 자리에 있으므로(FR-DRV-1) 나중에 더할 수 있다.
3. **HTML 문서의 스크립트 실행** (FR-DRV-22). 그것을 허용하는 순간 이 기능은
   저장소의 아무 파일이나 우리 화면에서 실행하는 길이 된다.
4. Jupyter 노트북 · PDF · 오피스 문서.
5. 인쇄·내보내기(PDF export).
6. 렌더 뷰 전용 찾기 패널. 브라우저의 것이 이미 그 자리를 쓴다.
7. Git diff 뷰의 렌더 — 그 뷰는 두 판의 텍스트이며 어느 쪽을 그릴지 정해지지 않았다
   (EDITOR_LSP_SRS 비목표 7 과 같은 근거).
8. 렌더 뷰의 **원격 데이터 가져오기** — 문서가 참조하는 외부 자원을 우리가 대신
   받아 오지 않는다.
9. **HTML 문서의 상대 스타일시트·스크립트·폰트.** 이미지만 우리 종단으로 옮긴다
   (FR-DRV-25). `raw` 는 이미지와 SVG 만 내보내며(FR-DRV-24), 거기에 CSS 를 더하는
   것은 방어선을 한 겹 더 여는 일이다 — 미리보기가 원본과 다르게 보이는 대가를
   받아들인다. 그 사실은 화면의 안내 줄이 말한다 (FR-DRV-22).

## 7. 마일스톤 (Milestones)

각 마일스톤은 **그 자체로 쓸 수 있는 상태**로 끝난다.

| M | 내용 | 끝났을 때 |
|---|---|---|
| **M1** | 묶음 A·B + Markdown (정화 · 코드 블록 색칠 포함) | `README.md` 에서 버튼을 누르면 옆 칸에 결과가 뜬다 — **요구의 본문** |
| **M2** | 묶음 D — 문서 구독·디바운스·스크롤 보존 | 고치는 대로 옆 칸이 따라온다 |
| **M3** | SVG — `<img>` 렌더 + `raw` 종단의 SVG 문(FR-DRV-24) | `icon.svg` 가 그림으로 보인다 |
| **M4** | HTML(sandbox iframe) · CSV/TSV(표) | 넷이 모두 그려진다 |
| **M5** | 링크 이동(FR-DRV-28) · 상한과 사유(FR-DRV-17·29) · 스크롤 동기화 | 문서 사이를 렌더 뷰에서 걸어 다닌다 |

**M1 이 접수한 요구의 본문이다.** Markdown 이 먼저인 것은 이 저장소에서 가장 자주
열리는 문서이고(`docs/internal/` 이 그 증거다), 정화 경로를 M1 에서 세우면 M3·M4 가
그 위에 선다.

**SVG 가 M3 인 것은 서버 종단을 건드리기 때문이다.** M1·M2 는 브라우저 안에서
끝나므로 서버 쪽 작업과 시간이 겹치지 않는다 — 다른 세션이 `internal/webserver` 를
만지고 있다면 그 순서가 충돌을 줄인다.
