## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

2026-11-11 대화의 요청 다섯 가지를 한 묶음으로 정한다.

1. **서브에이전트 보기**: 목록 보기로 고정하고 폴더 보기를 지운다.
2. **Explorer 다중 선택·단축키·내려받기**: 빈 여백을 끌어 사각형으로 고른다. 여러 항목을 고른 뒤의 우클릭 동작과 단축키는 선택 전체에 적용한다. 고른 항목을 Finder(데스크톱)로 끌어 놓으면 내려받는다.
3. **포커스 탭 하이라이트**: Repo 창의 Changes·Explorer 를 통틀어 하이라이트(선택)는 하나이고, 포커스된 탭을 따른다.
4. **Run 이슈 트리 미니맵**: 실제 트리를 줄여 보이고, 보기 상자를 끌어 옮긴다. 휠만으로 줌한다.
5. **실시간 갱신 누락**: 2026-11-11 전수 조사에서 찾은 항목 중 사용자가 고른 것을 고친다.

### 1.2 범위 (Scope)

- 포함: Activity 패널 서브에이전트 표시, Repo 창의 Explorer·Changes, Run 이슈 트리, 설정의 접속 허용 목록·샌드박스·노드 설정, Background 목록, Git 저장소 목록 배지, 짝의 마지막 응답 시각, LSP 상태 캐시.
- 비포함: §5.

### 1.3 정의 (Definitions)

| 용어 | 뜻 |
|---|---|
| **선택** | Explorer 의 `_sel`·`_selSet`, Changes 의 `_sel`. 행에 하이라이트로 보인다 |
| **포커스 탭** | Repo 창에서 포커스된 칸의 활성 탭. 파일 탭(`TAB_TYPE_EDITOR`) 또는 Diff 탭(`TAB_TYPE_GIT`, `gitView==='diff'`)이다 |
| **사각형 선택** | Explorer 의 빈 여백에서 누른 채 끌어 사각형을 그리고, 사각형과 겹친 행을 고르는 조작 |
| **보기 상자** | 미니맵 위에 지금 트리 영역이 보이는 범위를 그린 사각형 (`.run-tree-mini-view`) |
| **낡은 저장** | 패널을 연 뒤 다른 곳에서 바뀐 설정을, 그 사실을 모르는 패널이 통째로 덮어쓰는 저장 |

## 2. 현재 상태와 검증된 사실

### 2.1 서브에이전트 보기

- 보기는 폴더형(`tree`, 기본)과 목록형(`list`) 둘이다. 패널 머리의 `.ag-subview` 버튼으로 바꾸고 `localStorage.agentsSubView` 에 남긴다 (`web/js/core/app-agents-sub.js`, `app-agents.js`).
- 폴더형은 main 카드 아래에 하위 카드(`t:'sub'`)를 세우고, 접기 단추와 `sub:<도구 id>` 접힘을 쓴다.

### 2.2 Explorer 다중 선택

- Shift 클릭(범위)과 Cmd/Ctrl 클릭(토글)은 이미 있다 (`EXPLORER_MULTI_SELECT_SRS`, `ui/file-tree-paint.js`).
- 우클릭 메뉴에서 선택 전체에 적용되는 것은 삭제(`doDelete` → `_selTargets`)뿐이다. 다운로드·경로 복사·복사·잘라내기·복제는 우클릭한 행 하나다 (FR-M9-19 주석).
- 클립보드(`edClipSet`)는 경로 하나만 담는다.
- 행을 끌면 파일 옮기기가 시작된다. 선택된 행을 끌면 선택 전체가 옮겨진다 (`doMoveMany`). 빈 여백의 끌기는 아무 일도 하지 않는다.

### 2.2a Explorer 단축키와 바깥으로 끌기

- 단축키(`_onKey`, `ui/file-tree-paint.js`): Delete·Backspace(선택 전체 삭제), F2(이름 바꾸기), ⌘/Ctrl+C(**앵커 하나만** 복사), ⌘/Ctrl+V(붙여넣기), 화살표·Enter. 잘라내기·전체 선택·선택 풀기 키는 없다.
- 행을 끌면 `dataTransfer` 에 `text/plain` 과 트리 내부 형식만 싣고 `effectAllowed='move'` 다. 바깥(Finder)에 놓아도 아무 일도 없다.
- Chromium 계열 브라우저는 `DownloadURL`(`<mime>:<파일 이름>:<절대 URL>`) 을 실은 끌기를 OS 에 놓으면 그 URL 을 내려받는다. 파일은 하나만 실을 수 있다. Safari·Firefox 는 이 형식을 모른다.
- 서버: 파일은 `GET /api/fs/download`, 폴더는 `GET /api/fs/download-dir`(zip, 항목 수·바이트 상한, 동시 상한)이다. 여러 경로를 zip 하나로 주는 종단은 없다.

### 2.3 하이라이트

- 파일을 열면 Explorer 가 그 파일을 드러내고 고른다 (`revealPath`). 탭을 바꿀 때는 따라가지 않는다.
- Changes 의 선택은 Explorer 와 따로 산다. 두 패널에 동시에 하이라이트가 있을 수 있다.
- `app.render()` 는 화면을 그릴 때마다 `edWatchSync()` 를 부른다. 포커스 탭이 바뀌면 이 길을 지난다.

### 2.4 Run 이슈 트리 미니맵

- 미니맵은 노드 위치를 같은 색의 사각형(`--border-strong`)으로만 그린다. 간선과 상태 색이 없다. 그 위의 보기 상자는 반투명 채움이다 (`ui/run-tree.js` `_runTreeHud`, `style-runs.css`).
- 미니맵을 누르거나 끌면 누른 점이 화면 중심이 되도록 옮긴다. 보기 상자를 잡아 끄는 동작은 없다.
- 줌은 ⌘/Ctrl + 휠이다. 수식키 없는 휠은 Run 화면을 스크롤한다 (FR-ITC-13).
- 트리 영역은 Run 화면 높이의 50% 로 고정이다.

### 2.5 실시간 갱신 누락 (전수 조사 결과에서 사용자가 고른 것)

| 표면 | 사실 |
|---|---|
| 접속 허용 목록 | 저장이 `access_changed` 를 방송하지만 구독하는 곳이 없다. 열린 패널은 낡는다. `PUT /api/access` 는 전체 교체이고 버전 검사가 없다 |
| 샌드박스 정의 | `PUT /api/sandbox/config` 는 방송하지 않는다. 전체 교체이고 버전 검사가 없다 |
| 짝 노드 설정 폼 | `peers_changed` 는 목록만 다시 그리고 폼(`_pnNodePaint`)은 그리지 않는다. `PUT /api/peers/node` 는 전체 교체다 |
| Background 목록 | 행의 Run 표지와 cwd 는 조회 때 계산한다. 다시 받는 계기는 `tools_background_changed` 와 패널 열기뿐이다 |
| Git 저장소 목록 배지 | Repo 탭이 보이지 않으면 `gitStatusInterval`(기본 30초)마다만 다시 받는다 |

| LSP 상태 캐시 | 세션 동안 남고 설치할 때만 버린다. 다른 탭·터미널의 설치·삭제를 모른다 |

## 3. 요구사항 (Requirements)

### 3.1 서브에이전트 목록 (FR-SVL)

- **FR-SVL-1** 서브에이전트는 언제나 main 카드 안의 목록(FR-ASV-34)으로 그린다.
- **FR-SVL-2** 폴더형 하위 카드, 패널 머리의 보기 전환 버튼, 폴더 접기 단추, 접힘 키 `sub:<도구 id>` 를 지운다.
- **FR-SVL-3** `localStorage.agentsSubView` 를 읽지 않는다. 남아 있는 값은 지운다.

### 3.2 Explorer 다중 선택 (FR-EXM)

- **FR-EXM-1** 목록의 빈 여백(행이 아닌 곳)에서 왼쪽 버튼을 누른 채 끌면 사각형을 그린다. 사각형과 세로로 겹친 행이 선택이 된다.
  - 수식키가 없으면 선택을 사각형의 행으로 바꾼다.
  - Cmd/Ctrl 이나 Shift 를 누른 채 시작하면 시작 때의 선택에 더한다.
  - 끌다가 포인터가 목록 위·아래 끝 24px 안이나 그 밖에 있으면 프레임마다 12px 씩 그쪽으로 목록을 스크롤한다. 사각형의 시작점은 목록 내용에 붙어 있으므로 스크롤해도 따라간다.
  - 4px 미만으로 움직이고 놓으면 끌기가 아니다. 지금의 빈 여백 클릭과 같다(루트를 고른다, FR-EXR-1).
  - 끌기로 끝난 뒤 따라오는 클릭은 빈 여백 클릭으로 읽지 않는다.
  - 앵커(`_sel`)는 사각형에 든 행 중 포인터 쪽 끝의 행이다. 든 행이 없으면 수식키 없는 끌기는 선택을 비운다.
  - 사각형은 목록 위에 테두리 상자(`.ed-marquee`)로 그리고, 놓으면 지운다.
- **FR-EXM-2** 행에서 시작한 끌기는 지금과 같다(파일 옮기기, FR-EMS-24).
- **FR-EXM-3** 우클릭한 행이 선택 안에 있으면 아래 동작은 **선택 전체**(`_selTargets`)에 적용한다.

  | 동작 | 여러 항목일 때 |
  |---|---|
  | 다운로드 | zip 하나로 내려받는다 (FR-EXD-7). 항목이 하나면 지금과 같다 |
  | 절대 경로 복사 · 상대 경로 복사 | 경로를 화면 순서대로 줄바꿈으로 이어 한 번에 복사한다 |
  | 복사 · 잘라내기 | 클립보드가 경로 목록을 담는다. 붙여넣기는 항목마다 한다 |
  | 복제 | 항목마다 제 자리의 형제로 복제한다 |
  | 삭제 | 지금과 같다 |

- **FR-EXM-4** 이름 바꾸기·새 파일·새 폴더·업로드는 대상이 하나다. 선택이 둘 이상이면 이름 바꾸기는 비활성이다. 나머지 셋은 우클릭한 행이 정하는 자리를 그대로 쓴다.
- **FR-EXM-5** 동작 가능 여부를 서버에 묻는 범위(`edFsActions`)는 선택 전체다. 하나라도 할 수 없으면 그 동작은 비활성이고 사유를 보인다.
  - 서버 `POST /api/fs/actions` 는 `fs.move`·`fs.copy` 를 `paths` 전부로 판정한다(첫 거절이 답이다). `fs.rename` 은 지금처럼 `paths[0]` 하나다. `fs.delete` 는 지금도 전부다.
  - 이전 동작: `fs.move`·`fs.copy` 가 `paths[0]` 만 봤다. 새 동작: 전부를 본다. 이유: 여러 항목의 복사·잘라내기가 선택 전체에 적용되므로(FR-EXM-3) 판정 범위도 같아야 한다.
- **FR-EXM-6** 붙여넣기에서 일부가 실패하면 성공한 것은 남기고, 실패한 항목마다 사유를 그 자리에 붙인다(FR-EDT-92). 잘라내기는 모두 성공했을 때만 클립보드를 비운다. 일부가 실패하면 클립보드에는 실패한 항목만 남는다(옮겨진 원본은 이미 없으므로 다시 붙이면 "사라졌다" 로 실패한다).
- **FR-EXM-7** 클립보드(`edClipSet`·`edClipGet`)는 `{root, paths, move}` 를 담는다. `paths` 는 받은 순서를 지킨 경로 목록이다.
  - `edClipSet(root, paths, move)` 의 `paths` 는 목록이나 경로 하나(문자열)다. 문자열은 항목 하나의 목록으로 바꾼다.
  - 빈 값을 걸러 낸 목록이 비거나 `root` 가 없으면 클립보드를 비운다(`null`).
  - 붙여넣기는 `paths` 를 차례대로 하나씩 보낸다(복사는 서버가 이름을 정하므로 순서가 결과 이름을 정한다). 끝나면 성공한 항목 전부를 선택으로 한다.
  - 복제는 사용자의 클립보드를 바꾸지 않는다. 복제 뒤 클립보드는 `paths`·`move` 까지 복제 전과 같다(R4-6).

### 3.2a Explorer 단축키 (FR-EXK)

- **FR-EXK-1** 단축키는 Explorer 목록에 포커스가 있을 때만 받는다. 인라인 입력과 머리 버튼의 키는 그쪽 것이다(FR-EXR-55·57). 처리한 키만 삼킨다(FR-EXR-56).
- **FR-EXK-2** ⌘/Ctrl+C 는 선택 전체를 복사한다. ⌘/Ctrl+X 는 선택 전체를 잘라낸다. 둘 다 클립보드(FR-EXM-3)에 경로 목록을 담는다.
- **FR-EXK-3** ⌘/Ctrl+V 는 지금처럼 붙여넣는다. 자리는 `_targetDir()` 이다.
- **FR-EXK-4** Delete·Backspace 와 ⌘+Backspace(macOS 관용)는 선택 전체를 지운다. 확인은 `doDelete` 가 든다.
- **FR-EXK-5** ⌘/Ctrl+A 는 지금 보이는 행 전부(펼친 폴더의 하위 포함, 루트 제외)를 고른다. Escape 는 선택을 앵커 하나로 줄인다.
- **FR-EXK-6** 루트만 고른 상태에서는 복사·잘라내기·삭제 키가 아무 일도 하지 않는다(FR-EXR-54).

### 3.2b Finder 로 끌어 내려받기 (FR-EXD)

- **FR-EXD-1** 행 끌기를 시작할 때 `DownloadURL` 을 함께 싣는다. 트리 안의 옮기기(FR-EXM-2)는 그대로다.
- **FR-EXD-2** 끄는 대상이 파일 하나면 그 파일의 `GET /api/fs/download` URL 과 파일 이름을 싣는다. 폴더 하나면 `GET /api/fs/download-dir` 과 `<이름>.zip` 이다.
- **FR-EXD-3** 끄는 대상이 둘 이상(선택된 행을 끈 경우, FR-EMS-24)이면 새 종단 `GET /api/fs/download-many?root=<루트>&path=<경로>&path=<경로>…` 의 URL 과 `<루트 이름>-<n>-items.zip` 을 싣는다.
- **FR-EXD-4** `download-many` 는 각 경로를 zip 의 맨 위에 그 이름으로 담는다(폴더는 하위 포함, 뿌리 폴더 자신의 엔트리는 `download-dir` 처럼 넣지 않는다). 링크·읽을 수 없는 항목은 `download-dir` 과 같은 규칙으로 건너뛴다(FR-ETR-14·15). 항목 수·바이트 상한과 동시 상한은 경로 전체의 합으로 `download-dir` 과 같은 값을 쓴다. 경로가 루트 밖이거나 없으면 헤더를 쓰기 전에 거절한다. 경로가 없거나 같은 이름이 둘이면 400 이다.
- **FR-EXD-5** 링크 행을 끌면 `DownloadURL` 을 싣지 않는다(FR-ETR-16).
- **FR-EXD-6** `DownloadURL` 을 모르는 브라우저(Safari·Firefox)에서는 바깥에 놓아도 아무 일도 없다. 트리 안 옮기기는 같다.
- **FR-EXD-7** 우클릭 메뉴의 다운로드(FR-EXM-3)도 여러 항목이면 같은 `download-many` zip 하나로 내려받는다.

### 3.3 포커스 탭 하이라이트 (FR-FHL)

- **FR-FHL-1** Repo 창에서 하이라이트는 Changes 와 Explorer 를 통틀어 하나다.
- **FR-FHL-2** 포커스 탭이 파일 탭으로 바뀌면 Explorer 의 선택을 그 파일 하나로 바꾼다. 접힌 폴더 안이면 조상 폴더를 펼치고 행이 보이게 스크롤한다. Changes 의 선택은 지운다.
- **FR-FHL-3** 포커스 탭이 Diff 탭으로 바뀌면 Changes 의 선택을 그 Diff 의 대상 행 하나로 바꾼다. Explorer 의 선택은 지운다.
- **FR-FHL-4** Diff 탭이 보는 대상이 바뀌면(‹ › 이동, 다른 행 클릭) FR-FHL-3 을 다시 적용한다. 이때 Changes 의 선택은 그 이동이 정한 것(‹ › 는 대상 하나, Cmd·Shift 클릭은 사용자가 고른 것)을 그대로 두고, Explorer 의 선택만 지운다(FR-FHL-6 과 함께 지키기 위해서다).
- **FR-FHL-5** Changes·Explorer 사이드 탭은 자동으로 바꾸지 않는다. 보이지 않는 쪽의 선택도 위 규칙대로 바뀐다.
- **FR-FHL-6** 포커스 탭이 바뀌지 않으면 아무것도 하지 않는다. 사용자가 패널에서 고른 선택(Shift·Cmd·사각형)은 다음 탭 전환까지 그대로다.
- **FR-FHL-7** 포커스 탭이 파일·Diff 가 아니거나, 그 파일이 이 창의 루트 밖이면 두 패널의 선택을 바꾸지 않는다.
- **FR-FHL-8** Activity 패널의 에이전트 카드 하이라이트는 하나다. 포커스된 탭(어느 창이든 포커스 칸의 활성 탭)의 도구가 에이전트 카드를 가지면 그 카드 하나만 하이라이트하고, 없으면 어느 카드도 하이라이트하지 않는다. 포커스 탭이 바뀌면 곧바로 따라간다.
  - 포커스 탭은 포커스된 칸(슬롯)이 보는 창의 포커스 pane 의 활성 탭 하나다.
  - 확인 결과: 지금 `.ag-card.focused` 는 `_isToolFocusedActive` 로 정한다. 이 판정은 "같은 창을 보는 칸 중 어디서든 보이는가"(FR-SVS-13, 알람 억제용)라서 같은 창을 두 칸에 띄우면 두 칸의 활성 탭 카드가 모두 켜진다. 칸이 하나면 이미 요구와 같다.
  - 카드 하이라이트는 새 판정(포커스 칸의 탭 하나)을 쓴다. 알람 억제의 판정은 바꾸지 않는다.
  - 이전 동작: 같은 창을 두 칸에 띄우면 카드가 둘까지 켜졌다. 새 동작: 포커스 칸의 카드 하나만 켜진다. 이유: 사용자 요구(R17).

### 3.4 Run 이슈 트리 미니맵 (FR-RMM)

- **FR-RMM-1** 미니맵은 트리를 줄여 그린다. 노드는 작은 상자로, 간선은 선으로 그리고, 노드 상자는 그 노드의 상태 색(본 트리의 상태 클래스)을 따른다.
- **FR-RMM-2** 보기 상자는 테두리만 그린다. 노드를 가리지 않는다.
- **FR-RMM-3** 보기 상자 안을 누른 채 끌면 누른 점과 상자의 거리를 지키며 보기를 옮긴다. 상자 밖을 누르면 그 점이 중심이 되도록 옮기고, 이어서 끌면 따라온다.
- **FR-RMM-4** 미니맵은 트리가 다시 그려질 때(상태 변화·노드 추가)와 보기가 바뀔 때(줌·패닝·맞춤) 곧바로 따라간다.
- **FR-RMM-5** 트리 영역 위의 휠은 수식키 없이 줌한다(FR-ITC-13 개정). 줌의 중심은 커서다. 이 휠은 Run 화면을 스크롤하지 않는다.
- **FR-RMM-6** 트리 영역 밖의 휠은 지금처럼 Run 화면을 스크롤한다.

### 3.5 실시간 갱신 (FR-LIV)

**설정 패널**

- **FR-LIV-1** `GET /api/access`·`GET /api/sandbox/config`·`GET /api/peers` 는 응답 헤더 `ETag` 에 지금 설정의 지문을 싣는다. 지문은 저장된 설정 본문의 해시다.
- **FR-LIV-2** 같은 종단의 `PUT`(`/api/access`·`/api/sandbox/config`·`/api/peers/node`)이 `If-Match` 를 실었는데 지금 지문과 다르면 409 `stale_rev` 로 거절하고 아무것도 바꾸지 않는다. `If-Match` 가 없으면 지금처럼 저장한다(`dmctl`·옛 클라이언트).
- **FR-LIV-3** 샌드박스 저장은 성공 뒤에 `sandbox_changed` 를 방송한다.
- **FR-LIV-4** 브라우저는 `access_changed`·`sandbox_changed`·`peers_changed` 를 받으면 그 패널이 열려 있을 때 다음을 한다.
  - 저장하지 않은 수정이 없으면 다시 읽어 그린다.
  - 수정이 있으면 덮지 않고 "다른 곳에서 바뀌었습니다" 알림과 다시 불러오기 단추를 그 패널에 보인다.
- **FR-LIV-5** 패널은 읽을 때 받은 `ETag` 를 저장 때 `If-Match` 로 싣는다. 409 를 받으면 FR-LIV-4 의 알림을 보이고 저장하지 않는다.
- **FR-LIV-6** "저장하지 않은 수정"은 지금 폼의 값(`_aclCollect`·`_sbxCollect`·`_pnNodeCollect`)이 마지막으로 읽은 값과 다른 것이다.

**목록·상태**

- **FR-LIV-7** Activity 패널이 열려 있는 동안 Background 목록을 활동 주기(`agentsPollMs`)마다 다시 받는다. 상태 등록부의 `tool.background` 에 `every`·`when` 을 더한다.
- **FR-LIV-8** Git 저장소 목록은 서버의 git 변화 알림(`git_changed`)을 받으면 Repo 탭이 보이지 않아도 다시 받는다. 겹친 알림은 합친다.
- **FR-LIV-9** 짝에게서 인증된 호출을 받으면 그 짝의 마지막 응답 시각을 갱신한다. 마지막 응답 시각의 갱신은 짝마다 60초에 한 번만 `peers_changed` 를 방송한다.
- **FR-LIV-10** LSP 상태 캐시는 60초가 지나면 낡은 것으로 보고 다음에 쓸 때 다시 읽는다. 설치 때 버리는 것은 그대로다.

### 3.5a Activity 패널 접기 (FR-ACF)

이 절은 데스크톱 레이아웃(`body:not(.mobile)`)에 적용한다. 모바일은 FR-ACF-10 을 따른다.

- **FR-ACF-1** 데스크톱에서 Activity 패널의 상태는 둘이다: **펼침**(`#agents-panel.open`, 지금의 열린 패널)과 **레일**(`.open` 이 없음). 패널을 완전히 숨기는 상태는 없다.
- **FR-ACF-2** 레일의 폭은 사이드바 레일과 같다(`--sb-rail-w`). 레일의 폭은 끌어도 바뀌지 않는다. 펼침 폭(`--ag-w`)은 레일을 거쳐도 그대로 남는다.
- **FR-ACF-3** 레일은 펼침과 같은 DOM 을 쓴다(FR-RAL-4 와 같은 규약). 레일에서 보이는 것은 다음과 같다.
  - 구역 머리: 구역 아이콘(Agents `terminal`, Background `archive`, Runs `play`)과 항목 수 배지. 구역 이름·접기 꺽쇠·구역 동작은 숨긴다.
  - 에이전트 카드: 도구 이름(`.ag-loc`)을 두 줄까지. 넘치면 둘째 줄 끝에 `…`. 알람(`.attn`)과 포커스(`.focused`) 표시는 그대로다. 상태·detail·사용률·서브에이전트 줄은 숨긴다.
  - Background 행: 도구 이름(`.bg-name`)을 두 줄까지. 나머지는 숨긴다.
  - Run 행: 짧은 id(`.runs-short`)를 두 줄까지. 나머지는 숨긴다.
  - 창 그룹 머리: 이름·꺽쇠·알람 수를 숨기고 구분선만 남긴다. 그룹의 접힘은 레일에도 그대로 적용한다.
  - 숨기는 것: 패널 머리의 제목·새로고침, 빈 구역 안내, Usage 바닥.
  - 각 항목의 `title` 은 그대로다. 레일에서 잘린 이름을 끝까지 볼 수 있는 길이다.
- **FR-ACF-4** 레일에서 구역 머리를 누르면 패널을 펼치고 그 구역으로 간다(`actPanelOpen(key)` 와 같다. 구역이 접혀 있으면 편다). 레일의 카드·행을 누르면 펼침과 같은 일을 한다(카드는 그 도구로 이동, Background 행은 복귀, Run 행은 Run 열기). 패널은 펼치지 않는다.
- **FR-ACF-5** 패널 머리의 닫기 단추(`.ag-close`)는 접기 단추(`.ag-collapse`, 툴팁 `Collapse the panel`)가 된다. 누르면 레일이 된다. 레일에서 이 단추는 펼치기 단추(툴팁 `Expand the panel`)이고 누르면 펼친다.
- **FR-ACF-6** 경계 손잡이(`#agents-handle`)는 레일에서도 보인다. 손잡이를 끌어 패널 폭이 `AGENTS_COLLAPSE_AT_PX`(70px) 아래가 되면 레일이 된다. 레일에서 끌어 그 값 이상이 되면 펼친다. 사이드바 손잡이(FR-SBC-7)와 같은 규약이다.
- **FR-ACF-7** 상단바의 Activity 단추(`#agents-toggle`)를 지운다. 단축키 `agentsToggle`(Ctrl+Shift+A)는 펼침과 레일을 오간다. `runsToggle`·`bgToggle` 은 지금처럼 그 구역으로 펼치고, 같은 구역을 다시 부르면 레일이 된다.
- **FR-ACF-8** 레일 상태는 지금의 "닫힘" 값으로 저장한다. 탭 상태 `agentsPanelOpen`(sessionStorage)과 저장 레이아웃 `activity.open` 의 모양은 바뀌지 않는다. `false` 는 데스크톱에서 레일을 뜻한다. 레이아웃 저장(FR-PLY-11)은 레일이면 `open:false` 를, 펼침이면 `open:true` 를 담는다. 그 레이아웃으로 시작한 새 탭은 같은 상태로 선다. 기본값(값 없음)은 레일이다.
- **FR-ACF-9** 레일도 화면에 목록을 보이므로 Activity 의 주기 조회(`tool.activity`·`run.list`·`tool.background` 의 `when`)와 그리기(`agentsRender`)는 패널이 **보이는 동안** 돈다. 보이는 동안이란 데스크톱이거나 `.open` 인 것이다.
- **FR-ACF-10** 모바일은 바뀌지 않는다. `.open` 이 없으면 패널은 숨는다. 서랍의 Activity 단추(`#m-drawer-acts`)가 여는 길이다.
- **FR-ACF-11** Activity 가 오른쪽·왼쪽 어디에 있든(PANEL_DOCK_SRS) 레일의 경계선은 콘텐츠 쪽 면에 선다.

### 3.5b 사이드바 액션 단추 (FR-SBA)

- **FR-SBA-1** Windows 패널의 그룹 추가 단추(`#add-group`)는 `#add-window`·`#add-preset` 과 같은 규칙(좌우 여백 8px, 테두리, 높이, hover, 모바일 터치 높이)을 쓴다.
  - 확인 결과: `#add-group` 만 그 규칙의 선택자 목록에서 빠져 있어 패널 폭을 꽉 채웠다.

### 3.5c 포커스를 옮기면 알람을 끈다 (FR-AFC)

- **FR-AFC-1** 포커스 탭(FR-FHL-8 의 정의: 포커스 칸이 보는 창의 포커스 pane 의 활성 탭)의 도구가 **다른 도구에서 그 도구로 바뀌고**, 그 도구에 알람이 있으면 알람을 끈다. 이 해제는 "본 것" 이다(`typed=false`, FR-ATA-9 의 재무장 잠금이 선다).
  - 이 규칙에 드는 길(사용자 원문): Activity 의 에이전트 카드 선택, 탭 바에서 알람 탭 선택, Repo 창에 갔다가 Windows 창으로 돌아오기, 칸 포커스 옮기기 등. 포커스 탭이 바뀌는 길은 모두 `App.render` 를 지나므로 판정은 거기 하나다.
- **FR-AFC-2** 포커스 탭의 도구가 바뀌지 않으면 아무것도 하지 않는다. 그래서 다음은 알람을 끄지 않는다(FR-ATA-1 이 막은 것 그대로다).
  - 브라우저 창이 OS 포커스를 다시 얻는 것
  - 새로고침·부팅 뒤 첫 그리기 (그 전의 포커스 탭을 모른다)
  - 이미 포커스된 탭에 알람이 새로 서는 것. 그 알람은 지금처럼 그 탭 화면을 누르거나 키를 눌러야 꺼진다(FR-ATA-3~5)
- 이전 동작: 포커스 이동은 알람을 끄지 않았다(FR-ATA-1). 카드·알림 센터 클릭(`jumpToTool`, FR-ATA-6)만 직접 껐다. 새 동작: 포커스 탭이 다른 탭에서 알람 탭으로 바뀌면 끈다. 이유: 사용자 요구(R21) — 탭을 옮겨 그 화면을 보고 있는데 한 번 더 눌러야 꺼지는 것은 군더더기다.

### 3.5d 그룹 머리의 삼각형 (FR-RGT)

- 확인 결과: 그룹 머리의 접기 삼각형은 `.sbl-dot` 을 폭 0 으로 두고 테두리로 그린다. 점에 배경을 주는 규칙 둘이 그룹 머리에도 닿아 삼각형 자리가 파란·회색 사각형이 됐다. 글자 선택은 아니다.
  - 레일: "배지가 있으면 점을 강조색으로"(FR-RAL-7). 그룹 머리는 창 수 배지를 가진다.
  - 펼침: 알람 점(`.sbl-item.attn .sbl-dot` 과 그 `::before`). 알람 갱신(`_attnRefresh`)은 `data-sid` 로 행을 찾아 그룹 머리의 `.attn` 을 늘 껐고, 전체 다시 그리기는 켰다. 그래서 "가끔" 보였다.
- **FR-RGT-1** 그룹 머리의 점(삼각형)은 배지·알람 때문에 칠하지 않는다. 그룹의 알람은 행의 왼쪽 띠가 말한다.
- **FR-RGT-2** 알람 갱신은 그룹 머리의 `.attn` 을 그 그룹 안 창들로 판정한다(`groupHasAttn`, 다시 그리기와 같은 판정).
- 이전 동작: 그룹 머리의 알람 표시가 다시 그리기 때만 켜지고 알람 갱신 때 꺼졌다. 새 동작: 언제나 그 그룹의 창에 알람이 있는지를 따른다. 이유: 같은 사실을 두 길이 다르게 그리고 있었다.

### 3.5e 편집기 검색 색 (FR-EFC)

색은 모두 테마 강조색(`--accent`)에서 만든다(사용자 결정 2026-11-11).

- **FR-EFC-1** 현재(포커스) 일치(`.fe-find-hit-cur`)의 배경은 강조색 45%이고, 안쪽 1px 강조색 테두리를 가진다. 글자색은 바꾸지 않는다.
- **FR-EFC-2** 다른 일치(`.fe-find-hit`)의 배경은 강조색 25%다.
- **FR-EFC-3** 선택한 것과 같은 단어(`.cm-selectionMatch`)는 배경이 없고, 안쪽 1px 강조색 테두리를 가진다.
- 이전 동작: 현재 일치는 강조색 100% 배경 + 밝은 글자색 테두리, 다른 일치는 강조색 12%, 같은 단어는 강조색 20%. 새 동작: 위 셋. 이유: 강조색이 밝은 테마(Cobalt² `#ffc600`)에서 현재 일치의 흰 글자가 묻혔고, 다른 일치가 같은 단어보다 흐렸다(사용자 보고).

### 3.5f Repo 창의 탭 — 칸마다 미리보기 (FR-RTB)

사용자 결정(2026-11-11 질의응답). 원칙: **칸은 서로 영향을 주지 않는다.** 한 칸에서 고른 결과는 그 칸에만 선다. 여기서 "칸" 은 Repo 창 안의 분할 pane 이고, "지금 칸" 은 그 창의 포커스 pane 이다.

**미리보기와 고정**

- **FR-RTB-1** 미리보기 탭(`tab.preview`)은 칸마다 최대 하나다. 종류(편집기·Diff)는 가리지 않는다.
- **FR-RTB-2** 미리보기를 여는 요청은 **지금 칸**에 연다. 지금 칸에 미리보기 탭이 있으면 그 탭의 대상(과 종류)을 갈아 끼우고, 없으면 새 미리보기 탭을 만든다. 다른 칸의 미리보기 탭은 건드리지 않는다.
- **FR-RTB-3** 미리보기를 여는 길: Explorer 파일 한 번 클릭(편집기), Changes 행 한 번 클릭(추적 파일은 Diff, untracked 는 편집기, FR-RTU-50·51), History 의 파일 클릭(Diff). 보조키 클릭은 지금처럼 열지 않는다(FR-RTU-40).
- **FR-RTB-4** 지금 칸에 같은 대상의 탭(미리보기든 고정이든)이 있으면 새로 만들지 않고 그 탭을 활성으로 한다. 같은 대상이 **다른 칸에만** 있으면 지금 칸에 미리보기로 연다(FR-RTU-45 개정).
- **FR-RTB-5** 고정하면 그 탭은 보통 탭이 된다(기울임이 풀린다). 그 칸의 다음 미리보기는 새 탭으로 생긴다.
- **FR-RTB-6** 고정 계기는 다섯이다(편집기·Diff 공통).
  1. 미리보기 탭(이름) 더블클릭
  2. Explorer 파일 행 더블클릭 (그 파일의 편집기 탭)
  3. Changes 파일 행 더블클릭 (그 파일의 Diff 탭. untracked 는 편집기 탭) — D-RTU-23 의 "두 번 클릭 제거" 를 개정한다
  4. 미리보기 탭에서 수정 시작 (Diff 는 수정 가능한 오른쪽, FR-RTU-50)
  5. 미리보기 탭에서 저장(`Cmd+S`/`Ctrl+S`)
  - 본문 더블클릭은 고정하지 않는다(낱말 선택으로 남는다).

**Diff 탭**

- **FR-RTB-7** Diff 탭은 창에 하나가 아니다(FR-RTU-31 에서 Diff 를 뺀다). Diff 탭의 대상은 (저장소 루트, 경로, 축)이다. 축은 unstaged·staged·conflict·커밋(해시)이다. FR-RTB-4 의 "같은 대상" 은 이 셋이 같은 것이다.
- **FR-RTB-8** Diff 탭의 이름은 대상 파일명이다(FR-RTU-41). 미리보기면 기울임이다.
- **FR-RTB-9** Diff 탭의 ‹ › 이동: 미리보기 Diff 에서는 그 탭의 대상을 바꾼다. 고정 Diff 에서는 그 탭을 그대로 두고, 이전·다음 파일을 같은 칸의 미리보기 Diff 로 연다(FR-RTB-2). (사용자 결정 2026-11-11)
- **FR-RTB-10** Diff 탭의 수정 가능한 오른쪽(워킹 트리 파일)은 편집기 탭과 같이 동작한다: 수정·저장(FR-RTU-52·53), 정의로 이동(수정키+클릭, LSP), 링크, LSP hover. 읽기 전용 축(staged·커밋·삭제)은 지금처럼 읽기 전용이다. 왼쪽(원본)은 읽기 전용이다.

**유지·연동**

- **FR-RTB-11** History·Branches·Stash·Console·Worktrees 탭은 지금처럼 창마다 하나이고, 있으면 그 탭(다른 칸이어도)으로 간다(FR-RTU-31).
- **FR-RTB-12** 포커스 탭 하이라이트(FR-FHL-1~7)는 미리보기·고정을 가리지 않고 포커스된 탭 하나를 따른다. Diff 이면 **포커스된 Diff 탭의 대상** 행을 Changes 에 하나 고른다(Diff 탭이 여럿이므로 패널 하나의 대상이 아니라 탭의 대상을 읽는다).
- **FR-RTB-13** 미리보기 상태는 Diff 탭도 워크스페이스에 저장한다(FR-RTU-44). Diff 탭의 대상도 저장해 새로고침 뒤 같은 대상으로 되살린다.
- **FR-RTB-14** 저장하지 않은 수정이 있는 미리보기 탭은 대체되지 않는다 — 수정 시작이 이미 고정했기 때문이다(FR-RTB-6 ④). 그래서 미리보기 대체가 수정을 버리는 경우는 없다.

- 결함 수정(FR-RTB-6 ④, 묶음 1에서 발견): 이전 동작 — 미리보기 탭에서 입력해도 고정되지 않았다. 문서의 dirty 를 버퍼 구독이 편집기 갱신보다 먼저 바꿔 두어, 편집기의 "dirty 가 막 켜졌다" 판정이 늘 거짓이었다(시험이 없었다). 새 동작 — 이 칸에서 친 변경(REMOTE·FLUSH 아님)이면 고정한다. 다른 칸이 보낸 변경은 고정 계기가 아니다. 이유 — FR-RTB-6 ④.
- 구현 메모(묶음 2): Diff 탭은 탭마다 전용 GitPanel 을 갖는다(관측기는 저장소마다 하나를 함께 쓰므로 요청은 늘지 않는다). 대상은 `tab.diffTarget` 에 실려 워크스페이스에 남는다. Diff 의 고정 계기 ④(수정 시작)는 **포커스가 그 Diff 안에 있을 때** 문서가 dirty 가 되는 것으로 잰다 — 문서의 dirty 는 같은 파일의 편집기 탭에서 쳐도 Diff 에 알려지기 때문이다. FR-RTB-14 는 대체 직전에 한 번 더 지킨다: 갈아 끼울 미리보기 탭이 dirty 면(다른 탭에서 친 수정) 그 탭을 고정하고 새 미리보기를 세운다(편집기·Diff 공통). 그래서 REPO_FIX 05 §3A-3 F-2.4 의 "마지막 뷰가 dirty 면 전환 전에 묻는다" 는 Repo 창에서 일어나지 않는다(옛 Git 창에는 남는다). Diff 탭 패널은 원격 작업 표시를 갖지 않는다(`adoptJobs` 에서 뺀다).
- 이전 동작: 미리보기 탭은 창에 하나였고, 다른 칸에서 클릭해도 그 탭이 있는 칸이 바뀌고 포커스가 그리로 갔다. Diff 탭은 창에 하나였고 고정할 수 없었다. 다른 칸에 열린 고정 탭을 고르면 그 칸으로 갔다. Diff 오른쪽에서는 정의로 이동이 되지 않았다. 새 동작: 위 FR-RTB. 이유: 사용자 요구(R19) — 칸을 독립된 작업 공간으로 쓰고, Diff 도 편집기와 같은 규칙으로 다룬다.

### 3.5g 닫은 탭 다시 열기 · 뒤로·앞으로 (FR-RTR)

사용자 결정(2026-11-11 질의응답). 용어: "기록" 은 뒤로·앞으로가 오가는 자리의 목록이다(M9_SRS FR-M9-24 의 `_navBack`·`_navFwd`). "닫은 탭 목록" 은 이 절이 새로 두는 목록이다.

**닫은 탭 다시 열기**

- **FR-RTR-1** 대상은 Repo 창의 탭 전부다 — 편집기 탭, Diff 탭(대상 포함, FR-RTB-7), git 뷰 탭(History·Branches·Stash·Console·Worktrees). 터미널 탭과 Run 탭은 대상이 아니다(터미널은 프로세스가 끝나 같은 것을 되살릴 수 없다).
- **FR-RTR-2** 대상 탭을 닫으면 닫은 탭 목록의 맨 위에 넣는다. 넣는 것: 창 id, 칸 id, 칸 안의 위치, 탭 레코드(id 를 뺀 내용), 편집기·Diff 의 커서와 스크롤. 목록의 길이는 상수 하나로 묶는다. 목록은 브라우저 메모리에만 있고 새로고침을 넘지 않는다.
- **FR-RTR-3** 액션 `tabReopen` 은 닫은 탭 목록의 맨 위 하나를 다시 연다. 기본 단축키는 `Ctrl+Shift+KeyU` 다(브라우저·편집기 기본 키와 겹치지 않는다. 사용자 결정: "브라우저랑 안겹치는걸로"). 설정에서 바꿀 수 있다.
- **FR-RTR-4** 다시 여는 자리: 그 칸이 있으면 그 칸의 원래 위치, 칸이 없으면 그 창의 지금 칸, 창이 없으면 그 항목을 버리고 다음 항목으로 간다. 다시 연 탭은 보통 탭이다(미리보기가 아니다) — 칸마다 미리보기 하나(FR-RTB-1)를 깨지 않기 위해서다. 다시 연 탭을 활성으로 하고 그 칸을 포커스한다.
- **FR-RTR-5** 같은 대상의 탭이 그 칸에 이미 있으면 새로 만들지 않고 그 탭으로 간다(FR-RTB-4). git 뷰 탭은 창에 하나이므로(FR-RTB-11) 그 창에 있으면 그 탭으로 간다.
- **FR-RTR-6** 다시 연 편집기·Diff 탭은 닫을 때의 커서와 스크롤로 돌아간다.
- 구현 메모(묶음 1·2): `core/app-tab-reopen.js`. 칸 안의 위치는 칸이 사라져 그 창의 지금 칸에 열 때도 닫을 때의 index 를 쓴다 — 칸 하나의 탭을 모두 닫으면 칸도 지워지는데(FR-EDT-52), 그 뒤 차례로 다시 열어도 원래 순서가 되게 하려는 것이다. 다시 연 탭은 새 id 를 받고, 기록(뒤로·앞으로)의 옛 id 는 새 id 로 바꾼다. 커서·스크롤은 문서 길이가 닫을 때와 같을 때만 그대로 되돌리고, 다르면 커서만 두고 가운데로 보인다(편집기). Diff 는 내용을 받아 칸이 선 뒤에 되돌린다.

**뒤로·앞으로**

- **FR-RTR-7** 뒤로·앞으로가 이미 닫힌 탭의 자리를 만나면, 그 탭이 닫은 탭 목록에 있으면 그 자리에 다시 열고(FR-RTR-4~6) 그리로 간다. 닫은 탭 목록에서는 뺀다(FR-M9-24 의 "사라진 자리는 건너뛴다" 개정). 목록에 없는 자리(터미널·창이 사라진 자리)는 지금처럼 건너뛴다.
- **FR-RTR-8** 파일 안의 큰 점프도 기록의 한 칸이다. 점프는 셋이다: 검색 결과로 그 줄에 가기(FR-EGS-10), 정의로 이동(FR-LSP), 참조 목록에서 고르기. 점프하기 전 자리(탭과 커서)를 기록에 넣는다. 뒤로가기는 그 탭으로 가고 그 커서로 돌아간다. 편집기 안 정의 이동의 되돌아가기(`_lspBack`, FR-LSP-27)는 그대로 둔다.
- **FR-RTR-9** 기록의 자리에 커서가 없으면(탭 전환으로 생긴 자리) 커서를 움직이지 않는다.

**스크롤 보존 (사용자 덧붙임)**

- **FR-RTR-10** 탭을 열고 스크롤한 뒤 포커스를 옮겼다가(다른 창으로 갔다가) 돌아오면 그 탭의 스크롤이 그대로다. 대상은 편집기·Diff·git 뷰 탭이다. 원인은 구현 전에 조사해 이 조항 아래에 적는다.

**마우스 버튼**

- **FR-RTR-11** 마우스 4·5번 버튼 묶음(M9_SRS FR-M9-26)을 없앤다. 그 버튼은 브라우저의 것이다(사용자 결정: "앱에서 빼고 브라우저에 맡긴다"). 앱의 뒤로·앞으로는 단축키로만 한다.
- **FR-RTR-12** 단축키 목록·설정 화면·문서(`shortcuts-docs` 게이트)에 `tabReopen` 이 함께 선다.

**뒤로·앞으로 버튼 (사용자 덧붙임)**

- **FR-RTR-13** 뒤로·앞으로 버튼 두 개를 둔다. 자리: Repo 창이 활성일 때 상단바 오른쪽, 슬롯 버튼의 왼쪽이다. 슬롯 버튼과는 간격을 두고 구분선 등으로 묶음이 갈려 보이게 한다(사용자 결정). Repo 창이 아닐 때는 보이지 않는다.
- **FR-RTR-13a** 버튼은 단축키와 같은 액션(`focusBack`·`focusForward`)을 부른다.
- **FR-RTR-14** 갈 곳이 없으면 그 버튼은 비활성이다. 판정은 "건너뛰지 않고 갈 수 있는 자리가 기록에 하나라도 있는가" 다 — 열린 자리이거나 닫은 탭 목록으로 다시 열 수 있는 자리(FR-RTR-7). 기록이 바뀔 때마다(자리 이동·탭 닫기·창 닫기) 상태를 다시 칠한다.
- 구현 메모(묶음 3): `#nav-ctl`(`web/index.html`)이 슬롯 묶음 앞에 서고 왼쪽 구분선·간격으로 갈린다. 칠하기는 `renderer-chrome.js` `_rNavButtons`(렌더마다)와 기록이 바뀔 때(`_navNote`·`_navMove`)다. 판정은 `app.navCan(d)` — `_navMove` 가 건너뛰지 않는 자리(`_navReachable`)가 그 쪽 기록에 있는가. 모바일에는 서지 않는다(상단바 오른쪽은 모바일 단추 자리다). 기준선(V-LAY-1)에는 새 키만 더했다(`nav-btn`·`nav-ctl`).

- 이전 동작: 닫은 탭 다시 열기가 없었다. 뒤로가기는 닫힌 자리를 건너뛰었고 파일 안 점프는 기록하지 않았다. 마우스 4·5번이 앱의 뒤로·앞으로였고 브라우저 뒤로가기와 겹쳤다. 창을 오가면 탭의 스크롤이 맨 위로 갔다. 새 동작: 위 FR-RTR. 이유: 사용자 요구(R24) — VS Code 의 뒤로·앞으로와 닫은 탭 다시 열기.

### 3.5h 변경이 없어진 Diff (FR-DNC)

사용자 결정(2026-11-11 질의응답): "VS Code 기본 + 안내". 재현(커밋 세 가지: 변경 전부 커밋 · 그 파일만 커밋 · staged 커밋)에서 오류는 없었고, 갈린 것은 다음 둘이다. ① "목록에서 사라졌습니다" 안내는 Changes 목록이 비면 나오지 않았다(`_paintDiff` 의 조건에 `list.length` 가 있다). ② "변경 없는 줄 접기"의 접을 범위는 `@codemirror/merge` 6.12 의 `CollapsedRanges` 가 **칸을 만들 때 한 번** 계산한다. 커밋으로 원본 쪽만 바뀌면(`_cmSetOrig`) 칸을 다시 만들지 않으므로 접기가 새 내용을 따르지 않는다. 변경이 하나도 없으면 접기가 본문 전체를 한 띠로 접어 내용이 사라진 것처럼 보인다.

- **FR-DNC-1** 커밋 축이 아닌 Diff 탭의 대상이 Changes 목록에 없으면(커밋·되돌리기) 머리에 "변경이 없습니다 — 커밋됐거나 되돌려졌습니다" 안내를 띄운다. 목록이 비었는지와 상관없이 같은 규칙이다. 탭은 닫지 않는다(VS Code `git.closeDiffOnOperation` 의 기본값과 같다).
- **FR-DNC-2** 보일 변경 조각이 하나도 없으면 "변경 없는 줄 접기"가 켜져 있어도 접지 않는다. 본문은 파일 전체다.
- **FR-DNC-3** 접기는 늘 지금 내용을 따른다. 원본 쪽이 바뀌면(커밋·stage·unstage) 접을 범위를 다시 계산한다. 그때 커서와 스크롤 비율은 그대로다.
- **FR-DNC-4** 대상에 다시 변경이 생기면 안내가 걷히고 변경 색과 접기가 돌아온다.
- 구현 메모: 접기는 칸을 세울 때 정해지므로 접기를 켠 Diff 는 원본 쪽이 바뀌면 칸을 다시 세운다(커서·스크롤 비율 유지, `_cmBuild(true)`). 변경 유무가 접기와 어긋나면(밖에서 바뀐 내용) 다시 세운다. 그 Diff 칸에서 직접 치는 동안에는 다시 세우지 않는다 — 다시 세우면 입력 포커스를 잃기 때문이다. 그래서 변경이 없던 Diff 에서 직접 쳐서 변경을 만들면 접기는 다음 갱신(포커스를 떠난 뒤의 밖의 변경·원본 변경) 때 돌아온다. 안내 문구는 `git.diff_gone_note` 를 고쳐 쓴다("선택한 파일이 목록에서 사라졌습니다" → "변경이 없습니다 — 커밋됐거나 되돌려졌습니다"). 관측이 오기 전에는 띄우지 않는다.
- 이전 동작: 위 ①② 와 같다. 새 동작: FR-DNC-1~4. 이유: 사용자 요구(R25) — "Diff 내용이 사라지거나, 접기를 켜 두었는데 적용되지 않는다".

### 3.5i hunk 동작의 대상은 변경 블록이다 (FR-HKB)

재현: git hunk 는 문맥 3줄(`HunkContext`)로 만든다. 그래서 6줄 안에 붙은 변경은 hunk 하나로 묶인다(예: 30줄 파일의 10행·15행 변경 → `@@ -7,12 +7,12 @@` 하나). 화면은 변경 조각을 따로 칠하는데, 선택 없이 커서만 둔 툴바 동작은 git hunk 전체에 걸렸다(FR-DHB-31). 그래서 보이는 조각 하나를 되돌려도 묶인 조각이 함께 되돌아갔다. 작은 파일에서는 그것이 파일 변경 전체다.

- **FR-HKB-1** "변경 블록"은 hunk 본문에서 문맥 줄 없이 이어진 `-`·`+` 줄의 묶음이다. 화면에 보이는 변경 조각 하나에 맞는다.
- **FR-HKB-2** 선택 없이 커서만 있으면 툴바의 동작(stage·unstage·revert)은 커서가 있는 변경 블록 하나에만 걸린다. 서버에는 그 블록의 줄 범위(`from`·`to`)를 보낸다 — 서버 규약은 그대로다.
- **FR-HKB-3** 커서가 블록 위에 있다는 것은 커서 줄이 그 블록의 새 줄 가운데 하나라는 뜻이다. 삭제만 있는 블록은 새 쪽에 줄이 없으므로 삭제 바로 다음 줄(파일 끝의 삭제면 바로 앞 줄)을 그 블록의 자리로 본다.
- **FR-HKB-4** 커서가 문맥 줄(블록이 아닌 줄)에 있으면 툴바를 띄우지 않는다(사용자 결정: "툴바를 띄우지 않는다").
- **FR-HKB-5** 텍스트를 골랐을 때의 동작(FR-DHB-32·33, 고른 줄이 닿은 블록들)은 그대로다. 블록 동작의 라벨은 hunk 라벨(`Revert hunk` 등)이고, 되돌리기 확인 창의 대상 글은 그 블록의 줄 범위다.
- 이전 동작: 커서만 두면 git hunk 전체(묶인 블록 전부)에 걸렸고, 문맥 줄에서도 툴바가 떴다. 새 동작: FR-HKB-1~5. 이유: 사용자 요구(R26) — "hunk 는 해당 부분부분만 뒤로 돌려야 하는데 파일 전체를 뒤로 돌린다".
