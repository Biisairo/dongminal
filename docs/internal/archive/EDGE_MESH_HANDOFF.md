### D-2 내 설정 변경 알림 (2026-11-18)

> *"내 설정 변경 시 내가 바뀐것 알리는거 추가하자."*

- 내 이름·노드 포트·알릴 주소가 바뀌면 **모든 간선 상대에게 한 번 알린다(브로드캐스트). 재시도는 없다.**
- 못 받은 상대는 Edges 간선 줄에 **"알림 대기"** 표시를 남긴다. `dmctl edges` 에도 나온다.
- 상대가 "나도 알려 줘" 하면 **사람이 직접 알리기**를 누른다 — **GUI(간선 줄의 버튼)와 CLI 둘 다**.
  CLI 는 `dmctl edge notify <이름#번호|지문>` 을 가정했다(사용자 미확인 — 인터뷰에서 확인).
- **노드 포트를 끄는 것은 알리지 않는다.**
- 가정(사용자 미확인): 노드 포트가 꺼진 상태에서 이름만 바꾸면 이름만 보낸다. 주소·포트는 짝맞춤과 같은 규칙(노드
  포트가 열려 있을 때만)으로 싣는다.
- D-1 에 따라 이 알림은 **간선 계층의 망 정보 전파와 한 설계로 합칠 수 있다**(미결 Q-3).

### D-3 망 그리기 (2026-11-18)

> *"현재 간선 망을 알 수 있으면 해당 망을 그려줄 수 있나?"* → D-1 로 이어짐.

간선 계층의 망 정보를 `/api/edges` 로 내보내고 화면에 그래프로 그린다. 그리는 자리·모양은 미결.

### D-4 전파 통로 = 간선 연결 하나 (2026-11-18, Q-1)

- 간선마다 연결 하나를 **간선 계층**이 가진다. 연결 맺기·재연결·ping·망 정보 프레임의 서명·전파·온라인 판정은
  간선 계층이 맡는다.
- 그 연결 위에 간선 프레임(망 정보·ping)과 채팅 프레임(state·msg 등)을 **프레임 종류로 나눠** 함께 흘린다.
  각 계층은 바뀐 것만 자기 프레임으로 보낸다. 모든 정보를 한 덩어리로 묶어 보내지 않는다.
- 채팅은 연결을 직접 다루지 않는다. 간선 계층에 프레임 종류를 등록해 받고, 간선 계층의 보내기를 쓴다.

### D-5 주소·포트는 직접 상대에게만 (2026-11-18, Q-2)

- 이름·지문·간선 목록(links)은 망 전체에 공개한다. 주소·노드 포트는 망 정보 프레임에 싣지 않고 간선 상대에게만
  보낸다.
- 망 이웃끼리 간선을 맺으려면 **받을 노드의 지문에 묶인 초대**를 보낸다. 중간 노드가 채팅에서 코드를 읽고 먼저
  쓰는 것을 막기 위해서다(채팅은 종단 간 암호화가 없다, FR-PCH-7).

### D-7 변경 알림 (2026-11-18, Q-3 — D-2 를 대체)

- 이름: 망 정보 프레임으로 망 전체에 퍼진다. 직접 상대는 받으면 `edges.json` 의 `Edge.Name` 도 고친다.
- 주소·포트: 바뀔 때 열린 간선 연결로 직접 상대에게만 **한 번** 보낸다(재시도 없음). 옛 포트를 닫기 **전에** 보낸다.
  노드 포트를 끄는 것은 알리지 않는다.
- **간선 연결이 열릴 때마다** 서로의 지금 이름·주소·포트를 주고받는다. 다시 이어지면 저절로 맞춰진다.
- "알림 대기": 변경 뒤 아직 받지 못한 직접 상대. Edges 간선 줄과 `dmctl edges` 에 보인다.
- 수동 알리기: GUI 간선 줄 버튼 + `dmctl edge notify <이름#번호|지문 앞자리>`(확정). 그 상대에게 내가 걸어 연결을
  맺고 보낸다. 상대 주소를 모르면 사유 코드를 내고 1 로 끝난다. `--all`·`--pending` 같은 일괄 선택은 없다.

## 조사로 확정한 사실 — 다시 조사하지 않는다

### 간선 계층의 지금 모양

- 노드 포트 경로는 `/edge/v1/pair`·`unpair`·`chat` 셋뿐이다 (`internal/shared/edgenode/node.go:25-30`, `Handler` 177).
  `proto = 1`. 그 밖은 404 `not_found` — 옛 판 상대는 새 경로에 404 를 답하므로 "지원하지 않음" 으로 가를 수 있다.
- 출입: TLS 는 누구나, 요청 단계는 `pair` 만 누구나이고 나머지는 `store.IsEdge(fp)` (`node.go` `Admission`).
  상대 확인은 클라이언트 인증서 지문(mTLS) — 새 경로를 더하면 같은 보호를 그대로 받는다.
- **상대의 주소·포트는 짝맞춤 때 한 번 받는다.** 초대 코드에 초대한 쪽의 주소·노드 포트(`ops.go:252`), 맺기
  요청에 붙여 넣은 쪽의 주소·포트(노드 포트가 열려 있을 때만, `ops.go:290`, `node.go:pair`). 그 뒤 갱신 경로는
  사람이 하는 `PUT /api/edges/address`(`Store.SetAddress`)와 다시 맺기뿐이다. **설정 저장(`opNode`·
  `opProfileName`)은 상대에게 아무것도 보내지 않는다.**
- 상대가 보는 내 이름(`Edge.Name`)도 짝맞춤 때 한 번 받은 값이다 — Profile 에서 이름을 바꿔도 상대의 간선 목록에는
  옛 이름이 남는다. `#번호` 는 각자 지문에서 계산하므로 맞는다(PROFILE_NAME_SRS FR-PFN-5).
- 간선 계층은 요청할 때만 연결한다. **계속 열린 연결은 채팅 계층의 것뿐**이다(간선 상대마다 하나, D-PCH-22).
- 변경 방송: `Node.changed(Change)` → 서버의 `edgesChanged`(`internal/webserver/httpapi/edge_api.go`) →
  `edges_changed` SSE. 데몬 모드는 `edge_relay.go` 로 같은 함수에 온다. `Ref` 에 번호(`tag`)는 서버가 붙인다.
- 직접 모드(서버가 노드)와 데몬 모드(데몬이 노드, IPC `edge`) 둘 다 `edgenode.Node.Do(op)` 로 같은 연산을 탄다.
  새 연산을 더하면 두 모드에 함께 선다. 데몬 IPC 에 연산 이름 허용 목록은 없다.

### 채팅 계층은 이미 망 전체를 안다 — 앞 세션이 처음에 틀렸던 지점

- `PEER_CHAT_SRS` 묶음 G: **망 이웃**(간선을 건너 이어진 노드), 노드 상태 알림, 글 전파.
- 각 노드가 서명한 `state` 프레임 `{node, key, name, epoch, seq, links[], parts[], rooms[]}` 를 망 전체에 퍼뜨린다
  (FR-PCH-9, §3 프레임 표 241행). `(epoch, seq)` 가 큰 것만 쓴다. 전파 규칙 246행.
- A·B 간선은 양쪽 최신 `state` 의 `links` 에 서로 있을 때만 이어진 것으로 본다(251행). 온라인 판정은 그 그림의
  도달 여부(`internal/daemon/chat/view.go` 의 BFS).
- 구현: `chat/frame.go:51 Links`, `chat/service.go:541` 이 자기 `links` 를 채운다, `chat/link.go:322` 검증,
  `chat/human.go:179` 사람 명령 키 고정에 `links` 를 쓴다(FR-PCH-74, D-PCH-39 — **`links` 를 옮기면 이 보안 규칙에
  닿는다**).
- 스펙 §2 의 "간선을 건너 전달하지 않는다" 는 채팅 **이전의 현황**이다. 지금 동작이 아니다.
- `/api/chat` 은 노드별 `links` 를 화면에 내보내지 않는다.

- **Q-3 변경 알림(D-2)과의 합침.** 망 정보 전파가 서면 이름 변경은 그 안에서 퍼진다. 주소·포트 변경은 직접 상대가
  옛 포트로 걸기 때문에 **내가 상대에게 거는 방향**으로 알려야 한다. 수동 알리기 버튼·CLI·"알림 대기" 표시는 D-2 대로
  유지한다.
- **Q-4 직접 모드.** 채팅은 데몬 모드에서만 돈다. 간선 계층의 망 정보를 직접 모드에서도 지원하나.
- **Q-5 채팅 계층 정리.** 채팅 `state` 에서 `links`·`name` 을 빼고 간선 계층의 것을 쓰게 바꾼다. FR-PCH-74·D-PCH-39
  (망 이웃의 도우미 키를 `links` 로 믿는 규칙)를 어떻게 옮기나. 옛 판 노드와 섞여 있을 때의 호환.
- **Q-6 망 그리기의 자리·모양.** 설정 ▸ Edges 안의 그래프인가, 별도 화면인가. 노드 표시(이름#번호·온라인·나).
- **Q-7 V-LAY-1 기준선.** 아래 「남은 정리」 참고 — 이 일과 별개지만 사용자 결정이 필요하다.

## 값을 치르고 배운 것

- **e2e 를 도는 중에 다른 e2e 를 띄우지 않는다.** `global-setup` 이 e2e 바이너리를 다시 빌드하고 `dongminal-e2e-*`
  를 정리해 도는 전량을 깬다. 소스 편집은 괜찮다 — 바이너리가 시작할 때 자산을 내장한다.
- 전량 e2e 는 `make e2e > /tmp/dm-e2e-full.log 2>&1` 로 백그라운드. 결과는
  `LC_ALL=C sed 's/\x1b\[[0-9;]*[A-Za-z]//g' … | LC_ALL=C grep -a` 로 뽑는다(한글·ANSI 때문).
- 실패가 내 것인지는 `git stash -q -u` → 그 스펙만 실행 → `git stash pop -q` 로 가른다.
- 화면 확인은 `e2e/zz-tmp-*.spec.ts` 를 잠깐 만들어 스크린샷을 찍고 지운다(전량이 돌지 않을 때만).
- 요구사항 접두어는 쓰기 전에 `grep -rl "FR-XXX-" docs internal web` 로 겹침을 확인한다(FR-PRF 가 이미 있었다).
- `app-settings.js` 는 모듈 크기 게이트 500줄 경계에 있다.
- 테마마다 `--text` 와 `--text-bright` 가 같을 수 있다 — 색으로 단정하는 e2e 를 쓰지 않는다.

## 변하지 않는 규약

- 커밋 전: `make gates` · `make lint` · `make unit` · `npm run -s typecheck` · 관련 `go test`. 전량은 `make test`(약 3~4분).
- 커밋 메시지에 AI 서명 금지. 커밋·푸시는 사용자 확인 뒤.
