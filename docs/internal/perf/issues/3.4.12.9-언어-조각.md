**소속 판정 방법**
- 키의 "쓰는 곳" = 키와 똑같은 문자열 리터럴(복수형은 `.other`/`.one` 을 뗀 이름)이 든 `web/js` 파일의 묶음(`bundles.txt`) + `index.html` 의 따옴표 키(`'html'` = 부팅). 묶음 밖 파일(head 셋)은 부팅. 기존 미사용 판정과 같은 근거라 모든 키가 어딘가에 하나는 걸린다.
- 쓰는 곳이 지연 묶음 하나뿐이면 그 조각, 아니면 부팅. 근거: 그 리터럴은 묶음이 실행되기 전에는 메모리에 없고, 조각은 묶음 JS 앞에 실행된다.
- 지연 묶음 파일의 키 리터럴 중 `t()` 인자가 아닌 것(표·조건식, 50곳)을 훑었다 — 전부 묶음 안 지역 표(run-recover 사유, settings-claude 라벨 등)이고 저장소·서버로 나가 부팅 코드가 되읽는 자리는 없었다.

**부팅에 남긴 키와 이유**(부팅 868키)
- 부팅 파일·index.html 이 쓰는 키(대부분). 설정 창 마크업(`data-i18n`)은 index.html 이라 부팅이다.
- 동적 접두 키 193개(`err.`·`why.`·`cacct.*`·`usage.*`·`git.job_kind.` 등): 조립되는 자리를 리터럴로 볼 수 없고, Rust 대조 스크립트가 `ko.js`·`en.js` 를 직접 읽는다. 그중 `git.job_kind.`·`git.job_fix_label.`(git)·`cacct.color.`(settings)는 접두가 한 묶음에만 있어 옮길 수 있었으나(약 0.9 KB) 규칙을 둘로 나누지 않으려 남겼다.
- 여러 곳에서 쓰는 키 14개(`core.cancel`·`edge.invite_send`(chat+settings) 등).
- diag 키 9개(약 0.2 KB): `[diag]` 는 `Screens.load` 를 지나지 않는다(3.4.12.3, index.html 인라인의 `document.write`). 조각을 실을 길을 따로 두면 같은 일이 두 벌이 된다(D-11). `check-i18n` 의 `UNFRAGMENTED` 에 사유와 함께 적었다.
- mdlib·search·themes·keybar·mobile 은 전용 키가 없다.

**남은 위험**(MED)
- 판정은 리터럴 기준이다. 지연 묶음 코드가 키 문자열을 저장소·서버에 남기고 다음 부팅의 부팅 코드가 그 묶음 없이 `t()` 하는 꼴이 새로 생기면 키가 보인다. 지금은 없음을 확인했다(위 50곳). 같은 문자열이 우연히 다른 묶음에 리터럴로 있으면 부팅에 남을 뿐이다(안전 쪽).
- 조각과 묶음 JS 를 나란히 받으므로, 조각만 실패하면 묶음 JS 는 이미 돈 뒤 재시도에서 한 번 더 돈다 — CSS 실패 때와 같은 기존 성질이다.
- 키를 새로 더하는 사람은 쓰는 곳에 따라 `ko.js` 가 아니라 조각에 넣어야 한다(게이트가 위치를 알려 준다). 문구 교정 diff 가 여러 파일로 갈린다.
- 단위 시험 하네스는 조각을 자동으로 싣지 않는다. 지연 묶음 상수의 문구를 재는 새 단위 시험은 `i18n/<묶음>.ko.js` 를 함께 실어야 한다.
