## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 말은 세 묶음, 아홉 줄이다.

> **orchestration**
> 1. run 을 runs 모달에서 직접 지울 수 있는 버튼을 만들어줘.
> 2. run 이 끝나거나 해당 세션이 종료되면 자동으로 목록에서 지워줘
> 3. run 대시보드가 화면 크기에 맞게 꽉 차도록, 그치만 잘리지는 않도록 창 크기에 맞춰 fit 하게 나오도록 만들어라.
> 4. 하위 에이전트를 만들 때 상위 에이전트와 같은 경로로 터미널을 열고 만들어야한다. 안그러면 에이전트를 열 수 없을 수 도 있다.
>
> **기타 편의성**
> 1. chrom 의 기본 단축키를 막는다. 기본단축키가 단축키 설정을 자유롭지 못하게 한다.
> 2. 탭을 다른 window 로 옮길 수 있도록 하자
> 3. window 닫았을 때 git 탭으로 가는 오류
> 4. shell 이름을 사용하는 여러곳(백그라운드 모달, 알람 등)에서도 자동으로 설정된 터미널의 이름을 이용하도록 해줘
>
> **git**
> 1. git 의 add 버튼을 window 에서와 같은 위치에 배치. 윈도우와 깃 탭은 완벽하게 같은 구조를 가져야 한다. 나중에 추가되는 탭도 마찬가지이다.
> 2. git 에서 좌측 패널 요소 리스트 이동 로직을 window 와 동일하게. 두 탭은 완벽하게 같지만 타겟만 다른거야. 탭은 똑같이 만들어야해
> 3. change 에서 왼쪽에 M, D 등 상태 나타내는 기호들에 색상 추가

2026-08-28 인터뷰로 해석이 갈리던 넷을 확정했다 (§1.5).

## 3. 요구사항 (Specific Requirements)

### 3.1 묶음 D — Run 수명

#### 3.1.1 수동 삭제

| ID | 요구사항 |
|---|---|
| **FR-DEL-1** | Runs 모달의 각 행에 삭제 버튼이 있다 |
| **FR-DEL-2** | 삭제 버튼 클릭은 행 클릭(대시보드 열기)을 **발화시키지 않는다** |
| **FR-DEL-3** | 첫 클릭은 그 행에서 확인을 연다. 확인 전에는 아무것도 지워지지 않는다 |
| **FR-DEL-4** | 확인은 백그라운드 모달의 종료 확인(FR-BGK-1~5)과 **같은 상호작용 규약**을 쓴다 — 행 안에서 열리고, 다른 행을 건드리거나 모달을 닫으면 취소된다 |
| **FR-DEL-5** | 확인 후 `DELETE /api/runs/{id}` 를 부르고, 성공하면 목록에서 사라진다 |
| **FR-DEL-6** | 실패는 그 행에 남는다 (FR-BGK-10 과 같은 자리) |

#### 3.1.2 삭제의 의미 (D-1)

| ID | 요구사항 |
|---|---|
| **FR-DEL-7** | 삭제는 `runs.json` 에서 레코드를 **제거**한다 |
| **FR-DEL-8** | 삭제 전에 그 Run 이 만든 worktree 를 정리한다 — 정리 근거(`WorktreeTargets`)가 레코드와 함께 사라지므로 순서가 뒤집히면 트리가 영원히 남는다 |
| **FR-DEL-9** | **수동** 삭제는 잔여 트리가 있어도 수행한다. 사용자가 명시적으로 고른 것이며, 잔여는 응답에 실린다 |
| **FR-DEL-9a** | **자동** 제거는 **남긴 자원이 있으면** 레코드를 보존한다 — 잔여 worktree(FR-WKT-12)와 `--keep-tools` 로 살려 둔 헤드리스 도구(FR-HLM-5)다. 레코드가 그것을 아는 유일한 자리이므로, 지우면 아무도 모르는 자원이 된다. 사용자는 FR-DEL-1 의 버튼으로 언제든 지울 수 있다 |
| **FR-DEL-10** | 열려 있는 Run 의 삭제는 `close(force)` 와 같은 정리를 먼저 거친다 — 헤드리스 도구 종료·워크스페이스 표식 해제를 건너뛰면 고아가 남는다 |
| **FR-DEL-11** | 삭제 후 `run_changed` 를 방송한다. 열린 Run 탭은 FR-RVZ-9 의 "사라진 Run" 으로 떨어진다 — **탭을 자동으로 닫지 않는다** |

| **O1a** | 잔여가 있으면 자동 제거는 보류 | FR-WKT-12 는 "지우지 못한 자원은 조용히 남지 않는다" 를 세웠고, 그 자원을 아는 유일한 자리가 레코드다. 자동 제거가 그것을 지우면 잔여 트리는 **아무도 모르는 디렉터리**가 된다. 목록 정리라는 목적은 잔여 없는 정상 종료(대부분)만으로 달성된다 |
| **O1b** | 개정되는 기존 테스트 셋 | `TestApiRunClose_SweepsAbortedRun`·`SweepIsIdempotent` 는 "닫은 뒤에도 레코드가 남는다" 를 검증했다. FR-DEL-12 가 그 동작을 바꾸므로 두 테스트는 새 동작으로 개정한다. `CleansCleanKeepsDirty` 는 잔여가 있는 경우이므로 FR-DEL-9a 로 **그대로 통과한다** |
| **O2** | 조정자 도구 죽음을 주기적으로 본다 | D-2. `onExit` 배선은 데몬 경계를 넘어 서버까지 오지 않는다 (`toolclient.OnExit` 는 클라이언트 쪽 콜백이다). 수거는 이미 있는 `toolLive` 만으로 성립한다 |
| **O3** | 축소만 하고 확대하지 않는다 | 확대는 노드 글자를 키워 대시보드를 포스터로 만든다. "꽉 차게" 의 뜻은 **잘리지 않게** 다 |
| **O4** | `_mkWindow` 만 고친다 | `addTab`·`split` 은 이미 승계한다 (A6). 빠진 자리 하나를 메우는 것이 새 규약을 만드는 것보다 싸다 |
| **O5** | `preventDefault` 만 하고 전파는 두지 않는다 | 전파를 멈추면 xterm 이 키를 못 받아 터미널이 죽는다. 차단의 목적은 **브라우저** 를 막는 것이지 앱을 막는 것이 아니다 |
| **O6** | 창 항목을 드롭 대상으로 | D-4. 창 항목은 이미 드래그 참여자다 — 드롭 존을 하나 더 얹는 비용이 새 메뉴 체계보다 작다 |
| **O7** | 블루프린트는 서술자 확장으로 | `SB_TAB_DEFS` 가 이미 "탭 하나 = 서술자 하나" 를 세워 뒀다 (FR-SBT-19). 새 추상을 옆에 세우면 탭 정의가 두 곳이 된다 |
| **O8** | 기존 클래스 보존 | e2e 21곳이 `.si`·`.git-repo` 를 쓴다. 이름을 갈면 이 SRS 와 무관한 테스트가 무너지고, 무너진 이유가 이 변경과 무관해 보인다 |

⑥ 을 파고들며 같은 뿌리의 셋째가 드러났다 (FR-GRR-4·5). `V79`·`V93`·`M5` 가
전체 스위트에서 번갈아 하나씩 실패했는데, 공통 지점은 **Git 창을 연 직후**였다 —
탭 7개를 세는 검사가 0을 받았다. 세 증상이 한 원인이었다.

> **처방을 한 번 잘못 골랐다.** 처음에는 "새 Git 창은 저장이 끝나기를 기다린다"
> 로 막으려 했고, 그것이 오히려 경쟁 창을 넓혀 Git 창이 **항상** 사라졌다 —
> 기다리는 동안 이미 떠난 조회가 낡은 응답을 들고 돌아온다. 자동 검증(63개)은
> 통과했고 **스크린샷을 눈으로 보고서야** 드러났다. 막을 자리는 만드는 쪽이
> 아니라 적용하는 쪽이었다.

⑥ 이 가장 값이 컸다 — "불안정한 테스트" 로 넘겼다면 **리포를 전환한 직후 다른
브라우저의 변경이 그것을 되돌리는** 실사용 결함이 그대로 남았다. flaky 는 자주
결함의 그림자다.

②와 ⑤가 남긴 교훈은 같다 — **한 조항을 대체하는 개정이 그 조항을 참조하던
자리를 찾아 주지 않는다.** ②는 테스트가 그 사실을 계속 알렸는데 실패가 오래
방치됐고, ⑤는 앞선 400 이 뒤의 결함을 가리고 있었다.
