# SRS: 좌측 사이드바 접기 — IEEE 29148

## 1. 개요

### 1.1 목적

접수한 말은 한 줄이다.

> **"좌측 사이드바 열고 닫기 버튼 추가"**

지금 사이드바를 좁히는 유일한 손잡이는 `#sb-handle` 의 드래그뿐이고, 그것은
100px 아래로 내려가지 않는다 (`input-binding.js:46`). 화면을 온전히 콘텐츠에
쓰고 싶을 때 사용자가 할 수 있는 일이 없다.

이 SRS 는 **접힘 상태**를 하나 세우고, 그 상태를 켜고 끄는 버튼을 상단바에
둔다. 접힌 사이드바는 사라지지 않고 **아이콘 레일**로 줄어든다 — 탭 사이의
이동과 설정·새로고침이 접힌 채로도 손에 닿아야 하기 때문이다.

### 1.2 범위

**포함**
- 접힘 상태의 정의·저장 자리·복원
- 상단바의 토글 버튼
- 접힌 사이드바(아이콘 레일)의 구성과 그 안에서의 탭 전환
- 접힘·펼침에 딸린 터미널 재적합

**미포함**
- 사이드바 **폭**의 규약 — `--sb-w`·`ws.sidebarWidth`·드래그는 그대로다 (§6 비목표 #1)
- 모바일 드로어 — 접힘은 데스크톱의 것이다 (§2.4, §6 비목표 #2)
- 단축키 — 접수한 말은 버튼이다 (§6 비목표 #3)
- 사이드바 **탭**의 구성·순서·배지 규약 (GIT_SIDEBAR_TABS_SRS) — 아이콘 필드
  하나가 늘 뿐이다 (§6 비목표 #4)

## 2. 현재 상태

### 2.1 사이드바의 골격

`index.html:25~63` 의 구조는 셋이다.

| 요소 | 내용 | 접힘에서의 운명 |
|---|---|---|
| `#sb-tabs` | 탭 버튼 (서술자 배열이 그린다) | **남는다** — 아이콘만 |
| `.sb-panel` × 2 | 액션 버튼 행 + 목록 | 숨는다 |
| `#sb-bottom` | `⟳` · `⚙` | **남는다** — 이미 아이콘이다 |

`#sb-handle` 은 사이드바 **밖**의 형제다 (`index.html:66`).

### 2.2 폭이 사는 곳은 셋이다

```
--sb-w (CSS 변수)  ← 그리는 값
ws.sidebarWidth    ← 서버 워크스페이스 (app.js:152, app-cmd.js:446)
localStorage.sidebarWidth ← 부팅 첫 프레임용 (index.html:20)
```

세 곳이 있는 이유는 부팅 플래시다 — 워크스페이스가 오기 전에 이미 그려야 한다.
**접힘 상태도 같은 문제를 갖는다** (§3.2).

### 2.3 탭 서술자에는 아이콘이 없다

`SB_TAB_DEFS` 의 필드는 `id·label·panelId·title·badge·visible·onActivate·
onEnter·list·cycle` 이다 (`sidebar-tabs.js:19~31`). 레일은 라벨을 쓸 수 없으므로
(40px) 서술자가 아이콘을 하나 더 들어야 한다. **탭을 늘리는 비용이 서술자
1개라는 계약**(FR-SBT-21)이 여기서도 지켜져야 한다 — 아이콘 표를 따로 두면
탭이 늘 때 고칠 자리가 둘이 된다.

### 2.4 모바일은 이미 다른 규약이다

`body.mobile #sidebar` 는 하단 드로어이며 (`style.css:789`), `#sb-handle` 은
숨어 있다 (`style.css:788`). 드로어를 여닫는 손잡이는 `#m-drawer-toggle` 이
이미 갖고 있다 (`index.html:99`). **접힘은 그 위에 얹지 않는다.**

### 2.5 폭이 바뀌면 터미널을 다시 맞춘다

드래그가 끝날 때 하는 일이다 (`input-binding.js:47`):

```js
for(const p of this.app.tools.values()) if(p.el.classList.contains('vis')) p.doFit();
```

접힘·펼침은 폭 변화이므로 **같은 일을 해야 한다.**

## 3. 요구사항

### 3.1 상태

**FR-SBC-1** 사이드바는 **펼침**과 **접힘** 두 상태를 갖는다. 접힘은 데스크톱
에서만 뜻을 갖는다 (FR-SBC-20).

**FR-SBC-2** 접힘 상태에서 사이드바의 폭은 `--sb-rail-w`(40px)이며, 펼침 폭
(`--sb-w`)은 **보존된다** — 펼치면 접기 전의 폭으로 돌아간다.

**FR-SBC-3** 접힘은 `ws.sidebarWidth` 를 바꾸지 않는다. 폭과 접힘은 서로 다른
값이며, 접힘이 폭을 덮으면 펼쳤을 때 돌아갈 자리가 없다.

### 3.2 저장과 복원

**FR-SBC-4** 접힘 상태는 `localStorage.sidebarCollapsed` 에 산다 — `'1'` 이면
접힘, 그 밖(없음 포함)이면 펼침. **워크스페이스에 넣지 않는다**: 이것은
`sidebarTab`(FR-SBT-6)과 같은 범주의 "이 기기가 보는 방식"이고, 서버에 두면
다른 기기의 화면 폭에 맞춘 선택이 이 기기로 넘어온다.

**FR-SBC-5** 첫 프레임부터 접힌 채로 그린다. `index.html` 의 인라인 스크립트
(폭을 읽는 그 자리)가 같은 걸음에서 `document.documentElement` 에
`sb-collapsed` 클래스를 붙인다 — 자리를 나누면 폭은 즉시, 접힘은 스크립트
로드 뒤가 되어 사이드바가 한 번 펄럭인다.

**FR-SBC-6** 저장이 막힌 환경(사생활 모드)에서는 펼침으로 시작한다. 보기의
편의가 화면을 세우지 못하게 해서는 안 된다.

### 3.3 토글 버튼

**FR-SBC-7** 상단바 **맨 왼쪽**, `#window-name` **앞**에 버튼 하나가 선다:
`#sidebar-toggle`, 라벨 `☰`, 클래스 `tbtn desktop-only`.

**FR-SBC-8** 자리가 왼쪽 끝인 이유는 **접힌 상태에서도 같은 자리에 있어야**
하기 때문이다. 사이드바 안에 두면 접을 때 함께 줄어 여는 손잡이가 사라진다.

**FR-SBC-9** 버튼은 토글이다. 툴팁은 상태를 말한다 — 펼침이면
`Collapse the sidebar`, 접힘이면 `Expand the sidebar`.

**FR-SBC-10** `aria-expanded` 가 상태를 싣는다.

### 3.4 접힌 사이드바(레일)

**FR-SBC-11** 레일에 남는 것은 **탭 아이콘**과 `#sb-bottom` 뿐이다.
`.sb-panel`(액션 버튼 행 + 목록)은 숨는다 — 40px 에서 목록은 읽히지 않는다.

**FR-SBC-12** 탭 바는 가로에서 **세로**로 눕는다. 탭 버튼은 정사각(40×36)이고
라벨 대신 아이콘을 보인다.

**FR-SBC-13** 아이콘은 서술자의 `icon` 필드에서 온다 (§2.3). 필드가 없는
서술자는 라벨의 첫 글자를 쓴다 — 탭이 늘어도 이 SRS 를 다시 열지 않는다.

| 탭 | 아이콘 |
|---|---|
| `windows` | `▣` |
| `repo` | `⎇` |

**FR-SBC-14** 배지(FR-SBT-12·13)는 레일에서도 보인다. 자리가 없으므로 아이콘
**우상단에 겹친다**. 규약은 그대로다 — 비활성 탭에서만, 0·null 이면 없다.

**FR-SBC-15** `#sb-bottom` 의 두 버튼은 레일에서 **세로로** 쌓이며, 자리는
여전히 사이드바 최하단이다. 펼침에서 이 행을 아래로 미는 것은 `.sb-panel` 의
`flex:1 1 auto` 인데 레일에서는 그 패널이 숨으므로(FR-SBC-11) 미는 힘을
레일이 따로 세워야 한다 — 접었다는 이유로 버튼이 화면을 가로질러 옮겨
다녀서는 안 된다.

**FR-SBC-16** `#sb-handle` 은 접힘에서 숨는다. 레일의 폭은 고정이며, 드래그가
살아 있으면 접힌 사이드바를 끌어 펼칠 수 있는 것처럼 보인다.

### 3.5 레일에서의 탭 전환

**FR-SBC-17** 레일의 탭 아이콘을 누르면 **그 탭이 활성이 되고 사이드바가
펼쳐진다.** 접힌 채 탭만 바꾸는 것은 아무것도 보여 주지 않으므로 뜻이 없다.

**FR-SBC-18** 이미 활성인 탭의 아이콘을 눌러도 **펼쳐진다** — 두 동작(전환·
펼침) 중 할 수 있는 것을 한다.

### 3.6 부수 효과

**FR-SBC-19** 접힘·펼침 직후 보이는 터미널을 다시 맞춘다 (§2.5 와 같은 코드
경로). 사이드바 폭이 바뀌면 터미널의 열 수가 바뀐다.

**FR-SBC-20** `body.mobile` 에서는 접힘 규칙이 적용되지 않는다. 드로어가 이미
같은 필요를 채우며, 두 규약이 겹치면 드로어를 연 채 접힌 상태가 된다.

### 3.7 비기능

**NFR-SBC-1** 색·치수는 기존 팔레트 변수를 쓴다. 새 색을 만들지 않는다.

**NFR-SBC-2** 폭 전환에 애니메이션을 넣지 않는다. 기존 드래그 리사이즈도
즉시 반영이며, 전환을 넣으면 FR-SBC-19 의 재적합 시점을 `transitionend` 로
옮겨야 한다 — 얻는 것보다 늘어나는 것이 많다.

## 4. 설계 결정

**D-1 접힘은 클래스 하나다.** `documentElement.classList` 의 `sb-collapsed`.
폭을 JS 로 계산해 `--sb-w` 에 쓰면 펼침 폭을 잃는다 (FR-SBC-2) — CSS 가
`#sidebar` 의 폭을 덮는 쪽이 되돌릴 것이 없다.

**D-2 자리는 `documentElement` 다, `body` 가 아니다.** 인라인 스크립트가 도는
시점에 `body` 는 아직 없다 (FR-SBC-5).

**D-3 아이콘은 탭 서술자가 든다.** 표를 따로 두면 탭이 늘 때 고칠 자리가
둘이 된다 (§2.3, FR-SBT-21).

**D-4 상태는 localStorage 전용이다.** `sidebarWidth` 는 워크스페이스에도 있지만
그것은 옛 결정이고, 이 값의 성질은 `sidebarTab` 쪽이다 (FR-SBC-4). 서버 왕복을
더해서 얻는 것이 없다.

**D-5 토글 함수는 App 에 둔다.** `App.prototype._toggleSidebar` — 상태 변경·
저장·재적합이 한 자리에 모여야 나중에 단축키가 붙을 때 배선이 늘지 않는다.

## 6. 비목표

1. **사이드바 폭의 규약** — `--sb-w`·`ws.sidebarWidth`·드래그·100~400px 한계는
   그대로다. 접힘은 그 위에 얹히는 별개 상태다.
2. **모바일 드로어** — `#m-drawer-toggle` 이 이미 같은 필요를 채운다.
3. **단축키** — 접수한 말은 버튼이다. 붙일 자리는 D-5 가 남겨 둔다.
4. **탭의 구성·순서·배지 규약** — GIT_SIDEBAR_TABS_SRS 의 것이다. 늘어나는
   것은 서술자의 `icon` 필드 하나뿐이다.
5. **`#sb-bottom` 버튼의 구성** — `⟳`·`⚙` 가 무엇을 하는지는 이 SRS 밖이다.
