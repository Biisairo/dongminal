# 1.4.1 dmenv·dmlog

## 목표

환경변수 이름·홈 파일 이름·호스트 판정(dmenv)과 로그 계층(dmlog)을 옮긴다. dmlog 의 줄은 Go slog TextHandler 출력과 바이트 단위로 같아야 한다(시각 RFC3339 밀리초·로컬 시간대, 값 인용은 strconv.Quote 규칙 — dm-gocompat 을 쓴다). dmenv 는 의존이 없으므로 1.1 을 기다리지 않고 먼저 끝내도 된다. 공개 API 는 부모 이슈 1.4 의 진행 기록 "공개 API 안" 을 따른다. 바꿔야 하면 조정자에게 먼저 알린다.

## 대상 Go 코드

- `internal/shared/dmenv` (약 320줄)
- `internal/shared/dmlog` (약 200줄)

## 완료 조건

- 대상 Go 코드의 관측 동작을 Rust 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

- **review 요약**
  - crate: dm-shared-dmenv, dm-shared-dmlog
  - 공개 API(dmenv): `ENV_*`·`DEFAULT_*`·`CONTAINER_*`·홈 파일 이름 상수 전부, `helper_names`, `agent_hooks_dir_in`, `agent_shims_dir_in`, `millis_env(name, def, min: u64)`, `flag_env`, `or`, `is_unspecified_host`, `is_exposed_host`, `dial_host`, `listen_addr`, `base_url`, `exposure_label`
  - 공개 API(dmlog): `REQ_ID_HEADER`, `Level`, `ReqCtx<'a> = Option<&'a str>`, `Options { level, out }`, `init`, `reset`, `level`, `sanitize_req_id`, `new_req_id`, `Value::{Str, Int, Uint, Bool}`(+From), `log`, `debug/info/warn/error(ctx, msg, &[(k, Value)])`, 매크로 `debugf!/infof!/warnf!/errorf!(ctx, "fmt", ..)`
  - 옮긴 테스트: dmenv 14개(Go 7개 + netip 경계), dmlog 14개(Go 6개 + 형식·인용·수준 이름). 둘 다 통과. fmt·clippy 통과, 다섯 대상 cargo check 통과.
  - **Go 와 다르게 한 내부 결정**
    1. 요청 ID 는 `context.Context` 대신 `Option<&str>` 로 넘긴다.
    2. 서식 호출은 Go 의 가변 인자 함수 대신 매크로로 낸다.
    3. `Value` 는 실제 호출처가 쓰는 종류(문자열·정수·bool)만 둔다. 다른 값은 호출자가 문자열로 만들어 넘긴다.
    4. 표준 `log` 를 slog 로 돌리는 bridge 는 Rust 에 대응물이 없어 옮기지 않았다.
    5. `init` 전의 줄은 Go 의 slog 기본 핸들러 형식(`2006/01/02 15:04:05 LEVEL msg k=v`, info 이상, stderr)을 그대로 낸다.
    6. 환경변수를 바꾸는 검사는 edition 2024 에서 unsafe 가 필요하다. 그래서 읽은 값을 받는 내부 함수로 검사한다.
    7. 옮기지 않은 Go 검사: `TestEnvNamesLiveHere`(소스 리터럴 검사)
  - **남은 위험**
    1. `new_req_id` 의 난수 실패 대체 경로(`seq%d`)가 없다. `rand::fill` 은 OS 난수를 얻지 못하면 패닉한다. 실사용에서 일어날 일은 거의 없다.
    2. `millis_env` 에 Go 의 Duration 오버플로(약 9.2e15ms 이상)와 같은 감김 동작이 없다. 이런 값이 들어오면 Go 와 결과가 다르다.
