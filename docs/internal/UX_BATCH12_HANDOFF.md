## 3. 알려진 것 (이번 일과 무관하거나 남겨 둔 것)

- **기존 실패 e2e** (변경 전 코드에서도 실패한다): `git-history.spec.ts` H5(폭이 줄면 Commit → Date → Author 순으로 숨김), `ux-batch10.spec.ts:428`(나란히 보기에서 원본 쪽 찾기 — 나란히 보기가 서지 않음). 가끔 실패하는 것: `editor-ops.spec.ts` O7.
- **단위 시험 한 번 실패**: 이 세션에서 `make unit` 이 한 번 1건 실패했다. 어느 시험인지는 잡지 못했다. 그 뒤 세 번 다시 돌렸을 때는 모두 통과했다.
- **R18 기준선**: `e2e/baseline/ui-layout.{linux,win32}.json` 의 레일 요소 키와 이번의 `nav-ctl`·`nav-btn` 키는 darwin 에서 잰 값이다. 그 OS 의 CI 에서 다르면 그 OS 에서 다시 뜬다(새 키만 병합하는 절차는 아래 §4).
- **알려진 한계**: 접기를 켠 Diff 에서 그 칸에 직접 쳐서 변경을 만들면, 접기는 바로가 아니라 다음 갱신 때 돌아온다. 치는 중에 칸을 다시 세우면 입력 포커스를 잃기 때문이다(SRS FR-DNC-4 구현 메모). 뒤로·앞으로 기록에 싣는 커서는 편집기 탭만이다.

## 4. 다음 묶음이 알아 두면 좋은 것

- 전체 e2e 는 14분이다. 관련 스펙만 돌리고, playwright 를 두 개 동시에 돌리지 않는다(같은 서버 포트).
- `ui-layout-defaults.spec.ts` V-LAY-1 은 (화면, 태그+클래스) 키마다 **첫 요소**를 잰다. 숨은 새 요소가 같은 클래스 조합으로 앞에 서면 남의 키 값이 바뀐다. 새 요소에는 고유 클래스를 준다. 기준선은 원본 백업 → `LAYOUT_BASELINE=write` → 새 키만 병합 → 원본 복원 순서로 고친다.
- `@codemirror/merge` 의 "변경 없는 줄 접기"(`CollapsedRanges`)는 칸을 세울 때만 계산된다. 원본 쪽만 바꾸는 경로(`_cmSetOrig`)는 접기를 따라가지 않는다.
- git hunk 는 문맥 3줄로 만든다. 가까운 변경 여럿이 hunk 하나가 된다. 화면의 단위(변경 블록)는 `gitHunkBlockAt`(`core/hunk-coords.js`)이 준다.
- Python 으로 문서를 고칠 때 heredoc 안의 한글이 깨져 `SyntaxError: Non-UTF-8` 이 나는 일이 있었다. 스크립트를 파일로 쓰고 `# -*- coding: utf-8 -*-` 를 단다. 실패한 줄 뒤에 `&&` 없이 커밋을 이으면 빠진 채로 커밋된다.

## 5. 변하지 않는 규약

- 회귀 검사: `make unit`, `make gates`, `make lint`, `npm run typecheck --silent`, `go vet ./... && go test ./...`(Go 를 바꿨을 때), 바꾼 곳의 e2e 스펙만.
- 스펙과 코드가 부딪히면 멈추고 묻는다. 동작이 바뀌면 이전/새/이유를 SRS 에 적는다. 다른 SRS 의 조항을 개정하면 그 문서에 개정 한 줄을 남긴다.
- 커밋에 AI 서명을 넣지 않는다. push 하지 않는다. 사용자의 dongminal 을 재시작하지 않는다.
