# 5.2 허브·레코드 동기화·이음매 어댑터

## 목표

커맨드 브로드캐스트·git 관측 허브, 레코드 동기화, 이음매 어댑터를 옮긴다.

## 대상 Go 코드

- `internal/webserver/hub`
- `internal/webserver/recordsync`
- `internal/webserver/seam/adapters`

프로덕션 코드 약 2810줄.

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

## 진행 기록


- 시작 prod-pids: `38173 start --foreground` / `58470 d --handover-fd`
- 커밋(rp/5.2): `4af6735b` recordsync·adapters, `ea5a8a5f` hub.
- 공개 API 요약
  - `dm-webserver-recordsync`: `Writer::new(Sender) -> Arc<Writer>`, `start(CancellationToken)`, `put(kind, tool, &T)`(`()`/`None` = null 지우기), `flush()`. `Sender = Box<dyn Fn(&str,&str,RawMessage)->Result<(),SendError>>`, 거절 판정은 `SendError` 를 `RpcError` 로 downcast. Go nil Writer 는 소비자의 `Option<Arc<Writer>>`.
  - `dm-webserver-seam-adapters`: `ToolSource` trait(list·has·snapshot_tool·send_paste — Go ToolHub 중 쓰는 부분, toolclient 가 구현), `Tool{hub: Option<Arc<dyn ToolSource>>}`: ToolReader, `Client{hub}`: ClientToolResolver, `Workspace{ws: Arc<Manager>}`: WorkspaceReader.
  - `dm-webserver-hub`: `CommandBroker` trait(add·remove·broadcast·broadcast_and_await(BoxFuture)·deliver_result·observe_*), `CommandHub`(set_*_observer), `CmdSub`(recv·try_recv·closed·close·new), `CmdResult/TabRef/CmdPosition`, action 판정 함수들, `SUB_CAP`·`CMD_SUB_QUEUE`, `command_result_timeout`, `new_req_id`; `FocusRegistry`; `ReplySeats`+`SeatConn`(SafeConn 구현 포함, async); `AttnTracker`(probe 들은 동기 Arc<dyn Fn>, `start_sweeper(stop, mpsc::Receiver<()>)`, `sweep_idle_at`, mirror·restore·apply_attn); `ForegroundSource` trait + `start_foreground_poll`·`broadcast_foreground`·`foreground_snapshot`·`ticker(period, stop)`; `GitObserver`(Arc<Store> 구현) + `GitWatcher`(note/note_for/note_scoped/release_scope/attach/detach/tick/kick/set_worktree_every/훅) + `start_git_watch`; 페이로드 함수(background/update/claude_*). 상수(GIT_WATCH_*·GIT_KICK_*·SWEEPER_INTERVAL·FOREGROUND_INTERVAL)는 Go 값 그대로(FR-RSP-4).
- 옮긴 테스트: recordsync 5(nil 제외 전부), adapters 6, hub 63 — 총 74. Go hub 테스트 ~165 중 관측 동작(페이로드 바이트, 방송·상관, 포커스·좌석, 알람 판정, 거울, git 감시·임대·백오프·계기) 위주로 옮기고 같은 판정을 묶었다. 내부 전용(벤치, race, 로그 문구 비교 일부)은 옮기지 않았다.
- Go 와 다르게 한 내부 결정: ① Go `toolhub.ToolHub` 는 소비자 쪽 좁은 trait(`ToolSource`, `ForegroundSource`)로 정의(2.2.3 결정에 따름). ② `*CommandHub` 타입 단언 대신 `CommandBroker::observe_*` 기본 no-op 메서드. ③ 틱 주입은 `mpsc::Receiver<()>`, 정지는 `CancellationToken`. 동기 RPC(busy·list·record_set)는 `spawn_blocking`. ④ `ReplySeats::join/leave` 는 async(SafeConn::send 가 async). ⑤ GitWatcher 계기 타이머는 tokio spawn+abort, 테스트는 `AfterFn` 주입. ⑥ nil 수신자(Go nil *Writer/*GitWatcher)는 소비자의 `Option`.
- 남은 위험: Go 테스트 일부 미이식(gitwatch 느린 저장소 병렬·회차 시한 너머 status·SigChangeInvalidatesBefore 순서·QuietRepoCost, attn crossbrowser 일부). `GitObserver::observed` 대역은 늘 None 이라 "시한이 놓친 관측 채택" 경로 미검증. ring crate 없음 — adapters 만 3 대상 교차 clippy 통과, hub 는 tokio-tungstenite 의존이라 이 Mac 교차 검사 생략(OS 의존 코드 없음).
