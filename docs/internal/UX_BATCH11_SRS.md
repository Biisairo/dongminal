## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

`herdr-web-ui`(https://github.com/devswha/herdr-web-ui) 비교 검토(2026-10-01)에서 고른 넷을 한 묶음으로 정한다.

1. **터미널 복사·붙여넣기** — 선택 후 키로 복사하고, Win/Linux 에서 Ctrl+V 로 붙여넣고, 모바일에서도 선택·붙여넣기를 할 수 있게 한다.
2. **파일 경로 링크** — 터미널 출력의 `src/x.go:12:5` 를 누르면 편집기의 그 줄이 열린다.
3. **끊긴 동안의 입력** — 끊긴 사이 친 입력을 조용히 버리지 않고, 붙잡아 두었다가 사용자가 확인한 뒤 보낸다.
4. **주의 맥박 합성** — 보이는 모습은 그대로 두고 맥박이 매 프레임 다시 그리지 않게 한다.
5. **모바일 터치 스크롤** (개정 1) — 끌어도 스크롤이 안 되거나 손가락을 따라오지 않는 것을 고친다.

### 1.2 범위 (Scope)

- 포함: 터미널(xterm) 키 입력·선택·붙여넣기, 모바일 키바, 터미널 링크 공급자, 터미널 소켓 송신, 주의 맥박 CSS.
- 비포함: §5.

### 1.3 정의 (Definitions)

| 용어 | 뜻 |
|---|---|
| **mac** | `navigator.platform`/UA 로 판정한 Apple 플랫폼. 기존 판정(`IS_MAC` 계열)을 그대로 쓴다 |
| **단독 Ctrl+X** | `ctrlKey` 만 눌리고 `shiftKey`·`altKey`·`metaKey` 는 눌리지 않은 키 X |
| **보안 컨텍스트** | `window.isSecureContext` 가 참 — HTTPS 또는 localhost. `http://100.x` 원격은 아니다 |
| **쓰기 3단** | `ClipboardWriter.write` 의 `navigator.clipboard` → `execCommand('copy')` → 복사창 (FR-ETR-40) |
| **보고 응답** | xterm 이 질의에 스스로 답하는 바이트(`TERM_REPORT_RE`). 사용자 입력이 아니다 |
| **보류함** | 끊긴 동안의 사용자 입력을 담는 도구(소켓)별 메모리 버퍼 |
| **맥박** | `ATTENTION_PULSE_SRS` 의 2초 주기 주의 표식 애니메이션 |

## 2. 현재 상태와 검증된 사실

### 2.1 복사·붙여넣기

1. 복사의 유일한 화면 경로는 터미널 우클릭 메뉴의 "복사"다 (`web/js/ui/term-pane.js:110-113`). mac 의 Cmd+C 는 xterm 이 스스로 처리하는 `copy` 이벤트로 된다.
2. 단독 Ctrl+C 는 선택이 있어도 `0x03` 을 보낸다.
3. 터미널 상자의 keydown 이 Ctrl 이 눌린 키를 모두 `preventDefault` 한다 (`web/js/ui/term-input.js:40`). 그래서 Win/Linux 의 Ctrl+V 는 브라우저 붙여넣기가 일어나지 않고 `0x16` 이 간다.
4. `Ctrl+Shift+V` 는 세로 분할 단축키다 (`web/js/core/shortcuts.js` `splitV`).
5. 우클릭 "붙여넣기"는 `navigator.clipboard.readText` 를 쓰므로 보안 컨텍스트 밖에서는 비활성이다 (`term-pane.js:114-116`).
6. 쓰기 3단(`web/js/ui/clipboard.js`)은 보안 컨텍스트 밖에서도 사용자 제스처 안이면 `execCommand('copy')` 로 성공한다.
7. xterm 옵션(`web/js/core/constants.js:508` `TOPTS`)에 `macOptionClickForcesSelection` 이 없다. 그래서 mac 에서 마우스를 쓰는 TUI(vim·htop) 위에서는 드래그 선택을 강제할 길이 없다. 비-mac 은 xterm 기본인 Shift+드래그로 된다.
8. 모바일은 한 손가락 드래그가 스크롤이다 (`term-input.js` `_initTouchScroll`). slop(`MTI_TOUCH_SLOP_PX`=8) 이내의 탭만 xterm 에 간다. 터치로 선택할 길이 없다.
9. 모바일 키바(`MKB_KEYS`, `constants.js:146`)에 `^C`(raw `0x03`)·sticky `Ctrl` 이 있고, 붙여넣기 키는 없다.

### 2.2 파일 경로 링크

1. 터미널 링크는 `WebLinksAddon`(스킴 있는 URL)과 `bareLinkProvider`(맨 도메인, `web/js/ui/bare-link.js`)뿐이다. 파일 경로는 링크가 아니다.
2. `bareLinkProvider` 는 줄을 **칸 단위로** 읽어 넓은 글자의 자리 어긋남을 피한다. 기준 폴더는 그 도구의 `_cwd` 다.
3. `/api/file/stamps` 는 절대 경로 목록 중 **있는 파일만** 답한다 (`BARE_DOMAIN_LINK_SRS` §2-4).
4. `app.edOpenFile(abs,{line,col})` 은 편집기 탭을 열고 그 줄로 간다. `edOn()` 이 거짓이면 아무것도 하지 않는다 (`web/js/core/app-editor-file.js:18`).
5. 경로 조합은 `pathJoin`·`isAbsPath`(`web/js/core/path.js`)가 Windows 구분자까지 다룬다.

### 2.3 끊긴 동안의 입력

1. `TermSocket.send` (`web/js/ui/term-socket.js:127-136`)의 동작은 셋이다.
   - 열림(`OPEN`): 그대로 보낸다.
   - 여는 중(`CONNECTING`): 64개(`TERM_SEND_QUEUE_MAX`)까지 쌓았다가 열리면 **자동으로 보낸다**.
   - 그 밖(닫힘·소켓 없음): **버리고 `dropCount` 만 센다.** `dropCount` 는 테스트만 읽는다.
2. 끊기면 화면에는 "연결 끊김 — 재연결 중" 오버레이가 서지만(`term-pane.js` `_wsLost`), 그동안 친 키는 알림 없이 사라진다.
3. 사용자 입력과 보고 응답은 모두 `_sendText` → `OP.INPUT` 으로 나간다. 둘을 가르는 자리는 `_onTermData` 의 `TERM_REPORT_RE` 판정이다 (`term-input.js:103-116`).

### 2.4 주의 맥박

1. 맥박이 도는 일곱 자리 중 여섯은 `box-shadow`·`background`·`border-color` 를 키프레임으로 움직인다 (`web/style.css:735-762`, `web/style-sidebar.css:44`). 이 속성들은 합성기만으로 그릴 수 없어서 맥박이 도는 동안 **매 프레임 다시 그린다.**
2. 분할 칸(`.pn.attn::after`)만 `opacity` 를 움직인다.
3. FR-ATP-1(사용자 요청: "2초 주기로 천천히 사라졌다가")은 2초·`ease-in-out`·0/100% 표식 최대·50% 표식 사라짐이다.
4. e2e `attention-pulse.spec.ts` 의 `TARGETS` 는 자리마다 `[이름, selector, 속성, 겹]` 을 들고, 겹(`::after`)을 이미 다룬다.
5. 대상 여섯 자리에는 지금 `::before`·`::after` 를 쓰는 규칙이 없다.

### 2.6 설계 결정

- **D-9** 선택이 있을 때의 단독 Ctrl+C 복사 규칙은 **mac 을 포함한 모든 플랫폼**에 같게 적용한다. 한 규칙이 플랫폼마다 갈리면 원격 기기를 오갈 때 같은 손이 다른 결과를 낸다. 선택이 없으면 종전대로 `0x03` 이다.
- **D-10** 복사는 쓰기 3단 하나로만 쓴다 (FR-ETR-40). 새 쓰기 경로를 만들지 않는다.
- **D-11** 모바일 붙여넣기는 보안 컨텍스트면 클립보드를 바로 읽는다. 아니면 **입력칸 시트**를 띄워 사용자가 OS 기본 붙여넣기로 넣게 한다. 클립보드 읽기는 브라우저가 보안 컨텍스트 밖에서 주지 않으므로 다른 폴백이 없다.
- **D-12** 붙여넣기는 언제나 `term.paste(text)` 를 지난다. 그래야 브래킷 붙여넣기(`BRACKETED_PASTE_SRS`)가 PC 경로와 같게 적용된다.
- **D-13** 파일 경로 링크는 `bareLinkProvider` 와 같은 줄 읽기·같은 존재 확인(`/api/file/stamps`, 5초 기억)을 **공유**한다. 맨 도메인과 같은 글자가 실제 파일이면 파일 링크가 이긴다 — 맨 도메인 쪽이 이미 "그 이름의 파일이 있으면 링크가 아니다" 를 지키므로 새 규칙이 필요 없다.
- **D-14** 보류함에는 **사용자 입력만** 넣는다. 보고 응답은 그 순간의 질의에 대한 답이라 나중에 보내면 틀린 답이 되므로 보류하지 않고 종전대로 다룬다. 리사이즈도 종전대로다.
- **D-15** 보류함 배너가 떠 있는 동안 새로 친 입력은 **곧바로 보낸다.** 사용자는 연결된 화면을 보며 치고 있고, 보류분을 보낼지는 따로 묻는다.

### 2.7 모바일 터치 스크롤 (개정 1 — 실측·코드 확인)

1. 손가락 이동은 `MTI_TOUCH_GAIN`(2.5)을 곱해 한 프레임에 모은 뒤 **wheel 이벤트 하나**로 xterm 에 낸다
   (`term-input.js` `_touchScrollBy`·`_dispatchWheel`, FR-MTI-32).
2. **xterm 은 마우스 리포팅이 켜진 TUI 에 wheel 하나당 리포트를 하나만 보낸다** — 그 wheel 이 몇 행이든
   `getLinesScrolled` 가 0 이 아니면 `triggerMouseEvent` 한 번이다(번들 확인). 남는 행은 버려지고 소수부만
   이어진다. 그래서 빠르게 끌수록 움직임 대부분이 사라진다. **D-19 의 증상과 2.5 배가 그것을 덮던 까닭이다.**
   (보통 버퍼는 픽셀로 스크롤하므로 잃지 않는다. 마우스 리포팅이 꺼진 대체 화면은 행 수만큼 화살표를 낸다.)
3. 관성의 속도는 **마지막 touchmove 한 번의 이동량**을 "프레임당 속도" 로 쓴다(`_tsV=dy`). 손을 떼기 직전
   이벤트의 크기에 따라 관성이 없거나 튀고, 터치 샘플링이 120 Hz 인 기기에서는 절반이 된다.
4. slop(8 px)을 넘으면 **그 거리를 버리고** 시작한다 — 출발이 한 박자 늦다.
5. wheel 의 좌표가 터미널 **한가운데**다. 마우스 리포트는 그 칸을 싣는다 — 창이 갈린 TUI(vim 분할 등)에서는
   손가락 밑이 아닌 칸이 스크롤된다.
6. 터치 스크롤과 `touch-action:none` 은 **모바일 레이아웃(`body.mobile`)일 때만** 선다. 데스크톱 레이아웃의
   터치 기기(태블릿)에서는 xterm 의 1:1 터치 경로만 남고, 대체 화면 TUI 는 스크롤되지 않는다.
7. 비교 — herdr-web-ui(`PaneTerminal.tsx` 676-708): touchmove 마다 1:1 delta 를 손가락 좌표로 담아 wheel 을
   곧바로 낸다. 관성은 없다. 행 누적은 xterm 의 소수부 누적에 맡긴다.

### 3.2 파일 경로 링크 (FR-FPL)

| ID | 요구사항 | 우선 |

### 3.3 끊긴 동안의 입력 (FR-HIN)

| ID | 요구사항 | 우선 |
|----|---------|------|
| FR-HIN-1 | 소켓이 **한 번이라도 열린 뒤**, 열림이 아닌 동안(여는 중 포함)의 **사용자 입력**은 보내지도 버리지도 않고 그 도구의 보류함에 순서대로 넣는다. 보고 응답과 리사이즈는 보류하지 않고 종전대로 다룬다 (D-14). | 필수 |
| FR-HIN-2 | 한 번도 열린 적 없는 소켓의 여는 중 큐(`TERM_SEND_QUEUE_MAX`)는 종전대로 두고 열리면 자동으로 보낸다 (D-6). | 필수 |
| FR-HIN-3 | 보류함 상한은 UTF-8 64KiB 다. 넘치는 입력은 넣지 않고 "일부를 담지 못했다"는 표시를 세운다. 이미 담긴 앞부분은 지킨다 — 입력은 순서가 뜻이므로 앞을 밀어내지 않는다. | 필수 |
| FR-HIN-4 | 재연결로 소켓이 열렸을 때 보류함이 비어 있지 않으면 그 터미널 위에 배너를 세운다. 배너에는 담긴 바이트 수, 미리보기(앞 200자; 제어 문자는 `^X`, ESC 는 `^[`, CR·LF 는 `⏎`), FR-HIN-3 표시, [보내기]·[버리기]가 있다. **저절로 보내지 않는다.** | 필수 |
| FR-HIN-5 | [보내기]는 보류함을 담긴 순서대로 보내고 비운 뒤 배너를 걷는다. [버리기]는 보내지 않고 비운 뒤 배너를 걷는다. | 필수 |
| FR-HIN-6 | 배너가 떠 있는 동안 새로 친 입력은 곧바로 보낸다 (D-15). 배너가 떠 있는 채 다시 끊기면 보류함은 남고, 이후 입력은 그 뒤에 이어 담긴다. | 필수 |
| FR-HIN-7 | 보류함은 메모리에만 있다. 탭 닫힘·새로고침·도구 종료(`OP.EXIT`)에서 버린다. | 필수 |
| FR-HIN-8 | 배너 문구는 i18n 카탈로그(ko·en)에 둔다. 배너는 `role="status"` 이고 두 버튼은 키보드로 닿는다. | 필수 |

### 3.4a 모바일 터치 스크롤 (FR-MTS, 개정 1)

| ID | 요구사항 | 우선 |
|----|---------|------|
| FR-MTS-1 | 스크롤 이동은 **행 단위 wheel 여러 개**로 낸다. 모은 픽셀을 그 터미널의 행 높이로 나눠, 한 행마다 `deltaY = ±행 높이` 인 wheel 을 하나씩 내고 나머지는 다음으로 넘긴다 — 마우스 리포팅 TUI 에서 한 행이 리포트 하나가 되어 **움직임을 잃지 않는다** (§2.7-2). 내는 때는 종전대로 프레임당 한 번이다(FR-MTI-32의 병합은 유지, 한 wheel 로 합치는 것만 바뀐다). | 필수 |
| FR-MTS-2 | `MTI_TOUCH_GAIN` 은 **1** 이다 — 글자가 손가락을 따라온다. 종전 2.5 는 FR-MTS-1 의 손실을 메우던 값이다 (D-19, `MOBILE_TUI_INPUT_SCROLL_SRS` FR-MTI-6 개정). | 필수 |
| FR-MTS-3 | wheel 의 좌표는 **마지막 손가락 위치**다(관성 중에는 손을 뗀 자리). | 필수 |
| FR-MTS-4 | slop 을 넘으면 **시작점부터의 거리 전부**를 스크롤에 넣는다. | 필수 |
| FR-MTS-5 | 관성의 처음 속도는 최근 `MTI_VELOCITY_WINDOW_MS`(100 ms) 안의 터치 표본으로 잰 **px/ms** 다(첫 표본과 마지막 표본의 거리 ÷ 시간). 마지막 표본이 손을 뗀 때보다 그 창 이상 오래됐으면(멈췄다 뗐으면) 관성이 없다. 관성은 프레임 사이 실제 경과 시간으로 진행하고 감쇠도 경과 시간에 맞춘다(`MTI_FLING_DECAY` 는 16.67 ms 당). 상한·하한은 `MTI_FLING_MAX_V`·`MTI_FLING_MIN_V` 를 px/ms 로 고쳐 쓴다. | 필수 |
| FR-MTS-6 | 터치 스크롤(과 FR-TCP-7)은 모바일 레이아웃이거나 **주 포인터가 coarse**(`(pointer: coarse)`)일 때 선다. 그 둘에서 터미널 칸은 `touch-action:none` 이다. | 필수 |
| FR-MTS-7 | 탭(slop 미만)·포커스·소프트 키보드의 종전 동작(FR-MTI-9·22·29)은 그대로다. | 필수 |

## 5. 비목표 (Non-goals)

1. 놓는 순간 복사 (D-1).

6. 맥박의 주기·색·모양 변경.
7. 문제 보고 버튼 (D-8).
8. 터미널 출력 흐름 제어(ACK) — 별도 측정 과제로 분리.
