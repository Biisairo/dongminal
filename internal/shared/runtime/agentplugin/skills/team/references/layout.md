# 레이아웃 설계 이유

## 기본은 전용 창이다

팀은 `dmctl new-window --name <이름> -n --cwd "$PWD"` 로 만든 **자기 창**에서 산다. `--cwd` 를 생략하면 그 창은 홈에서 뜬다 (WORKBENCH_REVIEW_SRS FR-WBR-22). 사용자의 창을 쪼개지 않으므로 침범할 표면 자체가 없다.

이전 설계는 조정자의 분할 칸을 쪼개어 팀을 만들었고, 그래서 스킬 규칙의 상당 부분이 **사용자 공간 방어**에 쓰였다 — `--no-focus` 강제, `dmctl focus` 전면 금지, 셀 비율 보정 레이아웃 계산. 전용 창은 그 방어를 규칙이 아니라 **구조로** 푼다.

실측으로 확인한 것 (사용자 창 6개가 열린 워크스페이스에서):

- `dmctl new-window ... -n` 응답이 `newWindows[0]`(창 uuid)·`newTabs[0]`(시드 탭)을 직접 준다. `list-workspace` 로 되찾을 필요가 없다
- 전용 창을 만들고 그 안에서 분할한 뒤에도 **포커스 소유권과 사용자 창 6개가 무변경**
- 팀원 탭을 전부 닫으면 **전용 창이 스스로 사라진다**. `close-window` 를 호출할 일이 없다

전용 창에서는 사용자 화면의 가로세로 비율이 무관하다. 단순 균등 분할(`dmctl split-h "$N" --at "$SEED" -n`)로 충분하며 레이아웃 계산이 필요 없다.

## `inline` 을 쓸 때만 계산이 필요하다

조정자 옆에서 팀 활동을 바로 보고 싶을 때 `inline`(사용자 창 분할)을 선택할 수 있다. 이때는 사용자 창을 쪼개므로 비율이 실제로 문제가 된다.

### 셀 비율 보정 (`ROWS × 2.2`)

터미널 셀은 정사각형이 아니다. 셀 높이는 너비의 약 **2.2 배** (폰트·라인스페이싱에 따라 2.0~2.5). `dmctl who-am-i` 의 `size=COLSxROWS` 를 그대로 비교하면 시각 결과와 어긋난다.

- `COLS >= ROWS * 2.2` → 가로가 시각적으로 더 긺 → 1차 `dmctl split-h` (좌↔우)
- 반대면 1차 `dmctl split-v` (상↕하)
- 경계에서는 `split-v` 쪽이 보수적으로 안전 (가로 공간이 보존돼 각 팀원 셀폭 여유 확보)

`scripts/plan_layout.py` 가 수행한다. 직접 계산하지 말고 스크립트를 호출할 것.

### 긴 축 먼저 → 직교 축으로 N 등분

짧은 축을 먼저 나누면 팀 분할 칸이 납작해져 팀원 터미널이 사용 불가능한 크기가 된다. 긴 축을 먼저 쪼개 팀 분할 칸을 확보한 뒤, 그 내부를 직교 축으로 한 번에 `dmctl split-* N` 로 분할한다.

이진 분할을 (N−1) 번 중첩하면 50/25/25 같은 불균등 결과가 나온다. `N` 위치 인자 단일 호출은 정확한 균등 N 등분이며 왕복 수도 줄어 레이스 표면적이 작다.

| 환경 | 판정 | 1차 | 2차 |
|------|------|-----|-----|
| COLS=200 ROWS=50 N=3 | `200 >= 110` | `split-h` | `split-v 3` |
| COLS=132 ROWS=63 N=2 | `132 < 138.6` | `split-v` | `split-h 2` |
| COLS=80 ROWS=80 N=4 | `80 < 176` | `split-v` | `split-h 4` |

## 포커스

모든 레이아웃 명령은 `--at <uuid>` + `--no-focus`(`-n`) 조합이다. `--at` 을 지정한 `dmctl close-tab` 은 서버가 포커스를 건드리지 않는다.

`dmctl focus` 는 이 스킬에서 **호출하지 않는다** — 복원 목적 포함. 전용 창이 기본이라 되돌릴 일이 없고, 사용자가 그 사이 다른 분할 칸으로 이동했을 수 있어 "원위치 복원" 이 오히려 엉뚱한 곳으로 포커스를 보낸다.

## 식별자 안정성 — UUID

`W?.P?.T?` 라벨은 workspace.json 배열 위치로부터 매번 재계산되는 positional 좌표다. 다른 창·분할 칸이 닫히면 후속 라벨이 reflow 된다. 보관해둔 라벨이 다른 탭을 가리키는 순간 정리·라우팅이 깨진다.

생성 명령(`new-window`·`split-*`)의 응답이 uuid 를 직접 주므로 보관할 것은 그것이다. 그리고 팀원 매핑의 진실은 대화 기록도 라벨도 아닌 **`dmctl run status --run <uuid>`** 다 — 컨텍스트가 압축돼도 남는다.
