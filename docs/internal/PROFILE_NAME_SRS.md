# SRS: 프로필 이름 — 이름#번호 한 곳에서 정하기 — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: 데몬 모드 검증. e2e 전량은 2026-11-22 에 통과했다

## 1. 개요

### 1.1 목적

사용자 요구 (2026-11-18):

> *"display 에 페이지 제목, access 에 내 이름과 별명, 주소, 도메인이름, access 에 상대
> 이름과 별명, 주소, 도메인이름, edge 에 내 이름. 지금 이름 별명 주소 등등 너무 많은곳에서
> 수정을 하고 있어. 이거 좀 하나로 합치고 싶어."*
>
> *"모든곳에서 discord 나 블리자드처럼 이름을 설정. 이름은 내 맘대로 정할 수 있고 그 뒤에
> 숫자나 uid 를 붙여서 유사 uid 를 생성. 이 이름으로 모든 경우에 사용 가능하도록 진행.
> 뒤에 붙는 난수를 edge 의 지문으로 해도 좋겠네."*
>
> *"프로필창을 만들고 거기서 진행. 지문은 수정불가, 실행시 즉각적으로 생성됨."*

이 기기의 이름을 **프로필 패널 한 곳**에서 정한다. 이름 뒤에는 노드 지문에서 만든 번호
네 자리를 붙여 `이름#번호` 를 만든다. 이 값을 이 기기를 가리키는 모든 자리에 쓴다.

### 1.2 범위

포함:

- 설정 창의 새 **프로필** 패널 — 이름 입력, 번호·지문 표시.
- 이름 규칙과 번호 계산 (`internal/shared/edge`).
- Display ▸ 페이지 제목 칸 제거. 브라우저 탭 제목과 Telegram 기기 이름이 프로필 이름을 쓴다.
- Edges ▸ 이 노드의 이름 칸 제거. 간선 목록이 상대를 `이름#번호` 로 표시한다.
- Access ▸ 축②(이 서버를 부르는 이름) 의 별명(라벨) 칸 제거. 도메인만 입력한다.
- `otterctl edges`·`otterctl edge remove` 가 `이름#번호` 를 표시하고 받는다.

비포함 (비목표):

- Access ▸ 축①(접속을 허용할 상대)의 판정 규칙. 이름표 칸만 없앤다(FR-PFN-33).
- Edges ▸ 알릴 주소, Access ▸ 축② 도메인 목록의 통합.
- 노드 망 채팅이 상대에게 알리는 이름의 형식. 채팅은 지금처럼 `Config.Name` 을 읽는다.
- 지문(노드 신원) 다시 만들기.

### 1.3 정의

- **이름**: 사용자가 정하는 문자열. 규칙은 FR-PFN-2.
- **지문**: 노드 신원 인증서의 SHA-256, 16진수 소문자 64자 (`edge.Identity.Fingerprint`).
- **번호**: 지문에서 계산한 10진수 네 자리 (FR-PFN-4).
- **핸들**: `이름#번호`. 예: `동민#0427`.

## 2. 현재 상태 (조사로 확정)

| 자리 | 값 | 저장 | 규칙 | 쓰임 |
|---|---|---|---|---|
| Display ▸ 페이지 제목 (`ds-title`) | 자유 문자열 | `settings.json` `pageTitle` | 60자 | `document.title`, Telegram 기기 이름 (`telegram_wire.go` `device()`) |
| Edges ▸ 이 노드 (`eg-name`) | 노드 이름 | `edges.json` `name` | `[A-Za-z0-9._-]` 1~32자 (FR-PNW-3) | 짝맞춤 때 상대에게 알림, 채팅 |
| Access ▸ 축② (`acl-host-list`) | 도메인 + 라벨 | `access.json` `hosts` | 호스트명 + 자유 라벨 | Host 허용 |
| Edges ▸ 간선 목록 | 상대 이름 · 지문 16자 · 주소 | `edges.json` `edges` | 상대가 알린 이름 (64바이트) | 표시 |

- 지문은 `edgenode.New` → `edge.LoadOrCreateIdentity` 가 기동할 때 만든다. 노드 포트를 꺼도
  만든다. 사용자는 이 값을 바꿀 수 없다.
- `otterctl edge remove` 는 지문 앞자리 8자 이상만 받는다 (`Store.Resolve`, FR-EPR-30).

## 3. 요구사항

### 3.1 기능 요구사항

**프로필 이름**

- **FR-PFN-1** 이름은 `edges.json` 의 `name` 한 곳에만 저장한다. 다른 자리는 이 값을 읽는다.
- **FR-PFN-2** 이름은 영문 대소문자·한글 음절(`가`–`힣`)·숫자·`_`·`-` 로 된 1~32자(룬 기준)
  이고, UTF-8 로 64바이트 이내다(한글은 21자까지). 다른 문자가 있거나 길이를 넘으면 저장할 때
  거절한다.
- **FR-PFN-3** 저장된 이름이 FR-PFN-2 에 맞지 않으면(옛 규칙의 `.` 등) 읽을 때 허용하지
  않는 문자를 `-` 로 바꾸고 FR-PFN-2 의 길이 안으로 자른다. 결과가 비면 기존 기본 이름 규칙(호스트 이름,
  없으면 `node`)을 쓴다. 바뀐 값은 다음 저장 때 디스크에 쓴다.

**번호와 핸들**

- **FR-PFN-4** 번호는 지문 앞 8자리(16진수)를 부호 없는 32비트 정수로 읽고, 10000 으로 나눈
  나머지를 네 자리로 0 채운 값이다. 예: 앞자리 `00001a2b`(=6699) → `6699`.
- **FR-PFN-5** 번호는 저장하지 않고 받지도 않는다. 각 노드가 자기 지문과 간선의 지문에서
  직접 계산한다. 그러므로 구버전 상대도 같은 번호로 표시된다.
- **FR-PFN-6** 핸들은 `이름 + "#" + 번호` 다. 지문이 없으면(신원을 읽지 못함) 이름만 쓴다.

**프로필 패널**

- **FR-PFN-10** 설정 창에 **프로필** 패널을 더한다. 내용은 다음과 같다.
  - 이름 입력 칸 (편집 가능)
  - `#번호` (읽기 전용, 이름 칸 바로 옆)
  - 지문 전체 64자 (읽기 전용, 복사 가능)
  - 저장 버튼과 상태 줄
- **FR-PFN-11** 저장은 서버가 FR-PFN-2 로 검증한다. 거절하면 사유를 상태 줄에 보이고 아무것도
  바꾸지 않는다.
- **FR-PFN-12** 저장에 성공하면 브라우저 탭 제목을 곧바로 바꾼다.
- **FR-PFN-13** 낡은 값 덮어쓰기를 막는 기존 규약(ETag, UX_BATCH12 FR-LIV-5)을 따른다.

- **FR-PFN-14** 패널이 열린 동안 다른 창·기기가 노드 설정을 바꾸면(`edges_changed`) 패널이 따라간다.
  고치던 값이 없으면 다시 그리고, 있으면 덮지 않고 "설정이 바뀌었습니다" 안내를 띄운다
  (UX_BATCH12 FR-LIV-4·6 과 같은 규약). 이 창이 저장하는 중에 온 방송은 안내를 띄우지 않는다.

**이름을 쓰는 자리**

- **FR-PFN-20** 브라우저 탭 제목은 이름이다(번호 없음). 알림 수 표시 `(n) ` 접두는 지금과
  같다. 이름을 읽지 못하면 `Otterminal` 이다.
- **FR-PFN-21** Telegram 알림의 기기 이름은 핸들이다.
- **FR-PFN-22** Edges ▸ 간선 목록의 한 줄은 `상대 핸들 · 주소:포트` 다. 지문 앞 16자리는 그
  줄의 툴팁으로 옮긴다. 짝맞춤·끊김 알림도 상대를 핸들로 부른다.
- **FR-PFN-23** `otterctl edges` 는 이 노드와 각 간선을 핸들로 표시한다. `--json` 에는
  `tag`(번호) 필드를 더한다. 기존 필드는 바꾸지 않는다.
- **FR-PFN-24** `otterctl edge remove` 와 `Store.Resolve` 는 지문 앞자리에 더해 핸들(`이름#번호`,
  이름은 대소문자 무시)을 받는다. 둘 이상의 간선에 맞으면 `ErrAmbiguous` 다.

**제거**

- **FR-PFN-30** Display ▸ 페이지 제목 칸과 `pageTitle` 설정 키를 없앤다. 기존 `settings.json`
  의 `pageTitle` 값은 읽지 않는다(지우지는 않는다).
- **FR-PFN-31** Edges ▸ 이 노드의 이름 칸을 없앤다. 그 자리에 핸들을 읽기 전용으로 보이고
  "프로필에서 바꿉니다" 안내를 둔다. `PUT /api/edges/node` 는 `name` 이 없으면 기존 이름을
  유지한다.
- **FR-PFN-32** Access ▸ 축②의 라벨 칸을 없앤다. 서버는 축② 항목의 `label` 을 저장하지 않는다.
- **FR-PFN-33** Access ▸ 축①의 이름표 칸도 없앤다 (사용자 결정 2026-11-18: 이름표는 판정에 쓰이지 않는
  메모다). 서버는 `access.json` 의 `label` 을 읽을 때 버리고, 다음 저장 때 디스크에서도 사라진다.
  `GET /api/access` 응답에 `label` 이 없다.

### 3.2 인터페이스

- `GET /api/profile` → `{ "name": string, "tag": string, "handle": string, "fingerprint": string }`
- `PUT /api/profile` ← `{ "name": string }` → 위와 같은 모양. 검증 실패는 400 과 사유.
- `GET /api/edges` 의 `node` 와 각 `edges[]` 항목에 `tag` 를 더한다.
- `POST /api/edges/add` 의 응답과 `edges_changed` 방송의 `paired`·`removed` 에 `tag` 를 더한다.

### 3.3 비기능 요구사항

- **NFR-PFN-1** 번호 계산은 결정적이다. 같은 지문은 어느 노드·언어(Go·JS)에서도 같은 번호를
  낸다. 계산은 서버(Go) 한 곳에서 하고, 화면은 서버가 준 `tag` 를 쓴다.
- **NFR-PFN-2** 기존 `edges.json`·`access.json`·`settings.json` 을 그대로 읽는다. 마이그레이션
  실패로 서버가 서지 못하는 일은 없다.
- **NFR-PFN-3** 서버는 핸들을 기억해 두고, 노드 설정이 바뀌었다는 신호(`edges_changed` 를 내는 자리)에서만
  버린다. Telegram 알림마다 노드(데몬 모드에서는 IPC)를 부르지 않는다. 노드가 답하지 못한 결과는
  기억하지 않는다.

## 4. 동작 변경 기록

| 항목 | 이전 동작 | 새 동작 | 이유 |
|---|---|---|---|
| 브라우저 탭 제목 | Display ▸ 페이지 제목, 비면 `Otterminal` | 프로필 이름 | 이름을 한 곳에서 정한다 |
| Telegram 기기 이름 | 페이지 제목, 비면 호스트 이름 | 핸들 | 같은 이름을 쓰는 기기를 번호로 구별한다 |
| 노드 이름 규칙 | `[A-Za-z0-9._-]` 1~32자 | 영문·한글·숫자·`_-` 1~32자 | 한글 이름 허용. `.` 은 `#` 구분과 함께 쓰면 헷갈린다 |
| 간선 표시 | `이름 · 지문16 · 주소` | `이름#번호 · 주소` | 사람이 부르는 값으로 표시 |
| 축② 라벨 | 입력·저장 | 입력 칸 없음, 저장 안 함 | 별명은 프로필 이름 하나로 |
| 축① 이름표 | 입력·저장 | 입력 칸 없음, 저장 안 함 | 판정에 쓰이지 않는 메모였다 |

## 5. 가정과 리스크

- **A-1 (중요)** 번호는 10000 가지라서 두 노드가 같은 번호를 가질 수 있다(개인 망 규모에서는
  드물다). 이름까지 같으면 핸들로 찾을 때 `ErrAmbiguous` 가 나고, 지문 앞자리로 가리켜야 한다.
- **A-2** 기존 `pageTitle` 은 프로필 이름으로 옮기지 않는다. 사용자가 프로필에서 한 번 다시
  정한다.
- **R-1 (LOW)** 구버전 상대는 알린 이름을 `ValidDisplayName`(64바이트 유니코드)으로 받는다.
  FR-PFN-2 가 64바이트로 제한하므로 한글 이름도 그대로 받는다.
- **R-2 (LOW)** 채팅은 `Config.Name` 을 그대로 읽으므로 한글 이름이 채팅에도 나간다.

## 6. 검증

- Go 단위: 이름 검증(FR-PFN-2, 경계 0·1·32·33자·한글 21·22자, 한글 자모 단독 거절, `#`·`/`·`.`·공백 거절),
  옛 이름 정규화(FR-PFN-3), 번호 계산(FR-PFN-4, 고정 벡터), 핸들(FR-PFN-6), 핸들로 찾기·모호함
  (FR-PFN-24), `/api/profile` GET·PUT·400, 축② 라벨 비우기(FR-PFN-32), Telegram 기기 이름.
- JS 단위: `edgeWho` 가 핸들 형식을 낸다. 설정 스키마에 `pageTitle` 이 없다.
- e2e: 프로필에서 이름을 저장하면 탭 제목이 바뀌고 Edges 패널에 핸들이 보인다.
