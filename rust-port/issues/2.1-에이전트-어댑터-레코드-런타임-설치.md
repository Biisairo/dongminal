# 2.1 에이전트 어댑터·레코드·런타임 설치

## 목표

에이전트 어댑터 레지스트리, 에이전트 세션 레코드(agents.json·agents/*.jsonl), handover 레코드, 런타임 헬퍼·셸 훅·에이전트 플러그인 설치(`internal/shared/runtime` 의 임베드 자산 포함)를 옮긴다. 설치 결과(파일 경로·내용·권한·symlink)가 Go 와 같아야 한다 (FR-RSP-13).

## 대상 Go 코드

- `internal/shared/agentadapter`
- `internal/shared/agentrec`
- `internal/shared/handover`
- `internal/shared/runtime`

프로덕션 코드 약 2291줄.

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

### 2026-11-23 재개 → review (커밋 74bbc347 · 64321dfb · 960b6fe7 · fc7bd6e9, rust-port 병합 위)

- 시작 prod-pids.sh: `38173 start --foreground` / `58470 d --handover-fd`
- 끝 prod-pids.sh: `38173 start --foreground` / `58470 d --handover-fd` (같다)
- 게이트: `cargo fmt --all --check`, 네 crate 의 `cargo clippy --all-targets -D warnings`(호스트·x86_64-pc-windows-msvc·x86_64/aarch64-unknown-linux-gnu), 격리 실행 `cargo test` 모두 통과.

**공개 API 요약**
- `dm-shared-agentadapter`: `get(id) -> Result<&'static Adapter, Error>`, `ids()`, `by_command`, `status_line_reporter() -> Option<&str>`, `shim_commands()`. `Adapter` 의 필드는 Go 와 같다. Go 의 nil 함수는 `Option<fn>` 이다(`hook_parse` 는 `fn(&[u8]) -> Option<Report>`). `Adapter::{launch_line, launch_line_in(&dyn ShellProvider, …), resume_line, resume_line_in, can_resume, installed}`, `valid_session_id`, `InstallSpec{dir, plugin_dir, dmctl}::hook_command(&[&str])`. 상수는 `HOOKS_DIR_TOKEN`·`BRIDGE_INPUT_MAX`·`OMP_SHIM_FILE`·`OMP_MEMBER_CONFIG_FILE` 이다. `Error` 는 enum 이고, `Display` 는 Go 문구와 같다.
- `dm-shared-agentrec`: 보고 와이어 타입(`Request`·`Reply`·`ActivityReport`·`ReportAccount`·`NotifyReport`·`SubagentActivity`)은 직렬화와 해석을 모두 한다. `UsageReport`·`SubagentsReport`·`Usage`·`SubagentList`·`LimitRecord` 는 직렬화만 한다(아래 위험 1). 함수는 `socket_path`·`known_method`·`notify_reason`·`sanitize`·`subagent_activity_of`·`put_subagent_activity(&mut BTreeMap, …)`·`merge_limits(&mut BTreeMap, …)`·`agent_reports_turn_start` 이고, 상수 METHOD_*·IO_TIMEOUT 등이 있다.
- `dm-shared-handover`: `reload(home, exe, within) -> Outcome`, `hello`, `classify(&Reply, Option<&str>)`, `parse_daemon_args(&[String]) -> Result<DaemonArgs, String>`, `ReloadRequest`, `Kind`, 상수(사유 코드·메서드·ARG_*)가 있다.
- `dm-shared-runtime`: `install(bin)`, `install_with(bin, self_exe)`(공개. Go 에서는 비공개였다), `ensure_installed`, `inspect_helpers -> HelperStatus{installed, problems}`, `agent_plugin_dir`, `agent_memory_dir`, `HELPER_NOT_INSTALLED`, `HELPER_FIX_HINT`. 오류는 Go 와 같은 문구를 담은 `io::Error` 다.

**테스트**: 옮긴 Rust 테스트는 68개다(agentadapter 31, agentrec 11, handover 8, runtime 18). runtime 의 `tests/go_parity.rs` 는 `testdata/goref`(Go 참조 프로그램)를 빌드한다. 같은 bin 자리에 Go 로 한 번, Rust 로 한 번 설치하고 경로·종류·권한·내용·symlink 대상을 바이트 단위로 비교한다. 경우는 fresh(빈 bin)·stale(묵은 상태를 둔 bin)·ephemeral(`go run` 처럼 임시 경로의 실행 파일) 셋이며 모두 같다. `go` 가 없으면 건너뛴다.

**Go 와 다르게 한 내부 결정**
- 임베드 자산을 `rust/crates/shared/runtime/assets/` 로 복사했다. `include_bytes!` 정적 목록으로 넣는다. 시험이 목록·디스크·Go 트리가 같은지 확인한다.
- `os.MkdirAll` 은 0o755 로 직접 짰다(std `create_dir_all` 은 0o777&umask 다). 거울 정리(prune)는 Go WalkDir 처럼 이름 순으로 훑고, 링크를 따라가지 않는다.
- handover: gocompat Decoder 가 바이트만 받으므로, 값 하나가 끝날 때까지 읽는 루프를 crate 안에 두었다. 시한은 읽기마다 남은 시간으로 다시 건다.
- 옮기지 않은 Go 테스트: skills_contract·openurl_hook·bashhook·pshistory 의 문서·셸 내용 검사. 자산이 Go 트리와 바이트 단위로 같다는 시험이 대신한다. `TestInstallWritesNothingOutsideItsBinDir`·`TestInstallDoesNotTouchOmpHome` 도 옮기지 않았다. Rust 설치는 HOME 을 읽지 않고, Go 와 같은 bin 결과라는 것을 비교 시험이 보인다. `TestShellHooksPutShimsFirst` 는 셸 훅 내용이 같으므로 생략했다.

**남은 위험**
1. `dm-shared-statusline` 의 `Usage`·`Subagent`·`RateWindow` 등에 `Deserialize` 가 없다. 그래서 agentrec 의 레코드 다섯 개는 직렬화만 한다. 데몬·서버 이슈가 이 레코드를 해석하려면 statusline crate 를 고쳐야 한다(조정자 판단 필요).
2. `dm-shared-platform::copy_executable` 은 덮어쓸 자리가 빈 디렉터리이면 옆으로 밀어 둔 `<dst>.old` 디렉터리를 남긴다. Go 는 `os.Remove` 로 빈 디렉터리도 지우므로 남기지 않는다. 비교 시험에서 확인했고, 그 경우는 시험에서 뺐다. 1.4 쪽에서 고칠 일이다.
3. omp 멤버 오버레이의 `match: "dmctl *"` 은 omp 가 복합 명령을 나누지 않으면 `dmctl x; 다른명령` 까지 허용할 수 있다(보안 검토 지적). Go 기준선을 바이트 그대로 옮긴 것이라 바꾸지 않았다. 원 SRS(OMP_AGENT_SUPPORT_SRS)에서 다룰 일이다.
4. Windows 에서 `mkdir_all` 의 ENOTDIR 문구와 `is_ephemeral_exe` 의 임시 디렉터리 판정은 근사다(Windows 실행 시험 없음).
