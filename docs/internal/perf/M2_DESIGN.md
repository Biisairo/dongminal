### 1.2 데몬 → 서버

- 데몬은 연결 하나로 **모든 도구의 출력**을 서버에 민다(JSON 줄 `OutputEvent{tool,data,end}`). 서버가 구독했는지와 상관없다. 큐가 차면 그 조각을 버린다(`droppable`). — `rust/crates/daemon/ipc/src/server.rs:402~418`, `daemon/ipc/src/conn.rs:122~150`
- 서버 쪽 `ToolClient::subscribe(tool, tx)` 는 채널의 sid 마다 받는 곳을 하나씩 단다. 같은 도구를 여러 브라우저가 보면 받는 곳이 여럿이고, 데몬의 도구는 하나다. — `rust/crates/webserver/toolclient/src/push.rs:248`
- 데몬 기능은 `hello` 의 기능 이름으로 알린다(`FEATURE_SNAPSHOT_NOT_FOUND` 등). 새 IPC 기능은 이 방식으로 판을 가린다. — `rust/crates/shared/toolipc/src/protocol.rs:71~94`
- 서버는 데몬 판을 건강 정보에 싣기만 한다. 판이 달라도 데몬을 스스로 교체하지 않는다(`httpapi/src/health.rs`, 구현 전 다시 확인).

### 1.5 화면 읽기 (`read-screen`)

- `otterctl read-screen` 은 `GET /api/tools/output?strip=1&bytes=16384` 를 부른다. 서버는 **데몬 링의 마지막 16 KB 바이트에서 ANSI 를 걷어 낸 글자**를 준다. 실제 화면 격자가 아니다. TUI 화면에서는 지운 글자·덮어쓴 글자가 섞여 나온다. — `helper/runtimebin/src/otterctl/toolio.rs:20~66`, `httpapi/src/toolio.rs:110~155`, `httpapi/src/ansi.rs:13`, `webserver/seam/adapters/src/lib.rs:51`
- 이미 브라우저와 상관없이 서버·데몬이 답한다. 잠든 터미널에도 지금 답한다.
- `read-output` 은 같은 길에서 ANSI 를 걷지 않은 바이트(기본 8 KB)를 준다.

### 1.6 조사에서 드러난 것 (설계의 전제)

1. **순번은 새로 만들 필요가 없다.** 바이트 오프셋 `end` 가 데몬·서버·브라우저를 이미 꿴다. 화면 상태를 같은 잠금(`cmu`) 안에서 바이트와 함께 나아가게 하면, "스냅숏이 오프셋 `end` 의 화면"이라는 성질이 생긴다. 그 뒤로는 지금의 `trim_overlap`·`SEQ` 로 빠짐·겹침 없이 잇는다(FR-TRM-4).
2. **화면 상태는 데몬에 둬야 한 벌이다(FR-TRM-7).** 도구는 데몬에 하나이고, 브라우저마다 받는 곳만 여럿이다.
3. **xterm.js 는 스크롤백 위쪽에 줄을 끼워 넣는 공개 API 가 없다.** 위로 스크롤 받기(FR-TRM-5)는 xterm 버퍼에 이어 붙일 수 없다. 따로 보여 줄 자리가 필요하다(결정 D-M2-6).
4. **잠든 터미널은 질의에 답할 xterm 이 없다.** 지금은 열린 뒤 숨은 xterm 이 답한다. 모든 브라우저에서 잠들면 앱의 질의(DA·커서 위치 보고 등)에 아무도 답하지 않는다(결정 D-M2-9).
5. **잠든 터미널에서 일어나던 일 중 브라우저가 출력에서 읽던 것**은 Cwd·Download 둘이다. Cwd 는 데몬이 이미 안다. Download 는 정해야 한다(결정 D-M2-10).
6. `read-screen` 은 지금도 서버가 답하지만 화면이 아니라 바이트 꼬리다. 화면 상태가 생기면 진짜 화면으로 답할 수 있다(결정 D-M2-8).
7. 한 번도 안 보인 터미널의 `_buf` 는 상한이 없다. NFR-PRF-9(JS 힙)의 원인 하나다. 구독을 깬 터미널로 좁히면(FR-TRM-3) 함께 사라진다.

### 2.2 데몬 화면 상태 모듈 (FR-TRM-1·7)

- **범위**
  - 새 crate(가칭 `otter-shared-termstate`) 하나에 `alacritty_terminal =0.26.0` 을 가둔다(EMULATOR §8: 판 고정, 쓰는 표면을 한 모듈에). 바깥에는 `feed(&[u8])`·`resize(cols, rows)`·화면 셀 읽기·모드 읽기만 낸다. **개정(2.10)**: 실제 공개 표면은 `Screen` 의 `new`·`feed`·`resize`·`size`·`row`·`history_len`·`cursor`·`modes`·`snapshot`·`handover`·`restore`·`take_replies`·`store`·`set_store_cap`·`text` 와 값 타입이다. 기록 옮기기(`drop_oldest`)는 crate 안에서만 한다(`termstate/src/emu.rs`).
  - `Tool::handle_chunk` 에서 링에 넣는 잠금(`cmu`) 안에서 에뮬레이터에도 넣는다. 그래서 "오프셋 `end` 의 화면"이 한 순간에 정해진다. `resize_inner` 에서 에뮬레이터 크기도 바꾼다.
  - 에뮬레이터의 답장 사건(`PtyWrite`)은 PTY 에 쓰지 않는다. 쓸지 말지는 2.8.2(D-M2-9)가 정한다. **개정(2.8.2)**: 답은 `take_replies` 로 모으고, 좌석이 비면(붙은 연결 0) 도구가 PTY 에 쓴다(D-23, `toolhub/src/tool.rs`).
  - 에뮬레이터의 기록 상한은 작게 둔다(초기값 1,000줄, EMULATOR §6). 넘는 줄은 2.3 이 받는다. **개정(2.4)**: 1,000 은 남기는 줄 수(`EMU_KEEP`)다. 에뮬레이터의 상한은 keep + 2×256 + 화면 행 수다(`emu_cap`). **개정(4.1.2, D-49·D-52·D-56)**: `EMU_KEEP` 1,000 은 지웠다. keep 은 화면 행 수로 정한다 — `termlimit::emu_keep(rows) = max(64, 1000 − 2×256 − rows)`(120×40 → 448), 상한은 `termlimit::emu_cap` = max(1,000, keep + 2×256 + rows)이라 그리드는 alacritty 저장 단위 하나(화면 + 1,000행)에 든다. 크기를 바꾸면 다시 계산하고, 바꾼 뒤 기록을 저장소로 옮긴다. **개정(4.1.3, D-50·D-53)**: 출력이 5분 없는 도구는 에뮬레이터 기록을 모두 저장소로 옮기고 그리드를 화면만큼으로 줄인다(`Screen::compact`, 등록부의 compactor).
  - 비교 시험의 기준 자료: 2.1 스파이크(`/private/tmp/otter-emu-spike/corpus`)의 녹화와 경계 벡터를 저장소로 옮긴다. 기준 결과는 `@xterm/headless 5.5.0` + unicode11 로 만든 셀 격자 JSON 으로 커밋하고, 만드는 node 스크립트도 함께 둔다. cargo 시험은 node 없이 JSON 과 견준다.
- **RED 로 쓸 핵심 시험**
  - 경계 벡터·vim·less·top·agent-sim 의 모든 셀(글자·폭·색·속성)·커서·대체 화면이 xterm 기준과 같다(OSC 8 밑줄 4셀은 2.4 직렬화 뒤 0).
  - 크기 바꾸기 전후의 화면이 xterm 의 재흐름 결과와 같다.
  - 대체 화면 들어가기·나오기, 스크롤 영역(DECSTBM) 안의 스크롤.
  - 도구 하나에 에뮬레이터가 하나다 — 구독자를 둘 붙여도 `feed` 는 한 번만 일어난다(FR-TRM-7).
  - 에뮬레이터가 답장을 PTY 에 쓰지 않는다.
- **게이트**: `deny.toml`, RustSec, Windows 타입 검사(EMULATOR §7 에서 통과 확인).

### 2.3 줄 저장소 (FR-TRM-2, NFR-PRF-10)

- **범위**
  - 에뮬레이터 기록이 상한을 넘으면 가장 오래된 줄을 읽어 저장소로 옮기고 `grid.update_history()` 로 지운다(EMULATOR §6).
  - 줄 하나 = 글자 + 속성 구간(색·굵게 등이 바뀌는 자리만) + OSC 8 링크 구간. 일정 줄 수마다 블록으로 묶어 deflate 한다. 최근 블록 하나는 풀린 채로 둔다.
  - 줄에는 **절대 줄 번호**(지금까지 기록에 들어간 줄의 누적 수)를 붙인다. 스냅숏과 위로 받기가 이 번호로 구간을 말한다.
  - 줄 단위는 결정 D-M2-14 를 따른다(권장: 감싼 행을 합친 논리 줄).
  - 상한(기본 50,000줄)을 넘으면 가장 오래된 블록부터 버린다. **개정(4.1.1, D-51)**: 기본은 20,000줄이다(`termlimit::HISTORY_LINES_DEFAULT`). ED3(기록 지우기)를 받으면 저장소도 비우고, 번호는 이어 간다.
  - 한 번에 넣는 바이트가 에뮬레이터 기록 상한보다 많은 줄을 밀어 올리지 않게, 넣기 전에 나눠 넣는다(EMULATOR §6, §8 "줄을 잃음" 위험의 대응). 한 조각이 밀어 올리는 행의 상한 = 줄바꿈(LF·VT·FF) 수 + 바이트 수/열 수 + 1 (`linestore/src/split.rs` `split_for_rows`).
  - 구간 읽기: `lines(from, count) -> ANSI 줄 목록`. 에뮬레이터를 거치지 않는다.
- **RED 로 쓸 핵심 시험**
  - 넣은 줄을 꺼내면 글자·속성·링크가 같다(왕복).
  - 64 KB 청크 하나로 수천 줄을 밀어도 줄을 잃지 않는다 — 에뮬레이터 기록 + 저장소 = xterm 기준의 기록(마지막 N줄).
  - 상한을 넘으면 가장 오래된 줄부터 사라지고, 번호는 단조 증가한다.
  - ED3 뒤 저장소가 비고 번호가 이어진다.
  - 터미널 12개 × 5만 줄(agent-sim 녹화) 뒤 데몬 RSS 증가분이 터미널당 8 MB 이하(NFR-PRF-10, 측정 시험은 `--ignored`). **개정(4.1.3, D-55·D-57)**: 판정은 기본값 2만 줄·물리 사용량(footprint) 기준이고 5만 줄은 참고다. 측정 시험은 `toolhub/tests/daemon_memory.rs`, 판정은 SRS §7.4.

### 2.4 스냅숏 직렬화와 오프셋 연속성 (FR-TRM-4, A-2)

- **범위**
  - 직렬화기: 화면 + 최근 기록 N줄(N = 설정 `termScrollback`, 기본 5,000 — 2.5.1, 에뮬레이터 기록 → 모자라면 저장소) → 최소 재그리기 ANSI. 스파이크의 120줄 남짓 직렬화기를 바탕으로 한다.
  - 함께 싣는 상태: 커서 위치·모양·보임, SGR, OSC 8 링크, 대체 화면(주 화면 내용도), 스크롤 영역, 원점 모드, 자동 줄바꿈, 삽입 모드, 문자 집합(G0/G1 선 그리기), 앱 커서 키·키패드, 마우스 프로토콜·인코딩, 괄호 붙여넣기, 포커스 보고, 창 제목(OSC 0/2). `TermModes::restore_bytes` 가 하던 일은 이 직렬화기로 옮긴다.
  - 머리 정보: 오프셋 `end`, 크기, 대체 화면 여부, 첫 기록 줄의 절대 번호, cwd.
  - 오프셋 연속성: 스냅숏은 `cmu` 잠금 안에서 만든다. 그 순간의 `end` 가 스냅숏의 오프셋이다. 이어지는 출력은 `end` 뒤 바이트다.
  - IPC: 새 메서드(가칭 `screen`)와 기능 이름(가칭 `FEATURE_SCREEN_STATE`). 스냅숏은 데몬에서 만든다(결정 D-M2-4).
- **RED 로 쓸 핵심 시험**
  - 스냅숏을 새 xterm(headless)에 넣은 화면 = 원래 바이트를 넣은 화면(모든 자료, 대체 화면 중 포함).
  - **임의 분할점 시험**: 녹화를 무작위 자리 k 에서 끊어, `스냅숏(k) + 바이트[k..]` 를 넣은 xterm 의 최종 화면·기록 = `바이트 전체` 를 넣은 xterm. 분할점이 UTF-8 글자·이스케이프 시퀀스 한가운데여도 같다(데몬 파서 상태가 끊긴 시퀀스를 이어 받는 경우를 포함).
  - 모드 왕복: 각 모드를 켠 뒤 스냅숏 → 새 xterm 의 모드가 같다.
  - 스냅숏 크기는 화면 크기·N 에 비례하고 출력량과 무관하다.
- **주의**: "분할점이 시퀀스 한가운데"인 경우 데몬 에뮬레이터는 시퀀스를 반쯤 읽은 상태다. 스냅숏 + 나머지 바이트를 받은 브라우저는 그 앞부분을 모른다. 2.4 는 이 경우를 시험으로 드러내고, 대응(스냅숏 시점을 시퀀스 경계까지 미루기 등)을 정한다. **정한 대응(2.4)**: 미루지 않고 **물린다** — 스냅숏이 끝나지 않은 시퀀스·UTF-8 글자의 바이트 수 `back` 을 알리고, 이어 보낼 출력은 `end - back` 부터다(`termstate/src/lib.rs` `Snapshot::back`). 물리지 못한 경우만 끝나지 않은 바이트를 스냅숏 끝에 싣는다.

### 2.5 깨움·잠듦 (FR-TRM-3·4, NFR-PRF-6·14)

- **범위 — 서버**
  - `term.open` 에 깨움 표시(가칭 `snap:true`)가 있거나 `since` 가 없으면 바이트 재생 대신 화면 상태 스냅숏을 보낸다. 프레임 꼴은 결정 D-M2-5(권장: 지금 `OUTPUT` + `SEQ` 를 쓰고 `SEQ` 에 깃발 비트 하나 더함).
  - 스냅숏을 받은 브라우저에는 넛지를 걸지 않는다(스냅숏이 정확하므로). `SEQ` 의 새 깃발이 그것을 알린다.
  - 같은 도구를 여럿이 한꺼번에 깨우면 같은 `end` 의 스냅숏은 한 번만 만든다.
- **범위 — 브라우저**
  - 터미널을 만들 때 연결하지 않는다. 처음 보일 때(`vis`) 붙는다.
  - 숨으면(결정 D-M2-2 의 지연 뒤) `term.close` 하고, 버퍼를 비운다(결정 D-M2-1).
  - 다시 보이면 `term.open{snap}` → 스냅숏을 그린다. 그동안 입력은 지금의 보류함(FR-HIN)이 받는다.
  - 깨울 때 브라우저 스크롤백은 결정 D-M2-11 의 값(기본 5,000)이다. 스냅숏의 기록 행 수도 같은 설정 `termScrollback` 이다(2.5.1).
  - cwd 는 스냅숏 머리에서 받는다(잠든 동안 놓친 OSC 777 Cwd 를 메운다).
- **RED 로 쓸 핵심 시험**
  - 서버: 깨움 `term.open` 의 프레임 순서(`TOOLID` → `SIZE` → 좌석 → 스냅숏 `OUTPUT` → `SEQ(snap)` → 실시간). `SEQ` 오프셋 뒤 출력에 빠짐·겹침이 없다.
  - 프론트: 숨긴 터미널은 `term.close` 를 보내고 그 sid 의 바이너리 프레임을 받지 않는다. 깨면 `term.open{snap}` 을 보낸다. 스냅숏 `SEQ` 에는 넛지를 걸지 않는다.
  - e2e: 출력이 흐르는 터미널을 숨겼다 깨우면 화면이 숨기지 않은 터미널과 같다(TUI·줄 출력 둘 다). 잠든 터미널로 가는 바이트가 0(NFR-PRF-6). 깨워 그려질 때까지 p95 100 ms 이하(NFR-PRF-14, 로컬).
- **영향받는 e2e**: 숨은 터미널의 버퍼를 읽는 스펙을 찾아 고친다(1.4 의 17개 중 해당분).

### 2.6 흐름 제어를 스냅숏으로 (FR-TRM-6, FR-CON-6)

- **범위**: `relay` 의 두 재동기 자리(밀린 양이 `TERM_PENDING_MAX` 를 넘을 때, 출력에 틈이 날 때)를 바이트 재생에서 화면 상태 스냅숏으로 바꾼다. 밀린 프레임은 버리고 다음 프레임에 스냅숏 하나를 보낸다. 스냅숏 범위는 결정 D-M2-12.
- **RED 로 쓸 핵심 시험**
  - 브라우저가 읽지 않는 채널에 출력을 계속 넣으면, sid 의 밀린 양은 상한을 넘지 않고, 다시 읽기 시작하면 스냅숏 하나 + 이어지는 출력이 오며 최종 화면이 같다.
  - 출력 틈(데몬 큐가 조각을 버림)이 나도 채널을 닫지 않고 스냅숏으로 맞춘다.
  - M1 이슈 1.7 의 남은 위험("1 MB 흐름 제어 통합 시험 없음")을 이 시험이 메운다.

### 2.7 위로 스크롤 받기 (FR-TRM-5)

- **범위**
  - 채널 텍스트 프레임 둘: 브라우저 → 서버 `term.history{sid, before, count}`(절대 줄 번호 `before` 앞의 `count` 줄), 서버 → 브라우저 `term.history{sid, from, top, lines}`(`top` = 저장소에 남은 가장 오래된 줄 번호, 2.7 에서 더함). 서버는 데몬 저장소에 묻는다(IPC 메서드 가칭 `history`).
  - 요청은 별도 태스크에서 처리한다. 터미널 출력 차선과 입력을 막지 않는다. 응답은 상태 차선보다 앞, 터미널 출력보다 뒤에 둔다.
  - 브라우저 쪽 보여 주는 자리는 결정 D-M2-6(권장: 읽기 전용 기록 보기).
- **RED 로 쓸 핵심 시험**
  - 서버: 저장소의 구간을 순서대로 돌려준다. 저장소 맨 위를 넘으면 있는 만큼만 주고 끝을 알린다. 기록이 지워진 뒤의 옛 번호에는 빈 답을 준다.
  - 받는 동안 같은 sid 의 출력 지연이 늘지 않는다(대량 출력 중 요청 → 출력 프레임 간격).
  - e2e: 5천 줄보다 위로 스크롤하면 그 위 기록이 보이고 글자가 원래와 같다. 그동안 입력이 막히지 않는다.

### 2.8 지금 기능 옮기기 (FR-TRM-8)

- **2.8.1 read-screen** (deps 2.4)
  - `GET /api/tools/output?strip=1` 의 출처를 결정 D-M2-8 에 따라 바꾼다(권장: 에뮬레이터 화면 글자 + 최근 기록, `bytes` 상한 유지). `read-output`(ANSI 그대로)은 링에서 계속 준다.
  - RED: TUI 화면(vim·top)에서 read-screen 이 실제 화면 글자와 같다. 잠든 터미널(브라우저 구독 0)에 답한다. 출력 없음·없는 도구의 답은 지금과 같다.
- **2.8.2 검색·질의 답·내려받기·잔여 e2e** (deps 2.5)
  - 검색: 결정 D-M2-7(권장: 브라우저 버퍼 + 서버 기록 검색).
  - 질의 답: 결정 D-M2-9(권장: 좌석이 비면 데몬이 답한다). 서버가 좌석이 비고 차는 순간을 데몬에 알린다. **개정(2.8.2)**: 전이를 알리지 않는다 — 연결마다 IPC `seat` 로 좌석을 쥐고 놓고, 데몬이 쥔 수를 센다(0 이면 데몬이 답한다).
  - 내려받기: 결정 D-M2-10.
  - 칸 이동 스크롤 복원(`renderer-scroll.js`)·진단(`diag.js`)이 잠든 터미널의 빈 버퍼에서 깨지지 않게 한다.
  - RED: 잠든 터미널에서 도는 앱이 DA·커서 위치 질의에 답을 받는다(좌석이 빈 경우만, 깬 브라우저가 있으면 데몬은 답하지 않는다). 서버 기록 검색이 5천 줄 위의 일치를 찾는다. 주의 상태 판정은 바뀌지 않는다(데몬 판정이므로 기존 시험 유지).

### 2.9 기록 줄 수 설정과 데몬 교체 호환 (D-7, FR-TRM-2)

- **범위**
  - 설정 두 개(결정 D-M2-11). 데몬 값은 서버가 IPC 로 알린다(지금 `attnconfig` 와 같은 방식). 브라우저 값은 지금 상수 `TERM_SCROLLBACK_LINES` 를 대신한다.
  - 데몬 교체: 결정 D-M2-13(인계 판 2 — 스냅숏 + 저장소 블록 + 줄 번호를 넘김. 2026-11-25 개정으로 판 1 은 받지 않는다).
- **RED 로 쓸 핵심 시험**
  - 데몬 기록 값을 줄이면 저장소가 곧바로 그 줄 수로 줄고, 늘리면 그 뒤로 더 쌓인다.
  - 인계 판 2: 교체 전후 화면·기록 마지막 5만 줄·오프셋·모드가 같다.
  - (2026-11-25 개정으로 폐기: 판 1 받기, 기능 이름이 없는 데몬용 대체 동작)

동작 변경 두 건:

- **read-screen (D-22)** — 이전: 데몬 링의 마지막 16 KB 바이트에서 ANSI 를 걷어 낸 글자. 새: 데몬 에뮬레이터의 화면 격자 글자(화면 + 최근 기록, `--bytes` 상한 유지). 이유: 이전 답은 TUI 에서 지운 글자·덮어쓴 글자가 섞였고, FR-TRM-8 은 서버 화면 상태로 답하라고 한다. `read-output` 은 바뀌지 않는다.
- **OSC 777 Download (D-24)** — 이전: 숨은 터미널의 xterm 도 출력을 받아, 그 도구를 연 브라우저마다 내려받기를 일으켰다. 새: 깬 터미널에서만 동작하고 잠든 동안 온 요청은 버린다. 이유: 잠든 터미널은 출력을 받지 않으며(FR-TRM-3), 이 명령은 사람이 보는 터미널에서 친다.

항목은 의존 순서대로 적었다. 앞의 것이 뒤의 범위를 바꾼다.

### D-M2-4 스냅숏을 어디서 만드는가

| 선택지 | 내용 |
|---|---|
| **A. 데몬 (권장)** | 화면 상태가 있는 곳에서 바로 직렬화해 IPC 로 보낸다 |
| B. 웹서버 | 서버가 출력을 받아 자기 에뮬레이터를 따로 돌린다 |

- 근거: B 는 화면 상태가 두 벌이 된다(FR-TRM-7·D-11 위반). 서버가 다시 켜지면 상태를 잃는다. A 는 오프셋과 같은 잠금 안에서 만들 수 있어 연속성이 쉽다.
- 위험: LOW. 스냅숏(최대 수백 KB)이 JSON IPC 를 한 번 지난다. NFR-PRF-14 를 2.5 에서 잰다.

### D-M2-3 데몬의 1 MB 바이트 링을 어떻게 하는가

| 선택지 | 내용 |
|---|---|
| **A. 유지 (권장)** | 링은 남긴다. 깬 터미널의 짧은 끊김(채널 재연결) 이어 붙이기, `read-output`, 옛 판 인계에 쓴다. 깨움·흐름 제어는 스냅숏 |
| B. 제거 | 모든 재동기를 스냅숏으로 한다. `read-output` 은 저장소에서 만든다 |
| C. 축소 | 256 KB 로 줄여 둔다 |

- 근거: 링과 에뮬레이터는 같은 일을 하지 않는다(바이트 원본 vs 화면). 재연결 이어 붙이기는 브라우저 버퍼를 지키고 스냅숏보다 싸다. FR-TRS 의 동작과 관련 e2e 를 그대로 둔다. 메모리 어림: 링 1 MB + 에뮬레이터(120열 1,000줄) 약 3 MB + 저장소 1~2 MB ≈ 5~6 MB 로 8 MB 안이다. 넘으면 M4 에서 C 로 간다. **정정(4.1, 2026-11-25)**: 실제 에뮬레이터는 keep 1,000 + 상한 여유에 alacritty 저장 단위(1,000행)까지 더해 화면 + 2,000행(120열 약 6.3 MB)을 잡아 도구당 8.6~11 MB 였다. 4.1.2 가 화면 + 1,000행(약 3.1 MB)으로 낮추고 4.1.3 이 유휴 5분 뒤 비운다. 링은 그대로 1 MB 다(선택지 A 유지, SRS §7.4).
- 위험: LOW(A) / MEDIUM(B — `read-output` 이 바이트 원본을 못 주고, 재연결마다 버퍼를 다시 그린다).

### D-M2-14 줄 저장소의 줄 단위

| 선택지 | 내용 |
|---|---|
| **A. 논리 줄 (권장)** | 자동 줄바꿈으로 감싼 행을 하나로 합쳐 둔다. 꺼낼 때 지금 폭으로 다시 감싼다 |
| B. 화면 행 그대로 | 행을 그때 폭대로 둔다 |

### D-M2-5 스냅숏 프레임 꼴

| 선택지 | 내용 |
|---|---|
| **A. 지금 프레임 + 깃발 (권장)** | 스냅숏을 `OUTPUT`(초기화·지우기 포함 ANSI)으로 보내고 `SEQ(end)` 에 깃발 비트 `SNAP` 을 더한다. 브라우저는 `SNAP` 이면 넛지를 걸지 않는다 |

### D-M2-13 판 호환 — 데몬 교체와 판이 다른 웹서버·데몬

> **2026-11-25 개정 (사용자 결정)**: 옛 데몬은 쓰지 않는다. 판 1 받기와 옛 데몬용 대체 경로를 폐기한다. 아래 확정안 줄이 새 결정이고, 선택지 표는 처음 고른 근거로 남긴다.
>
> - 이전: A(인계 판 2 + 판 1 받기 + 옛 데몬엔 지금 경로)
> - 새: 인계 판 2 만. 스냅숏 + 저장소 블록 + 절대 줄 번호를 넘겨 새 데몬 → 새 데몬 교체에서 기록과 번호를 유지한다. 판 1 은 받지 않는다(FR-DSK-18 그대로). 옛 데몬 → 새 데몬은 전체 재시작(세션 잃음)이다. 서버에 옛 데몬용 대체 경로를 새로 만들지 않는다
> - 이유: 옛 데몬은 쓰지 않는다. 또 옛 데몬은 요청과 새 바이너리의 판을 정확히 같음으로 검사하므로(배포된 코드), 판을 2 로 올리면 판 1 → 판 2 교체는 옛 데몬이 거절한다 — 판 1 받기는 처음부터 이룰 수 없었다

| 선택지 | 내용 |
|---|---|
| A. 인계 판 2 + 판 1 받기 + 옛 데몬엔 지금 경로 (처음 권장) | 새 데몬 → 새 데몬: 스냅숏 ANSI 와 저장소 블록을 넘기고, 받는 쪽은 스냅숏을 새 에뮬레이터에 먹여 되세운다. 옛 데몬(판 1) → 새 데몬: 링 바이트를 에뮬레이터에 먹인다(기록은 링 분량만). 새 웹서버가 `FEATURE_SCREEN_STATE` 없는 옛 데몬에 붙으면 잠듦 없이 지금의 바이트 재생으로 돈다 |
| B. 링 바이트만 넘김 | 인계는 지금 그대로. 교체 때마다 기록이 링 분량(1 MB)으로 준다 |
| C. 옛 데몬을 받지 않음 | 기능 이름이 없으면 데몬 교체를 요구한다 |
| **확정 (2026-11-25)** | **인계 판 2 만**(위 개정) |

- 처음 근거: 스냅숏 직렬화기(2.4)를 인계에 다시 쓰면 새 형식을 따로 만들지 않는다. 서버는 데몬을 스스로 교체하지 않으므로(1.2), 판이 다른 조합이 실제로 생긴다.
- 위험: LOW. 옛 데몬을 쓰던 설치는 한 번 전체 재시작해야 한다.

## 5. 비목표

- 데몬 → 서버 IPC 가 구독과 상관없이 모든 도구 출력을 미는 구조는 바꾸지 않는다. 브라우저로 가는 양(NFR-PRF-6·7)이 M2 의 목표다. 서버·데몬 사이 비용은 M4 에서 잰다.
- 브라우저 탭 자체가 숨었을 때의 잠듦은 M3 3.5(생명주기)에 둔다(D-M2-2).
- 기록을 디스크에 남기는 것(데몬이 꺼졌다 켜져도 남는 기록)은 하지 않는다. 데몬 교체(인계)만 지킨다.
- 색 질의(OSC 10/11)에 데몬이 답하는 것.
- 편집기·git 화면 등 터미널 밖의 화면.
- 운영 인스턴스(Go 판, D-8).
