# 4.15.3 git-job-indicator 새로고침 뒤 kind 빔

## 목표

- 새로고침 뒤 잡 칸은 보이나 kind 글자가 비어 있다. M4 이전 판(`b64402c8`)에서도 실패. 채널 `git.jobs` 재부착 경로(M1 C4) 의심.

## 완료 조건

- 원인 확인 → RED → 고침 → GREEN. 관련 e2e 를 빈 OTTER_E2E_RUN 폴더로 3회 통과.
- 동작 변경은 이전 / 새 / 이유.

## 진행 기록

### 2026-11-26 원인 확인·고침 (review)

- 원인: 새로고침 직후 채널의 `git.jobs` full 이 Git 패널(`app.gitPanel`)보다 먼저 온다. `GitSync._gitJobsAdopt` 는 목록을 `app._gitJobs` 에 두고 패널이 없으면 아무에게도 넘기지 않는다. 패널·표시기가 뒤에 서도 그 목록을 읽는 곳이 없었다. 토픽은 목록이 바뀔 때만 다시 밀므로 다음 full 은 잡이 끝난 뒤의 빈 목록이다. 그래서 표시기는 잡에 붙지 못하고 kind 칸이 비었다. 진단 실행에서 `_remoteView._jobs` 가 null 로 남는 것을 확인했다. 패널이 먼저 서는 경우에는 붙는다 — 타이밍에 따라 갈렸다. M1 C4 에서 상태바의 주기 GET(안전망)을 없애면서 생긴 틈이다. M4 이전 판(`b64402c8`)에서도 실패한 이유와 맞다.
- 고침: `GitViews._remote()` 가 표시기(`GitJobs`)를 처음 만들 때 `app.git.sync.gitJobs()`(마지막으로 받은 목록)를 `adoptJobs` 로 넘긴다. `GitSync.gitJobs()` 를 새로 둔다 — `check-layer` 가 git/ 의 `app._gitJobs` 직접 접근을 막기 때문이다.
- 바꾼 파일: `web/js/git/git-views.js`, `web/js/core/git-sync.js`, 새 시험 `web/js/test/git-jobs-seed.test.mjs`.
- 동작 변경: 이전 — 패널보다 먼저 온 진행 중 목록을 버렸고, 새로고침 뒤 도는 잡에 붙지 못했다. 새 — 표시기를 세울 때 그 목록을 딛어 바로 붙는다. 이유 — 토픽은 바뀔 때만 밀고 주기 GET 이 없어졌다.
