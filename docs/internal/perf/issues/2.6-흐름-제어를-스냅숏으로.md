# 2.6 흐름 제어를 스냅숏으로 (FR-TRM-6, FR-CON-6)

## 목표

`channel/term.rs` `relay` 의 두 재동기 자리(밀린 양 > `TERM_PENDING_MAX`, 출력 틈)를 바이트 재생에서 스냅숏(화면 + 5천 줄, D-26)으로 바꾼다. 밀린 프레임은 버리고 다음 프레임에 스냅숏 하나를 보낸다.

설계: `perf/M2_DESIGN.md` §2.6. 이슈 1.7 의 남은 위험(1 MB 흐름 제어 통합 시험 없음)을 이 시험이 메운다.

## 완료 조건

- RED: 읽지 않는 채널에 출력을 계속 넣으면 sid 의 밀린 양이 상한을 넘지 않고, 다시 읽으면 스냅숏 하나 + 이어지는 출력이 오며 최종 화면이 같다.
- RED: 출력 틈(데몬 큐가 조각을 버림)에도 채널을 닫지 않고 스냅숏으로 맞춘다.
- 바꾼 부분의 시험(단위·관련 e2e 한두 개)·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.

**바꾼 것** (`httpapi/src/channel/term.rs`·`outbox.rs`·`screens.rs`)

- `relay` 의 두 재동기 자리(출력 틈, 밀린 출력 초과)가 `resync(tool)` 하나로 곧장 화면 상태 스냅숏(`ScreenFlights`)을 받는다. 링 이어 붙이기(`snapshot_tool_since`)는 `term.open` 의 `since` 에만 남는다.
- 흐름 제어 판정을 프레임을 넣기 **전**에 한다: `밀린 양 + 이 프레임 > TERM_PENDING_MAX + held`. `held` 는 마지막 맞춤 프레임(스냅숏 `OUTPUT`+`SEQ`)의 바이트 수다. 넘으면 그 sid 의 밀린 `OUTPUT`·`SEQ` 만 버리고(이 프레임도 버림) 스냅숏 하나를 보낸다.
- `Outbox::drop_term_output` — 도구 id·크기·좌석 통보는 남긴다. `term_pending(sid)` 가 밀린 양을 준다.

**지운 것**: Outbox 의 브라우저 좌표 추적(`TermMirror.delivered`, `pop` 의 SEQ/OUTPUT 계산, `term_state`, `drop_term`) — 재생 시작점을 고르는 데만 썼다.
