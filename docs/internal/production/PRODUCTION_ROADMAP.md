## 1. 개요

### 1.1 목적

7축 감사가 찾은 결함 173건과 "프로덕션 제품이라면 있어야 하는데 존재 자체가 없는 역량" 56건을, **의존 관계와 리스크 순으로 배치한 실행 순서**로 만든다. 결함 수정과 갭 충족을 분리하지 않는다 — 목표가 결함 제거가 아니라 프로덕션 레벨 품질 확보이기 때문이다.

### 1.2 확정 전제 (사용자 결정 — 변경 대상 아님)

1. **원격 접속이 이 제품의 핵심 목적이고 기본 사용 형태다.** 사용자 원문: "`--expose` 는 필수인게 원격 작업을 위한 프로젝트임." `--expose`/`DONGMINAL_HOST` 는 부수 기능이 아니라 제품이 존재하는 이유다. "로컬 전용이니 괜찮다" 논리는 이 문서 어디에도 쓰지 않았고, "노출은 예외적 사용" 이라는 서술도 쓰지 않는다.
2. 노출 시 **인증 필수** — 위 1 에 의해 이것은 조건부 요구가 아니라 **제품 성립 요건**이다.
3. **단일 사용자 전용 제품이다.** 사용자 원문: "멀티유저는 필요없음, 나 혼자 사용함." 한 인스턴스를 한 사람이 쓴다. 멀티유저 호스트는 지원하지 않는다.
4. 목표는 결함 수정이 아니라 **프로덕션 레벨 품질 확보**.

> **전제 1 의 파급**: 기본 바인드가 `127.0.0.1`(`dmenv.go:45-46`)인 것은 유지한다 — 개발·초기 기동의 안전장치로서 여전히 옳고 감사도 양호로 판정했다. 다만 **실사용 형태는 노출**이므로, "기본이 안전하니 노출 경로의 결함은 낮은 등급" 이라는 추론을 하지 않는다. 이 전제로 재판정한 항목은 §1.6 에 모았다.

### 1.5 마일스톤 지도

```
M0 비가역 결정·저장소 메타데이터
 └─ M1 CI 게이트·정적분석·공급망  ← 이후 모든 리팩터의 안전망
     ├─ M2 브라우저 매개 공격 봉합 + 서버 하드닝   (P0 5건)
     │   └─ M3 데이터 안전·업그레이드·롤백·복원 검증  (P0 3건)
     │       └─ M4 인증·인가·전송 보호 + 제품 경계
     │           ├─ M5 관측성·에러 규약·설정·문서·릴리스 운영  ┐
     │           ├─ M6 렌더 파이프라인 + e2e 계통 결함 + 프론트 계층  │ 상호
     │           │   └─ M7 접근성·디자인 시스템·UX 안전            │ 의존
     │           │       └─ M9 국제화(i18n)  ← M5·M6 도 선행       │ 없음
     │           └─ M8 Go 아키텍처 부채                           ┘
```

M5·M6·M8 은 서로 의존하지 않는다. M7 은 M6 을, M9 는 M7·M6·M5 를 선행으로 요구한다.

**게이트 허용목록 요구사항** (`13 §7` — B1 의 판정 함수가 만족해야 할 10항. `authGate` 와 같은 자리이므로 M4 가 이 함수를 그대로 쓴다):
1. **스킴을 하드코딩하지 마라** — `http`·`https` 둘 다 유효한 배치가 있다(평문 기본 + TLS 옵션). Origin 비교에 스킴을 고정하면 TLS 전환마다 깨진다.
2. **포트 유무를 정규화하라** — `net.SplitHostPort` 실패를 "포트 없음" 으로 정상 처리.
3. **기본 허용목록을 "서버 자신이 도달 가능한 주소" 에서 자동 유도하라** — `localhost` ∪ `127.0.0.1`/`::1` ∪ 실제 바인드 주소 ∪ **`access.go:73` 의 `s.self`(인터페이스 주소 전부)** ∪ 시스템 호스트명. **새 수집 코드가 필요 없고**, `--expose 0.0.0.0` 기본 경로에서 사용자가 어느 로컬 IP 로 접속하든 자동 통과한다.
4. `*.ts.net` 접미사는 **기본이 아니라 옵션**(`--allowed-host '*.ts.net'`). 와일드카드 접미사 문법은 지원해야 한다.
5. `--allowed-host` 로 명시 확장(반복 지정 또는 쉼표 구분) — 공인 도메인·CNAME 사용자의 유일한 입구.
6. **`Origin` 부재는 거부가 아니다** — 비브라우저(`dmctl`·`curl`·e2e `page.request`)는 보내지 않는다. 부재 = 통과, 존재하면 대조. **어기면 M4 의 `dmctl` Bearer 경로 17곳/9파일이 전부 막힌다.**
7. **`Host` 는 존재하면 항상 대조** — DNS 리바인딩 방어의 본체.
8. **`X-Forwarded-*` 를 읽지 않는다** — `FR-ACL-6` 승계. 리버스 프록시 미지원 결정(§4-3-E)으로 신뢰 옵트인 설계 자체가 범위 밖이라 판정 함수가 단순해진다.
9. 거부는 로그에 남고 본문에 허용목록을 노출하지 않는다(`FR-ACL-13` 형식).
10. **`/ws` 와 HTTP 종단이 한 판정 함수를 쓸 것.** 권장은 **업그레이드 이전에 미들웨어에서 판정이 끝나 있게 하는 것**(`accessGate` 가 이미 `server.go:215` 에서 `/ws` 를 포함해 덮는 구조와 같은 자리) — 새 종단이 생겨도 자동으로 덮이고 `authGate` 와 예외 경로 목록이 한 벌로 유지된다.

**규모 합**: S×20 + S/M×3 + M×5 → **L**. **SRS**: 2건 — ① 요청 게이트 체인(판정 규칙·예외 경로·비브라우저 규약·`authGate` 자리 예약), ② 파일 API 경계(`/api/file/*` 루트 대조 정책과 그 밖을 켜는 방법).

- **리버스 프록시 미지원 선언**이 `G10-1` 에 있고, **"불가능해지는 것이 아니라 보증하지 않는 것"** 이라는 차이가 명시된다 — 앱을 `127.0.0.1` 에 두고 프록시를 붙이는 것은 지금도 동작하며 그때는 ACL 을 끄면 된다. `X-Forwarded-*` 를 읽는 코드를 **넣지 않는다**(`FR-ACL-6` 승계).
- **첫 경험**: 인증 미설정 + 비 loopback 바인드에서 기동을 거부할 때 **`dongminal auth init` 을 함께 출력**한다. 거부만 하면 사용자가 막힌다. `--isolated` 는 **강제에서 제외**한다(e2e·개발 격리 실행이 매번 인증을 요구하면 테스트가 무너진다).
- **`G10-1` 이 다음을 모두 담는다(전제 1 로 범위 재정의)**: ① 위협 모델 — 주 시나리오가 "로컬 도구가 실수로 노출되는 경우"가 아니라 **"인터넷 또는 사설망에 상시 노출된 원격 작업 도구"**다. 공격면은 도달 가능한 PTY·파일 읽기/쓰기·git 쓰기·명령 실행 종단 전부. ② 지원 배포 형태를 **권장 순서**로: Tailscale·WireGuard 등 오버레이 망 뒤(권장) → 리버스 프록시 + TLS → LAN + 인증 + TLS → loopback 전용(개발용). 각 형태의 보증 수준을 적는다. ③ **명시 선언: 단일 사용자 전용 · 멀티유저 호스트 미지원**(결정 7 확정). ④ **배포 형태별 보증표에 `13 §4` 의 경로를 그대로 싣는다** — P4(사용자 제공 인증서)·P5(공인 도메인)·P7(SSH 포트포워딩)·P9(Tailscale `cert`)·**P10(평문 = 명시적 열등 등급: 데스크톱 알림 미동작·`Secure` 쿠키 불가)**. **리버스 프록시·funnel·멀티유저는 미지원 선언** — 리버스 프록시는 "불가능해지는 것이 아니라 보증하지 않는 것" 임을 명시하고, 쓰려면 앱을 `127.0.0.1` 에 두고 프록시를 붙이며 그때 ACL 을 끄라는 한 줄을 적는다 ⑤ 상시 노출 전제에서 추가되는 운영 권고 — 자격증명 회전 주기, 인증 실패 로그·잠금(`G1-4`)의 확인 방법, **노출 상태의 가시화**(상태바 또는 `/api/health` 에 "노출 중" 표시). ⑥ `README.md:77-79` 대체와 M2 의 임시 안내 절 회수. ⑦ **ACL 의 기여와 한계**: `--expose` 기본 배치에는 프록시가 없어 `RemoteAddr` 이 진짜 출발지이므로 **ACL 은 정상 작동한다**(`13 §2-3`). 켜면 LAN 의 임의 기기가 로그인 화면에도 도달하지 못해 `G1-4` 무차별 대입 표면이 줄어드는 **의미 있는 심층 방어**다. 다만 **기본 꺼짐**(`access.go:288`)이고 IP 기반이라 DHCP 에서 스스로 잠길 수 있어 **단독 방어선이 될 수 없다** — 이것이 `accessGate → authGate` 직렬 배치의 근거다.
- **[미결정 6 종속]** `CHANGELOG.md` 의 파괴적 변경 명시와 버전 번호.

### M6 — git 갱신 계층 재설계 + 렌더 파이프라인 + e2e 계통 결함

**목표**: **워크스페이스 재채택이 로컬 레이아웃 변경을 덮는 것을 막고**, git 관측·수명 계층의 국소 결함을 고쳐 flaky 8건의 **제품 측 원인**을 제거한다. 그 다음 서버 감시 비용을 signature 2단 게이트로 되돌리고, 마지막에 프론트 거대 모듈을 분리한다.

> **목표 재서술의 근거** — 1차 감사(`TEST-5`)는 "flaky 아홉 건이 모두 관측 → 전체 재렌더 → DOM 교체라는 동일 기전" 이라 판정했고 이전 판 로드맵은 그 서술을 그대로 썼다. `11 §5` 가 9건을 코드로 매핑해 **그 판정이 절반만 맞다**는 것을 확인했다:
> - 기전은 **셋**이다. ① **뷰/탭 유실**(9건 중 5건: H14·D1·BR11·X4·V10-13, 가능성 H15) — `_onWorkspaceChanged` 가 서버 레이아웃을 채택하면 방금 연 git 뷰 탭이 사라진다(`app-cmd.js:306-330`, `app.js:531-556`). **관측과 무관하다.** ② **관측 파생 상태 초기화**(B6) — `branches.js:118-120,145-152` 의 `_adopt`/`reset` 이 `_refs=[]` 로 비우고 `if(!this._repo) return` 이면 다시 받지 않으며, 이후 `_obsSig` 가드가 `paintAll` 도 막아 빈 목록이 굳는다. ③ **관측이 만드는 부수 요청**(K2 = `GP-10`)과 **관측 자체가 서지 않음**(P4 = `GP-2`).
> - **9건 중 8건이 제품 결함으로 설명된다. "테스트가 취약한 것" 이 아니다.** H15 만 미확정(뷰 유실인지 `GP-5` 무응답 fetch 잠금인지 — 실패 트레이스의 `/api/git/log` 요청 유무로 갈린다).
> - `fixtures.ts:224-233` 의 **"재렌더는 앱의 정상 동작이므로 견디는 쪽은 테스트다" 는 근거가 없다** — git 관측은 `render()` 를 부르지 않는다(`app-git.js:610`: "전체 render() 를 부르지 않는다"). 탭이 사라지는 진짜 이유는 워크스페이스 재채택이고 그것은 정상 동작이 아니라 고쳐야 할 자리다.
> - **따라서 `TEST-5` 의 조치 (2)("`reconcileList`/탭 바가 노드를 교체하지 않게")는 아홉 중 최대 1건에만 닿는다.** 실제로 필요한 것은 ① 로컬 레이아웃 보호 ② `GP-2`·branches `_adopt`·`GP-10` 세 국소 수정이다.

**끝나면 보장되는 것**: flaky 가 CI 실패로 승격된 상태에서 전량 실행이 초록이다. 설정을 어떻게 두어도 자동 갱신이 통째로 멎지 않는다. 아무 변화가 없는 저장소에 대해 서버가 1초마다 `git status` 를 돌리지 않는다. e2e 가 프론트 내부 필드 이름에 결합되어 있지 않다.

#### 3-A-2. 제약 3 재검토 — 전제 1(원격이 기본)과 결정 7(단일 사용자)에서도 유지되는가

팀장 질의: 인증이 "노출을 쓸 때만 필요한 옵션" 이 아니라 제품 성립 요건이라면 M4 를 M2·M3 보다 앞당겨야 하는가. **결론: 앞당기지 않는다. 제약 3 은 유지되고 근거는 세 갈래로 강해졌다.**

원래 근거는 "기존 `--expose` 사용자의 기동이 거부되는 파괴적 변경이므로 이행 안내와 롤백이 먼저" 였고, 그 무게가 **이행 안내를 받을 사용자 집단**에 있었다. 결정 7 로 그 집단이 인스턴스마다 한 명이 되면서 이 근거만 약해졌다. 그러나 나머지가 남고, 재프레이밍으로 오히려 커진다.

1. **판 불일치(`G3-1`)는 사용자 수와 무관하고, 단독 사용자에게 더 확실히 일어난다.** 업그레이드 실제 절차는 "바이너리 덮어쓰기 → `dongminal start`" 인데 `start` 는 데몬이 살아 있으면 그대로 둔다(`start.go:66-70` "dongminald 실행 중 (세션 보존)"). 즉 **인증을 요구하는 새 서버 + 인증을 모르는 옛 데몬**이 정확히 이 경로로 공존한다. 감지가 없다는 것은 `07 §3` 이 코드로 확정했다. 이것은 다른 사용자의 문제가 아니라 **업그레이드하는 본인에게 일어나는 일**이다.
2. **인증 401 이 `FE-2`(빈 판 덮어쓰기)의 새 트리거다.** `07 §1` 프론트 부팅 행: "401 → 로그인 화면 분기. 정적 HTML 은 인증 없이 나가되 `/api/settings`·`/api/state` 401 을 부팅 화면이 받아야 한다(현재 `main.js:14-21` 은 설정 실패를 `catch{}` 로 삼킨다)". 로그인 분기를 만들기 전 상태에서 401 이 오면 `_fetchStateKnown` 실패 → `_mkWindow` → If-Match 없는 PUT → 워크스페이스가 빈 판으로 덮인다. **인증 도입이 스스로 데이터 손실 경로를 하나 새로 연다.** `G4-2`+`FE-2`(M3)가 먼저 닫혀 있어야 한다.
3. **전제 1 이 롤백의 가치를 키운다.** 원격 접속이 기본 사용 형태이므로 "되돌릴 수 없는 상태" 는 곧 **원격에서 작업을 못 하는 상태**다. 그리고 결정 7(단독 사용자)이라 대신 고쳐 줄 사람이 없다. 백업 세대(`G4-1`)·롤백 경로(`G3-2`)·진단 번들(`G2-3`)이 M4 앞에 있어야 할 이유가 커진다.

**대신 한 것**: ① M3 의 **내부 순서**를 인증 전제 항목(`G3-1`·`G2-2` → `G4-1`·`G4-2`·`FE-2`) 우선으로 명시했다. ② M2 의 노출 게이트(`SEC-3`·`SEC-10`·`SEC-11`)를 그 마일스톤의 필수 완료 항목으로 두고, **M2~M4 구간의 운영 안내**를 M2 DoD 에 추가했다. ③ `SEC-3` 을 §1.6 에서 P0 로 재판정해 M4 의 시급성을 문서에 남겼다.

**하지 않은 것**: `04 P0-1` 제안 2("기동 시 난수 세션 토큰을 `index.html` 에 심고 `$DONGMINAL_HOME/token` 을 `dmctl` 이 읽는다 — `P1-1` 의 `--expose` 안전장치를 겸한다")를 M2 에 앞당겨 넣는 것. 그렇게 하면 M4 의 쿠키 세션(결정 5)과 자격증명 체계가 두 벌이 되고, 두 번째가 첫 번째를 걷어내야 한다. M2 의 노출 게이트(인증 미설정 시 ACL 강제)가 그 구간의 방어를 맡는다.

#### 3-A-3. fsnotify 판정 — 도입하지 않는다, 그리고 사용자 진단은 옳았다

팀장 질의: `11` 의 fsnotify 판정을 반영하라.

**결론: (C) 2단계 권장안을 채택한다. fsnotify 는 도입하지 않는다.** 근거는 `11 D-2`~`D-4` 가 코드로 확정한 것이다.

- **감지를 fsnotify 로 바꿔도 남는 문제가 다수다.** 확인된 18건 중 감지 결함 9 · 갱신(표시·DOM·도메인) 결함 9 인데, fsnotify 로 해결되는 것은 감지 9건 중 5건(`GP-11a~e`)과 비용(`GP-7`·`GP-8`)뿐 — **전체의 약 1/3.** `P0`(`GP-1`)과 P1 8건 중 6건이 그대로 남는다. 사용자가 겪는 "가끔 안 눌린다·화면이 낡았다" 의 8/9 는 갱신·수명 계층에 있다.
- **fsnotify 가 여는 구멍은 stat 3~4회로 같은 값에 메울 수 있다.** `.git/config` stat 1회로 `GP-11b/c`, `logs/refs/stash` 또는 `refs/` 파일 mtime 으로 `GP-11a/d`, `obsMark` 에 필드 하나로 `GP-11e`.
- **이 저장소는 파일시스템 시각 신호를 믿을 수 없다는 실측을 이미 갖고 있다** — "Windows 러너에서 `git branch` 뒤 45초 동안 `refs/heads` mtime 이 그대로였다"(`CI_E2E_MATRIX_SRS` FR-CEM-32). 그 실측 위에 `RefsShape`(이름 해시)라는 대응책을 세워 두었다. fsnotify 로 옮기면 그 지식을 버리고 플랫폼별 한계를 새로 떠안는다.
- **감시 범위가 `.git/` 만으로 부족하다.** 작업 트리까지 감시해야 하고 그러면 `.gitignore` 를 fsnotify 계층이 스스로 해석해야 한다(git 이 하던 일의 재구현). **이 저장소 자신이 그 문제의 사례다** — `e2e/` 실행 중 `test-results/` 아래에 초당 수십 파일이 생긴다.
- **의존성 제약**(§0-2, `go.mod` 직접 의존 2개 유지)을 깨야 하는데 깨서 얻는 것이 "1초 `git status` 를 없애는 것" 하나이고, 그 하나는 2단 signature 감지로 **의존성 없이** 얻는다. `11 D-3` 이 적었듯 "표준 라이브러리 대안은 새 설계가 아니라 이미 있는 것(`ReadSignature`)을 다시 켜는 일" 이다.

**사용자 진단은 정확했다.** 사용자가 제기한 "지금 구조는 변경이 없어도 1초마다 git 을 돌린다" 는 **사실이다**(`GP-7`: `gitwatch.go:242` 가 `Store.Status()` 를 부르고, TTL 200ms 캐시를 지나지만 1초 주기에서는 매 회차 실제 `git status --porcelain=v2` 프로세스가 뜬다. 최대 16개 저장소 동시, 브라우저가 숨어도 TTL 90초 동안 계속). `GIT_PUSH_OBSERVE_SRS §1.2` 가 fsnotify 를 기각하며 든 비용 논거("`ReadSignature` = read 1회 + stat 2회 = 0.02ms")는 **현재 구현에 대해 무효**다. 갈린 것은 해법뿐이다 — 필요한 것은 파일 감시가 아니라 **서버가 원래 쓰기로 했던 signature 를 1차 게이트로 되세우는 것**이다(M6 5단계).

**순서가 요점이다.** 1단계(갱신·수명, `GP-1`~`GP-6`·`GP-9`·`GP-10` + 낙관적 레이아웃 보호)를 먼저 하고 2단계(감지, `GP-7`·`GP-8`·`GP-11`)를 뒤에 둔다. 반대로 하면 사용자가 겪는 증상 대부분이 그대로인 채 서버 비용만 줄어든다.

#### 3-A-1. 왜 외부화(M9)를 문구 확정(M7·UX-20)보다 **뒤**에 두는가

팀장 질의: i18n 이 UX 문구 변경과 충돌하는지 — 같은 문자열을 두 번 건드리는지.

**결론: 겹친다. 그리고 순서는 "M7 = 문자열이 놓일 자리(시맨틱·토큰·구조) 확정 → M9 = 외부화와 문구를 한 패스에서 함께 확정" 이 싸다.** UX-20(혼용 해소)을 M9 로 이관한 것이 그 이행이다.

- **UX-20 을 먼저 하면 두 번 만진다.** `03 UX-20` 조치는 "문자열이 이미 `constants*.js` 에 모여 있어 **표 하나만 고치면 된다**" — 즉 값을 한국어로 고치는 작업이다. `G7-3` 조치는 "`constants*.js` **키화**" — 같은 표의 같은 항목을 키로 바꾸는 작업이다. 값을 고친 뒤 키로 바꾸면 `constants*.js` 5파일 2,737줄 + `index.html` 178줄 + JS 77파일 241줄을 **두 번 훑는다.**
- **외부화 패스가 문구 판정을 흡수한다.** 외부화는 모든 문자열 리터럴을 한 번 훑어 키를 부여하는 작업이므로, 그 자리에서 ko 값을 확정하면 한 번으로 끝난다. i18n 도입 후 UX-20 은 "코드 결함" 이 아니라 "ko 카탈로그에 영어 항목이 섞여 있다" 는 **데이터 문제**로 좁혀진다 — M9 DoD 의 마지막 항목이 이것을 "코드 변경 없이 교정되는가" 로 검증한다.
- **다만 M7 이 먼저여야 하는 이유가 따로 있다.** `G7-3` 은 `index.html` 정적 문구를 **렌더 경로로 이관**한다. 그 문구가 놓이는 컨테이너의 시맨틱(`role`·`aria-labelledby`·라이브 리전)과 골격(모달 7벌 → `.ui-modal`)이 M7 에서 확정되지 않으면, 이관한 문구를 다시 옮겨야 한다. 특히 `UX-3`(모달 `aria-labelledby`)·`UX-8`(라이브 리전)·`UX-16`(모달 골격 수렴)이 문구의 **소유 노드를 바꾸는** 변경이다.
- **M9 로 이관한 4건의 개별 근거**:
  - `UX-20`(혼용) — 위 논리. 외부화 패스에서 값 확정.
  - `UX-9`(`lang="en"`) — i18n 이 들어오면 `lang` 이 정적 값이 아니라 **활성 로케일로 동적 세팅**되어야 한다. `03` 도 "영어 툴팁이 섞이면 해당 요소에 `lang="en"`" 를 언급 — 요소 단위 `lang` 은 카탈로그가 어느 로케일 항목인지 알아야 붙일 수 있다.
  - `UX-11`(CSS `content` 문구) — `03` 이 직접 "`::after` 텍스트는 … **i18n 불가**" 라고 적었다. DOM 텍스트 이관이 외부화의 **전제**이므로 M9 안에 둔다.
  - `UX-21`(툴팁 단축키 정적) — 조치가 `displayKey(shortcuts.*)` **보간**이다. 보간 자리표시자·치환 규약은 카탈로그 규약(복수형·파라미터)과 같은 설계이므로 한 자리에서 처리한다.
- **M7 에 남긴 것**: 문구가 아니라 **컨테이너·토큰·상호작용**인 항목 전부(UX-2~8·UX-10·UX-12~19·UX-22~26). `UX-10`(검색 입력 `aria-label`)은 문자열이지만 접근성 속성이고 카탈로그 항목이 되면 M9 에서 키로 바뀌는 대상 — M7 에서 값을 넣고 M9 에서 키화하는 **한 줄짜리 중복만** 남는다(이관 비용보다 작다).

### 5-1. 기계적·저위험 묶음(D, 26건)의 별도 처리 방식

**전용 마일스톤을 만들지 않는다.** 이 묶음만 모아 커밋하면 다른 마일스톤의 대규모 diff 와 충돌하고, 리뷰가 "값이 맞는가" 를 확인할 문맥을 잃는다. 세 규칙으로 처리한다.

1. **편승 규칙** — 어떤 마일스톤이 파일 X 를 여는 순간 X 에 남은 D 항목을 **그 PR 안에서 함께** 처리한다. 각 마일스톤 DoD 의 마지막 항목으로 "이 마일스톤이 만진 파일에 D 잔여 0" 을 넣는다. 예: M2 가 `handlers_files.go` 를 열면 `GO-38`·`SEC-19` 를 함께, M6 가 `renderer.js` 를 열면 `FE-14`·`FE-27` 을, M7 이 `applyThemeObj` 를 열면 `UX-14`·`UX-15`·`UX-18` 을, M9 가 `constants*.js` 를 열면 `FE-24`(토픽 하드코딩)를 함께.
2. **재발 방지 게이트** — 값을 옮기는 것보다 **다시 흩어지지 않게 하는 것**이 본체다. `scripts/check-timers.sh`(원시 타이머 금지)와 같은 형태의 grep 게이트를 추가한다: `check-html.sh`(innerHTML 보간, M2) · 미정의 CSS 커스텀 프로퍼티 검출(M7) · 하드코딩 색 리터럴 검출(M7) · `log.Printf` 금지(M5) · 스펙의 `app._xxx` 접근 금지(M6) · 축 의존 위반(M8) · **하드코딩 문자열 검출(M9)**. 게이트가 있으면 잔여는 새로 늘지 않고 자연 감소한다.
3. **일괄 처리 예외 2건** — `GO-22`(paned 핸들러 12개가 디코드+에러코드 중복)와 `TEST-23`(저장소 픽스처 7벌)은 편승 대상 파일이 많아 편승으로 끝나지 않는다. 각각 `decodeParams[T]` 제네릭 도입과 `gittest` 헬퍼 패키지 신설이라는 **한 번의 신규 추가 + 기계적 치환**이므로 M8 안에서 독립 PR 2개로 처리한다.

### 5-2. 거대 파일 분할(E, 16건)의 착수 조건

`00-INDEX` 는 대부분 S~M 로 적었지만 **분할이 위험한 것은 규모가 아니라 검증 부재**다. 다음을 만족한 파일만 분할한다.

- **Go**(`GO-14~21`): `golangci-lint`·`gofmt`·`-race -shuffle` 게이트 존재(M1) + 해당 패키지 커버리지 기준선 기록. 분할 후 커버리지 하락 0.
- **프론트**(`FE-9~13`·`FE-23`): 로드 순서 검사기 또는 eslint `no-undef` 존재(M6) + e2e 가 `app.testing` 공개 계약만 사용(M6 2단계). 이 둘 없이 옮기면 `ReferenceError` 가 런타임에만, 해당 경로가 실행될 때만 나타난다(`02 FE-3`).

- **공통**: **분할 PR 은 동작 변경 0**. 이동 전후 대응표를 남기고 같은 PR 에 기능 변경을 섞지 않는다.
