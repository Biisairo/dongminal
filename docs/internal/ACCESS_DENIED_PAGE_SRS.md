# SRS: 막힌 출발지에게 보이는 화면 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요

### 1.1 목적

사용자 요구 (2026-09-11):

> *"ip 맞지않아 막힐 때 보여지는 페이지 만들어줘. 로딩페이지랑 비슷하게 톤앤매너
> 맞춰서. 여기에는 막힌 본인의 ip, 그리고 해당 서버 소유자에게 문의하라는 내용이
> 있어야해."*
>
> *"화면에는 본인 접근 ip가 있어야 서버장한테 알릴 수 있으므로 보여준다."*

지금은 `403 forbidden` **평문 한 줄**이다. 그 한 줄은 무엇이 막혔는지도, 무엇을
해야 하는지도 말하지 않는다 — 접속하려던 사람은 자기 IP 를 알 방법이 없고, 소유자는
무엇을 허용해야 하는지 들을 방법이 없다.

### 1.2 범위

- `internal/webserver/httpapi/access_denied.go` (**신규**) — 판정과 화면.
- `internal/webserver/httpapi/access.go` — `accessGate` 의 거절 갈래 한 곳.
- Go 검사.

비포함:

- **차단의 자리와 규칙**. 그것은 `ACCESS_ALLOWLIST_SRS` 의 것이며 한 줄도 바뀌지
  않는다 — 이 문서는 **거절의 표현**만 다룬다.
- 인증(`authGate`)·`requestGate`(Host·Origin)의 거절 화면. 그쪽의 실패는 성질이
  다르다(브라우저 매개 공격의 자리다).
- 소유자에게 자동으로 알리는 길(요청 보내기 버튼 등).

### 1.3 정의

- **문서 요청**: 브라우저의 주소창 이동. `Sec-Fetch-Mode: navigate` 이거나
  `Accept` 에 `text/html` 이 있고 WebSocket 업그레이드가 아니다.
- **자족적(self-contained)**: 바깥 자산(CSS·JS·글꼴·이미지)을 하나도 참조하지
  않는다.

## 2. 현재 상태 (조사로 확정)

### 2.1 차단은 **애플리케이션 계층**이다

`accessGate`(`access.go:471`)는 `loggingMiddleware` 안쪽·`mux` 바깥의 HTTP
미들웨어다. 즉 TCP 핸드셰이크는 **끝나고**, 요청 줄과 헤더를 읽은 뒤에 거절한다.

그러므로 **거절 시점에 우리는 응답을 쓸 수 있다** — 이 요구가 성립하는 이유다.
커널·방화벽에서 막았다면 화면을 줄 자리 자체가 없다.

### 2.2 막힌 출발지는 **정적 자산도 받지 못한다**

`FR-ACL-11`: 게이트는 `/`·정적 자산·`/api/*`·`/ws` 를 한 겹에 덮는다. 그래서
차단 화면이 `style.css` 를 참조하면 그 요청도 403 이 되고, 화면은 **영영 맨몸**으로
뜬다. 화면은 자족적이어야 한다.

### 2.3 목록은 나가면 안 된다

`FR-ACL-8`: 응답에 목록 내용을 싣지 않는다. **요청자 자신의 IP 는 이 규칙과
충돌하지 않는다** — 그는 이미 그 값을 안다(그의 주소다). 오히려 그것을 말해 주지
않으면 소유자에게 무엇을 알려야 하는지 모른다.

## 3. 요구사항

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| FR-ADP-1 | **문서 요청**이면 거절을 화면으로 낸다. 그 밖(API·`/ws`)은 지금처럼 평문이다 — API 클라이언트에 HTML 을 주면 그쪽의 오류 처리가 그것을 파싱하려 들고 진짜 사유가 화면 뒤로 숨는다 | 필수 |
| FR-ADP-2 | 상태 코드는 **403 그대로**다. 화면이 바뀐다고 뜻이 바뀌지 않는다 | 필수 |
| FR-ADP-3 | 화면은 **요청자 자신의 IP** 를 보인다. 정규화에 실패했으면 `RemoteAddr` 원문이라도 보인다 — 알릴 것이 없으면 이 화면은 있으나 마나다 | 필수 |
| FR-ADP-4 | 화면은 **소유자에게 알리라**고 말하고, 소유자가 고칠 자리(`설정 ▸ Access`)를 함께 적는다 | 필수 |
| FR-ADP-5 | 화면은 **자족적이다** (§2.2) — 스타일은 인라인, 로고는 인라인 SVG, 스크립트는 없다 | 필수 |
| FR-ADP-6 | **오류 화면으로 읽혀야 한다.** 브랜드(바탕·글꼴·로고)는 같지만 **부트 화면에 글자만 바꾼 것이어서는 안 된다** — 사용자 요구: *"확실하게 너는 거부되었다는 걸 알려주는 게 중요해. 로딩에 글자만 바꾸지 말고 다른 오류창처럼 만들어야 해."* 그러므로 ① 테두리 있는 **카드** ② 위쪽의 **경고색 선**과 `ACCESS DENIED` 배지 ③ **제목**(`접근이 차단되었습니다`)과 상태 이름(`403 Forbidden`) ④ 로딩의 부속(흐르는 진행 바)은 **없다** | 필수 |
| FR-ADP-6a | IP 는 **레이블이 붙은 상자**에 담고 `user-select:all` 로 한 번에 잡히게 한다 — 소유자에게 알리려면 복사해야 하고, 이 화면에는 스크립트가 없어 복사 버튼을 둘 수 없다. 그 손짓을 한 줄로 **말해 준다**("클릭하면 주소 전체가 선택됩니다") | 필수 |
| FR-ADP-6b | 경고는 **넓고 옅은 붉은 기운 + 원 안의 금지 표시**로 준다. 하드한 경고줄(상단 3px 선)은 쓰지 않는다 — 그것은 옛 알림창의 관용이며 이 제품의 화면과 어울리지 않는다(사용자 판정: *"디자인 너무 못생겼는데"*). 원 밖의 맨 글리프는 장식으로 읽히고 **원 안의 것이 상태로 읽힌다** | 필수 |
| FR-ADP-7 | 목록 내용은 한 줄도 싣지 않는다 (`FR-ACL-8`) | 필수 |
| FR-ADP-8 | 이 응답도 보안 헤더를 진다 — CSP·`nosniff`·`X-Frame-Options: DENY`·`no-store`. 한 자리만 정책 없이 나가면 그 자리가 예외가 된다 | 필수 |

## 4. 설계 결정

- **D-1. 판정은 `Sec-Fetch-Mode` 먼저, `Accept` 는 폴백.** 브라우저의 주소창 이동은
  전자를 붙이며 그것이 가장 곧은 근거다. 옛 판·`curl` 을 위해 후자를 남긴다.
- **D-2. WebSocket 은 무조건 평문.** `Upgrade: websocket` 은 `Accept` 에 무엇이
  있든 문서가 아니다.
- **D-3. 인라인 스크립트를 두지 않는다.** 두면 CSP 에 해시가 필요하고, 해시는
  서빙되는 바이트에서 계산해야 하며(`FR-MVN-13a`), 그 계산을 이 자리에 또 만들면
  같은 기계가 두 벌이 된다. 스크립트가 필요 없는 화면이므로 만들지 않는다.
- **D-4. 자기 IP 는 누설이 아니다** (§2.3).

## 5. 검증

| ID | 재는 것 | 기대 |
|----|--------|------|
| V-ADP-1 | 문서 요청 | 403 · `text/html` · 자기 IP 가 보인다 |
| V-ADP-2 | 같은 응답 | "소유자" 안내가 있다 |
| V-ADP-3 | 같은 응답 | 목록 항목(`10.0.0.1`)·`allow`·`entries` 가 **없다** |
| V-ADP-5 | `Accept: application/json` · 헤더 없음 · WebSocket 업그레이드 | 셋 다 평문 403 |
| V-ADP-6 | 화면 본문 | `<script`·`src=`·`href=`·`@import` 가 **하나도 없다** |
| V-ADP-7 | 응답 헤더 | CSP 가 있고 `script-src` 에 `unsafe-inline` 이 없다 |
| V-ADP-8 | `RemoteAddr` 가 주소가 아닐 때(`pipe`) | 그 원문이 화면에 있다 |
| **V-ADP-9** | 화면이 오류로 읽히는가 (`FR-ADP-6`) | 제목(`<h1`) · `차단` · `403` · 경고색(`#f7768e`)이 함께 있고, 로딩의 부속(`boot-bar`·`불러옵니다`)은 **하나도 없다** |

## 6. 비목표

- 소유자에게 자동 통지·요청 보내기.
- 재시도 안내(새로고침 버튼) — 허용은 소유자가 하는 일이고 이쪽에서 다시 눌러
  달라지는 것이 없다.
- 다국어. 이 제품의 화면은 한국어다.
- `requestGate`(Host·Origin) 거절의 화면화 — 성질이 다르다 (§1.2).

## 7. 리스크

| ID | 리스크 | 등급 | 완화 |

| R-ADP-1 | API 클라이언트가 HTML 을 받아 오류 처리가 어긋난다 | MEDIUM | `FR-ADP-1` 의 판정과 `V-ADP-5` 의 세 경우 |

| R-ADP-3 | 화면이 목록을 누설한다 | HIGH | `V-ADP-3`. 그리고 화면에 들어가는 값은 **요청자 IP 하나**뿐이다 |
