```bash

go build ./... && go vet ./... && go test ./...
```

## 1. 한 줄 상태

네 단계(통짜 파일 분할 · e2e 헬퍼 회수 · flaky 수정 · `RunsPanel` 추출)가 끝났다.
남은 일은 **`App` 상태 추출의 나머지 후보를 재검토**하는 것이다.

## 2. 이번 세션의 일

**남은 후보를 완벽하게 분석하고, 확실한 것만 진행한다. 확실하지 않으면 패스하고
사유를 SRS 에 남긴다.** 이득 없는 추출은 위임 계층만 늘린다 — 하지 않는 것이 옳은
결과일 수 있다.

### 대상

| 후보 | 상태 |
|---|---|
| `app-statusbar.js` | **미조사.** 전용 필드 7개로 남은 것 중 가장 많다 — 먼저 재라 |
| `app-editor.js` | 잠정 부적합 (바깥이 부르는 메서드 35/50) |
| `app-attn.js` | 잠정 부적합 (14/26) + 주제 혼재 |
| `app-reload.js` | 잠정 이득 없음 (전용 필드 3) |

**잠정 판정을 그대로 믿지 마라.** 앞 세션의 측정은 한 번 틀렸다. 직접 다시 재라.

### 추출보다 값이 클 수 있는 것

`app-attn.js` 가 알림과 무관한 공용 유틸(`_findToolLocation`·`_jumpToTool`·
`_toolName`)을 정의하고 있다. 객체로 뽑을 것이 아니라 **제자리로 돌려보내는**
일이며 위임 껍데기가 필요 없다. 별도 SRS 를 세워라.

## 3. 반드시 지킬 것

**조사할 때 세 가지를 모두 센다.** ① 바깥이 부르는 메서드 ② 바깥이 `app.` 으로 읽는
필드 ③ **형제 파일이 `this.` 로 만지는 필드**. ③ 이 최대 함정이다 — 형제 `app-*.js`
는 `app.` 이 아니라 `this.` 로 접근하므로 `app\.` 으로 찾으면 걸리지 않는다. 파일은
갈렸어도 `this` 는 하나다. 앞 세션이 이것을 놓쳐 e2e 3건이 깨졌다.

**측정할 때 어느 파일이 무엇을 정의하는지 먼저 매핑한다.** `this.<이름>` 을 전부
필드로 세면 다른 파일의 메서드 호출이 섞여 들어간다 — 앞 세션이 그렇게 틀렸다.

**옮기기는 `Object.assign` 증강으로, 메서드 이름은 바꾸지 않는다.** 그래야 "옮기기만
했다" 가 diff 로 증명된다.

**e2e 실패 1건은 회귀가 아닐 수 있다.** 이 저장소는 전량 실행에서 927개 중 1개
정도가 산발로 흔들리고 실행마다 다른 스펙이 걸린다. 실패하면 **반드시 단독 재실행**
으로 가른다.

**조직 규정**: 스펙 문서 없이 작업하지 않는다. 커밋 메시지에 AI 서명을 넣지 않는다.
