  - **Go 와 다르게 한 내부 결정**
    - `Service.mu` 는 tokio Mutex 다. `switch` 가 잠근 채 프로필 조회(네트워크)를 기다리기 때문이다. 파일 락·키체인·디렉터리 락은 Go 처럼 그 안에서 블로킹으로 부른다(호출부는 멀티스레드 런타임이어야 한다).
    - `switch` 의 실패는 `Err` 하나다. Go 는 실패 때도 부분 `SwitchResult` 를 돌려주지만 호출부(smart.switchTo, httpapi)는 오류일 때 그 값을 쓰지 않는다.
    - Go `map` 을 순회하던 `Resolve`(같은 길이 폴더 둘이 걸릴 때)·`PruneTabs` 는 BTreeMap 순서로 정해진다. Go 는 그 경우를 정하지 않는다.
    - `EvalSymlinks` 는 `fs::canonicalize` 다. Windows 의 `\\?\` 머리는 뗀다.
    - `sharedLinker` 의 시험 이음매는 `SharedLinker{symlink, junction}`(Box<dyn Fn>) 로 옮겼다.
  - **남은 위험**: Windows 경로(정션·대소문자 접기·canonicalize 머리)는 이 Mac 에서 실행 검증하지 못했다(MEDIUM, 8.x). `State.accounts` 의 null↔[] 차이는 Service 경로에서는 드러나지 않음을 확인했다(쓰기는 늘 계정을 넣거나 빈 non-nil slice 를 남긴다).
