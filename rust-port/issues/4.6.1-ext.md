# 4.6.1 ext

## 목표

확장 플러그인 내려받기·설치·매니페스트·내장 목록(builtin JSON 포함). 시험에서 실제 네트워크에 나가지 않고 로컬 HTTP 가짜 서버를 쓴다. 부모 이슈는 4.6 이다.

## 대상 Go 코드

- `internal/webserver/domain/ext` (프로덕션 약 2195줄)

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)

- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  - **Go 와 다르게 한 내부 결정**
    - Go 의 전역 var(MaxArchiveBytes·renameDir·writeDeployedFile)를 시험 훅으로 바꾸지 않고 내부 `Opts`·`deploy_with` 인자로 주입한다. 병렬 시험이 서로 간섭하지 않게 하려는 것이다. `MAX_ARCHIVE_BYTES` 는 const 다.
    - Kind·SourceKind·Origin·MissingKind 는 String 과 상수로 두었다. 모르는 값을 오류 문구에 그대로 실어야 하기 때문이다.
    - targets·provides 는 BTreeMap 이다. Go map 의 순회 순서가 무작위라 타깃 여럿이 깨졌을 때 어느 사유가 먼저 보고될지 Go 는 정하지 않는다. Rust 는 이름 순으로 고정한다.
    - Go `os` 함수의 동작과 문구(MkdirAll 단계, Remove, CreateTemp, MkdirTemp, ReadDir 정렬)는 ext 안의 `goos.rs` 에 옮겼다. 공용으로 둘 곳이 없어서다. 다른 이슈가 같은 것을 원하면 gocompat 으로 옮길 후보다.
    - 아카이브 읽기 오류 문구는 Go archive/tar·zip·gzip 과 다를 수 있다. 머리 오류(`gzip: invalid header`, `zip: not a valid zip file`, `unexpected EOF`)만 맞췄다. 이 문구는 Outcome.detail 에만 나간다.
    - HTTP 전송 오류 꼬리는 reqwest 문구다(`Get "url": …` 앞부분과 상태 문구 `<url>: 404 Not Found` 는 Go 와 같다). 1.3 release 와 같은 한계다.
  - **남은 위험**: 위의 시험 미완(fetch·install 경로는 아직 시험으로 검증하지 않았다 — MEDIUM). windows·linux 교차 check 를 하지 못했다. HostExec 의 WaitDelay·취소 동작은 실행 검증 전이다.
