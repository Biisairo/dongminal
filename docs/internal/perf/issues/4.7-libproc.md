**바꾼 것**
- `shared/platform/src/procinfo/darwin.rs`: 커널 접근 트레이트 `Kernel`(name·cwd·parent·pids·children)을 주입받는다. has_children·children_of·cwd·cwds·names·parent_pid·parents 는 커널에서 읽는다. listener_pids·connection_owner_pid 만 `lsof` 를 띄운다.
- 새 `procinfo/darwin/libproc.rs`(macOS 전용): `proc_listchildpids`·`proc_listallpids`(버퍼 여유·꽉 차면 두 배로 다시 읽기), `proc_pidinfo(PROC_PIDVNODEPATHINFO)`(cwd), `proc_pidinfo(PROC_PIDT_SHORTBSDINFO)`(부모·물러섬 이름), `sysctl(KERN_PROCARGS2)`(argv[0]). 반환 크기를 구조체 크기와 대조하고, unsafe 마다 SAFETY 주석을 달았다. 버퍼 상수는 이름 있는 상수(주기 값 아님 — cadence 대상 아님).
- `webserver/seam/adapters`: `resolve_client_pane` → `resolve_with(&dyn ProcInfo, …)`. `parents()` 를 한 번 읽어 표로 조상을 오른다.
- `procinfo.rs`: `children_from_pairs` 는 이제 Windows 만 쓴다(`cfg_attr(not(windows), allow(dead_code))`).
- 문서(이 이슈 범위): CROSS_PLATFORM_SRS FR-XPI-3 개정, §5 비목표 7 취소선, §4.1 검증 표에 darwin 시험 추가.

**지운 것**: darwin 의 `ps_pairs`·`parse_pid_ppid`·`parse_lsof_cwds`·`parse_lsof_cwd`·`parse_ps_comm_output`·`join_pids` 와 그 시험, ps·pgrep 기반 시험(`darwin_proc_info`·`names_is_single_call`·`cwds_single_call_and_pairing` 등). 대체 시험은 `kernel_answers`·`kernel_reads_spawn_nothing` 이다.

**동작 변경**
- 이전: 데몬 전경 이름(2초)·busy·cwd·부모 조회마다 `ps`·`pgrep`·`lsof` 를 띄웠다. 조상 오르기는 단계마다 `ps -o ppid=` 를 띄웠다.
- 새: 위 조회는 외부 프로세스를 띄우지 않는다. 조상 오르기는 `parents()` 한 번이다.
- 이유: 유휴 외부 프로세스 0(FR-SRV-3·NFR-PRF-5, D-60).
- 이름 값: 실측에서 자기 사용자 프로세스 전부(약 620개)가 `ps -o comm=` 과 같았다. 좀비는 이름이 없다(이전 `<defunct>`). 다른 사용자 프로세스는 16바이트 `p_comm` 이다(이전 ps 는 전체 경로). 전경 이름은 자기 사용자 프로세스만 쓰므로 영향이 없다.

**설계와 다르게 한 것**
- 이름을 `proc_name` 이 아니라 `KERN_PROCARGS2` 의 argv[0] 으로 읽는다. 물러섬은 `pbsi_comm` 이다. `proc_name` 은 실행 파일의 실제 이름을 준다. 예를 들어 claude 는 버전 디렉터리 링크라서 `claude` 대신 `2.1.332` 가 나온다. 그러면 탭 이름(FR-TAN)이 퇴행한다. 또 다른 사용자 프로세스에는 EPERM 이 난다.
- 부모 조회에 `PROC_PIDT_SHORTBSDINFO` 를 쓰고, 전체 목록은 `proc_listallpids` 로 읽는다(설계 §2 에 없는 호출).
- 조상 오르기 `parents()` 는 전 프로세스(약 900개)마다 `proc_pidinfo` 를 부른다. libproc 에서는 `parent_pid` 를 몇 번 부르는 쪽이 더 싸다. 그래도 승인된 설계(`parents` 1회)를 따랐다. whoami 폴백 경로라 드물게 불린다.

**시험**
- RED 확인: `kernel_reads_spawn_nothing`·`kernel_answers`·`only_connection_queries_spawn_lsof`(실행기 호출 10회)와 adapters `client_resolver_reads_parent_table_once`(parent_pid 2회)가 실패했다.
- GREEN: `otter-shared-platform --lib` 259 통과, `otter-webserver-seam-adapters --lib` 7 통과, `otter-shared-toolhub --lib` 119 통과, `otter-webserver-httpapi --lib info_api` 20 통과.
- 실제 대조 `libproc_matches_system_tools`: 자기 PID 이름 = `ps -o comm=`, 부모 = getppid, cwd = current_dir, pid 1 의 부모 = 0, 없는 pid 는 None.
- fmt·clippy(platform·adapters, -D warnings) 통과. Linux·Windows 대상 clippy 는 디스크 정리 전에 한 번 통과했고, 그 뒤 조정자 지시로 다시 돌리지 않았다.
- 게이트: check-*.mjs 전부, check-*.sh 전부(check-cross 는 조정자 지시로 제외), scripts/test 105개 중 104 pass·0 fail. 첫 실행의 check-*.sh 실패 9개는 디스크 부족 때문이었다. 정리 뒤 다시 돌리니 check-gitwrite 를 포함해 전부 통과했다.
- 릴리스 빌드·e2e 는 하지 않았다(조정자 지시로 대기).

**남은 위험**
- unsafe FFI(MED): 크기·반환값을 검사한다. 실기 대조는 macOS(aarch64)에서만 했다.
- `darwin::current` 를 `target_os = "macos"` 로 한정했다. macOS·Linux·Windows 가 아닌 unix(예: FreeBSD)는 `procinfo::current` 의 darwin 가지가 컴파일되지 않는다. 이전에는 ps 기반으로 컴파일됐다. 빌드 대상이 아니라고 보았다.
- `otterctl doctor` 의 이름 출력이 argv[0] 기반이라 이전과 같다.

**코드와 어긋난 문서(고치지 않음)**: CROSS_PLATFORM_SRS NFR-XP-3("platform 은 cgo 를 쓰지 않는다", Go 시절 문구). Rust 에는 cgo 가 없고 이미 libc FFI 를 쓴다.
