# SRS: 다시 세우는 모든 동작에 로딩 화면 (IEEE 29148 준수)

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)
화면을 **처음부터 다시 세우는 모든 동작**에서 준비되지 않은 화면 대신 로딩 화면(`#boot`)을
보인다. 지금 그 화면이 도는 것은 브라우저 새로고침 하나뿐이며, 나머지 새로고침 셋은 낡은
화면이나 빈 골격을 그대로 노출한다.

### 1.2 범위 (Scope)
- 포함: `web/js/ui/boot-screen.js`(다시 세우는 손잡이), `web/js/core/constants.js`(단계 문구),
  `web/js/core/app-reload.js`(내부 새로고침), `web/js/ui/version-watch.js`(새 버전 자동 새로고침),
  `web/js/core/app-backup.js`(설정 되돌리기 후 새로고침), `e2e/boot-reuse.spec.ts`(신규).
- 비포함: **걷힘 조건 변경**(BOOT_SCREEN_SRS FR-BTS-13 · D-1 을 유지한다 — D-BTR-1),
  테마 선주입, 부팅 화면의 시각 구성, `softReload` 의 복원 순서·항목(FR-SRL-1).

### 1.3 정의 (Definitions)
- **로딩 화면**: `#boot` 오버레이. BOOT_SCREEN_SRS 가 정의한 그 노드이며 새로 만들지 않는다.
- **다시 세우는 동작**: 워크스페이스·도구·패널을 옛 화면 위에서 다시 구성하거나, 문서 자체를
  다시 여는 동작. 이 스펙에서는 셋이다 — 내부 새로고침 · 새 버전 자동 새로고침 · 설정 되돌리기.

## 2. 현황 (Current State)
1. `#boot` 는 **첫 문서 로드에서만 산다.** `BootScreen.done()` 이 `el.remove()` 로 노드를 떼고
   `_done` 을 true 로 잠그며(`boot-screen.js:22-28`), 그 뒤의 `step`·`done` 은 전부 무시된다.
2. 내부 새로고침(`softReload`, `app-reload.js`)은 워크스페이스·편집기 목록·Git 패널·탐색기 트리·
   모든 터미널을 다시 세우면서도 화면을 덮지 않는다. 표시는 버튼의 `busy` 하나뿐이다(FR-SRL-11) —
   그 동안 낡은 화면이 그대로 조작 가능하다.
3. 앱이 스스로 여는 새로고침 둘(`version-watch.js:68` 새 버전 감지, `app-backup.js:170` 설정
   되돌리기)은 `location.reload()` 를 부르기만 한다. 요청부터 새 문서의 첫 페인트까지 옛 화면이
   남고 그 구간에는 아무 표시도 없다.
4. 실측(격리 인스턴스, 2026-09-06): 브라우저 새로고침에서 `#boot` 는 정상적으로 서며 약 200ms
   뒤 걷힌다. 즉 결함은 첫 부팅 경로가 아니라 **나머지 세 경로에 그 화면이 없다**는 것이다.

### 2.1 사용자 결정 (2026-09-06)
- **D-BTR-1** 걷힘 조건은 지금 그대로다(테마 결정 + `app.init()` 완료). 터미널 첫 페인트나 패널
  렌더까지 늘리지 않는다 — BOOT_SCREEN_SRS D-1 을 유지한다.
- **D-BTR-2** 대상은 다시 세우는 동작 **전부**다: 내부 새로고침 · 새 버전 자동 새로고침 ·
  설정 되돌리기 후 새로고침.

### 2.2 설계 결정
- **D-BTR-3** `done()` 의 `remove()` 는 그대로 두고, **떼어 낸 노드를 보관했다가 다시 붙인다.**
  숨김(`hidden`)으로 바꾸면 FR-BTS-12 와 그 검증(`toHaveCount(0)`)이 함께 뒤집힌다. `remove()` 된
  노드의 참조는 살아 있으므로 되붙이는 데 새 DOM 이 필요 없다.
- **D-BTR-4** 상한(FR-BTS-14)은 **세울 때마다** 다시 건다. 모듈 로드 시 한 번만 걸린 지금 구조로는
  두 번째 표시에 상한이 없어, 끝나지 않는 새로고침이 화면을 영영 잠근다.
- **D-BTR-5** 걷을 때 상한 타이머를 **해제한다.** 해제하지 않으면 첫 부팅의 상한이 뒤늦게 도착해
  방금 세운 화면을 즉시 걷는다.
- **D-BTR-6** 페이드아웃 뒤의 `remove()` 는 **여전히 걷힌 상태일 때만** 한다. 페이드 도중
  (`BOOT_FADE_MS`) 다시 세워지면 그 제거가 방금 붙인 노드를 떼어 간다.
- **D-BTR-7** `location.reload()` 앞의 표시는 문구만 다르고 **같은 손잡이**다. 다시 열린 문서의
  `#boot` 와 이어져 사용자에게는 끊기지 않은 한 장면이다.
- **D-BTR-8** 단계 문구는 상수다(`constants.js`). 부르는 자리마다 문자열을 적으면 같은 장면이
  자리마다 다른 말을 한다.

## 3. 요구사항 (Requirements)

### 3.1 기능 요구사항 (Functional)
| ID | 요구사항 | 우선 |
|----|---------|------|
| FR-BTR-1 | `BootScreen.show(text)` 는 걷힌 로딩 화면을 다시 세운다: 보관한 노드를 `body` 의 첫 자식으로 되붙이고, `gone` 을 떼고, 잠금(`_done`)을 풀고, 단계 문구를 `text` 로 세운다. | 필수 |
| FR-BTR-2 | 이미 서 있는 상태의 `show` 는 문구만 바꾼다 — 노드를 다시 붙이지 않는다. | 필수 |
| FR-BTR-3 | `show` 는 상한 타이머를 다시 건다. 표시 뒤 `BOOT_MAX_MS` 가 지나면 걷힌다 (D-BTR-4). | 필수 |
| FR-BTR-4 | `done()` 은 자기가 건 상한 타이머를 해제한다 (D-BTR-5). | 필수 |
| FR-BTR-5 | 페이드아웃 뒤의 노드 제거는 그 시점에도 걷힌 상태일 때만 수행한다 (D-BTR-6). | 필수 |
| FR-BTR-6 | `#boot` 가 없으면(이미 제거됐고 참조도 없는 경우) `show` 는 아무 일도 하지 않는다 — 호출한 동작 자체는 진행된다. | 필수 |
| FR-BTR-7 | `softReload()` 는 시작에서 `show(BOOT_STEP_RELOAD)` 하고, `finally` 에서 `done()` 한다. | 필수 |
| FR-BTR-8 | 겹쳐 부른 `softReload` 는 종전대로 즉시 돌아가며(`_softReloading` 가드) 로딩 화면을 세우지도 걷지도 않는다. | 필수 |
| FR-BTR-9 | 버튼의 `busy` 표시(FR-SRL-11)는 그대로 남는다 — 로딩 화면이 그것을 대신하지 않는다. | 필수 |
| FR-BTR-10 | 새 버전 자동 새로고침은 `location.reload()` **직전에** `show(BOOT_STEP_VERSION)` 한다. | 필수 |
| FR-BTR-11 | 설정 되돌리기 후의 새로고침은 `location.reload()` 직전에 `show(BOOT_STEP_BACKUP)` 한다. | 필수 |
| FR-BTR-12 | 로딩 화면이 서 있는 동안 그 아래 UI 는 포인터 입력을 받지 않는다 — FR-BTS-8 이 그대로 적용된다(새 CSS 없음). | 필수 |

### 3.2 비기능 요구사항 (Non-functional)
- NFR-BTR-1 새 DOM·새 CSS 를 만들지 않는다. 첫 부팅과 **같은 노드·같은 스타일**이다.
- NFR-BTR-2 첫 부팅 경로의 동작은 바뀌지 않는다 — `e2e/boot-screen.spec.ts` 는 수정 없이 통과한다.
- NFR-BTR-3 `softReload` 의 복원 순서·실패 격리(FR-SRL-1·4)는 바뀌지 않는다.

### 3.3 이전 동작 / 새 동작 / 이유
| 항목 | 이전 | 새 | 이유 |
|------|------|-----|------|
| 내부 새로고침 중 화면 | 낡은 화면이 그대로 보이고 조작된다 | 로딩 화면이 덮는다 | 다시 세우는 중의 화면은 조작 대상이 아니다 |
| 자동 새로고침 요청 직후 | 옛 화면이 그대로 | 로딩 화면이 서고, 새 문서의 `#boot` 로 이어진다 | 사용자에게는 한 장면이어야 한다 |
| `BootScreen` 의 수명 | 첫 부팅 1회 | 몇 번이든 다시 세운다 | 다시 세우는 동작이 셋이다 |
| 상한 타이머 | 모듈 로드 시 1회 | 세울 때마다 걸고 걷을 때 해제 | 두 번째 표시에도 잠김 방어가 있어야 한다 |

## 5. 리스크
- LOW: 노드를 되붙이는 것 외에 새로 만드는 것이 없다. 실패 경로는 전부 "세우지 않음 = 종전 동작"으로 떨어진다.
- LOW: 내부 새로고침이 오래 걸리면 로딩 화면이 그만큼 오래 남는다 — 상한(6초)이 그 자리에서 걷는다.
- 잔여: 브라우저 새로고침의 걷힘 시점은 그대로다(D-BTR-1). 터미널 첫 출력 전의 빈 골격 구간은 이 스펙의 대상이 아니다.
