# SRS: 자산 판의 단일 출처 — `?v=` 를 손으로 적지 않는다 — IEEE 29148

## 1. 개요

### 1.1 목적

접수한 말은 하나다.

> **"지금 js 버전을 전체 js 에 명시하고 있는데 이거 한쪽에서 한 개로 관리 못하나"**

`web/index.html` 은 지금 `?v=232` 를 **70 번** 적는다. 자산을 하나라도 고치면 그 70 개를
한꺼번에 올려야 하고, 올리지 않으면 브라우저는 캐시에 있는 옛 JS 를 계속 돌린다.

그 계약은 **사람의 기억**이었다. 실제로 두 커밋이 `web/js/` 를 고치면서 `?v=` 를 그대로
뒀고, e2e 는 매번 새 브라우저 컨텍스트라 캐시가 없어 전부 통과했다 — 아무도 울지 않는
실패였다. 그래서 `web/version_test.go` 와 `web/assets.lock` 이 잠금으로 서 있다.

이 문서가 하는 일은 **관리 지점을 하나로 줄이는 것**을 넘어선다. 자산의 판을 자산 자신의
내용에서 파생시켜 **"올리는 것을 잊는다"는 실패 모드 자체를 없앤다.** 잠금이 지킬 것이
없어지므로 잠금도 함께 걷는다.

### 1.2 범위

**포함**
- `index.html` 의 `?v=` 를 **자리표시자 하나**로 바꾸고, 서버가 서빙 시점에 치환하는 것
- 판을 **embed 된 JS·CSS 의 내용 해시**에서 파생시키는 것
- 그 판을 SSE 인사(`server_hello`)와 자동 새로고침 판정이 그대로 쓰게 하는 것
- 치환된 문서에 맞는 ETag
- `web/version_test.go` · `web/assets.lock` 의 폐기와 대체

**미포함**
- `vendor/` 자산의 캐시 무효화 (§6 비목표 #1)
- `?v=` 표기 자체의 폐기 — 전 자산 `no-cache` 로 가는 길 (§6 비목표 #2)
- 자동 새로고침의 **동작**. 판의 형식만 바뀌고 흐름은 `RELOAD_CONTINUITY_SRS` 묶음 P·S
  그대로다 (§6 비목표 #3)
- 빌드 시점 번들링·해시 파일명 (§6 비목표 #4)

## 2. 현재 상태

### 2.1 판은 70 곳에 손으로 적혀 있다

```html
<link rel="stylesheet" href="style.css?v=232">
...
<script src="js/core/constants.js?v=232"></script>
...
<script src="js/ui/diag.js?v=232"></script>
```

`web/index.html` 에 `?v=` 가 70 개. 값은 전부 같아야 하며, 그것을 `web/version_test.go`
의 `assetVersion` 이 검사한다 — 갈리면 "한 페이지가 두 세대의 자산을 섞어 부른다".

### 2.2 그 값의 소비자는 셋이다

단순한 캐시 버스터가 아니다.

1. **브라우저 캐시 무효화.** `internal/webserver/httpapi/static.go` 가 적은 계약이다 —
   HTML 은 `no-cache` 로 늘 재검증하고, **나머지 자산은 `?v=` 로만 무효화된다.**
2. **앱의 판 식별자.** `server.go:262` 의 `core/main\.js\?v=(\d+)` 가 서빙되는 문서에서
   값을 긁어 SSE 인사에 싣고(`commands.go:233`), `version-watch.js` 가 자기 것과 견주어
   자동 새로고침을 건다 (`RELOAD_CONTINUITY_SRS` FR-RLC-20·21·23).
3. **잠금.** `web/version_test.go` + `web/assets.lock` — 자산이 바뀌었는데 `?v=` 가
   그대로면 실패시킨다.

### 2.3 잠금은 실패를 잡을 뿐, 일을 줄이지 않는다

잠금이 붙잡는 것은 "잊었다" 이고, 그때 사람이 해야 할 일은 여전히 둘이다 — 70 개를 올리고
`assets.lock` 을 새 해시로 바꾼다. 잠금은 **사람이 하는 일을 대신하지 않는다.**

### 2.4 판정은 `(\d+)` 를 전제한다

값이 십진수라는 전제가 다섯 자리에 박혀 있다.

| 자리 | 표현 |
|------|------|
| `internal/webserver/httpapi/server.go:262` | `core/main\.js\?v=(\d+)` |
| `web/js/ui/version-watch.js:31` | `/[?&]v=(\d+)/` |
| `web/js/ui/version-watch.js:98` | `/core\/main\.js\?v=(\d+)/` |
| `web/version_test.go:26` | `\?v=(\d+)` |
| `e2e/version-autoreload.spec.ts` (4 곳) | `\?v=\d+` · `[?&]v=(\d+)` |

판정 자체(`saw`·`tried`·`reload`)는 값을 **문자열로만** 비교한다 — 형식에 매이지 않는다.

## 3. 요구사항

### 3.1 묶음 A — 판의 출처 (FR-AVS)

**FR-AVS-1** 자산의 판은 **서빙되는 자산의 내용에서 파생한다.** 사람이 적는 수가 아니다.
값은 embed 된 `.js` · `.css` 전체를 경로 순으로 이어 붙인 SHA-256 의 앞 12 자리 hex 다.

> 경로도 해시에 넣는다. 내용을 그대로 둔 채 파일을 옮기거나 이름을 바꾸는 것도 판의
> 변화이며, 내용만 이으면 그것이 보이지 않는다.

**FR-AVS-1a** `vendor/` 는 제외한다. 우리가 고치지 않는 제3자 사본이고, 고치는 순간 파일
이름이 바뀐다 — `?v=` 의 대상이 아니다. (기존 `hashAssets` 와 같은 근거·같은 경계다.)

**FR-AVS-1b** `index.html` 자신은 제외한다. 그것이 판을 담으므로 넣으면 서로를 물고
늘어진다.

**FR-AVS-2** 계산은 **프로세스당 한 번**이다. 자산은 바이너리에 박혀 있어
(`web/embed.go`) 프로세스가 사는 동안 바뀌지 않는다.

**FR-AVS-3** 판을 아는 자리는 **하나**다. 서빙하는 문서를 치환하는 쪽과 SSE 인사에 싣는
쪽이 **같은 값**을 받는다.

> 이것이 `RELOAD_CONTINUITY_SRS` FR-RLC-21 의 걱정을 구조적으로 해소한다. 그 조항은
> "빌드 시점에 손으로 적는 상수를 쓰면 `?v=` 와 갈라진다"를 막으려고 서버가 **서빙되는
> 문서를 되읽게** 했다. 이제 서버가 그 문서를 **쓰는 쪽**이므로 갈릴 수가 없다 — 되읽는
> 것은 같은 값을 두 번 만드는 일이며, 정규식이라는 깨질 자리를 하나 더 두는 것이다.

### 3.2 묶음 B — 문서의 치환 (FR-AVS)

**FR-AVS-4** `index.html` 은 판을 **자리표시자 하나**로 적는다: `?v=__ASSETV__`. 파일에
십진수 판이 남지 않는다.

**FR-AVS-5** 정적 핸들러는 `index.html` 을 서빙할 때 그 자리표시자를 FR-AVS-1 의 값으로
바꾼다. 치환된 바이트는 핸들러를 세울 때 한 번 만들어 들고 있는다 — 요청마다 하지 않는다.

**FR-AVS-6** `index.html` 로 이르는 **모든 경로**가 치환된 문서에 닿는다. 한쪽만
치환하면 다른 쪽으로 들어온 화면이 리터럴 `?v=__ASSETV__` 를 받는다.

> `/index.html` 은 `http.FileServer` 가 예전부터 `./` 로 301 을 준다. 그 리다이렉트를
> 없애지 않는다 — 조용한 동작 변경이 되고, 따라가면 어차피 치환본에 닿는다. 치환본을
> 직접 내는 경로는 `/` 하나다.

**FR-AVS-7** `index.html` 의 ETag 는 **치환 결과**에서 계산한다.

> **이것이 이 변경의 함정이다.** 지금 ETag 는 embed 원본의 해시다. JS 만 고친 빌드에서
> `index.html` 원본은 한 글자도 바뀌지 않는데 **출력**은 달라진다. 원본 기준 ETag 를
> 그대로 두면 브라우저가 `no-cache` 로 재검증하러 와도 서버가 같은 검증자를 주고 **304**
> 를 돌려준다 — 옛 HTML 이 남고, 옛 `?v=` 를 가리키고, 자동 새로고침도 영영 뜨지 않는다.
> `?v=` 를 올리지 않았을 때와 **정확히 같은 증상**이며, 이 문서가 없애려는 바로 그것이다.

**FR-AVS-8** 서빙된 문서에 리터럴 `__ASSETV__` 가 남아 있어서는 안 된다. 남아도 파일
서빙은 멀쩡히 되고 캐시 키만 영구히 고정되므로 — **조용히 틀린다** — 시험이 지킨다.

**FR-AVS-9** `index.html` 밖의 자산은 치환하지 않는다. 자리표시자를 두는 곳은 문서
하나다.

### 3.3 묶음 C — 판을 모르는 경우 (FR-AVS)

**FR-AVS-10** 판을 얻지 못하는 경우는 **정적 자산이 아예 없는 구성**(`StaticFS == nil`)
하나로 줄어든다. 그때 SSE 인사는 `RELOAD_CONTINUITY_SRS` FR-RLC-22 대로 **보내되 판을
싣지 않는다.**

> 종전의 두 번째 경우 — "`index.html` 에 `?v=` 가 없다" — 는 성립하지 않게 된다. 판은
> 문서의 표기가 아니라 자산의 내용에서 나오므로, 문서가 어떤 모양이든 값은 있다.

**FR-AVS-10a** JS·CSS 가 하나도 없는 `StaticFS` 여도 판은 있다 — 빈 목록의 해시다. 그것도
유효한 판이며, 자산이 생기면 달라진다.

### 3.4 묶음 D — 형식을 전제한 자리 (FR-AVS)

**FR-AVS-11** 판이 hex 가 되므로 `(\d+)` 를 쓰는 모든 자리를 `([0-9a-f]+)` 로 고친다
(§2.4 의 표). 판정 로직은 값을 문자열로만 비교하므로 손대지 않는다.

**FR-AVS-12** `server.go` 의 `assetVersionRe` 는 **없앤다.** FR-AVS-3 에 따라 서버는 자기가
만든 값을 그대로 쓴다.

**FR-AVS-13** e2e 에서 현재 판을 읽는 코드는 네 곳에 흩어져 같은 정규식을 되풀이한다.
**헬퍼 하나**로 모은다 — 형식이 또 바뀔 때 고칠 자리가 하나여야 한다.

### 3.5 묶음 E — 잠금의 폐기 (FR-AVS)

**FR-AVS-14** `web/assets.lock` 을 지운다. 지킬 계약이 없다 — 판은 자산이 바뀌면 저절로
바뀐다.

**FR-AVS-15** `web/version_test.go` 는 **다시 쓴다.** 지우지 않는다. 새로 지킬 것이 있다:
`index.html` 의 모든 `?v=` 가 자리표시자여야 하며, 십진수 판이 되살아나서는 안 된다
(FR-AVS-4). 손으로 적는 판이 하나라도 다시 들어오면 그것만 무효화되지 않는다.

## 4. 대가와 위험

**D-1** 판이 사람이 읽기 어려워진다. `232` 는 순서를 말하지만 `a3f0c1d24b8e` 는 말하지
않는다. 잃는 것은 크지 않다 — 이 값을 사람이 읽는 자리는 없고, 견주는 것은 **같은가
다른가** 뿐이다 (FR-RLC-23).

**D-2** `index.html` 이 embed 원본과 다르게 나간다. `web/embed.go` 의 바이트를 그대로
믿는 코드가 앞으로 생기면 어긋난다. 지금 그런 코드는 `server.go:274` 하나이며
FR-AVS-12 가 그것을 없앤다.

**R-1 (MEDIUM)** FR-AVS-7 을 빠뜨리면 조용히 틀린다. 시험으로 고정한다 (TC-AVS-5).

**R-2 (LOW)** 치환이 `/index.html` 경로를 놓치면 그쪽으로 들어온 화면만 리터럴을 받는다.
TC-AVS-3 이 두 경로를 함께 잰다.

**R-3 (LOW)** 판의 길이가 12 자라 이론상 충돌이 가능하다. 자산 전체가 서로 다른 두
빌드가 앞 12 자리까지 같을 확률은 무시할 수 있고, 틀렸을 때의 대가는 "새로고침이 한 번
늦는다" 다.

## 6. 비목표

1. **`vendor/` 의 캐시 무효화.** vendor 는 지금도 `?v=` 없이 로드되고 ETag 만으로
   재검증된다. 그 틈은 이 문서 이전부터 있었고 이 변경이 넓히지 않는다.
2. **`?v=` 표기 자체의 폐기.** 전 자산에 `no-cache` 를 붙이고 ETag 로만 무효화하면
   `index.html` 이 더 깨끗해지지만, 매 로드마다 조건부 요청이 70 건 나간다. 원격·모바일
   접속(`app-mobile.js`)이 있는 이상 공짜가 아니다.
3. **자동 새로고침의 동작 변경.** 판의 **형식**만 바뀐다. 감지 계기·판정·되풀이 방지·떠남
   확인 우회는 `RELOAD_CONTINUITY_SRS` 그대로다.
4. **번들링·해시 파일명.** 스크립트 70 개를 그대로 두고 순서도 그대로 둔다. `index.html`
   의 주석들이 그 순서의 근거를 적고 있다.

## 7. 개정되는 조항

`RELOAD_CONTINUITY_SRS` 의 두 조항이 이 문서로 대체된다.

- **FR-RLC-21** — "값은 서빙하는 `index.html` 에서 파생한다" → **FR-AVS-1·3.** 파생의
  근원이 문서에서 **자산 내용**으로 내려간다. 조항의 목적("손으로 적은 상수와 `?v=` 가
  갈리는 것을 막는다")은 유지되며, 오히려 더 강하게 달성된다.
- **FR-RLC-22** — 판을 모르는 두 경우 중 "형식이 다른 문서" 가 사라진다 → **FR-AVS-10.**
