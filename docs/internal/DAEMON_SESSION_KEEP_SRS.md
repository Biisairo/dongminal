# SRS: 데몬 교체 때 터미널 세션 유지 — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: 실제 운영 데몬에서의 첫 교체 확인(사용자 몫 — 처음 한 번은 `--refresh-daemon` 이 필요하다). 묶음 C·H·R 과 사용자 문서는 마쳤다
> **입력**: 2026-11-18 사용자 요청과 인터뷰. 결정은 §5 에 있다.
> - 요청 2 "dongminal start 시 reset daemon 에서 터미널 세션을 유지하기" — 이 문서의 대상이다.
> - 요청 1 "데몬 전체를 내렸다 올렸을 때의 run 복구" — 이 문서 다음에 따로 한다(D-DSK-1, §6).

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

데몬(`dongminald`)의 코드를 새 빌드로 바꿔도 터미널 세션이 끊기지 않게 한다.

지금은 데몬 코드를 바꾸려면 `dongminal start --restart-daemon` 을 써야 한다. 이 명령은 데몬을 죽이고 새로 띄운다. 그래서 모든 셸·에이전트·화면 내용을 잃는다(`DAEMON_STALENESS_SRS` §1.1). 사용자는 세션을 잃거나, 낡은 데몬 위에서 일하거나 둘 중 하나를 고른다. 이 문서는 그 선택을 없앤다.

### 1.2 범위 (Scope)

| 묶음 | 이름 | 요구 |
|---|---|---|
| **묶음 C** | 명령 (Command) — `start` 의 기본 동작과 플래그 | `FR-DSK-1..6` |
| **묶음 H** | 인계 (Handover) — 데몬이 같은 프로세스 번호로 새 바이너리를 exec 하고 상태를 넘긴다 | `FR-DSK-10..19` |
| **묶음 R** | 되살리기 (Restore) — 새 데몬이 인계 상태로 도구를 다시 쥔다 | `FR-DSK-20..26` |

대상 OS 는 macOS·Linux 다. Windows 는 이번 범위에서 뺀다(D-DSK-7, §2.5).

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 말 | 뜻 |
|---|---|
| **교체** | 데몬이 프로세스 번호를 그대로 둔 채 새 바이너리를 `exec` 해 자기를 갈아 끼우는 일. 세션이 남는다 |
| **새로 띄우기** | 데몬을 끝내고 새 프로세스로 띄우는 일. 지금의 `--restart-daemon` 이다. 세션을 잃는다 |
| **인계 상태** | 옛 데몬이 exec 직전에 쓰고 새 데몬이 기동 때 읽는 내용. 도구 목록·파일 디스크립터 번호·화면 내용·에이전트 기록을 담는다. 디스크에 이름이 없는 임시 파일의 fd 로 넘긴다(FR-DSK-13) |
| **되찾기** | 인계 상태 없이, 새 데몬이 쥔 PTY fd 와 자식 프로세스를 맞춰 도구를 다시 쥐는 일(FR-DSK-27) |
| **인계 판** | 인계 상태 형식의 정수 판. 두 바이너리의 판이 같아야 교체한다 |
| **사전 확인** | 옛 데몬이 exec 전에 새 바이너리를 따로 실행해 인계 판을 묻는 일 |
| **미지원 데몬** | 교체 요청을 모르는 옛 판 데몬. 지금 도는 데몬이 그렇다 |

## 2. 현재 상태 (조사로 확정한 사실, 2026-11-18)

### 2.1 재시작 흐름

`dongminal start` 의 순서는 다음과 같다(`start.go:100~114`).

1. 서버 포트를 쥔 프로세스를 끈다(`killPort`).
2. `--restart-daemon` 이면 데몬에 종료 신호를 보낸다(`stopDaemon`, `proc.go:157`). 없으면 데몬을 그대로 둔다.
3. 새 서버를 띄운다. 서버는 데몬 소켓에 붙고, 데몬이 없으면 띄운다(`toolclient` 의 `spawnDaemon`).

`dongminal stop --all` 도 `stopDaemon` 으로 데몬을 끈다(`stop.go:35`).

### 2.2 데몬이 끝나면 잃는 것

| 상태 | 자리 | 데몬을 새로 띄우면 |
|---|---|---|
| 셸·에이전트 프로세스 | 데몬의 자식 | 함께 끝난다 |
| 화면 내용(스크롤백) | `Tool.stream` (`outbuf.Stream`, 메모리) | 사라진다 |
| 탭 도구 | `tools.json` | **같은 uuid 의 빈 셸**로 다시 만든다(`persist.go` `LoadAll`) |
| 백그라운드·샌드박스 도구 | 기록하지 않는다(`persist.go` `SaveAll`) | 사라진다. 헤드리스 멤버 도구만 빈 셸로 돌아온다 |
| 에이전트 기록(활동·알람·사용량·서브에이전트·한도) | 데몬 메모리(FR-ARD-10) | 사라진다 |

### 2.3 서버는 데몬이 사라져도 다시 붙는다

서버의 데몬 클라이언트는 연결이 끊기면 물러서기(backoff)를 하며 다시 붙는다. 붙으면 도구·기록·간선·채팅을 다시 맞춘다(`toolclient/client.go:333`, `resyncAfterReconnect`·`resyncRecords`·`resyncEdge`·`resyncChat`). 그래서 교체 동안 연결이 잠시 끊겨도 서버 쪽에 새 코드가 필요하지 않다.

### 2.4 데몬의 소켓

| 소켓 | 연결 | 비고 |
|---|---|---|
| `paned.sock` | 하나씩만 받는다. 서버가 쥔다(IPC-24) | `start` 가 여기 붙으면 서버가 놓을 때까지 기다린다 |
| 보고 소켓 (`agentrec.SocketPath`) | 여러 연결을 동시에 받는다 | 요청 하나·답 하나의 JSON (`report.go`) |
| 채팅·간선 노드 소켓 | 데몬이 연다 | 새 데몬이 다시 연다 |

### 2.5 Windows 에서 교체가 막히는 이유

- Windows 에는 프로세스 번호를 유지하는 `exec` 가 없다.
- 파이프와 프로세스 핸들은 다른 프로세스로 넘길 수 있다. 그러나 의사 콘솔(HPCON)은 커널 핸들이 아니라 프로세스 메모리 안의 구조체 주소다. 그 안의 conhost 핸들은 비공개이고, 공식 방법으로 넘길 수 없다(`pty_windows.go`).
- 공식 API 만으로 세션을 남기려면 의사 콘솔을 쥐는 별도 보관 프로세스가 필요하다. 이것은 데몬 구조를 바꾸는 큰 일이다(§6).

## 3. 요구사항 (Requirements)

### 3.1 묶음 C — 명령

**FR-DSK-1** 플래그 없는 `dongminal start` 는 데몬이 돌고 있으면 **교체**를 요청한다. 데몬이 돌고 있지 않으면 지금처럼 새로 띄운다.

**FR-DSK-2** 교체 요청은 서버를 끄기 **전에** 한다. 순서는 다음과 같다.

1. 데몬에 교체를 요청하고 결과를 기다린다(FR-DSK-10).
2. 교체가 성공하면 서버 포트의 프로세스를 끄고 새 서버를 띄운다.
3. 교체가 실패하면 **아무것도 끄지 않는다.** 서버·데몬·세션이 그대로 남는다. 실패 이유와 다음 할 일(`--refresh-daemon`)을 알리고 종료 코드 1로 끝난다.

근거: 사용자 결정 D-DSK-4 — "명령을 안 친 것처럼 된다".

**FR-DSK-3** 데몬이 **미지원 데몬**이면 교체를 실패로 보지 않는다. 지금의 기본 동작처럼 데몬은 그대로 두고 서버만 새로 띄운다. 그리고 다음을 알린다. 종료 코드는 0 이다.

```
⚠ 도는 dongminald 는 세션 유지 교체를 모르는 옛 판입니다 — 서버만 다시 띄웠습니다.
  한 번은 `dongminal start --refresh-daemon` 이 필요합니다 (세션을 잃습니다).
```

미지원 판정은 교체 요청에 데몬이 "모르는 메서드"로 답한 경우다(`agentrec.KnownMethod` 의 거절, §3.2a).

**FR-DSK-4** `--server-only` 플래그를 더한다. 데몬에 아무 요청도 보내지 않고 서버만 다시 띄운다. 지금의 플래그 없는 `start` 와 같다. 낡은 데몬 경고(FR-DFP-9)는 그대로 낸다.

**FR-DSK-5** `--refresh-daemon` 플래그를 더한다. 지금의 `--restart-daemon` 과 같다 — 데몬을 끝내고 새로 띄우며 세션을 잃는다. 안내 문구도 같다("터미널 세션을 잃습니다").

**FR-DSK-6** `--restart-daemon` 을 없앤다. 이 플래그를 주면 모르는 플래그로 거절하지 않고, 아래 안내와 함께 종료 코드 2로 끝난다. 아무것도 끄지 않는다.

```
--restart-daemon 은 없어졌습니다.
  세션을 유지하며 데몬을 바꾸려면: dongminal start
  세션을 버리고 새로 띄우려면:    dongminal start --refresh-daemon
```

`--server-only` 와 `--refresh-daemon` 을 함께 주면 같은 방식으로 거절한다(종료 코드 2).

**FR-DSK-7** `DAEMON_STALENESS_SRS` FR-DFP-8 의 출력 문구를 새 명령에 맞춘다.

| 상태 | 새 출력 |
|---|---|
| 일치 | 데몬 코드 그대로 — `start` 는 세션을 유지한다 |
| 불일치 | 데몬 코드가 바뀌었다 — `start` 가 세션을 유지하며 교체한다 |
| 모른다 | 판을 모른다 — `start` 가 세션을 유지하며 교체한다 |

`--server-only` 로 뜬 뒤의 불일치 경고(FR-DFP-9)는 "`dongminal start` 로 교체하라"를 권한다.

### 3.2 묶음 H — 인계

**FR-DSK-10** 교체 요청은 **보고 소켓**의 새 메서드 `reload` 로 보낸다.

| | |
|---|---|
| 요청 | `{"method":"reload","body":{"exe":"<새 바이너리 절대경로>","handover":<인계 판>}}` |
| 성공 답 | `{"ok":true}` — 데몬이 exec 직전에 보낸다 |
| 실패 답 | `{"error":"<사유 코드>: <설명>"}` |

`exe` 는 `start` 를 실행한 바이너리(`os.Executable`)다. 데몬은 자기 경로가 아니라 이 경로를 exec 한다. 근거: 빌드가 바이너리를 같은 자리에 덮어쓰면 Linux 의 `/proc/self/exe` 는 지워진 파일을 가리킨다.

**FR-DSK-11** 데몬은 `exe` 를 받아들이기 전에 다음을 확인한다. 하나라도 어긋나면 실패로 답하고 아무것도 바꾸지 않는다.

| 확인 | 사유 코드 |
|---|---|
| 절대경로이고, 일반 파일이고, 실행할 수 있다 | `reload_exe` |
| 파일 소유자가 데몬의 실효 사용자와 같다 | `reload_exe` |
| 심볼릭 링크를 푼 경로가 **데몬 자신의 실행 파일 경로**(기동 때 정한 값)와 같다. 사전 확인과 exec 도 요청 경로가 아니라 이 경로로 한다 | `reload_exe` |
| 요청의 `handover` 가 데몬의 인계 판과 같다 | `reload_version` |
| 진행 중인 교체가 없다 | `reload_busy` |
| OS 가 교체를 지원한다 (Windows 가 아니다) | `reload_unsupported` |

**FR-DSK-12** 데몬은 **사전 확인**을 한다. `exe` 를 `<exe> d --handover-version` 으로 실행해 표준 출력의 정수를 읽는다. 시한은 5초다. 그 값이 데몬의 인계 판과 다르거나, 시한을 넘기거나, 0 이 아닌 종료 코드면 `reload_preflight` 로 답한다.

근거: exec 뒤에 새 데몬이 상태를 읽지 못하면 되돌릴 수 없다(§7 R-1). 판을 미리 맞춰 이 위험을 줄인다.

**FR-DSK-13** 사전 확인을 통과하면 데몬은 다음 순서로 인계 상태를 만든다.

1. 새 서버 연결과 보고 연결을 받지 않는다.
2. 모든 도구의 읽기 루프를 멈춘다. 멈춘 뒤 읽지 않은 출력은 커널의 PTY 버퍼에 남아, 새 데몬이 이어 읽는다.
3. 도구마다 아래를 담는다(FR-DSK-14).
4. 인계 상태를 **이름 없는 임시 파일**에 쓴다. Linux 는 `memfd_create` 로 만들고, macOS 는 `$DONGMINAL_HOME` 아래에 `0600` 으로 연 즉시 지운다(unlink). 디스크에 이름이 남지 않으며, 그 파일은 열린 fd 로만 존재한다.
5. 넘길 파일 디스크립터의 close-on-exec 표시를 지운다.
6. 보고 연결에 성공을 답한다.
7. `syscall.Exec(exe, [exe, "d", "--handover-fd", <fd 번호>], env)` 를 부른다.

2~5 중 하나가 실패하면 1·2 를 되돌리고(읽기 루프와 연결 받기를 다시 시작한다) 실패로 답한다. 사유 코드는 `reload_state` 다.

7 이 실패하면 데몬은 같은 방식으로 되돌리고 인계 상태의 fd 를 닫는다. 보고 연결에는 이미 성공을 답했으므로, `start` 는 FR-DSK-17 로 실패를 알아챈다.

**FR-DSK-14** 인계 상태는 다음을 담는다.

| 항목 | 내용 |
|---|---|
| 판 | 인계 판 |
| 도구 | 살아 있는 **모든** 도구. 탭·백그라운드·헤드리스·샌드박스를 가리지 않는다(D-DSK-6) |
| 도구마다 | id, 이름, PTY 마스터 fd 번호, 자식 pid, 크기(cols·rows), 백그라운드·샌드박스 표시, 화면 내용(스크롤백 바이트)과 누적 바이트 좌표(FR-TRS-15), 터미널 모드(`termmodes`), 에이전트 기록(FR-ARD-10 의 도구별 기록 전부) |
| 데몬 전체 | 에이전트별 계정 한도(FR-ARD-10), 소유 집합 등 `ToolManager` 가 메모리에만 두는 값 |
| 리스너 | `paned.sock`·보고 소켓의 리스너 fd 번호 |

화면 내용은 지금 `outbuf.Stream` 이 들고 있는 만큼만 담는다. 크기 상한을 따로 두지 않는다 — 이미 메모리에 있는 양이다.

**FR-DSK-15** 채팅·간선 노드의 네트워크 연결은 넘기지 않는다. 새 데몬이 기동 경로 그대로 다시 열고, 디스크의 상태를 읽는다. 상대 노드는 끊김을 보고 다시 붙는다.

**FR-DSK-16** 서버 연결(`paned.sock` 의 현재 연결)은 넘기지 않는다. exec 로 끊기고, 서버는 §2.3 의 재접속으로 새 데몬에 붙어 상태를 다시 맞춘다.

**FR-DSK-17** `start` 는 성공 답을 받은 뒤 새 데몬이 떴는지 확인한다. 아래가 모두 참이 될 때까지 기다리며, 시한은 10초다.

- `paned.pid` 의 pid 가 요청 전과 같다.
- `paned.build` 가 `start` 바이너리의 데몬 지문과 같다(지문이 빈 값이면 이 조건은 건너뛴다, FR-DFP-3).
- 보고 소켓이 새 메서드 `hello` 에 답한다.

시한을 넘기면 실패로 본다. 이때는 데몬이 이미 바뀌었을 수 있으므로 FR-DSK-2 의 "아무것도 끄지 않는다"를 지킬 수 없다. 서버는 끄지 않고, 상황(데몬 pid·지문)을 알린 뒤 종료 코드 1로 끝난다.

**FR-DSK-18** 인계 판은 상수 하나다. 인계 상태의 모양을 바꾸는 변경은 그 판을 올린다. 판이 다르면 교체하지 않는다(FR-DSK-11·12) — 판 사이의 변환은 만들지 않는다.

**FR-DSK-19** `reload` 는 보고 소켓의 다른 메서드와 같은 접근 통제를 받는다(소켓 디렉터리 `0700`). 요청 본문은 크기 상한을 둔다(64 KiB).

### 3.3 묶음 R — 되살리기

**FR-DSK-20** `dongminal d --handover-fd <fd>` 로 뜬 데몬은 일반 기동의 `LoadAll`(tools.json 에서 빈 셸 만들기) 대신 인계 상태로 도구를 되살린다.

**FR-DSK-21** 도구마다 PTY 마스터 fd 와 자식 pid 로 `platform.Terminal` 을 다시 만든다. 이 터미널은 지금의 터미널과 같은 계약을 지킨다 — 읽기·쓰기·크기 바꾸기·전경 조회·종료·`Wait`.

`Wait` 는 `exec.Cmd` 없이 pid 로 자식을 거둔다(`wait4`). exec 는 프로세스 번호를 바꾸지 않으므로 셸은 여전히 데몬의 자식이다.

**FR-DSK-22** 화면 내용과 누적 바이트 좌표를 `outbuf.Stream` 에 되넣는다. 되살린 뒤의 출력 좌표는 옛 좌표에 이어진다. 그래서 브라우저가 다시 붙으면 FR-TRS-15 의 겹침 자르기가 그대로 맞는다.

**FR-DSK-23** 에이전트 기록과 데몬 전체 기록을 되넣는다. 서버가 다시 붙을 때의 스냅샷(FR-ARD-13)이 이 값을 싣는다.

**FR-DSK-24** 리스너 fd 로 `paned.sock`·보고 소켓을 다시 연다. 소켓 파일을 지우거나 다시 만들지 않는다.

**FR-DSK-25** 인계 상태를 다 읽으면 그 fd 를 닫는다. 이름이 없으므로 닫는 순간 OS 가 내용을 치운다. 그다음 `paned.pid`·`paned.build` 를 쓴다(FR-DFP-4). pid 는 같고 지문은 새 바이너리의 것이다.

**FR-DSK-26** 되살리기는 세 겹이다(D-DSK-13). 앞 겹에서 짝을 찾지 못한 것만 다음 겹으로 넘어간다.

| 겹 | 근거 | 돌아오는 것 | 잃는 것 |
|---|---|---|---|
| ① 인계 상태 | FR-DSK-20~25 | 전부 | 없다 |
| ② 되찾기 | FR-DSK-27 | 셸·에이전트·도구 id·이름·cwd | 화면 내용, 에이전트 기록 |
| ③ 입양 | FR-DSK-28 | 셸·에이전트 | 도구 id(새로 받는다)·화면·기록 |

인계 상태 전체를 읽지 못하면 모든 도구가 ② 로 간다. 인계 상태는 읽었으나 한 도구의 fd 나 pid 가 맞지 않으면 그 도구만 ② 로 간다. 어느 겹으로 돌아왔는지 도구마다 로그에 남긴다.

`tools.json` 에 있으나 ①~③ 어디에서도 셸을 찾지 못한 도구는 일반 기동처럼 빈 셸로 만든다(`LoadAll` 의 규칙). 인계로 넘어온 PTY fd 는 **자식 셸과 짝이 없는 것만** 닫는다. 짝이 있는 fd 를 닫으면 셸이 SIGHUP 으로 끝나기 때문이다.

**FR-DSK-27** 되찾기는 다음 순서로 PTY fd 와 셸을 짝짓는다.

1. 자기 프로세스의 열린 fd 를 훑는다(Linux `/proc/self/fd`, macOS `/dev/fd`). 그중 PTY 마스터를 골라 짝 단말 이름을 얻는다(`ptsname`).
2. 부모 pid 가 자기인 프로세스를 찾고, 각각의 제어 단말을 읽는다. 1 의 단말 이름과 같으면 짝이다. 한 단말에 자식이 여럿이면 세션 리더(셸)를 고른다.
3. 짝지은 셸의 pid 를 `tools.json` 의 `pid` 에서 찾는다. 그 항목의 id·이름·cwd 를 쓴다. `tools.json` 은 교체 직전(멈춘 뒤)에 한 번 동기로 쓴다. exec 는 pid 를 바꾸지 않으므로 pid 가 정확한 열쇠다.
5. 같은 id 의 도구로 등록한다. 탭이 그 id 를 가리키므로 화면이 다시 붙는다.

백그라운드·헤드리스·샌드박스 표시는 `tools.json` 에 없으므로 ② 에서는 알 수 없다. ② 로 돌아온 도구 중 어느 탭도 가리키지 않는 것은 백그라운드 도구로 둔다.

**구현 중 바뀐 것 (2026-11-18, 사용자 결정 D-DSK-14)**: 처음에는 3 을 "셸 환경의 `DONGMINAL_TOOL_ID` 를 읽는다"로 정했다. macOS 는 같은 사용자의 자식이어도 다른 프로세스의 환경 변수를 내주지 않는다(`kern.procargs2` 가 환경을 빼고, `ps -E`·`ps eww` 도 보여 주지 않는다). 그래서 모든 OS 에서 `tools.json` 의 pid 를 쓴다. 대가: `tools.json` 에 기재하지 않는 백그라운드·샌드박스 도구는 ② 가 아니라 ③ 으로 간다(헤드리스 Run 도구는 기재되므로 ② 다).

**FR-DSK-28** 3 에서 `tools.json` 에 pid 가 없거나 그 id 가 이미 쓰인 셸은 **새 id 의 백그라운드 도구로 입양**한다. 죽이거나 숨기지 않는다. 사용자는 백그라운드 목록에서 그 도구를 찾아 탭에 붙이거나 닫을 수 있다. 입양한 도구는 로그와 데몬 기동 알림에 개수를 남긴다.

### 3.5 구현 메모 (2026-11-18)

구현하며 정한 것이다. 요구를 바꾸지 않는다.

| 자리 | 정한 것 | 이유 |
|---|---|---|
| 읽기 멈춤 | POSIX 터미널의 읽기를 `poll(2)` 와 깨우기 파이프로 바꿨다(`platform.readGate`). 멈춘 동안 `Read` 는 바이트를 가져가지 않고 `ErrFrozen` 을 돌려준다. 도구의 읽기 루프는 그 자리에서 기다린다 | macOS 의 ptmx 는 Go 폴러에 오르지 않아 읽기 시한(`SetReadDeadline`)을 받지 않는다. 막힌 `read` 는 다음 출력을 곧바로 가져가므로, 교체 직전의 출력이 Go 메모리에서 exec 로 사라진다(NFR-DSK-2) |
| 0 바이트 읽기 | `poll` 뒤 `read` 가 오류 없이 0 을 주면 `io.EOF` 로 읽는다 | macOS 는 슬레이브가 닫히면 그렇게 답한다. 그대로 두면 읽기 루프가 끝나지 않는다 |
| 생성 봉인 | `FreezeAll` 은 도구 생성을 막고(`ErrSealed`) 띄우는 중인 도구가 등록되기를 기다린다. 되돌리면 푼다 | 담은 뒤 생긴 도구의 fd 는 close-on-exec 라 exec 에서 닫히고 셸이 끝난다(FR-DSK-13 1) |
| close-on-exec | 넘길 fd 의 표시는 성공 답을 쓴 **뒤** `commit` 에서 지운다. exec 가 실패하면 다시 세운다 | 지운 채 남으면 뒤에 띄우는 모든 자식이 그 fd 를 물려받는다 |
| 물려받은 소켓 | 인계 상태나 리스너를 못 쓰면, 우리 소켓 경로에 묶인 fd 를 닫은 뒤 `Listen` 한다 | 닫지 않으면 `Listen` 의 안전 검사가 그 소켓에 붙어 "다른 데몬이 있다" 로 보고 데몬이 끝난다 — 그때 모든 셸이 함께 끝난다 |
| 셸 거두기 | 넘겨받은 셸은 `wait4(pid)` 로 거둔다. 종료 코드는 `ExitCode()` 를 가진 오류로 나간다 | `exec.Cmd` 가 없다 |

### 3.4 비기능 (Non-functional)

**NFR-DSK-1** 도구 20개, 도구마다 화면 내용 1 MiB 일 때 교체 요청부터 새 데몬이 보고 소켓에 답하기까지 2초를 넘지 않는다.

**NFR-DSK-2** 교체 동안 셸이 낸 출력을 잃지 않는다. 읽기 루프를 멈춘 뒤의 출력은 커널 버퍼에 남는다(FR-DSK-13).

**NFR-DSK-3** 인계 상태에는 화면 내용이 실린다. 화면에는 비밀이 있을 수 있으므로 디스크에 이름을 남기지 않는다(FR-DSK-13). 다른 프로세스가 경로로 열 수 없고, 데몬이 fd 를 닫거나 죽으면 OS 가 치운다.

## 5. 설계 결정 (Design Decisions)

**D-DSK-1 세션 유지를 먼저, Run 복구는 뒤에 한다.** 교체가 되면 흔한 경우(코드를 고친 뒤 재시작)에 에이전트가 끊기지 않는다. 그러면 Run 복구는 데몬이 실제로 죽은 경우(충돌·재부팅·`stop --all`·`--refresh-daemon`·Windows)만 맡으면 된다. (사용자 결정, 2026-11-18)

**D-DSK-2 플래그 없는 `start` 가 교체한다.** 데몬을 두고 서버만 다시 띄우는 일은 `--server-only` 로 한다. `--restart-daemon` 은 없앤다. (사용자 결정)

**D-DSK-3 세션을 버리는 재시작은 `start --refresh-daemon` 으로 남긴다.** (사용자 결정)

**D-DSK-4 교체에 실패하면 명령을 안 친 것처럼 된다.** 그래서 교체 요청을 서버를 끄기 전에 한다(FR-DSK-2). (사용자 결정)

**D-DSK-5 화면 내용도 넘긴다.** 넘기지 않으면 셸은 살아 있어도 화면이 빈 채로 시작하고, TUI 는 다시 그릴 때까지 비어 있다. (사용자 결정)

**D-DSK-6 살아 있는 도구 전부와 에이전트 기록을 넘긴다.** 채팅·간선의 네트워크 연결은 새로 맺는다. (사용자 결정)

**D-DSK-7 Windows 는 이번 범위에서 뺀다.** Windows 의 `start` 는 `reload_unsupported` 를 받아 FR-DSK-2 의 실패 경로를 탄다 — 아무것도 끄지 않는다. 의사 콘솔 보관 프로세스는 후속 과제다(§6). (사용자 결정)

**D-DSK-8 미지원 데몬이면 서버만 다시 띄우고 알린다.** 지금 도는 데몬이 그렇고, 새 바이너리의 첫 `start` 가 반드시 이 경우를 만난다. 실패로 다루면 첫 `start` 가 늘 멈춘다. (사용자 결정)

**D-DSK-9 교체는 exec 로 한다.** 다른 방법은 새 프로세스를 띄워 fd 를 유닉스 소켓으로 넘기는 것(`SCM_RIGHTS`)이다. 그러면 셸이 옛 데몬의 자식으로 남아, 옛 데몬이 끝나면 고아가 된다. 새 데몬은 그 셸을 거둘(`wait4`) 수 없고 종료 코드도 알 수 없다. exec 는 프로세스 번호가 그대로라 셸이 계속 데몬의 자식이다.

**D-DSK-10 교체 요청은 보고 소켓으로 보낸다.** `paned.sock` 은 연결을 하나만 받고 서버가 쥔다(IPC-24). 신호(`SIGUSR2`)는 결과를 답할 수 없어, D-DSK-4 의 "실패면 아무것도 끄지 않는다"를 지킬 수 없다. 보고 소켓은 동시 연결과 요청·답을 이미 갖고 있다.

**D-DSK-11 인계 판은 손으로 올리는 상수다.** 데몬 지문(DAEMON_STALENESS D-1)은 코드가 바뀌면 늘 달라져 교체를 늘 막는다. 인계 판은 "인계 상태의 모양"만 센다. 올리기를 잊으면 TC-DSK-7 의 골든 시험이 잡는다.

**D-DSK-12 인계 상태는 이름 없는 임시 파일의 fd 로 넘긴다.** exec 를 넘는 것은 인자·환경 변수·열린 fd 뿐이고, 화면 내용은 인자·환경 변수의 크기 한도를 넘는다. 이름 있는 파일은 화면의 비밀을 디스크에 남기고 지우는 규칙이 따로 필요하다. 파이프는 버퍼(약 64 KiB)를 넘으면 exec 전에 쓰기가 막힌다. (사용자 결정, 2026-11-18)

**D-DSK-13 되살리기는 세 겹이다.** exec 뒤에도 PTY fd 와 자식 셸은 새 데몬이 쥐고 있다. 인계 상태를 잃어도 그 둘과 셸 환경의 `DONGMINAL_TOOL_ID` 로 도구를 되찾을 수 있다. id 를 모르는 셸도 죽이지 않고 입양한다 — 사용자가 하던 일을 데몬이 마음대로 끝내지 않는다. (사용자 결정, 2026-11-18)

**D-DSK-14 되찾기는 셸 pid 로 도구를 알아본다.** `tools.json` 에 셸 pid 를 적고 교체 직전에 한 번 쓴다. 셸 환경의 `DONGMINAL_TOOL_ID` 는 macOS 에서 읽을 수 없다. (사용자 결정, 2026-11-18)

## 6. 비목표 (Non-goals)

- **Run 복구.** 데몬이 실제로 죽은 뒤 되살아난 빈 셸에서 에이전트를 재개(`sessionId`)하는 일. 이 문서 다음에 따로 한다(D-DSK-1).
- **Windows 의 세션 유지.** 의사 콘솔을 쥐는 작은 보관 프로세스를 두고 데몬이 거기 붙는 구조(tmux·dtach 와 같은 모양)가 공식 API 만으로 가능한 방법이다. Windows 실행 검증 환경을 갖춘 뒤 따로 설계한다.
- **인계 판 사이의 변환.** 판이 다르면 교체하지 않는다(FR-DSK-18).
- **자동 교체.** 빌드나 판 불일치를 보고 데몬이 스스로 교체하지 않는다. 교체는 사람이 `start` 로 한다.
- **직접 모드(데몬 없음).** 서버가 곧 PTY 를 쥐는 모드는 바꾸지 않는다.

## 7. 위험 (Risks)

| | 위험 | 등급 | 대응 |
|---|---|---|---|
| R-1 | exec 가 성공한 뒤 새 데몬이 인계 상태를 읽지 못하면 되돌릴 수 없다 | MEDIUM | 사전 확인(FR-DSK-12)으로 판을 맞춘다. 읽지 못해도 되찾기·입양(FR-DSK-27·28)으로 셸은 남고 화면·기록만 잃는다. TC-DSK-9·14 가 잰다 |
| R-1a | 새 데몬 프로세스가 기동 중에 죽으면 PTY 마스터가 닫혀 셸이 SIGHUP 으로 끝난다. 되찾을 프로세스가 남지 않는다 | HIGH | 사전 확인으로 줄인다. 남은 경우는 Run 복구(§6, 다음 일)가 맡는다 |
| R-2 | 읽기 루프를 멈추는 사이 셸 출력이 커널 PTY 버퍼(macOS 약 1 KiB~수 KiB)를 채우면 셸 쓰기가 막힌다 | MEDIUM | 막힐 뿐 잃지 않는다. 교체 시간이 짧으므로(NFR-DSK-1) 새 데몬이 읽으면 풀린다 |
| R-3 | Go 런타임이 연 fd 는 기본으로 close-on-exec 다. 표시를 지우지 못한 fd 는 exec 에서 닫혀 그 셸이 끊긴다 | MEDIUM | 넘길 fd 를 명시 목록으로 다루고 TC-DSK-9 로 잰다 |
| R-4 | macOS 에서 임시 파일을 연 뒤 지우기 전에 데몬이 죽으면 이름 있는 파일이 남는다 | LOW | 열자마자 지운다(만들기와 지우기 사이에 다른 일을 하지 않는다). 권한 `0600`. 다음 기동이 남은 이름을 지운다 |
| R-5 | `reload` 의 `exe` 로 임의 바이너리를 데몬 권한으로 실행시킬 수 있다. 사용자가 홈을 마운트한 샌드박스 창은 보고 소켓에 닿고, 같은 uid 로 마운트 폴더에 쓴 파일은 호스트에서 사용자 소유로 보인다 — 샌드박스 탈출이다(2026-11-18 보안 검토) | HIGH→LOW | 교체 대상을 데몬 자신의 실행 파일 경로로 고정한다(FR-DSK-11). 그 자리를 덮어쓸 수 있는 쪽은 다음 재시작 때도 어차피 실행되므로 교체가 권한을 넓히지 않는다. 다른 경로의 바이너리로 바꾸려면 `--refresh-daemon` 을 쓴다 |
