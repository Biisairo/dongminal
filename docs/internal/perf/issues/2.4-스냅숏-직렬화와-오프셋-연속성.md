# 2.4 스냅숏 직렬화와 오프셋 연속성 (FR-TRM-4, A-2)

## 목표

화면 + 최근 기록 N줄(기본 5,000)을 최소 재그리기 ANSI 로 직렬화한다. 커서·SGR·OSC 8·대체 화면(주 화면 포함)·스크롤 영역·원점·자동 줄바꿈·삽입·문자 집합·앱 커서 키·키패드·마우스·괄호 붙여넣기·포커스 보고·창 제목을 싣는다(`TermModes::restore_bytes` 의 일을 옮긴다). 머리: 오프셋 `end`·크기·대체 화면·첫 기록 줄 번호·cwd. `cmu` 잠금 안에서 만들어 `end` 와 한 순간을 맞춘다. IPC 메서드(가칭 `screen`)와 기능 이름(가칭 `FEATURE_SCREEN_STATE`)을 더한다.

설계: `perf/M2_DESIGN.md` §2.4. 결정: D-18. 분할점이 시퀀스·UTF-8 한가운데인 경우(HIGH 위험)를 먼저 시험으로 드러내고 대응을 정한다.

## 완료 조건

- RED: 스냅숏을 새 xterm(headless)에 넣은 화면 = 원래 바이트를 넣은 화면(대체 화면 중 포함, OSC 8 포함).
- RED: 임의 분할점 k 에서 `스냅숏(k) + 바이트[k..]` 의 최종 화면·기록 = 바이트 전체. 분할점이 이스케이프·UTF-8 한가운데여도.
- RED: 모드 왕복 — 각 모드를 켠 뒤 스냅숏 → 새 xterm 의 모드가 같다.
- 스냅숏 크기·생성 시간을 잰다(5천 줄, NFR-PRF-14 예산 판단용).
- 바꾼 부분의 시험(단위·관련 e2e 한두 개)·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.
