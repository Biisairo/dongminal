# 1.16 1.14·1.15 병합 뒤 시험 회복

## 목표

통합 브랜치(perf-m1, 1.15 병합 뒤)에서 깨진 것을 고친다. main 병합의 전제다.

1. 프론트 단위 9건 실패(`git-panel-parts.test.mjs` TC-FEP-1·2·3·TC-DLG-1·2, `git-panel-obs.test.mjs` adopt·collect 3건). 원인: 1.15 가 `git-poll.js` 의 클래스 필드 `retryMs=GIT_STATUS_RETRY_MS` 를 더했는데, 이 상수는 `core/constants-git-detect.js` 에 있고 그 파일은 실릴 때 i18n `t()` 를 부른다. 시험 하네스는 그 파일을 싣지 않는다. 하네스 `GITPANEL` 에 더하면 i18n 이 없어 `t is not defined` 이고, `GITPANEL` 목록을 검사하는 TC-FEP-2 도 깨진다(조정자가 시도해 확인, 되돌림). 고칠 방향은 담당이 정한다(예: 상수를 i18n 을 부르지 않는 상수 파일로 옮기기, 또는 시험이 i18n·상수를 함께 싣기). 1.15 에이전트는 자기 worktree 에서 1611 통과를 보고했다 — 왜 거기서는 통과했는지도 확인한다.
2. e2e `editor-fs-watch` V-ELR-34 실패: "`/api/fs/watch` 가 404 면 주기 폴링으로 바깥 변경을 반영한다" 는 대체 경로를 1.14 가 주기 틱을 지우며 없앴다. 서버 감시가 없을 때의 반영 경로를 어떻게 할지 정한다 — 사건 없는 대체 주기를 남기면 D-9 와 부딪히므로, 판단이 갈리면 조정자에게 알린다.
