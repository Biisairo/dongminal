# 2.8.2 검색·질의 답·내려받기·잔여 e2e (FR-TRM-8)

## 목표

- 검색: 브라우저 5천 줄 + 끝에 닿으면 "이전 기록에서 찾기"로 데몬 저장소 검색, 고르면 기록 보기로 연다(D-21). 기록 보기는 2.7 의 것을 쓴다 — 2.7 이 먼저 끝나지 않았으면 서버 검색까지만 하고 연결은 2.7 뒤에 한다.
- 질의 답: 서버가 좌석이 비고 차는 순간을 데몬에 알리고, 비어 있는 동안 데몬이 DA·DSR·커서 위치 질의에 답한다. 색 질의는 답하지 않는다(D-23).
- 내려받기: OSC 777 Download 는 깬 터미널에서만(D-24). 동작 변경 — 이전: 숨은 터미널의 xterm 도 내려받기를 일으켰다. 새: 잠든 동안 온 요청은 버린다. 이유: 잠든 터미널은 출력을 받지 않는다.
- 칸 이동 스크롤 복원(`renderer-scroll.js`)·진단(`diag.js`)이 잠든 터미널의 빈 버퍼에서 깨지지 않게 한다.

설계: `perf/M2_DESIGN.md` §2.8.

## 완료 조건

- RED: 잠든 터미널의 앱이 DA·커서 위치 질의에 답을 받는다. 깬 브라우저가 있으면 데몬은 답하지 않는다. 좌석이 바뀌는 순간 둘이 함께 답하지 않는다.
- RED: 서버 기록 검색이 5천 줄 위의 일치를 찾는다.
- RED: 잠든 터미널의 Download 는 내려받기를 일으키지 않는다.
- 바꾼 부분의 시험(단위·관련 e2e 한두 개)·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.

## 진행 기록


### 2026-11-25 agent-pf-2-8-2 — review (브랜치 pf/2.8.2, **커밋 거절됨 — 변경 37개 파일은 스테이징 상태**)

자동 권한 판정이 커밋을 거절했다. 메시지 안은 조정자 보고에 붙였다. 기준은 perf-m1 1ff020dc.

**바꾼 것**

- 질의 답(D-23)
  - termstate `Screen::take_replies` — alacritty `PtyWrite` 중 DA(`CSI ?…c`·`CSI >…c`)·DSR(`CSI 0 n`)·커서 위치(`CSI r;c R`)만 모은다. 색(OSC 10/11)·모드(`$y`)·키보드(`?u`)·창 크기·클립보드는 버린다. 데몬 교체로 되세울 때 모인 답을 버린다.
  - toolhub `Tool`: `cmu` 에 `seat_holds`·`replied_end`. `feed` 가 같은 잠금 안에서 "쥔 수 0 이면 답한다"를 정하고 잠금 밖에서 PTY 에 쓴다. `hold_seat(bool) -> i64`·`replied_end()`.
  - IPC `seat`(`SeatParams{held,id}` → `SeatResult{repliedEnd}`). 데몬 `Conn` 이 연결마다 도구별로 세고 `stop()` 에서 모두 놓는다.
  - 서버 `channel/term.rs` `Session::run`: **구독 전에** `seat_tool(true)`, 끝나면(unsub 뒤) `seat_tool(false)`. `since < repliedEnd` 면 이어 붙이지 않고 스냅숏(데몬이 이미 답한 질의를 브라우저가 델타에서 다시 답하지 않게). `ToolHub::seat_tool` 추가(구현: ReqHub, adapters `Hub`, 시험 가짜 둘), `ToolClient::seat_tool`.
  - 좌석 판정 위치: 서버의 기존 `ReplySeats`(브라우저끼리의 주인 정하기)는 그대로 두고, 데몬에는 "깬 연결 수"만 센다. 서버가 전이(0↔1)를 계산해 보내는 안은 서로 다른 sid 의 쥠·놓음 IPC 순서가 뒤집히면 데몬이 비었다고 오판할 수 있어, 데몬이 세는(교환 법칙이 서는) 쪽을 골랐다.
- 이전 기록에서 찾기(D-21)
  - toolhub `search.rs`: `Query::new(pattern, regex, case, word)`(정규식이 아니면 글자 그대로, `regex` crate), `Tool::search(q, before, limit)` — 줄 저장소에서 번호 `before` 앞을 새 줄부터, 블록(256줄) 하나씩 잠가 찾는다. 일치 `{line, col(코드 포인트), text(512자까지)}`. `ToolManager::search_tool`.
  - IPC `search`(`SearchParams{before,case,id,limit,pattern,regex,word}` → `SearchResult{hits}`, 상한 `SEARCH_LIMIT_MAX`=1,000). 데몬은 느린 요청 줄(`go_slow`)에서 돈다. 깨진 정규식은 `CODE_INVALID_PARAMS`.
  - 서버 `GET /api/tools/search?id=&q=&before=&regex=1&case=1&word=1` → `{hits}`(한 번 200개). `before` 없음 400, 없는 도구 404, 데몬이 찾지 못함(정규식 등) 422.
  - 브라우저: `TerminalTool._firstLine`(스냅숏 SEQ 꼬리의 첫 기록 줄 번호, 모르면 -1). 찾기 줄에 `#search-older` 버튼과 `#search-older-list` 목록. `ToolSearch.searchOlder()` 가 찾기 줄의 선택지를 그대로 싣고, 고르면 `p.openHistoryAt(line)` 을 부른다 — **2.7 의 기록 보기 진입점 이름이다. 2.7 에 아직 없어서 지금은 고르면 아무 일도 없다**(아래 남은 일).
- 내려받기(D-24): 코드 변경 없음. 2.5 가 이미 이룬다 — 잠들면 `term.close`(그 sid 의 늦은 프레임은 `live=false` 로 걸러짐), `sleep()` 이 좌표를 버린 뒤 `_resetDecoderIfNoResume` 이 보류 출력(`_outputBuf`)까지 비워 flush 를 기다리던 Download 도 일어나지 않는다. 시험으로 굳혔다.
- 칸 이동 스크롤 복원(`renderer-scroll.js`)·진단(`diag.js`): 읽어 보니 버퍼 읽기가 모두 `try` 안이고 빈 버퍼면 "맨 아래"로 잡혀(보이지 않는 칸은 되돌리지 않음) 깨지지 않는다. 고치지 않았다.

**지운 것** — 없음. 2.2 의 `screen_does_not_write_replies_to_pty` 를 `screen_replies_only_status_queries_and_only_while_seat_is_vacant` 로 바꿨다(같은 질의 묶음으로 "쥔 동안 아무것도 쓰지 않는다"를 그대로 재고, "비면 DA·DSR·CPR 만"을 더했다).
