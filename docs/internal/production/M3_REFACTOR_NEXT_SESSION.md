## 1. 건드리지 말 것 — "중복처럼 보이지만 의도된 것"

일반적인 체크리스트를 그대로 돌리면 아래가 전부 "중복·복잡" 으로 잡힌다.
**지우면 버그가 돌아온다.** 손대려면 괄호 안의 결정 문서를 먼저 개정해야 한다.

  · 오류 본문 방언 4종
      git {error,message} · fs {code,message} · runs {error,detail} · 단문 {error}
      (architecture.md:141-176 — 공개 계약. "통일하지 않는다(파괴적 변경)")
  · core/api.js 와 git/api.js 의 `ok` 판정이 다른 것
      (CLIENT_API_SRS FR-CAPI-15 — git 은 언제나 JSON, 코어에는 204 가 있다)
  · TimerHub 의 겹침 정책 두 벌 (queue / drop)
      ("하나로 통일하면 둘 중 하나가 깨진다" — timer-hub.js 주석)
  · /api/fs/* 와 /api/file/* 의 경로 가드 두 벌
      (루트를 고르는 방법이 다르다. FILE_API_BOUNDARY_SRS §5 비목표 1)
  · git 실행 초크포인트 · 업로드 MaxBytesReader · ACL 설계 ·
    파괴적 확인창 설계 · 패닉 그물(SSE/WS 구분)
      (MILESTONE_KICKOFF.md M2 의 "건드리지 말 것" — 전부 양호 판정)
  · index.html 의 head 선주입 스크립트 둘
      (BOOT_SCREEN_SRS NFR-1 — 네트워크에 닿으면 안 된다. CSP 해시로 허용돼 있다)
  · 상수 파일이 크다는 이유로 쪼개는 것

## 2. 착수 근거는 취향이 아니라 실측이다

"함수가 300줄이다" 는 근거가 아니다. 아래 중 하나를 **숫자로** 보여라.

  (a) 같은 것을 고치는 자리가 N 곳이고, 그중 일부만 고쳐진 이력이 있다
      → git log 로 그 이력을 보여라. 이것이 가장 강한 근거다.
         (예: DEEPENING_REFACTOR_SRS 묶음 C 는 "호출자 22곳 중 4곳이 echo 검증을
          안 하고 있었다" 를 근거로 삼았다 — 정리가 아니라 버그 부류의 제거였다)
  (b) 이 함수가 **서로 다른 이유로** 바뀐다 — 그 이유를 둘 이상 대라
  (c) 새 종단·새 화면을 더할 때 손대야 하는 파일이 N 개다
  (d) 감사 문서가 이미 실측해 둔 항목이다 (§3)

근거가 (a)~(d) 중 어디에도 없으면 **하지 마라.** CLAUDE.md 가 투기적 추상화를
금지한다. "충분한 추상화" 에는 멈추는 조건이 없으므로, 멈추는 조건을 위 넷으로
대신한다.
