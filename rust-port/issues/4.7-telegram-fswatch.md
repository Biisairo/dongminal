# 4.7 telegram·fswatch

## 목표

telegram 브리지와 파일 감시(notify)를 옮긴다. 시험에서 실제 telegram API 에 나가지 않는다.

## 대상 Go 코드

- `internal/webserver/domain/telegram`
- `internal/webserver/fswatch`

프로덕션 코드 약 2065줄.

## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  **한 것 — telegram (dm-webserver-domain-telegram) 거의 완료**
  - 공개 API: `Client::new(base, token)` + `get_me`·`get_updates`·`call<T>`·`call_discard`(async, reqwest+rustls ring, 오류 `Error::{Api(ApiError{code,description,retry_after}), Other}` 문구 Go 와 같음, URL·token 은 오류에 싣지 않음), `Store::open/config/view/set_token/set_enabled/set_silence/set_user`(telegram.json 은 Go MarshalIndent 와 바이트 같음, 권한 600), `StoreError::{InvalidSilence, SaveFailed}`, `Pairing::new(now)/issue/redeem/pending/cancel`(시각은 `time::OffsetDateTime`), `last_reply(path)`, `Bridge::new(st, host, base, now) -> Arc<Bridge>` + `on_activity/on_attention/on_attention_clear/on_notice/on_tool_gone/pairing` + `run(cancel)`(async), `trait Host { last_browser_input -> Option<OffsetDateTime>, location, attend }`, `Event`·`Location`.
  - Bot API 요청 본문은 dm-gocompat json(키 정렬·HTML 이스케이프)으로 만든다. 와이어 바이트 시험 있음.
  - 시험 69개 통과(Go bridge·client·config·pair·render·transcript 테스트 이식, 가짜 HTTP 서버는 127.0.0.1 의 60147 이상 포트). fmt·clippy(darwin) 통과.
  - Go 와 다르게 한 내부 결정: 알림 내용은 클로저 대신 `Body` 열거형으로 표현. classify 잠금 시험(TC-ATF-43)은 Go 의 전역 `readReply` 바꿔 끼우기에 기대므로 옮기지 않았다(구조상 잠금 밖에서 읽음). User-Agent 는 `Go-http-client/1.1` 로 맞췄고, Go 가 자동으로 보내는 `Accept-Encoding: gzip` 과 h2 는 맞추지 않았다(Telegram 쪽 동작 차이 없음).

  **다음에 할 일**
  1. fswatch(dm-webserver-fswatch) 전부 — 미착수. 설계 메모: macOS 는 notify 의 kqueue 백엔드(`features = ["macos_kqueue"]`)를 쓰되, notify 의 비재귀 kqueue 는 디렉터리 안 파일을 감시하지 않으므로 fsnotify 처럼 파일마다 감시를 더하고 디렉터리 Write 때 다시 읽어 Create 를 만드는 층이 필요하다. Linux 는 inotify 비재귀로 Go 와 같다. NFC 정규화(macOS)에는 unicode-normalization crate 가 필요해 DEPENDENCIES.md 추가가 필요하다. 경로는 dm_gocompat::filepath(dir·base·join)를 쓴다. 타이머는 Clock 주입(가짜 시계 시험).
  2. telegram 의 windows·linux `cargo check` — 이 기계에 ring 의 C 교차 컴파일러가 없어 빌드 스크립트에서 실패한다(코드 문제 아님). 교차 툴체인이 있는 곳에서 다시 확인.

  **남은 위험**
  - dm-gocompat json 디코딩: `"silenceMin": null` 이 Go 는 기본값(5)을 남기지만 gocompat 는 0 으로 만든다(serde 기본값 규칙). 관측 차이는 손으로 쓴 telegram.json 에만 생긴다. 조정자 판단 필요(gocompat 쪽 문제).
  - 전송 오류 문구(reqwest)는 Go net/http 문구와 다르다. 로그에만 나온다.
