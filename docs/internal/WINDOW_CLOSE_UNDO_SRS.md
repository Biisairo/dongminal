## 1. 개요

### 1.1 목적

`delWindow` 는 저장하지 않은 편집(FR-CLG-1)과 실행 중인 프로세스(FR-BG-1)가 있을
때만 묻는다. **한가한 셸은 즉시 `_kill`** 이다 — 스크롤백·작업 디렉터리·환경이
클릭 한 번에 사라지고 되돌릴 길이 없다. `×` 는 hover 에서만 보이는 16px 이고
모바일에서는 항상 보이는 44px 이라 행을 누르려다 닿는다. `UX-4` 가 키보드 길
(`Delete`/`Backspace`)을 하나 더 냈으므로 우발의 면적이 늘었다.

`03` 은 두 길을 적었다: (a) Undo 토스트 (b) 항상 확인. **(a) 를 택한다** — 확인창은
매번 손을 멈추고, 한가한 셸을 닫는 일이 실제로는 거의 언제나 뜻한 일이다. 되돌릴
수 있으면 묻지 않아도 된다. git 커밋의 Undo(FR-GIT-81~83)가 같은 판단이고, `UX-8`
이 `Toast` 에 동작 버튼을 세운 이유가 이것이다.

### 1.2 범위

- `web/js/core/app-layout.js` `delWindow` — 확인이 뜨지 않는 갈래.
- `web/js/core/constants.js` — 유예·문구.
- `e2e/window-close-undo.spec.ts`.

비포함:
- 탭 닫기(`closeTab`)의 되돌리기. 다른 요구이고(`03` 은 창만 적었다) 탭은 창보다
  잃는 것이 작다.
- 확인을 지나는 갈래의 변경. 저장 확인·프로세스 확인은 그대로다 (FR-WCU-5).
- 서버 변경. kill 을 지연하는 것은 클라이언트이며 서버 API 는 그대로다.

### 1.3 정의

| 용어 | 정의 |
|---|---|
| **한가한 창** | `delWindow` 가 확인창을 띄우지 않는 창 — dirty 편집기도 busy 도구도 없다 |
| **유예** | 창이 목록에서 사라진 뒤 도구가 아직 살아 있는 `WINDOW_CLOSE_UNDO_MS` |
| **최종** | 유예가 끝나 도구를 죽인 상태, 또는 확인을 지나 곧바로 죽인 상태 |

## 2. 현재 상태

- `delWindow` (`app-layout.js:177`): dirty → `_confirmClose`, busy → `_confirmClose`,
  그 밖에는 `pids` 전부 `_kill` 후 `splice`.
- 되돌리기 선례: `git/commit.js` `_undoShow/_undoHide/_undoRun` — `Toast.show(…,
  {actions:[…]})` 한 벌, 손잡이 `close` 로 타이머까지 함께 끝낸다.
- 도구를 살려 두는 상태는 이미 있다 — **백그라운드**(FR-BG). 창에 없는 도구가
  백그라운드도 아니면 화면 어디에도 없고 새로고침 뒤에는 닿을 길이 없다.
- `/api/state` 의 `tools` 가 살아 있는 도구의 목록이다 (e2e 가 그것으로 생사를 본다).

## 4. 설계 결정

**D-WCU-1: 유예 동안 도구는 백그라운드다 — 보이지 않는 상태를 만들지 않는다.**

  kill 만 미루면 도구는 어느 창에도 없고 백그라운드도 아닌 상태가 된다. 그동안
  새로고침하면 타이머는 사라지고 도구는 데몬이 다시 뜰 때까지 산다 — 화면 어디에도
  없이. 백그라운드는 정확히 "창에 없지만 살아 있다" 를 위해 있는 상태이고, 이미
  목록·복귀·종료의 길을 갖는다. 유예 5초 동안 Background 개수가 하나 늘어 보이는
  것은 사실을 보이는 것이다.

  그 대신 만료가 조심해야 한다 (FR-WCU-4): 백그라운드에 있는 동안 사용자가 그
  목록에서 되살릴 수 있다. 만료는 "내가 보낸 도구" 가 아니라 **"지금 어느 창에도
  없는 도구"** 를 죽인다.

**D-WCU-2: 확인을 지난 닫기에는 되돌리기를 두지 않는다.**

  확인창에서 "닫기" 를 고른 사용자에게 다시 5초의 Undo 를 주면 안전망이 둘이고,
  둘째 것은 첫째 것을 의심하는 것이다. busy 도구를 확인 뒤에도 살려 두려면
  "백그라운드로" 가 이미 그 답이다. 한가한 창에는 확인이 없으므로 Undo 가 그
  하나다.

**D-WCU-3: 되돌리기는 창 객체를 그대로 되살린다 — 다시 만들지 않는다.**

  `splice` 로 빼낸 객체(레이아웃·탭·도구 id·포커스 칸)를 같은 인덱스에 되돌린다.
  도구 인스턴스(`app.tools`)는 `_kill` 을 지나지 않았으므로 살아 있고, 다음 render
  가 붙인다. 새로 만들면 탭 이름·분할이 사라진다.

## 6. 비목표

1. 탭 닫기의 Undo.
2. 서버가 kill 을 미루는 것 — 서버 토큰(git undo 식)은 필요 없다. 도구는 백그라운드로
   서버에 이미 살아 있다.
3. `×` 의 모양·노출(hover 전용)을 바꾸는 것 — 되돌릴 수 있으면 잘못 누르는 것이
   덜 아프다.
