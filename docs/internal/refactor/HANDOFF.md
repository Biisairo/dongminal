## 0. 착수 블록 — 이번 세션이 할 일

**일곱 묶음(B1~B7)의 구현이 전부 끝났다. 남은 것은 최종 검증과 종결이다.**
이번 세션은 **새 코드를 쓰지 않는다** — 쓰게 되면 그것은 검증이 찾아낸 결함이고,
그때는 고치고 그 사실을 적는다.

### 0-1. 먼저 이것부터 — 검증 다섯

작업 트리는 깨끗하고 직전 커밋은 `02987c9b` 다. `git status` 로 확인하고 시작한다.

```
make gates          # 49종
npm run unit        # 프론트 289건
npm run typecheck
make lint
go test -race -shuffle=on ./...
make e2e            # 8샤드, 약 25분
```

**앞의 다섯은 B6·B7 진행 중 항목마다 통과시켰다.** 마지막으로 한 번 더 모아
돌리는 것이고, 빨간 것이 나오면 그것은 **묶음 사이의 간섭**이므로 반드시 쫓는다.

> **`make e2e` 는 새로 돌려야 한다.** 인계자가 백그라운드로 띄웠지만 그 프로세스는
> **탭이 닫히면서 함께 죽는다.** 직전 회차(B6 완료 시점, 커밋 `e381c2fb`)의 결과는
> **1,754 passed · failed 0 · flaky 1** 이었고, 그 뒤 B7 이 `ui-layout-defaults` 와
> `check-*` 게이트를 건드렸으므로 **다시 재야 한다.**

**`make e2e` 의 종료 코드는 믿지 마라** (§3-6). 샤드별 요약을 직접 센다:

```
for i in 1 2 3 4 5 6 7 8; do echo -n "샤드 $i: "; \
  LC_ALL=C grep -a "샤드 $i/8" <로그> | LC_ALL=C grep -aoE '[0-9]+ (passed|failed|flaky)' | tr '\n' ' '; echo; done
```

### 0-2. 그다음 — 종결 기록

검증이 전부 초록이면 **리팩토링 전체를 닫는 커밋** 하나를 쓴다. 담을 것은 셋이다.

1. **`docs/internal/refactor/README.md` §6 묶음표** — B1~B7 이 전부 `끝났다` 이고
   남은 것은 `B2-K`(사용자가 직접) 하나임을 표가 말하게 한다. B6·B7 행은 이미
   갱신돼 있다 (`02987c9b`).
2. **최종 수치** — `make gates` 종수 · 프론트 단위 · Go 단위 · e2e 전량의 실측.
   착수 시점(B5 종료)은 게이트 45 · 프론트 289 · e2e 1,745 였다.
3. **남은 빚** — §5 의 목록을 그대로 옮긴다. **줄이지 마라.** 이 저장소에서 빚을
   줄여 적은 자리가 다음 세션의 표본이 됐다 (§3-1).

### 0-3. 하지 않을 것

- **새 리팩터를 시작하지 않는다.** §5 의 빚과 §6 의 비목표는 각자 다른 결정을
  기다린다 — 여기서 주워 담으면 그 결정이 조용히 내려진다.
- **게이트를 느슨하게 만들어 통과시키지 않는다** (규약 2). 빨간 게이트는 고치거나,
  **재는 대상이 달라진 것**임을 문서에 근거와 함께 적고 기준선을 옮긴다.
- **드리프트 기준선을 재생성하지 않는다** (D-DSY-3). `LAYOUT_BASELINE=write` 는
  이번 세션의 도구가 아니다 — 그것은 *"지금이 옳다"* 를 선언하는 일이고, 왜
  달라졌는지 모르는 채로 하면 회귀를 기준선에 굳힌다.

## 3. 이 세션이 값을 치르고 안 것

### 3-1. "손으로 센 수는 표본" 이 **열한·열두·열세 번째**다

| 센 사람 | 무엇 | 적은 수 | 실측 |
|---|---|---:|---:|
| (앞의 열은 이전 인계서 §3-1) | | | |
| 감사 `AUDIT-fe-ui` P-2·P-4 | 폴링 경로의 `innerHTML=''` | **6** | **4** (셋은 사용자가 연 대화상자였다) + 감사에 없던 자리 하나 |
| 인계서 §0-6 | 결정 색인이 놓치는 결정 | **≈26** (세 문서) | **358** (49개 문서) |
| `AUDIT-docs-gap` **자기 요약표** | *"문서 낡음"* | **6** | **7** (본문의 `- **차이**:` 줄을 세면 LOW 가 둘이다) |

**셋째 줄이 새롭다.** 지금까지는 *"사람이 손으로 센 것"* 이 틀렸는데, 이번에는
**감사의 요약표가 자기 본문과 어긋났다.** 요약은 본문의 셈이어야 하는데 그것도
손으로 적힌다. 그래서 B7 은 대상을 요약표가 아니라 **본문에서 파생했다**
(FR-DSY-2).

> **도구를 고치는 일의 첫 판도 표본이었다.** 결정 색인의 프로토타입은 932를 냈다 —
> 느슨한 패턴이 `**D-Day …**` 를 `D-D` 로 줍고, 반대로 `D-8b`·`D-WRD-9a` 같은
> **정정 판**을 놓쳤다. 좁히고 넓혀 다시 세니 967이다. 그 과정에서 **색인이 표 행에서도
> `D-WRD-9a` 를 `D-WRD-9` 로 읽어 다른 결정의 번호를 달아 주고 있었다**는 것이 나왔다.

### 3-2. B6 의 성격 — **"고치지 않는다" 도 산출이다**

열다섯 중 둘을 재고 고치지 않았다. 그 둘이 이 묶음에서 가장 값비싼 판단이었다.

**항목 3 (`render()` 합치기)**. 감사의 근거는 *"호출 지점 57곳"* 이었고 그 수는
맞다. 틀린 것은 **회차당 57번**이라는 읽기다 — 실측은 어느 시나리오에서도
**동작당 한 번**이고, 감사가 대표로 든 *"폴링 1분"* 은 아예 **0회**다.
합치기는 **중복 호출**을 줄이는 장치인데 중복이 없었다.

**항목 12 (`refsTree` mtime 게이트)**. 감사 자신이 *"측정이 먼저다"* 로 조건을
걸었다. 재 보니 예산 아래였고, 더 중요한 것은 **그 게이트가 `shape` 가 존재하는
이유를 되돌린다**는 것이다 — `shape`(항목 이름 접기)는 **mtime 을 못 믿어서**
생겼다 (Windows 에서 `git branch` 뒤 mtime 이 45초 동안 그대로였다, FR-GVR-21a).

> **고친 것보다 고치지 않은 것을 적는 데 더 긴 근거가 들었다.** 그것이 맞다 —
> "했다" 는 diff 가 증명하고, "안 했다" 는 글만이 증명한다.

### 3-3. 한 축만 보면 **옮겨 간 비용이 보이지 않는다**

`grepWithGo` 의 첫 판(`ReadString`)이 그 자리였다:

```
B/op        22,985,593 → 12,901,105   (-44%)   ← 좋아졌다
allocs/op          538 → 160,419      (×298)   ← 나빠졌다
ns/op       16,160,087 → 15,797,301   (그대로)
```

바이트만 보고 끝냈으면 **성과로 적었을 것**이다. 비용이 사라진 것이 아니라 줄마다
string 을 잡는 쪽으로 옮겨 갔을 뿐이었다. `ReadSlice` + 되쓰는 버퍼로 고쳐 세 축이
함께 내려갔다 (−88% · −15% · −37%).

같은 모양이 `refsTree` 에도 있었다 — 해시를 인라인 FNV 로 바꾼 실험이 **할당을
한 톨도 줄이지 못했다.** 2,036 중 대부분이 `os.ReadDir` 의 것이었고
`h.Write([]byte(name))` 은 탈출하지 않아 컴파일러가 이미 없애고 있었다.
**재 보지 않았으면 그 실험을 성과로 적었을 것이다.**

### 3-4. **측정 하네스가 아무것도 재지 않는** 자리가 셋이었다

| 하네스 | 무엇이 틀렸나 | 어떻게 알았나 |
|---|---|---|
| `MutationObserver` | `takeRecords()` 만 쓰면 `await` 사이에 콜백이 큐를 비운다 | **고치기 전 코드에서도 초록**이었다 |
| `BenchmarkStaticPrecompressed` | ① 같은 줄을 되풀이한 본문은 gzip 이 수백 바이트로 줄인다 ② `httptest.NewRecorder()` 의 본문 버퍼가 재려던 할당을 덮는다 | 4,584 → 3,880 B/op 이라는 **너무 작은 차이** |
| `countingFS` | `Stat` 을 위임하지 않으면 `fs.Stat` 이 `Open` 으로 물러서 존재 확인이 읽기로 잡힌다 | 요청 5회에 **7**을 봤다 |

**규약 3-1 이 이것을 잡는다.** *"RED 를 실제로 본다"* — 첫 판이 고치기 전 코드에서
초록이면 그 검사는 다른 것을 재고 있다. B6 은 그 규약을 `FR-PRF-93`으로 명시했다.

### 3-5. **흔들리는 수를 게이트로 세우지 않는다** — 그 판단이 다섯 번 나왔다

`PERFORMANCE_BUDGET.md` §5-1 이 이미 같은 판정을 했고(성능 회귀 CI 를 두지 않는
이유), B6·B7 이 그것을 다섯 자리에서 되풀이했다.

| 감사가 적은 측정 | 왜 게이트가 못 되나 | 대신 무엇을 물었나 |
|---|---|---|
| pane 20회 뒤 **힙 스냅샷** | GC 에 흔들린다 | *"관측자를 잡는가"* (파싱) |
| 부팅 구간의 **Layout 이벤트 수** | 브라우저 계측 · 기계마다 다르다 | *"레이아웃을 애니메이션하는가"* (파싱) |
| `start` 의 **벽시계** | 2ms 는 기계 소음에 묻힌다 | *"부팅당 Install 진입이 몇인가"* |
| 핀 10개의 **응답 시간** | 이 기계의 `rev-parse` 속도다 | *"동시에 몇 개가 돌았는가"* |
| 레이아웃 **드리프트 합** | `기준선에만` 이 회차마다 흔들린다 (62 ↔ 74) | 붙박이 둘만 잠그고 셋째는 **찍는다** |

마지막 줄이 이번에 새로 배운 모양이다: **세지 않는 것과 보이지 않는 것은 다르다.**
잠그지 않더라도 실패 메시지에 찍어 사람이 볼 수 있게 둔다.

### 3-6. `LC_ALL=C sort` 가 아니면 **한국어를 세지 못한다**

`check-settings-docs.sh` 의 첫 판이 빠진 여섯 중 **셋만** 보고했다.
`en_US.UTF-8` 의 collation 아래에서 `sort -u` 가 서로 다른 이름을 같다고 본다:

```
편집기 줄바꿈 · 편집기 미니맵 · 탭 너비 · 탭 너비 고정 ·
알림 가장자리 · 비활성 창 가장자리     →  sort -u 뒤 여섯이 넷
```

`check-api-docs`·`check-commands-docs`·`check-vendor` 가 **이미** `LC_ALL=C sort` 를
쓰고 있었다 — 같은 함정을 먼저 만난 자리다. 나머지 게이트가 무사한 것은 **ASCII 만
정렬하기 때문**이고, 한국어를 세는 검사를 새로 만들 때는 그 한 줄이 필요하다.

> 같은 부류가 하나 더 있다 (이전 인계서 §3-7): `make e2e` 의 샤드 요약을
> `✘` 로 grep 하면 색 코드 때문에 안 잡힌다. `N failed` 를 센다.

### 3-7. 게이트가 **서자마자 하나를 찾는다**

B5 가 클립보드·겨냥·홈·모듈 크기에서 겪은 것이 B7 에서도 그대로였다.

- `check-home-layout` 에 문서를 더하자 **`verify-too-large.bin` 이 문서에 없었다** —
  B5 가 손으로 맞춘 뒤 아무도 표를 건드리지 않았는데 이미 어긋나 있었다.
- `check-repaint` 등록부를 채우다 **`panel-changes.js` `_paintHead` 의 배지 줄**이
  나왔다 — 감사의 여섯에 없던 자리다.
- 결정 색인의 패턴을 모으다 **정정 판 번호(`D-8b`)를 잘못 읽고 있었다**는 것이
  나왔다.

**손으로 맞춘 것은 유지되지 않는다.** 그것이 B7 의 여섯 항목이 전부 *"검사를
고치는 일"* 이었던 이유다.

### 3-8. 감사의 전제가 **절반만 참**인 자리가 있다

항목 6 이 그랬다. 감사는 *"폴링 회차마다 목록 전면 교체"* 라 적었는데,
`panel-poll.js:580` 의 `_obsSig` 가드가 **관측이 같으면 `paintAll()` 자체를 부르지
않는다.** 값이 그대로인 회차에 다시 그리던 것은 **원격 목록 하나뿐**이었다.

몸통은 **바뀐 회차**에 있었다 — `↑↓` 하나에 refs 사이드바 전체가, 미커밋 파일
하나에 배지와 열린 상세가 새로 만들어졌다. 그래서 측정이 둘이 됐다:
① 값이 그대로인 회차 → 변이 0 ② **바뀐 회차 → 바뀌지 않은 행이 살아남는다.**

**②가 없으면 ①은 "아무것도 안 그린다" 로도 통과한다.**

## 4. 변하지 않는 규약

`CONTRIBUTING.md` 가 원본이다.

1. **SRS → 테스트 → 코드.** RED 를 **실제로** 보고 나서 구현한다
2. **게이트를 느슨하게 만들어 통과시키지 않는다.** 다만 **재는 대상이 달라진 것**은
   느슨하게 만드는 것이 아니다
3. **새 게이트를 세우면 탐침으로 검출을 확인하고 지운다.** 잡아야 하는 것과
   **잡으면 안 되는 것**을 둘 다
4. **동작을 바꾸면 근거 문서를 같은 변경에서 고친다.** 이전 / 새 / 이유 셋
5. **커밋 메시지에 FR 번호를 단다. AI 서명 금지**
6. **생성물을 직접 고치지 않는다** — `docs/external/errors.md` · `docs/internal/decisions.md`
7. **색은 팔레트를 바꾸지 않는다** (FR-TOK-16)
8. **낱말·값을 바꾸기 전에 그것을 못박은 요구를 grep 으로 찾는다**
9. **대상 목록을 손으로 적지 않는다** — 파싱으로 파생한다 (§3-1, 열세 번 반복됐다)
10. **수를 문서에 적으려면 그 수를 지키는 것이 함께 선다** (D-DSY-6, 이번에 추가).
    적기만 한 수는 낡고, 새 수로 바꾸는 것은 같은 결함을 다시 심는 일이다
