설계와 다르게 한 것
- `.git`·common_dir 를 따로 감시하지 않았다(4.9 와 같음). gitdir·common_dir 경로 값은 `.git`(디렉터리 또는 linked worktree 의 `.git` 파일)이 정하고 그 변화는 저장소 루트 감시가 잡는다. common_dir 의 내용 변화(refs 등)는 해석 값을 바꾸지 않고 signature 가 본다. `.git` 파일이 가리키는 곳이 사라지면 signature 읽기 실패가 해석을 지운다.

남은 위험
- (LOW) macOS 디렉터리 사건 `<repo>/` 는 루트의 파일 하나만 바뀌어도 온다. 그때마다 gitdir 해석이 한 번 더 돈다(사용 중에만, 유휴 0).
- (LOW) 감시 대상이 아닌 저장소의 `.git` 이 바뀌었는데 signature 를 계속 읽을 수 있으면(예: 일반 저장소 ↔ linked worktree 로 같은 경로를 바꿈) 서버를 다시 띄우거나 `forget_root` 가 불릴 때까지 옛 gitdir 을 쓴다.
- (LOW) FSEvents 가 디렉터리 경로를 끝 구분자와 함께 알린다는 가정은 매처가 `<repo>`·`<repo>/` 둘 다 받아 덜었다. 실제 FSEvents 사건으로 `.git` 파일 교체를 재는 시험은 없다.
