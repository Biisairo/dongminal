## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 말은 넷이고, 인터뷰에서 다섯째가 붙었다.

> **새 기능**
> 1. 수정된 파일 닫을 때 저장하고닫기/그냥닫기/취소 팝업
>
> **오류**
> 1. 샌드박스 new 버튼에 아이콘과 글자 간격이 너무 좁다. slot +, - 버튼도 간격이 너무 좁다.
> 2. editor 에서 minimap 과 스크롤이 동기화 되지 않음.
> 3. md 미리보기(랜더) 버튼이 없음. 다른 미리보기도 같을것으로 추정
>
> **인터뷰에서 더해진 말**
> - "지금 미리보기 스크롤 ui 따로놀아. 공통 스크롤 ui 사용해."
> - (오류 2) "vsc 에서는 미니맵을 늘려서라도 적용되게 하던데."

접수한 넷 중 **둘은 이미 서 있는 것이 확인됐다** — 새 기능 1의 팝업은 탭 닫기에
있고(§2.1), 오류 3의 버튼은 DOM 에 있다(§2.4). 그러므로 이 문서가 다루는 것은
"만들라" 가 아니라 **닿지 않는 자리를 메우고, 보이지 않는 것을 보이게 하는 것**이다.

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 닫기 가드 | 창 닫기와 브라우저 떠남에 저장 안 된 편집의 가드를 세운다 |
| **B** 간격 | 샌드박스 `Box` 와 `− Slot +` 의 아이콘·글자 간격 |
| **C** 미니맵 | 미니맵 슬라이더와 스크롤바 슬라이더의 좌표계를 하나로 |

| **E** 미리보기 스크롤 | 공통 스크롤 표면을 키트에 세우고 렌더 뷰가 그것을 쓴다 |

## 2. 현재 상태 (실측으로 확정한 사실)

측정은 이 저장소를 그대로 띄운 인스턴스(`:58200`)에서 했다.

### 2.1 닫기 팝업은 **탭 닫기에만** 있다

`app-layout.js:527` 이 그 자리이고, 실측으로 세 버튼을 확인했다 —
`저장 후 닫기 / 닫기 / 취소`. 접수한 "새 기능"은 여기 이미 서 있다.

가드가 **없는** 경로가 둘이다.

| 경로 | 지금 | 잃는 것 |
|---|---|---|
| `delWindow(sid)` (`app-layout.js:169`) | 실행 중인 **프로세스**만 묻는다 | 그 창의 모든 편집 |
| `beforeunload` (`main.js:139`) | `app.tools.size>0` 만 본다 | 도구가 없는 Editor 창의 편집 |

`_edRemove` 경로는 이미 막혀 있다 — dirty 인 창은 남기고 알린다 (FR-WBR-40).
**같은 손실을 다른 길에서 조용히 낼 이유가 없다**는 그 문서의 근거가 이 둘에도
그대로 선다.

### 2.2 `Box` 에는 간격 토큰이 없다

`#add-window` 는 `display:flex;gap:6px` 을 갖는다. 그 안쪽 오른쪽에 앉는
`#add-sandbox-window` 는 `<svg>` + `Box` 를 담고도 **display 가 기본값(inline)**
이라 gap 이 걸리지 않는다 — 아이콘과 글자가 맞붙는다.

`.slot-ctl` 은 `gap:2px` 다. `− Slot +` 세 조각이 한 덩어리로 읽혀야 한다는
FR-WSL-50 의 뜻은 지켜지지만, 그 값이 키트의 `--ui-gap`(6px)보다 좁다.

### 2.3 `size:'fit'` 은 **짧은 문서에 적용되지 않는다**

400줄 문서, 편집기 높이 1180px 에서 잰 값이다.

| `minimap.size` | 스크롤 0% | 45% | 100% | `minimapHeightIsEditorHeight` |
|---|---|---|---|---|
| `'fit'` | 미니맵 0 / 바 0 | 미니맵 **311** / 바 **454** | 미니맵 **692** / 바 **1009** | `false` |
| `'fill'` | 0 / 0 | **454 / 454** | **1009 / 1009** | `true` |

3000줄 문서에서는 `'fit'` 도 세 지점 모두 일치했다. 즉 FR-MMP-1 의 실측(800줄)은
옳았고, **그 규칙이 덮지 못한 구간이 "문서가 편집기보다 짧을 때"** 다. `'fit'` 은
정의상 **줄이기만 한다** — 줄일 것이 없으면 아무것도 하지 않고, 그때 미니맵은
자기 콘텐츠 높이(줄수×2px)를 좌표계로 삼아 스크롤바와 갈라선다.

접수한 말이 그 해법을 지목한다 — **"vsc 에서는 미니맵을 늘려서라도 적용되게
하던데."** 그것이 `'fill'` 이다.

### 2.4 미리보기 버튼은 **있고, 보이지 않는다**

`.fe-render` 는 DOM 에 서 있다 (실측: `renderBtnCount:1`, `visibility:visible`,
`z-index:6`). 보이지 않는 이유는 셋이 겹친 것이다.

- 글자가 `◈` 하나뿐이다 — 무엇을 하는 버튼인지 읽히지 않는다
- `22×22`, `opacity:.65`, `color:var(--text-dim)` — 배경에 잠긴다
- 자리가 미니맵 위다. 언어 서버 제안 띠가 서면 `top:38px` 로 한 번 더 내려간다

### 2.5 렌더 뷰의 스크롤은 **꾸며지지 않은 유일한 본문 표면**이다

`.dr-body{overflow:auto}` 뿐이라 OS 기본 스크롤바가 뜬다. 앱의 다른 표면은 저마다
값을 적어 두고 있고(터미널 8px/`--text-dim`, 모달 6px/`--border`, 목록 4px),
**한 자리에서 정하는 규칙이 없다.** 미리보기는 소스 편집기와 나란히 서므로 그
차이가 가장 크게 보인다 — 접수한 말이 그것이다.

## 4. 요구사항 (Requirements)

### 4.1 묶음 A — 닫기 가드

- **FR-CLG-1** `delWindow(sid)` 는 그 창에 dirty 편집기가 있으면 닫기 팝업을
  띄운다. 버튼과 문구는 탭 닫기와 **같다** — 같은 사건에 다른 말을 쓰지 않는다.
- **FR-CLG-2** `저장 후 닫기` 는 **그 창의 dirty 편집기를 모두** 저장한 뒤 닫는다.
- **FR-CLG-3** `취소` 는 창을 남긴다. 창이 남으면 그 도구도 종료되지 않는다 —
  가드는 실행 중 프로세스 확인보다 **앞에** 선다.
- **FR-CLG-4** 하나의 창 닫기에 팝업은 최대 둘이다(편집 → 프로세스). 편집 가드에서
  취소하면 프로세스 확인은 뜨지 않는다.
- **FR-CLG-5** `beforeunload` 가드의 사유에 **dirty 편집기의 존재**를 더한다.
  도구가 없어도 편집이 있으면 묻는다.
- **FR-CLG-6** 그 판정은 `confirmLeave` 스위치 **아래**에 있다 (FR-LVC-9). 스위치를
  끈 사용자에게 새 사유로 다시 묻지 않는다.
- **FR-CLG-7** 자기 새로고침(`__dmReloading`)은 여전히 예외다 (FR-RLC-5a).

### 4.2 묶음 B — 간격

- **FR-GAP-1** `#add-sandbox-window` 는 아이콘과 글자 사이에 `--ui-gap` 을 둔다.
- **FR-GAP-2** `.slot-ctl` 의 간격도 `--ui-gap` 이다.
- **FR-GAP-3** 값을 px 로 적지 않는다 — 키트의 토큰을 읽는다 (FR-UIK-2).

### 4.3 묶음 C — 미니맵

- **FR-MMP-2** `minimap.size` 는 `'fill'` 이다 — **편집기와 diff 둘 다** (FR-MMP-1
  이 규정한 표면 그대로). **FR-MMP-1 을 개정한다.**
- **FR-MMP-3** 문서 길이와 무관하게 미니맵 슬라이더와 스크롤바 슬라이더의 `top` 과
  `height` 가 같다.

### 4.4 묶음 D — 미리보기 버튼

- **FR-DRB-1** 버튼의 이름은 **낱말 하나**다 (`미리보기`). 기호(`◈`)는 두지 않는다 —
  라벨이 선 뒤로 그것은 뜻을 보태지 않는 장식이다. **FR-DRV-3 을 개정한다.**
- **FR-DRB-2** 기본 불투명도와 글자색을 올린다 — 배경에 잠기지 않는다.
- **FR-DRB-3** 자리는 편집기 **좌상단**이다 (제안 띠가 서면 `top:38px`). 오른쪽은
  미니맵·스크롤바가 서는 자리이며 라벨이 붙으면서 덮는 폭이 세 배가 됐다. 버튼의
  오른쪽 변은 미니맵의 왼쪽 변을 넘지 않는다. **FR-DRV-3 을 개정한다.**
- **FR-DRB-4** 문자열은 `constants-docrender.js` 한 자리에서 온다.

### 4.5 묶음 E — 공통 스크롤

- **FR-SCR-1** 키트에 `.ui-scroll` 을 세운다 — 폭·손잡이 색·hover 를 한 자리에서
  정한다. 색은 소유하지 않는다 (FR-UIK-2).
- **FR-SCR-2** `.dr-body` 가 그것을 쓴다.
- **FR-SCR-3** 터미널 뷰포트(`.xterm-viewport`)도 같은 정의를 딛는다 — 두 벌로 두면
  한쪽만 고쳐진다.

### 4.6 비기능 (Non-functional)

- **NFR-1** 새 옵션·설정을 만들지 않는다. 접수한 넷은 모두 **기본값의 문제**다.
- **NFR-2** 닫기 가드는 사용자의 답을 기다리는 동안 워크스페이스를 바꾸지 않는다 —
  `delWindow` 는 답을 받은 **뒤에** splice 한다 (NFR-WBR-3 과 같은 근거).

## 6. 비목표 (Non-goals)

- 앱의 **모든** 스크롤 표면을 한 값으로 통일하는 것. 좁은 목록의 4px 은 그 자리의
  뜻이 있다. 이번에 묶는 것은 **본문 표면** 둘이다 (FR-SCR-3)
- 닫기 팝업의 문구·버튼 구성 변경. 이미 선 것을 그대로 쓴다 (FR-CLG-1)
- 미리보기 버튼을 **탭바로** 옮기는 것. 자리는 편집기 오버레이로 남는다 — 탭바는
  모든 탭 타입이 지나는 렌더 경로다 (FR-DRV-3 의 근거, D-5 는 그 안에서의 이동이다)
- 미니맵의 `scale`·`showSlider` 변경. 접수한 것은 **좌표계**다
