dongminal 저장소의 `refactor` 브랜치를 이어받는다.

## 0. 가장 먼저

**`docs/internal/REFACTOR_HANDOFF.md` 를 전부 읽어라.** 이 프롬프트는 그 문서의
착수 순서일 뿐이다.

```bash
git branch --show-current      # refactor 이어야 한다
git status --short             # 비어 있어야 한다
go build ./... && go vet ./... && go test ./...
```

## 1. 한 줄 상태

**열린 작업 항목이 없다.** 아홉 단계가 끝났고, 마지막 셋이 남아 있던 구멍을
메웠다 — `App` 상태 추출 노선 종결(`APP_STATE_EXTRACT_SRS` §8), `FG_RESTORE_RACE_SRS`
§7.4 가 미조사로 남긴 복원 경쟁의 조사(§8)와 수정(`RESTORE_FLIGHT_SRS`),
그리고 `agents-poll` 배선 회수.

검증 상태: Go 29개 패키지 전량 통과 · **e2e 933개 전량 통과(실패 0)**.

## 2. 이번 세션의 일 — 물을 것 하나

작업이 아니라 **판단**이 하나 남았다.

**`refactor` 를 `main` 에 병합할 것인가.** `git log --oneline origin/main..HEAD` 가
세는 커밋 전부가 `main` 밖에 있고 `main` 은 손대지 않았다. 이것 말고는 이 브랜치가
사용자에게 요구하는 것이 없다.

병합하지 않기로 하면 §3·§4 를 읽고 **아무것도 새로 열지 마라** — 열린 항목이
없는 것이 이 브랜치의 상태다.

## 3. `App` 을 다시 분해하려는 유혹이 들면

**하지 마라. 이 저장소는 이 측정을 두 번 틀렸다.** 그래도 열려면
`APP_STATE_EXTRACT_SRS` §8.1(측정 절차) · §7.3(판정 조건 셋) · §8.2(실측표)를
읽고 **같은 측정을 재현한 뒤** 열어라. 요약:

- `app-statusbar.js` — `_gitJobs` 를 `app-git.js` 가 13곳에서 쓴다
- `app-editor.js` — 50개 중 35개를 바깥이 붙잡는다
- `app-attn.js` — 26개 중 15개. 대신 유틸 회수로 처리했다
- `app-reload.js` — 전용 필드가 하나뿐이다

`App` 의 46%가 전용 필드인 것은 사실이나 **그 필드들이 파일 경계와 정렬돼
있지 않다.** 파일 단위 분해는 위임 계층만 늘린다.

## 4. 하지 말 것

`GitPanel` 객체 분해(필드를 10~21개 공유한다) · `constants-git.js` 분할 ·
staticcheck 잔여 8건(전부 오탐이거나 CLI 출력이다) · **`_bgRefresh`·`_focusRestore`
에 복원 비행 규약을 붙이는 것**(증분 갱신 경로가 없어 죽은 코드가 된다 —
`RESTORE_FLIGHT_SRS` §5 N1). 사유는 핸드오프 §5 에 있다.

### 4.1 복원을 새로 쓰게 되면

서버 스냅숏을 fetch 해 로컬 상태와 정합하는 함수를 새로 만든다면 **`_restoreBegin`·
`_restoreLive`·`_restoreNote` 규약을 쓴다** (`app-cmd.js`). 규약을 손으로 옮겨
적다가 한 방향을 놓친 것이 이 저장소가 같은 결함을 두 번 낸 이유다.

## 5. 반드시 지킬 것

**조사할 때 세 가지를 모두 센다.** ① 바깥이 부르는 메서드 ② 바깥이 `app.` 으로
읽는 필드 ③ **형제 파일이 `this.` 로 만지는 필드**. ③ 이 최대 함정이다 — 파일은
갈렸어도 `this` 는 하나다. 절차는 핸드오프 §4.1.

**옮기기는 `Object.assign` 증강으로, 메서드 이름은 바꾸지 않는다.** 그래야
"옮기기만 했다" 가 diff 로 증명된다.

**e2e 실패 1건은 회귀가 아닐 수 있다.** 927개 중 1개꼴로 산발로 흔들린다.
실패하면 **반드시 단독 재실행**으로 가른다.

**조직 규정**: 스펙 문서 없이 작업하지 않는다. 커밋 메시지에 AI 서명을 넣지 않는다.
