  **fswatch 공개 API (dm-webserver-fswatch, 동기·스레드)**
  - `Manager::new(ManagerOptions)`, `ManagerOptions::defaults(emit)`(notify 백엔드·실제 시계·OS 규칙), `attach(cid) -> u64`, `detach(cid, epoch)`, `set(cid, &[Dir{path, real}]) -> Result<Vec<String>, NotAttached>`(정렬된 철자), `close()`.
  - emit: `Arc<dyn Fn(&[Change], bool)>` — overflow 면 changes 는 비었다. `Change{path, kind: Kind::{Added,Updated,Deleted}}`, `Kind::as_str()` 는 "added"·"updated"·"deleted".
  - 상수: `CHANGES_DELAY` 75ms, `DELETE_RECHECK_DELAY` 100ms, `CHUNK_SIZE` 100, `CHUNK_PAUSE` 200ms, `MAX_BUFFERED` 10000, `MAX_RESTARTS` 5, `KQUEUE_ENTRIES_MAX` 4096 (Go 와 같다). `watchable(real)`: macOS 는 `/Volumes/` 와 항목 4096 초과 제외, Linux 참, Windows 거짓.
  - 주입점: `Backend` trait + `BackendMsg::{Event(RawEvent), Error(BackendError::{Overflow, Exhausted, Other})}`, `Clock` trait(`RealClock` 은 타이머 스레드 하나), `Pipeline`, `coalesce`.

  **Go 와 다르게 한 내부 결정**
  - macOS: notify 의 비재귀 kqueue 감시는 디렉터리 안 파일을 보지 않는다. 그래서 백엔드 안에서 fsnotify 처럼 항목마다 감시를 걸고, 디렉터리 Write 때 다시 읽어 새 항목을 Create 로, 항목 Remove·Rename 뒤에는 부모를 다시 읽어(덮어쓴 파일) Create 로 낸다. 하위 디렉터리의 Write 는 fsnotify 와 같이 내지 않는다. Linux 는 notify inotify 비재귀를 그대로 쓰고 이벤트 종류를 fsnotify op 로 옮긴다(이름 바뀜 To→Create, From→Rename, Both 무시, rescan 표시→Overflow).
  - 백엔드 오류·이벤트를 채널 하나로 받는다(Go 는 두 채널). 멎은 백엔드 판정은 세대 번호로 한다.
  - 실제 시계는 Go AfterFunc 의 goroutine 대신 타이머 스레드 하나에서 콜백을 차례로 부른다. emit 은 오래 막지 않아야 한다.
  - NFC 정규화에 `unicode-normalization` 을 허용 목록에 더했다(DEPENDENCIES.md·루트 Cargo.toml). Go x/text 와 유니코드 판이 달라도 기존 글자의 합성 규칙은 같다.
