# 2.9 기록 줄 수 설정과 데몬 교체 호환 (D-7, FR-TRM-2)

## 목표

설정 `termHistoryLines`(데몬, 기본 50,000, 1,000~200,000)와 `termScrollback`(브라우저, 기본 5,000, 500~50,000)을 더한다(D-25). 데몬 값은 서버가 IPC 로 알린다(`attnconfig` 방식). 브라우저 값은 상수 `TERM_SCROLLBACK_LINES` 를 대신한다.
데몬 교체: 인계 판 2 로 스냅숏 ANSI 와 저장소 블록을 넘기고, 판 1(링 바이트)도 받아 에뮬레이터에 먹인다(D-27).

설계: `perf/M2_DESIGN.md` §2.9.

## 완료 조건

- RED: 데몬 기록 값을 줄이면 저장소가 곧바로 그 줄 수로 줄고, 늘리면 그 뒤로 더 쌓인다. 범위 밖 값은 거절한다.
- RED: 인계 판 2 전후로 화면·기록 마지막 5만 줄·오프셋·모드가 같다.
- RED: 인계 판 1(옛 데몬 → 새 데몬)로 화면을 되세우고 도구가 계속 돈다.
- 바꾼 부분의 시험(단위·관련 e2e 한두 개)·fmt·clippy·관련 게이트 통과. 전체 시험은 마일스톤 끝에서 한 번만(2.10).
- 시험을 먼저 쓰고 RED 를 확인한 뒤 구현한다.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.

**바꾼 것 — 데몬 교체 (D-27)**

- `LineStore::export`/`import(cap, &[u8])` — 형식 번호 1 + 첫·끝 번호 + 블록(첫 번호·줄 수·deflate 바이트). 풀린 블록은 압축해 담는다. 빈틈·남는 바이트·모르는 형식은 `None`. 받을 때 지금 상한을 얹는다.
- `termstate::Handover{snapshot, back, store}`, `Screen::handover()`(에뮬레이터 기록 전부 + 화면을 스냅숏으로, 저장소 줄은 싣지 않음 — 대체 화면이면 가려진 주 화면의 기록도), `Screen::restore(cols, rows, cap, snapshot, store)` — 스냅숏을 넣는 동안 `keep` 을 넘어 옮겨진 줄은 넘겨받은 저장소 뒤에 잇는다. 그림이 깨졌으면 빈 저장소로 시작하고 화면은 되세운다. 스냅숏 내부 `state()` 는 시험 전용이 됐다.
- `HandoverTool` 선택 필드: `screenState`(스냅숏)·`screenBack`·`history`(저장소 그림). 비면 직렬화하지 않는다 — Go 골든(`GO_FULL`)은 그대로이고, 옛 데몬은 모르는 필드를 무시한다(gocompat 디코더 기본).
- `export_handover` 가 담고, `adopt_handover` 가 `Tool::adopt_screen` 으로 되세운다: 필드가 있으면 스냅숏 + 저장소 그림 + 링의 마지막 `back` 바이트, 없으면(옛 데몬) 링 바이트를 에뮬레이터에 먹인다(링이 잘렸으면 첫 줄바꿈까지 버림).

**지운 것**: `TERM_SCROLLBACK_LINES`, `TOPTS.scrollback`.
