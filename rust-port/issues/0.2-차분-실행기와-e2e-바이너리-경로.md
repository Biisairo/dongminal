# 0.2 차분 실행기와 e2e 바이너리 경로

## 목표

V-RSP-2 의 차분 실행기를 `rust/parity/` 에 만든다. 시나리오(YAML 또는 Rust 코드)를 Go 바이너리와 Rust 바이너리에 각각 격리 실행으로 돌리고 CLI 출력·종료 코드·HTTP 응답·홈 파일을 비교한다. 정규화 규칙(시각·PID·임시 경로·무작위 ID)을 시나리오마다 선언할 수 있어야 한다. Go 참조 바이너리는 내 worktree 에서 `go build -o rust/target/go-ref/dongminal ./cmd/dongminal` 로 만든다(저장소 루트에 만들지 않는다). 함께 FR-RSP-31(`DM_E2E_PREBUILT_BIN`)을 `e2e/global-setup.ts` 에 구현한다. 아직 Rust 쪽은 빈 껍데기이므로 `version`·`--help` 같은 최소 시나리오로 실행기 자체를 검증하고, 시나리오 작성 가이드를 `rust/parity/README.md` 에 둔다.

- **내린 결정**
  - 시나리오는 Rust 코드로 쓴다. YAML crate 가 허용 목록에 없기 때문이다.
  - HTTP 클라이언트는 std `TcpStream` 위에 직접 구현했다. 와이어를 그대로 보기 위해서다. 헤더 이름은 대소문자를 가리지 않는다(hyper 는 소문자로 보낸다). `Content-Length`·`Transfer-Encoding` 은 비교하지 않고, `Date` 는 있는지만 본다.
  - 실행 오류는 관측값 `error` 로 비교한다. 그래서 두 쪽이 똑같이 실패하면 차이가 아니다. 이 함정은 실제로 겪었다(처음에는 Go 서버가 소켓 경로 한도 때문에 두 쪽 모두 뜨지 못했는데도 Go 대 Go 가 통과했다). 그래서 `go_server_scenarios_really_serve` 테스트로 Go 쪽이 `ready=ok`·`200 OK` 인지 따로 확인한다.
  - 쪽 뿌리 이름을 짧게 했다(`pg1a2b3c`). `{home}/paned.sock` 이 103바이트를 넘으면 실행 전에 오류를 낸다.
  - 포트는 60147 이상(기본 60400)에서 고른다. 쥔 프로세스가 있는 포트와 같은 프로세스가 이미 내준 포트는 건너뛴다. Go `start` 는 포트를 쥔 프로세스를 종료하므로, 병렬 테스트가 같은 포트를 받으면 서로의 서버를 끈다. 이 문제를 실제로 겪고 고쳤다.
  - 정리는 serve 로 띄운 자식과, `paned.pid` 가 가리키는 프로세스 중 실행 파일이 그 쪽 바이너리인 것만 끈다(TERM, 5초 뒤 KILL). 운영 바이너리 경로와 `.dongminal` 아래의 바이너리는 거절한다.
  - `version` 시나리오는 `go1.27.2` 같은 런타임 판 토큰을 `<GORUNTIME>` 으로 정규화한다. Rust 판이 이 자리에 무엇을 찍어야 하는지는 6.1·7 이 정한다. 필요하면 그때 규칙을 좁힌다.
