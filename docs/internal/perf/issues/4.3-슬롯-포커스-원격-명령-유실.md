# 4.3 첫 칸이 아닌 슬롯에 포커스가 있으면 원격 명령이 버려진다

## 배경 (사용자 보고 2026-11-25)

- 슬롯 [1] 이상에 포커스가 있으면 `otterctl new-tab`·`new-window` 가 `timedOut:true`·`newTabs:null` 로 실패하고, `close-tab --force`(·`--background`)는 `ok:true` 인데 탭이 남는다. `rename-tab` 처럼 실행자를 지정하지 않는 명령은 된다. 새로 고침이나 슬롯 [0] 클릭으로 풀린다.
- 관찰(운영 server.log 요약, 사용자 제공): `action=newTab … delivered=3 newTabs=0 timedOut=true`, 새로 고침(`POST /api/focus/claim`) 뒤 `newTabs=1 timedOut=false`.
- 원인 셋:
  1. 서버가 실행자 하나를 지정 — `httpapi/src/commands.rs:139-141`(`is_single_executor_action` 이면 `exec_client_id = focus.executor()`), `hub/src/focus.rs:26-42`(가장 최근 포커스를 주장한 clientId).
  2. 슬롯은 칸마다 다른 clientId 로 포커스를 주장 — `web/js/core/slots-controller.js` 머리(FR-WSL-10, `_slotIds`, [0] 은 `app.clientId`), `focus-owner.js:85`.
  3. 브라우저 라우터는 슬롯 [0] id 로만 비교 — `web/js/core/event-bus.js:168` `if(m.execClientId&&m.execClientId!==this.app.clientId) return;` → 어느 연결도 자기 것으로 알아보지 못해 버려지고 echo 가 오지 않는다.
- 영향: 에이전트 트리(`/otterminal:issue-tree`)가 하위 탭을 열고 닫지 못해 멈춘다. 사용자에게 오류가 보이지 않는다.

## 목표 (사용자 결정 2026-11-25: A + 공통 보강)

- **A**: 라우터가 그 창의 모든 슬롯 id(`app.slot._slotIds` 등 — 코드로 확인)를 자기 것으로 알아본다. 지정된 슬롯의 문맥(그 칸의 활성 창)으로 실행할지 첫 칸이 대신 실행할지는 `WINDOW_SLOTS_SRS` 「소유권」 규칙을 근거로 정하고 기록한다.
- **공통 보강**: 지정된 실행자가 받지 못한 명령을 알아챌 길 — 서버의 시간 초과 응답(과 로그)에 「지정 실행자 = <clientId>」를 싣는다. `commands.rs` 를 건드리므로 4.2 병합 뒤에 한다.

## 완료 조건

- RED 먼저: 슬롯 둘에서 [1] 포커스 뒤 newTab·newWindow·closeTab(--force·--background) 성공(e2e), 슬롯 [0] 포커스 회귀 없음, 기기 둘(다른 연결)일 때 「가장 최근 포커스」 규칙(FR-SXE-4) 유지, 라우터 단위 시험.
- 동작 변경 이전 / 새 / 이유. 전체 시험 금지.
