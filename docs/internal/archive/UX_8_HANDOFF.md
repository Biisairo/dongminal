## 2. 첫 일 — 받은 결정 (다시 묻지 않는다)

사용자 신고(그대로): *"선택중임을 나타내는 동그라미와 에이전트 실행중을 나타내는 동그라미가 동일하게 겹친다. 펼친 패널에서는 구분되어 보여서 문제없으나 패널이 레일모드가 되면 더더욱 구분이 안간다. 고로 두 원을 합친다. 실행중인 에이전트는 선택 원 주변을 두르는 링 처럼 만든다. 또한 실행중 에이전트는 다른 색을 사용한다. 이때는 테마가 바뀌어도 문제없게 테마색을 이용한다. 이는 다른 위치에서도 에이전트 활성화 관련 색들을 전부 같은 색을 사용하도록 하여 통일성있게한다."*

색에 대한 이어진 답(그대로): *"green 으로 하면 안돼. 그럼 테마가 바뀌어도 초록이잖아. 테마에 따라 바뀌는 색으로 해야한다."* → *"테마색을 추가한다. work 로 하지 말고 범용적인 이름으로 해서 다른데도 사용 가능하게, accent 2 가 좋겠다. 하는김에 accent 를 3~5 정도까지 늘려서 테마색 선택지를 늘리자."*

- **D-42 (스펙에 적을 것)**: 테마 UI 슬롯에 `accent2`·`accent3`·`accent4`·`accent5` 를 더한다(범용 이름 — 용도 이름 금지). 54개 테마(`web/js/ui/themes.js`, 테마마다 `ui:{…accent…}`) 와 **사용자 정의 테마**(테마 편집기) 둘 다. CSS 토큰은 `--accent2`…`--accent5`
- **D-43**: 에이전트 **실행 중** 색은 `--accent2` 다. 쓰는 자리를 전부 맞춘다 — 지금 갈라져 있다:
  - accent 를 쓰는 곳: `.work-dot`(칸 탭·사이드바 창 행, `style.css:779`), `#m-act-btn .m-act-dot`(`style.css:2051`), Run 노드 `state-working`(`style-runs.css:107·123·174·216`)
  - `--term-green` 을 쓰는 곳: `:is(.ag-state,.ag-dot).working`(`style.css:1004`), `.ag-sub-state.working`(`style.css:1032`)
  - **`--term-green` 은 거절됐다** — 테마가 바뀌어도 초록이다
- **D-44**: 사이드바 창 행의 선택 점(`.sbl-dot`, 활성이면 accent)과 작업 점(`.work-dot`)을 **합친다.** 실행 중이면 선택 점을 **두르는 링**(색 `--accent2`)이다. 레일에서도 그 링으로 구분된다
  - 지금: `sidebar-list.js:199` `if (r.work) workDotSync(el, true, null)` 가 이름 뒤에 `.work-dot` 를 붙이고, 레일에서는 `style.css:782~783` 이 그 점을 선택 점 아래에 겹쳐 얹는다 — 같은 accent 라 구분이 안 된다
  - 그룹 머리 행(`groupRow`, `sidebar-tabs.js:40`)은 작업 표식이 없다 — 손대지 않는다
  - 칸 탭(`.pn-tab>.work-dot`)은 선택 점이 없다 — 점은 남기고 색만 `--accent2` 로

### 스펙을 쓸 때 정할 것 (사용자에게 하나씩 물을 것 — 아직 묻지 않았다)

- 54개 테마의 accent2~5 값을 **어떻게 정하나**: 손으로 하나씩 / 그 테마 터미널 팔레트(blue·magenta·cyan·green·yellow)에서 accent 와 다른 색을 차례로 / 혼합. 권장안을 붙여 묻는다
- 사용자 정의 테마의 기본값(값이 없을 때): 같은 규칙으로 파생
- accent3~5 는 지금 쓰는 자리가 없다 — "선택지를 늘린다" 는 뜻이 테마 편집기에서 고르는 슬롯인지, 화면 어딘가에 쓸 것인지 확인한다
- 대비: `deriveContrastTokens`(테마 6색을 4.5:1 로 끌어올림, `style.css` FR-SEM-1 주석 참고)에 accent2 를 넣을지

## 3. 이 세션이 값을 치르고 배운 것

- **e2e 의 끌기 시험은 실제 마우스로 해야 한다.** `window-groups.spec` 은 명령 API 로만 순서를 바꿔 실제 끌기 결함을 못 봤다. 합성 끌기(`page.mouse`)는 마지막 이동의 `dragover` 를 놓칠 때가 있다 — 목표에서 1px 더 움직인다(`window-groups.spec.ts` TC-WGR-3b 의 `drag` 도우미)
- **zsh 는 따옴표 없는 변수를 단어로 나누지 않는다.** `npx playwright test $files` 는 한 덩어리로 넘어간다 — 파일 이름을 직접 적거나 `${=files}`
- **스크롤 시험의 높이 붙이기**: 컨테이너 자신에 `padding-bottom` 을 주면 그 높이가 함께 커져 스크롤 여유가 생기지 않는다. `::after` 는 몸통에 따라 그려지지 않는다. 자식들에 `margin-bottom` 을 준다(`panel-tabs-unify.spec.ts` `tall`)
- **바뀐 동작을 시험이 정말 재는지** 옛 코드로 확인한다: `git stash push -- web/js` → 새 시험 실행(실패해야 한다) → `git stash pop`. 첫 판 시험이 옛 규칙으로도 통과하던 일이 있었다(그룹 밖 판정 띠 안쪽 좌표)
- **중단된 도구 호출도 일부 실행됐을 수 있다.** 사용자가 끊은 명령이 파일을 이미 고쳐 D-39 가 두 줄이 됐다 — 끊긴 뒤에는 `git diff` 로 본다
- **스펙의 범위 문구를 좁게 읽지 않는다.** D-32 를 "모바일 서랍" 으로만 구현했다가 사용자가 "왜 안 했어" 라고 짚었다 — 같은 모양이 데스크톱에도 있으면 묻는다
- `dmctl`·화면 시험: `app.testing.<이름>` 만 쓴다(게이트 FR-ATC-1). `_openSettings` 는 `openSettings` 로 노출된다(밑줄이 떨어진다). `_shortCwd` 는 노출되지 않는다
- `ui/`·`git/` 에서 App 의 `_` 이름을 부르면 계층 게이트가 막는다 — 이름을 승격한다(`mTopPaint`)
- 다시 그리기 등록부: `innerHTML=''` 꼴은 `PERFORMANCE_BUDGET.md` §2-5-1 표에 올린다. `replaceChildren` 으로 피해 가지 않는다
- 모듈 크기 게이트: `app-settings.js` 500 경계(지금 500), `file-tree-paint.js`·`app-layout.js` 975(최대). 늘리면 줄을 합치거나 새 파일로
- V-LAY-1 은 **단독**(`--workers=1`)으로 돌린다. 의도한 차이면 `LAYOUT_BASELINE=write` 로 다시 뜨고 다시 대조한다
- `activity-rail` TC-ACF-1 과 `editor-ops` O7 은 전체 실행에서만 가끔 진다(단독 통과) — 받아들인 흔들림
- 설정 화면의 불리언은 전부 `ui-switch` 여야 한다(`kit-components` TC-CMP-3)
