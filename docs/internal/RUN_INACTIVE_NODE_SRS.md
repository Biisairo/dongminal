# SRS: Run 의 비활성 노드 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요

### 1.1 목적

접수한 요청은 다음과 같다.

> 여전히 run 에서 끝난 노드가 활성 노드와 똑같이 생겼고 클릭이 된다. 비활성 노드는 크기를 작게 줄이고, 필요하지 않은 데이터(에이전트 상태 및 사용량)는 지우고, 노드와 노드 아래 에이전트 목록을 눌러도 오류가 나지 않도록 클릭이 안 되게 한다. 아래 에이전트 목록에서는 비활성 에이전트를 뺀다.

`lost`(보고 없이 도구가 사라진 멤버)는 사용자 결정으로 따로 다룬다: 비활성으로 두되 눈에 띄게 표시하고, 클릭을 막고, 세션이 다시 잡히면 다시 활성이 된다.

### 1.2 범위

**포함:** Run 대시보드의 이슈 트리 노드(`run-tree.js`), 멤버 카드(`run-dashboard.js` `_runPaintCards`), 서버의 멤버 상태 판정(`deriveMemberState`).

**미포함:** 트리가 아닌 Run 의 관계 그래프(`_runNodeEl`). 그 노드는 원래 클릭할 수 없다.

### 1.3 정의

| 용어 | 정의 |
|---|---|
| **끝난 멤버** | 상태가 `done`·`failed`·`released` 인 멤버. 보고를 마쳤거나 놓여났다 |
| **잃은 멤버** | 상태가 `lost` 인 멤버. 보고하지 않았는데 도구가 **확인된 죽음**이다 |
| **비활성 노드** | 끝난 멤버 또는 잃은 멤버의 노드·카드 |

## 2. 현재 상태 (코드 근거)

- 트리 노드(`run-tree.js` `_runTreeNodeEl`)는 끝난 노드에 `ended` 클래스(흐리게)만 붙인다. 크기·상태·맥락 % 가 그대로이고, 누르면 `_runJumpToMember` 를 부른다.
- 카드(`run-dashboard.js` `_runCardEl`)는 상태와 상관없이 모두 그리고, 누르면 `_runJumpToMember` 를 부른다.
- `_runJumpToMember` 는 도구가 화면에 없으면 `/api/runs/attach` 를 부른다. 끝났거나 잃은 멤버는 붙일 도구가 없어 실패하고, 카드에 오류가 남는다.
- 서버의 `deriveMemberState` 는 두 값 생존(`toolLive`)을 쓴다. 데몬이 잠깐 답하지 못하면 살아 있는 멤버가 `lost` 가 된다 (AGENT_RECORD_DAEMON_SRS §2.2 와 같은 결함).

## 3. 요구사항

### 3.1 트리 노드

- **FR-RIN-1** 끝난 멤버의 노드는 작은 상자로 그린다. 이슈 번호와 제목 한 줄만 싣는다. 상태·맥락 %·잎 표시·사슬 이름은 싣지 않는다.
- **FR-RIN-2** 잃은 멤버의 노드는 보통 크기로 그리되 눈에 띄는 표시를 한다(경고색 점선 테두리, 상태 글자 `lost` 를 경고색으로). 맥락 % 는 싣지 않는다.
- **FR-RIN-3** 비활성 노드는 누를 수 없다. 클릭·키보드 처리기를 걸지 않고, `role=button`·`tabindex` 를 두지 않으며, 커서는 기본 모양이다. 툴팁(`title`)은 남긴다.
- **FR-RIN-4** 트리의 선은 각 노드 상자의 실제 아래 끝에서 나간다. 작은 상자의 부모도 선이 끊기지 않는다.
- **FR-RIN-5** 끝난 노드의 상자는 폭도 좁다(`RUN_TREE_NODE_W_ENDED`). 가로 칸은 노드마다 그 상자 폭만큼 받는다. 부모 상자가 자식들이 차지한 폭보다 넓으면 그 가지 전체를 부모 폭에 맞춰 오른쪽으로 민다. 같은 줄의 상자는 겹치지 않는다. 선은 각 상자의 가운데로 이어진다.

### 3.2 멤버 카드

- **FR-RIN-10** 끝난 멤버는 카드 목록에서 뺀다.
- **FR-RIN-11** 잃은 멤버의 카드는 남기되 FR-RIN-2 와 같은 표시를 하고 누를 수 없다. 맥락 표시는 싣지 않는다. 서버가 허락한 버튼(예: 분리)은 그대로 둔다.

### 3.3 다시 활성

- **FR-RIN-20** 잃은 멤버의 도구가 다시 살아 있으면(서버의 다음 응답에서 상태가 `lost` 가 아니면) 노드와 카드는 보통의 활성 모양과 클릭으로 돌아간다. 화면은 따로 기억하지 않고 서버의 상태만 따른다.
- **FR-RIN-21** 서버는 생존을 **모를 때**(`unknown`) 멤버를 `lost` 로 판정하지 않는다. 그때는 살아 있는 것처럼 훅 상태로 판정한다. `lost` 는 확인된 죽음일 때만이다.

### 3.4 비기능

- **NFR-RIN-1** 활성 노드·카드의 모양과 동작은 바뀌지 않는다. 기존 e2e 가 통과한다.

## 4. 설계

| 자리 | 내용 |
|---|---|
| `run-tree.js` | `RUN_TREE_ENDED` 에 더해 잃은 상태를 가른다. 끝난 노드는 높이 `RUN_TREE_NODE_H_ENDED` 의 상자와 머리 한 줄. 배치의 `pos[i]` 에 상자 높이 `h` 를 실어 선이 그 끝에서 나간다. 비활성이면 처리기를 걸지 않는다 |
| `run-dashboard.js` | `_runPaintCards` 가 끝난 멤버를 거른다. 잃은 카드는 `inactive` 클래스, 처리기 없음, 맥락 없음 |
| `style-runs.css` | `.run-tree-node.inactive`·`.run-card.inactive` 커서 기본, 잃은 표시(경고색 점선) |
| `httpapi/handlers_runs.go` `deriveMemberState` | `live := s.toolLiveness(id) != livenessDead` |

## 5. 검증

| TC | 대상 | 방법 | 기대 |
|---|---|---|---|
| TC-RIN-1 | FR-RIN-1·3·4 | 단위(run-tree): done 노드 | 작은 상자, 상태·맥락 없음, 처리기·role 없음. 선이 상자 끝에서 나간다 |
| TC-RIN-5 | FR-RIN-5 | 단위(run-tree-layout): 끝난 잎·끝난 부모가 섞인 트리 | 끝난 상자 폭이 좁다. 같은 줄의 상자가 겹치지 않는다. 그림 폭이 모두 보통 폭일 때보다 좁다 |
| TC-RIN-2 | FR-RIN-2·3 | 단위(run-tree): lost 노드 | lost 표시, 맥락 없음, 누를 수 없음 |
| TC-RIN-3 | FR-RIN-10·11 | 단위(run-dashboard): 카드 | done 카드가 없다. lost 카드는 누를 수 없다 |
| TC-RIN-4 | FR-RIN-21 | Go(httpapi): 생존 unknown 인 멤버 | `lost` 가 아니다. dead 면 `lost` 다 |
