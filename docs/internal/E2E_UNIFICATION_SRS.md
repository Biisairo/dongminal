# SRS: 종단간 검증의 통일 — 세 OS 가 같은 목록을 돈다 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

이 저장소의 종단간 검증은 **대상마다 다른 것을 검사한다.** macOS 는 셸 스크립트로
21항목을, Linux 는 CI 인라인 bash 로 5단계를, Windows 는 CI 인라인 PowerShell 로
같은 5단계를 돈다. 세 벌은 서로의 목록을 모른다.

결과가 둘이다.

1. **어떤 보증은 한 대상에서만 선다.** darwin 의 git 읽기 표면 8종·`/api/stats`·
   `/api/settings`·정적 자산 검사는 Linux·Windows 에서 한 번도 돌지 않는다.
   반대로 CI 의 입력→출력 왕복은 darwin 에서 돌지 않는다.
2. **규칙이 두 벌이라 한쪽만 고쳐진다.** Linux 와 Windows 의 종단간은 bash 와
   PowerShell 로 각각 적혀 있고, 실제로 한쪽만 고친 이력이 있다.

이 문서는 검사의 **정의를 Go 한 벌로 옮기고**, 세 대상이 그 한 벌을 돌게 하는
요구사항을 정의한다.

### 1.2 범위 (Scope)

**대상 안**

- 새 서브커맨드 `dongminal verify` — 격리 인스턴스를 스스로 띄우고 HTTP 표면을
  훑은 뒤 치운다
- 현행 세 하네스가 검사하던 항목의 **합집합**을 그 한 벌에 담는다
- 대상별로 성립하지 않는 항목을 **능력 질의**로 건너뛰되, 건너뛴 사실과 이유를
  보고서에 남긴다
- `.github/workflows/verify.yml` 의 두 인라인 종단간 블록을 그 한 줄로 교체
- `scripts/verify-isolated.sh` 를 그 한 줄을 부르는 껍데기로 축소

**대상 밖** — §5.

### 1.3 정의 (Definitions)

| 용어 | 뜻 |
|---|---|
| **종단간(e2e)** | 서버를 **데몬 모드로** 띄우고 HTTP 표면을 실제로 두드리는 검증. 프로세스 경계를 넘는다 |
| **doctor** | `dongminal doctor`. 서버 **없이** 플랫폼 계층을 계층별로 in-process 로 실행하는 진단 |

### 2.2 진단

**D-1. 대상마다 다른 보증.** 위 표의 ✗ 는 전부 "그 대상에서 그 회귀를 잡을 수단이
없다" 는 뜻이다. 특히 직전 감사에서 바뀐 **자격증명 마스킹**과 **원격 이름 거부**는
git 표면의 동작 변경인데, 그 표면이 Linux·Windows 에서 한 번도 두드려지지 않는다.

**D-2. macOS 검증은 사람의 기억에 달려 있다.** CI 에 없으므로, 부르지 않으면
일어나지 않는다.

**D-3. 종단간이 두 벌이다.** bash 와 PowerShell 이 같은 5단계를 각각 적는다. 이
저장소가 반복해서 경계하는 "규칙을 두 벌로 두면 한쪽만 고쳐진다" 가 **검증 하네스
자체**에 적용된 자리다.

**D-4. 격리 가드가 한 벌뿐이다.** 운영 인스턴스를 죽인 사고를 막는 가드 3종은
`verify-isolated.sh` 에만 있다. CI 는 고정 포트 58147 을 쓰는 것으로 대신하는데,
그것은 가드가 아니라 우연이다.

### 2.3 이미 갖춰져 재사용 가능한 것

이 트랙이 새로 만들 것은 생각보다 적다.

| 필요한 것 | 이미 있는 것 |
|---|---|
| 임시 홈 + 빈 포트 | `resolveStartTarget` (`start.go`) — `MkdirTemp("dongminal-iso-")` + `FreePort()` |
| 데몬 모드 기동 | `startDetached` — 자기 자신을 `start --foreground` 로 끊어 띄운다 |
| ✅/❌ 보고 + 실패 재수집 + exit code | `doctorReport` (`doctor.go`) |
| 셸 준비 판정 | doctor 의 "출력이 오고 조용해지면 준비" (`doctorReadyWait`·`doctorQuietFor`) |
| 프로세스 종료 | `platform.Process.Terminate`/`Kill`/`Alive` |
| 소켓 존재 판정 | `platform.IPC.Exists` — **Windows 의 AF_UNIX 종단이 소켓 비트를 세우지 않는 차이를 이미 흡수한다.** 종단 이름도 `paned.sock` 로 세 OS 가 같다 |
| OS 분기 없는 전제 처리 | `internal/shared/testpath` 의 능력 질의 3종이 선례 |

즉 **셸 스크립트가 stdout 파싱으로 되찾던 값(PID·URL·격리 홈)을 Go 는 애초에 손에
쥐고 있다.** 파싱이 사라지는 것이 이 이관의 부수 이득이다.

## 3. 요구사항 (Requirements)

### 3.1 묶음 A — 진입점 (FR-E2C)

**FR-E2C-1** 서브커맨드 `dongminal verify` 를 신설한다. `Actions` 에 추가하고
`Usage`/`help` 에 싣는다.

**FR-E2C-2** `verify` 는 **격리 전용**이다. 격리를 끄는 수단을 제공하지 않는다.

**FR-E2C-3** `verify` 는 `--port`·`--home`(`Common` 의 두 옵션)을 **거부한다.**
받아서 무시하는 것이 아니라 오류로 끝낸다. 운영 인스턴스를 겨눌 방법 자체를 두지
않는 것이 사고를 막는 가장 단순한 형태다 (D-4).

**FR-E2C-4** `verify` 는 환경변수 `DONGMINAL_HOME`·`DONGMINAL_PORT` 를 **무시한다.**
CI 가 다른 목적으로 그 값을 세워 두어도 검사는 격리 홈·빈 포트에서 돈다. 띄우는
서버에도 격리 값을 명시적으로 넘긴다 (`withEnv` 가 이미 그렇게 한다).

**FR-E2C-5** `verify` 의 옵션은 다음뿐이다.

| 옵션 | 뜻 | 기본 |
|---|---|---|
| `--repo <경로>` | git 표면 검사의 대상 저장소 | 현재 작업 디렉터리 |
| `-h`/`--help` | 도움말 | — |

**FR-E2C-6** 종료 코드는 실패 0건이면 `0`, 1건 이상이면 `1` 이다. **건너뜀은 실패가
아니다** — 건너뛴 항목만 있고 실패가 없으면 `0` 이다.

**FR-E2C-7** `verify` 는 서버를 **데몬 모드로** 띄운다. `--foreground` 로 대신하지
않는다. 이 트랙이 잡으려는 결함이 정확히 "끊어 띄운 프로세스에서만" 났기 때문이다
(CROSS_PLATFORM_SRS §11.6).

### 3.2 묶음 B — 격리 가드 (FR-E2G)

`verify-isolated.sh` 의 가드를 Go 로 옮긴다. 옮기면 세 대상이 그 가드를 공유한다.

**FR-E2G-1** 기동 전, 정해진 대상이 다음을 **모두** 만족해야 한다. 하나라도
어긋나면 아무것도 띄우지 않고 즉시 중단한다.

1. 홈이 `dongminal-iso-` 를 이름에 포함하는 임시 디렉터리다
2. 홈이 사용자 기본 홈(`~/.dongminal`)이 **아니다**
3. 포트가 기본 포트(`dmenv.DefaultPort`, 58146)가 **아니다**

**FR-E2G-2** 가드를 통과하기 전에는 **어떤 프로세스도 종료하지 않고 어떤 디렉터리도
지우지 않는다.** 중단 시 정리 대상은 비어 있어야 한다.

**FR-E2G-3** 정리는 **우리가 띄운 것만** 겨눈다.

- 우리가 받은 서버 pid
- `<격리 홈>/paned.pid` 가 가리키는 데몬 pid

**FR-E2G-4** 정리에 `killPort`·`stop --all` 을 쓰지 않는다. `stop` 은 홈이 아니라
**포트**로 대상을 찾으므로, 그 경로를 쓰는 순간 기본 포트의 운영 인스턴스를 죽일
갈래가 생긴다. 실제로 그 사고가 났다 (`verify-isolated.sh` 머리말).

**FR-E2G-5** 종료는 `Process.Terminate` → 유예 → `Process.Alive` 확인 → 남으면
`Process.Kill` 순이다. OS 신호를 직접 다루지 않는다 (FR-XPL-5).

**FR-E2G-6** 격리 홈은 검사 뒤 지운다. 단 FR-E2G-1 의 이름 조건을 **지우기 직전에
다시 확인한다.** 삭제 실패는 경고이며 검사 실패로 치지 않는다 (R-2).

**FR-E2G-7** 검사 도중 어느 단계에서 중단되더라도 정리는 수행된다.

### 3.3 묶음 C — 검사 목록 (FR-E2K)

**FR-E2K-1** 검사 목록은 현행 세 하네스의 **합집합**이다. 아래가 그 전량이며, 세
대상이 **같은 목록**을 돈다.

|---|---|---|---|
| **기동 표면** ||||
| 1 | 서버 프로세스 생존 | `Process.Alive(pid)` | mac |

| 3 | `/api/ping` | 200 | 셋 다 |

| 7 | `/api/tools/output?id=&bytes=` | 200 | mac |
| 8 | **입력→출력 왕복** — `echo <마커>` 를 넣고 출력에서 마커를 본다 | 마커 등장 | CI |
| **워크스페이스·설정** ||||
| 9 | `/api/workspace` | 200 | mac |

**FR-E2K-2** 검사 8(왕복)은 **고정 대기를 쓰지 않는다.** doctor 가 쓰는 "출력이
오고 일정 시간 조용하면 준비된 것으로 본다" 규칙을 딛는다. CI 의 `sleep 3` 은
Linux 에서 플레이크를 냈고 그것을 준비 대기로 바꾼 이력이 있다 (`0279751`·`ff7ad5e`).

**FR-E2K-3** 검사 21 의 자산 목록을 **손으로 적지 않는다.** `index.html` 응답에서
`src` 를 뽑아 그 전량을 두드린다 — 적는 순간 `index.html` 과 갈라진다 (현행
스크립트의 주석이 밝히는 이유를 그대로 승계한다).

**FR-E2K-4** git 표면 검사의 대상은 **실제 git 저장소**여야 한다. 비-git 디렉터리는
`ErrNotRepo` 로 **정당하게** 404 를 내므로 라우팅 누락과 구별되지 않는다 — 그러면
그 검사는 아무것도 보증하지 않는다.

**FR-E2K-5** git 검사는 **상태 코드만** 본다. 응답 내용을 단언하지 않는다. CI 의
체크아웃은 얕은 클론·분리된 HEAD 일 수 있어 내용이 대상마다 다르다 (R-4).

**FR-E2K-6** 한 검사의 실패가 다음 검사를 막지 않는다. 한 번 띄운 인스턴스로 전부
훑는 것이 목적이다. 다만 **검사 4가 실패하면 5~8 은 선행 실패로 건너뛴다** —
id 가 없으면 물을 것이 없다.

### 3.4 묶음 D — OS 차이의 처리 순서 (FR-E2S)

**FR-E2S-0 (지배 조항)** OS 마다 갈리는 것은 **인터페이스 아래로 밀어 넣는다.**
검사 목록과 그 실행 로직은 대상이 무엇이든 **글자 그대로 같은 코드**여야 한다.

처리 순서는 다음이며, 위에서부터 소진한다.

1. **`platform` 인터페이스가 흡수한다.** 호출부는 같은 함수를 부르고 같은 뜻의
   값을 받는다. 차이는 구현 안에만 있다
2. 인터페이스로 흡수할 수 없는 **호스트 환경**의 차이만 능력 질의로 건너뛴다
3. **OS 이름으로는 어떤 경우에도 가르지 않는다** (FR-XBD-3·FR-XPL-3)

**흡수의 본보기**: `paned.sock` 존재 판정. POSIX 는 소켓 비트를 보지만 Windows 의
AF_UNIX 종단은 재분석 지점으로 나타나 그 비트가 서지 않는다. 호출부는 그 사실을
모른 채 `IPC.Exists(endpoint)` 하나를 부르고, 차이는 `unixSocketIPC.isSocket` 주입
안에서 끝난다. **검사도 테스트도 한 벌이 된다** — 이것이 이 트랙이 따르는 형태다.

**FR-E2S-1** 어떤 검사가 대상별 분기를 **필요로 한다면, 그것은 `platform` 인터페이스가
덜 흡수했다는 신호다.** 검사 쪽에 갈래를 만들지 말고 인터페이스를 넓히거나 새
이음매를 세운다. 검사에 갈래를 넣는 것은 이 조항을 소진한 뒤의 최후 수단이다.

**FR-E2S-2** §3.3 의 22항목은 **OS 를 근거로 건너뛰는 항목을 하나도 갖지 않는다.**
실측 결과다 — HTTP 표면·정적 자산·git 은 OS 무관이고, 유일하게 갈릴 뻔한 소켓
검사는 위처럼 이미 흡수돼 있다. 이 조항은 회귀 게이트다: 이관 뒤 OS 를 근거로 한
건너뜀이 생기면 그것은 인터페이스가 후퇴했다는 뜻이므로 결함으로 다룬다.

**FR-E2S-3** 남는 능력 질의는 **호스트 환경**뿐이며 현 시점에 다음 둘이다.

| 능력 | 물음 | 성격 | 걸리는 검사 |
|---|---|---|---|
| `gitRepo(dir)` | 이 디렉터리가 git 저장소인가 | 환경 | 12~18 중 `repo` 인자를 받는 것 |
| `gitBinary()` | `git` 이 PATH 에 있는가 | 환경 | 위와 같음 |

둘 다 **OS 가 아니라 그 호스트가 무엇을 갖췄는지**를 묻는다. `/api/git/policy`·
`/api/git/jobs` 는 `repo` 인자가 없으므로 항상 돈다.

**FR-E2S-4** 건너뛴 검사는 **보고서에 남긴다** — `⏭` 와 이유를 함께 적고 요약에
건수를 따로 센다. 침묵으로 빠지지 않는다 (FR-WTP-31 의 취지: 빠진 줄 모르는 보증이
늘어나는 것을 막는다).

**FR-E2S-5** 능력 질의는 한 자리에 모으고 검사 정의가 그것을 참조한다. 주입 가능한
형태로 두어 단위테스트가 양쪽 갈래를 **모든 대상에서** 본다.

### 3.5 묶음 E — 보고 (FR-E2R)

**FR-E2R-1** 보고 형식은 doctor 와 **같은 한 벌**을 쓴다. `doctorReport` 를
`internal/ctl/cli` 안의 공용 보고자로 올리고 doctor·verify 가 함께 딛는다.
형식을 두 벌로 두면 이 문서가 지적한 D-3 을 새로 만드는 것이 된다.

**FR-E2R-2** 공용 보고자는 `ok`·`info`·`bad` 에 더해 **`skip(이유)`** 을 갖는다.

**FR-E2R-3** 보고서 끝에 실패 줄을 다시 모아 찍는다. doctor 가 이미 그렇게 하는
이유(보고서가 길어 앞부분이 잘린 채 전달된 사례)가 verify 에도 그대로 적용된다.

**FR-E2R-4** 요약은 `통과 N건 / 실패 M건 / 건너뜀 K건` 이다.

**FR-E2R-5** 검사가 실패하면 **데몬 로그 꼬리**를 함께 찍는다. CI 인라인 블록이
실패 시 `daemon.log` 를 40줄 찍던 동작을 승계한다.

**FR-E2R-6** 가드 통과 직후 대상을 한 줄로 남긴다 — url·홈·pid. 무엇을 겨눴는지
로그만 보고 알 수 있어야 한다.

### 3.6 묶음 F — 통합과 철거 (FR-E2I)

**FR-E2I-1** `verify.yml` 의 `windows-runtime`·`linux-runtime` 두 잡에서
「종단간」 인라인 블록을 `dongminal verify` 호출로 교체한다. **bash·PowerShell
종단간 스크립트는 사라진다.**

**FR-E2I-2** 두 잡의 「정리」 단계를 제거한다. verify 가 스스로 치운다 (FR-E2G-3·6).

**FR-E2I-3** 두 잡의 「doctor」 단계는 **유지한다.** doctor 와 verify 는 겹치지
않는다 (§5-2).

**FR-E2I-4** `scripts/verify-isolated.sh` 를 `go build` + `dongminal verify` 를
부르는 껍데기로 축소한다. 이름은 유지한다 — 개발자가 기억하는 진입점이고 문서
여러 곳이 그것을 가리킨다.

**FR-E2I-5** macOS 는 CI 에 추가하지 않는다 (사용자 결정). 개발자가 로컬에서
FR-E2I-4 의 껍데기로 **같은 목록**을 돈다.

**FR-E2I-6** 이관 뒤 검사 항목 수는 대상별로 같아야 한다. 이 문서 §4.2 의 회귀
게이트가 그것을 확인한다.

### 3.7 비기능 요구 (NFR)

**NFR-E2E-1** 새 외부 의존을 추가하지 않는다. 표준 라이브러리와 이미 있는
`x/sys`·`creack/pty`·`gorilla/websocket` 뿐이다. `go` 지시자를 올리지 않는다.

**NFR-E2E-2** `verify` 한 회 실행은 **CI 기준 90초 이내**에 끝난다. 현행 두 잡의
종단간 단계가 그 안에 끝나므로 예산은 같다.

**NFR-E2E-3** `verify` 는 `internal/ctl/cli` 안에 산다. `platform` 을 직접 딛되
OS 이름으로 갈라지지 않는다 (`scripts/check-seams.sh` 통과).

**NFR-E2E-4** 검사 정의는 **데이터로** 적는다 — 각 항목이 이름·기대·경로·능력 조건을
갖는 표. 절차로 흩어 적으면 목록을 세는 일(FR-E2I-6)이 불가능해진다.

**NFR-E2E-5** `verify` 는 프로덕션 경로에 테스트 전용 갈래를 만들지 않는다. 서버·
데몬은 평소와 **똑같이** 뜬다.

### 3.8 제약 (Constraints)

**C-1** Windows·Linux 의 실동작은 **CI 로만** 확인된다. 개발 호스트는 darwin 이다.

**C-2** `gh` 계정은 이 저장소에 READ 권한뿐이다. run 취소·재실행은 불가하고 로그
조회만 된다. 검증 주기는 "푸시 → 5~8분 대기 → 로그" 다.

**C-3** CI 러너의 체크아웃은 git 저장소이지만 얕을 수 있다 (FR-E2K-5).

## 5. 비목표 (Non-Goals)

1. **macOS 를 CI 에 추가하는 것** — 사용자 결정. 로컬에서 같은 목록을 돈다.
2. **doctor 와 verify 의 통합** — 갈라 둔다. doctor 는 **서버 없이** 도는 것이 존재
   이유다. 셸을 방정식에서 뺀 그 한 걸음이 ConPTY 의 원인을 좁혔다
   (CROSS_PLATFORM_SRS §11.5). 서버를 요구하는 순간 그 값어치가 사라진다.
   반대로 verify 는 데몬 모드가 전제다. 합치면 한쪽이 다른 쪽을 못 돌게 된다.
3. **브라우저 e2e(Playwright)** — 현행 어느 하네스도 하지 않는다. 별도 트랙.
4. **git 쓰기 계열 검사** (`fetch`·`pull`·`push`) — 네트워크와 자격증명이 필요하다.
   읽기 표면만 본다 (현행과 같다).
5. **응답 내용 단언** — 상태 코드만 본다 (FR-E2K-5).
6. **`verify` 를 사용자용 기능으로 다듬는 것** — 개발자·CI 하네스다.

## 6. 구현 계획 (Implementation Plan)

각 단계 끝에서 빌드·테스트가 통과해야 한다.

**1단계 — 보고자 공용화 (FR-E2R-1,2)**
`doctorReport` 를 `report.go` 로 옮기고 `skip` 을 더한다. doctor 의 동작은 무변경.
회귀 게이트: 기존 테스트 전량 + darwin doctor 실행.

**2단계 — 옵션·진입점 (FR-E2C)**
`VerifyOpts`·`ParseVerify`·`Actions`·`Usage`. 아직 검사는 비어 있다.
테스트: 옵션 거부·도움말.

**3단계 — 격리 가드 (FR-E2G-1,2,6)**
가드 판정을 순수 함수로 분리하고 단위테스트로 위험 조합을 전부 막는다.
**프로세스를 띄우기 전에 이 단계를 끝낸다** — 순서가 안전의 일부다.

**4단계 — 기동·정리 (FR-E2C-7, FR-E2G-3,4,5,7)**
격리 인스턴스를 띄우고 pid·url·홈을 손에 쥔다. stdout 파싱 없이.

**5단계 — 검사 표와 실행기 (FR-E2K, NFR-E2E-4)**
22항목을 데이터로 적고 순서대로 돈다. 항목 수·이름을 골든 테스트로 고정한다.

**6단계 — 능력 질의와 건너뛰기 (FR-E2S)**
git 능력 질의 둘. 주입 가능한 형태로 두어 단위테스트가 양쪽 갈래를 본다.

**7단계 — darwin 실동작**
`scripts/verify-isolated.sh` 의 21항목과 새 verify 의 결과를 **나란히 대조한다.**
이관 무결성의 실증이다. 이 대조가 끝난 뒤에 8단계로 간다.

**8단계 — CI·스크립트 이관 (FR-E2I)**
워크플로우 두 블록 교체, 정리 단계 제거, 스크립트 축소. 푸시 → CI 확인.

**9단계 — 문서**
`CROSS_PLATFORM_HANDOFF.md` §3 을 닫고, 이 문서에 §10 구현 결과를 적는다.

| | 리스크 | 대응 |
|---|---|---|
| **R-1** | Windows 의 셸 준비 시간이 달라 왕복(검사 8)이 플레이크 | 고정 대기 금지(FR-E2K-2). doctor 의 "조용해질 때까지" 규칙 재사용. 같은 플레이크를 이미 그렇게 고친 이력이 있다 |

| **R-4** | CI 체크아웃 상태 때문에 git 응답이 대상마다 다르다 | 상태 코드만 본다 (FR-E2K-5) |

| **R-6** | Linux·Windows 에서 git 표면이 **처음** 돌면서 새 실패가 드러난다 | 그것이 이 트랙의 목적이다. 드러나면 결함으로 다룬다 — 검사를 무르지 않는다 |

**R-6 은 리스크이자 기대 효과다.** git 표면 8종이 두 대상에서 한 번도 돈 적이
없으므로, 처음 돌 때 실패가 나올 가능성이 실재한다. 그 경우 이 트랙의 범위는
"검사를 세우는 것" 이고, 드러난 결함은 별건으로 기록한 뒤 고친다.

## 9. 구현 결과 (Implementation Outcome)

### 9.1 최종 상태

`dongminal verify` 가 신설됐고 **세 대상이 같은 22항목을 돈다.**

| 대상 | 수단 | 어디서 | 결과 |
|---|---|---|---|
| macOS | `scripts/verify-isolated.sh` → `dongminal verify` | 로컬 | ✅ 22/22 |
| Linux | `dongminal verify` | CI | CI 확인 |
| Windows | `dongminal verify` | CI | CI 확인 |

이관 무결성은 **나란한 대조**로 실증했다 (§6 7단계). 구 `verify-isolated.sh` 21항목이
전부 통과하는 상태에서 새 verify 를 돌려, 21항목이 모두 새 목록에 대응하고 CI 의
왕복 하나가 더해져 22 임을 확인했다. 정적 자산 수도 양쪽 모두 **49개**로 같았다.

### 9.2 규모 변화

| 대상 | 이전 | 이후 |
|---|---|---|
| `.github/workflows/verify.yml` | 190줄 | 96줄 |
| `scripts/verify-isolated.sh` | 196줄 | 23줄 |

### 9.3 스펙 대비 정정

**정정 1 — 능력 질의가 git 을 직접 실행할 수 없다.**
초안의 `probeCaps` 는 `exec.Command("git", ...)` 로 저장소를 판정했다.
`TestNoDirectGitExecOutsidePackage` 가 이를 잡았다 — git 실행은
`webserver/domain/git` 안에서만 한다 (FR-GIT-1).

`core.New().RepoRoot(ctx, repo)` 로 바꿨다. 결과적으로 더 낫다: **서버가 쓰는 바로
그 판정**을 딛으므로 "저장소인가" 의 답이 검사와 서버에서 갈리지 않는다. 갈렸다면
정당한 404 를 결함으로 읽거나 그 반대가 됐을 것이다 (FR-E2K-4). `ErrGitMissing` 이
git 부재까지 한 번에 답해 `LookPath` 도 필요 없어졌다.

**정정 2 — 검사가 상세를 낼 자리가 필요했다.**
초안의 `Run` 은 `error` 만 냈다. 그러면 구 스크립트가 찍던
`script 49개 전량 200` 의 **수가 사라진다** — 자산이 49개에서 3개로 줄어도 전량
200 이면 검사는 조용히 통과한다. `Run` 을 `(string, error)` 로 바꿔 통과 시 상세를
함께 남긴다. 도구 id 와 왕복 바이트 수도 같은 자리에 실린다.

**정정 3 — 서버 로그를 격리 홈 안에 둔다.**
`prepareServerCmd` 가 `$DONGMINAL_LOG` 또는 기본 로그 자리를 쓰므로, 그대로 두면
verify 의 서버 로그가 운영 인스턴스의 로그에 섞인다. `logPath` 를 인자로 받게 하고
verify 는 `<격리 홈>/server.log` 를 준다. `start` 는 `""` 를 넘겨 종전과 같다.

### 9.4 스펙에 없었던 발견

**왕복은 표시를 두 번 봐야 한다.** 입력한 `echo <표시>` 는 셸에 **에코**되어 화면에
한 번 그려진다. 한 번만 보고 통과시키면 셸이 명령을 실행하지 않아도 통과한다 —
검사가 보증하려던 것이 정확히 "실행됐는가" 인데 그것을 놓친다. 현행 CI 의
PowerShell·bash 블록은 `-match` / `grep -q` 로 **한 번만** 봤다. 즉 종전 CI 의
왕복 검사는 에코만으로도 통과할 수 있었다.

**리터럴 셋이 가드의 전제였다.** `dongminal-iso-`(start.go)와 `.dongminal`
(options.go·main.go)이 흩어져 있었다. 가드는 그 값과의 **일치**로 판정하므로,
만드는 쪽만 바뀌면 가드가 조용히 무력해진다. `isolatedHomePrefix`(cli)와
`dmenv.DefaultHomeDir` 로 묶고,
`TestGuardIsolated_AcceptsWhatResolveStartTargetMakes` 가 그 일치를 붙든다.

### 9.5 남은 위험

- **R-6 이 아직 열려 있다.** git 읽기 표면 8종이 Linux·Windows 에서 **처음** 돈다.
  darwin 에서는 전부 통과하지만 두 대상의 결과는 CI 가 답한다
- `prepareServerCmd` 추출로 `start` 의 기동 경로가 바뀌었다. 문구와 순서는
  보존했으나(로그 열기 실패 시의 출력 순서 포함) 실동작 회귀는 CI 가 확인한다
