## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

`/api/file/{read,write,raw,probe}` 는 절대경로면 **어디든** 연다. 가드가 없는 것은
사고가 아니라 명시된 설계다 (`handlers_fs.go:22-25`):

> 경로 가드가 `/api/fs/{read,write}` 와 **다르다.** 저쪽은 절대경로인지만 보고 그 위의
> 상한이 없는데, 그것은 **사용자가 경로를 이미 알고 지목한 읽기·쓰기**이기 때문이다.

그 전제가 성립하는 상대는 **대화형 사용자**다. 그리고 `ACCESS_ALLOWLIST_SRS`
`FR-ACL-21` 이 "PTY 가 이미 전권이므로 같다" 로 그것을 정당화했다.

**브라우저 매개 공격자에게는 성립하지 않는다.** 그쪽에게 이 종단은 PTY 보다 훨씬 쉬운
경로다 — 응답을 읽을 필요조차 없는 `write` 한 번으로 `~/.zshrc` 나
`~/.ssh/authorized_keys` 를 덮으면 다음 셸 기동이 곧 RCE 다.

`REQUEST_GATE_SRS` 가 그 경로의 **호출**을 닫는다. 이 문서는 **닿는 범위**를 닫는다.
게이트 하나에 전부 걸면, 게이트가 언젠가 새는 날 파일시스템 전체가 함께 샌다.

그리고 이 종단에는 **단위 테스트가 0건**이다 (`05-test.md` §1 의 P0). 편집기의 저장이
이 경로이므로, 여기서 잘리는 것은 우리 상태 파일이 아니라 **사용자가 쓰던 원본**이다.

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 두 계층이 나란히 있고 가드가 한쪽에만 있다

| 계층 | 가드 | 근거 |
|---|---|---|
| `/api/fs/*` (탐색기) | **있다** — `fsRoot` 가 클라이언트의 `root` 를 `Entries.Roots()` 와 대조하고(`handlers_fs.go:109-135`), `fsResolveExisting`/`fsResolveTarget` 이 `EvalSymlinks` 뒤 조각 단위로 본다 | 양호 판정 |
| `/api/file/*` (편집기 저장·읽기) | **없다** — `filepath.IsAbs` 하나 (`handlers_files.go:379`) | 이 문서 |

`/api/fs/*` 의 가드는 **재사용할 원형이 이미 있다**는 뜻이다. 새로 설계하지 않는다.

### 2.2 `apiFileWrite` 의 전량

```go
body, _ := io.ReadAll(r.Body)          // 상한 없음 → REQUEST_GATE_SRS FR-RQG-14
json.Unmarshal(body, &req)
if req.Path == "" { 400 }
if !filepath.IsAbs(req.Path) { 400 }
platform.WriteFileAtomic(req.Path, []byte(req.Content), 0o644)   // ← 어디든
```

`WriteFileAtomic` 자체는 옳다 (FR-CAF-11 — 사용자 원본을 잘리지 않게 쓴다). 문제는 그
위에 경계가 없다는 것뿐이다.

### 2.3 `FR-ACL-21` 의 논거가 절반만 맞다

"PTY 가 이미 전권이므로 파일 API 를 제한해도 의미가 없다" 는 **대화형 사용자**에 대해
참이다. 그 사용자는 터미널에서 무엇이든 할 수 있다.

**브라우저 매개 공격자에 대해서는 거짓이다.** PTY 를 쓰려면 WebSocket 을 열고 프레임
규약을 따라 명령을 타이핑하고 출력을 읽어야 한다. `POST /api/file/write` 는 요청 하나이며
**응답을 읽을 필요가 없다.** 난이도가 다르면 같은 위험이 아니다.

그러므로 이 문서는 `FR-ACL-21` 을 폐기하지 않고 **적용 대상을 좁힌다**(§6).

### 2.4 루트를 아는 자리가 이미 있다

`Entries.Roots()`(`wsentry.go:146`)가 Editor 목록의 루트를 준다. `Home()`·`Notes()`·
`Plugins()` 도 있다. 도구의 작업 폴더는 `ToolManager.Cwd(id)`(`manager_hub.go:38`).

**새 상태를 만들지 않는다.**

### 2.5 읽기에 크기 상한이 없다

`apiFileRead`(`handlers_files.go:325`)가 절대경로면 그대로 `os.Open` 하고 전량을 응답에
싣는다. 클라이언트 쪽도 짝이 없다 — 편집기가 `probe.size` 를 받고도 전체를 Monaco 에
올린다 (`FUI-06`).

### 2.6 테스트가 0건이다

`apiFileWrite` 의 함수 커버리지가 0.0% 다. 편집기 저장 경로 전체가 검사 밖이다.

### 2.7 제약 (Constraints)

- **`/api/fs/*` 의 가드를 건드리지 않는다.** 양호 판정이며 이 문서의 비목표다.
- 새 런타임 의존을 넣지 않는다.
- `WriteFileAtomic` 의 원자성을 바꾸지 않는다.
- 오류 봉투를 바꾸지 않는다 — `/api/file/*` 는 단문 `{error}` 방언이다
  (`architecture.md:141-176` 의 공개 계약).

## 3. 요구사항 (Requirements)

### 3.1 묶음 B — 경계

**FR-FAB-1** `/api/file/{read,write,raw,probe}` 는 대상 경로가 **허용 루트 아래**일 때만
동작한다. 밖이면 **403** 이고 본문에 루트 목록을 싣지 않는다.

**FR-FAB-2 (허용 루트)** 다음의 합집합이다. 전부 서버가 이미 아는 값이며 새 상태를
만들지 않는다 (§2.4).

| 루트 | 출처 | 왜 |
|---|---|---|
| Editor 목록의 루트들 | `Entries.Roots()` | 편집기의 저장이 이 종단이다 — 여는 것이 곧 여기다 |
| 살아 있는 도구들의 `cwd` | `ToolManager.Cwd(id)` | 터미널에서 `edit <파일>` 로 여는 자리 |
| Notes · Plugins 디렉터리 | `Entries.Notes()`·`Plugins()` | 제품이 스스로 쓰는 자리 |
| `$DONGMINAL_HOME` | `dmenv` | 설정·워크스페이스. 자기 상태다 |

**홈 디렉터리 전체는 루트가 아니다.** `~` 를 넣으면 `~/.ssh`·`~/.aws` 가 다시 들어오고,
그것이 이 문서가 막으려는 바로 그 경로다.

**FR-FAB-3 (대조 방법)** `/api/fs/*` 의 것을 **재사용한다** — 읽기는
`fsResolveExisting`(전량 `EvalSymlinks`), 쓰기는 `fsResolveTarget`(부모만 풀고 마지막
조각은 그대로). 두 벌을 만들지 않는다.

근거: 마지막 조각을 따라가지 않는 덕에 링크 자체를 지우거나 옮길 수 있고, 중간
디렉터리가 링크여서 루트를 벗어나는 경우는 걸린다 (`FR-EDT-112`).

**FR-FAB-4** 루트 목록은 요청마다 다시 읽는다. 도구를 새로 열거나 Editor 를 추가한
직후에 그 자리가 막혀 있으면 사용자는 제품이 고장 났다고 읽는다.

### 3.2 묶음 O — 넓힘

**FR-FAB-5** 허용 루트 밖을 켜는 길이 하나 있다: 설정의 `fileApiUnrestricted`(기본
**거짓**). 참이면 종전 동작(절대경로면 어디든)으로 돌아간다.

**FR-FAB-6** 그 설정이 참이면 기동 로그에 남긴다. 조용히 열려 있으면 안 된다.

**FR-FAB-7** 노출 모드(`--expose`)에서는 이 설정이 참이어도 **무시하고 제한한다.**
LAN 에 열린 서버에서 파일시스템 전체를 여는 조합은 사용자가 의도했다고 보기 어렵다.

### 3.3 묶음 S — 크기

**FR-FAB-8** `apiFileRead`·`apiFileRaw` 에 상한을 둔다. 넘으면 **413** 이고 응답에
실제 크기를 실어 클라이언트가 안내를 만들 수 있게 한다.

**FR-FAB-9 (클라이언트 짝, `FUI-06`)** 편집기는 `probe.size` 가 그 상한을 넘으면 Monaco 에
올리지 않고 사유를 보인다. **서버와 같은 값**을 쓴다 — 두 벌이면 한쪽만 고쳐지고, 그때
사용자는 "열린다고 했는데 안 열린다" 를 만난다.

### 3.4 묶음 T — 테스트

**FR-FAB-10** `handlers_files_test.go` 에 다섯이 선다. `05-test.md` §1 이 지목한 목록
그대로다.

| # | 확인 |
|---|---|
| 1 | 정상 쓰기 → `{"ok":true}` |
| 2 | 상대경로 → 400 |
| 3 | 빈 `path` → 400 |
| 4 | 쓰기 실패 → 500 |
| 5 | **허용 루트 밖 절대경로 → 403** |

### 3.5 비기능 요구 (NFR)

**NFR-FAB-1** 대조는 요청당 `EvalSymlinks` 몇 번이다. 루트 목록은 `Entries` 의 캐시를
읽는다 — 디스크를 다시 읽지 않는다.

**NFR-FAB-2** `-race` 통과. 도구 목록은 `ToolManager` 의 잠금 아래에서만 읽는다.

**NFR-FAB-3** 루트 목록을 읽지 못하면 **fail-closed** 다. 읽기 실패로 전부 열리면 그
실패가 곧 우회 경로가 된다.

## 5. 비목표 (Non-goals)

1. **`/api/fs/*` 의 가드 변경.** 양호 판정이다. 이 문서는 그 코드를 **재사용**하지
   수정하지 않는다.
2. **`/api/upload`·`/api/download` 의 경계.** 같은 계층이지만 업로드는 이미
   `MaxBytesReader` 를 갖고 있고 경계 도입은 전송 UX 를 함께 바꾼다. M8 로 넘긴다.
   **그때까지 `REQUEST_GATE_SRS` 의 게이트가 그 경로의 호출을 덮는다.**
3. **파일 권한 모델·소유자 검사.** 멀티유저 미지원 선언(확정 결정 7)의 범위다.
4. **`WriteFileAtomic` 재설계.** 실제 사고에서 배운 방어다.
5. **오류 봉투 변경.** `architecture.md` 의 공개 계약.
6. **샌드박스 경로 정책.** `SANDBOX_WINDOW_SRS` 의 것이며 독립이다.

## 6. 기존 문서 개정

**`ACCESS_ALLOWLIST_SRS` FR-ACL-21** — "PTY 가 이미 전권이므로 파일 API 를 제한해도
의미가 없다". 적용 대상을 **대화형 사용자**로 좁히는 단서를 단다. 브라우저 매개
공격자에게는 난이도가 다르고, 난이도가 다르면 같은 위험이 아니다 (§2.3).

**`handlers_fs.go:22-25` 의 주석** — "저쪽은 절대경로인지만 보고 그 위의 상한이 없다" 가
더는 사실이 아니게 된다. 두 계층의 차이를 다시 적는다: 이제 둘 다 루트를 대조하고,
다른 것은 **루트를 고르는 방법**이다(`fs` 는 클라이언트가 보낸 `root` 를 대조, `file` 은
서버가 목록을 만든다).
