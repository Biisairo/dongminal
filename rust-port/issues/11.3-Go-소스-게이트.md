### 한 것

G-15~G-28 의 게이트 14개를 Rust 소스로 옮겼다. 파일 이름·통과 줄 형식·실패 머리 줄·종료 코드는 Go 판과 같다. 바뀐 낱말은 Go 이름이 Rust 이름이 된 것뿐이다(DIFF-GRM-2). 모든 게이트에 빈 통과 막기(원천 0개 → 종료 1)를 넣었다.

| 게이트 | Rust 판 원천·규칙 | 통과 줄(지금) |

공용 도우미 `scripts/lib/`: `rs-test-files.pl`(시험 전용 파일과 인라인 `#[cfg(test)] mod {}` 줄 범위 — Go `_test.go` 자리), `rs-src.sh`(`rs_drop_tests`·`rs_src_files`), `rs-calls.pl`(여러 줄 호출을 한 줄로), `rs-fn-body.pl`(함수 본문), `rs-const.pl`(문자열 상수를 값으로), `rs-home-sites.pl`.

G-56: `architecture.md` 패키지 표의 `cmd/`·`internal/` 트리를 `rust/` crate 트리로 바꿨다(gocompat·web·scripts·parity 추가, runtime 의 자산은 `assets/` 아래, sysstat·decidx·errdoc 줄의 Go 문구 고침, pkg-axis 설명 문단 고침). 루트 `scripts/` 아래 Go 생성기 네 줄은 R10 이 지울 때 표에서도 빼야 한다.

조정자 지시로 `dm-shared-platform` `ipc/sys_unix.rs` 의 timeval 을 `as _` 로 채웠다(커밋 `3cc5dec6`, port(1.4)). 7개 대상 clippy·platform 시험 246개 통과.

### 수락 시험(V-GRM-9) 기록

- ① 그대로: 13개 게이트(cross 제외) 종료 0 — PATH 에서 go 를 뺀 격리 실행, 그리고 `internal/`·`cmd/`·`go.mod` 를 지운 트리에서 각각 확인. cross 는 다섯 대상 ✅(병합 전후 두 번).
- ② 위반 심기: 게이트마다 한 건을 심어 실패 머리 줄과 종료 1 을 확인(pkg-axis 는 ALLOW 하나를 빼서, gitwrite 는 파이프라인을 열지 않는 POST 를 더해서, home-layout 은 표에 없는 조각·표에서 뺀 항목, activity 는 값 바꿈 등). 심은 것은 모두 되돌렸다.
- ③ 원천 비우기: 빈 rust/crates 트리에서 각 게이트가 종료 1.
- 자동 시험 파일은 따로 만들지 않았다 — 위 ①②③ 은 손으로 돌린 기록이다.

### Go 와 다르게 한 결정·남은 위험

- 실패 목록의 줄 모양: http-error 처럼 호출을 읽는 게이트는 Go 의 `파일:줄:원문` 대신 `파일:줄: 함수(인자)` 로 낸다(rustfmt 가 인자를 여러 줄로 나누기 때문).
- 한국어 `http_err` 본문은 Rust 에서 6곳(Go 9). sandbox 두 곳이 상수 하나로, kill 셋이 둘로 합쳐졌고 `focus registry 없음` 은 Rust 에 없다. 동결 상한 9 는 그대로 뒀다(줄어드는 것은 허용) — SRS 의 "9 가 아니면 플래그" 에 따라 알린다.
- Rust 제품 코드가 규칙을 비껴간 자리를 예외 표로 올렸다(Q-GRM-8): seams 6, http-error 3, body-limit 4, agent-names 2, server-target 2, home-layout 1. 가장 고칠 만한 것은 agent-names 의 `runtimebin/src/shim.rs` `"claude"` 리터럴(Go 는 클로저로 이름을 붙잡았다).
- check-cross 는 이 Mac 에서 ring 을 C 툴체인 없이 검사하는 cross-check.sh 방식에 기댄다. CI 러너에서 clang·llvm-tools 가 있어야 한다(R7).
- Makefile 의 단계 제목(`활동 상태 어휘 (Go 와 JS …)` 등)은 R6(11.6) 의 몫이라 고치지 않았다.
- 게이트가 이제 `cargo`·`node`·`perl` 을 쓴다. CI gates job 에 Rust 툴체인이 필요하다(R7).
