# SRS: Telegram 알림 — 에이전트 알람을 휴대폰으로 받기 — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: TC-TGB-90(실기기). 서버를 다시 빌드·재시작한 뒤 휴대폰으로 확인한다
> **개정**: 2026-11-12 개정 2 — 양방향 브리지에서 알림 전용으로 바꿨다(§9).
> **입력**: 2026-11-12 대화. 사용자 결정은 §4 에 적는다. 실측 결과는 §2 에 적는다.
> **실험 기능**: 사용자는 "해 보고 안 되면 지운다" 고 했다. 그래서 이 기능은 설정에서 끄면 없는 것과 같아야 한다(NFR-TGB-1). 걷어 낼 때 지울 범위도 그 경계와 같다.

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

사용자는 PC 에서 에이전트에게 일을 시킨 뒤 자리를 비운다. 이 SRS 는 그때 PC 알람과 같은 순간에 휴대폰(Telegram)으로 알림을 보낸다. 알림에는 무슨 일인지(완료·오류·질문·권한 요청·입력 대기), 어디인지(기기 › 윈도우 › 탭), 내용(접힌 문단)을 싣는다.

Telegram 은 **보기 전용**이다. Telegram 에서 에이전트를 조작하지 않는다. PC 의 Claude Code 는 이 기능이 있는지 모른다.

### 1.2 범위 (Scope)

**포함**
- 설정: 켜기·끄기, 봇 token, 허용 계정 등록(짝맞춤 코드), PC 입력 후 무음 시간
- PC 알람이 울릴 때 허용 계정과의 1:1 대화방에 알림 메시지 하나를 보낸다

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|---|---|
| **브리지** | 이 기능 전체. 서버 프로세스 안에서 돈다 |
| **PC 알람** | 서버가 브라우저로 보내는 `tool_attention` 신호. 사유는 `done`(턴 끝남) 또는 `waiting`(사람을 기다림)이다 |
| **알림** | 이 SRS 가 Telegram 으로 보내는 메시지 하나 |
| **허용 계정** | 짝맞춤으로 등록한 Telegram 사용자 하나(`from.id`). 1:1 대화방의 `chat_id` 와 같다 |
| **위치** | `기기 이름 › 윈도우 이름 › 탭 이름` |
| **기기 이름** | 설정 Display ▸ 페이지 제목(`pageTitle`). 비어 있으면 OS 호스트 이름 |
| **접힌 문단** | Telegram HTML `<blockquote expandable>`. 처음에는 몇 줄만 보이고 누르면 펼쳐진다 |
| **무음 시간** | PC 브라우저에서 그 탭에 입력한 뒤 알림을 소리 없이 보내는 시간 |

## 2. 현황과 실측 (Identified Facts)

### 2.1 Telegram

| 항목 | 결과 |
|---|---|
| 봇 하나의 `getUpdates` | 한 곳에서만 받을 수 있다. 두 곳이 같은 token 으로 받으면 `409 Conflict` 다. 그래서 PC 한 대에 봇 하나다(D-TGB-15) |
| 읽음 표시 | Bot API 에는 없다 |
| Threaded Mode(DM 토픽) | 켜 두면 사용자가 일반 대화창에 쓴 글로 Telegram 앱이 토픽을 새로 만든다. 이 SRS 는 토픽을 쓰지 않으므로 켤 필요가 없다 |
| 링크 버튼의 MagicDNS 짧은 이름 | `http://macmini-office:58146/` 은 "Wrong HTTP URL" 로 거절된다(2026-11-12) |
| Mini App 주소 | HTTPS 만 받는다 |

### 2.2 Claude Code hook (dongminal 이 이미 거는 것)

모두 보고만 하고 끝난다. PC 의 Claude Code 를 막지 않는다.

| hook | 실린 값 | 브리지에 쓰는 곳 |
|---|---|---|
| `PermissionRequest` | `tool_name`, `tool_input` 전체 | 권한 요청·질문 알림의 내용 |
| `PreToolUse`(AskUserQuestion) | `questions[].question·header·options[].label·description` | 질문 알림의 내용 |
| `Stop` | 턴 끝 | 완료 판정 |
| `StopFailure` | `error`(`rate_limit` 등) | 오류 판정과 내용 |
| `Notification` | `message` | 입력 대기 알림의 내용 |
| 모든 hook | `transcript_path` | 완료 알림의 마지막 응답 |

hook 보고는 같은 요청 안에서 PC 알람보다 먼저 브리지 큐에 들어간다(`handlers_attention.go` 의 `telegramActivity` → `ReportActivity`). 그래서 알람을 처리할 때 그 알람을 낳은 hook 을 이미 알고 있다.

### 2.3 transcript

transcript JSONL 에는 응답 글·도구 호출·도구 결과 말고도 시스템 프롬프트와 사용자 이메일이 든 내부 줄(`api-request-blob` 등)이 섞여 있다. 마지막 응답은 `assistant` 줄의 `text` 블록만 골라 읽는다.

## 3. 요구 (Requirements)

### 3.1 설정

- **FR-TGB-1** 설정 창에 Telegram 항목을 둔다. 항목은 켜기·끄기, 봇 token, 허용 계정(등록·해제), 무음 시간(분, 기본 5, 0 이면 무음 없음)이다.
- **FR-TGB-2** 설정은 전용 파일 `~/.dongminal/telegram.json`(권한 600)에 둔다. 일반 설정(`settings.json`)에는 두지 않는다. 일반 설정은 모든 브라우저에 내려가기 때문이다.
- **FR-TGB-3** token 은 쓰기 전용이다. API 응답·SSE·로그에는 token 을 싣지 않는다. 화면은 "설정됨" 과 봇 이름(`getMe.username`)만 보인다.
- **FR-TGB-4** token 을 저장하면 서버가 `getMe` 로 확인한다. 실패하면 저장을 거절하고 이유를 보인다. (개정 2: 토픽 기능 확인을 뺐다)
- **FR-TGB-5** token 을 바꾸면 허용 계정을 지운다.

### 3.2 허용 계정 (짝맞춤)

- **FR-TGB-10** 설정 창의 "등록" 은 6자리 코드를 만든다. 코드는 10분 동안 한 번만 쓴다.
- **FR-TGB-10a** 틀린 시도가 5번이면 그 코드를 폐기한다. 실패는 서버 로그에 남긴다.
- **FR-TGB-11** 봇이 `/pair <코드>` 를 받으면 코드를 확인하고 보낸 사람의 `from.id` 를 허용 계정으로 저장한다. 허용 계정은 하나다. 새로 등록하면 이전 계정을 바꾼다.
- **FR-TGB-12** 허용 계정이 아닌 사람의 update 에는 답하지 않는다. 서버 로그에 `from.id` 와 종류만 한 줄 남긴다. 본문은 남기지 않는다.
- **FR-TGB-13** 판정은 `from.id` 로 한다. `chat.id` 로 하지 않는다.
- **FR-TGB-14** 허용 계정이 `/pair` 가 아닌 글을 보내면 "이 봇은 알림만 보냅니다." 로 답한다. `[읽음]`(FR-TGB-58)이 아닌 버튼(`callback_query`)을 누르면 "지원하지 않는 버튼입니다." 로 `answerCallbackQuery` 한다. 개정 1 의 메시지에 남은 버튼이 로딩으로 멈추지 않게 하기 위해서다.

### 3.3 알림 보내기

- **FR-TGB-50** PC 알람(`done`·`waiting`)이 울릴 때마다 알림 하나를 허용 계정의 1:1 대화방에 보낸다. 판정은 PC 알람의 것을 그대로 쓴다. 브리지가 따로 판정하지 않는다.
- **FR-TGB-51** 알림의 첫 줄은 `<이모지> <b><종류></b>` 이고, 권한 요청이면 ` · <도구>` 를 붙인다. 이모지는 종류 표시에만 쓴다. 위치는 접힌 문단의 머리에 둔다(FR-TGB-52). 종류는 아래 표로 정한다. "직전 hook" 은 그 탭에서 알람 전에 마지막으로 온 해당 hook 이다(FR-TGB-55).

  | PC 알람 | 직전 hook | 이모지·종류 | 내용 |
  |---|---|---|---|
  | `done` | `StopFailure` | ❌ 오류 | `error` 값 |
  | `done` | 그 밖 | ✅ 완료 | 그 턴의 마지막 응답(FR-TGB-53) |
  | `waiting` | 열린 질문(AskUserQuestion) | ❓ 질문 | 질문마다 머리말·질문·번호 붙인 선택지(설명 포함) |
  | `waiting` | 열린 권한 요청 | 🔐 권한 요청 · `<도구>` | 도구 입력 요약(Bash 는 명령, 파일 도구는 경로, 그 밖은 입력 원문) |
  | `waiting` | 그 밖 | ⏳ 입력 대기 | `Notification.message`. 없으면 내용 없음 |
  | 그 밖 | — | 🔔 알림 | 없음 |

- **FR-TGB-52** 첫 줄 아래에 접힌 문단 하나를 둔다. 접힌 문단의 머리는 위치 세 줄이다: `<code>Server :</code> <b>기기</b>`, `<code>Window :</code> <b>윈도우</b>`, `<code>Tab    :</code> <b>탭</b>`. 라벨은 고정폭이라 `:` 가 같은 자리에 온다. 윈도우를 모르면 그 줄을 뺀다. 접힌 상태에서 보이는 첫 세 줄이 곧 위치다. 내용이 있으면 머리 아래에 빈 줄, 구분선(`──────────`), 빈 줄을 두고 그 아래에 내용을 쓴다. 내용이 비면 구분선도 두지 않는다. 내용의 모양은 종류마다 다르다. 모든 글은 HTML 이스케이프한 뒤 아래 태그만 더한다.
  - 완료: 마지막 응답의 Markdown 을 Telegram HTML 로 옮긴다(FR-TGB-52a).
  - 질문: 질문마다 `<b>[머리말] 질문</b>` 한 줄, 그 아래 선택지를 `N. 이름 — 설명` 으로 한 줄씩 쓴다. 질문 사이는 빈 줄이다.
  - 권한 요청: 요약을 줄마다 `<code>` 로 감싼다(FR-TGB-52b).
  - 오류·입력 대기: 평문이다.
- **FR-TGB-52a** Markdown 옮기기 규칙은 아래와 같다. 그 밖의 글은 평문으로 둔다.
  - 제목(`#`~`######`) → 굵게
  - 목록(`-`·`*`·`+`) → `• `
  - `**굵게**` → `<b>`, `` `코드` `` → `<code>`. 코드 안은 바꾸지 않는다
  - 코드 울타리(```` ``` ````) → 줄마다 `<code>`(FR-TGB-52b). 닫히지 않았으면 끝까지를 코드로 본다
  - 표 → 첫 행은 칸을 ` · ` 로 이어 굵게, 나머지 행은 `• ` 뒤에 칸을 ` · ` 로 잇는다. 구분 행(`|---|`)은 버린다
  - 인용(`> `) → 기호를 떼고 평문. 접힌 문단 안에 인용을 겹칠 수 없기 때문이다
  - 가로줄(`---`) → 버린다. 빈 줄이 여러 개 이어지면 하나로 줄이고, 앞뒤 빈 줄은 걷는다
- **FR-TGB-53** 마지막 응답은 transcript 에서 main `assistant` 줄의 마지막 `text` 블록이다(§2.3). 사이드체인(서브에이전트) 줄과 도구 호출·결과·내부 줄은 읽지 않는다.
- **FR-TGB-52b** 알림에 쓰는 태그는 허용 목록 셋뿐이다: `<b>`, `<code>`, 그리고 바깥의 `<blockquote expandable>` 한 번. 그 밖의 태그(특히 블록 태그 `<pre>`·겹친 `<blockquote>`)는 쓰지 않는다. Telegram 은 `<pre>` 자리에서 접힌 문단을 여러 상자로 끊고(2026-11-12 실기기: 코드 블록이 든 응답이 상자 6개로 나뉨), 겹친 인용은 받지 않는다. 원문의 `<`·`>` 는 모두 이스케이프하므로 원문에서 태그가 생기지 않는다. 여러 줄 코드는 줄마다 `<code>` 로 감싸고, 빈 줄은 그대로 둔다.
- **FR-TGB-54** 내용의 원문은 3500자(유니코드 글자)를 넘으면 앞부분만 남기고 끝에 `…(PC 에서 보기)` 를 붙인다. 자르기는 HTML 로 옮기기 전에 한다. Telegram 의 4096자 한도는 태그를 뺀 글자 수이므로 머리가 들어갈 자리가 남는다.
- **FR-TGB-55** 열린 권한 요청·질문은 그 탭의 `PermissionRequest` 또는 AskUserQuestion `PreToolUse` 로 열리고, 같은 탭의 다음 `PostToolUse`·`PostToolUseFailure`·`Stop`·`StopFailure`·`UserPromptSubmit`·`SessionStart`·`SessionEnd` 로 닫힌다. `PermissionRequest` 의 도구가 AskUserQuestion 이고 입력이 없으면 앞서 연 질문의 입력을 쓴다.
- **FR-TGB-56** 위치의 윈도우·탭 이름은 워크스페이스의 이름이다. 탭 이름이 없으면 전경 프로그램 이름, 그것도 없으면 도구 id 다. 그 탭을 워크스페이스에서 찾지 못하면 윈도우 줄을 뺀다.
- **FR-TGB-57** PC 브라우저에서 그 탭에 무음 시간 안에 입력이 있었으면 알림을 `disable_notification` 으로 보낸다.
- **FR-TGB-58** 알림마다 `[읽음]` 버튼 하나를 단다. 버튼 데이터는 `r:<도구 id>` 다. 64바이트를 넘으면 버튼을 달지 않는다(Telegram 상한).
- **FR-TGB-58b** PC 알람이 꺼지면(포커스·입력·`[읽음]` 등 무엇으로든) 그 탭의 알림 중 버튼이 남은 것의 버튼을 모두 걷는다. 브리지는 탭마다 버튼이 남은 메시지 id 를 메모리에 둔다. 서버를 다시 띄우면 잊으므로 그 전 알림의 버튼은 남는다. 남은 버튼을 눌러도 이미 꺼진 알람을 다시 끄는 것이라 해가 없다.
- **FR-TGB-58a** 허용 계정이 `[읽음]` 을 누르면 그 탭의 PC 알람을 `Attend(tool, typed=false)` 로 끈다. PC 에서 그 탭에 포커스를 준 것과 같다. 그리고 "읽음" 으로 `answerCallbackQuery` 하고, 그 메시지의 버튼을 걷는다. 허용 계정이 아니면 아무것도 하지 않는다(FR-TGB-12).
- **FR-TGB-59** hook 이 없는 에이전트(codex 등)의 알람은 직전 hook 이 없으므로 ✅ 완료·⏳ 입력 대기에 내용 없이 간다. transcript 경로가 없으면 완료 알림에도 내용이 없다.

### 3.4 hook 보고

- **FR-TGB-80** `parseClaudeHook` 은 hook 이름(`hook`)과 transcript 경로(`transcript`)를 보고에 싣는다. 경로만이고 내용은 아니다.
- **FR-TGB-81** `PermissionRequest` 와 AskUserQuestion 의 `PreToolUse` 는 `tool_input` 원문을 보고에 싣는다. 상한은 16KB 다. 넘으면 원문을 싣지 않고 넘었다는 표시(`inputOver`)만 단다. 그때 브리지는 `Detail`(512자)로 요약을 보인다.
- **FR-TGB-82** 이 확장은 브리지가 꺼져 있어도 실린다. 다만 서버는 브리지가 꺼져 있으면 이 값을 브리지로 넘기지 않는다.

### 3.5 비기능

- **NFR-TGB-1** 꺼져 있으면 Telegram 으로 아무 요청도 보내지 않고, transcript 를 읽지 않는다.
- **NFR-TGB-2** 브리지는 PC 의 Claude Code 를 막지 않는다. 막는 hook(대기·결정 반환)을 쓰지 않는다. 사건은 큐로 받고, 큐가 차면 버린다.
- **NFR-TGB-3** Telegram 은 long polling 으로 받는다(짝맞춤 때문). 들어오는 포트를 열지 않는다.
- **NFR-TGB-4** Telegram 이 닿지 않거나 429 를 주면 받기는 지수 백오프로 다시 시도한다. 그동안 dongminal 의 다른 기능은 영향받지 않는다. 보내기에 실패한 알림은 로그만 남기고 다시 보내지 않는다.
- **NFR-TGB-5** transcript 는 완료 알림을 보낼 때 한 번만, 끝에서 최대 512KB 만 읽는다. 감시·주기 조회를 하지 않는다.
- **NFR-TGB-6** 브리지는 AI 모델을 부르지 않는다.
