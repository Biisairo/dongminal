### 2026-11-25 agent-pf-3-4-8 — review (pf/3.4.8 `2cf7d5c7`, 본 커밋 `1e76d09e`, perf-m1 985e13c7 병합 `e9a2a142`)

**바꾼 것**

- `web/bundles.txt` 끝에 `[docrender]` 묶음을 더했다. 순서는 `vendor/highlight.js` → `constants-docrender.js` → `doc-render-util.js` → `doc-render.js` → `doc-render-life.js`(새 파일) → `style-docrender.css` 다. index.html 에서 `vendor/highlight.js` 와 `style-docrender.css` 를 뺐다.
- `editor-view-life.js` 에서 `DocRender.prototype` 의 sleep·wake 를 `doc-render-life.js` 로 떼었다. 3.4.7 이 FileEditor 부분을 떼었으므로, 병합 뒤에는 boot 에 `edViewLifeDoc` 만 남는다.
- 부팅 코드가 읽는 상수 넷(`DOC_RENDER_EXTS`·`DOC_RENDER_BTN`·`DOC_RENDER_BTN_TITLE`·`DOC_RENDER_TAB_MARK`)을 `constants-file.js` 로 옮겼다(D-32). 읽는 쪽은 `renderer-pane.js` 의 탭 이름과 `editor-doc-render.js` 의 버튼이다.
- 편집기에 서는 진입 버튼 `.fe-render` 의 CSS 를 `style-editor-tools.css` 끝으로 옮겼다. 캐스케이드 자리는 전과 같다. 묶음 CSS 로 두면 묶음이 실리기 전에는 버튼에 스타일이 없다.
- `editor-doc-render.js` 끝에서 `Screens.register('docrender',{css:true, tab: 렌더 탭})` 를 부른다. 렌더러의 `new DocRender` 는 3.4.7 이 등록한 진입점 `Renderer.prototype._mountTabBody` 아래에 있다. 처음 구현에서는 별도 진입점 `EditorDocRender.docRenderView` 를 두었다. 병합 뒤 `_mountTabBody` 가 진입점이 되었으므로 그 진입점을 지웠다.

**결정 (조정자 승인)**: markdown-it·DOMPurify 는 boot 에 남긴다. 터미널 맨 도메인 링크(`bare-link.js`, term-pane)와 편집기 링크(`cm-link.js`)가 markdown-it 을 쓰고, LSP hover 정화(`lsp-client.js`)가 DOMPurify 를 쓴다. 둘을 옮기면 링크가 오류 없이 꺼지거나(`typeof` 가드) hover 에서 ReferenceError 가 난다. vendor UMD 라서 경계 게이트도 이 참조를 잡지 못한다. 그래서 완료 조건을 "부팅 때 `b/docrender.js`·highlight 요청이 없다" 로 고쳤다. 줄어드는 양은 약 180 KB 다(highlight 129 KB 와 문서 렌더 코드·CSS). 셋 다 옮겼을 때 예상하던 양은 약 320 KB 다.

**동작 변경**

- 이전: 부팅 때 highlight.js 와 문서 렌더 코드·CSS 를 모두 받았다.
- 새: 렌더 탭을 처음 그릴 때 `b/docrender.js`·`b/docrender.css` 를 받는다. 그동안 자리표시("불러오는 중…")가 선다.
- 이유: 부팅 JS 와 요청 수를 줄인다(FR-SPA-1·2, D-29~31).
