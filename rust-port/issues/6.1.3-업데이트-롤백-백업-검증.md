  - Go 와 다르게 한 결정
    - **번들 비밀 가림(FR-RSP-6, 조정자 보안 지적)**: Go 는 URL userinfo 만 가렸다. Rust 는 그 뒤에 PEM 본문·인증 헤더 값·Bearer·비밀 이름(token·secret·password·…·auth·cookie·signature·credential 로 끝남, sig·pwd)의 JSON 문자열 값·`이름=값`·`이름: 값` 을 `***` 로 가린다. `key` 단독은 고르지 않는다(단축키 설정). 비밀 없는 입력은 바이트 동일 — 조정자가 DIFF 로 올린다
    - `start::mkdir_temp(dir, prefix)` 로 자리를 인자로 받는다(doctor 6.1.2 에서). `start::wait_ready_for(url, tries, interval)` 을 verify 와 나눠 쓴다. `http::Reply` 에 헤더를 더했다(보안 헤더 검사)
    - `CheckReport` 에 `skip`·`skipped`·`out()` 을 더했다(verify 몫)
    - verify 의 Go `url.QueryEscape` 는 `verify::query_escape` 로 옮겼다(gocompat 에 없음)
    - rollback 의 세대 시각은 `time` crate + gocompat 시간대로 Go `2006-01-02 15:04:05`(지역)·`20060102T150405Z`(UTC) 를 만든다
  - 남은 위험
    - **verify 종단간은 돌리지 않았다.** 자기 실행 파일을 `start --foreground` 로 띄우므로 이슈 7 의 실행 파일이 있어야 서버가 뜬다. 또 빈 포트가 60147 미만일 수 있어 운영 보호 규약상 Go 참조로도 돌리지 않았다. 단위 검사(가드·표 골든·능력 질의·보고·도우미)와 컴파일로만 확인. 이슈 7 이후 격리 실행으로 한 번 돌려야 한다
