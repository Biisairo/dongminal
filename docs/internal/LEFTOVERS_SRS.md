## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 위반 셋은 전부 같은 모양이다

| 자리 | 가드 | 사유 |
|---|---|---|
| `handlers_fs_relpath_test.go:205` | `runtime.GOOS == "windows"` | 심링크에 권한이 필요하다 |
| `handlers_fs_zip_test.go:212` | 〃 | 〃 |
| `handlers_fs_zip_test.go:240` | 〃 | 퍼미션 모델이 다르다 |

셋 다 **"이 OS 인가" 가 아니라 "이 능력이 있는가"** 를 묻고 있었다. 그 질문을
담을 자리는 이미 있다 — `internal/shared/testpath` 의 `PermChecked()` ·
`POSIXShell()` · `ForegroundGroups()` 가 build tag 로 갈린 그 관행이다.

세 번째 자리가 묻는 것은 **정확히 `PermChecked()`** 다. 앞의 둘이 묻는 것(심링크를
만들 수 있는가)만 아직 없다.

### 2.2 설치는 자기가 놓은 것을 거두지 않는다

`Install` 은 지금 `helperNames()` 를 **놓기만** 한다. 이름이 목록에서 빠지면 이미
설치된 파일은 그대로 남는다 — 실제로 사용자 `bin/` 에 `mdview` 가 있고, 그 이름은
코드 어디에도 없다.

에이전트 플러그인은 이 문제를 이미 풀었다 — `installAgentPlugin` 은 "설치 트리는
임베드 트리의 **거울**" 이라는 규칙을 두고 임베드에 없는 것을 지운다(실측 기록:
b3dc910 에서 지운 스크립트가 설치 트리에 남아 옛 세션이 그것을 실행했다). 헬퍼에는
그 규칙이 없다.

### 2.3 무엇을 지워도 되는지가 문제다

`bin/` 에는 헬퍼만 있지 않다 — 셸 훅(`bash-hook.sh`·`zdotdir/`), 에이전트
훅·플러그인, 그리고 덧없는 자기 자신의 복사본(`dongminal-self`)이 함께 산다.
**모르는 파일을 지우는 규칙은 둘 수 없다.** 우리가 놓은 것만 거둘 수 있어야 한다.

`mdview` 는 그 기록이 없던 시절에 놓인 것이라, 기록만으로는 닿지 않는다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 S — 규약

- **FR-LFT-1** `platform` 밖에 `runtime.GOOS` 가 없다. `scripts/check-seams.sh` 가
  통과한다.
- **FR-LFT-2** 테스트는 OS 가 아니라 **능력**을 묻는다. 심링크를 만들 수 있는지는
  `testpath.Symlinks()` 가 답한다 — 기존 `PermChecked()` 와 같은 자리·같은 방식
  (build tag).
- **FR-LFT-3** 퍼미션을 묻던 자리는 이미 있는 `testpath.PermChecked()` 를 쓴다.
  새 수단을 만들지 않는다.
- **FR-LFT-4** 건너뛰는 조건과 사유는 그대로다 — 이 작업은 **묻는 방식**만 바꾼다.

### 3.2 묶음 R — 잔재

- **FR-LFT-5** 설치는 **자기가 놓았던 헬퍼 중 지금 목록에 없는 것**을 거둔다.
- **FR-LFT-6** 무엇을 놓았는지는 `bin/` 에 기록으로 남긴다. 기록에 없는 파일은
  건드리지 않는다 (§2.3).
- **FR-LFT-7** 기록이 없던 시절의 이름은 **폐지 목록**으로 거둔다. 지금 그 목록은
  `mdview` 하나다.
- **FR-LFT-8** 거두기 실패는 설치의 실패가 아니다. 남은 파일은 해가 없고, 설치를
  막는 것이 더 해롭다.
- **FR-LFT-9** 기록은 헬퍼 이름만 담는다 — 훅·플러그인·자기 복사본은 각자의 규칙이
  따로 있다.

## 5. 확정 결정 (Decisions)

- **D-1 능력을 묻는다.** "Windows 인가" 는 오늘의 사실이고 "심링크를 만들 수 있는가"
  는 검사가 실제로 기대는 사실이다. 뒤엣것을 물으면 다음 플랫폼에서 자동으로 맞는다.
- **D-2 기록으로 거둔다.** 모르는 파일을 지우는 규칙은 위험하고(§2.3), 우리가 놓은
  것만 거두면 안전하다. 에이전트 플러그인의 "거울" 규칙과 같은 생각이다.
- **D-3 폐지 목록은 최소로 둔다.** 기록이 생긴 뒤에 빠지는 이름은 기록이 알아서
  거두므로, 이 목록은 **기록 이전의 이름만** 담는다. 늘어날 자리가 아니다.
- **D-4 지우기는 조용히 실패한다.** 남은 헬퍼는 해가 없다 — 잘못된 것을 가리키면
  `InspectHelpers` 가 이미 알린다 (FR-HLI-7).

## 6. 비목표 (Non-goals)

1. `bin/` 의 훅·플러그인 정리 — 각자 규칙이 이미 있다.
2. 사용자가 직접 넣은 파일의 정리.
3. 헬퍼 판번호 검사.
4. `check-seams.sh` 의 규칙 자체 변경 — 규칙은 옳고, 어긴 쪽을 고친다.
