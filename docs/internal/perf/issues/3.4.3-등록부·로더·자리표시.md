# 3.4.3 등록부·로더·자리표시 (D-30)

## 목표

- `Screens.register(name,{bundle,css})`·`Screens.load(name)`(Promise, 같은 이름은 같은 Promise, 실패는 기억하지 않고 URL 을 바꿔 다시 시도 — `loadCodeMirror` 규약)·`Screens.ready(name)`.
- 렌더러 `_mountTabBody` 는 묶음이 아직이면 자리표시(스켈레톤 킷)를 붙이고 `Screens.load` 뒤 `app.render()` 한 번. 렌더러는 동기로 남는다.
- 아직 어떤 화면도 옮기지 않는다(빈 시험 묶음으로 확인). e2e 도우미 `app.testing.load(name)`. (정정 2026-11-25, PERF 3.4.11: 지금 이름은 `app.testing.loadScreen(name)` 이다.)
- 렌더러 파일 병합 순서: 3.5.1 → **3.4.3** → 3.6.2(`perf/M3_DESIGN.md` §3.7).

## 완료 조건

- RED(하네스 단위, 가짜 `document`): 같은 이름 두 번 `load` → `<script>` 하나. 실패하면 reject, 다음 `load` 는 새 URL. CSS 와 JS 가 둘 다 끝나야 푼다. 등록되지 않은 이름은 reject.
- 단위: 자리표시는 묶음이 실린 뒤 다시 그리기 한 번으로 실제 본문으로 바뀐다. 전체 시험 금지.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.
