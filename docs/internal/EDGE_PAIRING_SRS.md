# SRS: 간선 맺기·지우기 단순화 (Edge Pairing) — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: 단계 E4(§8). E1~E3 은 끝났다
> **입력**: 2026-11-17 대화. 사용자 결정: "안전하지만 간단하게 연결 과정을 바꾼다", "한쪽에서 간선을 지우면 양쪽에서 지워진다".
> **대체**: `PEER_NETWORK_SRS.md` 의 FR-PNW-23~31·33·41·80(승인 대기 구역)·81·82, I-1·I-5·I-37 은 이 문서가 앞선다. 나머지(노드 포트·초대 코드·지문 고정·감사 로그)는 그대로다.
> **선행**: `PEER_DAEMON_SRS.md` (노드 = 데몬, 서버는 통로), `PEER_CHAT_SRS.md` §3.12(도우미 키 고정 `helperKey`).

## 1. 개요 (Introduction)

### 1.1 목적

간선 맺기를 "초대 코드 만들기 → 붙여 넣기" 두 걸음으로 줄이고, 한쪽에서 지운 간선이 양쪽에서 지워지게 한다. 안전은 지금처럼 지문 고정 TLS 와 일회용 토큰이 지킨다.

### 1.2 범위

| 묶음 | 내용 |
|---|---|
| P | 맺기: 초대, 등록, 다시 시도 |
| D | 지우기: 알림, 나중에 맞추기 |
| N | 이름과 식별: 지문으로 찾기, 표시 이름 |
| S | 표면: 노드 포트·로컬 API·dmctl·화면·`edges.json` |

### 1.3 정의

| 용어 | 정의 |
|---|---|
| 초대하는 노드(B) | 초대 코드를 만든 노드. 노드 포트가 열려 있어야 한다 |
| 초대받는 노드(A) | 초대 코드를 붙여 넣은 노드. 노드 포트가 닫혀 있어도 된다 |
| 지문 | 노드 인증서 공개키의 SHA-256 hex 64자리. 노드의 신원이다 |
| 지문 앞자리 | 지문의 앞 8자리 이상. 간선 목록 안에서 하나로 정해질 때만 쓴다 |
| 표시 이름 | 상대가 스스로 알린 노드 이름. 겹쳐도 된다. 식별에 쓰지 않는다 |

## 2. 현황 (Identified Issue)

조사: 2026-11-17 (`internal/shared/edge`, `internal/shared/edgenode`, `httpapi/edge_api.go`, `runtimebin/dmctl_edge.go`, `web/js/core/app-settings-edges.js`).

- 맺기는 다섯 걸음이다: B 초대 → A 붙여 넣기(+이름) → B 승인 대기 → B 사람이 승인(+이름) → B 가 A 에 `confirm` 통지. A 는 B 의 통지를 받으려고 노드 포트를 열어 두어야 한다.
- 승인은 토큰이 이미 한 확인을 되풀이한다. `dmctl edge approve` 는 같은 OS 계정의 에이전트도 부를 수 있어 사람 확인이 되지 않는다.
- 간선 항목의 이름(`Edge.Name`)은 지우기·주소 고치기의 대상 찾기에만 쓰인다. 이름이 하나뿐이어야 해서 409 `edge_name_taken`, `-2` 붙이기, 이름 입력 칸이 생겼다. 출입 판정·채팅은 이미 지문으로 찾는다.
- 지우기는 자기 쪽만 지운다(FR-PNW-31). 상대는 지운 노드를 계속 간선으로 알고, 채팅 연결을 계속 다시 건다.
- 노드 포트는 간선이 아닌 클라이언트 인증서를 TLS 단계에서 끊는다(FR-PNW-41). 그래서 지운 쪽이 "간선이 아니다"를 상대에게 말할 길이 없다.

## 3. 요구 (Requirements)

### 3.1 묶음 P — 맺기

- **FR-EPR-1** 초대는 지금과 같다: 일회용 토큰(128비트), 10분, 동시에 하나, 코드 `dmedge1:` + base64url(`{addr, port, fp, token}`). 초대하려면 B 의 노드 포트가 열려 있어야 한다.
- **FR-EPR-2** A 는 코드의 `fp` 로 B 의 서버 인증서를 고정해 `POST /edge/v1/pair` `{token, name, addr, port}` 을 보낸다. `name` 은 A 의 노드 이름이다. A 의 노드 포트가 열려 있을 때만 `port` 를 싣고(`addr` 은 알릴 주소, 없으면 비움), 닫혀 있으면 둘 다 비운다. B 는 `port` 가 있으면 `addr`(없거나 틀리면 이 연결의 출발지 IP)과 함께 A 의 주소로 저장하고, 없으면 A 의 주소를 비워 둔다. 주소가 빈 간선에는 B 가 걸지 않는다 — A 가 건다.
- **FR-EPR-3** B 는 토큰이 맞으면 토큰을 쓰고, A 의 지문(TLS 클라이언트 인증서)을 **바로 간선으로 저장**한다. 승인 단계는 없다. 응답은 200 `{name}`(B 의 노드 이름)이다.
- **FR-EPR-4** A 는 200 을 받으면 B 를 간선으로 저장한다(코드의 주소·포트, 응답의 이름). 맺기는 여기서 끝난다.
- **FR-EPR-5** 양쪽은 맺은 뒤 `edges_changed` `{paired:{fp, name}}` 를 낸다. 화면은 "{name}(지문 앞자리)와 맺었습니다" 알림을 띄운다. 데몬 IPC push `edges` 도 같은 값(`paired`·`removed` 객체)을 싣는다.
- **FR-EPR-6** 다시 시도: B 는 쓴 토큰을 그 초대가 만료될 때까지 쓴 지문과 함께 기억한다. 같은 지문이 같은 토큰으로 다시 오면 200 으로 답한다(응답이 중간에 끊긴 A 가 다시 시도하는 경우). 다른 지문에게는 이미 초대가 없으므로 403 `edge_no_invite` 다. 살아 있는 초대에 틀린 토큰은 지금처럼 403 `edge_token_invalid` 다. 그 지문의 간선을 지우거나(어느 쪽이 지웠든) 새 초대를 만들면 다시 시도 기억도 지운다 — 끊은 상대가 같은 코드로 다시 맺지 못한다(보안 검토).
- **FR-EPR-7** 이미 간선인 지문과 다시 맺으면 간선 하나로 남는다. 주소·표시 이름만 바뀌고 고정한 도우미 키(`helperKey`)는 남는다(PEER_CHAT §3.12a R-2).
- **FR-EPR-8** 상대 이름이 표시 이름 규칙(제어 문자 없음, 64바이트 안)에 맞지 않으면 거절하지 않고 `DefaultName` 으로 고쳐 저장한다.

### 3.2 묶음 D — 지우기

- **FR-EPR-20** 어느 쪽이든 간선을 지우면, 먼저 상대에게 지문 고정 TLS 로 `POST /edge/v1/unpair` `{}` 를 보낸다(3초 시한). 성공하든 실패하든 자기 쪽 간선을 지운다. 응답에 상대에게 알렸는지(`notified`)를 싣는다.
- **FR-EPR-21** `unpair` 를 받은 노드는 보낸 지문의 간선을 지우고 200 을 답한다. 간선이 아니면 403 `edge_not_edge` 다.
- **FR-EPR-22** 지운 뒤 맞추기: 노드 포트는 간선이 아닌 지문의 요청(`pair` 제외)에 403 `edge_not_edge` 로 답한다. 간선 상대에게 채팅 연결을 걸다가 그 상대(지문을 고정한 서버 인증서)가 `edge_not_edge` 로 답하면, 그 간선을 지운다. 그래서 지울 때 상대가 꺼져 있었어도 다시 닿는 순간 양쪽이 맞춰진다.
- **FR-EPR-23** 간선을 지우면 그 간선의 채팅 연결을 닫고, `edges_changed` `{removed:{fp, name}}` 를 낸다. 화면은 상대가 지워서 사라진 간선을 "{name} 간선이 끊겼습니다"로 알린다.
- **FR-EPR-24** 지운 간선과 다시 맺으려면 새 초대로 맺는다. 도우미 키도 새로 고정한다.

### 3.3 묶음 N — 이름과 식별

- **FR-EPR-30** 간선은 지문으로만 찾는다. 지우기·주소 고치기는 지문 전체나 지문 앞자리(8자리 이상, 간선 목록에서 하나로 정해질 때)를 받는다. 둘 이상에 맞으면 400 `edge_ambiguous`, 없으면 404 `edge_not_found` 다.
- **FR-EPR-31** 간선 항목의 이름은 상대가 알린 표시 이름이다. 사용자가 정하지 않고, 겹쳐도 된다. 이름 입력(`--name`, 이름 칸)과 이름 충돌 처리(409 `edge_name_taken`, `-2` 붙이기)는 없앤다.
- **FR-EPR-32** 화면·dmctl 은 간선을 `표시 이름 · 지문 앞 16자리 · 주소:포트` 로 보인다.
- **FR-EPR-33** 노드 자기 이름(`edges.json` 의 `name`)은 남긴다. 기본값은 호스트 이름이고, 설정 ▸ Edges 의 "이 노드"에서 바꾼다. 맺을 때 상대에게 알리고, 채팅의 표시 이름(`<노드 이름>/<탭>`)에 쓴다.

### 3.4 묶음 S — 표면

노드 포트

- **FR-EPR-40** 경로는 `POST /edge/v1/pair`, `POST /edge/v1/unpair`, `GET /edge/v1/chat`(PEER_CHAT §3.9) 셋이다. `/edge/v1/pair/confirm` 은 없앤다.
- **FR-EPR-41** 출입 판정: TLS 단계는 클라이언트 인증서가 있기만 하면 받는다(지문을 읽으려고). 요청 단계에서 `pair` 는 누구나 닿고 처리기가 초대·토큰을 본다(출발지 요청 횟수 제한, 초대가 없으면 403 `edge_no_invite`). `unpair`·`chat` 과 그 밖의 경로는 간선일 때만 받고, 아니면 403 `edge_not_edge`(`{code,message}` 본문과 코드 머리)다.

로컬 API (`/api/edges/*`)

- **FR-EPR-50** `GET /api/edges` → `{node, invite, edges[{fp, name, addr, port}], port}`. `pending` 은 없다.
- **FR-EPR-51** `POST /api/edges/add` `{code}` → `{fp, name}`. `name` 인자는 없다.
- **FR-EPR-52** `POST /api/edges/remove` `{fp}` → `{fp, name, notified}`. `PUT /api/edges/address` `{fp, addr, port}`.
- **FR-EPR-53** `GET /api/edges/pending`, `POST /api/edges/approve`, `POST /api/edges/reject` 는 없앤다(404).
- **FR-EPR-54** 오류 코드: `edge_name_taken`·`edge_pending_not_found` 는 없애고 `edge_not_edge`(403)·`edge_ambiguous`(400)를 더한다.

dmctl

- **FR-EPR-60** `dmctl edges`(목록), `dmctl edge invite [--addr]`, `dmctl edge add <코드>`, `dmctl edge remove <지문 앞자리>`. `approve`·`reject`·`--name` 은 없앤다. 목록 줄은 `edge fp=<앞 16자리> name=<표시 이름> addr=<주소:포트>` 다. 승인 대기 줄은 없다.

화면 (설정 ▸ Edges)

- **FR-EPR-70** 구역은 셋이다: **이 노드**(지금 그대로), **초대**(만들기·복사·남은 시간 + 코드 붙여 넣기 칸과 `맺기` 단추), **간선**(표시 이름·지문 앞 16자리·주소, 주소 고치기, 끊기). 승인 대기 구역, 승인 확인창, 이름 입력 칸, 승인 대기 주의 알림은 없앤다.
- **FR-EPR-71** 끊기 확인창은 "{name}(지문 앞자리) 간선을 끊습니다. 상대 쪽에서도 지워집니다."를 보인다. 상대에게 알리지 못했으면 "상대에게 알리지 못했습니다. 다시 이어지면 상대 쪽에서도 지워집니다." 알림을 띄운다.

저장

- **FR-EPR-80** `edges.json` 의 간선 항목은 `{fp, name, addr, port, helperKey}` 다. `addr`·`port` 는 비어 있을 수 있다(FR-EPR-2). `state`·`expires` 는 없앤다. 읽을 때 옛 항목 가운데 `state` 가 `paired` 가 아닌 것(옛 `pending-out`)은 버리고, `paired` 는 그대로 받는다. 지문은 하나뿐이어야 한다. 이름 중복 검사는 없다.

## 4. 결정 (Decisions)

| ID | 결정 | 이유 |
|---|---|---|
| D-EPR-1 | 승인 단계를 없앤다. 토큰이 맞으면 바로 간선이다 | 사용자 결정. 토큰은 B 의 사람이 건넨 코드에만 있고, 승인은 에이전트도 할 수 있어 사람 확인이 아니었다 |
| D-EPR-2 | 간선은 지문으로 찾고 이름은 표시용이다 | 이름이 기능에 쓰인 곳은 지우기·주소 고치기의 대상 찾기뿐이었다 |
| D-EPR-3 | 지우면 상대에게 알리고, 못 알렸으면 상대가 다시 걸 때 403 `edge_not_edge` 로 맞춘다 | 사용자 결정(양쪽 지우기). 403 은 지문을 고정한 상대의 서버가 낸 답이라 믿을 수 있다 |
| D-EPR-4 | 노드 포트의 TLS 단계는 간선이 아닌 인증서도 받고, 판정은 요청 단계에서 한다 | 지운 쪽이 "간선이 아니다"를 말하려면 TLS 를 마쳐야 한다. 간선이 아닌 상대가 닿는 것은 403 과 초대 경로뿐이고 횟수 제한을 받는다 |
| D-EPR-5 | 응답이 끊긴 맺기는 같은 지문·같은 토큰의 다시 시도를 초대 만료까지 받는다 | 한쪽만 저장된 간선을 남기지 않는다 |

### 4.1 검토하고 버린 안

| 안 | 버린 이유 |
|---|---|
| 승인 단계를 두되 자동 승인 | 걸음만 남고 하는 일이 없다 |
| 지운 간선을 묘비(`removed` 상태)로 남겨 TLS 에서 알아보기 | 저장을 늘린다. 요청 단계 판정으로 충분하다 |
| TLS alert 로 "간선 아님"을 알아내기 | 오류 모양이 OS·판마다 다르고, 다른 실패와 가르기 어렵다 |
| 노드 이름까지 없애고 지문만 보이기 | 채팅 표시 이름이 읽을 수 없게 된다. 노드 이름은 이 노드가 정하는 표시값으로 남긴다 |

### 4.2 동작 변경

| 이전 | 새 동작 | 이유 |
|---|---|---|
| 붙여 넣은 뒤 B 의 사람이 승인해야 맺어진다 | 붙여 넣으면 바로 맺어진다 | D-EPR-1 |
| A 의 노드 포트가 닫혀 있으면 경고하고, B 의 통지를 받지 못하면 B 와 `node.info` 로 다시 확인한다 | A 의 노드 포트는 상관없다 | 통지가 없다 |
| 지우기는 내 쪽만 지운다 | 양쪽에서 지워진다 | D-EPR-3 |
| 간선 이름으로 지우고 주소를 고친다 | 지문(앞자리)으로 한다 | D-EPR-2 |
| 간선이 아닌 인증서는 TLS 단계에서 끊긴다 | TLS 를 마치고 403 을 받는다 | D-EPR-4 |

| TC-EPR-9 | FR-EPR-50~54·60 | httpapi·dmctl: 새 경로·인자, 없앤 경로 404, 없앤 명령은 모르는 명령 | 표대로 |
| TC-EPR-10 | FR-EPR-70·71 | JS 단위: 간선 줄 모양, 끊기 문구, 승인 대기 구역 없음, `paired`·`removed` 알림 | 표대로. e2e `edges-settings.spec.ts` 는 고치되 돌리는 것은 사용자 몫 |

## 6. 비목표 (Non-goals)

1. 옛 판(승인 단계가 있는 판)과의 맺기. 이 브랜치의 이름 변경으로 이미 맺을 수 없다.
2. 간선 이름 바꾸기 기능. 표시 이름은 상대가 정한다.
3. 지운 간선 기록 보관.

## 7. 위험 (Risks)

| 위험 | 등급 | 대응 |
|---|---|---|
| 초대 코드가 새면 10분 안에 누구나 맺는다(승인이 없다) | MEDIUM | 일회용·10분. 맺으면 양쪽에 알림이 뜨고 바로 끊을 수 있다. 끊으면 상대 쪽에서도 지워진다 |
| 간선이 아닌 상대도 TLS 를 마친다 | LOW | 닿는 것은 403 과 초대 경로뿐이고 횟수 제한을 받는다 |
| B 가 A 의 주소를 모르는 간선(A 의 노드 포트가 닫혀 있었음)은, A 가 지울 때 B 가 꺼져 있었으면 B 쪽에 남는다. B 는 A 에 걸지 않으므로 맞출 기회가 없다 | LOW | B 화면에 주소 없이 남는다. 사용자가 지우면 된다(알림은 실패하고 자기 쪽만 지운다). 해가 없다 — A 는 B 를 받지 않는다 |
| 한쪽이 `edges.json` 을 잃으면 상대도 그 간선을 지운다 | LOW | "한쪽에서 지우면 양쪽에서 지운다"와 같은 결과다. 새 초대로 다시 맺는다 |
