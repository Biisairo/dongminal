## 주제 1 — 연결된 기기 사이의 클립보드 공유

**사용자 요구(2026-11-26)**

> otterminal 이 연결된 기기들에서 otterminal 을 쓸 때 클립보드를 공유하고 싶다. 처음 목적은, 다른 기기의 otterminal 을 쓸 때 claude 에 이미지를 붙여 넣을 수 없는 문제다.

메모장 `memo` 62줄도 같은 주제다: "다른 pc 에서 이미지 claude 에 넣기. 클립보드 공유? kde connect".

**문제의 모양(가설, 확인 필요)**

- claude 의 이미지 붙여넣기는 claude 프로세스가 도는 PC 의 OS 클립보드를 읽는다.
- 브라우저로 원격 otterminal 을 쓰면 이미지는 사용자 기기의 클립보드에 있고, claude 가 도는 PC 의 클립보드에는 없다.

**논의할 결정**

- 무엇을 공유하는가: 글자만, 이미지까지, 파일까지.
- 방향: 사용자 기기 → 에이전트 PC, 반대 방향, 양방향.
- 계기: 붙여넣기 순간에 보낼지, 늘 맞출지.
- 대상: 같은 망의 다른 노드(간선 `edge`)까지 넓힐지.
- 보안: 클립보드는 민감한 정보다. 사내 규정(기밀은 승인된 경로만)과 R-5 와 같은 검토가 필요하다.

**출발점(코드)**

- 웹의 클립보드: `web/js/ui/clipboard.js`, `web/js/ui/term-clipboard.js`, `web/js/ui/term-clip.js`.
- 노드 사이 연결: 간선 설정 `web/js/core/settings-edges.js`, `rust/crates/shared/edge*`.
- 먼저 claude 가 이미지를 붙여 넣을 때 어디서 읽는지 실측한다(OS 클립보드, 파일 경로 붙여넣기 등).

## 주제 2 — 에이전트 입력 중에 otterctl 프롬프트가 끼어드는 문제

**사용자 요구(2026-11-26)**

> otterctl 로 에이전트에 프롬프트를 넣으면 붙여넣기 뒤 엔터를 눌러 버린다. 사용자가 입력하는 중에 이 일이 일어나면, 쓰던 입력이 미완성인 채로 함께 제출된다. 해결법을 연구한다.

메모장 `memo` 64줄도 같은 주제다: "에이전트 입력창에 입력 시 현재 입력된 내용 저장 후 삭제한 뒤 입력하고 저장한 내용 다시 쓰기".

**지금 동작(코드)**

- 텍스트를 넣고, submit 이면 120ms 뒤 CR 로 제출한다. 셸이 bracketed paste 를 켰으면 감싼다: `rust/crates/shared/toolhub/src/manager.rs`(966줄 부근, `PASTE_BEGIN`, FR-BPW-4/5).
- 에이전트 사이 메시지 엔벨로프: `rust/crates/webserver/httpapi/src/toolio.rs` `agent_envelope`.

**이미 알려진 것(ISSUE_TREE_CHAT_SRS)**

- 채팅 알림은 붙여넣기를 없애고 Stop 훅 `asyncRewake` 로 깨운다(D-ITH-3). 실측에서 입력창에 쳐 둔 글은 남았고, 엔터로 따로 제출됐다(TC-ITH-7, `ISSUE_TREE_CHAT_PROGRESS.md`).
- 따라서 `otterctl msg` 도 같은 깨움 경로로 옮기는 것이 후보다. 다만 그 경로는 에이전트가 쉬고 있을 때만 깨운다.

**연구할 후보**

1. 깨움 훅 경로로 옮긴다(입력창을 건드리지 않는다).
2. 메모의 방식: 입력창 내용을 저장 → 지운다 → 넣고 제출한다 → 저장한 내용을 되살린다. 터미널 밖에서 입력창 내용을 정확히 읽을 수 있는지가 관건이다(화면 스냅숏, TUI 별 차이).
3. 사용자가 최근에 입력했으면 미룬다(입력 정지 감지, 시간 값은 `cadence` 상수).
4. 에이전트 쪽 기능(claude 의 입력 큐, MCP 알림 등)을 쓴다 — 실측이 필요하다.
