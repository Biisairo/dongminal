### 공개 API 요약

`dm-webserver-domain-worktree`
- `Manager::new(root)` + `with_runner`·`with_lock_wait`·`with_service(Arc<git_core::Service>)`. 메서드는 모두 `async`, 첫 인자 `&git_core::Ctx`: `resolve`·`create`·`add_spec`(동기)·`configure`·`branch_exists`·`rollback`·`list`·`remove`·`remove_listed`·`main_root`·`current_branch`, 그리고 `root()`·`path(run, leaf)`
- `Service` 트레이트(dyn 가능, `Fut<'a, T>` 반환) — Go `worktree.Service`. `Manager` 가 구현한다
- `lock_repo(ctx, key, wait) -> Result<RepoLock, Error>` (Go `LockRepo`; 반납은 `RepoLock::release` 또는 drop)
- `Spec`·`ExecSpec`·`Repo`·`Entry`·`RemoveSpec`·`RemoveResult`(Go `Result`, JSON 태그 동일, `err` 는 직렬화 제외)
- `branch`·`repo_bucket`·`check_name`, 잔여물 상수 `RESIDUE_*`, `UNGUARDED_REASON`, `Runner`·`git_runner(Option<Arc<Service>>)`·`exec_git`
- `Error`: `is(Kind)`(GitMissing·NotRepo·UnsafeArgument·UnsafePath·RepoBusy), `is_core(git_core::Kind)`(Timeout·Canceled·NotRepo 등), `Failure{text, err}`

`dm-webserver-domain-submodule`
- `Manager::new(Runner)`: `list`·`update`·`sync` (async, `&Ctx`), `update_spec(...) -> Spec{argv, reason}`, `runner_for(Option<Arc<Service>>)`·`exec_git`
- `Entry`(JSON: path·oid·state·describe omitempty), `STATE_*`, `UNGUARDED_REASON`
- `Error`: `is(Kind::{UnsafePath, Failed})` 와 `is_core(..)` 를 함께 판정한다 (Go 의 다중 Unwrap)

`dm-webserver-domain-wsentry`
- `Store`(pub 필드 `work`·`commands`·`repo_root`·`home_fn`·`notes_dir`·`plugins_dir`, `Store::default()` 뒤 필드 대입): `home`·`notes`·`plugins`·`read`·`list`·`roots`·`editor_add`(async, `&Ctx`)·`editor_remove`·`editor_reorder`·`pin_add`·`pin_remove`·`mutate`
- 트레이트 `WorkspaceStore`(`dm_shared_workspace::Manager` 에 구현 포함)·`Broadcaster`, 타입 `RepoRootFn`·`HomeFn`, `Lists`
- `normalize_path`·`fixed_roots`·`check_editor_path`, 연동 4규칙 `link_*`
- `Error` 열거형 — `Display` 가 Go 문구와 같다. `is_stale()` = Go `errors.Is(err, workspace.ErrStale)`

### Go 와 다르게 한 내부 결정
- Go `context.Context` → `git_core::Ctx`, Go `Runner (string, error)` → `Result<String, Failure{text, err}>`. 실패에도 진단 텍스트가 있는 점은 같다
- 함수형 옵션 → 빌더 메서드. `LockRepo` 의 release 함수 → `RepoLock` 가드
- 잠금은 전역 `HashMap<키, Semaphore(1)>` 이다. 키 정규화(exclusion_key)·대기 상한 문구(`repo_busy: <k> 의 worktree 조작이 30ms 안에 끝나지 않았다`)·ctx 사유 문구는 Go 와 같다
- Go 테스트 중 `ctx.Value` 로 호출자 ctx 전달을 보던 것은 취소 상태 전달로 바꿔 검사한다. `gittest.Count` 는 Runner 를 세는 방식으로 바꿨다(이 패키지의 git 은 모두 Runner 를 지난다). `TestLinkRulesDoNotCallEachOther`(go/ast)는 link.rs 원문 검사로 옮겼다. 벤치(roots_bench)는 옮기지 않았다
- wsentry 의 `map[string]any` 왕복은 `serde_json::Map` + `dm_gocompat::json` 으로 한다. Go 바이트(키 정렬, float64 숫자, HTML 이스케이프)와 같은지 테스트로 확인했다
- wsentry `RepoRootFn` 의 오류는 문구(String)다 — 소비처가 "루트 아님" 으로만 읽는다

### 남은 위험
- LOW: worktree `create` 의 디렉터리 생성 실패 문구는 `mkdir <부모 경로>: …` 다. Go `os.MkdirAll` 은 실제로 실패한 조각의 경로를 낸다(부모가 파일인 경우 등). 응답 detail 에만 드러난다
- LOW: wsentry 의 JSON 동등성은 dm-gocompat json 에 기댄다(1.x 범위)
