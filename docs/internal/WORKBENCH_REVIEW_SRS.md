## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 말은 여덟이다. **원문 그대로 적는다.**

> **새 기능**
> - editor 에서 파일 및 폴더 복사, 복제 기능
> - git change 에 폴더단위 staging/unstaging 추가
>
> **오류**
> - 메모장 메모가 제대로 저장되지 않는 오류
> - editor 에서 메모장이 안보이는 경우가 있음
> - 새 윈도우 만들 때 ~ (home) 이 아닌 현재 위치에서 만들어지는 오류
> - 메모리 누수인지 뭔지 메모리 너무많이먹음(순간적으로 30gb 넘음)
> - "자기 자신이나 자기 하위로는 옮길 수 없습니다" 가 지워지지 않음
> - editor 에서 한줄보기/줄바꿔보기 옵션 필요

**뒤에 하나가 더 접수됐다** (2026-09-05).

> - changes, untracked 에는 discard all 도 있어야하겠어

아홉은 규모도 성격도 다르다. 이 문서는 사실이 확정된 것부터 요구사항으로
굳혀 왔다 — 1차가 넷(묶음 X·W·C·N), 2차가 하나(묶음 S), **3차가 셋(묶음 D·P·F)**
이다. 마지막 하나(메모리)는 §5.1 에 착수 조건만 둔다 — 재현이 없는 것을
요구사항으로 적으면 무엇을 고쳤는지 말할 수 없다 (D-WBR-6).

### 1.2 범위 (Scope)

**포함(1차):** 탐색기 조작 실패 메시지의 수명 · 편집기 줄바꿈 옵션 · 새 창의 cwd ·
메모장 행이 사라지는 자리.

**포함(후속):** 메모 저장 · 저장하지 않은 편집의 보존 · `Changes`·`Untracked` 의
Discard All · 탐색기 복사/복제 · git 폴더 단위 스테이징.

**포함하되 재현 대기:** 메모리.

**비포함:** 편집기의 다른 옵션(글꼴·미니맵…)을 설정으로 여는 일 · diff 뷰의 줄바꿈 ·
편집기마다 따로 두는 줄바꿈 토글.

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 탐색기의 실패 메시지는 **성공한 조작**만이 지운다

`_fail(anchor,msg)` 는 `this._err={anchor,msg}` 에 남기고 다시 그린다
(`file-tree-paint.js:660`). 지우는 것은 `_clearErr()` 이고 **`_err=null` 만 할 뿐
다시 그리지 않는다** (`:661`).

`_clearErr()` 를 부르는 자리는 일곱이다 — 만들기·이름변경 입력의 시작과 취소
(`file-tree-edit.js:14·27·36·48·52`), 업로드의 시작(`file-tree-xfer.js:52`),
그리고 **끝난 조작의 뒷정리**(`_after`, `:167`).

`doRename` 은 그중에 없다. 자기 자신·자기 하위로의 이동은 서버에 가기 전에
클라이언트가 막고(FR-EDT-85, `file-tree-edit.js:160`) 곧바로 돌아오므로 **상태가
바뀌지 않는다.** 지울 계기가 영영 오지 않고, 그 뒤의 모든 다시 그리기(선택·펼치기·
git 폴링)가 그 줄을 **함께 다시 그린다.** 접수한 말 그대로다.

### 2.2 편집기 옵션은 전부 코드 안의 고정값이다

`monaco.editor.create` 의 인자 열여덟이 `file-editor.js:333~357` 에 리터럴로 있고
`wordWrap:'off'` 도 그중 하나다. **설정으로 열린 것은 하나도 없다.**

설정이 사는 자리는 **둘**이고 뜻이 다르다.

| 자리 | 무엇이 사는가 | 성질 |
|---|---|---|
| `localStorage` | `attnDesktop`·`attnSound`·`agentsPollMs`·`sidebarWidth` | **기기별**. 알림 권한과 화면 치수처럼 옮기면 뜻을 잃는 것 |
| `/api/settings` (`_saveSettings`) | `themeName`·`shortcuts`·`statusBar`·`layoutPresets`·`fgTabNames`·`pageTitle`·`confirmLeave`… | **취향**. 기기를 넘고 설정 내보내기에 담긴다 (SETTINGS_PORTABILITY_SRS) |

`_saveSettings` 는 **블롭 전체를 갈아치운다**(`app-settings.js:11`) — 읽어 쓰는 값이
그 리터럴에서 빠지면 다른 설정을 건드릴 때 조용히 사라진다. 새 값을 더할 때 함께
고쳐야 하는 자리다.

화면의 자리는 설정 다이얼로그이며, 편집기·언어 서버의 것은 `#panel-code`
(EDITOR_LSP_SRS 묶음 A)에 모인다.

### 2.3 새 창의 cwd 는 **서로 다른 두 장치**로 정해진다

| 길 | 무엇이 정하는가 | 근거 |
|---|---|---|
| `+` 버튼 | `_mkWindow` 가 포커스 칸에서 **승계** | FR-CWD-1, `app-layout.js:110-112` |
| `dmctl new-window` | 호출자 도구 id 를 `cwdTool` 로 **명시**해 보낸다 | FR-CWD-4, `dmctl.go:176` → `app-cmd.js:528` |

**둘은 섞이지 않는다.** `_mkWindow` 는 `opts.cwd` 나 `opts.cwdTool` 이 있으면 승계
계산 자체를 건너뛴다(`:111`). 즉 FR-CWD-1 을 폐기해도 팀 창은 흔들리지 않는다 —
착수 전 인터뷰에서 "함께 되돌아간다" 고 적었던 것은 **사실이 아니었다.**

`--cwd` 라는 플래그는 지금 없다. `--workdir` 은 **샌드박스 전용**이고
(`dmctl.go:80`) 그 값은 `args.workdir` → `opts.cwd` 로 들어간다(`app-cmd.js:528`).

### 2.4 메모장이 사라지는 자리가 하나 남아 있다

`_edApply(d)` 는 서버가 준 것 **전부**를 반영하고, `d.notes` 가 없으면 빈 문자열로
지운다(`app-editor.js:107-118`, FR-NOT-11). 그 실수를 막으려고 `_edPatchList` 가
있고, 그 주석에 선례가 적혀 있다 — "실제로 `notes` 를 더할 때 `app-cmd.js` 의 한
자리가 빠져 메모장 창이 워크스페이스 동기화 한 번에 사라졌다".

**같은 실수가 한 자리 더 있다.**

```js
// web/js/core/app.js:410 — `notes` 가 없다
this._edApply({home:this._editors.home, list:rem.editors.list});
```

그 경로는 워크스페이스 저장이 충돌한 뒤 **서버 값을 채택하는 재시도**다(FR-EDT-21).
평소에는 지나가지 않고 충돌한 순간에만 지나간다 — 접수한 말의 "경우가 있음" 과
맞는다.

### 2.5 아직 사실이 없는 것 둘

- **메모 저장.** `notes` 는 `DataDir/notes` **디렉터리**이고(`handlers_fs_stamp_test.go`)
  그 안의 파일은 일반 편집기 경로로 저장된다. 무엇이 "제대로 저장되지 않는" 지는
  재현 조건이 있어야 가른다.
- **메모리.** 사용자 관측은 "메모리 모니터에서 dongminal 이었던 것 같다" 이다.
  재현 조건이 없으므로 요구사항으로 적지 않는다 (D-WBR-6). 다만 **후보를 좁히는
  일은 재현 없이도 된다** — 그 결과가 §2.14 다.

### 2.14 메모리 — 무엇이 상한을 갖고 무엇이 갖지 않는지 (재현 없이 좁힌 것)

**서버(Go) 자신의 큰 경로는 전부 상한이 있다.** 코드로 확인했다.

| 자리 | 상한 |
|---|---|
| PTY 출력 버퍼 (`outbuf.Stream`) | `max` 보유, `2*max` 넘으면 앞을 버린다 |
| git 명령 출력 (`core.Service`) | `DefaultMaxOutput` **1MiB** (FR-GIT-6) |
| git job 의 보존 줄 | `lineCap`, stderr 는 200줄 |
| 탐색기 목록·삭제·복사 | `fsListMax`·`fsDeleteMax`·`fsCopyMax` = 10000 |
| 파일 내용 검색 | `fsGrepMaxBytes` **2MiB**, 넘으면 아예 읽지 않는다 |
| 폴더 zip 다운로드 | `zip.NewWriter(w)` 로 **스트리밍**한다 — 메모리에 담지 않는다 |
| 파일 읽기 (`/api/file/read`) | `io.Copy(w, f)` 로 **스트리밍**한다 |

상한이 없는 것은 **요청 본문**(`io.ReadAll(r.Body)`)뿐이고, 그것은 정상 사용이
아니라 `--expose` 의 공격면이다 (FILE_TRANSFER_SRS §6 이 이미 남긴 것과 같은 성질).

**가장 유력한 후보는 서버가 아니라 그 자식이다.**

| 근거 | 값 |
|---|---|
| 동시에 살아 있는 LSP 세션 상한 | **6** (`lsp/manager.go:18`, FR-LSP-19) |
| 쓰이지 않은 세션을 정지시키기까지 | **20분** (`:15`, FR-LSP-17) |
| 서버 | `gopls` · `typescript-language-server` · `pyright-langserver` … |

`gopls` 는 큰 모듈에서 수 GB 를 쓰는 것이 흔하고 `typescript-language-server` 도
그렇다. **여섯이 동시에 살면 자릿수가 맞는다.** 그리고 이들은 dongminal 이 띄운
**자식 프로세스**이므로 macOS 활성 상태 보기의 프로세스 트리는 그것을 부모 아래로
굴려 보여준다 — "메모리 모니터를 봤을 때 dongminal 이었던 것 같다" 와 맞는다.

**dongminal 은 이 자식들에 메모리 상한을 걸지 않는다.**

다음에 그 일이 나면 **먼저 확인할 것**은 이것이다:

```
ps -Ao rss,command | sort -rn | head -20
```

`gopls`·`*-language-server` 가 위에 있으면 원인이 좁혀지고, dongminal 자신이 위에
있으면 위 표의 상한 중 하나가 새는 것이므로 `pprof` 의 heap 으로 간다.

### 2.6 `Discard All` 에서 새로 세울 것은 **표면뿐**이다

`GIT_GROUP_BULK` 는 **그룹당 동작 하나**를 담는 map 이고(`constants-git.js:167`)
그리기도 그 모양이라 그룹 머리에 버튼을 하나만 만든다(`panel-changes.js:248-256`).
자료구조부터 바뀐다.

**그러나 명령의 분기는 이미 서 있다.** `_bulk(group,act)` 는 `_run` 을 지나고,
`_run` 은 `discard` 를 `_discard` 로 보내며, `_discard` 는 `i.group!=='untracked'`
로 tracked 와 untracked 를 가른다(`panel-files.js:182·197·258`). 서버의 `Discard`
도 둘을 따로 받아 `checkout -q` 와 `clean -q -f` 로 실행한다(`write/stage.go:86`).

### 2.7 discard 확인창이 권하는 명령은 untracked 에서 **실패한다**

`_discard` 는 recovery hint 로 `git stash push -- <경로들>` 을 보인다
(`panel-files.js:267`). **실측했다.**

| 대상 | `git stash push -- …` | `git stash push -u -- …` |
|---|---|---|
| untracked 만 | **실패** — `pathspec … did not match any file(s) known to git` | 성공 |
| tracked + untracked | **실패** — 하나도 stash 되지 않는다 | 성공 |
| tracked 만 | 성공 | 성공 — 다른 untracked 를 끌어오지 않는다 |

`-u` 를 **언제나** 붙이면 셋 다 옳다. 경로가 status 목록의 정확한 파일 이름이라
`-u` 가 대상을 넓히지 않는다는 것이 셋째 줄의 뜻이다.

같은 실수가 다른 자리에는 없다 — `Clean` 의 hint 는 이미 `git stash push -u` 이고
(`write/uncommitted.go:100`), hunk revert 의 것은 tracked 파일 하나다
(`write/patch.go:238`). **`panel-files.js:267` 한 자리다.**

GIT_ACTIONS_SRS FR-GIT-277 은 Clean 의 `-u` 를 적으면서 그것을 **"discard 의
선례"** 라 부른다. 선례가 아니었다 — 코드가 스펙이 말한 것보다 좁았다.

### 2.8 복사 종단이 없고, 있는 것들의 규약은 "거부" 다

`/api/fs/*` 는 `list`·`create`·`rename`·`delete`·`download`·`upload` 다
(`handlers_api.go:145-165`). **복사는 없다.**

있는 것들은 충돌을 전부 거부한다(FR-EDT-86·115 / FR-FTR-16). 그리고 **루트를
하나만 받는다** — `fsResolveTarget(root,…)` 이 `from` 과 `to` 를 같은 root 로
검사하므로(`handlers_fs.go:153`) 홈 트리와 저장소 트리 사이를 오갈 길이 없다.

자동 개명이 밟는 함정 하나를 실측했다 — Go 의 `filepath.Ext(".gitignore")` 는
**`".gitignore"` 를 돌려준다.** 순진하게 자르면 `" copy.gitignore"` 라는, 공백으로
시작하는 이름이 된다.

### 2.9 git 트리는 **그룹마다 따로** 서고, 플랫에는 폴더 행이 없다

`_emitTree(items, group, entries, limit)` 는 **그 그룹의 entries 만으로** 트리를
만든다(`panel-changes.js:437`). 그래서 `changes` 의 폴더 행 아래에는 `changes`
파일만 있다 — **"하위에 여러 그룹이 섞인다" 는 없는 문제다.**

반면 `_emitFlat` 은 파일만 depth 0 으로 낸다(`:429`). **플랫 보기에는 폴더 행이
아예 없다.**

### 2.10 브라우저는 OS 클립보드로 파일을 나를 수 없다

이 저장소가 이미 실측해 문서로 남긴 사실이다(`term-clipboard.js:12-17`,
EXPLORER_TRANSFER_IGNORE_SRS 묶음 F / FR-ETR-40 / D-12).

| 방향 | 되는가 |
|---|---|
| 웹 → OS 로 **파일** | **절대 안 된다.** 클립보드에 담기는 것은 text·html·image 뿐이라, Finder·탐색기가 붙여넣기로 받는 형식을 웹이 쓸 수 없다 |
| 웹 → OS 로 **경로 글자** | 환경이 정한다. `navigator.clipboard` 는 **secure context(https·localhost)에서만 존재해** 원격 접속(`http://100.x`)에는 없다 |
| OS → 웹으로 **파일** | 된다(Chromium). 그러나 그것은 바이트가 올라오는 것 = **업로드**이고 `/api/fs/upload` 와 드래그&드롭이 이미 한다 |
| OS 클립보드 **되읽기** | 사실상 못 쓴다 — 크롬은 권한을 묻고 파이어폭스는 노출하지 않는다 |

**§6 비목표 6(외부 접속의 알림)을 죽인 것과 같은 벽이다.**

### 2.11 저장이 날아가 있는 동안 뷰가 파괴되면 **문서에 자국이 남는다**

`save()` 는 문서의 값을 뷰의 참조로 만진다 (`file-editor.js:495·496·515`).

```js
if (this._doc && this._doc.saving) return;   // 495
if (this._doc) this._doc.saving = true;      // 496
…  await fetch('/api/file/write', …)         // 그 사이에 destroy() 가 올 수 있다
this._dirty = false;                         // 505
} finally { if (this._doc) this._doc.saving = false }   // 515
```

`destroy()` 는 `this._doc = null` 로 끊는다 (`:915`). 그래서 저장이 날아가 있는
동안 그 뷰가 파괴되면 **`finally` 의 조건이 거짓**이 되어 공유 문서의 `saving` 을
내리지 못한다. 문서는 `_edDocs` 에 살고 **다른 칸이 붙들고 있으면 남으므로**
(`app-editor.js:401-408`, FR-SVS-55) 그 기록이 살아남고, 495 가 그 뒤 **그 파일의
모든 저장을 조용히 건너뛴다.**

**같은 창에 둘째 결과가 있다.** `set _dirty(v){ if(this._doc) this._doc.dirty=v;
else this.__dirty=v }` 이므로(`:208`) 505 의 `this._dirty=false` 는 파괴된 뒤에
**죽은 필드**에 쓴다. 쓰기는 성공했는데 공유 문서가 `dirty:true` 로 남아 다른 칸의
탭에 저장 안 됨 표시가 남고, 재조정이 그 창을 붙들며(FR-WBR-40) 미룬 사실까지
알린다(FR-WBR-41) — **이미 디스크에 있는 내용을 두고서다.**

닿기 어려운 경로가 아니다. 미리보기 탭은 탐색기에서 다른 파일을 누를 때마다
편집기를 파괴한다 (`app-layout.js:430-435`).

### 2.12 소프트 리로드의 트리 갱신은 **죽어 있다**

```js
// app-reload.js:50-54
for(const w of this._edWindows())
  if(w&&w.editor&&typeof w.editor.refresh==='function') w.editor.refresh();
```

`w.editor` 는 창 레코드의 `{root, side, explorerWidth}` 라 `refresh` 가 없다.
`typeof` 가드 때문에 **조용히 아무 일도 하지 않는다.** 살아 있는 트리 뷰는
`_edTrees` 에 있고(`app-editor.js:431-438`) 그쪽에 `refresh()` 가 있다
(`file-tree-paint.js:93` — FR-EDT-64, 펼쳐진 겹만 다시 읽고 펼침을 보존한다).

### 2.13 `_paneNewToolRef` 의 editor 분기에는 **닿는 길이 있다**

D-WBR-8 이 "확인하지 못해 남겨 둔다" 고 적은 자리다. **확인했다 — 남겨야 한다.**

호출자는 둘이다. `_splitInner` 는 `_isEditorWin(s)` 면 먼저 돌아가고(FR-EDT-50·51)

| 가드 | 무엇 |
|---|---|
| `app-layout.js:344` | Editor 창에서는 `editor`·git 말고 못 만든다 → 터미널 탭이 여기 오지 않는다 |
| `app-layout.js:348` | 편집기 탭은 일반 창에 생기지 않는다 — **`this._edOn()` 일 때만이다** |

`_edOn()` 은 `/api/editors` 가 실패하면 거짓이고(`app-editor.js:24`, FR-EDT-120),

**FR-WBR-4. 자기 자신·자기 하위로의 이동 거부(FR-EDT-85)도 같은 규약을 따른다.**

### 3.5 묶음 S — 저장하지 않은 편집의 보존

**FR-WBR-40. 재조정은 저장하지 않은 편집이 있는 Editor 창을 지우지 않는다.**
그 창은 편집이 저장되거나 버려질 때까지 남는다.

지금은 루트가 `_edRoots()` 에서 빠지면 창 레코드를 **통째로 splice** 하고
(`app-editor.js:214·221`), 그 순간 그 창의 탭 id 가 사라져 렌더러의 회수기가
편집기를 파괴하며(`renderer.js:235`) `_edDocDrop` 이 **모델까지 dispose** 한다 —
저장하지 않은 편집이 **묻지도 알리지도 않고** 사라진다.

**탭을 닫을 때는 이미 묻고 있다** (`app-layout.js:519`: dirty 면 저장·버림·취소를
묻는다). 같은 손실을 다른 길에서는 조용히 낸다.

**FR-WBR-41. 미룬 사실을 알린다.** 목록과 창이 어긋난 채로 남으므로 그 이유가
화면에 없으면 "지웠는데 안 지워진다" 가 된다.

**FR-WBR-42. 편집이 사라지면 다음 재조정이 그 창을 거둔다.** 미루는 것이지
면제가 아니다.

**메모장이 유독 약한 이유.** `_edRoots()` 는 `[home, notes?, ...list]` 인데 `home`
은 없으면 `_edApplyServer` 가 반영 자체를 포기하는 반면 **`notes` 는 선택적이라
응답 한 번에 빈 문자열이 된다** (FR-NOT-11). 그 순간 메모장 창이 통째로 지워진다.
FR-WBR-30 이 고친 자리(`app.js` 의 충돌 재시도)가 그 방아쇠 하나였다.

### 3.6 묶음 D — `Changes`·`Untracked` 의 Discard All

**FR-WBR-50. 그룹 머리는 동작을 여럿 담는다.** 지금은 그룹당 하나다(§2.6).
`Changes` 와 `Untracked` 가 스테이지와 폐기를 함께 갖는다.

**FR-WBR-51. 폐기가 오른쪽이다.** 행 동작의 원칙 — "파괴적인 것이 손에서 가장
멀다"(FR-GIT-236) — 이 그룹 머리에도 온다.

**FR-WBR-52. 일괄 동작은 행 동작과 같은 어휘의 아이콘이다** — `+`·`−`·`↺`
(`GIT_ACT_LABEL`). 글자 라벨(`Stage All`)을 버린다.

> **개정 (D-WBR-18).** 처음 판은 글자 라벨을 그룹마다 갈랐다 —
> `Discard All` / `Delete All`. **실측이 그것을 뒤집었다**: 기본 폭 220px 에서
> 머리 안쪽은 203px 인데 `Stage All`(61)+`Discard All`(70)+간격은 **136** 이고
> 이름·개수·caret 이 쓰고 남는 자리는 **80** 뿐이다. 이름을 60px 하한까지 눌러도
> 99 라 모자라고, `Stage`·`Discard` 로 줄여도(115) 모자란다. **글자 라벨 둘은
> 어떤 조합으로도 220px 에 들어가지 않는다.** 줄을 늘리면 머리가 36→71px 이 되어
> **FR-GIT-220**(머리글 높이가 일괄 버튼의 유무로 달라지면 안 된다)을 깨고, 밀린
> 목록의 행이 화면 밖으로 나갔다(실측). 아이콘 둘은 65px 라 여유 15px 로 선다.

**FR-WBR-52a. 갈리는 것은 라벨이 아니라 툴팁이다.** `Changes` 의 `↺` 는 "변경
전부 버리기", `Untracked` 의 `↺` 는 **파일이 삭제되고 되살릴 수 없다**는 것을
말한다. 두 그룹의 명령이 다르다는 사실(§2.6)은 그대로이므로, 그것을 말하는 자리만
옮긴다. 누른 뒤의 확인창은 여전히 갈린다 (FR-WBR-55).

**FR-WBR-52b. 아이콘 버튼의 히트 영역은 행 동작과 같다** — `--git-hit`(30px).
FR-GIT-226 이 아이콘 버튼과 라벨 버튼의 하한을 이미 30px 하나로 모았으므로 새 값이
생기지 않는다.

**FR-WBR-53. 비활성 판정은 버튼마다 따로다.** 지금은 그룹의 유일한 버튼에
`disabled=!entries.length` 를 건다(`panel-changes.js:380`). 버튼이 둘이 되면 둘 다
그 판정을 받는다.

**FR-WBR-54. `Conflicts` 는 대상이 아니다.** 그 그룹의 해결은 `ours`·`theirs`·
`stage` 이고 폐기는 그중에 없다.

**FR-WBR-55. 확인창의 note 가 그룹에 맞춰 갈린다.** untracked 가 대상에 있으면
**파일 자체가 삭제되며 되살릴 값이 없다**는 사실을 먼저 적는다. 서버의
`discardHint` 가 실행 **뒤에** 적는 것과 같은 뜻을, 실행 **전에** 화면이 말한다.

**FR-WBR-56. discard 의 recovery hint 명령은 언제나 `-u` 를 갖는다** —
`git stash push -u -- <경로들>`. 지금 명령은 untracked 가 섞이기만 해도 실패하며
**하나도 stash 되지 않는다**(§2.7). 되살릴 길을 안내한다면서 듣지 않는 명령을
주고 있었다.

> **이전 동작 / 새 동작 / 이유.** 이전: `git stash push -- <경로들>`. 새:
> `git stash push -u -- <경로들>`. 이유: untracked 가 있으면 실패하고, tracked
> 만일 때 `-u` 를 붙여도 대상이 넓어지지 않는다(§2.7 실측). **그룹 일괄만이 아니라
> 행의 `↺` 도 같은 자리를 지나므로 함께 고쳐진다.**

> **바뀌는 시험.** `git-staging` **E8** 이 `git stash push -- tracked.txt` 를
> 단언한다(`:157`) — 그 줄이 함께 고쳐진다. 나머지 `stash push` 단언은 영향이
> 없다: `git-confirm`·`git-dialog` 는 hint 를 **시험이 직접 만들어** 확인창에
> 넘기고, `git-hunk` 와 `write/patch_test.go` 는 hunk revert(서버가 만드는 tracked
> 파일 하나)이며, `git-file-actions` F12 는 이미 `-u` 를 본다.

### 3.7 묶음 P — 탐색기의 복사·복제

**FR-WBR-60. `POST /api/fs/copy` 를 신설한다.** 서버가 자기 파일시스템 안에서
복사한다 — 파일 바이트가 브라우저를 오가지 않으므로 **브라우저가 어느 기기에
있든 결과가 같다.**

**FR-WBR-61. 루트를 둘 받는다.** `{srcRoot, src, dstRoot, dstDir}` 이고 **둘 다**
Editor 목록에 있어야 한다(FR-EDT-87·112 의 검사를 두 번 한다). 홈 트리에서
복사해 저장소 트리에 붙여넣는 길이 이것뿐이다. **`rename` 은 손대지 않는다** —
이동의 뜻은 이 판이 정한 것이 아니다.

**FR-WBR-62. 대상은 디렉터리를 받고, 최종 이름은 서버가 정한다.** 개명이 서버의
일이므로(FR-WBR-63) 이름을 클라이언트가 미리 정할 수 없다. 응답이 **만들어진
경로**를 돌려준다 — 트리가 그 행을 골라 보이는 데 쓴다.

**FR-WBR-63. 이름이 충돌하면 서버가 개명한다** — `name` → `name copy` →
`name copy 2` → `name copy 3` …

- 확장자가 있으면 그 **앞**에 넣는다: `a.txt` → `a copy.txt`.
- **점으로 시작하는 이름은 확장자가 없는 것으로 본다** — `.gitignore` →
  `.gitignore copy`. `filepath.Ext` 를 그대로 믿으면 공백으로 시작하는 이름이
  된다(§2.8, 실측).
- 충돌하지 않으면 **이름을 바꾸지 않는다.** 다른 폴더로 복사하는 흔한 길에서
  이름이 달라지면 그것이 놀라움이다. "복제" 는 언제나 충돌하므로 언제나 개명된다.
- **덮어쓰기는 여전히 어디에도 없다.** FR-EDT-86 이 금하는 둘 중 덮어쓰기는 그대로
  지키고, **자동 개명만** 이 종단이 갖는다.

**FR-WBR-64. 자기 자신·자기 하위로는 복사할 수 없다 — 서버가 막는다.**
이동(FR-EDT-85)은 클라이언트만 막고 있으나, 복사는 막지 않으면 **무한 재귀**로
디스크를 채운다. 판정은 심볼릭 링크를 푼 뒤의 경로로 한다.

**FR-WBR-65. 심볼릭 링크는 따라가지 않고 링크 자체를 복사한다.** 순환과 뿌리
이탈을 한 규칙으로 막는 기존 판단을 잇는다(EDITOR_TAB_SRS FR-EDT-85 의 근거).

**FR-WBR-66. 항목 수에 상한이 있다.** 삭제와 같은 규약이다 — **먼저 세고**, 상한을
넘으면 시작하지 않는다(FR-EDT-118). 값은 `fsDeleteMax` 와 같은 자리에 둔다.

**FR-WBR-67. 도중에 실패하면 만들다 만 것을 거둔다.** 대상 이름은 서버가 방금
만든 것이므로 지워도 사용자의 것을 잃지 않는다 — 절반만 복사된 트리가 남는 것보다
낫다.

**FR-WBR-68. 파일 모드를 보존한다.** 실행 비트가 사라지면 복사한 스크립트가 돌지
않는다.

- **재는 것은 "원본과 같은가" 다.** Windows 에는 실행 비트가 없어 `os.Chmod` 가
  읽기전용 비트만 만지고 `Perm()` 은 `0666` 을 돌려준다 (CI 실측). "0755 인가" 로
  재면 코드가 아니라 시험의 전제가 플랫폼을 탄다.

**FR-WBR-70. 메뉴에 셋을 더한다** — `복사`·`붙여넣기`·`복제`.

- `붙여넣기` 는 **복사한 것이 없으면 비활성**이고, 사유를 툴팁이 말한다
  (`download` 의 링크 규약과 같다).
- 붙여넣는 자리는 우클릭한 행이 정한다 — 폴더면 그 안, 아니면 그 형제
  (FR-EDT-81 과 같은 규칙이며 지금 `dir` 계산 그대로다).
- `복제` 는 원본의 **형제** 자리에 붙여넣는 것과 같다 — 종단이 하나인 이유다.

**FR-WBR-71. "무엇을 복사했는가" 는 앱이 든다.** dongminal 의 **모든 창·분할 칸·
탐색기**가 공유하고, **새로고침이면 비운다.** 서버에도 `localStorage` 에도 두지
않는다 — 무기한 사는 상태는 "언젠가 복사한 것" 이 메뉴에 남는다는 뜻이다.

**FR-WBR-72. OS 클립보드는 쓰지 않는다.** 쓸 수 없기 때문이다(§2.10) — 웹은 파일을
클립보드에 올릴 수 없고, `navigator.clipboard` 는 secure context 밖에서 아예 없다.

**FR-WBR-73. 원본이 사라졌으면 붙여넣기가 실패하고 그 자리에 사유가 붙는다** —
조작 실패 메시지의 규약 그대로다(FR-EDT-92 / FR-WBR-1~4).

**FR-WBR-74. 조작 뒤에는 영향받은 폴더만 다시 읽는다**(FR-EDT-88). 복사는 대상
폴더 하나다.

### 3.8 묶음 F — git Changes 의 폴더 단위 스테이징

**FR-WBR-80. 트리 보기의 폴더 행이 그 그룹의 동작을 갖는다.** `staged` 는
언스테이지, `changes`·`untracked` 는 스테이지다 — 그룹이 이미 무엇을 할 수 있는지
가른다(`GIT_ROW_ACTS` 와 같은 근거).

**FR-WBR-81. 대상은 그 폴더 아래 전부다** — 그려진 행이 아니다. 목록이 잘려 보이는
것(`GIT_FILE_ROW_CHUNK`)과 대상 범위는 별개이며 **접힌 폴더도 같다**. `_bulk` 의
규약(FR-GIT-66·67)을 폴더로 좁힌 것이다.

**FR-WBR-82. 한 그룹 안이다.** 트리가 그룹마다 따로 서므로(§2.9) 폴더 행은 한
그룹에만 속한다. 다른 그룹의 같은 이름 폴더는 **다른 행**이고 서로를 건드리지
않는다.

**FR-WBR-83. 플랫 보기에는 두지 않는다.** 거기에는 폴더 행이 없다(§2.9). 플랫은
"경로를 펼쳐 다 보여준다" 가 뜻이므로 폴더라는 단위가 없는 것이 일관된다.

**FR-WBR-84. 폐기는 두지 않는다.** 접수한 말은 staging/unstaging 이다.

### 3.10 묶음 R — 인계가 남긴 조사 셋

**FR-WBR-90. `saving` 은 문서의 것이므로 문서로 내린다.** 저장을 시작한 뷰가 그
사이에 파괴돼도 기록이 남지 않는다 (§2.11).

> **이전 동작 / 새 동작 / 이유.** 이전: `finally` 가 `this._doc` 을 거쳐 내려,
> 파괴된 뷰에서는 내리지 못했다. 새: 저장을 시작할 때 잡은 문서로 내린다.
> 이유: 플래그의 임자는 문서이고, 그것을 놓는 일이 **뷰가 아직 그 문서를 들고
> 있는지**에 달릴 이유가 없다.

**FR-WBR-91. 저장이 성공하면 문서의 dirty 가 내려간다** — 뷰가 파괴된 뒤라도.
지금은 죽은 필드에 써서 쓰기가 성공해도 문서가 dirty 로 남는다 (§2.11).

**FR-WBR-92. 저장 뒤의 탭 표시 갱신도 문서를 딛는다.** 같은 이유다.

**FR-WBR-95. 소프트 리로드가 열린 겹을 실제로 다시 읽는다** (§2.12). 대상은
`_edTrees` 의 살아 있는 트리 뷰이고, 각 뷰의 `refresh()`(FR-EDT-64)가 펼쳐진 겹만
읽어 펼침을 보존한다.

- 같은 루트를 보는 칸이 여럿이어도 요청은 한 벌이다 — `_busy` 가 store 로
  위임하므로(`file-tree.js:86`) 둘째 호출이 그 자리에서 돌아간다 (FR-SVS-20).

### 3.9 비기능 요구 (NFR)

**NFR-WBR-1.** 줄바꿈 전환이 편집 중인 내용을 잃지 않는다 — 옵션 갱신이지 편집기
재생성이 아니다.

**NFR-WBR-2.** 실패 메시지의 수명이 늘어난 지우기 계기 때문에 **더 짧아지지
않는다** — 실패한 그 순간의 다시 그리기(낙관적 되돌림)는 지우는 계기가 아니다.

**NFR-WBR-3. 재조정은 확인창을 띄우지 않는다.** 그것은 서버 상태를 반영하는
비동기 경로이고 SSE 로 아무 때나 불린다 — 사용자의 답을 기다리는 동안 화면과
워크스페이스가 어긋난 채 멈춘다. 탭 닫기(사용자가 지금 한 조작)와 규약이 다른
이유가 그것이다. **묻는 대신 미룬다.**

**NFR-WBR-10. 기본 폭에서는 한 줄이고, 모든 그룹 머리의 높이가 같다**
(FR-GIT-220). 아이콘을 고른 이유가 이것이다 — 220px 에서 여유 15px 로 선다.

**NFR-WBR-10a. 하한 폭에서는 줄을 늘린다** (NFR-RTU-6 / FR-RTU-101). 100px 에서는
아이콘 둘이어도 이름 60px 을 지킬 수 없으므로, 감추지 않고 머리를 두 줄로 늘린다 —
`.git-file` 행이 `conflicts` 에서 이미 그렇게 한다. 측정은 두 폭에서 한다 —
**기본 220px(한 줄·높이 균일) 과 하한 100px(이름 60px·버튼 전부 닿음)**.

머리 클릭이 접기라는 뜻은 그대로다. 버튼은 `stopPropagation` 으로 그것을 일으키지
않는다(지금 규약).

**NFR-WBR-11. 폴더 행도 같은 규약을 받는다.** 행 클릭이 접기라는 뜻을 가지므로
이름의 60px 하한이 그대로 온다(NFR-RTU-6).

**NFR-WBR-12. 복사는 브라우저의 기기를 타지 않는다.** 원본도 대상도 서버에 있고
경로만 오간다(FR-WBR-60). 유일하게 기기를 타는 것은 "무엇을 복사했는가" 이며 그것은
의도된 것이다(FR-WBR-71).

**NFR-WBR-13. 복사가 실패해도 사용자의 것을 잃지 않는다.** 덮어쓰지 않고
(FR-WBR-63), 만들다 만 것만 거둔다(FR-WBR-67).

**NFR-WBR-4. 재조정이 저장을 대신하지 않는다.** 지우기 전에 조용히 저장하면
사용자가 버리려던 내용이 디스크에 남는다 — 요청하지 않은 쓰기다.

| Discard All | 라벨을 가른다(`Discard All` / `Delete All`) · 좁은 폭은 줄을 늘린다 · 확인창의 note 를 그룹에 맞춰 가른다 |
| 복사·복제 | `복제` + `복사`/`붙여넣기` 둘 다 · 충돌은 서버가 개명 · 클립보드는 앱 안(새로고침이면 비운다) · 루트 교차 허용 |
| 폴더 스테이징 | 트리 보기에서만 |

**조사가 인계의 전제 둘을 뒤집었다.**

- "하위에 여러 그룹이 섞였을 때 무엇을 스테이지하는가" 는 **없는 문제였다** —
  트리가 그룹마다 따로 선다(§2.9).
- "두 그룹의 discard 는 같은 명령이 아니다" 는 맞으나, **분기는 이미 코드에
  서 있었다**(§2.6). 남은 것은 표면뿐이다.

### 5.3 순서

1. **묶음 D** — 표면만 바뀌고 명령 분기가 이미 있다. `-u` 결함(§2.7)이 여기 딸린다.
2. **묶음 P** — 서버 종단이 새로 생기므로 Go 시험이 먼저다.
3. **묶음 F** — D 가 만든 "그룹 머리의 여러 동작" 규약을 폴더 행이 물려받는다.
4. **메모리** — 재현이 먼저다(§5.1).

## 6. 비목표 (Non-goals)

1. **편집기 옵션 전반의 설정화.** 이번에 여는 것은 줄바꿈 하나다.
2. **diff 뷰의 줄바꿈.** 그쪽은 두 축을 나란히 놓는 화면이라 근거가 다르다.
3. **편집기마다 따로 두는 줄바꿈.** 설정이 둘이면 두 동작을 다 검증해야 한다
   (REPO_TAB_UNIFY 비목표 6 과 같은 이유).
4. **실패 메시지에 닫기 버튼.** 수명 규약으로 푸는 문제다 (FR-WBR-2).
5. **`--cwd` 의 상대경로.** 절대경로만 받는다 — 상대경로는 무엇을 기준으로 하는지
   호출자와 서버가 다르게 안다.
6. **외부 접속에서의 데스크톱 알림.** 접수했고(2026-09-04) **조사 끝에 사용자가
   넘기기로 정했다.** 다시 조사하지 않도록 결론만 적는다 — 브라우저가 알림을
   **보안 컨텍스트**(https 또는 `localhost`)에서만 허용한다. 본 컴퓨터의
   `http://localhost:포트` 는 그 조건을 만족하지만 밖에서 `http://<LAN IP>:포트` 로
   붙으면 아니다. 크롬은 권한을 `denied` 로 고정하고 파이어폭스는 `Notification`
   자체를 노출하지 않으며, 어느 쪽이든 `app-attn.js:335·391` 의 가드에 걸려 조용히
   아무 일도 하지 않는다. **코드로 뚫을 수 없다** — https 종단(자체 서명·Tailscale·
   역방향 프록시)이나 SSH 터널로 클라이언트를 `localhost` 로 만드는 것이 유일한
   길이다. 사운드(`_attnBeep`)는 그 제약이 없어 외부에서도 울리지만, 사용자가
   **"소리만 되는 건 의미없다"** 로 판단해 이 판에서 손대지 않는다 — 조용한 실패를
   화면이 말하게 하는 것(체크박스가 켜진 채 남는다)도 함께 미룬다.

7. **폴더 행의 폐기(discard).** 접수한 말은 staging/unstaging 이다 (FR-WBR-84).
8. **플랫 보기의 폴더 단위 동작.** 거기에는 폴더 행이 없다 (FR-WBR-83).
9. **덮어쓰기 선택지.** 복사가 자동 개명을 갖게 되어도 **덮어쓰기는 어디에도
   없다** — FR-EDT-86 이 금하는 둘 중 그쪽은 그대로다 (FR-WBR-63).
10. **잘라내기·붙여넣기.** 이동 수단은 드래그 하나로 둔다 (FILE_TRANSFER_SRS §6 을
    잇는다). 이 판이 더하는 것은 **복사**뿐이다.
11. **경로를 OS 클립보드에 글자로 복사하는 항목.** 접수한 말에 없다. `navigator.clipboard`
    가 secure context 밖에서 없으므로 두려면 3단 폴백(FR-ETR-40)을 함께 들여야 한다.
12. **`rename` 의 루트 교차.** 복사만 두 루트를 받는다 (FR-WBR-61) — 이동의 뜻은
    이 판이 정한 것이 아니다.
