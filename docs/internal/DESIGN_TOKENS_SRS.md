# SRS: 디자인 토큰 — 색·크기·글자·z-index 의 목록과 파생 규칙 (IEEE 29148)

> **문서 상태**: 승인·구현중

- 접수: 2026-09-12 (로드맵 M7 선행 SRS ② · `style-kit.css` 머리말 D-5 가 종료
  조건 없이 열어 둔 것)
- 마일스톤: M7. 짝은 [ACCESSIBILITY_BASELINE_SRS](./ACCESSIBILITY_BASELINE_SRS.md)
  (선행 SRS ①) — **무엇을 만족해야 하는가**는 그쪽이, **어떻게 보장하는가**는
  이 문서가 소유한다.
- 딛는 것: [UI_KIT_SRS](./UI_KIT_SRS.md). 그 문서가 **크기** 토큰을 세웠고
  **색은 소유하지 않는다**(FR-UIK-2)고 적었다. 이 문서가 그 빈자리를 채운다.

---

## 1. 개요

### 1.1 목적

`UI_KIT_SRS` 가 크기 토큰(`--ui-btn-h`·`--ui-radius`·`--ui-icon-*`)을 세울 때
색은 명시적으로 비켜 갔다.

> 색은 소유하지 않는다 (FR-UIK-2). `--accent`·`--border`·`--text-*`·`--danger`
> 는 style.css 의 :root 와 테마가 준다.

그 판단은 그때 옳았다 — 키트의 일이 아니었다. 그러나 **아무도 소유하지 않게
됐다.** 결과가 §2 다: 글자 크기 12종이 토큰 없이 흩어졌고, z-index 값 28종이
서로를 모른 채 커졌으며, Tokyo Night 의 색 값이 CSS 안에 160곳 박혔고,
정의되지 않은 `--bg-alt` 를 네 곳이 읽는다. 그리고 **248개 글자 선언이 어떤
테마에서도 AA 를 넘지 못하는 토큰 위에 서 있다**(§2.1).

이 문서는 넷을 정한다: **토큰 목록 · 파생 규칙 · 하드코딩 금지 게이트 ·
과도기 클래스의 종료 조건.**

### 1.2 범위

**포함**
- 색 토큰의 **목록과 뜻**, 대비 보장을 위한 **파생 규칙** (§3.1·§3.2)
- 글자 크기 토큰 5종 · z-index 계층 토큰 5종 · 백드롭·그림자 토큰 (§3.3·§3.4)
- 하드코딩 금지 게이트 · 미정의 커스텀 프로퍼티 게이트 · 포커스 짝 게이트 (§3.6)
- `style-kit.css` D-5 **과도기 클래스의 종료 조건** (§3.7)
- 테마 54종 팔레트의 **원본 값 보존** — 파생은 팔레트를 고치지 않는다

**비포함**
- 접근성 기준·검사 방법 → `ACCESSIBILITY_BASELINE_SRS`
- 테마 팔레트의 **미적 선택** (어떤 색이 예쁜가). 이 문서는 **계산 가능한 제약**만
- 터미널(xterm) ANSI 팔레트 — `t.terminal` 은 터미널 텍스트의 몫이고 UI 토큰이
  아니다 (`helpers.js` 의 SLOT_EDGE_MIX 주석이 같은 이유를 적었다)
- Monaco 편집기 테마 — `FileEditor.applyTheme()` 가 별도로 파생한다
- 레이아웃 규약(사이드바 폭·분할 비율) — `UI_KIT_SRS` 비포함과 같다

### 1.3 정의

| 용어 | 정의 |
|------|------|
| **팔레트** | `themes.js` 의 `ui` 객체. 테마의 **정본 값**이다 — 이 문서는 고치지 않는다 |
| **토큰** | `--xxx` CSS 커스텀 프로퍼티. 쓰는 자리가 보는 유일한 이름 |
| **파생 토큰** | 팔레트 값에서 **계산해서** 세우는 토큰. `applyThemeObj` 가 만든다 |
| **바닥(floor)** | 그 토큰이 배경에 대해 넘어야 하는 최소 대비 |
| **앵커** | 파생이 섞어 가는 방향의 색. 대비를 올리는 쪽 끝 |
| **참조 배경** | 대비를 재는 상대. `--bg` 와 `--sidebar-bg` **둘 다** (§3.2) |
| **과도기 클래스** | 키트 도입 때 지우지 않고 남긴 옛 클래스 (`.tbtn` 등, D-5) |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 색 — 글자가 읽히지 않는다

테마는 **54종**이다 (dark 43 · light 11). 로드맵이 적은 "44개" 는 낡았다.

`--bg` 대비 (WCAG 2.1 상대휘도):

| 토큰 | 최소 | 중앙값 | 최대 | ≥ 4.5:1 |
|---|---|---|---|---|
| `--text-bright` | 4.99 | 13.24 | 19.03 | 54/54 |
| `--text` | 4.13 | 9.84 | 19.03 | 53/54 |
| `--accent` | 2.69 | 5.90 | 15.89 | 45/54 |
| `--danger` | 2.80 | 4.77 | 7.84 | 33/54 |
| `--text-muted` | 1.69 | 3.21 | 6.15 | **10/54** |
| `--text-dim` | 1.09 | 1.28 | 1.91 | **0/54** |

쓰이는 방식:

| 토큰 | `color:` | `background:` | `border*:` | 합 |
|---|---|---|---|---|
| `--border` | 2 | 26 | 188 | 226 |
| `--accent` | 96 | 20 | 71 | 215 |
| `--text-muted` | **149** | 2 | 0 | 155 |
| `--text-bright` | 103 | 3 | 0 | 110 |
| `--text-dim` | **99** | 3 | 2 | 106 |
| `--danger` | 57 | 1 | 24 | 86 |
| `--text` | 73 | 0 | 0 | 80 |
| `--attn` | 49 | 4 | 13 | 78 |

**`--text-dim` 은 99번 글자로 쓰이고 54종 어디서도 3:1 조차 넘지 않는다.**

### 2.2 `--bg-alt` 는 정의된 적이 없다

7곳이 읽는데 `:root` 에도 `applyThemeObj` 의 맵에도 없다.

| 자리 | 꼴 | 결과 |
|---|---|---|
| `style.css:159` · `:564` | `var(--bg-alt)` | **투명으로 떨어진다** |
| `style-git.css:587` | `var(--bg-alt)` | 〃 |
| `style-git-views.css:94` | `var(--bg-alt)` | 〃 |
| `style-docrender.css:16` · `:63` · `:150` | `var(--bg-alt,var(--bg))` | 폴백이 받는다 |

**폴백을 적은 셋과 적지 않은 넷이 같은 파일 묶음에 있다** — 이것이 토큰에
목록이 없을 때 생기는 일이다. 로드맵이 센 "4곳" 은 폴백 없는 넷이고 정확하다.

### 2.3 하드코딩된 색 160곳

| 파일 | 색 리터럴 |
|---|---|
| `style.css` | **119** |
| `style-editor.css` | 17 |
| `style-git-views.css` | 10 |
| `style-kit.css` | 8 |
| `style-git.css` | 5 |
| `style-docrender.css` | 1 |

가장 많은 것은 `rgba(0,0,0,…)` **67회**(그림자·백드롭)다. 그다음이 **Tokyo Night
팔레트 값**이다 — `#16161e`(sidebarBg) 7회, `#7aa2f7`(accent) 3회,
`rgba(247,118,142,…)`(danger) 10회, `#1a1b26`(bg) 2회. 기본 테마에서만 맞고
나머지 53종에서 어긋난다 (`UX-14`).

### 2.4 글자 크기 12종

실측: `7px 8px 9px 10px 11px 11.5px 12px 13px 14px 15px 18px 20px`.

`11px` 과 `11.5px` 이 함께 있고 `13·14·15` 가 함께 있다 — 어느 것도 뜻으로
갈리지 않는다. `UI_KIT_SRS` 가 `--ui-font:11px` 하나를 세웠으나 키트 밖은 그것을
모른다.

### 2.5 z-index — 44 선언 · 28 값 · 1~9999

의미의 층이 값에서 읽히지 않는다. 실측으로 드러난 어긋남:

| 무엇 | 값 | 문제 |
|---|---|---|
| `#modal-overlay` (설정 모달) | 100 | 같은 뜻인데 |
| `.ui-modal` · `.confirm-overlay` · `.bg-modal` | 200 | 값이 다르다 |
| `.toast-host` 420 · `.git-undo-toast` 400 | | 같은 토스트가 둘 |
| `.ui-menu` · `.git-menu` | 3000 | 모달보다 훨씬 위 — 뜻은 맞으나 간격이 근거 없다 |
| `.ed-find` 9997 · `.tc-copy` 9999 | | **메뉴보다 위**. 편집기 찾기 줄이 컨텍스트 메뉴를 덮는다 |
| `#boot` 1000 · `#focus-edge` 500 · `#attn-edge` 501 | | 각자 정한 값 |

`9997`·`9999` 가 요점이다 — **위에 있어야 한다는 뜻을 값으로 말할 방법이 없어서
큰 수를 골랐다.** 층이 이름을 갖지 않으면 매번 그렇게 된다.

### 2.6 포커스 — `outline:none` 17 vs `:focus-visible` 9

차이 8 이 `UX-13` 이다. 지운 자리와 되살린 자리가 짝이 맞지 않는다.

### 2.7 과도기 클래스 — D-5 가 종료 조건 없이 열려 있다

`style-kit.css` 머리말:

> **기존 클래스를 지우지 않는다** (D-5 / FR-UIK-10). `.ui-btn` 은 `.tbtn` 과
> 함께 붙는다 — e2e 131개와 기존 캐스케이드가 옛 이름 위에 서 있다.

그 판단의 근거 중 **e2e 쪽 절반은 M6 이 없앴다.** `TEST-18` 판정이 확인한 것은
e2e 가 짚는 것이 **도메인 클래스**(`.sbl-item`·`.pn-tab`)이고 CSS 정리가 바꾸는
것은 **선언**이라는 사실이다. 키트 클래스를 단독으로 짚던 자리는 두 곳뿐이었고
둘 다 닫혔다 (`M6_PROGRESS.md` §4).

남은 절반은 **캐스케이드**다. 그것은 여전히 사실이고, 그래서 D-5 를 철회하는
것이 아니라 **끝나는 조건을 준다** (§3.7).

## 3. 요구사항

### 3.1 색 토큰의 목록과 뜻

| ID | 요구 | 등급 |
|---|---|---|
| FR-TOK-1 | 색 토큰은 **목록이 있다.** 목록 밖의 색 토큰을 새로 만들려면 이 문서를 고친다. 목록은 **뜻**으로 갈리고 값으로 갈리지 않는다. | 필수 |
| FR-TOK-2 | 글자 토큰은 **넷**이다 — `--text-bright`(가장 또렷) · `--text`(본문) · `--text-muted`(보조) · `--text-hint`(가장 흐린 것). **넷 다 파생 토큰**이다 (§3.2). | 필수 |
| FR-TOK-2a | `--text-bright` 의 바닥은 **고정값이 아니라 그 테마에서 파생된 `--text` 가 실제로 닿은 대비**다(하한 7.0). 고정 바닥만 두면 둘 다 7.0 을 넘으면서 순서가 뒤집힌다 — 실측 6/54 가 그랬다 (D-TOK-9). | 필수 |
| FR-TOK-3 | `--text-dim` 은 **글자 토큰이 아니다.** 팔레트의 원시값으로 남아 **경계·채움·비활성 배경**에만 쓰인다. 현재의 `color:var(--text-dim)` 99곳은 `--text-hint` 로 간다 (D-TOK-2). | 필수 |
| FR-TOK-4 | 글자로 쓰이는 강조색은 별도 파생 토큰을 갖는다 — `--accent-text` · `--danger-text` · `--attn-text`. 원본 `--accent`·`--danger`·`--attn` 은 **경계·배경·틴트**용으로 남는다. 대비 요구가 용도마다 다르기 때문이다 (글자 4.5:1 vs UI 경계 3:1). | 필수 |
| FR-TOK-5 | `--bg-alt` 를 **정의한다** — 표 머리·그룹 머리의 표면. `mixHex(--bg, --text, .06)` 로 파생한다. `--border` 쪽으로 섞지 않는 것은 실측 때문이다: 테마에 따라 `border` 가 `bg` 와 거의 같아 표면이 사라진다(최소 1.001 — 없는 것과 같다). `text` 쪽은 54종 전부에서 1.067~1.202 로 **고르게** 벌어지고, 밝은/어두운 테마의 방향이 자동으로 따라온다. `var(--bg-alt,…)` 의 폴백 세 자리는 폴백을 **지운다**: 토큰이 정의되면 폴백은 거짓 안전망이다. | 필수 |
| FR-TOK-5a | 구문 강조색 여섯(`--term-red`·`green`·`yellow`·`blue`·`magenta`·`cyan`)을 **터미널 팔레트에서 파생한다.** `style-docrender.css` 가 *"터미널 팔레트에서 파생하므로 편집기·터미널·렌더가 같은 색 세계를 쓴다"*(`DOC_RENDER_VIEW_SRS` FR-DRV-13d)고 적어 두고 **그 파생을 두지 않아** 여섯 다 폴백으로 떨어지고 있었다. 구문 강조도 글자이므로 같은 바닥(4.5)을 받는다. | 필수 |
| FR-TOK-5b | 고정폭 글꼴 토큰 `--mono` 를 정의한다 — `style-docrender.css` 가 스택을 따로 적고 `style-git.css` 는 없는 `--mono` 를 읽어 `monospace` 로 떨어지고 있었다. | 필수 |
| FR-TOK-6 | 백드롭·그림자가 토큰을 갖는다 — `--backdrop`(모달 뒤) · `--shadow-1`·`--shadow-2`. `rgba(0,0,0,…)` 67곳이 여기로 수렴한다. | 필수 |
| FR-TOK-7 | 위험색·상태색·구분선이 토큰화된다 — Tokyo Night 리터럴(`#16161e`·`#7aa2f7`·`#1a1b26`·`rgba(247,118,142,…)`)이 CSS 에서 사라진다 (`UX-14`). 라이트 테마에서 사라지는 구분선은 `--border` 가 아니라 `--border-strong` 을 쓰거나 파생 대비 바닥 3:1 을 받는다 (`UX-15`). | 필수 |

### 3.2 파생 규칙 — 대비 보장

> **사용자 결정 (2026-09-12)**: 팔레트 54벌을 손으로 고치지 않고 **파생**으로
> 보장한다. Nord 의 `#4c566a` 는 Nord 그 자체이므로 팔레트는 정본으로 남는다.

| ID | 요구 | 등급 |
|---|---|---|
| FR-TOK-8 | 글자 토큰은 **원시 팔레트 값을 앵커 쪽으로 섞어** 바닥을 넘는 **최초의** 값으로 세운다. 넘지 않는 동안만 섞는다 — 필요한 최소량만 움직인다. | 필수 |
| FR-TOK-9 | **참조 배경은 셋이다** — `--bg` · `--sidebar-bg` · `--bg-alt`. 같은 토큰이 본문·사이드바·표 머리 전부에 쓰이므로 **전부**에서 바닥을 넘어야 한다. 하나를 빠뜨리면 그 표면 위에서만 조용히 미달이 된다 — `--bg-alt` 를 넣기 전 실측에서 `--text-hint` 가 그 위에서 **4.33** 이었다. 그래서 `--bg-alt` 는 파생이 **소유한다**(다른 자리에서 따로 계산하면 두 값이 갈린다). | 필수 |
| FR-TOK-10 | **앵커는 `--text-bright`**, 그것이 `--text` 의 바닥을 못 넘으면 흰색/검은색 중 **배경 대비가 더 큰 쪽**(동률이면 모드가 가른다). 실측 54종 중 53종이 `--text-bright`, 1종이 흑/백이다 (D-TOK-3). | 필수 |

## 4. 설계 결정

**D-TOK-1: 팔레트는 정본이고 파생이 보장한다.**

  (사용자 결정 2026-09-12)
  54벌의 `textMuted`·`textDim` 을 손으로 올리는 대안은 두 가지를 잃는다: ① 정본
  팔레트와의 대조 가능성 — Nord·Solarized·Gruvbox 는 상류에 원본이 있고 그것과
  다르면 "우리가 왜 다른가" 를 매번 설명해야 한다. ② 새 테마의 안전 — 사람이
  손으로 맞춰야 하고, 맞추지 않으면 조용히 미달로 들어온다. 파생은 **새 테마도
  자동으로 받는다.**

**D-TOK-2: `--text-dim` 의 뜻을 가른다.**

  한 토큰이 글자(99곳)와 경계·채움(5곳)
  양쪽에 쓰이고 있었다. 글자의 바닥은 4.5, UI 경계의 바닥은 3:1 이므로 **같은
  값일 수 없다.** `--text-dim` 을 비글자용 원시값으로 남기고 `--text-hint` 를
  새로 세운다. 이름을 바꾸지 않고 값만 올리면 경계까지 밝아져 테마가 뭉개진다.

**D-TOK-3: 앵커는 `--text-bright`.**

  배경 반대편 극단(흰색/검은색)으로 바로
  섞지 않는 이유는 **색상(hue)을 잃기 때문**이다 — Gruvbox 의 흐린 글자가 회색이
  되면 Gruvbox 가 아니다. `--text-bright` 는 그 테마가 스스로 고른 "가장 또렷한
  글자" 이므로 그 쪽으로 섞으면 테마 안에 머문다. 실측 53/54 가 이 앵커로 닿고,
  닿지 않는 1종만 흑/백으로 내려간다.

  **내려갈 때 모드를 보지 않는다.** 초판 초안은 `mode` 로 흑/백을 갈랐는데,
  게이트 탐침이 그것이 틀릴 수 있음을 드러냈다: 배경이 `#808080` 이면 검은색이
  5.32 인데 흰색은 3.95 다 — `mode:'dark'` 를 따르면 **더 나쁜 쪽**을 고른다.
  `mode` 는 배경의 밝기를 **짐작한** 값이고, 여기서는 짐작할 필요 없이 **재면
  된다**. 동률일 때만 `mode` 가 가른다.

  **그리고 닿지 못하는 팔레트가 있다.** 중간 밝기 배경에서는 흰색도 검은색도
  7.0 에 미치지 못한다 — 그 배경 위에 그 대비는 **존재하지 않는다.** 내장 54종에는
  없고 게이트가 새로 들어오는 것을 막지만, 사용자 지정 테마는 게이트를 지나지
  않는다(FR-TOK-17). 그때 파생은 **닿을 수 있는 가장 먼 곳**을 준다 — 바닥을 못
  넘는 것과 원래 색 그대로 두는 것 중에는 앞이 낫다.

**D-TOK-4: 바닥은 사다리다 (4.5 / 5.5 / 7.0).**

  이것이 이 문서에서 가장 비싼
  결정이고, **실측이 결정했다.** 세 토큰에 같은 바닥 4.5 를 주면:

  > 미달 0 · **계층깨짐 34/54** · `--text-muted` − `--text-hint` 간격 평균
  > **−0.03** (최소 −0.57)

  가장 흐리던 것(`--text-dim`, 시작 1.28)이 가장 많이 올라가 **중간 단계를 추월
  한다.** Dracula 에서 hint 4.88 > muted 4.73 이 된다 — 흐리라고 만든 색이 더
  진해진다. 사다리(4.5 / 5.5 / 7.0)를 주면:

  > 미달 0 · **계층깨짐 0/54** · 간격 muted−hint 평균 0.95(최소 **0.56**) ·
  > text−muted 평균 4.28(최소 **1.04**)

  `--text` 의 7.0 은 **AAA 수준이지만 부담이 아니다** — 중앙값이 이미 9.84 이고
  손대는 테마가 13/54 뿐이다. 접근성을 위해 고른 값이 아니라 **아래 두 단계가
  숨 쉴 공간**을 만들려고 고른 값이다.

**D-TOK-5: 게이트와 런타임이 같은 함수를 쓴다.**

  게이트가 값을 다시 계산하면
  둘이 갈라지고, 갈라진 순간 **게이트는 초록인데 화면은 미달**이 된다. M6
  "비싸게 배운 것 9"(초록인 게이트와 재고 있는 게이트는 다르다)의 같은 부류다.
  그래서 파생은 의존 0 의 순수 모듈이어야 한다 (NFR-TOK-4).

**D-TOK-6: 미정의 프로퍼티는 폴백이 있어도 잡는다.**

  `style-docrender.css` 의
  `var(--bg-alt,var(--bg))` 는 지금 **동작한다** — 그러나 그 자리는 `--bg-alt` 가
  있다고 믿고 쓴 자리이고, 폴백은 그 믿음이 틀렸다는 사실을 숨긴다. 같은 묶음의
  네 자리가 폴백 없이 투명으로 떨어진 것이 그 증거다.

**D-TOK-7: 과도기의 끝은 "선언이 비었는가" 다.**

  날짜나 마일스톤이 아니라
  **파일이 말하는 조건**이어야 한다 — D-5 가 종료 조건 없이 열린 이유가 그것을
  사람의 판단에 맡겼기 때문이다. 선언이 0개면 그 클래스는 더 이상 외형을 주지
  않고, 그때부터 그것은 **선택자**이지 스타일이 아니다.

**D-TOK-9: `--text-bright` 의 바닥은 `--text` 가 정한다.**

  초안은 글자 토큰을 셋으로 적었다. 구현 중 실측이 넷째를 드러냈다 —
  `--text-bright` 는 `color:` 로 **103번** 쓰이는데, `--text` 를 7.0 까지 올리고
  나면 **6/54 에서 bright 가 본문보다 흐려진다.** Solarized Light 의 `#586e75` 는
  4.39 로 AA 자체를 못 넘었다. "가장 또렷한 글자" 가 본문보다 흐린 것은 이름이
  거짓말을 하는 상태다.

  고정 바닥(가령 8.0)으로는 풀리지 않는다 — 테마마다 `--text` 가 닿는 곳이
  달라(7.0~19.03) 어떤 고정값도 어떤 테마에서는 뒤집힌다. 그래서 바닥을
  **그 테마의 파생된 `--text`** 로 잡는다. 앵커가 이미 그 대비를 넘으므로 항상
  닿는다.

  **한 자리만 예외다**: 앵커가 `textBright` 자신이면 그리로 섞는 것이 제자리
  걸음이다. Monokai 가 그렇다 — 팔레트의 `#f8f8f0`(13.93)이 `#f8f8f2`(13.94)보다
  0.01 흐리다. **팔레트 자신의 모순**이지 파생이 만든 것이 아니다. 그때는 둘을
  합친다: 본문이 곧 가장 또렷한 글자다.

**D-TOK-8: z-index 층 안에서 값을 다투지 않는다.**

  `#focus-edge` 500 /
  `#attn-edge` 501 은 "이 둘 중 누가 위인가" 를 값으로 적은 자리다. 같은 층이면
  DOM 순서가 답이고, DOM 순서로 답할 수 없으면 **층이 다른 것**이다.
