## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

사용자 요구(2026-11-26)는 다음과 같다.

> 이슈트리 고도화 — 로컬 이슈트리 기능을 공식으로 한다. 이슈트리를 만들면 채팅방을 만들고, 생기고 사라지는 모든 에이전트가 그 방에 들어온다. 이슈트리의 안내·공지·전달·알람·사용자 확인은 모두 채팅으로 하고, 에이전트 사이의 통신도 채팅으로 한다(`otterminal msg` 를 쓰지 않는다). 채팅으로 보내는 내용은 화면에도 똑같이 내어, 사용자가 화면과 채팅 어디를 봐도 일할 수 있게 한다. 이것은 뒤에 이슈트리 밖의 기본 동작도 채팅으로 일하게 하는 바탕이다.
>
> 채팅 — 채팅방의 가독성과 UI 를 고친다. 에이전트·사용자 알람을 고친다(지금은 훅과 프롬프트 주입이다). 사용자 입력을 가로챌 가능성을 없애면서 알람을 제대로 보게 한다. 만들어지는 채팅방을 텔레그램에 방 하나당 토픽 하나로 잇고, 채팅방 내용(보낸 이·내용)이 그대로 보이게 한다.

이 SRS 는 위 요구를 다섯 묶음으로 나누어 정한다.

### 1.3 정의 (Definitions)

`PEER_CHAT_SRS` §1.3(노드·방·참가자), `ISSUE_AGENT_TREE_SRS` §1.3(노드·사슬 이름·그룹), `ISSUE_TREE_OPS_SRS` §1.3(배정·트리 멤버), `ISSUE_TREE_CLOSE_SRS` §1.3(조율) 의 용어를 따른다. 이 SRS 고유 용어만 적는다.

| 용어 | 정의 |
|---|---|
| **지정** | 글을 보낼 때 그 글을 받을 상대를 적은 목록(`call`). 항목은 참가자 id, 도구 id(`toolId`), 별칭 `user`(그 방의 사람 참가자 모두) 중 하나다 |
| **부른 글** | 어떤 참가자에게 "부른 글" 인 글. 판정은 FR-CAL-3 이다 |
| **알림 단계** | 참가자가 방마다 갖는 값. `all`(그 방의 모든 새 글) · `called`(나를 부른 글) · `off`(없음) |
| **깨울 글** | 참가자의 알림 단계에 걸린 새 글 |
| **깨움 훅** | shim 이 주입하는 Claude Code `Stop` 훅. `asyncRewake: true` 로 걸려 백그라운드에서 깨울 글을 기다리다가, 생기면 종료 코드 2 로 끝나 세션을 깨운다 |
| **알림 표식** | 깨움 훅이 이미 알린 글에 MCP 글함이 붙이는 표식. 같은 글로 두 번 깨우지 않게 한다 |
| **토픽** | 허용 계정과 봇의 1:1 대화방 안의 Telegram 토픽(Bot API 9.1+ 의 private chat topic) |
| **거울** | 토픽이 방과 같은 내용을 보이는 관계. 방의 글이 토픽에 올라가고, 토픽에 쓴 사용자 글이 방에 올라간다 |
| **보관 방식** | 이슈가 어디에 있는가. `github`(GitHub 하위 이슈) 또는 `local`(이슈 폴더의 파일) |
| **실행 방식** | 에이전트를 어떻게 세우는가. `tree`(노드 트리 — 노드가 바로 아래 자식을 띄운다, 지금의 issue-tree) 또는 `coord`(조정자 — 조정자 하나가 ready 이슈마다 일꾼을 띄운다) |
| **이슈 폴더** | 로컬 이슈 파일들이 있는 폴더. 명령 인자로 받는다 |
| **원본 폴더** | 트리를 시작할 때 Run 에 기록한 이슈 폴더의 절대경로. 상태는 여기서만 고친다 |
| **조정자** | `coord` 방식에서 트리를 연 세션. 일꾼을 띄우고 병합한다 |
| **일꾼** | `coord` 방식에서 이슈 하나를 맡은 에이전트 |
| **트리 방** | 이슈트리 하나에 하나 있는 단체채팅 방 |
| **사람 참가자** | 데몬이 노드마다 하나 세우는 사람 참가자(`<노드 이름>/User`, `PEER_CHAT_SRS` §3.11) |

### 2.6 로컬 이슈트리 (perf 작업)

- 이슈는 `docs/internal/perf/issues/<ID>-<짧은 이름>.md` 파일 하나가 하나다. 머리말은 `id · title · status · deps · owner · branch`, 본문은 목표 · 완료 조건 · 진행 기록이다. ID 는 점으로 이은 트리 경로이고 부모는 마지막 조각을 뗀 ID 다.
- 상태 흐름: `todo → ready → in-progress → review → done`, 곁가지 `blocked` · `split`.
- 조정자 하나가 ready 이슈마다 일꾼을 띄웠다. 일꾼은 이슈 worktree·브랜치(`pf/<ID>`)에서 일하고 `review` 까지 한다. 조정자가 통합 브랜치에 병합하고 `done` 으로 바꿨다. 115개 이슈를 끝까지 돌렸다.
- 상태는 통합 worktree 의 원본만 고친다는 규칙을 문서(`AGENT_RULES.md`)로 지켰다. 트리 보기는 `tree.sh` 였다.
- 하위 에이전트의 `git add`·`git commit` 이 자동 모드 분류기에 자주 막혀, 조정자가 대신 커밋했다. 병렬 worktree 의 `rust/target` 으로 디스크가 찼다.

### 2.7 이슈트리의 통신 (지금)

`issue-tree.md` 의 노드는 부모·자식·조율과 `otterctl msg` 로 주고받는다. 새 노드의 첫 지시도 `otterctl msg` 다. `msg` 는 받는 탭의 입력에 넣고 곧바로 제출한다.

### 2.8 대화 기록

채팅은 그 순간 방에 있는 참가자에게만 글을 전하고, 노드는 대화를 들지 않는다. 사람 쪽 대화는 브라우저 메모리에만 있다(FR-PCH-85). 이 SRS 는 이것을 바꾸지 않는다(D-ITH-22).

## 3. 요구 (Requirements)

### 3.1 묶음 A — 알림

**부른 글**

- **FR-CAL-1** `chat_send` 는 선택 인자 `call`(지정)을 받는다. 항목은 참가자 id · 도구 id · `user` 중 하나다. 방에 없는 상대는 `bad_request` 로 거절한다.
- **FR-CAL-2** 채팅 화면의 입력칸은 `@` 자동완성과 답장으로 `call` 을 채운다(FR-CUX-13). 텔레그램 토픽의 글은 FR-TGT-9 로 채운다.
- **FR-CAL-3** 부른 글의 판정은 다음과 같다.
  1. 개인채팅의 글은 상대를 부른 글이다.
  2. 에이전트가 쓴 글은 `call` 에 든 상대만 부른다. `call` 이 없으면 아무도 부르지 않는다.
  3. 사람이 쓴 글은 `call` 이 있으면 그 상대만, 없으면 그 방의 모든 에이전트를 부른다(D-ITH-12).
- **FR-CAL-4** 데몬은 글을 넘길 때 받는 참가자마다 "나를 부른 글인가" 를 판정해 `msg` 프레임에 싣는다(`called: bool`). MCP 글함과 화면은 이 값을 쓴다.

**알림 단계**

- **FR-CAL-5** 참가자는 방마다 알림 단계(`all` · `called` · `off`)를 갖는다.
- **FR-CAL-6** 에이전트는 새 도구 `chat_notify {room, level}` 로 자기 단계만 바꾼다. 정하지 않으면 `called` 다. `chat_rooms` 는 방마다 내 단계를 돌려준다.

### 3.2 묶음 U — 채팅 화면

- **FR-CUX-7** 나를 부른 글은 왼쪽 띠와 `@나` 표시로 구분한다. 다른 참가자를 부른 글은 머리에 `@<이름>` 을 붙인다.

### 3.5 묶음 C — 트리 방

- **FR-ITR-1** 트리를 시작하면 조율(`tree`) 또는 조정자(`coord`)가 트리 방을 만든다. 이름은 그룹 이름, 목적은 트리 표지와 루트 이슈 제목이다. 방 id 를 Run 에 기록한다.
- **FR-ITR-2** 데몬은 트리 방을 만든 노드의 사람 참가자를 그 방에 넣는다.
- **FR-ITR-3** 트리 멤버(배정을 가진 Run 멤버)의 세션이 채팅에 붙으면 데몬이 그 참가자를 트리 방에 넣는다. 세션이 끝나 연결이 끊기면 나간다. 에이전트는 들어가고 나가는 일을 하지 않는다.
- **FR-ITR-4** 트리의 모든 통신(보고 · 지시 · 완료 · 실패 · 종료 요청 · 준비됨 · 막힘)은 트리 방에서 받을 상대를 `call` 로 지정해 보낸다. 본문 첫 줄이 종류다(지금 `issue-tree.md` 의 종류 그대로). `otterctl msg` 를 쓰지 않는다.
- **FR-ITR-5** 안내 · 공지 · 알람 · 사용자 확인 요청도 트리 방에 쓴다. 사용자 확인은 `call: ["user"]` 이다.
- **FR-ITR-6** 새 노드·일꾼의 첫 지시(배정 · 프리앰블 · 이슈)는 claude 실행 인자의 첫 프롬프트로 준다. 긴 본문은 파일로 쓰고, 첫 프롬프트는 그 파일을 읽고 시작하라는 한 줄이다. 기록이 없으므로(D-ITH-22) 첫 지시는 일에 필요한 맥락을 모두 담는다.
- **FR-ITR-7** 에이전트는 보낸 글과 받은 글을 자기 응답에도 옮긴다: `보냄 → <상대>: <본문>`, `받음 ← <보낸 이>: <요지>`. 그 탭의 화면만 봐도 주고받은 것이 보인다.
- **FR-ITR-8** 사용자 확인의 답은 터미널 입력과 채팅(웹·텔레그램) 가운데 먼저 온 것을 따른다. 답을 받은 에이전트는 트리 방에 `결정: <내용> (터미널에서|채팅에서)` 를 남긴다.
- **FR-ITR-9** 자기와 무관한 글로 깨어난 에이전트는 아무것도 하지 않고 턴을 끝낸다.
- **FR-ITR-10** 트리 종료(`ISSUE_TREE_CLOSE_SRS`)의 마지막에 조율 또는 조정자가 트리 방에서 나간다. 사람 참가자도 나가면 방이 사라지고, 토픽도 지워진다(FR-TGT-3).
- **FR-ITR-11** `otterctl msg` 명령은 이슈트리 밖의 쓰임을 위해 남긴다.

### 3.6 비기능 (Non-functional)

- **NFR-ITH-1** 유휴 규칙(FR-SRV-3, NFR-PRF-5)을 지킨다. 깨움 훅은 소켓 읽기에서 막혀 기다리고 주기적으로 깨지 않는다. 서버와 데몬은 이 묶음 때문에 외부 프로세스를 띄우거나 주기 작업을 더하지 않는다. 시간 값은 `cadence` 또는 해당 crate 의 상수로 둔다.
- **NFR-ITH-2** 부팅 JS 는 1,150,000 B 이하를 지킨다(NFR-PRF-12). 이 SRS 로 부팅 JS 가 늘지 않는다.
- **NFR-ITH-3** 망에서 온 값(방 이름 · 목적 · 본문 · 보낸 이)은 입력창과 훅 출력에 들어가지 않는다. MCP 도구 결과로만 에이전트에게 간다(FR-PCH-52).
- **NFR-ITH-4** 「채팅 토픽」 을 끄면 Telegram 으로 토픽 요청을 하나도 보내지 않는다.
- **NFR-ITH-5** 시험은 결정론적이다. tokio 시험은 `start_paused = true`, 깨움 훅 시험은 가짜 데몬 소켓을 쓴다.
