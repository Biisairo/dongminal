# 2.2.3 ToolManager·tools.json·허브

## 목표

도구 집합을 다루는 ToolManager 를 옮긴다. 생성(상한·배치)·복원·삭제, tools.json 저장·적재(형식은 Go 와 바이트 단위로 같다), 허브 표면(Write·Resize·Snapshot·Background), 주의·활동·크기 알림과 sweeper, 전경 이름 갱신, handover(Export/Adopt), FreezeAll/seal, 붙여넣기, 브라우저 WebSocket 쓰기 창구 SafeConn.

## 대상 Go 코드

- `internal/shared/toolhub` 의 manager*.go, persist.go, handover.go, freeze.go(Manager 부분), foreground.go, bracketpaste.go, conn.go(SafeConn), hub.go(인터페이스) (약 1800줄)

## 완료 조건

- 대상 Go 코드의 관측 동작을 Rust 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)

- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  - Go 와 다르게 한 내부 결정:
    ① `DaemonHub`·`ToolHub` 인터페이스는 옮기지 않았다. 구현(toolclient, 5.3)과 소비자(httpapi, 5.5)가 비동기 여부를 정해야 하는 자리라, 그 이슈에서 소비자 쪽 trait 로 정의한다.
    ② `SafeConn` 은 tokio-tungstenite `Sink` 위의 제네릭이다. Go `Upgrader` 의 설정(버퍼 8192, CheckOrigin 항상 참 — 요청 게이트가 mux 밖에서 판정)은 5.5 가 옮긴다. 읽기 쪽(SetReadLimit·SetReadDeadline·PongHandler)도 처리기가 스트림 반쪽으로 다룬다.
    ③ `SetForegroundProbe`·`toolProcInfo` 같은 전역 갈아 끼우기는 관리자별(`set_foreground_probe`, `with_proc_info`)로 바꿨다.
    ④ 동기 Go 메서드 중 대기·타이머가 있는 것(Terminate, SendPaste, FreezeAll, 두 티커)은 async 다. Delete·SaveAll 은 블로킹 동기이고, 비동기 쪽은 spawn_blocking 으로 부른다(FR-RSP-36).
    ⑤ `ParseSize(*http.Request)` 는 쿼리 값 두 개를 받는 `parse_size` 다. `strconv.ParseUint` 와 같게 `+`·공백을 거절한다.
    ⑥ `BusyMany` 의 ok 는 늘 참이라 반환하지 않는다.
  - FR-RSP-6 보안 강화(조정자에게 SRS 3.7 등재 요청): 붙여넣기 감싸기에서 본문 안의 `ESC[201~` 를 Go 는 한 번만 지운다. 그래서 `ESC[20` `ESC[201~` `1~` 처럼 지운 자리에서 끝 표시가 다시 생기고, bracketed paste 를 빠져나와 나머지가 명령으로 실행된다. Rust 판은 남지 않을 때까지 지운다. 끝 표시가 겹치지 않은 본문의 결과는 Go 와 같다.
  - 남은 위험: `load_all` 의 JSON 타입 오류 로그 문구에서 맨 위 slice 타입 이름(`[]toolhub.ToolState`)이 Go 와 다를 수 있다(로그 한 줄). Windows 의 `adopt_handover` 는 platform 이 handover 를 지원하지 않으므로 오류가 난다(Go 와 같음).
