# SRS: 간선 계층의 망 정보 · 내 설정 변경 알림 · 망 그리기 · 간선 초대 — IEEE 29148

> **문서 상태**: 승인·구현완료
> **남은 것**: 없음. 적용(모든 노드 업데이트·데몬 재시작)과 V-LAY-1 의 linux·win32 기준선(CI 산출물)은 사용자가 한다
> **입력**: 2026-11-18 인터뷰. 결정은 §4 이고 원문은 `EDGE_MESH_HANDOFF.md` D-1~D-12 다.

## 1. 개요

### 1.1 목적

사용자 요구 (2026-11-18):

> *"간선계층에서 간선망 정보, 간선 망 내의 노드들의 정보를 알 수 있고, 채팅 계층에서는 각 노드들의 사용자 및
> 위에 적은 내용들을 알 수 있게 하면 될 것 같아. chat 은 채팅 계층이기때문에 망 정보는 간선 계층에 만드는게 맞아."*
>
> *"내 설정 변경 시 내가 바뀐것 알리는거 추가하자."*
>
> *"현재 간선 망을 알 수 있으면 해당 망을 그려줄 수 있나?"*
>
> *"직접 상대에게만 보내고 개인채팅을 통해 상호간에 간선 짓기를 할때만 초대를 보내서 간선을 연결한다."*

이 SRS 는 네 가지를 한다.

1. 간선마다 계속 열어 두는 연결 하나를 **간선 계층**이 갖게 한다. 망 정보(누가 누구와 이어졌나, 각 노드의 이름·
   지문)는 간선 계층이 그 연결로 퍼뜨린다. 채팅은 그 연결 위에 얹힌다.
2. 내 이름·노드 포트·알릴 주소가 바뀌면 직접 상대에게 알린다.
3. 설정 ▸ Edges 에 망을 그래프로 그린다.
4. 망 이웃에게 간선 초대를 보낸다. 초대는 받을 노드만 열 수 있다.

### 1.3 정의

| 용어 | 정의 |
|---|---|
| **간선 연결** | 간선 상대 사이에 계속 열어 두는 연결 하나. 간선 계층이 갖는다. 옛 "채팅 연결"(PEER_CHAT_SRS)을 대신한다 |
| **망 정보** | 노드 하나가 자기에 대해 서명해 퍼뜨리는 `net` 프레임. 이름·지문·공개키·지금 열린 간선 연결의 상대 목록(`links`)을 담는다 |
| **망 이웃** | 간선 상대는 아니지만 간선을 건너 이어진 노드 (PEER_CHAT_SRS 와 같다) |
| **직접 정보** | 간선 상대에게만 보내는 `hello` 프레임. 이름·알릴 주소·노드 포트를 담는다 |
| **알림 대기** | 내 직접 정보가 바뀐 뒤 아직 그것을 받지 못한 간선 상대의 표시 |
| **옛 판** | 간선 연결 경로(`/edge/v1/link`)를 모르는 노드 |
| **위층** | 간선 연결 위에 얹힌 계층. 지금은 채팅 하나다 |

## 2. 현황 (조사로 확정)

- 노드 포트 경로는 `/edge/v1/pair`·`unpair`·`chat` 셋이다(`edgenode/node.go`). 계속 열린 연결은 채팅 계층의
  `/edge/v1/chat`(Upgrade `dmchat1`) 하나다. 채팅이 맺기·다시 걸기(1~60초)·ping(15초)·끊김(45초)을 한다.
- 망 구조는 채팅 `state` 의 `links` 로 퍼진다. 온라인 판정(`chat/view.go`)과 도우미 키 신뢰(`chat/human.go`
  `trustedKeyLocked`)가 그것을 쓴다.
- 상대의 이름·주소·포트는 짝맞춤 때 한 번 받는다. 그 뒤에는 사람이 고치거나(`PUT /api/edges/address`) 다시 맺어야
  바뀐다. 설정 저장은 상대에게 아무것도 보내지 않는다.
- 채팅 `state` 의 `name` 은 지금 설정값이라 망에 퍼지지만, 상대의 `edges.json` 이름은 바뀌지 않는다.
- 직접 모드(데몬 없이 서버가 노드)는 데몬을 띄우지 못할 때만 타는 예비 경로이고 채팅이 없다.

## 3. 요구

### 3.1 묶음 L — 간선 연결

- **FR-EGM-1** 간선 연결은 간선 계층(새 패키지 `internal/shared/edgemesh`)이 갖는다. 데몬 모드에서만 선다. 직접
  모드에서는 서지 않고 그 경로는 404 다.
- **FR-EGM-2** 경로는 `/edge/v1/link`, Upgrade 프로토콜은 `dmlink1` 이다. `/edge/v1/chat` 은 없앤다. 출입 판정은
  지금과 같다 — 간선만 닿는다.
- **FR-EGM-3** 맺기·다시 걸기·생존 확인은 옛 채팅 연결과 같다: 주소를 아는 간선에 걸고, 실패하면 1초에서 60초까지
  두 배로 늘려 다시 건다. 15초마다 `ping`, 45초 동안 받은 것이 없으면 끊는다. 같은 상대와 연결이 둘이면 지문이 작은
  쪽이 건 연결을 남긴다. 간선을 지우면 연결을 바로 닫는다. 상대가 `edge_not_edge` 로 답하면 간선을 지운다.
- **FR-EGM-4** 연결의 한 줄은 프레임 `{t, b, s}`(종류·본문 원문·서명)다. 간선 계층은 `ping`·`hello`·`net`·`invite`
  를 처리하고, 그 밖의 종류는 위층에 넘긴다. 위층이 없으면 버린다.
- **FR-EGM-5** 위층은 연결을 직접 다루지 않는다. 간선 계층이 위층에 주는 것은 다음이 전부다: 프레임 받기, 새 연결
  알림(그 연결로 처음 보낼 줄을 넣는다), 모든 연결로 보내기(받은 연결 제외), 한 연결로 보내기, 망 그림의 바뀜 알림,
  온라인 판정, 두 노드가 서로 이어졌는가.
- **FR-EGM-6** 새 연결에는 간선 계층이 먼저 `hello`, 자기 `net`, 아는 노드들의 `net` 을 넣고, 그다음 위층이 처음
  보낼 줄을 넣는다. 위층이 첫 줄을 넣기 전에는 위층의 "모든 연결로 보내기"가 그 연결을 건너뛴다 — 받는 쪽은 늘
  노드 상태(`state`)를 글(`msg`)보다 먼저 받는다. 그 연결은 위층이 연 뒤에야 자기 `net` 의 `links` 와 온라인 판정에
  든다 — 온라인으로 보이는데 글이 그 연결을 건너뛰어 사라지는 틈을 두지 않는다(독립 리뷰).
- **FR-EGM-7** 상대에게 걸 때 상대가 404 로 답하면 그 간선을 **옛 판**으로 표시한다. 옛 판 노드가 이 노드의
  `/edge/v1/chat` 에 걸어 와도 404 로 답하고 그 간선을 옛 판으로 표시한다. 연결이 맺어지면 표시를 지운다. 이
  표시는 메모리에만 둔다.

### 3.2 묶음 N — 망 정보

- **FR-EGM-10** 각 노드는 `net` 프레임 `{node, key, name, epoch, seq, links[]}` 를 노드 키로 서명해 퍼뜨린다.
  `links` 는 지금 열린 간선 연결의 상대 지문이다. 자기 연결이 열리거나 끊길 때, 이름이 바뀔 때 새로 낸다.
- **FR-EGM-11** 받은 쪽은 `SHA-256(key) = node`, 서명, 모양(이름은 제어 문자 없이 256바이트 안, `links` 는 256개
  안)을 확인한다. `(epoch, seq)` 가 그 노드에 대해 아는 것보다 클 때만 받고, 받은 연결을 뺀 모든 연결로 넘긴다.
  자기 지문의 `net` 은 받지 않는다.
- **FR-EGM-12** 노드 A·B 는 A 의 최신 `net` 이 B 를, B 의 최신 `net` 이 A 를 `links` 에 담을 때만 이어진 것으로
  본다. 자기의 `links` 는 지금 열린 연결이다. 자기에게서 이 간선들로 닿는 노드가 **온라인**이다. 시간 확인을 쓰지
  않는다(PEER_CHAT_SRS FR-PCH-10a 를 옮긴다).
- **FR-EGM-13** 아는 노드는 256 개까지다. 넘으면 닿지 않는 노드 가운데 가장 오래 소식이 없는 것을 잊는다. 잊은
  노드의 마지막 `(epoch, seq)` 는 4096 개까지 기억해 옛 `net` 을 다시 받지 않는다.
- **FR-EGM-14** 망 정보에는 주소·포트를 싣지 않는다(D-EGM-2).

### 3.3 묶음 H — 직접 정보와 변경 알림

- **FR-EGM-20** `hello` 는 서명하지 않고 전파하지 않는다(연결이 mTLS 로 상대를 확인한다). 본문은
  `{name, addr, port}` 이고 `addr`·`port` 는 아래 규칙일 때만 싣는다.
  - 연결이 열릴 때: 노드 포트가 켜져 있고 듣는 중이면 `port` 와 알릴 주소 `addr`(비어 있을 수 있다)를 싣는다.
  - 설정을 바꿀 때(FR-EGM-22): 새 설정의 노드 포트가 켜져 있으면 싣는다.
- **FR-EGM-21** `hello` 를 받으면 그 간선의 `name` 을 `DisplayName(name)` 으로 고친다. `port` 가 있으면 주소도
  고친다: `addr` 이 바른 주소면 그 값, 아니면 지금 저장한 주소, 그것도 없으면 이 연결의 출발지 IP 다. 셋 다 없으면
  주소를 고치지 않는다. `port` 가 없으면 주소를 그대로 둔다 — 노드 포트를 끈 것은 알리지 않는다. 바뀐 것이 있으면
  저장하고 `edges_changed` 를 낸다.
- **FR-EGM-22** 다음이 바뀌면 직접 정보가 바뀐 것이다: 이름, 또는 새 설정의 노드 포트가 켜져 있으면서 노드 포트
  번호·알릴 주소·켜짐 여부 가운데 하나. 노드 포트를 끄기만 한 것은 아니다.
- **FR-EGM-23** 직접 정보가 바뀌면 모든 간선을 **알림 대기**로 표시하고, 열린 간선 연결마다 새 `hello` 를 **한 번**
  보낸다. 다시 시도하지 않는다. 그 `hello` 를 다 쓴 뒤(모든 간선을 합쳐 최대 2초) 새 노드 포트
  설정을 적용한다 — 옛 포트로 걸어 온 상대도 받는다.
- **FR-EGM-24** 어떤 간선 연결로든 `hello` 를 다 쓰면 그 간선의 알림 대기를 지운다. 연결이 열릴 때마다
  `hello` 를 보내므로(FR-EGM-6) 다시 이어진 상대는 저절로 맞춰진다.
- **FR-EGM-25** 알림 대기는 `edges.json` 의 간선 항목에 `pending: true` 로 저장한다. 데몬을 다시 띄워도 남는다.
- **FR-EGM-26** 수동 알리기(`notify`): 그 간선 연결이 열려 있으면 `hello` 를 보내고 다 쓰기를 기다린다. 닫혀
  있으면 다시 걸기 간격을 무시하고 바로 걸어 연결을 맺는다 — 맺으면 `hello` 가 간다. 상대 주소를 모르면
  `edge_addr_unknown`(409), 닿지 않으면 `edge_unreachable`(502), 옛 판이면 `edge_peer_outdated`(502)로 실패한다.

### 3.4 묶음 I — 간선 초대

- **FR-EGM-30** 망 이웃(온라인, 간선 아님, 자기 아님)에게 간선 초대를 보낼 수 있다. 노드 포트가 듣는 중이고 알릴
  주소가 있어야 한다. 아니면 지금 초대 만들기와 같은 코드(`edge_port_closed`·`edge_addr_required`)로 실패한다.
- **FR-EGM-31** 초대를 보내면 **받을 노드의 지문에 묶인** 일회용 토큰(10분)을 만든다. 이 토큰은 사람이 만드는
  초대 하나와 따로 둔다(서로 밀어내지 않는다). 묶인 토큰은 32개까지이고 넘으면 가장 오래된 것을 버린다. 묶인
  토큰을 다른 지문의 노드가 쓰면 `edge_token_invalid` 로 거절하고 토큰은 남는다.
- **FR-EGM-32** 초대 코드(지금 형식 `dmedge1:…`)는 받을 노드의 노드 공개키로 암호화한다: 보낸 노드의 노드 키와 받을
  노드의 노드 공개키로 ECDH(P-256), HKDF-SHA256(salt = 초대 id, info = `dmlink1 invite` ‖ from ‖ to)로 32바이트
  키, AES-256-GCM(무작위 nonce 12바이트, AAD = id ‖ from ‖ to). `box = base64(nonce ‖ 암호문)` 이다.
- **FR-EGM-33** `invite` 프레임 `{id, from, to, at, exp, box}` 을 노드 키로 서명해 망에 넘긴다. `id` 는 무작위
  16바이트 hex, `at`·`exp` 는 ms 다. 받은 쪽은 `from` 의 `net` 으로 배운 키로 서명을 확인한다. 키를 모르거나,
  `exp` 가 지났거나, `exp - at` 이 10분을 넘거나, `at` 이 지금보다 5분 넘게 뒤면 버린다. 본 `id` 는 만료까지(최대
  1024개) 기억해 다시 넘기지 않는다. 받은 연결을 뺀 모든 연결로 넘긴다.
- **FR-EGM-34** `to` 가 자기면 상자를 연다. 열리지 않거나, 코드가 틀렸거나, 코드의 지문이 `from` 이 아니면 버린다.
  열린 초대는 메모리의 **받은 초대** 목록에 둔다: `{id, from, name, tag, expires}`. 같은 `from` 의 앞 초대는 새 것이
  대신한다. 16개까지이고 만료된 것은 지운다. 이미 간선인 노드의 초대는 버린다. 받으면 `edges_changed` 에
  `invited {fp, name, tag}` 를 싣는다.
- **FR-EGM-35** 받은 초대의 **맺기**는 그 코드로 지금의 `add` 를 한다. 성공하면 그 초대를 지운다. **거절**은
  목록에서 지우기만 한다 — 보낸 쪽에 알리지 않고, 보낸 쪽 토큰은 만료로 사라진다. 거절한 초대 id 는 만료까지(256개)
  기억해, 같은 초대가 다시 와도 목록에 올리지 않는다.
- **FR-EGM-36** 중간 노드는 `from`·`to`·시각만 본다. 코드와 그 안의 주소는 받을 노드만 연다.

### 3.5 묶음 C — 채팅 계층 정리

- **FR-EGM-40** 채팅은 간선 계층의 위층으로 선다. 채팅 연결·`Handler`·다시 걸기·ping·`Drop` 을 채팅에서 없앤다.
- **FR-EGM-41** 채팅 `state` 에서 `links`·`name` 을 뺀다. 본문은
  `{node, key, epoch, seq, parts[], rooms[], helper, pins}` 다.
- **FR-EGM-42** 채팅의 온라인 판정과 노드 이름은 간선 계층의 것을 쓴다. 온라인 목록의 노드는 간선 계층이 아는
  노드다. 방을 만든 노드의 이름도 간선 계층에서 얻는다.
- **FR-EGM-43** 도우미 키 신뢰(PEER_CHAT_SRS FR-PCH-74·D-PCH-39)의 "X 와 서로 이어진 노드"는 간선 계층의 서명된
  `net` 으로 판정한다(FR-EGM-12). 고정값(`pins`)과 `helper` 는 채팅 `state` 에 남는다. 보안 성질은 같다: 노드
  하나를 바꿔쳐서는 이웃에게 가짜 사람 명령을 믿게 할 수 없다.
- **FR-EGM-44** 간선 상대의 도우미 키 고정은 "간선 상대 자신의 연결로 온 `state`" 일 때만 한다 — 위층이 받은
  프레임마다 어느 연결로 왔는지 안다.
- **FR-EGM-45** 옛 판과는 섞지 않는다. 과도기 호환을 두지 않는다.

### 3.6 묶음 U — 화면

- **FR-EGM-50** 설정 ▸ Edges 에 **망** 구역을 둔다. 망을 SVG 그래프로 그린다. Activity 패널에는 두지 않는다.
- **FR-EGM-51** 배치: 나를 가운데 고정한다. 나머지는 힘 배치(이어진 노드는 당기고 모든 노드는 서로 민다)로
  놓는다. 처음 자리는 지문 순서로 원 위에 두고 정해진 횟수만 계산해, 같은 망은 늘 같은 그림이다.
- **FR-EGM-52** 노드는 `이름#번호` 로 적는다. 온라인은 채운 점, 연결 끊김은 빈 점이다. 나는 따로 표시한다. 내
  간선은 굵은 선, 남들끼리의 간선은 가는 선이다. 간선 상대가 알림 대기이거나 옛 판이면 노드 아래 작은 글자로
  적는다.
- **FR-EGM-53** 노드를 누르면(키보드로도) 그 노드를 고르고, 그림 아래에 할 수 있는 일을 보인다: 망 이웃(온라인,
  간선 아님)은 **간선 초대 보내기**, 간선 상대는 **알리기**. 나와 연결 끊긴 이웃은 할 일이 없다.
- **FR-EGM-54** 간선 줄에 알림 대기·옛 판(업데이트 필요)을 표시하고 **알리기** 버튼을 둔다.
- **FR-EGM-55** 받은 초대가 있으면 Edges 에 줄마다 "`이름#번호` 가 간선을 맺자고 합니다" 와 **맺기**·**거절**을
  보인다. `edges_changed` 의 `invited` 로 알림(토스트)을 띄운다.
- **FR-EGM-56** 채팅의 개인채팅 방에서 상대 노드가 간선이 아니고 온라인이면 **간선 초대 보내기** 버튼을 보인다.
  누르면 그 노드에 FR-EGM-30 의 초대를 보낸다.

- **FR-EGM-60** 새 오류 코드: `edge_addr_unknown`(409, 상대 주소를 모른다), `edge_peer_outdated`(502, 상대가 옛 판),

- **FR-EGM-63** `otterctl edges` 의 간선 줄 끝에 `알림 대기`·`옛 판` 을 적는다. `--json` 은 API 답 그대로다.
- **FR-EGM-64** IPC push `edges`·SSE `edges_changed` 에 `invited {fp, name, tag}` 를 더한다.

### 3.8 비기능

- **NFR-EGM-1** 간선 계층은 위층의 잠금을 잡지 않는다. 위층은 자기 잠금 안에서 간선 계층을 불러도 된다(잠금
  순서: 위층 → 간선 계층). 간선 계층은 자기 잠금 밖에서만 위층을 부른다.
- **NFR-EGM-2** 프레임 한 줄은 1 MiB, 연결 하나의 보낼 줄은 1024 개까지다. 넘치면 그 연결을 끊는다.
- **NFR-EGM-3** 디스크에 새로 쓰는 것은 간선 항목의 `pending` 하나다. 망 정보·받은 초대·옛 판 표시는 메모리에만
  둔다.
- **NFR-EGM-4** 새 패키지는 `shared/` 만 가져온다(`check-pkg-axis.sh`). `architecture.md` 패키지 표에 더한다.
- **NFR-EGM-5** JS 모듈은 500줄 게이트를 넘지 않는다. 망 그림은 새 모듈 `web/js/core/app-edges-mesh.js` 에 둔다.
