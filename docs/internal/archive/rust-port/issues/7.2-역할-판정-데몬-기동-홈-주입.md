### 공개 API
- `dm_shared_toolhub::ToolManager::set_env_overlay(&self, Vec<(String, String)>)`: 이 등록부가 띄우는 도구 셸의 환경을 프로세스 환경 위에 덮는다. bin 자리·PATH·HOME·히스토리 자리도 덮개 값으로 정한다. 같은 이름의 프로세스 환경 항목은 빼고 한 번만 싣는다. 내부적으로 `set_start` 를 덮어쓴다.
- dongminal crate(`pub(crate)`): `daemon::{dial_or_start_daemon(home, tool_home) -> Result<ToolClient, DaemonUnavailable>, dial_or_start_daemon_with, start_daemon, daemon_env, DAEMON_SUBCOMMAND, DAEMON_BUSY_WAIT(3s), DAEMON_READY_TRIES(20), DAEMON_READY_POLL(100ms)}`. `DaemonUnavailable` 의 Display 는 Go 문구 전체다.

### Go 와 다르게 한 내부 결정
- Go 의 `os.Setenv(DONGMINAL_HOME)`(main resolveHome·doctor)와 `os.Setenv(DONGMINAL_TOOL_HOME)`(격리 전경 기동)는 프로세스 환경을 바꾸지 않는 방식으로 옮겼다. ① 데몬: `boot::run` 이 `set_env_overlay([DONGMINAL_HOME=home])` 를 건다(3.3 crate 한 줄). ② doctor: 같은 API 로 바꿔 `extra_env` 우회를 없앴다. 이제 기본 홈·`--home` 다른 홈에서도 훅·PATH 의 bin 이 Go 와 같다. ③ 데몬 자식: `start_daemon` 이 `DONGMINAL_HOME` 과 (비지 않았으면) `DONGMINAL_TOOL_HOME` 을 자식 환경에 직접 넣는다.
- 첫 dial 을 기다리는 일은 스레드 + `recv_timeout(3s)`, 준비 대기는 동기 루프(Go pollwait.Until 과 같은 의미: 먼저 묻고 poll 마다 묻고, 남은 시간이 poll 보다 짧으면 그만큼 잔다)로 했다.
- 로그 파일을 열지 못하면 데몬 출력은 null 장치다(Go exec.Cmd 기본값). stdin 도 null 이다.
- `mod serve` 는 7.3 이 채울 자리다. 지금은 `server init: …` 를 찍고 1 을 돌려준다. `mod daemon` 의 `expect(dead_code)` 는 7.3 이 serve 에서 `dial_or_start_daemon` 을 부르면 경고를 내므로 그때 지운다.

### 조정자 넘긴 일 처리
- tool_home 전달: 끝남(위 ③). toolhub 홈 주입 공개 자리 + doctor 교체: 끝남. `dmlog::init`(stderr TextHandler, 수준은 `DONGMINAL_LOG_LEVEL`): main 첫머리에서 한다. 끝남.
- platform `hostname()`: Go 의 `os.Hostname()` 호출 자리 네 곳(httpapi handlers_api·telegram_wire·reqgate, daemon boot edge)이 Rust 에서 모두 이미 `dm_shared_platform::hostname()` 을 쓴다. 이 이슈에서 더할 일은 없다.
