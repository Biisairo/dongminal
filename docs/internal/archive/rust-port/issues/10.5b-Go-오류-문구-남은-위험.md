# 10.5b Go 오류 문구 — 10.5 남은 위험

## 목표

조정자 지시(2026-11-24): 10.5 진행 기록의 남은 위험 1~5 를 고친다.

1. 따로 흉내 낸 mkdir_all 3곳(ext goos, wsentry fsx, claudeacct fsutil)을 `dm_gocompat::oserr::mkdir_all` 로 모은다.
2. `DirBuilder::recursive` 자리 가운데 오류 문구가 응답·로그·CLI 출력으로 나가는 곳은 mkdir_all 로 바꾸고, 나가지 않는 곳은 확인 결과만 적는다.
3. look_path 를 거치지 않고 이름으로 실행하는 자리를 훑어 Go 처럼 ErrDot 을 거치게 한다.
4. 명시 경로 실패의 원인 문구를 Go `findExecutable` 과 같게 한다.
5. `envset::tests::thread_count_sees_new_thread` 를 결정적으로 만든다.

### review (2026-11-24) — rp/10.5b @ 3354fa46

분기점은 rust-port `cfa998da` 다. review 직전에 다시 병합하려 했으나 새 커밋이 없었다.

**① MkdirAll 흉내 3곳** (`33272d5f`): ext `goos`, wsentry `fsx`, claudeacct `fsutil` 의 `mkdir_all` 이 `dm_gocompat::oserr::mkdir_all` 을 부른다. 쓰지 않게 된 `not_a_directory`·`fix_root_directory`·`mkdir` 을 지웠다.
- 시험: 세 crate 에 `mkdir_all_matches_go` 를 두었다(막힌 칸의 경로, `x/.`). claudeacct 는 `x/.` 에서 RED 였다. ext·wsentry 는 unix 에서 이미 Go 와 같아 RED 가 없다. 이 둘의 차이는 Windows 볼륨(UNC) 처리뿐이다.

**② DirBuilder::recursive 7곳** (`e10f88ea`)
- 바꾼 곳(문구가 밖으로 나간다. 모두 RED→GREEN):
  - daemon ipc `listen`·`listen_reports`: 전에는 경로 없이 `Not a directory (os error 20)` 이었다. `mkdir_sock_dir` 로 모았다.
  - daemon chatsock `create_dir`.
  - sandbox helper `mkdir_parent`.
  - privhelper `mkdir_all`·`save_secret`.
  - 부모 경로는 Go 처럼 `filepath.Dir` 로 맞췄다(전에는 `Path::parent`).
- 시험: `listen_mkdir_error_matches_go`, `create_dir_error_matches_go`, `mkdir_parent_error_matches_go`, `mkdir_errors_match_go`.
- 기록만 한 곳: sandboxplace `mkdir_0700`. Go `place.go:166` 도 오류를 버리고(성공했을 때만 AddrDir 을 정한다) 문구가 나가지 않는다.

**③ 맨 이름 실행** (`01c83e42`)
- 새 API `dm_shared_platform::command_path(name)`·`command_path_in(name, path_env)`: Go `exec.Command` 처럼 `filepath.Base(name)==name` 이면 LookPath(ErrDot 포함)를 거치고, 실패는 Go `exec.Error` 문구다.
- 이 API 를 거치게 바꾼 곳: platform handover `ps`×2, junction `cmd`(Windows), procinfo darwin `exec_run`, secrets `run_with_stdin`, runtimebin `openurl`·statusline 의 pass-through, sandbox helper 의 `cargo`, privhelper `launchctl`×3·`sudo`. ctl-cli `open` 은 ErrDot 을 NotFound 로 합치던 것을 `try_look_path` 로 고쳤다.
- 확인만 한 곳:
  - 이미 찾은 경로를 받는 곳: sandbox `exec`(find_runtime 결과), lsp `start_process`, ext `HostExec`·git core(10.5 에서 고침), daemon·start·handoff·doctor_probe·swap(current_exe).
  - runtimebin shim: Go `findRealCommand` 와 같은 방식으로 직접 훑는다.
- 시험:
  - `command_path_in_follows_exec_command`
  - 게이트 `platform/tests/exec_gate.rs`: 시험 밖 코드에 `Command::new("맨이름")` 리터럴이 없는지 본다. 시험 지원 crate `gittest` 는 뺀다. RED 일 때 9건이었다.

**④ 명시 경로 실패 원인** (`6e8c56e2`)
- `LookPathError::Find(String)` 를 더했다. `Copy` 는 뗐고 `as_str(&self)` 로 바꿨다.
- unix `findExecutable`: stat 실패는 `stat <p>: …`, 디렉터리는 `is a directory`, eaccess 실패는 errno 문구, 권한 비트로 내려가 실패하면 `permission denied` 다.
- Windows `findExecutable`·`chkStat`: 확장자가 있는 이름은 `file does not exist`, 없는 이름은 ErrNotFound, PATHEXT 가 비면 chkStat 의 원인이다. 디렉터리는 `permission denied` 다.
- 시험:
  - go1.27.2 실측 기대값: `exec: "$ROOT/missing": stat $ROOT/missing: no such file or directory`, `exec: "$ROOT/dir": is a directory`, `exec: "$ROOT/plain": permission denied`, `exec: "$ROOT/plain/x": stat $ROOT/plain/x: not a directory` → `explicit_path_errors_match_go`.
  - `windows_explicit_path_errors`.
  - `unix_rules` 의 명시 경로 기대값을 바꿨다.

**남은 위험**
1. Windows `chkStat` 의 op 는 Go `os.Stat` 의 갈래를 짐작해 정했다. 없는 파일이면 `GetFileAttributesEx`, 그 밖은 `CreateFile` 이다. FindFirstFile 갈래(공유 위반)는 흉내 내지 않았다. Windows 실기 검증은 못 했다.
2. std `Command` 는 맨 이름을 자식 환경의 PATH 로 찾지만, Go 는 부모 PATH 로 찾는다. command_path 를 거친 자리는 이제 부모 PATH 로 찾은 절대경로를 넘기므로 Go 와 같다. 게이트는 리터럴만 잡는다. 변수로 맨 이름을 넘기는 새 자리는 리뷰로 막아야 한다.
3. 디스크 여유가 한때 7.9Gi 까지 내려갔다. incremental 을 비워 18Gi 로 되돌렸다.
