# SRS: 스크롤백을 지운 뒤에는 바닥을 따른다 — ED3 와 시선 — IEEE 29148

> **문서 상태**: 승인·구현완료

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수(2026-09-24): *"omp(oh my pi)를 쓰다가 다른 화면에 갔다 오면 한 번씩 맨 위로
튄다. 터미널 문제인지 omp 문제인지부터 알아야 한다."*

실측으로 원인을 가렸다(§2). 앱이 스크롤백을 지우고(`ED3`) 전체를 다시 쓸 때,
xterm 뷰포트가 바닥에서 한 줄이라도 떨어져 있으면 맨 위(`y=0`)에 멈춘다. 이것을
앱과 무관하게 고친다.

### 1.2 범위 (Scope)

- 포함: `web/js/ui/term-pane.js` — 생성자의 파서 훅 등록, ED3 훅 메서드.
- 비포함: omp 의 재그리기 방식 · 소유권·재생 경로(`OWNER_TRANSFER_REPLAY_SRS`) ·
  숨김/부착 시 scrollTop 복원(`VIEW_SCROLL_RESTORE_SRS`).
- 사용자 결정(2026-09-24): 앱을 가리지 않는다 — omp 에 한정하지 않는다 (D-ESF-1).

### 1.3 정의 (Definitions)

- **ED3**: `CSI 3 J` (`ESC [ 3 J`). xterm 확장 "Erase Saved Lines" — 스크롤백을 지운다.
  보이는 화면은 지우지 않는다(그것은 `ED2`).
- **바닥**: 뷰포트가 버퍼 끝을 보는 상태 (`viewportY === baseY`).
- **사용자 스크롤 상태**: xterm 이 뷰포트가 바닥이 아니라고 기억하는 상태
  (`isUserScrolling`). 이 상태에서는 새 줄이 쌓여도 뷰포트가 따라 내려가지 않는다.

### 1.4 참조 (References)

- `OWNER_TRANSFER_REPLAY_SRS` FR-OTR-9 — 같은 방식(xterm 파서 훅, `false` 반환)의 선례
- `VIEW_SCROLL_RESTORE_SRS` FR-VSR-24 · `M9` FR-M9-29 — 부착 뒤 scrollTop 이 `ydisp` 를 어긋나게 하는 경로
- pi-tui `src/tui.ts` `#emitFullPaint`(`\x1b[H\x1b[3J`) · `#beginResizeViewport` (omp 17.4.0)

## 2. 현황 (Current State) — 실측 (2026-09-24)

### 2.1 omp 는 크기가 바뀌면 스크롤백을 지우고 전부 다시 쓴다

omp 17.4.0 을 PTY 에 띄우고 SIGWINCH 를 보내 출력을 셌다.

| 자극 | omp 출력 |
|---|---|
| 크기 그대로 | 0 B |
| 높이만 (30→26, 26→30) | `ESC[H ESC[3J` + 대화 전체 (~17 KB) |
| 폭 (100→90) | `?1049h` → `?1049l` → `ESC[H ESC[3J` + 대화 전체 |
| 폭 + `PI_TUI_RESIZE_IN_PLACE=1` | ED3 없음 (제자리 재그리기) |

omp 의 설계다 — 멀티플렉서 밖에서는 스크롤백을 새 폭으로 다시 줄바꿈하려고 지운다.

### 2.2 xterm 은 사용자 스크롤 상태에서 ED3 를 받으면 맨 위에 멈춘다

§2.1 의 바이트를 `@xterm/headless` 6.0 에 넣었다 (500줄 스크롤백 → ED3 → 500줄).

| 넣기 전 | 넣은 뒤 |
|---|---|
| 바닥 (y=471/471) | y=471 — 정상 |
| 한 줄 위 (y=470/471) | **y=0** — 맨 위 |

ED3 가 스크롤백을 지우며 `ydisp` 를 0 으로 당기고, 사용자 스크롤 상태는 풀리지
않으므로 뒤이은 줄을 따라가지 않는다.

### 2.3 판별 실험 (사용자, 2026-09-24)

`PI_TUI_RESIZE_IN_PLACE=1 omp` 에서는 튀지 않았다. 원인은 §2.1 과 §2.2 의 합이다.
(그 모드에서는 포커스 복귀 뒤 재렌더가 되지 않는다 — 전체 재그리기를 끈 대가이므로
해법이 아니다.)

고친 뒤(§2.5) 기본 모드 omp 에서 튀지 않고 재렌더도 됨을 사용자가 확인했다 (V-ESF-7, 2026-09-24).

### 2.4 ED3 는 omp 만 쓰지 않는다

`clear`(`ESC[3J ESC[H ESC[2J`), Claude Code 2.1.281(`\x1B[2J\x1B[3J\x1B[H`),
Gemini CLI 번들에도 있다.

### 2.5 고친 뒤의 실측 (2026-09-24)

Chromium 에서 `web/vendor/xterm.js` 를 열고 §2.2 의 "한 줄 위" 시나리오를 재생했다.

| | 넣기 전 | 넣은 뒤 |
|---|---|---|
| 훅 없음 | y=470/471 | **y=0**/471 |
| 훅 있음 (FR-ESF-1) | y=470/471 | y=471/471 |

## 3. 요구사항 (Requirements)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-ESF-1 | 일반 화면(활성 버퍼가 `alternate` 가 아닐 때)에서 ED3(`CSI 3 J`)를 받으면, 그 쓰기의 파싱이 끝난 시점(`onWriteParsed`)에 뷰포트를 바닥으로 보낸다(`scrollToBottom`). | 필수 |
| FR-ESF-2 | 대체 화면에서 받은 ED3 에는 아무것도 하지 않는다 — 대체 화면에는 스크롤백이 없다. | 필수 |
| FR-ESF-3 | ED3 가 아닌 ED(`CSI J` · `CSI 1 J` · `CSI 2 J`)에는 아무것도 하지 않는다. 스크롤백이 남아 있으므로 사용자의 시선이 여전히 뜻을 갖는다. | 필수 |
| FR-ESF-4 | 파싱이 끝나기 전 ED3 가 여러 번 와도 바닥으로 보내는 것은 한 번이다. 끝난 뒤의 다음 ED3 는 다시 한 번 보낸다. | 필수 |
| FR-ESF-5 | 훅은 xterm 의 처리를 가로채지 않는다(`false` 를 돌려준다). | 필수 |

## 4. 검증 (Verification)

| ID | 대상 | 방법 |
|---|---|---|
| V-ESF-1 | FR-ESF-1 | 단위: 일반 화면에서 `CSI 3 J` 훅 → 파싱 완료 통지 → `scrollToBottom` **1회**. 통지 전에는 0회. |
| V-ESF-2 | FR-ESF-2 | 단위: 활성 버퍼 `alternate` 에서 `CSI 3 J` → 파싱 완료 뒤에도 **0회**. |
| V-ESF-3 | FR-ESF-3 | 단위: `CSI J` · `CSI 1 J` · `CSI 2 J` → **0회**. |
| V-ESF-4 | FR-ESF-4 | 단위: 통지 전 `CSI 3 J` 두 번 → 통지 → **1회**. 이어 `CSI 3 J` → 통지 → 누적 **2회**. |
| V-ESF-5 | FR-ESF-5 | 단위: 훅은 언제나 `false` 를 돌려준다. |
| V-ESF-6 | FR-ESF-1 · §2.2 | 실측: 브라우저에서 `web/vendor/xterm.js` 를 열고 §2.2 의 "한 줄 위" 시나리오를 훅과 함께 재생 → 넣은 뒤 `viewportY === baseY`. 훅 없이는 `viewportY === 0`. |
| V-ESF-7 | §2.3 | 사용자 확인: 기본 모드 omp 에서 다른 화면에 갔다 와도 맨 위로 튀지 않고, 재렌더도 된다. |
| V-ESF-8 | NFR-ESF-2 | `node scripts/check-file-size.mjs` 통과. |

## 5. 결정 (Decisions)

- **D-ESF-1 앱을 가리지 않는다** (사용자 결정 2026-09-24). 증상은 ED3 뒤에 많은 줄을
  다시 쓰는 모든 앱에서 같다(§2.4). ED3 직후에는 사용자가 보던 줄이 이미 지워졌으므로
  지킬 시선이 없고, 바닥은 `y=0` 보다 나쁠 수 없다. `clear` 처럼 뒤이은 출력이 없으면
  바닥과 맨 위가 같은 자리라 차이가 없다. 앱을 골라내려면 전경 프로세스 이름을
  읽어야 하는데 omp 는 bun 으로 돌아 그 이름이 흔들린다.

## 6. 리스크

| 위험 | 정도 | 대응 |
|---|---|---|
| ED3 뒤 사용자가 일부러 위를 보고 있었다 | LOW | 그 줄은 ED3 로 이미 지워졌다 — 보던 자리가 남아 있지 않다 (D-ESF-1) |
| 재그리기가 여러 쓰기에 걸쳐 온다 | LOW | 첫 통지에서 바닥으로 보내면 사용자 스크롤 상태가 풀리고, 뒤의 쓰기는 xterm 이 스스로 따른다 |

## 7. 비목표 (Non-goals)

- omp 의 동작을 바꾸지 않는다 (`PI_TUI_RESIZE_IN_PLACE` 를 설정·주입하지 않는다).
- 부착 뒤 scrollTop 복원이 `ydisp` 를 어긋나게 하는 경로(§1.4)를 고치지 않는다.
  그 어긋남은 이 결함의 조건 중 하나지만, ED3 가 없으면 튀지 않는다.
- 전량 재생 경로를 바꾸지 않는다.
