# issue-tree

이슈마다 에이전트 하나를 둔다. 에이전트는 자기 이슈를 계획하고, 나눌 필요가 있으면 하위 이슈를 만들어 그 하위마다 에이전트를 띄운다. 나눌 필요가 없으면 직접 일한다. **진행 중인 경로에만** 에이전트가 떠 있다.

**인자**: `$ARGUMENTS`. 첫 낱말이 이슈다. 이슈가 없으면 사용자에게 묻는다. 그 밖의 인자가 없으면 기본값을 쓰고, 되묻지 않는다.

| 인자 | 기본값 | 뜻 |
|---|---|---|
| `--ctx <퍼센트>` | `60` | 중간 노드가 migration 하는 맥락 사용률 |
| `--no-commit` | 없음 | 트리 전체가 커밋하지 않는다. 사용자가 그렇게 말했을 때만 붙인다 |

스펙: `docs/internal/ISSUE_AGENT_TREE_SRS.md` (FR-IAT-*). 이 문서와 SRS 가 다르면 멈추고 사용자에게 말한다.

## 역할

| 역할 | 누구 | 하는 일 |
|---|---|---|
| **발사대** | 이 명령을 실행한 세션 | 트리를 세우고 루트 노드만 띄운다. 그 뒤 빠진다. 자기 탭은 닫지 않는다(사용자의 탭이다) |
| **노드** | 이슈 하나를 맡은 에이전트 | 아래 「노드 절차」. 이 문서를 엔벨로프로 받아 읽는다 |
| **루트 노드** | 최상위 이슈의 노드 | 노드 절차 + 마지막의 push·병합 확인과 정리 |

## 절대 원칙

1. **노드는 바로 아래 자식만 띄운다.** 여러 단계를 한꺼번에 띄우지 않는다.
2. **일하지 않을 노드로 가는 길은 띄우지 않는다.** 병렬이 없으면 일하는 잎은 하나다.
3. **중간 노드는 하위를 띄운 뒤 턴을 끝낸다.** `dmctl msg` 가 와야 깨어난다. 상태를 폴링하지 않는다. sleep 루프를 짜지 않는다.
4. **트리의 window·탭은 트리 그룹 안에만 만든다.** 그룹 밖의 window·탭을 만들거나 옮기거나 닫지 않는다.
5. **각 걸음은 기대 출력을 확인한 뒤 다음으로 간다.** 확인하지 못하면 멈추고 말한다.
6. **push 와 사용자 브랜치로의 병합은 사용자의 확인 뒤에만 한다.** 커밋과 이슈 닫기는 이 명령의 실행으로 승인된 것이다. `--no-commit` 이면 커밋하지 않는다.

## 식별자

| 값 | 어디서 | 어디에 쓰나 |
|---|---|---|
| 탭 `uuid` | `who-am-i` 의 `uuid=` · 응답의 `newTabs[0].uuid` | `--at` (탭 명령 · `send-input` · `wait` · `status` · `close-tab`) |
| `toolId` | `who-am-i` 의 `toolId=` · `newTabs[0].toolId` | `dmctl msg --to`. 엔벨로프의 `from=` 과 같다 |
| window `uuid` | `newWindows[0]` | `run start --window` · `move-window --at` |
| 그룹 `uuid` | `new-group` 의 `newGroups[0]` · `list-groups` | `--group` · `move-group --at` · `delete-group --at` |

좌표·라벨(`W1.P1.T1`)은 어디에도 넣지 않는다. 레이아웃 명령에 `--help` 를 붙여 도움말을 보지 않는다 — `dmctl --help` 를 쓴다.

## 이름

- **별칭**: 저장소 이름을 `-` · `_` · `.` 로 나눈 낱말의 첫 글자를 소문자로 잇는다. 낱말이 하나면 앞 세 글자다. 예: `common-chart-renderer-ts` → `ccr`.
- **사슬 이름**: `<별칭>#<루트>›<번호>›…›<이 노드>`. 다른 저장소의 하위 이슈는 그 칸에 별칭을 다시 붙인다(`ccr#32›dmn#120`).
- **탭 이름**: `<사슬 이름> <이슈 제목의 짧은 형태>`. 예: `ccr#32›33›35›62 피킹`.
- **window 이름**: 그 window 에 처음 선 노드의 사슬 이름.
- **그룹 이름**: `<별칭>#<루트> <루트 제목>`. 트리 표지는 `owner/repo#<루트>` 다.

## 이슈 규약

이슈 규약(프로젝트 보드 · 담당자 · 필드 · 커밋 메시지의 이슈 번호 · 닫는 방식)은 **그 프로젝트의 지시 문서**(CLAUDE.md · README 등)를 따른다. 이 명령은 규약을 만들지 않는다. 규약이 없으면 GitHub 기본 동작(하위 이슈 만들기 · 닫기)만 한다.

이슈 관계는 GitHub 하위 이슈(sub-issues)를 근거로 한다.

```
gh api graphql -f query='query($o:String!,$r:String!,$n:Int!){repository(owner:$o,name:$r){issue(number:$n){
  number title state body
  parent{ number title repository{ nameWithOwner } }
  subIssues(first:100){ nodes{ number title state body repository{ nameWithOwner } } }
}}}' -F o=<owner> -F r=<repo> -F n=<번호>
```

- `parent` 가 `null` 이면 그 이슈가 루트다.
- `subIssues` 의 순서가 진행 순서다.

## 발사대 절차

### 1. 자기 자리

```
dmctl who-am-i
```

`uuid=` · `toolId=` 를 적는다. 실패하면 dongminal 안이 아니다 — 사용자에게 말하고 멈춘다.

### 2. 경로

입력 이슈에서 `parent` 를 따라 루트까지 오른다. **루트 → 입력 이슈의 경로**(이슈 번호 목록)를 적는다. 이 경로가 루트 노드에 넘길 「목표 경로」다.

### 3. 그룹

```
dmctl list-groups --json
```

`tree` 가 `owner/repo#<루트>` 인 그룹이 있으면 그것을 쓴다. 없으면 만든다. 트리가 이미 도는지는 4의 `run start --tree` 가 서버에서 판정한다.

```
dmctl new-group --name "<별칭>#<루트> <루트 제목>" --tree <owner/repo>#<루트>
```

기대 출력: `newGroups` 가 하나. 그 값을 적는다.

### 4. 루트 window 와 Run

```
dmctl new-window -n --group <그룹> --name "<별칭>#<루트>" --cwd "<저장소 루트>"
cd "<저장소 루트>"
dmctl run start --objective "<별칭>#<루트> 이슈 트리" --window <newWindows[0]> --isolation per-run --tree <owner/repo>#<루트>
```

**같은 트리는 두 번 열리지 않는다.** 같은 트리의 열린 Run 이 있으면 `run start` 가 `tree_open` 으로 거절한다.

- 안내에 「이미 돌고 있다」가 나오면 멈추고 사용자에게 말한다. 4에서 만든 window 는 닫는다(`dmctl close-window --at <그 window 의 탭 uuid> --force`).
- 「멈췄다(살아 있는 멤버 없음)」가 나오면 사용자에게 정리할지 묻는다. 정리하라고 하면 안내의 `dmctl run close --run <id> --force` 를 실행하고 4를 다시 한다.

- 새 window 의 `newTabs[0].uuid`·`toolId` 를 적는다. 이 탭이 루트 노드의 자리다.
- 트리의 진행은 Runs 대시보드의 「이슈 트리」 에 보인다(노드를 누르면 그 탭으로 간다). 같은 내용을 `dmctl run tree --ref <owner/repo>#<루트>` 로 읽는다.
- `run start` 의 `run=` 을 적는다. `--isolation per-run` 이 사용자 작업 트리와 분리된 worktree 를 만든다. 사용자 작업 트리는 트리가 도는 동안 고치지 않는다.

### 5. 루트 노드를 띄운다

「노드 띄우기」 를 루트 window 의 첫 탭으로 한다. 배정의 `목표 경로` 는 2의 경로에서 루트를 뺀 나머지다.

### 6. 보고하고 빠진다

루트 노드가 `state=working` 이면 사용자에게 다음을 보고하고 끝낸다: 그룹 이름 · 루트 window · Run · 목표 경로. **자기 탭은 닫지 않는다.**

## 노드 띄우기 (공통)

부모가 자식 하나를 띄우는 절차다. 발사대가 루트 노드를 띄울 때도 같다.

### 자리

| 경우 | 자리 | Run |
|---|---|---|
| 사슬의 자식 · 병렬 자식 중 첫째 | `dmctl new-tab -n --at <자기 탭 uuid> --after <자기 탭 uuid>` | 부모와 같은 Run |
| 병렬 자식 중 둘째부터 | `dmctl new-window -n --group <그룹> --name "<자식 사슬 이름>" --cwd "<자기 worktree>"` | 새 Run (아래) |

새 Run 은 자식 window 를 갖고, 부모 브랜치의 지금 HEAD 에서 갈라진다. 부모의 worktree 에서 실행한다.

```
dmctl run start --objective "<자식 사슬 이름>" --window <newWindows[0]> --isolation per-run --base "$(git rev-parse HEAD)" --tree <owner/repo>#<루트> --branch
```

기대 출력을 확인한다: `newTabs` 하나, `timedOut:false`. `delivered:0` 이면 브라우저가 없다 — 사용자에게 말하고 멈춘다.

### 이름 · 등록 · 기동

```
dmctl rename-tab --at <새 탭 uuid> "<자식 탭 이름>"
dmctl run member --run <Run> --role "<자식 사슬 이름>" --agent claude --at <새 탭 uuid> --brief - <<'B'
<자식 이슈 한 줄 요약과 배정 (아래 「배정」)>
B
dmctl run launch --member <member uuid> | dmctl send-input --at <새 탭 uuid> --execute -
dmctl wait --at <새 탭 uuid> --for ready --timeout-ms 180000
dmctl read-screen --at <새 탭 uuid>
```

`run member` 가 `node_taken` 으로 거절하면 그 이슈는 다른 노드가 이미 맡고 있다. 그 하위를 띄우지 않는다. 만든 탭·window 를 닫고 부모에게 `보고` 로 알린다.

`wait` 가 `ready` 를 내도 입력을 받을 준비가 아닐 수 있다. `read-screen` 에 에이전트의 입력 프롬프트가 보여야 한다. 신뢰·권한 확인을 묻고 있으면 답한 뒤 다시 확인한다. 준비되지 않은 탭에 엔벨로프를 보내지 않는다.

### 배정 (Kickoff)

```
dmctl msg --to <새 탭 toolId> - <<'M'
[ISSUE-TREE 배정]
이 문서를 읽고 「노드 절차」 대로 일하라: <이 문서의 절대 경로>
노드: <owner/repo#번호> — <제목>
사슬 이름: <자식 사슬 이름>
목표 경로: <남은 번호 목록 | 없음>
부모: <자기 toolId>
그룹: <그룹 uuid>
Run: <Run uuid>
병렬 가지: <예 — 이 노드의 브랜치는 끝나면 부모가 병합한다 | 아니오>
맥락 기준: <--ctx 값>%
커밋: <허용 | 금지(--no-commit)>
[/ISSUE-TREE]
M
dmctl status --at <새 탭 uuid>
```

`state=working` 을 확인한다. 세 번 시도해도 아니면 멈추고 사용자에게 말한다.

## 노드 절차

### 1. 자기 자리와 이슈

```
dmctl who-am-i
```

`uuid=` · `toolId=` 를 적는다. 배정의 이슈를 위 GraphQL 로 읽는다. 프로젝트의 지시 문서에서 이슈 규약을 확인한다.

### 2. 갈래를 고른다

1. **목표 경로가 남아 있다** → 그 첫 번호의 노드 **하나만** 띄운다. 배정의 목표 경로에는 나머지를 넣는다. 4로 간다.
2. **끝나지 않은 하위 이슈가 있다** → 3에서 지금 열 것을 고른다.
3. **하위 이슈가 없다** → 직접 할지 나눌지 정한다.
   - 직접 한다 → 「잎 노드의 일」.
   - 나눈다 → 하위 이슈를 만든다(프로젝트 규약). 하위 이슈를 만들 때 순서와 의존을 정해 본문에 적는다(아래). 그 뒤 3.

### 3. 지금 열 하위 이슈

- 기본은 **서브이슈 순서대로 하나씩**이다. 각 이슈는 바로 앞 형제에 의존한다고 본다.
- 본문에 `의존: 없음` 이 있으면 앞 형제를 기다리지 않는다. `의존: #61, #63` 이면 그 이슈들이 닫힌 뒤에 연다.
- 열 수 있는 이슈가 여럿이면 함께 연다(병렬). 상한은 없다.
- 의존 대상이 모두 닫혔는지 확인한 뒤 연다.

**하위 이슈를 만들 때**: 앞 형제에 의존하지 않으면 본문에 `의존: 없음` 을 적는다. 작업이 시스템 성능에 예민하면(측정 · 부하 시험 등) 병렬로 만들지 않는다.

### 4. 하위를 띄우고 쉰다

열기로 한 하위마다 「노드 띄우기」 를 한다. 병렬이면 첫째는 사슬 탭, 둘째부터 새 window 다. 그 뒤 **턴을 끝낸다.**

### 5. 메시지가 왔을 때

엔벨로프 본문의 첫 줄이 종류다.

| 종류 | 할 일 |
|---|---|
| `보고` | 공유 문서(결정 · 설계)에 남길 것이면 **내가** 문서에 적는다. 하위는 문서를 고치지 않는다 |
| `질문` | 코드 · 문서로 **사실에 근거해 확실히** 답할 수 있으면 `답` 을 보낸다. 판단 · 방향 결정이 필요하면 답하지 않고 `답: 사용자에게 물어라` 를 보낸다 |
| `완료` | 아래 「하위가 끝났을 때」 |
| `실패` | 지우지 않는다. 무엇이 막혔는지 사용자에게 내 탭에서 말한다 |

### 6. 하위가 끝났을 때 (안전 지점)

1. 병렬 가지였으면 그 브랜치를 내 브랜치에 병합한다. 충돌은 내가 푼다. 풀 수 없으면 사용자에게 묻는다. 병합 뒤 `dmctl run close --run <그 가지의 Run>`.
2. 보고에 문서에 남길 것이 있으면 적는다.
3. 맥락 사용률을 본다:
   ```
   dmctl status --json
   ```
   `context.usedPct` 가 배정의 맥락 기준 이상이면 `/dongminal:migration` 으로 새 세션에 넘긴다. 새 세션의 탭 이름은 지금과 같게 한다. 넘긴 뒤 하위 노드들에게 새 `toolId` 를 알린다. 값이 없으면 넘기지 않고 계속하며, 그 사실을 보고에 적는다.
4. 다음에 열 하위 이슈가 있으면 3으로 간다. 모두 닫혔으면 내 이슈를 끝낸다(「잎 노드의 일」 의 4~7).

## 잎 노드의 일

1. 이슈를 계획하고 일한다. 공유 문서는 고치지 않는다 — 남길 것은 보고에 담는다.
2. 시험한다(프로젝트 규약).
3. 판단 · 방향 결정이 필요한 질문은 먼저 부모에게 `질문` 으로 보낸다. 부모가 `사용자에게 물어라` 로 돌려주면 **내 탭에서** 사용자에게 묻는다.
4. 커밋한다(배정이 `금지` 면 하지 않는다). 메시지는 프로젝트 규약을 따른다. AI 서명을 넣지 않는다.
5. 이슈를 프로젝트 규약대로 닫는다.
6. 기록하고 부모에게 알린다:
   ```
   dmctl run report --outcome succeeded --summary "<세 문장>"
   dmctl msg --to <부모 toolId> - <<'M'
   완료 <사슬 이름>
   커밋: <해시 목록>  브랜치: <병렬 가지면 브랜치 이름>
   문서에 남길 것: <없음 | 내용>
   M
   ```
7. 내 탭을 닫는다. 병렬 가지의 첫 노드이면 window 를 닫는다.
   ```
   dmctl close-tab --at <내 탭 uuid> --force
   dmctl close-window --at <내 탭 uuid> --force
   ```
   둘 중 하나만 쓴다. 닫기 전에 6의 `msg` 가 `전송 완료` 였는지 확인한다.

실패로 끝나면 커밋하지 않은 변경을 지우지 않는다. `dmctl run report --outcome failed` 와 `실패` 메시지를 보내고, 탭은 닫지 않는다.

## 루트 노드의 끝

루트 이슈의 하위가 모두 닫히면:

1. 내 탭에서 사용자에게 묻는다: Run 브랜치를 사용자의 원래 브랜치에 병합할지 · push 할지 · PR 로 할지. **답을 받기 전에는 하지 않는다.**
2. 답대로 한 뒤 `dmctl run close --run <루트 Run>`.
3. 트리 그룹을 지운다. window 는 닫히지 않고 풀린다.
   ```
   dmctl delete-group --at <그룹 uuid>
   ```
4. 내 탭에 최종 보고를 남긴다: 닫은 이슈 · 커밋 · 병합/push 결과. **내 탭은 닫지 않는다** — 사용자가 읽는다.

---

## 이 명령이 하지 않는 것

- 이슈 규약을 정하지 않는다. 프로젝트의 문서를 따른다.
- 병렬 가지의 결과를 자동으로 비교하지 않는다. 병합은 부모가 한다.
- 그룹 밖의 window · 탭을 건드리지 않는다.
- 사용자에게 묻지 않고 push 하거나 사용자 브랜치에 병합하지 않는다.
