# SRS: 채팅 창 — 채팅을 메인 패널의 탭과 자기 창으로 옮긴다 — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: V-LAY-1 의 linux·win32 기준선(푸시 뒤 `layout-baseline` 워크플로). e2e 전량은 2026-11-22 에 통과했다(2309 통과·흔들림 1(TC-CAC-27, 원인 고침 — `QUALITY_FLAKY_SRS` FR-FLK-12)·실패 0)
> 접수: 2026-11-20. 근거: `UX_AUDIT_FIX_SRS` 사용자 결정 D-7·D-22, 이 문서 §2.1 의 결정 D-CW-1~D-CW-6.
> 이 문서는 `PEER_CHAT_SRS` §3.11 의 **화면 자리**(Activity 의 Chats 탭, 터미널 창 칸의 채팅 탭)와 결정 D-PCH-31 을 **대체한다**.
> 채팅의 동작(방·참가자·글·안 읽은 수·데몬)은 `PEER_CHAT_SRS` 그대로다.

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

채팅을 작업 패널(Activity) 안의 한 탭에서 꺼내, 메인 패널(사이드바)의 `창`·`저장소` 옆 세 번째 탭과 **채팅 전용 창**으로 옮긴다.
채팅 창은 터미널·Repo 창처럼 칸을 나누고 탭을 옮겨 배치할 수 있다. 탭 하나가 방 하나다.

### 1.2 범위 (Scope)

| 범위 안 | 범위 밖 |
|---|---|
| 메인 패널의 `채팅` 탭(방 목록·온라인 목록) | 채팅 서버·데몬·API (`PEER_CHAT_SRS` 그대로) |
| 창 종류 `chat` 과 그 칸·탭 규칙 | 대화 내용의 영속(종전대로 브라우저 메모리) |
| 작업 패널에서 Chats 탭 제거 | 새 채팅 기능(파일 전송 등) |
| 기존 채팅 탭의 정리, 방 나가기 두 자리 | 채팅 창을 여럿 두는 일 |
| 모바일에서 채팅에 가는 길 | |

### 1.3 정의 (Definitions)

| 용어 | 뜻 |
|---|---|
| 메인 패널 | 사이드바. 탭 `창`·`저장소`(`SB_TAB_DEFS`). 자리(왼쪽·오른쪽)는 사용자가 바꾼다 |
| 채팅 창 | 창 종류 `chat` 인 창(`type:'chat'`). 노드(워크스페이스)에 하나 |
| 채팅 탭 | 탭 종류 `chat`(`TAB_TYPE_CHAT`), 기록 `{id,name,type:'chat',roomId}` |
| 일반 창 | 종류가 없는 터미널 창(`plainWindows`) |

### 1.4 참조 (References)

`PEER_CHAT_SRS`(§3.11, D-PCH-31) · `UX_AUDIT_FIX_SRS`(D-7·D-22) · `GIT_SIDEBAR_TABS_SRS`(FR-SBT-18~31) ·
`SIDEBAR_COLLAPSE_SRS`(FR-SBC-13·18) · `archive/EDITOR_TAB_SRS`(FR-EDT-40~56·94) · `archive/REPO_TAB_UNIFY_SRS` · `MOBILE_UX_OVERHAUL_SRS`

## 3. 요구사항 (Specific Requirements)

### 3.1 창 종류

**FR-CW-1** — 창 종류 `chat`(`WINDOW_TYPE_CHAT`)을 둔다. 판정은 `isChatWin(s)`(`s.type==='chat'`)이다. 채팅 창의 이름은 로케일의
`채팅`/`Chat` 이다(`chat.window_name`).

**FR-CW-2** — 채팅 창은 워크스페이스에 **하나**다. 불러온 워크스페이스에 둘 이상이면 창 목록 순서의 첫 창만 남기고, 나머지 창의
채팅 탭은 첫 창으로 옮긴 뒤(같은 방이 이미 있으면 버린다) 그 창을 지운다.

**FR-CW-3** — 채팅 창은 필요할 때 만든다: `채팅` 탭을 고를 때, 방을 열 때. 만든 채팅 창은 칸이 없다(`layout:null`).

**FR-CW-4** — 채팅 창은 칸이 0 이어도 남는다. 칸이 없으면 본문 가운데에 빈 상태 한 줄(`chat.window_empty`: `채팅 목록에서 방을 고르세요`)을 보인다. 안내문은 패널의 자리(왼쪽·오른쪽)를 말하지 않는다 — 패널 자리는 사용자가 언제든 바꾼다(C-4).

**FR-CW-5** — 채팅 창은 `창` 탭의 목록, 창 순회 키, 활성 창이 사라졌을 때의 대체 대상에서 빠진다(Repo 창과 같다).
`otterctl list-workspace` 는 채팅 창의 탭을 종전처럼 행으로 내고, 창 번호(`win_pos`)를 주지 않는다(`Type!=""`, 기존 규칙).

### 3.2 칸과 탭

**FR-CW-10** — 채팅 창에는 채팅 탭만 선다. 일반 창·Repo 창에는 채팅 탭이 서지 않는다(`_tabTypeFits`). 끌어 놓기로 창 사이를
옮기려 해도 받지 않는다.

**FR-CW-11** — 채팅 창 안에서는 탭을 끌어 칸 사이로 옮기고, 칸 가장자리에 놓아 칸을 나눈다(일반 창과 같은 끌어 놓기). 분할 단추·
분할 단축키는 채팅 창에서 아무 일도 하지 않고, 칸의 `+`(새 탭) 단추는 서지 않는다(A-1).

**FR-CW-12** — 같은 방의 탭은 하나다. 방을 열 때 그 방의 탭이 있으면 그 탭으로 가고, 없으면 채팅 창의 포커스 칸(칸이 없으면 새 칸)에 연다.
그 뒤 채팅 창이 활성 창이 된다.

**FR-CW-13** — 탭을 닫아도 방에서 나가지 않는다(종전). 마지막 탭을 닫으면 칸이 사라지고 창은 FR-CW-4 의 빈 상태다.

**FR-CW-14** — 워크스페이스를 불러올 때, 채팅 창이 아닌 창에 있는 채팅 탭은 **닫는다**(D-CW-3). 닫은 수가 있으면 콘솔 경고
`[chat] closed N chat tab(s) outside the chat window (CHAT_WINDOW_SRS FR-CW-14)` 를 남긴다. 탭이 0 이 된 칸은 붕괴 규약대로
사라지고, 칸이 0 이 된 일반 창은 종전대로 사라진다.

> 이전 동작: 채팅 탭은 활성 창의 포커스 칸에 열렸다. 활성 창이 Repo 창이면 방에 들어가기만 하고 탭은 조용히 열리지 않았다.
> 지금: 위. / 이유: 사용자 결정 D-7·D-CW-1~3.

### 3.3 메인 패널의 `채팅` 탭

**FR-CW-20** — 메인 패널 탭은 `창`·`저장소`·`채팅` 셋이다. `채팅` 탭은 서술자 하나(`SB_TAB_DEFS`)로 더한다: 라벨 `chat.title`,
아이콘 `message-square`, 패널 `#sb-panel-chat`, 배지 `_chatUnreadTotal()`(0 이면 없음), 툴팁 `Chat rooms and people online`.

**FR-CW-24** — 데스크톱 메인 패널의 머리 폭이 180px 미만이면 탭 셋은 이름 없이 아이콘만 선다(레일과 같은 아이콘, 이름은 툴팁). 사이드바 최소 폭
(`SIDEBAR_W_MIN_PX` 100px)에서 탭 셋이 이름을 나누면 한 탭이 20px 남짓이라 읽히지 않는다. 규칙은 `UX_AUDIT_FIX_SRS` D-27(넓으면 라벨, 좁으면 아이콘)과 같다.

> **`UX_AUDIT_FIX_SRS` FR-UXF-98·99(D-35)로 대체됨 (2026-11-20).** 이전 — 머리 폭 180px 미만이면 아이콘만 /
> 지금 — 고정 폭이 아니라 **모든 탭의 라벨이 제 몫의 폭에 들어가는가**로 판정한다(`TabBar.fit`). 아이콘은 늘 보이고, 하나라도 잘리면 라벨이 모두 숨는다 /
> 이유 — 라벨 길이가 로케일마다, 배지 수가 때마다 달라 고정 폭은 맞지 않는다.

> `GIT_SIDEBAR_TABS_SRS` V-SBT-16("100px 에서 두 탭 이름이 읽힘") 개정: 이전 — 두 탭의 이름 / 지금 — 100px 에서는 탭 셋의 아이콘이 겹치지 않는다 /
> 이유 — 탭이 셋이 되었다(D-7).

**FR-CW-21** — `채팅` 탭의 본문은 종전 Activity Chats 구역의 내용과 같다: `+ 새 그룹 대화` 단추, `방` 소제목과 방 행, `온라인` 소제목과 노드별 참가자
(`_chatItems`). 방 행을 누르면 들어간 뒤(들어가지 않았으면) 방을 연다(FR-CW-12).

**FR-CW-22** — `채팅` 탭을 고르면 콘텐츠가 채팅 창으로 바뀐다(없으면 만든다, FR-CW-3). 채팅 창이 활성이 되면 탭이 `채팅` 으로
따라온다. `채팅` 탭에서 채팅 창이 아닌 창이 활성이 되면 탭은 그 창의 탭으로 간다.

**FR-CW-23** — 방 행에는 들어간 방에서만 동작 단추 `⋯`(`.chat-row-more`, 툴팁 `More actions for this room`)가 선다. 데스크톱은 행에 올리거나
고른 행에서, 모바일은 늘 보인다. 누르거나 행을 우클릭하면 메뉴가 열린다: `나가기`(들어간 방), 도우미가 있으면 `강제 삭제`(종전 우클릭 메뉴).

### 3.4 방 나가기

**FR-CW-30** — 방 나가기는 두 자리다: 방 화면 머리의 `⋯`(종전)과 방 행의 메뉴(FR-CW-23). 둘 다 `_chatLeave` 를 지난다.

**FR-CW-31** — 나가기에 성공하면 그 방의 채팅 탭을 닫는다(D-CW-4). 실패하면 탭은 남고 종전대로 토스트로 알린다.

### 3.5 작업 패널

**FR-CW-40** — 작업 패널의 탭은 에이전트·백그라운드·Run 셋이다. Chats 구역(`ACTIVITY_SECTIONS` 의 `chats`)을 뺀다. 저장된 고른 탭이
`chats` 면 첫 탭이다(종전 `_actTab` 규칙).

> 이전 동작: 작업 패널 탭 줄이 넷(Agents·Background·Runs·Chats)이었다(`PEER_CHAT_SRS` FR-PCH-80·83, D-PCH-31).
> 지금: 셋. 채팅은 메인 패널이다. / 이유: 사용자 결정 D-7.

### 3.6 모바일

**FR-CW-50** — 모바일에서 채팅은 서랍(☰)의 `채팅` 탭으로 간다. 모바일에서 `채팅` 탭을 골라도 콘텐츠 창은 바뀌지 않는다(FR-CW-22 의 예외 —
창이 바뀌면 서랍이 닫혀 방 목록이 사라진다). 방을 누르면 서랍이 닫히고 채팅 창이 열린다. 채팅 창의 칸은 터미널
창처럼 한 번에 하나씩 보이고 칸 이동(`‹ ›`)을 쓴다.

**FR-CW-51** — 작업 시트(상단바 작업 단추)에는 Chats 가 없다(FR-CW-40).

| 500줄 근처 파일(`sidebar-tabs.js` 474)에 서술자를 더하면 게이트가 진다 | MEDIUM | 채팅 서술자는 새 파일에 두고 배열에 넣는다 |

## 6. 비목표 (Non-goals)

- 대화 기록 영속, 서버의 탭 종류 해석
- 채팅 탭을 터미널 옆 칸에 두는 일 — 대신 슬롯으로 두 창을 나란히 둔다
