# 다음 세션 프롬프트

아래 블록을 새 세션 첫 메시지로 그대로 붙여넣는다.

---

dongminal 의 엔티티 모델 재정비 작업을 이어서 진행한다.

**먼저 이 두 문서를 읽어라. 순서대로.**

1. `docs/internal/ENTITY_MODEL_HANDOFF.md` — 인계 문서. 확정된 모델, 진행 상황, 잔여 작업, 반복하면 안 되는 함정 7개
2. `docs/internal/ENTITY_MODEL_RESTRUCTURE_SRS.md` — 단일 진실 공급원 (IEEE 29148). 요구사항 ID(`FR-EM-*`, `FR-BG-*`)와 8단계 계획

**현재 상태**: P1~P7 커밋 완료(`6572b9c`), 작업트리 청결. Go 테스트 전체 통과.
e2e 는 17 실패 / 94 통과이며 이 17개는 **HEAD 기준선과 동일한 기존 실패**다 — 회귀 판단은 반드시 기준선 집합과 대조해서 하라.

**이번 세션의 작업 — 순서대로**

1. **P8: 문서·스킬 어휘 최종 스윕** (유일한 잔여 단계)
   - 인계 문서 §4.1 의 확인 명령으로 잔재를 찾고, P5·P6 에서 새로 생긴 심볼·계약을 반영하라: `ToolManager` 등 개명된 타입, 파일명 변경, 신규 패키지(`internal/migrate`·`internal/run`), P6 신규 표면(`detach` CLI, `/api/tools/background*`, 상태바 배지, `DONGMINAL_TOOL_ID`)
   - `docs/internal/*_SRS.md` 의 **과거 스펙은 손대지 마라**. 완료된 작업의 기록이며 당시 어휘가 맞다
   - `skills/dongminal-team`·`dongminal-workflow` 는 MCP 툴명·dmctl·좌표계가 전부 바뀌어 실행 불가일 가능성이 높다. **P8 에서는 어휘만 맞추고 토폴로지 재설계는 하지 마라** — 요구 3과 겹친다
   - 끝나면 SRS 의 DoD 를 실측해 보고하라

2. **커밋 후 사용자에게 업그레이드 안내**
   - 인계 문서 §4.2 의 순서를 그대로 제시하라. 사용자는 "모든 작업 완료 후" 실행하겠다고 했다
   - 사용자 홈(`~/.dongminal`)은 아직 v1 이고 구 바이너리가 돌고 있어 정상이다. **직접 마이그레이션하거나 재기동하지 마라**

3. **요구 3(오케스트레이션) 착수 여부를 사용자에게 확인**
   - 인계 문서 §4.3 에 조사 결론과 해소해야 할 결정(worktree 격리를 Run 단위 선택으로 둘지, 항상 격리할지)이 있다
   - 사용자 결정: "Orca 의 장점을 최대한 모방. 동작뿐 아니라 실제 구현(MIT 공개 소스)도 참고"
   - 착수한다면 `RUN_ORCHESTRATION_SRS` 를 IEEE 29148 로 새로 작성하고, 그 전에 결정을 해소하라

**작업 규약**

- 중·대 규모는 스펙 → 테스트 → 코드 순서를 지킨다. 신규 동작은 RED 를 먼저 확인한다
- 일괄 정규식 치환 전에 인계 문서 §6 의 함정 1~4 를 다시 읽어라. 스키마 값·와이어 키·마이그레이션 코드·TS 타입 주석이 매번 침범당했다
- 커밋은 사용자 확인 후에만. 커밋 메시지에 AI 서명 금지
- e2e 결과가 이상하면(대량 실패·런타임 급증) 코드를 의심하기 전에 PTY 를 확인하라:
  `ps -eo tty | awk '$1 ~ /^ttys/' | sort -u | wc -l` (상한 511)
