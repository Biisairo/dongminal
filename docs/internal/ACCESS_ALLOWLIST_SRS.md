# SRS: 접속 허용 목록 (Access Allowlist) — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

`dongminal start --expose` 는 `0.0.0.0` 에 바인드하는 것이 전부다
(`internal/ctl/cli/start.go:40`, `options.go:44`). 그 뒤에 어떤 접근 제어도 없다.
그런데 이 서버가 여는 표면은 PTY 터미널·파일 읽기/쓰기/zip·명령 실행이다 —
**`--expose` 는 인증 없는 원격 코드 실행 종단을 네트워크에 여는 것과 같다.**

본 SRS 는 서버가 **출발지 기준 허용 목록**을 소유하고, 목록에 없는 출발지의 요청을
HTTP·WebSocket 을 통틀어 거절하게 한다. 목록과 그 적용 여부는 설정 화면에서
추가·제거·수정한다.

### 1.2 범위 (Scope)

**포함:**

| 묶음 | 내용 |
|---|---|
| S | 서버 소유 저장소 `access.json` — 적용 토글 + 항목 목록. 부팅 시 로드, 원자적 저장 |
| G | 요청 경로의 게이트 미들웨어. 정적 자산·`/api/*`·`/ws` 전부를 한 자리에서 덮는다 |
| N | 호스트명 항목의 **정방향** 해석기. 요청 경로 밖에서 주기적으로 돌며 IP 집합을 캐시한다 |
| E | 종단 `GET/PUT /api/access` 와 설정 화면의 편집 UI |
| H | **이 컴퓨터의 별명** — `Host`/`Origin` 이름 판정용 목록. 저장·검증·판정 배선·UI (§3.5) |

**미포함:** §5 비목표. 특히 **인증(토큰·비밀번호)·TLS 는 본 SRS 가 하지 않는다.**
허용 목록은 "어느 기기"만 판정하며 "누구"는 판정하지 못한다.

> **개정 (2026-09-10, U-18).** 원문은 "Host 헤더 검증" 도 미포함에 넣었다. 그 판정의
> **계약**은 `REQUEST_GATE_SRS`(FR-RQG-2·6)에 있고 그대로다 — 다만 그 판정이 읽는
> **목록의 소유·검증·UI 는 묶음 H 로 이 문서에 들어왔다.** 저장소가 `access.json` 하나이고
> 편집 화면이 access 탭 하나이기 때문이다. 판정은 저쪽, 목록은 이쪽이다.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **출발지 (origin address)** | `http.Request.RemoteAddr` 에서 뽑은 IP. 프록시 헤더는 보지 않는다 (FR-ACL-6) |
| **항목 (entry)** | 허용 목록의 한 줄. IP 리터럴·CIDR·호스트명 중 하나와 이름표를 갖는다 |
| **적용 토글 (enforcement toggle)** | 목록을 실제로 적용할지의 단일 불리언. 끄면 게이트가 모두 통과시킨다 |
| **게이트 (gate)** | 출발지를 목록과 대조해 통과·거절을 판정하는 미들웨어 |
| **자기 주소 (self address)** | loopback(`127.0.0.0/8`·`::1`) + 이 서버 머신이 가진 모든 로컬 인터페이스 주소. 목록·토글과 무관하게 항상 통과한다 (FR-ACL-5) |
| **해석 캐시** | 호스트명 항목을 정방향 해석해 얻은 IP 집합. 게이트는 이것만 읽는다 |
| **축① (출발지)** | **누가** 들어오나. 출발지 IP 판정 — `entries` · `allowed()` |
| **축② (이름)** | **뭐라고 불리며** 들어오나. `Host`/`Origin` 의 이름 판정 — `hosts` · `hostAllow.ok()` (§3.5) |
| **별명 (host alias)** | 이 서버가 **불리는 이름**. 문자열로 비교되며 IP 로 해석되지 않는다 |

## 2. 실측된 현황 (Current State)

### 2.1 미들웨어 체인에 게이트 자리가 이미 있다

```go
// server.go:200
return loggingMiddlewareFor(s, recoverMiddleware(mux))
```

정적 핸들러·`/ws`·`/api/*` 가 모두 이 `mux` 아래다. 한 겹만 끼우면 전 표면이 덮인다.
따로 핸들러마다 검사를 뿌릴 이유가 없고, 뿌리면 새 종단이 추가될 때마다 빠뜨린다.

### 2.2 `settings.json` 은 이 규칙을 담을 자리가 아니다

`handlers_settings.go:14` 의 규약은 명시적이다 — **"브라우저 설정은 서버가 해석하지 않는
JSON blob"**. 방송 페이로드에 본문을 싣지 않는 이유도 같다(같은 파일 :80). 접근 제어는
서버가 해석해야 하는 값이므로 그 blob 에 넣으면 규약을 깨뜨린다. 저장소를 분리한다.

### 2.3 출발지 이름은 요청에 실려 오지 않는다

요청이 가진 것은 IP 뿐이다. "특정 도메인만 허용" 을 판정하려면 이름과 IP 를 잇는 단계가
따로 있어야 한다. 역방향(PTR) 해석은 요청마다 DNS 왕복이 붙고 대개 레코드가 없거나
신뢰할 수 없다 — 본 SRS 는 **정방향** 해석만 쓴다(묶음 N).

### 2.4 이름 해석은 이 환경에서 실제로 동작한다 (실측)

Tailscale MagicDNS 가 켜진 macOS 에서 `net.LookupHost` 를 직접 돌린 결과다.
`CGO_ENABLED=0` (pure-Go resolver) 에서도 같았다 — tailscaled 가 `/etc/resolv.conf`
에도 MagicDNS 서버(`100.100.100.100`)와 search domain 을 써 두기 때문이다.

| 입력 | 결과 |
|---|---|
| `macmini` | `100.117.248.111` |
| `macmini.tail5da9ae.ts.net` | `100.117.248.111` |
| `macmini-office` | `100.89.214.106` |
| `macmini.local` | **실패** (`no such host`) |

두 가지가 따라 나온다: (i) MagicDNS 짧은 이름·FQDN 모두 묶음 N 으로 판정 가능하다,
(ii) mDNS 이름은 불가능하다 (FR-ACL-14a).

## 3. 요구사항 (Requirements)

### 3.1 묶음 S — 저장소

**FR-ACL-1.** 서버는 `<DataDir>/access.json` 을 소유한다. 모양은:

```json
{
  "enabled": false,
  "entries": [
    { "id": "<uuid>", "value": "100.101.102.103", "label": "macmini", "enabled": true }
  ]
}
```

**FR-ACL-2.** 파일이 없거나 읽지 못하면 `enabled=false`, 빈 목록으로 선다 — 즉
**읽기 실패가 서버를 잠그지 않는다.** 실패는 로그에 남긴다.

**FR-ACL-3.** 저장은 `platform.WriteFileAtomic` 으로 한다 (`handlers_settings.go:55` 와
같은 근거 — 사용자가 손으로 만든 값이고 잘리면 되돌릴 수 없다).

**FR-ACL-4.** 저장은 메모리 상태에 **즉시** 반영된다. 서버 재시작을 요구하지 않는다.

### 3.2 묶음 G — 게이트

**FR-ACL-5.** **자기 주소**에서 온 요청은 목록·토글과 무관하게 항상 통과한다. 오설정으로
자기 자신이 잠기는 일이 구조적으로 불가능해야 한다.

자기 주소는 loopback 만으로는 부족하다. 서버를 띄운 그 컴퓨터에서 브라우저가
`http://macmini-office:8080` 처럼 **자기 이름**으로 붙으면 출발지는 `127.0.0.1` 이
아니라 그 인터페이스의 주소(`100.89.214.106`)다 — loopback 예외에 걸리지 않아
"내 컴퓨터인데 내 서버에 막히는" 상태가 된다. 자기 이름으로 붙는 것은 흔한 습관이므로
(북마크·MagicDNS) 이 경우를 예외에 포함한다.

**이것이 목록을 약하게 만들지 않는다.** 출발지가 서버 자신의 주소인 TCP 연결은 자기
자신뿐이다. 남이 그 주소를 위조하면 응답 패킷이 위조된 주소(=서버 자신)로 가므로
핸드셰이크가 성립하지 않는다.

**FR-ACL-5a.** 로컬 인터페이스 주소 집합은 부팅 시 수집하고, 호스트명 해석과 같은
주기로 갱신한다 (인터페이스는 VPN 접속·네트워크 전환으로 바뀐다). 수집에 실패해도
loopback 예외는 남는다 — 최후의 탈출구가 사라지면 안 된다.

**FR-ACL-5b.** SSH 포트 포워딩(`ssh -L`)은 출발지가 서버 쪽 loopback 이므로 목록을
지나간다. 이는 의도된 성질이다 — 그 터널을 세울 수 있는 사람은 이미 셸 권한을 가졌고,
목록이 막을 수 있는 것이 아니다.

**FR-ACL-6.** 출발지는 `RemoteAddr` 에서만 뽑는다. `X-Forwarded-For`·`X-Real-IP` 등
클라이언트가 쓸 수 있는 헤더는 **신뢰하지 않는다.** 신뢰하면 목록이 헤더 한 줄로 무력화된다.

**FR-ACL-7.** 적용 토글이 꺼져 있으면 게이트는 모든 요청을 통과시킨다 — 현행 동작과 같다.

**FR-ACL-8.** 토글이 켜져 있고 출발지가 어느 활성 항목과도 맞지 않으면 `403` 으로 끊는다.
본문은 최소한으로 하고 목록 내용을 응답에 싣지 않는다.

**FR-ACL-9.** 토글이 켜져 있고 목록이 비어 있으면 **자기 주소만** 통과한다 (FR-ACL-5 의 귀결).

**FR-ACL-10.** 게이트는 `loggingMiddlewareFor` **안쪽**, `recoverMiddleware` **바깥쪽**에
선다. 로깅 안쪽이어야 거절이 접근 로그에 남는다.

**FR-ACL-11.** 게이트는 정적 자산·`/api/*`·`/ws` 를 구분하지 않는다. 예외 경로는 없다.

**FR-ACL-12.** 이미 수립된 WebSocket 연결은 목록 변경으로 끊지 않는다. 게이트는 **연결
수립 시점**에만 판정한다.

**FR-ACL-13.** 거절은 로그에 출발지와 경로를 남긴다. 목록이 켜졌는데 접속이 안 되는
상황에서 이유를 찾을 수 있는 유일한 근거다.

### 3.3 묶음 N — 항목 해석

**FR-ACL-14.** 항목 `value` 는 세 형태를 받는다:

| 형태 | 예 | 판정 |
|---|---|---|
| IP 리터럴 | `100.101.102.103`, `fd7a::1` | 출발지와 같은가 |
| CIDR | `192.168.0.0/24`, `100.64.0.0/10` | 출발지를 포함하는가 |
| 호스트명 | `macmini`, `macmini.tail5da9ae.ts.net` | 해석 캐시의 IP 집합에 출발지가 있는가 |

**FR-ACL-14a.** 호스트명은 **표준 DNS 로 풀리는 이름만** 지원한다. mDNS(`*.local`)는
지원하지 않는다 — Go 의 `net.LookupHost` 로 풀리지 않는다(§2.4 실측). 그런 값은
FR-ACL-16 에 따라 "해석 실패" 로 드러난다.

**FR-ACL-15.** 호스트명 해석은 **요청 경로에서 하지 않는다.** 부팅 시 1회, 이후 주기적으로
백그라운드에서 돌며 캐시를 갱신한다. 게이트는 캐시만 읽는다.

**FR-ACL-16.** 해석에 실패한 호스트명 항목은 아무 출발지와도 맞지 않는다(= 통과시키지
않는다). 실패는 로그와 `GET /api/access` 응답에 상태로 드러난다.

**FR-ACL-17.** `enabled=false` 인 항목은 판정에서 빠진다 — 지우지 않고 잠시 끌 수 있어야 한다.

**FR-ACL-18.** 형식이 유효하지 않은 `value` 는 저장 시점에 거절한다(`400`). 저장된 뒤에
조용히 무시되면 사용자는 규칙이 걸린 줄 안다.

### 3.4 묶음 E — 종단과 UI

**FR-ACL-19.** `GET /api/access` 는 현재 토글·항목·항목별 해석 상태를 돌려준다.

**FR-ACL-20.** `PUT /api/access` 는 토글과 목록 전체를 교체 저장한다. 저장 뒤 설정 변경
방송을 낸다 (`settingsChangedPayload` 와 같은 규약 — 본문 없이 "다시 받으라").

**FR-ACL-21.** 두 종단은 게이트 **뒤**에 있다. 즉 허용된 출발지는 목록을 고칠 수 있다.
근거: 허용된 기기는 이미 PTY 전권을 갖고 있어 `access.json` 을 직접 고칠 수 있다 —
종단만 막는 것은 실질 방어가 아니면서 원격 관리를 불가능하게 만든다.

> **개정 — 적용 대상은 *대화형 사용자*다 (2026-09-10, `FILE_API_BOUNDARY_SRS` §2.3).**
>
> "PTY 가 이미 전권이므로 같다" 는 터미널 앞에 앉은 사람에게 참이다. **브라우저
> 매개 공격자에게는 거짓이다** — PTY 를 쓰려면 WebSocket 을 열고 프레임 규약을
> 따라 명령을 타이핑하고 출력을 읽어야 하는데, `POST /api/file/write` 는 요청
> 하나이고 응답을 읽을 필요조차 없다. **난이도가 다르면 같은 위험이 아니다.**
>
> 그래서 `/api/file/*` 는 허용 루트 아래로 좁혔고, 이 조항은 `access.json` 종단에
> 한정된다.

**FR-ACL-22.** 설정 화면에 전용 탭을 둔다. 적용 토글 1개, 항목 목록(추가·제거·값 수정·
이름표·항목별 on/off), 저장 버튼.

**FR-ACL-23.** UI 는 화면을 열 때 **현재 접속 중인 출발지**를 보여준다. 무엇을 목록에
넣어야 하는지 사용자가 알 방법이 달리 없다.

**FR-ACL-24.** 저장하려는 목록이 **현재 자기 출발지를 통과시키지 못하면** UI 가 경고하고
확인을 받는다. 서버는 그 저장을 막지 않는다 — 서버 머신에서 언제나 되돌릴 수 있다(FR-ACL-5).

### 3.5 묶음 H — 이 컴퓨터의 별명 (축②)

> **근거: U-18** (`production/M2_PROGRESS.md` §3.4 — 조사 완료·결정 확정, 2026-09-10).
> tailnet 의 다른 기기에서 IP 로는 붙고 **MagicDNS 이름으로는 붙지 못했다**(`/ws`·`/api/*`
> 가 전부 421). 막은 것은 `requestGate` 의 Host 판정이고, 서버가 자기 이름을
> `os.Hostname()`(`DongyoonKimui-Macmini.local`)으로만 알아 tailnet 별명
> `macmini-office` 를 자기 것으로 인식하지 못했다.
>
> **축이 둘인데 UI 는 하나만 표현했다** — ①누가 들어오나(출발지 IP, 이 문서 §3.1~3.4 가
> 담당·정상 작동) · ②**뭐라고 불리며 들어오나**(Host, **입력할 자리가 없었다**).
> `--allowed-host` 가 축②의 설계였으나 CLI 배선이 없다(`cmd/dongminal/main.go`). 이 묶음이
> 축②를 UI 가 소유하는 목록으로 만든다. **보안 경계를 넓히는 변경이므로 과도한 패턴을
> 막는 검증(FR-ACL-29)이 조항이다.**

**FR-ACL-25.** `access.json` 에 `hosts` 배열을 더한다. 항목 모양은 `accessEntry` 를
**그대로 재사용**한다 — 새 구조체를 만들면 검증·UI 행 렌더·직렬화가 두 벌이 된다.

```json
{
  "enabled": false,
  "entries": [ { "id": "…", "value": "macmini", "label": "내 맥미니", "enabled": true } ],
  "hosts":   [ { "id": "…", "value": "macmini-office", "label": "tailnet 이름", "enabled": true } ]
}
```

**FR-ACL-26.** `hosts` 의 적용은 **적용 토글(`enabled`)과 무관하다.** 근거: Host 판정은
토글과 무관하게 **항상** 돈다(`REQUEST_GATE_SRS` FR-RQG-2). 토글에 매면 목록을 끈
사용자(=기본값)의 이름 접속이 그대로 막히고, 그것이 U-18 의 증상이다.
**항목별 `enabled=false` 는 판정에서 빠진다** — FR-ACL-17 의 성질을 승계한다.

**FR-ACL-27.** `hosts` 키가 없는 기존 파일은 **빈 목록**으로 읽는다(하위 호환). 저장은
`WriteFileAtomic`(FR-ACL-3 승계), 반영은 즉시이며 **서버 재시작을 요구하지 않는다**
(FR-ACL-4 승계).

**FR-ACL-28.** `hosts[].value` 는 **정확 일치용 호스트명 하나**다. RFC 1123 라벨 규칙
(`isHostname`)을 쓴다. 짧은 이름(`macmini-office`) · FQDN
(`macmini-office.tail5da9ae.ts.net`) · **`.local`** 을 받는다.

`.local` 이 여기서 유효한 이유: 축②는 문자열 비교이고 **DNS 해석이 필요 없다.**
FR-ACL-14a(mDNS 미지원)는 해석이 필요한 축①의 조항이다.

**FR-ACL-29.** **와일드카드를 지원하지 않는다.** 다음은 저장 시점에 `400` 으로 거절한다.

| 거절 | 예 |
|---|---|
| 빈 값·공백만 | `""`, `"   "` |
| 와일드카드를 포함한 모든 값 | `*`, `*.`, `*.ts.net`, `*.local`, `a*b`, `?`, `**` |
| IP 리터럴·CIDR | `100.89.214.106`, `192.168.0.0/24` |
| 스킴·포트·경로·사용자정보가 붙은 값 | `http://x`, `x:58146`, `x/y`, `u@x` |
| 라벨 규칙 위반·253자 초과 | `-x`, `x-`, `x..y` |

근거 셋:

1. 축②는 **"이 컴퓨터의 별명"** 이다. 자기 이름은 유한하고 열거 가능하므로 와일드카드가
   필요한 이유가 없다.
2. 문제의 이름은 **점이 없는 짧은 이름**이라 접미사 와일드카드로 **애초에 걸리지 않는다** —
   `matchHostPattern` 이 `*.` 접미사에 점 하나를 강제한다. 와일드카드는 U-18 을 풀지 못한다.
3. **방어가 약해지는 설계는 채택하지 않는다.** 와일드카드를 받으면 "어디까지 넓은 것을
   막을지"(`*`·`*.com`·라벨 수 하한…)라는 판정을 새로 만들어야 하고, 그 판정 자체가 다음
   구멍의 자리가 된다. 축②는 DNS 리바인딩 방어의 화이트리스트다 — 넓힐 수 있는 문법을
   UI 에 놓지 않는다.

공인 도메인·CNAME 처럼 와일드카드가 정말 필요한 배치의 입구는 `--allowed-host` →
`hostAllow.extra` 로 **그대로 남는다**(`production/13-tls-tailscale.md` §7 요구 ④⑤ ·
`REQUEST_GATE_SRS` TC-RQG-13).

**FR-ACL-30.** 저장 시 정규화는 **앞뒤 공백 제거 · 소문자화 · 후행 점 제거**다. 비교는
`normalizeHost()` 결과와의 문자열 동등이다. IP·CIDR 을 거절하는 것이 축①과의 차이이므로
축②는 `validateAccessValue` 를 **쓰지 않고 자기 검증 함수를 갖는다.** 하나라도 유효하지
않으면 **아무것도 저장하지 않는다**(FR-ACL-18 승계).

**FR-ACL-31.** `hostAllow.ok()` 는 **활성 `hosts` 항목**과 대조한다. 읽기는
`accessStore.mu` 아래에서만 한다(`REQUEST_GATE_SRS` NFR-RQG-2 승계). 이 목록은 `Host` 와
`Origin` **둘 다**에 적용된다 — 두 헤더가 한 판정 함수를 지나는 것이 FR-RQG-3 의 설계다.

**FR-ACL-32 (동작 변경).** 편의 규칙 `hasHostname` 을 **제거한다.**

| | 내용 |
|---|---|
| **이전 동작** | 축① `entries` 의 활성 호스트명 항목을 **Host 이름으로도** 인정했다 |
| **새 동작** | 인정하지 않는다. 이름 판정은 `hosts` 만 본다 |
| **이유** | 두 축을 섞는 자리였다 — 축①에 적은 "들여보낼 기기 이름" 이 축②의 "내가 불리는 이름" 으로 조용히 승격됐다. 그래서 사용자는 축②에 무엇을 적어야 하는지 알 수 없었다 |
| **실제로 끊기는 접속** | 없다 — 현재 `entries` 는 전부 **타 기기** 이름이라 이 서버를 그 이름으로 부를 일이 없다 |

**FR-ACL-33.** `hosts` 가 비면 이름 판정은 **`hasHostname` 경로를 뺀 나머지 전부와
동일하다** — loopback/localhost 리터럴 · `os.Hostname()`+`.local` · 자기 IP(`isSelf`) ·
`extra`. FR-ACL-5 와 FR-RQG-6 항목 1~3·5 는 **유지된다.**

**FR-ACL-34.** `hosts` 는 **해석하지 않는다** — `refresh()` 의 `lookupHost` 대상이 아니고
해석 캐시에 들어가지 않는다. 근거: (i) 이름↔이름 비교이므로 해석할 것이 없다 (ii) 주기당
불필요한 DNS 왕복을 만들지 않는다(NFR-RQG-1 승계) (iii) 해석하면 UI 에 **"해석 실패" 라는
무관한 오류**가 뜨고 그것이 사용자에게 잘못된 신호가 된다.

**FR-ACL-35.** `GET /api/access` 응답에 세 필드를 **가산적으로** 더한다. 기존 필드의
이름과 의미는 바꾸지 않는다.

| 필드 | 뜻 | 왜 |
|---|---|---|
| `hosts` | 별명 목록(저장 모양 그대로. 해석 상태는 없다 — FR-ACL-34) | 편집 대상 |
| `hostname` | 서버가 아는 자기 이름(`os.Hostname()`) | U-18 의 원인이 이 값이었고 사용자가 그것을 알 방법이 없었다 |
| `host` | **지금 이 요청의 `Host`**(정규화 후) | 무엇을 넣어야 하는지 알 방법이 이것뿐이다 — FR-ACL-23 과 같은 근거 |

**FR-ACL-36.** `PUT /api/access` 는 종전대로 **전체 교체**다(FR-ACL-20 승계) — `hosts` 가
없는 본문은 별명 목록을 **빈 목록으로 교체한다.** 병합하지 않는 이유: 어느 필드가
병합되고 어느 것이 교체되는지가 문서 밖에 남으면 다음 필드에서 같은 질문을 다시 한다.

**FR-ACL-37.** access 탭의 **"지금 내 주소" 와 "허용 목록" 사이**에 섹션 **"이 컴퓨터의
별명"** 을 둔다(위치는 사용자 지정).

1. 서버가 아는 자기 이름(`hostname`)과 지금 들어온 이름(`host`)을 읽기 전용으로 보여준다.
2. 추가·제거·값 수정·이름표·항목별 on/off — 축① 행과 같은 조작(`_aclRow` 재사용).
3. **저장 버튼은 하나다.** 기존 저장이 두 목록을 함께 보낸다 — 저장이 둘이면 어느 쪽이
   저장됐는지가 화면에서 사라진다.
4. 검증 실패 본문을 그대로 띄우는 `_aclSave` 규약을 유지한다(어느 줄이 잘못됐는지 모르면
   고칠 수 없다).
5. 숨김·표시 어휘는 기존 둘만 쓴다 — 있으면 보임 `.vis` · 있으면 숨김 `[hidden]`
   (`UI_LAYOUT_DEFAULTS_SRS`).

**FR-ACL-38.** UI 문구는 두 가지를 적는다.

- 이 칸은 **DNS 리바인딩 방어의 화이트리스트**다. 남의 도메인을 넣으면 그 도메인이 이
  서버를 가리키게 만든 페이지가 응답을 읽을 수 있다. 넣을 것은 **이 컴퓨터가 불리는
  이름뿐**이다.
- **막힌 상태에서는 원격 브라우저로 이 칸을 고칠 수 없다** — `/api/*` 가 421 이므로 패널이
  값을 받지 못한다. 서버가 도는 컴퓨터에서, 또는 IP 로 접속해 고친다. FR-ACL-5 가 "그
  컴퓨터에서는 언제나 되돌릴 수 있다" 를 보장하는 것과 같은 자리다.

## 5. 비목표 (Non-goals)

1. **인증.** 토큰·비밀번호·사용자 개념을 만들지 않는다. 허용된 출발지 뒤의 사람이
   누구인지 서버는 모른다.
2. **TLS.** 평문 HTTP 그대로다. 같은 네트워크에서 트래픽은 읽힌다.
3. ~~**Host 헤더 검증.**~~ **개정 — `REQUEST_GATE_SRS` 가 그 "별도 SRS" 다 (2026-09-10).**
   원문: "어느 이름으로 들어왔는가 는 클라이언트가 정하는 값이라 접근 제어가 되지
   않는다. DNS rebinding 방어가 필요해지면 별도 SRS 로 다룬다."
   그 방어가 필요해졌다 — `04-secops` P1-7 이 실제 경로를 확정했다. Host 는 접근
   **제어**가 아니라 **리바인딩 방어**로 쓰이며, 그 둘은 다른 일이다.
4. **역방향 DNS(PTR) 기반 판정.** §2.3.
5. **속도 제한·차단 이력·잠금.** 반복 거절을 세거나 막지 않는다.
6. **`--expose` 의 기본 동작 변경.** 토글 기본값은 꺼짐이며, 기존 사용자의 동작은 그대로다.
7. **축② 의 와일드카드·정규식 문법.** FR-ACL-29. UI 가 소유하는 목록은 정확 일치만 받는다.
8. **`--allowed-host` CLI 배선.** `Config.AllowedHosts` → `hostAllow.extra` 경로는 그대로
   두며 플래그를 잇지 않는다 (U-18 결정 4).
9. **tailscale 을 실행해 이름을 자동 유도하는 방식.** 새 실행 의존성을 만들지 않는다
   (U-18 결정 5).
