# SRS: 디자인 토큰 — 색·크기·글자·z-index 의 목록과 파생 규칙 (IEEE 29148)

> **문서 상태**: 승인·구현완료

- 접수: 2026-09-12 (로드맵 M7 선행 SRS ② · `style-kit.css` 머리말 D-5 가 종료
  조건 없이 열어 둔 것)
- 마일스톤: M7. 짝은 [ACCESSIBILITY_BASELINE_SRS](./ACCESSIBILITY_BASELINE_SRS.md)
  (선행 SRS ①) — **무엇을 만족해야 하는가**는 그쪽이, **어떻게 보장하는가**는
  이 문서가 소유한다.
- 딛는 것: [UI_KIT_SRS](./UI_KIT_SRS.md). 그 문서가 **크기** 토큰을 세웠고
  **색은 소유하지 않는다**(FR-UIK-2)고 적었다. 이 문서가 그 빈자리를 채운다.

## 1. 개요

### 1.1 목적

`UI_KIT_SRS` 가 크기 토큰(`--ui-btn-h`·`--ui-radius`·`--ui-icon-*`)을 세울 때
색은 명시적으로 비켜 갔다.

> 색은 소유하지 않는다 (FR-UIK-2). `--accent`·`--border`·`--text-*`·`--danger`
> 는 style.css 의 :root 와 테마가 준다.

그 판단은 그때 옳았다 — 키트의 일이 아니었다. 그러나 **아무도 소유하지 않게
됐다.** 결과가 §2 다: 글자 크기 12종이 토큰 없이 흩어졌고, z-index 값 28종이
서로를 모른 채 커졌으며, Tokyo Night 의 색 값이 CSS 안에 160곳 박혔고,
정의되지 않은 `--bg-alt` 를 네 곳이 읽는다. 그리고 **248개 글자 선언이 어떤
테마에서도 AA 를 넘지 못하는 토큰 위에 서 있다**(§2.1).

이 문서는 넷을 정한다: **토큰 목록 · 파생 규칙 · 하드코딩 금지 게이트 ·
과도기 클래스의 종료 조건.**

### 1.2 범위

**포함**
- 색 토큰의 **목록과 뜻**, 대비 보장을 위한 **파생 규칙** (§3.1·§3.2)
- 글자 크기 토큰 5종 · z-index 계층 토큰 5종 · 백드롭·그림자 토큰 (§3.3·§3.4)
- 하드코딩 금지 게이트 · 미정의 커스텀 프로퍼티 게이트 · 포커스 짝 게이트 (§3.6)
- `style-kit.css` D-5 **과도기 클래스의 종료 조건** (§3.7)
- 모달 골격 7벌의 **`.ui-modal` 수렴** — 오버레이·상자의 겉모습 (§3.9, `UX-16` 의 나머지 절반)
- 테마 54종 팔레트의 **원본 값 보존** — 파생은 팔레트를 고치지 않는다

**비포함**
- 접근성 기준·검사 방법 → `ACCESSIBILITY_BASELINE_SRS`
- 테마 팔레트의 **미적 선택** (어떤 색이 예쁜가). 이 문서는 **계산 가능한 제약**만
- 터미널(xterm) ANSI 팔레트 — `t.terminal` 은 터미널 텍스트의 몫이고 UI 토큰이
  아니다 (`helpers.js` 의 SLOT_EDGE_MIX 주석이 같은 이유를 적었다)
- Monaco 편집기 테마 — `FileEditor.applyTheme()` 가 별도로 파생한다
- 레이아웃 규약(사이드바 폭·분할 비율) — `UI_KIT_SRS` 비포함과 같다

### 1.3 정의

| 용어 | 정의 |
|------|------|
| **팔레트** | `themes.js` 의 `ui` 객체. 테마의 **정본 값**이다 — 이 문서는 고치지 않는다 |
| **토큰** | `--xxx` CSS 커스텀 프로퍼티. 쓰는 자리가 보는 유일한 이름 |
| **파생 토큰** | 팔레트 값에서 **계산해서** 세우는 토큰. `applyThemeObj` 가 만든다 |
| **바닥(floor)** | 그 토큰이 배경에 대해 넘어야 하는 최소 대비 |
| **앵커** | 파생이 섞어 가는 방향의 색. 대비를 올리는 쪽 끝 |
| **참조 배경** | 대비를 재는 상대. `--bg` 와 `--sidebar-bg` **둘 다** (§3.2) |
| **과도기 클래스** | 키트 도입 때 지우지 않고 남긴 옛 클래스 (`.tbtn` 등, D-5) |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 색 — 글자가 읽히지 않는다

테마는 **54종**이다 (dark 43 · light 11). 로드맵이 적은 "44개" 는 낡았다.

`--bg` 대비 (WCAG 2.1 상대휘도):

| 토큰 | 최소 | 중앙값 | 최대 | ≥ 4.5:1 |
|---|---|---|---|---|
| `--text-bright` | 4.99 | 13.24 | 19.03 | 54/54 |
| `--text` | 4.13 | 9.84 | 19.03 | 53/54 |
| `--accent` | 2.69 | 5.90 | 15.89 | 45/54 |
| `--danger` | 2.80 | 4.77 | 7.84 | 33/54 |
| `--text-muted` | 1.69 | 3.21 | 6.15 | **10/54** |
| `--text-dim` | 1.09 | 1.28 | 1.91 | **0/54** |

쓰이는 방식:

| 토큰 | `color:` | `background:` | `border*:` | 합 |
|---|---|---|---|---|
| `--border` | 2 | 26 | 188 | 226 |
| `--accent` | 96 | 20 | 71 | 215 |
| `--text-muted` | **149** | 2 | 0 | 155 |
| `--text-bright` | 103 | 3 | 0 | 110 |
| `--text-dim` | **99** | 3 | 2 | 106 |
| `--danger` | 57 | 1 | 24 | 86 |
| `--text` | 73 | 0 | 0 | 80 |
| `--attn` | 49 | 4 | 13 | 78 |

**`--text-dim` 은 99번 글자로 쓰이고 54종 어디서도 3:1 조차 넘지 않는다.**

### 2.2 `--bg-alt` 는 정의된 적이 없다

7곳이 읽는데 `:root` 에도 `applyThemeObj` 의 맵에도 없다.

| 자리 | 꼴 | 결과 |
|---|---|---|
| `style.css:159` · `:564` | `var(--bg-alt)` | **투명으로 떨어진다** |
| `style-git.css:587` | `var(--bg-alt)` | 〃 |
| `style-git-views.css:94` | `var(--bg-alt)` | 〃 |
| `style-docrender.css:16` · `:63` · `:150` | `var(--bg-alt,var(--bg))` | 폴백이 받는다 |

**폴백을 적은 셋과 적지 않은 넷이 같은 파일 묶음에 있다** — 이것이 토큰에
목록이 없을 때 생기는 일이다. 로드맵이 센 "4곳" 은 폴백 없는 넷이고 정확하다.

### 2.3 하드코딩된 색 160곳

| 파일 | 색 리터럴 |
|---|---|
| `style.css` | **119** |
| `style-editor.css` | 17 |
| `style-git-views.css` | 10 |
| `style-kit.css` | 8 |
| `style-git.css` | 5 |
| `style-docrender.css` | 1 |

가장 많은 것은 `rgba(0,0,0,…)` **67회**(그림자·백드롭)다. 그다음이 **Tokyo Night
팔레트 값**이다 — `#16161e`(sidebarBg) 7회, `#7aa2f7`(accent) 3회,
`rgba(247,118,142,…)`(danger) 10회, `#1a1b26`(bg) 2회. 기본 테마에서만 맞고
나머지 53종에서 어긋난다 (`UX-14`).

### 2.4 글자 크기 12종

실측: `7px 8px 9px 10px 11px 11.5px 12px 13px 14px 15px 18px 20px`.

`11px` 과 `11.5px` 이 함께 있고 `13·14·15` 가 함께 있다 — 어느 것도 뜻으로
갈리지 않는다. `UI_KIT_SRS` 가 `--ui-font:11px` 하나를 세웠으나 키트 밖은 그것을
모른다.

### 2.5 z-index — 44 선언 · 28 값 · 1~9999

의미의 층이 값에서 읽히지 않는다. 실측으로 드러난 어긋남:

| 무엇 | 값 | 문제 |
|---|---|---|
| `#modal-overlay` (설정 모달) | 100 | 같은 뜻인데 |
| `.ui-modal` · `.confirm-overlay` · `.bg-modal` | 200 | 값이 다르다 |
| `.toast-host` 420 · `.git-undo-toast` 400 | | 같은 토스트가 둘 |
| `.ui-menu` · `.git-menu` | 3000 | 모달보다 훨씬 위 — 뜻은 맞으나 간격이 근거 없다 |
| `.ed-find` 9997 · `.tc-copy` 9999 | | **메뉴보다 위**. 편집기 찾기 줄이 컨텍스트 메뉴를 덮는다 |
| `#boot` 1000 · `#focus-edge` 500 · `#attn-edge` 501 | | 각자 정한 값 |

`9997`·`9999` 가 요점이다 — **위에 있어야 한다는 뜻을 값으로 말할 방법이 없어서
큰 수를 골랐다.** 층이 이름을 갖지 않으면 매번 그렇게 된다.

### 2.6 포커스 — `outline:none` 17 vs `:focus-visible` 9

차이 8 이 `UX-13` 이다. 지운 자리와 되살린 자리가 짝이 맞지 않는다.

### 2.7 과도기 클래스 — D-5 가 종료 조건 없이 열려 있다

`style-kit.css` 머리말:

> **기존 클래스를 지우지 않는다** (D-5 / FR-UIK-10). `.ui-btn` 은 `.tbtn` 과
> 함께 붙는다 — e2e 131개와 기존 캐스케이드가 옛 이름 위에 서 있다.

그 판단의 근거 중 **e2e 쪽 절반은 M6 이 없앴다.** `TEST-18` 판정이 확인한 것은
e2e 가 짚는 것이 **도메인 클래스**(`.sbl-item`·`.pn-tab`)이고 CSS 정리가 바꾸는
것은 **선언**이라는 사실이다. 키트 클래스를 단독으로 짚던 자리는 두 곳뿐이었고
둘 다 닫혔다 (`M6_PROGRESS.md` §4).

남은 절반은 **캐스케이드**다. 그것은 여전히 사실이고, 그래서 D-5 를 철회하는
것이 아니라 **끝나는 조건을 준다** (§3.7).

### 2.8 모달 골격 7벌 · 버튼 외형 (실측 2026-09-13, 다섯째 세션)

**오버레이 여섯이 같은 8선언을 각자 들고 있다.** `#modal-overlay` ·
`.confirm-overlay` · `.bg-modal` · `.runs-modal` · `.gc-modal` · `.git-dialog` 의
본문은 전부 `position:fixed;inset:0;z-index:var(--z-modal);background:var(--backdrop);
backdrop-filter:blur(2px);display:flex;align-items:center;justify-content:center` 다
(`#modal-overlay` 만 `display:none` + `.open{display:flex}`). `.ui-modal` 은 그중
`backdrop-filter` 가 없다 — 일곱째가 여섯과 다른 자리는 그 하나뿐이다.

**상자 여섯도 겉모습이 같다.** `.confirm-box` · `.bg-box` · `.runs-box` · `.gc-box` ·
`.git-dialog-box` · `#modal` 은 전부 `background:var(--bg);border:1px solid
var(--border);border-radius:8px;box-shadow:var(--shadow-2)` 위에 자기 치수를 얹는다
(`#modal` 만 반경 10px · `.gc-box` 만 테두리가 `--danger`). `.ui-modal-box` 는
`--sidebar-bg` · 6px 다 — **키트가 소수**다.

**`.tbtn` 은 키트 없이 쓰이는 자리가 아홉이다.** `index.html` 의 열셋은 `ui-btn`
과 병기지만 `term-pane.js:769` · `app-statusbar.js:250·262·264` · `runs-panel.js:
198·210·234·241·813` 은 `.tbtn` 만 붙인다 — 그 자리에서 `.tbtn` 을 비우면 버튼이
맨몸이 된다. 병기가 먼저다.

**옛 버튼 클래스는 열한 종이 아니라 서른 남짓이다.** `UI_KIT_SRS` §2.1 의 열한
종에 더해, 키트 이전 뒤에 병기된 채 자기 외형을 **그대로 들고 있는** 것들이 있다
— `.modal-close` 17 · `.drawer-close` 17 · `.fe-find-*` 16×3 · `.gc-go/.gc-cancel`
14×2 · `.git-dialog-go/-cancel/-opt` 15·15·16. 병기는 됐는데 선언이 남아 있으니
키트가 그리고 옛 규칙이 다시 덮는다 — 두 벌이 한 요소 위에 있다. §7 이 그
전수다.

**탭은 이 문서의 이번 범위 밖이다.** `.pn-tab` 43 · `.sb-tab` 35 · `.mtab` 13 ·
`.ed-side-tab` 16 — 로드맵 §M7 DoD 에 탭 수렴 항목이 없고, `.pn-tab` 은 e2e 43
파일이 짚는 도메인 훅이다. §7 에 행으로 남겨 D-5 가 아직 닫히지 않았음을 말하게
한다.

## 3. 요구사항

### 3.1 색 토큰의 목록과 뜻

| ID | 요구 | 등급 |
|---|---|---|
| FR-TOK-1 | 색 토큰은 **목록이 있다.** 목록 밖의 색 토큰을 새로 만들려면 이 문서를 고친다. 목록은 **뜻**으로 갈리고 값으로 갈리지 않는다. | 필수 |
| FR-TOK-2 | 글자 토큰은 **넷**이다 — `--text-bright`(가장 또렷) · `--text`(본문) · `--text-muted`(보조) · `--text-hint`(가장 흐린 것). **넷 다 파생 토큰**이다 (§3.2). | 필수 |
| FR-TOK-2a | `--text-bright` 의 바닥은 **고정값이 아니라 그 테마에서 파생된 `--text` 가 실제로 닿은 대비**다(하한 7.0). 고정 바닥만 두면 둘 다 7.0 을 넘으면서 순서가 뒤집힌다 — 실측 6/54 가 그랬다 (D-TOK-9). | 필수 |
| FR-TOK-3 | `--text-dim` 은 **글자 토큰이 아니다.** 팔레트의 원시값으로 남아 **경계·채움·비활성 배경**에만 쓰인다. 현재의 `color:var(--text-dim)` 99곳은 `--text-hint` 로 간다 (D-TOK-2). | 필수 |
| FR-TOK-4 | 글자로 쓰이는 강조색은 별도 파생 토큰을 갖는다 — `--accent-text` · `--danger-text` · `--attn-text`. 원본 `--accent`·`--danger`·`--attn` 은 **경계·배경·틴트**용으로 남는다. 대비 요구가 용도마다 다르기 때문이다 (글자 4.5:1 vs UI 경계 3:1). | 필수 |
| FR-TOK-5 | `--bg-alt` 를 **정의한다** — 표 머리·그룹 머리의 표면. `mixHex(--bg, --text, .06)` 로 파생한다. `--border` 쪽으로 섞지 않는 것은 실측 때문이다: 테마에 따라 `border` 가 `bg` 와 거의 같아 표면이 사라진다(최소 1.001 — 없는 것과 같다). `text` 쪽은 54종 전부에서 1.067~1.202 로 **고르게** 벌어지고, 밝은/어두운 테마의 방향이 자동으로 따라온다. `var(--bg-alt,…)` 의 폴백 세 자리는 폴백을 **지운다**: 토큰이 정의되면 폴백은 거짓 안전망이다. | 필수 |
| FR-TOK-5a | 구문 강조색 여섯(`--term-red`·`green`·`yellow`·`blue`·`magenta`·`cyan`)을 **터미널 팔레트에서 파생한다.** `style-docrender.css` 가 *"터미널 팔레트에서 파생하므로 편집기·터미널·렌더가 같은 색 세계를 쓴다"*(`DOC_RENDER_VIEW_SRS` FR-DRV-13d)고 적어 두고 **그 파생을 두지 않아** 여섯 다 폴백으로 떨어지고 있었다. 구문 강조도 글자이므로 같은 바닥(4.5)을 받는다. | 필수 |
| FR-TOK-5b | 고정폭 글꼴 토큰 `--mono` 를 정의한다 — `style-docrender.css` 가 스택을 따로 적고 `style-git.css` 는 없는 `--mono` 를 읽어 `monospace` 로 떨어지고 있었다. | 필수 |
| FR-TOK-6 | 백드롭·그림자가 토큰을 갖는다 — `--backdrop`(모달 뒤) · `--shadow-1`·`--shadow-2`. `rgba(0,0,0,…)` 67곳이 여기로 수렴한다. | 필수 |
| FR-TOK-7 | 위험색·상태색·구분선이 토큰화된다 — Tokyo Night 리터럴(`#16161e`·`#7aa2f7`·`#1a1b26`·`rgba(247,118,142,…)`)이 CSS 에서 사라진다 (`UX-14`). 라이트 테마에서 사라지는 구분선은 **테마를 따르는 토큰**을 쓴다 (`UX-15`). **사상표 — 색 리터럴 (구현이 산출, 2026-09-13)**

착수 시 실측은 `:root` 밖 **116곳**이다. §2.3 의 "160곳" 은 `:root` 와 주석을
포함한 수였다. 그리고 **116 중 52 가 색이 아니었다** (아래).

| 무엇 | 곳 | 어디로 |
|---|---|---|
| `mask-image` · `-webkit-mask-image` 안의 `#000`·`rgba(0,0,0,α)` | **52** | **범위 밖** — 색이 아니다 (아래) |
| 백드롭 `background:rgba(0,0,0,α)` (α 여섯 종) | 12 | `--backdrop`(.6) · `--backdrop-soft`(.4) |
| 그림자 `box-shadow` (geometry 11종 × α 다섯 종) | 23 | `--shadow-1` · `--shadow-2` (**전체 값**) |
| 위험 틴트 `rgba(247,118,142,α)`(α 여섯 종) + `rgba(255,80,80,.1)` | 11 | `--danger-subtle`(.12) · `--danger-strong`(.2) |
| 구분선 `rgba(255,255,255,.03)` | 4 | `var(--border)` (`UX-15`) |
| `var()` 안의 Tokyo Night 폴백 + 맨 리터럴 하나 | 9 | **폴백을 지운다** (FR-TOK-5 의 규약) |
| 부팅 화면의 브랜드 발광·그림자 | 2 | `--boot-glow` · `--boot-shadow` (`--boot-brand` 옆) |
| 성공색 `#4caf50` · `--run-ok:#9ece6a` | 2 | `var(--term-green)` |
| 문서의 종이색 `#fff` | 1 | `--doc-paper` |
| | **116** | |

**마스크의 `rgba` 는 색이 아니다.** `mask-image` 는 **알파 채널만** 읽는다 —
`#000` 은 "알파 1", `rgba(0,0,0,.18)` 은 "알파 .18" 이고 RGB 는 버려진다.
`#focus-edge` 의 주석이 이미 적어 뒀다: *"흐려지는 것은 마스크의 알파이지 화면의
픽셀이 아니다"*(D-6). **알파 값에 색 이름을 붙이는 것은 거짓말**이므로 이 52곳은
FR-TOK-29 의 범위 밖이다. 게이트는 건너뛴 수를 **출력에 찍는다** — 조용한 예외는
예외가 아니라 구멍이다.

**백드롭이 둘인 것은 뜻이 둘이기 때문이다** (사용자 결정 2026-09-13).
`--backdrop` 은 **막는다**. `--backdrop-soft` 는 **뒤가 보여야 한다** —
`.pn-dimmed` 의 "클릭하여 포커스" 는 도는 터미널 위에 얹히고 그 터미널이 보이는
것이 그 오버레이의 요구다. 한 값으로 접으면 "이 칸은 다른 창이 가진다" 가 "이 칸을
보지 말라" 가 된다. 변하는 자리는 넷이다: 드로어 .5→.6 · 모달 .55→.6 ·
팔레트 .35→.4 · `.tp-overlay` .7→.6.

**그림자는 색이 아니라 전체 `box-shadow` 값이다** (사용자 결정 2026-09-13).
알파만 토큰화하면 `0 1px 4px`·`0 2px 10px`·`0 2px 12px`·`0 4px 16px`·`0 6px 20px`·
`0 6px 24px`·`0 8px 32px` **일곱이 남고**, 그것은 글자 크기 12종·z-index 28값과
정확히 같은 부류다 — 값이 뜻을 말하지 않으면 다음 사람은 옆줄을 베껴 쓴다. 뜻은
둘이다: 화면에 붙은 것(`--shadow-1: 0 2px 10px`)과 떠 있는 것
(`--shadow-2: 0 8px 32px`). 업줄이 달라지는 자리는 10곳이고 모달·메뉴 11곳은
그대로다.

**구분선은 3:1 을 받지 않는다 — 실측이 초안을 정정했다** (`UX-15`).

| 토큰 | 3:1 미달 | 범위 (`--bg`·`--sidebar-bg` 중 나쁜 쪽) |
|---|---|---|
| `--border` | **54 / 54** | 1.00 ~ 1.74 (Solarized 둘은 **1.00** — 경계가 배경과 같은 색) |
| `--border-strong` | **36 / 54** | 1.48 ~ 3.94 |

초안이 제시한 첫 선택지(`--border-strong`)가 **자기 요구를 만족시키지 못한다.**
그래서 판정을 바꿨다: 이 넷은 **장식용 구분자**다 — 행을 식별하는 것은 라벨과
컨트롤이고 선이 아니다. WCAG 1.4.11 은 "UI 컴포넌트를 식별하는 단서" 와 "내용
이해에 필요한 그래픽" 에만 3:1 을 걸므로 이 구분선은 대상이 아니다. `UX-15` 의
**실제 결함**은 값이 `rgba(255,255,255,.03)` — **하드코딩된 흰색**이어서 라이트
테마에서 흰 바탕 위 흰 선이 된다는 것이고, 그것은 `var(--border)` 로 해소된다.
앱의 다른 모든 구분선이 이미 그 토큰을 쓴다. 3:1 을 받는 구분선이 필요해지면
그것은 **새 파생 토큰**(`liftContrast(border, anchor, bgs, 3.0)`)이고 이 문서를
고치는 일이다 — `--border-strong` 은 `SLOT_TITLE_BOUNDARY_SRS` 가 **구조 경계**용
으로 소유한 토큰이므로 그 자리에 쓰지 않는다.

### 3.4 z-index 계층

| ID | 요구 | 등급 |
|---|---|---|
| FR-TOK-21 | z-index 는 **여섯 층**의 토큰으로 수렴한다. 층은 **뜻**이고 값은 그 뜻의 부산물이다. (초안은 다섯이었다 — 사상표를 만들다 여섯째가 필요해졌다. 아래 "왜 여섯인가" 를 본다. 사용자 결정 2026-09-13) | 필수 |
| FR-TOK-22 | 층 안의 순서는 **DOM 순서**가 정한다. 같은 층에서 값을 ±1 하지 않는다 — `#focus-edge` 500 / `#attn-edge` 501 이 그 부류다. | 필수 |
| FR-TOK-23 | 44개 선언 전부가 여섯 토큰 중 하나로 사상되고, **사상표가 이 문서에 남는다.** 사상할 수 없는 선언이 있으면 층이 부족한 것이고, 그때 층을 더하는 것은 이 문서를 고치는 일이다. | 필수 |

**층 (§2.5 의 실측 + 44선언 전수 사상에서 도출)**

| 토큰 | 뜻 | 여기 있는 것 |
|---|---|---|
| `--z-raised` | 같은 뷰 안에서 한 겹 위 | 분할 손잡이 · 드래그 표식 · 편집기 안의 알림 줄 |
| `--z-sticky` | 뷰 안의 고정 요소 | 탭 줄 · 목록 머리 · 검색 줄 · 모바일 키바 |
| `--z-overlay` | 뷰를 덮는 것 | 백드롭 · 드로어 · 부팅 화면 · 칸을 덮는 것 |
| `--z-modal` | 모달·확인창 상자 | `.ui-modal` · `#modal-overlay` · `.confirm-overlay` · `.bg-modal` · **`.ed-find`** |
| `--z-popover` | 모달 **위**에 뜨는 것 | 메뉴 · 토스트 · HUD · `.tc-copy` · 드롭다운 |
| `--z-edge` | 창 수준의 **비상호작용** 표식 | `#focus-edge` · `#attn-edge` |

**왜 여섯인가.** D-TOK-8 이 답을 미리 적어 뒀다 — *"같은 층이면 DOM 순서가
답이고, DOM 순서로 답할 수 없으면 **층이 다른 것**이다."* `#focus-edge`(500)·
`#attn-edge`(501)는 `position:fixed;inset:0;pointer-events:none` 인 **창 전체
테두리 표식**이고, 지금 모달(200·300)·토스트(420)·HUD(450) 위에 있다. 다섯 층에
넣으면 `--z-overlay` 가 되어 **설정 모달이 포커스 테두리를 덮는다** — 어느 창이
포커스를 가졌는지가 모달을 열면 안 보인다. `--z-popover` 로 올리면 뜻이 어긋난다:
popover 는 사용자가 **띄우는** 것이고 이 둘은 사용자가 띄우지 않는다. 그래서
층이 다르다. 두 표식 사이의 순서(500/501)는 같은 층 안에서 DOM 이 정한다 —
FR-TOK-22 가 지목한 바로 그 ±1 이 사라진다.

**`.ed-find` 는 편집기 찾기 줄이 아니다** (초안 정정). §2.5 가 `.ed-find`(9997)를
"편집기 찾기 줄" 로 읽고 `--z-popover` 에 넣었으나 실측은 다르다 —
`position:fixed;inset:0;background:rgba(0,0,0,.35)` 로, **배경을 깐 전체 화면
팔레트**다(빠른 열기·전체 검색이 같은 껍데기를 쓴다). 편집기 안의 찾기 줄은
`.fe-find`(12) 쪽이고 그것은 `.file-editor` 안에 사는 `--z-raised` 다. 그래서

**`.search-bar` 의 `z-index` 는 무력하다.** 그 규칙에 `position` 이 없어서

**`--z-raised` 는 1 이 될 수 없다.** `.fe-dd-peek` 의 `6` 은 임의값이 아니다 —

**`.file-editor` 의 세 겹은 DOM 순서가 답하지 못했다** (사용자 결정 2026-09-13).
`.fe-offer`(11) · `.fe-find`(12) · `.fe-note`(13) 은 셋 다 **첫 사용 시점에**
`appendChild` 된다 (`file-editor.js:944`·`966`, `file-editor-find.js:76`) — 사용자가
무엇을 먼저 건드렸느냐로 DOM 순서가 갈린다. 그러면서 **알림과 찾기는 좌표가
같고**(`top:6px;right:18px`) 찾기는 제안 띠 위에 얹힌다. FR-TOK-22 의 "DOM
순서가 정한다" 가 여기서는 답이 없다.

그래서 **보일 때 맨 뒤로 옮긴다** — `findOpen` 과 `note()` 가 `appendChild` 로
자신을 끝에 다시 붙인다. "마지막에 보인 것이 위" 이고, 그것이 사용자가 방금 한
일을 보여 준다. **동작 1건이 바뀐다**: 종전 사다리는 알림이 **항상** 위였고,
좌표가 같으므로 알림이 뜬 동안 찾기를 열면 **방금 열어 놓은 입력 칸이
가려졌다.** 이제 찾기가 보인다 — 변경이면서 거의 수정이다.

**`#focus-edge` / `#attn-edge` 의 ±1 은 DOM 순서로 옮겼다.** 종전 500/501 은
D-TOK-8 이 지목한 "누가 위인가를 값으로 적은 자리" 다. 같은 층(`--z-edge`)에
두고 `index.html` 에서 **`#attn-edge` 를 뒤로** 옮겼다 — 알림 테두리가 포커스
테두리 위여야 하기 때문이다(종전 501 > 500): `#focus-edge` 의
`backdrop-filter:invert` 가 알림색을 뒤집으면 알람이 알람으로 보이지 않는다.
동작은 같고 ±1 은 사라졌다.

**`.git-commit` 의 선언이 사라졌다 — 층 체계가 그것을 불필요하게 만들었다.**
종전 `.git-commit{position:relative;z-index:5}` 는 **메뉴를 형제들 위로
들어올리려고 상자에 걸린 값**이었다(그 규칙의 주석이 그렇게 적고 있다 — 뒤따르는
`.git-changes-body` 가 메뉴를 가려 클릭이 먹지 않았다).

그 방식의 대가가 실측으로 드러났다: **메뉴의 층이 상자의 층에 갇힌다.**
`.git-files-bar` 가 `--z-sticky`(200, 그 규칙은 진짜 `position:sticky` 다)로 가자
상자(`--z-raised` 100)보다 위가 되어 메뉴의 클릭이 다시 먹지 않았다.

그래서 `position:relative` 만 남기고 **층은 메뉴가 자기 것을 쓴다**
(`.git-commit-menu` → `--z-popover` 500). 상자는 쌓임 문맥을 만들지 않으므로 그
500 이 `.git-view` 문맥에서 실제로 효력을 갖고, `.git-files-bar`(200)·
`.git-head`(100)·목록 행(0)을 전부 넘는다.

**이것이 층 체계가 있는 이유다**: 팝오버는 팝오버 층에 있으면 되고, 그것을 담은
상자가 같이 올라갈 필요가 없다. 상자를 올리는 방식은 그 상자와 형제들의 값을
**영원히 서로 매어 둔다** — 44선언을 값으로 다투던 시절의 문법이다. 선언 하나가
줄어 **43** 이 됐고, 그것이 이 마일스톤이 무엇을 없앴는지를 말한다.

## 4. 설계 결정

**D-TOK-1: 팔레트는 정본이고 파생이 보장한다.**

  (사용자 결정 2026-09-12)
  54벌의 `textMuted`·`textDim` 을 손으로 올리는 대안은 두 가지를 잃는다: ① 정본
  팔레트와의 대조 가능성 — Nord·Solarized·Gruvbox 는 상류에 원본이 있고 그것과
  다르면 "우리가 왜 다른가" 를 매번 설명해야 한다. ② 새 테마의 안전 — 사람이
  손으로 맞춰야 하고, 맞추지 않으면 조용히 미달로 들어온다. 파생은 **새 테마도
  자동으로 받는다.**

**D-TOK-2: `--text-dim` 의 뜻을 가른다.**

  한 토큰이 글자(99곳)와 경계·채움(5곳)
  양쪽에 쓰이고 있었다. 글자의 바닥은 4.5, UI 경계의 바닥은 3:1 이므로 **같은
  값일 수 없다.** `--text-dim` 을 비글자용 원시값으로 남기고 `--text-hint` 를
  새로 세운다. 이름을 바꾸지 않고 값만 올리면 경계까지 밝아져 테마가 뭉개진다.

**D-TOK-3: 앵커는 `--text-bright`.**

  배경 반대편 극단(흰색/검은색)으로 바로
  섞지 않는 이유는 **색상(hue)을 잃기 때문**이다 — Gruvbox 의 흐린 글자가 회색이
  되면 Gruvbox 가 아니다. `--text-bright` 는 그 테마가 스스로 고른 "가장 또렷한
  글자" 이므로 그 쪽으로 섞으면 테마 안에 머문다. 실측 53/54 가 이 앵커로 닿고,
  닿지 않는 1종만 흑/백으로 내려간다.

  **내려갈 때 모드를 보지 않는다.** 초판 초안은 `mode` 로 흑/백을 갈랐는데,
  게이트 탐침이 그것이 틀릴 수 있음을 드러냈다: 배경이 `#808080` 이면 검은색이
  5.32 인데 흰색은 3.95 다 — `mode:'dark'` 를 따르면 **더 나쁜 쪽**을 고른다.
  `mode` 는 배경의 밝기를 **짐작한** 값이고, 여기서는 짐작할 필요 없이 **재면
  된다**. 동률일 때만 `mode` 가 가른다.

  **그리고 닿지 못하는 팔레트가 있다.** 중간 밝기 배경에서는 흰색도 검은색도
  7.0 에 미치지 못한다 — 그 배경 위에 그 대비는 **존재하지 않는다.** 내장 54종에는
  없고 게이트가 새로 들어오는 것을 막지만, 사용자 지정 테마는 게이트를 지나지
  않는다(FR-TOK-17). 그때 파생은 **닿을 수 있는 가장 먼 곳**을 준다 — 바닥을 못
  넘는 것과 원래 색 그대로 두는 것 중에는 앞이 낫다.

**D-TOK-4: 바닥은 사다리다 (4.5 / 5.5 / 7.0).**

  이것이 이 문서에서 가장 비싼
  결정이고, **실측이 결정했다.** 세 토큰에 같은 바닥 4.5 를 주면:

  > 미달 0 · **계층깨짐 34/54** · `--text-muted` − `--text-hint` 간격 평균
  > **−0.03** (최소 −0.57)

  가장 흐리던 것(`--text-dim`, 시작 1.28)이 가장 많이 올라가 **중간 단계를 추월
  한다.** Dracula 에서 hint 4.88 > muted 4.73 이 된다 — 흐리라고 만든 색이 더
  진해진다. 사다리(4.5 / 5.5 / 7.0)를 주면:

  > 미달 0 · **계층깨짐 0/54** · 간격 muted−hint 평균 0.95(최소 **0.56**) ·
  > text−muted 평균 4.28(최소 **1.04**)

  `--text` 의 7.0 은 **AAA 수준이지만 부담이 아니다** — 중앙값이 이미 9.84 이고
  손대는 테마가 13/54 뿐이다. 접근성을 위해 고른 값이 아니라 **아래 두 단계가
  숨 쉴 공간**을 만들려고 고른 값이다.

**D-TOK-5: 게이트와 런타임이 같은 함수를 쓴다.**

  게이트가 값을 다시 계산하면
  둘이 갈라지고, 갈라진 순간 **게이트는 초록인데 화면은 미달**이 된다. M6
  "비싸게 배운 것 9"(초록인 게이트와 재고 있는 게이트는 다르다)의 같은 부류다.
  그래서 파생은 의존 0 의 순수 모듈이어야 한다 (NFR-TOK-4).

**D-TOK-6: 미정의 프로퍼티는 폴백이 있어도 잡는다.**

  `style-docrender.css` 의
  `var(--bg-alt,var(--bg))` 는 지금 **동작한다** — 그러나 그 자리는 `--bg-alt` 가
  있다고 믿고 쓴 자리이고, 폴백은 그 믿음이 틀렸다는 사실을 숨긴다. 같은 묶음의
  네 자리가 폴백 없이 투명으로 떨어진 것이 그 증거다.

**D-TOK-7: 과도기의 끝은 "선언이 비었는가" 다.**

  날짜나 마일스톤이 아니라
  **파일이 말하는 조건**이어야 한다 — D-5 가 종료 조건 없이 열린 이유가 그것을
  사람의 판단에 맡겼기 때문이다. 선언이 0개면 그 클래스는 더 이상 외형을 주지
  않고, 그때부터 그것은 **선택자**이지 스타일이 아니다.

**D-TOK-9: `--text-bright` 의 바닥은 `--text` 가 정한다.**

  초안은 글자 토큰을 셋으로 적었다. 구현 중 실측이 넷째를 드러냈다 —
  `--text-bright` 는 `color:` 로 **103번** 쓰이는데, `--text` 를 7.0 까지 올리고
  나면 **6/54 에서 bright 가 본문보다 흐려진다.** Solarized Light 의 `#586e75` 는
  4.39 로 AA 자체를 못 넘었다. "가장 또렷한 글자" 가 본문보다 흐린 것은 이름이
  거짓말을 하는 상태다.

  고정 바닥(가령 8.0)으로는 풀리지 않는다 — 테마마다 `--text` 가 닿는 곳이
  달라(7.0~19.03) 어떤 고정값도 어떤 테마에서는 뒤집힌다. 그래서 바닥을
  **그 테마의 파생된 `--text`** 로 잡는다. 앵커가 이미 그 대비를 넘으므로 항상
  닿는다.

  **한 자리만 예외다**: 앵커가 `textBright` 자신이면 그리로 섞는 것이 제자리
  걸음이다. Monokai 가 그렇다 — 팔레트의 `#f8f8f0`(13.93)이 `#f8f8f2`(13.94)보다
  0.01 흐리다. **팔레트 자신의 모순**이지 파생이 만든 것이 아니다. 그때는 둘을
  합친다: 본문이 곧 가장 또렷한 글자다.

**D-TOK-8: z-index 층 안에서 값을 다투지 않는다.**

  `#focus-edge` 500 /
  `#attn-edge` 501 은 "이 둘 중 누가 위인가" 를 값으로 적은 자리다. 같은 층이면
  DOM 순서가 답이고, DOM 순서로 답할 수 없으면 **층이 다른 것**이다.

**D-TOK-10: 상자의 겉모습은 다수값이 진실이다 — 키트를 고친다.**

  (사용자 결정 2026-09-13)
  `.ui-modal-box` 는 `--sidebar-bg` · 6px 인데 옛 상자 여섯은 전부 `--bg` · 8px 다
  (§2.8). 세 갈래가 있었다: ① 키트를 다수값으로 고친다 — 옛 여섯의 화면은
  그대로이고 키트 모달 셋만 바뀐다. ② 키트 값이 진실 — 설정·확인창·git
  다이얼로그 등 자주 보는 화면 전부가 바뀐다. ③ 구조만 접고 겉모습은 각자 —
  선언이 0 이 되지 않아 D-5 가 닫히지 않는다. **①** 을 택했다: 변경 표면이 가장
  작고, 키트가 "표준" 인 이유는 값이 아니라 **한 자리**라는 데 있다.

**D-TOK-11: 과도기 클래스의 "0" 은 외형의 0 이고, 이름을 키로 쓰는 배치 규칙은
옮긴다.**

  (실측 2026-09-13)
  `.tbtn` 의 18선언 중 열넷은 외형(`padding`·`border`·`background`·`color`·
  `:hover`)이고 넷은 **이름을 훅으로 쓰는 배치**다 — `.slot-ctl .tbtn{min-width}`
  · `body.mobile .tp-ov-acts .tbtn{min-height:var(--touch-min)}`. `.mtbtn` 도
