## 1. 개요

### 1.1 목적

접수한 말은 이렇다.

> **"탭 이름표의 크기는 탭의 이름에 따라 너비가 달라지잖아. 이거 고정하는 옵션.
> vsc 에도 있는 옵션이니까 확인해봐."**

이름이 길면 탭이 넓어지고 짧으면 좁아지므로, **같은 탭이 이웃의 이름이 바뀔 때마다
다른 자리로 옮겨 간다.** 손이 기억한 위치가 무효가 되고, 연속으로 닫을 때 다음 탭이
커서 밑으로 오지 않는다.

### 1.2 VSCode 의 계약 (확인함, 2026-09-06)

지시대로 확인했다. 출처는 `workbench.contribution.ts` 의 설정 스키마다.

| 설정 | 타입 | 값 | 기본 |
|---|---|---|---|
| `workbench.editor.tabSizing` | string | `fit` · `shrink` · `fixed` | `fit` |
| `workbench.editor.tabSizingFixedMinWidth` | number (최소 38) | — | 50 |
| `workbench.editor.tabSizingFixedMaxWidth` | number (최소 38) | — | 160 |

- `fit` — "Always keep tabs large enough to show the full editor label."
- `shrink` — "Allow tabs to get smaller when the available space is not enough…"
- `fixed` — "Make all tabs the same size, while allowing them to get smaller…"

**지금 이 앱은 `fit` 이다** — `.pn-tab{white-space:nowrap;flex-shrink:0}` (style.css:288).

### 1.3 인터뷰에서 확정한 것 (2026-09-06)

| 물음 | 확정 | 뜻 |
|---|---|---|
| 옵션의 범위 | **고정 토글 하나 + 폭 하나** | VSCode 의 3값을 그대로 옮기지 않는다. `shrink` 는 제공하지 않으며, 최소/최대 두 값 대신 **폭 하나**다 |
| 넘칠 때 | **지금처럼 가로 스크롤** | 고정 폭은 **언제나** 지켜진다 — 자리가 모자라도 줄이지 않는다. `.pn-tabs{overflow-x:auto}` 를 건드리지 않는다 |

**그래서 이 문서의 `fixed` 는 VSCode 의 `fixed` 와 다르다.** VSCode 것은 공간이
부족하면 최소 폭까지 줄어들지만, 여기서는 줄어들지 않고 스크롤한다 (D-2).

### 1.4 정의

| 용어 | 정의 |
|---|---|
| **탭** | 칸(pane)의 탭 줄에 서는 항목 (`.pn-tab`) — 터미널·편집기·Git 뷰 전부 |
| **고정 너비** | 이름의 길이와 무관하게 모든 탭이 갖는 같은 너비 |
| **탭 줄** | `.pn-tabs` — 가로 스크롤하는 컨테이너 |

### 1.5 참조

- `web/style.css:282~297` (`.pn-tabs`·`.pn-tab`·`.pn-tab-x`)
- `web/js/ui/renderer.js:590` (탭 골격), `web/js/core/app-settings.js:8` (`saveSettings`)
- VSCode `workbench.contribution.ts` — §1.2

## 2. 현재 상태 (조사로 확정한 사실)

```css
/* style.css:282 */
.pn-tabs{height:28px;min-height:28px;display:flex;align-items:stretch;
  background:var(--sidebar-bg);border-bottom:1px solid var(--border);
  overflow-x:auto;flex-shrink:0}
/* style.css:288 */
.pn-tab{display:flex;align-items:center;padding:0 10px;gap:4px;
  font-size:12px;color:var(--text-muted);cursor:pointer;
  border-right:1px solid var(--border);white-space:nowrap;flex-shrink:0}
```

- `flex-shrink:0` + `white-space:nowrap` → 라벨 전체가 보이는 폭. 곧 `fit` 이다
- 탭 하나의 구조는 `<span class="pn-tab-label">` + `<span class="pn-tab-x">×</span>`
  (`renderer.js:590`) — 라벨에 `overflow`·`text-overflow` 규칙이 **없다**
- 설정은 `/api/settings` 블롭 하나에 실린다. `saveSettings` 가 **읽어 쓰는 값을
  전부 다시 실으므로**, 새 값을 그 목록에 더하지 않으면 다른 설정을 바꿀 때
  조용히 사라진다 (`app-settings.js:11` 의 주석이 그 함정을 적어 두었다)

## 3. 기능 요구사항

**FR-TBW-1** 설정 ▸ Display 에 **`탭 너비 고정`** 토글이 선다. 기본은 **끔**이며,
끈 상태의 동작은 지금과 **완전히 같다** (FR-TBW-9).

**FR-TBW-2** 그 아래 **`탭 너비 (px)`** 입력이 선다. 기본값은 **160** 이다 — VSCode
의 `tabSizingFixedMaxWidth` 기본과 같은 값이며, 그것이 "긴 이름도 웬만큼 보이는
폭"으로 이미 검증된 수다.

**FR-TBW-3** 폭의 하한은 **40px** 이다. 그보다 좁으면 닫기(`×`)가 들어갈 자리가
없어 **닫을 수 없는 탭**이 된다 (D-3 이 실측 근거). 상한은 **480px** 이다.

**FR-TBW-4** 범위를 벗어난 값은 **하한·상한으로 잘린다.** 거부하지 않는다 — 숫자
입력은 타이핑 도중에 잠깐 범위 밖이 되며, 그때마다 오류를 내면 입력이 불가능해진다.

**FR-TBW-5** 고정이 켜지면 **모든 탭이 그 너비를 갖는다.** 이름이 그보다 길면
말줄임(`…`)으로 잘린다. 짧아도 그 너비를 채운다.

**FR-TBW-6** **잘린 이름은 툴팁이 밝힌다.** 말줄임만 있고 전체 이름을 볼 길이
없으면, 고정 폭은 이름을 읽을 수 없게 만드는 기능이 된다.

**FR-TBW-7** 고정 폭은 **언제나 지켜진다.** 탭이 많아 줄이 넘치면 지금처럼 가로
스크롤한다 (인터뷰 확정) — 폭을 줄이지 않는다.

**FR-TBW-8** 설정은 **서버에 저장되어 기기 사이에 따라온다.** 다른 표시 설정과 같은
블롭(`/api/settings`)에 실린다.

**FR-TBW-9 (끈 상태의 불변)** 토글이 꺼져 있으면 탭의 폭·말줄임·툴팁이 **지금과
같다.** 이 기능은 켠 사람에게만 보인다.

**FR-TBW-10** 값을 바꾸면 **곧바로 반영된다.** 새로고침을 요구하지 않는다.

**FR-TBW-11** `+`(탭 추가, `.pn-tab-add`)는 대상이 아니다 — 탭이 아니라 진입점이며,
고정 폭을 주면 이름 없는 버튼이 탭만큼 넓어진다.

## 4. 비기능 요구사항

**NFR-TBW-1** 폭은 **CSS 변수 하나**(`--tab-w`)로 전달한다. 탭마다 인라인 스타일을
쓰지 않는다 — 탭이 수십 개일 때 재계산이 그 수만큼 늘고, 규칙이 CSS 와 JS 두 곳에
갈린다.

**NFR-TBW-2** 켜고 끄는 것은 **클래스 토글 하나**다 (`body.tabfix`). 렌더러가 탭을
다시 만들지 않는다 — 다시 만들면 그 순간 스크롤 위치와 드래그 상태가 날아간다.

## 5. 설계 결정

**D-1** VSCode 의 3값을 옮기지 않고 **토글 하나**로 좁힌다 (인터뷰 확정). 근거는
접수한 말이 "고정하는 옵션" 하나였다는 것이다. `shrink` 는 지금의 스크롤과 겹치는
동작이라, 셋을 다 두면 "스크롤과 줄임 중 무엇이 언제 이기는가"를 사용자가 알아야
한다.

**D-2** VSCode 의 `fixed` 는 공간이 부족하면 줄어들지만 **여기서는 줄어들지
않는다** (인터뷰 확정). 그래서 이 문서는 그 값을 `fixed` 라 부르지 않고 **`탭 너비
고정`** 이라 부른다 — 같은 이름을 다른 뜻으로 쓰지 않는다.

**D-3** 하한이 40px 인 근거는 실측이다: `.pn-tab` 은 좌우 패딩 20px + gap 4px +
`.pn-tab-x`(11px 글자)를 쓰므로 **이름 이전에 이미 소비되는 폭**이 있다.

**구현 뒤 40px 에서 실측했다** (2026-09-06):

```
X-BOX: {"tabW":40, "xW":6.44, "inside":true, "visible":"1"}
```

닫기(`×`)가 탭 경계 안에 온전히 들어가고(`inside:true`) 폭이 0 이 아니다 — 즉
**누를 수 있다.** 이름은 한 글자와 말줄임(`a…`)이 선다. 그보다 좁으면 닫기가
잘려 **닫을 수 없는 탭**이 된다.

**D-4** Git 창의 뷰 탭(`.pn-tab.git`)도 **같은 규칙을 받는다.** 예외를 만들면 "왜
어떤 탭만 고정인가"가 생기고, 그 판정이 CSS 와 사용자의 머릿속 두 곳에 살게 된다.
뷰 탭의 이름은 짧아 고정 폭이 남지만, 그 남는 자리는 **일관성의 값이다.**

**D-5** 툴팁(FR-TBW-6)은 **고정 여부와 무관하게 언제나** 붙인다. 켠 뒤에만 붙이면
그 붙이는 시점이 설정 변경 경로에 생기고, 그 경로를 타지 않는 탭(이미 그려진 것)이
빠진다. 언제나 붙이면 `fit` 에서는 잘릴 일이 없어 보이지 않을 뿐이다.

## 7. 비목표

1. **`shrink` 모드** (D-1).
2. **최소·최대 두 값** — 폭 하나다 (인터뷰 확정).
3. **탭 줄 접기(wrap)** — VSCode 의 `wrapTabs` 에 해당하는 것. 접수한 말 밖이다.
4. **탭 순서·핀 고정** — 이 문서는 폭만 다룬다.
5. **사이드바 목록(`.si`)·Git 뷰 진입점(`.ed-side-act`)의 폭** — 탭이 아니다.

## 7.1 구현하며 확정한 사실

| # | 사실 | 결과 |
|---|---|---|
| 1 | **폭을 바꾸고 곧바로 새로고침하면 값이 날아갔다** (실측, W7). 디바운스 500ms 가 끝나기 전이었다 | 디바운스는 타이핑 중 요청 폭주를 막는 장치이지 확정을 미루는 장치가 아니다 — `blur` 에서 대기 중인 타이머를 취소하고 **곧바로 저장**한다. 포커스를 놓는 순간이 곧 확정이다 |
| 2 | 저장·로드 자체는 정상이었다 | 원인을 가르려고 둘을 따로 쟀다: 서버에 `{tabFixedWidth:true, tabWidthPx:120}` 이 실렸고, 새로고침 뒤 `--tab-w:120px` 과 `body.tabfix` 가 섰다. 그래서 남는 것이 타이밍뿐임이 드러났다 |
| 3 | 하한 40px 에서 닫기가 실제로 닿는다 | D-3 에 실측값을 적었다 |
| 4 | 탭의 `title` 을 단정하거나 폭을 재는 기존 e2e 가 **없다** | 그래서 R2 가 실현되지 않았다 — 새 `title`(FR-TBW-6)이 기존 시험과 부딪히지 않는다 |
| 5 | 전체 회귀에서 남은 실패 둘(`sidebar-tabs` T6 · `slot-view-state` TC-SVS-50)은 **본 변경 전 기준선에서 실패하던 것과 정확히 같다** | UX_BATCH5_SRS §8.1 이 잰 기준선(변경 전 1075/2)의 실패 집합과 일치한다 — 새 실패를 만들지 않았다 |
