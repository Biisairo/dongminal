## 4. 발견

1. **서버의 `git` 실행이 60초에 17번에서 0번이 되었다.** idle-git·idle-closed 모두 그렇다. 4.9 가 작업 트리 `git status` 를 파일 감시 사건으로 바꾸었고, 4.14 가 gitdir 해석(`git rev-parse`)의 30초 시간 만료를 없앴다. 이제 gitdir 은 첫 회차에 한 번 해석하고, `.git` 자체가 바뀐 사건·감시 넘침·물러섬 회차에서만 다시 해석한다.
2. **데몬의 `ps` 실행이 60초에 17~21번에서 0번이 되었다.** 전경이 셸이 아닐 때(`--idle-fg`)도 그렇다. 4.6 이 전경 이름 조회를 PTY 입출력 뒤 한 번으로 바꾸었고, 4.7 이 이름·cwd·부모를 libproc 로 읽는다.
3. **페이지를 닫은 뒤(idle-closed) 깨어남이 가장 많이 줄었다.** 서버 CSW 는 14.1 → 2.9/초, 데몬 CSW 는 9.5 → 0.5/초다. 1초 스위퍼·유휴 판정(4.8), 2초 전경 poll(4.8), 2초 sysstat 샘플러(4.10), 1초 상시 gitwatch 회차(4.9)가 사라진 결과와 맞는다.
4. **페이지가 열린 idle 에서도 서버 CSW 는 13.6 → 8.9/초, 데몬은 11.9 → 5.8/초다.** 남은 깨어남은 채널 ping·`stats:` 발행(구독 중, 초당 약 1.4 프레임)과 toolclient 심장박동 같은 남기는 주기(CHANNEL_PROTOCOL §10.5 표)다.
5. **데몬 RSS 는 평균 21.5 → 19.5 MB 다.** 6회 가운데 4회가 18.4~18.5 MB, 2회가 21.5 MB 다.
6. **IDLEW 는 이번에 0 이 아닌 값이 나왔다.** 기계 부하가 낮아(부하 평균 약 3) 코어가 유휴 상태로 갔기 때문으로 본다(추정). 값은 초당 0~1.6 으로 작다. 기준선과 기계 부하가 달라서 IDLEW 는 비교에 쓰지 않는다. CSW 를 주 지표로 쓴다(기준선 §2 와 같다).

## 5. 조건 차이

- 기계 부하: 기준선은 다른 작업과 함께 돌아 부하 평균이 18~30 이었다. 이번에는 측정 뒤 약 3 이었다. CPU %·CSW 는 프로세스 자신의 값이라 부하의 영향이 작다. 그러나 비교에 이 차이를 고려한다.
