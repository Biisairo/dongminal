# SRS: 글자 크기 설정 (IEEE 29148 준수)

> **문서 상태**: 승인·구현완료

## 1. 개요

### 1.1 목적

화면의 글자 크기를 **사용자가 정할 수 있게** 한다. 지금은 두 값 모두 코드에
박혀 있어 바꿀 길이 없다 — UI 는 `--fs-*` 다섯의 px 리터럴이고, 터미널은 그중
`--fs-lg`(14px)를 읽는다.

### 1.2 범위

설정 둘과 그것이 얹히는 자리다.

| 설정 | 단위 | 대상 |
|------|------|------|
| `uiFontScale` | 배율 % | `--fs-*` 다섯 · 크기 토큰 · Monaco 편집기 |
| `termFontSize` | px | xterm 터미널 |

**둘은 서로 독립이다.** 사용자 결정 2026-09-19: *"터미널 + UI 각각 따로"*.
지금은 터미널이 `--fs-lg` 에 묶여 있으므로 **그 결합을 끊는 것이 이 스펙의
절반**이다 (§2.1).

### 1.3 비목표

- **단축키와 Ctrl+휠.** 조작 수단은 설정 모달의 컨트롤 하나씩이다 (사용자 결정
  2026-09-19). `term-pane.js:174` 가 `Ctrl+` 조합을 터미널로 통과시키고 `Cmd+`
  를 브라우저에 남기므로, 단축키를 열면 그 규약과 브라우저 줌 양쪽을 함께
  정리해야 한다 — 이 스펙이 지지 않는다.
- **탭·pane 별 글자 크기.** 값은 전역 하나다. pane 별로 두려면 크기를 pane
  상태에 싣고 레이아웃 프리셋·재접속까지 보존해야 한다.
- **rem 전환.** §2.6.
- **글자 종류(font-family).** 이 스펙은 크기만 다룬다.
- **테마 미리보기의 글자.** `DESIGN_TOKENS_SRS` §3.3 이 *"테마 미리보기는
  `--fs-*` 를 쓰지 않는다"* 로 이미 갈라 두었다 (`.pv-status` 7px 등). 그 규약은
  그대로이고, 미리보기는 배율을 따르지 않는다.

## 2. 전체 기술

### 2.1 `FR-M11-15` 의 개정

`M11_SRS` `FR-M11-15`(2026-09-15)는 *"하단의 글꼴은 터미널과 같은 상수에서
온다"* 였다. 그때 `TOPTS.fontSize:14` 를 **지우고** CSS 토큰 `--fs-lg` 를 단일
진실로 삼았다 — 요구의 절반이 *"값이 두 벌이 되지 않는 것"* 이었기 때문이다.

**그 조항이 묶던 두 자리 중 하나는 이미 없다.** `.agp-dash` 는 에이전트 GUI 와
함께 제거됐고(`AGENT_GUI_REMOVAL_SRS`), `agp-dash` 는 `web/`·`e2e/` 어디에도
남아 있지 않다. 검증 `V-M11-35`(*"`.agp-dash` 의 글꼴이 터미널과 같다"*)는 잴
대상을 잃었다.

남은 것은 **짝을 잃은 결합**이다. 터미널이 UI 토큰을 읽을 이유가 그 조항 말고는
없고, 그 결합이 있는 한 UI 를 키우면 터미널이 따라 커진다 — 사용자가 갈라
달라고 한 바로 그 동작이다.

그러므로 **개정한다**: 터미널 글꼴은 자기 설정 `termFontSize` 에서 온다. 값이 두
벌이 되지 않는다는 `FR-M11-15` 의 정신은 유지된다 — 터미널 글꼴의 진실은 여전히
한 자리이고, 그 자리가 CSS 토큰에서 설정 키로 옮길 뿐이다.

### 2.2 배율은 곱셈이다 — 기준값은 그대로 남는다

`--fs-*` 다섯의 px 값(9·11·12·14·18)은 `DESIGN_TOKENS_SRS` §3.3 의 사상표가
근거를 든 **실측 결과**다. 배율은 그 값을 **대체하지 않고 곱한다**.

```css
:root{
  --fs-scale:1;
  --fs-xs:calc(9px  * var(--fs-scale));
  --fs-sm:calc(11px * var(--fs-scale));
  --fs-md:calc(12px * var(--fs-scale));
  --fs-lg:calc(14px * var(--fs-scale));
  --fs-xl:calc(18px * var(--fs-scale));
}
```

이렇게 두면 **`var(--fs-*)` 사용처 374곳을 한 글자도 건드리지 않는다.** 토큰
정의부 한 곳만 바뀐다. `--ui-font:var(--fs-sm)`(FR-TOK-20)도 그대로다.

### 2.3 크기 토큰도 함께 커진다

글꼴만 키우면 **버튼 안에서 글자가 넘친다** — `--ui-btn-h:26px` 안에 11px 글자가
있고, 배율 180% 에서 글자는 19.8px 가 되지만 버튼은 26px 에 멈춘다.
`--ui-icon-ratio:.68` 이 아이콘을 버튼 높이에서 파생시키므로(FR-UIK-5 / D-7)
아이콘도 함께 멈춘다.

그래서 **같은 `--fs-scale` 이 크기 토큰에도 걸린다** (사용자 결정 2026-09-19):

| 토큰 | 기준 | 배율 | 근거 |
|------|------|------|------|
| `--ui-btn-h` · `-sm` · `-lg` | 26 · 22 · 30px | 걸림 | 글자를 담는 상자다 |
| `--ui-tab-h` | 30px | 걸림 | 같음 |
| `--ui-icon-sm` · `-md` | 13 · 16px | 걸림 | 글자 옆에 서는 눈금 (FR-GLY-5) |
| `--ui-btn-px` · `--ui-gap` | 10 · 6px | 걸림 | 높이만 키우면 좌우가 옥죈다 |
| `--ui-icon-ratio` | .68 | **안 걸림** | 비율이다. 곱하면 두 번 커진다 |
| `--ui-radius` | 4px | **안 걸림** | 모서리는 크기의 함수가 아니다 |

`.ui-icon-lg{width:20px;height:20px}`(`style-kit.css:52`)는 **토큰이 아니라
직접 px** 다. 이 스펙에서 `--ui-icon-lg` 토큰으로 승격하고 배율을 건다 — 그러지
않으면 큰 아이콘만 멈춘다.

### 2.4 이전 동작 / 새 동작

| | 이전 | 새 |
|---|------|-----|
| UI 글자 | `--fs-*` 다섯의 px 고정 | 배율이 정한다. **기본 100% = 종전과 같은 값** |
| 버튼·탭·아이콘 | px 고정 | 같은 배율로 커진다 |
| Monaco 편집기 | `fontSize:13` 하드코딩 | `13 × 배율`. **이미 열린 편집기도 따라온다** |
| 터미널 | `--fs-lg`(14px) 파생 | `termFontSize`. **기본 14 = 종전과 같은 값** |
| 터미널과 UI 의 관계 | UI 를 키우면 터미널도 커짐 | **서로 독립** |

**두 기본값 모두 종전과 같은 화면을 낸다.** 설정을 더하는 일이 동작을 바꾸는
일이 되어서는 안 된다 (`EDITOR_MINIMAP_TOGGLE_SRS` §2.2 와 같은 규약).

### 2.5 터미널은 **다시 재야** 한다

글꼴 크기가 바뀌면 xterm 의 셀 크기가 바뀌고, 같은 픽셀 상자에 들어가는 `cols`·
`rows` 가 달라진다. 값을 얹는 것만으로는 화면이 어긋난 채 남는다.

순서가 있다: `term.options.fontSize` → `fit.fit()` → `onResize` 가 발화 →
`_sendResize` 가 PTY 에 새 크기를 알린다. 마지막 단계는 `term-pane.js:180` 이
이미 가진 길이고 `resizeCheck` 가 **창 소유자만** 보내게 막는다 (M10_SRS
FR-M10-1) — 이 스펙은 그 길을 새로 만들지 않고 앞의 두 단계만 더한다.

### 2.6 rem 을 쓰지 않는 까닭

배율을 루트 글꼴 크기로 싣고 토큰을 rem 으로 적는 길이 있으나, 이 저장소에서는
얻는 것이 없다.

1. **rem 사용처가 0 이다.** `web/*.css` 전체가 px + 변수다.
2. **루트가 이미 px 로 고정돼 있다.** `style.css:161` `html,body{…font-size:var(--fs-lg)}`.
   rem 의 유일한 실익인 *"브라우저·OS 기본 글꼴 존중"* 을 이 선언이 덮는다.
   살리려면 그 고정을 걷어내야 하고, 그것은 이 스펙보다 큰 개정이다.
3. **순환이 생긴다.** `--fs-lg` 를 rem 으로 적으면 위 선언과 서로를 참조한다.
4. **사상표가 px 기준이다.** `DESIGN_TOKENS_SRS` §3.3 이 다섯 값과 원본 선언 수
   (8·237·93·33·3)를 px 로 기록한다. rem 이면 `0.786rem` 류 소수로 전부 다시 쓴다.

### 2.7 게이트에 걸리지 않는다

`scripts/check-font-size.mjs` 는 **`font-size:` 선언**의 값만 본다 (FR-TOK-32).
`--fs-sm:calc(11px * …)` 는 커스텀 프로퍼티 정의이므로 지금 `--fs-sm:11px` 이
통과하는 것과 똑같이 통과한다. `--ui-font` 가 `var(--fs-sm)` 이어야 한다는
조건(FR-TOK-20)도 그대로 지킨다.

**대신 다른 것이 깨진다: 토큰을 문자열로 읽는 코드.**
`getPropertyValue('--fs-sm')` 은 계산 **전** 값을 돌려주므로 이제 `calc(11px *
var(--fs-scale))` 이 나오고 `parseFloat` 는 `NaN` 이 된다. 착수 시 그런 자리는
저장소 전체에 **둘**이었다:

| 자리 | 처리 |
|------|------|
| `web/js/ui/term-pane.js` — `--fs-lg` 읽기 | FR-FSS-13 이 어차피 없앤다 |
| `e2e/ui-kit-icons.spec.ts` — `V-GAP-1` 의 `--ui-gap` 읽기 | 탐침 요소에 얹어 계산값을 읽도록 고쳤다 |

제품 코드에 남은 자리는 0 이다. 값을 재려면 **실제 속성에 얹어** 브라우저가
계산하게 한다 — `e2e/font-size.spec.ts` 의 `cssPx` 가 그 손이다.

## 5. 리스크

| 리스크 | 등급 | 완화 |
|--------|------|------|
| 높은 배율에서 고정 px 폭과 부딪힌다 — 사이드바(`style.css:822` `width:200px`) · 메뉴(`min-width:200px;max-width:320px`) · 탭(`min-width:40px;max-width:120px`) | **MEDIUM** | 이번 스펙은 폭을 건드리지 않는다. 배율 상한 200 에서 대표 화면 넷(사이드바·설정 모달·탭 줄·컨텍스트 메뉴)을 눈으로 확인하고, 깨지는 자리가 있으면 **그 자리를 후속 항목으로 기록**한다 — 폭까지 이 스펙에 넣으면 범위가 레이아웃 전면으로 번진다 |
