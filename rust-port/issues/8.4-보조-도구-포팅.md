# 8.4 보조 도구 포팅

## 목표

CI 보조 도구 4종을 옮긴다. 대상 소스가 Go 에서 Rust 로 바뀌는 점을 반영해야 하므로, 시작 전에 조정자와 범위를 정한다.

## 대상 Go 코드

- `scripts/check-action-reasons`
- `scripts/check-shared-constants`
- `scripts/gen-decisions`
- `scripts/gen-errors`



## 완료 조건

- 대상 Go 패키지의 관측 동작을 Rust crate 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  - **Go 와 차분 실행**(격리, 저장소 뿌리): 네 도구의 정상 갈래(`… ok`, `-check`, 쓰기 모드)는 stdout·stderr·종료 코드가 같고, 쓰기 모드로 다시 만든 `decisions.md`·`errors.md` 는 바이트가 같다(git 변경 없음). `-bogus` 는 오류 문구가 같고 Usage 줄의 실행 파일 경로만 다르다. Go 는 `go run` 이 `exit status 2` 와 종료 코드 1 로 감싸지만, 컴파일된 Go 바이너리처럼 Rust 는 2 를 낸다.
  - **Go 와 다르게 한 것(조정자에게 한 줄로 보냄)**: 생성물 어긋남·없음 안내가 `go run ./scripts/gen-…` 대신 실제 명령 `cargo run -p dm-scripts-gen-… --` 을 가리키고, gen-errors 의 원천 표기는 `codes_doc.go` 대신 `apierr 의 코드 안내(code_doc)` 다. check-shared-constants 의 사유 문구는 짝 ID·형식이 같고 파일·상수 이름이 Rust 의 것이다(예: `query::OP_*`, `workspace::SCHEMA_VERSION`, `리터럴이나 Duration::from_<단위>(N) 로 둔다`, `… 를 Rust 로 읽지 못했다`). K12 사유는 두 쪽 이름이 같아 `화면 X=a 와 서버 X=b` 로 적는다.
  - **남은 것**: `scripts/*.sh` 래퍼는 여전히 `go run` 을 부른다(조정자 결정 5, 전환 범위). dm-ctl-errdoc `render()` 의 오류 문구(`codes_doc.go 의 CodeDoc 에 …`)는 errdoc crate 의 것이라 고치지 않았다(같은 종류의 안내 문구 차이 후보). JS 쪽 정규식의 `\s`·`\d`·`\w` 는 Rust regex 에서 유니코드 범위다(Go RE2 는 ASCII). 지금 JS 파일에서는 결과가 같다.
