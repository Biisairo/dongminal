# SRS: 탐색기의 무시 표시·폴더 단위 전송·경로 자동채움 — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 넷이다.

> ① Editor 탐색기에서 **gitignore 대상을 흐리게** 보이게 한다 (VS Code 와 같이).
> ② 업로드·다운로드를 **폴더 단위**로도 할 수 있게 한다 — NAS 처럼 쓸 예정이다.
> ③ 한번씩 접속이 안 된다. Tailscale 로 원격 접속 중이며, 어떨 때는 **SSH 로도**
>    들어가지 못한다.
> ④ Git·Editor 의 `+ Add` 버튼을 눌렀을 때 **경로 채우기가 잘 안 된다.**
> ⑤ 터미널에서 복사가 안 된다. `sent 54 chars via DSC 52 …` 가 뜨는데
>    **서버가 열려 있는 곳에서만 되고 원격에서는 안 된다.**

조사 결과 ①은 미구현이고 근거가 될 데이터조차 클라이언트에 없으며(§2.1), ②는
`FILE_TRANSFER_SRS` §6 이 명시적 비목표로 남긴 자리이고(§2.2), ④는 서버가
**틀린 값을 그럴듯하게 답하는** 결함이다(§2.4).

③은 원인이 확정되지 않았다. 본 SRS 는 그것을 다루지 않는다 — 조사 절차와 지금까지
확정한 사실은 [`./CONNECTIVITY_INVESTIGATION.md`](./CONNECTIVITY_INVESTIGATION.md)
에 따로 둔다 (§6 비목표).

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 무시 표시 | 무시된 항목을 흐리게. 근거는 `git check-ignore` 온디맨드 |
| **B** 폴더 다운로드 | 폴더를 zip 으로 스트리밍하는 새 종단과 메뉴 |
| **C** 폴더 업로드 | 폴더 드롭·폴더 선택. 상대경로를 받아 하위 구조를 세운다 |
| **D** 전송 실패의 선택 | 실패한 자리에서 재시도·건너뛰기를 사용자가 고른다 |
| **E** 경로 자동채움 | `+ Add` 가 서버의 cwd 를 사용자 것으로 착각하지 않게 한다 |
| **F** 터미널 복사 | OSC 52 를 받아 클립보드에 쓰고, 막히면 복사할 자리를 준다 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **무시된 항목** | `git check-ignore` 가 그 경로를 무시 대상으로 답한 것 |
| **흐림** | 행의 이름을 `--text-dim` 으로 낮추는 표시. 상태색과 겹치지 않는다 |
| **폴더 전송** | 디렉터리 하나를 통째로 내려받거나 올리는 것. 구조가 보존된다 |
| **상대경로 업로드** | `relPath` 필드를 실은 업로드. 대상 폴더 **아래로** 구조를 세운다 |
| **자동채움** | `+ Add` 다이얼로그가 열릴 때 경로 칸에 미리 넣는 값 |

## 2. 현재 상태 (조사로 확정한 사실)

**추측이 아닌 파일:줄과 실측으로만 적는다.** 실측은 실행 중인 서버(포트 58146)와
실제 `git` 에 직접 물어 얻은 것이다.

### 2.1 무시 여부를 아는 자리가 없다

탐색기가 색을 칠하는 근거는 `/api/git/status` **하나뿐이다**
(`file-tree.js:209` `pollGit`). 그리고 서버의 `StatusOf` 는 `--ignored` 를
**일부러 주지 않는다** — `status_test.go:237` 이 그 이유와 argv 를 함께 고정한다:

```go
want := []string{"status", "--porcelain=v2", "-z", "--branch", "--untracked-files=all"}
```

즉 무시된 파일은 서버가 관측하지도, 클라이언트에 보내지도 않는다. 행을 그리는
`_el`(`file-tree.js:406`)에 무시를 표현할 클래스가 없는 것은 그 결과이지 원인이
아니다.

### 2.2 폴더 전송은 두 층 모두에서 막혀 있다

**다운로드.** `apiFSDownload`(`handlers_fs.go`)는 `serveDownload` 로 넘기고,
그것은 FR-FTR-2 에 따라 **디렉터리를 400 으로 거절한다.** 클라이언트도 같은 선을
긋는다 — 메뉴의 다운로드는 `kind==='file'` 에서만 활성이고 그 밖에는
`EDITOR_DOWNLOAD_FILE_ONLY`("파일만 내려받을 수 있습니다")를 사유로 보인다
(`file-tree.js:775`). `download(p)`(`:689`)도 첫 줄에서 파일이 아니면 돌아선다.

**업로드.** `uploadInto`(`handlers_files.go`)는 multipart 의 `file` **하나**를
받아 `filepath.Base(header.Filename)` 로 이름을 취한다. 이름에서 경로가 지워지므로
**구조를 실을 자리가 없다.** 클라이언트도 `dataTransfer.files` 만 읽고
(`file-tree.js:822`), 그것은 드롭한 폴더의 **내용을 펴서 주지 않는다** — 폴더를
드롭하면 `files` 는 비거나 폴더 자신 하나를 담는다.

`FILE_TRANSFER_SRS` §6 이 이것을 비목표로 남긴 이유도 적혀 있다 — *"서버 표면과
항목 수·크기 상한을 새로 정해야 한다."* 본 SRS 가 그것을 정한다 (§3.2).

### 2.3 실패는 멈추기만 하고 사용자에게 선택지가 없다

`doUpload`(`file-tree.js:702`)는 FR-FTR-19 대로 순차로 올리다 첫 실패에서
`break` 한다. 이미 올라간 것은 남고 사유는 그 자리에 붙지만, **사용자가 할 수 있는
것은 처음부터 다시 하는 것뿐이다.** 파일 몇 개를 고를 때는 견딜 만하나, 폴더를
통째로 올리는 순간 이 규약은 무너진다 — 수백 개 중 하나가 부딪히면 전부를 다시
올려야 한다.

### 2.4 `+ Add` 는 서버의 cwd 를 사용자 것으로 착각한다

**실측** (2026-08-30, 포트 58146):

```
$ curl '/api/git/repo-at?tool=deadbeef'          # 없는 도구
{"cwd":"/Users/dykim/personal/dongminal","isRepo":true,"path":"/Users/dykim/personal/dongminal",…}

$ curl '/api/git/repo-at?tool='                  # 도구를 아예 안 줌
{"cwd":"/Users/dykim/personal/dongminal","isRepo":true,…}
```

`gitToolCwd`(`gitapi/handlers_git.go:169`)가 도구를 못 찾으면 `os.Getwd()` 로
폴백한다. 그것이 **마침 저장소라서** `isRepo:true` 로 나가고, 클라이언트
(`app-git.js:320`)는 `at.isRepo && at.path` 만 보므로 그 값을 그대로 채운다.

```js
const here=(at&&at.isRepo&&at.path)?at.path:'';
```

사용자가 보는 것은 **빈 칸이 아니라 그럴듯한 남의 경로**다. 그래서 "잘 안 된다"로
읽힌다 — 비어 있으면 직접 넣겠지만, 채워져 있으면 맞는 줄 안다.

같은 결함이 Editor 쪽에도 있다. `_edTermCwd`(`app-editor.js:549`)는 `/api/cwd` 를
부르고 `d.cwd` **만** 읽는다:

```js
return (d&&d.cwd)||'';
```

`/api/cwd` 는 FR-FTR-7 이 넣은 `source` 를 이미 싣는다 (실측:
`{"cwd":"…/dongminal","source":"server"}`). **판단 근거가 응답에 있는데 소비자가
읽지 않는다.** `repo-at` 에는 그 필드가 아예 없다.

**폴백을 타는 계기**는 `_focusedTerminal`(`app-search.js:33`)이다. 활성 창의 포커스된
pane 의 활성 탭이 터미널일 때만 값을 주므로, **Git 창이나 Editor 창에서 `+ Add` 를
누르면 언제나 `null` 이다.** `_gitTermToolId`(`app-git.js:226`)의 폴백 둘
(`_lastTermTool` · `_anyTermToolId`)이 그것을 받아내지만, 둘 다 비면 빈 문자열이
서버로 가고 위의 실측이 된다.

### 2.5 터미널의 복사는 받을 사람이 없다

`term-pane.js` 가 가로채는 OSC 는 **777 하나뿐이다** — `_doFlush`(`:414`)의
정규식이 `\x1b\]777;(\w+);([^\x07]*)\x07` 이고, Download 와 Cwd 가 그 길로 온다.
`Terminal` 생성(`:26`)에도 파서 훅이 없다.

**xterm.js 는 OSC 52 를 스스로 처리하지 않는다.** 그래서 Claude Code 가 보낸
클립보드 쓰기는 `term.write` 로 흘러 들어가 조용히 버려진다. 화면에 뜨는
`sent 54 chars via DSC 52 …` 는 **보낸 쪽이 찍은 것**이지 받았다는 증거가 아니다.

"서버가 열려 있는 곳에서만 된다" 도 이것으로 설명된다 — 그쪽에서는 iTerm2·
Terminal.app 을 직접 쓰고, 그 터미널들이 OSC 52 를 처리한다. 브라우저로
들어오면 처리할 사람이 없다.

**핸들러를 붙이는 것만으로는 부족하다.** `navigator.clipboard` 는 secure
context 에서만 존재하는데 원격 접속은 `http://100.x` 다 — 폴더 다운로드가 zip 이
된 것과 같은 뿌리다 (D-4). 게다가 OSC 52 는 셸이 보내는 것이라 **사용자 제스처가
없어** `document.execCommand('copy')` 폴백도 브라우저가 거부할 수 있다. 그래서
마지막 수단이 필요하다 (FR-ETR-40).

### 2.6 `check-ignore` 의 성질 (실측)

설계가 이 셋에 기댄다.

```
$ printf 'node_modules\0src\0app.log\0tracked.log\0' | git check-ignore -z --stdin
node_modules
app.log                       ← 디렉터리도 판정된다
                              ← 추적 중인 tracked.log 는 나오지 않는다
$ printf 'src\0' | git check-ignore -z --stdin ; echo $?
1                             ← "무시된 것 없음" 은 종료코드 1 이다. 오류가 아니다
```

| 사실 | 뜻 |
|---|---|
| 추적 중인 파일은 보고하지 않는다 | `--no-index` 없이 부르면 VS Code 와 같은 판정이 된다 (D-3) |
| 무시 없음 = 종료코드 1 | 1 을 실패로 다루면 정상이 오류가 된다 |
| 디렉터리도 판정한다 | 폴더 행도 같은 요청으로 함께 물을 수 있다 |
| `-z --stdin` 은 한 번에 여럿 | 디렉터리 한 겹을 프로세스 **한 번**으로 판정한다 |

## 3. 요구사항 (Requirements)

### 3.1 묶음 A — 무시된 항목의 흐림

**FR-ETR-1.** `POST /api/fs/ignored` 를 신설한다. 본문은
`{root, dir, names:[…]}` 이고 응답은 `{ignored:[…]}` — 무시된 **이름**만 담는다.
`root` 는 `fsRoot`, `dir` 은 `fsResolveExisting` 으로 검사한다 (FR-EDT-112·113 과
같은 규약).

> GET 이 아닌 이유: 한 겹의 이름 수는 `fsListMax`(10000)까지 갈 수 있어 URL 길이
> 한계에 걸린다. 부수효과가 없는 POST 다.

**FR-ETR-2.** 판정은 `git -C <dir> check-ignore -z --stdin` 하나로 한다. 이름들은
NUL 로 구분해 표준입력에 넣고, 출력도 NUL 로 갈라 읽는다. **디렉터리 한 겹당
프로세스 한 번이다.**

**FR-ETR-3.** 종료코드 **1 은 성공이다** — "무시된 것이 하나도 없다"는 답이며 빈
목록을 준다 (§2.6). 0 은 목록이 있다는 뜻이고, 그 밖은 실패다.

**FR-ETR-4.** `dir` 이 git 저장소 안이 아니면 `404 not_repo` 다. 클라이언트는 그
답을 받으면 **그 창에서 다시 묻지 않는다** — `pollGit` 의 `_gitOff` 와 같은 관례다
(`file-tree.js:228`).

**FR-ETR-5.** 클라이언트는 `load(dir)` 로 한 겹을 읽은 **뒤에** 그 겹의 이름들로
한 번 묻는다. 결과는 디렉터리별로 캐시하고, 그 겹을 다시 읽을 때 갱신한다.

**FR-ETR-6.** **무시된 폴더의 하위는 묻지 않는다.** 부모가 무시되면 자식도 무시된
것으로 친다. `gitignore(5)` 가 *"It is not possible to re-include a file if a
parent directory of that file is excluded"* 라고 못박으므로 이 생략은 판정을
바꾸지 않는다 (D-2). `node_modules` 를 펼쳐도 프로세스가 늘지 않는다.

**FR-ETR-7.** 무시된 행은 `ed-ignored` 클래스를 받아 이름이 `--text-dim` 으로
흐려진다. **git 상태색보다 약하다** — 상태가 있는 행은 상태색을 유지한다. 무시된
파일은 `status` 에 나오지 않으므로(§2.1) 실제로 겹치는 자리는 없지만, 규칙을 적어
두지 않으면 다음 사람이 순서를 뒤집는다.

**FR-ETR-8.** 흐림은 **표시일 뿐이다.** 무시된 항목도 열고·고치고·옮기고·지우고
전송할 수 있다. 어떤 조작도 이 상태를 근거로 막지 않는다.

### 3.2 묶음 B — 폴더 다운로드

**FR-ETR-9.** `GET /api/fs/download-dir?root=<abs>&path=<abs>` 를 신설한다. 대상
디렉터리를 zip 으로 **스트리밍**한다. 가드는 `/api/fs/download` 와 같다
(FR-FTR-12).

**FR-ETR-10.** 파일 이름은 `<디렉터리 이름>.zip` 이고, 헤더는 FR-FTR-1 의 두 벌
규칙(`filename` + `filename*`)을 **같은 함수**로 만든다 (FR-FTR-4 와 같은 근거).

**FR-ETR-11.** 대상이 디렉터리가 아니면 `400` 이다. 파일은 `/api/fs/download` 의
자리이며, 두 종단이 서로의 일을 대신하지 않는다.

**FR-ETR-12.** **먼저 세고 나서 쓴다.** 항목 수가 `zipMaxEntries`(50,000)를,
또는 총 바이트가 `zipMaxBytes`(2 GiB)를 넘으면 헤더를 하나도 쓰기 **전에** `400`
으로 거절한다. 스트리밍이 시작된 뒤에는 되돌릴 수 없다 — FR-FTR-2 가 같은 교훈에서
나왔고, `apiFSDelete` 도 같은 순서를 지킨다 (FR-EDT-118).

**FR-ETR-13.** 압축은 Deflate 다. 원격이 Tailscale 이라 대역폭이 CPU 보다 비싸다
(D-5).

**FR-ETR-14.** 심볼릭 링크는 **건너뛴다.** 따라가면 순환과 루트 밖 유출이 함께
열리고, 링크로 저장하면 푸는 쪽 플랫폼마다 결과가 갈린다 (D-7). 빈 디렉터리는
엔트리로 넣어 구조를 보존한다.

**FR-ETR-15.** 읽을 수 없는 파일 하나가 전체를 무너뜨리지 않는다. 그 파일을
건너뛰고 나머지를 계속 쓴다 — 스트리밍이 시작된 뒤에는 오류를 보낼 자리가 없고,
절반짜리 zip 보다 하나 빠진 zip 이 낫다.

**FR-ETR-16.** 탐색기 메뉴의 **다운로드**는 폴더 행에서도 활성이며, 폴더면
`download-dir` 로 간다. 링크 행에서는 비활성을 유지하고 사유를 보인다 —
링크 자신을 내려받는다는 뜻이 정해져 있지 않다.

### 3.3 묶음 C — 폴더 업로드

**FR-ETR-17.** `POST /api/fs/upload` 는 multipart 필드 `relPath` 를 **선택적으로**
받는다. 있으면 파일은 `dir/relPath` 에 저장되고, 없으면 지금과 같이
`dir/<파일이름>` 이다. 기존 호출자의 동작은 바뀌지 않는다.

**FR-ETR-18.** `relPath` 는 상대경로여야 하고, 조각에 `..` 이 있으면 거절한다
(`400 bad_request`). 합친 경로는 `fsUnderRoot` 로 한 번 더 검사한다 — FR-FTR-15 가
이름 하나에 대해 하는 것과 같다.

**FR-ETR-19.** `relPath` 의 **중간 디렉터리는 만든다** (`os.MkdirAll`). 대상 `dir`
자신은 여전히 실재해야 한다 — FR-FTR-6 은 그대로다. 확장은 "대상 **아래로**
구조를 세운다" 까지이며, 대상 자체를 만드는 것이 아니다 (D-8).

**FR-ETR-20.** 마지막 조각(파일)이 이미 있으면 `409 exists` 다. FR-FTR-16 이 그대로
적용된다 — 덮어쓰지 않고 이름을 바꾸지도 않는다. 중간 디렉터리가 이미 있는 것은
충돌이 아니다.

**FR-ETR-21.** 탐색기는 **폴더 드롭**을 받는다. `dataTransfer.items` 의
`webkitGetAsEntry()` 를 재귀로 걸어 `{file, relPath}` 목록을 만든다.
`dataTransfer.files` 만으로는 폴더의 내용을 얻을 수 없다 (§2.2).

**FR-ETR-22.** 재귀 수집에 상한을 둔다 — 항목 `uploadMaxEntries`(10,000). 넘으면
수집을 멈추고 사유를 그 자리에 보인다. 사용자가 홈 폴더를 잘못 놓았을 때 브라우저가
멎지 않아야 한다.

**FR-ETR-23.** 메뉴에 **폴더 업로드**를 더한다. `<input webkitdirectory>` 로 받으며,
`webkitRelativePath` 가 곧 `relPath` 다. 기존 **업로드**(파일 여럿)는 그대로 둔다 —
한 input 이 두 모드를 겸할 수 없다.

**FR-ETR-24.** 빈 디렉터리는 올라가지 않는다. 브라우저의 파일 목록에 나타나지 않기
때문이다. 이것은 제약이며 §6 에 기록한다.

**FR-ETR-25.** 전송이 끝나면 대상 폴더를 펼치고 그 겹만 다시 읽는다
(FR-FTR-19·20b, FR-EDT-88).

### 3.4 묶음 D — 실패했을 때의 선택

**FR-ETR-26.** 업로드 중 한 항목이 실패하면 **거기서 멈추고 사용자에게 묻는다.**
선택지는 넷이다 — **재시도 · 건너뛰기 · 이후 모두 건너뛰기 · 중단.**

> "이후 모두 건너뛰기" 가 있는 이유: 폴더 하나가 수백 개일 수 있고, 같은 사유로
> 실패하는 항목이 이어질 때 묻기를 되풀이하면 그 자체가 고장이다.

**FR-ETR-27.** 묻는 것은 `GitDialog` 의 `choices` 다 (FR-GIT-172·177). 브라우저의
`confirm` 을 쓰지 않는다 — 어느 파일이 왜 실패했는지 보일 자리가 없다.

**FR-ETR-28.** 다이얼로그는 **실패한 항목의 상대경로와 사유**를 본문에 싣는다.
사유는 `EDITOR_FS_ERR_MSG` 의 코드 문구를 그대로 쓴다.

**FR-ETR-29.** 다이얼로그를 열지 못하면(`GitDialog._cur` 가 이미 있으면) **중단**
으로 친다 — `GitDialog._safe` 가 그렇듯 안전한 쪽이다 (FR-GIT-97).

**FR-ETR-30.** 끝난 뒤 실패·건너뜀이 하나라도 있으면 그 수를 대상 폴더에 사유로
붙인다 (FR-EDT-92). 조용히 끝나면 사용자는 전부 올라간 줄 안다.

### 3.5 묶음 E — 경로 자동채움

**FR-ETR-31.** `/api/git/repo-at` 응답에 `source` 를 싣는다 — `"tool"` 또는
`"server"`. `/api/cwd` 와 **같은 규약**이다 (FR-FTR-7). 폴백 자체는 유지한다
(D-4 를 뒤집지 않는다).

**FR-ETR-32.** `+ Add`(Git)는 `source==="tool"` 일 때만 경로를 채운다. `"server"`
면 **빈 칸으로 열고** 사유를 본문에 보인다 — 지금 터미널의 경로를 얻지 못했다는
사실이 그 자리에서 보여야 한다.

**FR-ETR-33.** `+ Add`(Editor)도 같다. `_edTermCwd` 는 `source` 를 읽어
`"tool"` 이 아니면 빈 문자열을 준다.

**FR-ETR-34.** 두 다이얼로그의 본문 문구는 세 경우를 가른다 — ⑴ 채웠다(그 경로를
보인다) ⑵ 지금 터미널이 없다 ⑶ 터미널은 있으나 저장소가 아니다(Git 만). ⑵ 와 ⑶ 은
사용자가 할 일이 다르다.

**FR-ETR-35.** `_gitTermToolId` 의 폴백 사슬은 그대로 둔다 (`app-git.js:226`).
그것은 "포커스가 터미널에 없을 때 마지막으로 쓰던 터미널을 쓴다" 는 별개의 규칙이며,
본 묶음이 고치는 것은 **그 사슬이 전부 빈 뒤** 서버가 답하는 값이다.

**FR-ETR-36.** 도구 id 가 빈 문자열이면 클라이언트는 **요청 자체를 보내지 않는다.**
보내도 서버의 cwd 가 돌아올 뿐이고, 그 왕복은 값을 만들지 않는다.

### 3.6 묶음 F — 터미널의 복사

**FR-ETR-37.** 터미널은 **OSC 52 를 받는다.** `term.parser.registerOscHandler(52,…)`
로 붙이며, 받은 것은 `<targets>;<base64>` 다. 클립보드 대상(`c`·`p`·`s`)은 가르지
않는다 — 브라우저에는 클립보드가 하나뿐이다.

**FR-ETR-38.** base64 는 **바이트로 풀고 UTF-8 로 읽는다.** `atob` 의 결과를
그대로 쓰면 한글이 깨진다 — 그것은 바이트열이지 문자열이 아니다.

**FR-ETR-39.** `<base64>` 가 `?` 이면 **읽기 요청**이다. 응답하지 않는다 — 원격의
셸에 사용자의 클립보드를 넘기는 통로를 열지 않는다.

**FR-ETR-40.** 쓰기는 세 단으로 내려간다.

1. `navigator.clipboard.writeText` — secure context 에서만 존재한다
2. 실패하면 `document.execCommand('copy')` — 사용자 제스처가 없어 거부될 수 있다
3. 그것도 실패하면 **복사창을 띄운다** — 받은 내용을 담고, 사용자가 한 번 누르면
   복사된다. 그 클릭이 제스처이므로 2단이 그 자리에서는 통한다

**FR-ETR-41.** 복사창은 내용을 **미리 선택한 채로** 연다. 누르지 않고 `Cmd/Ctrl+C`
로 끝낼 수 있어야 한다. `Esc` 로 닫는다.

**FR-ETR-42.** OSC 52 는 화면에 아무것도 남기지 않는다. 핸들러가 `true` 를 돌려
xterm 이 그것을 처리된 것으로 보게 한다 — `false` 면 잔재가 찍힌다.

**FR-ETR-43.** 상한을 둔다 — `OSC52_MAX_BYTES`(1MiB). 넘으면 무시한다. 셸이 보낸
것을 그대로 메모리에 올리는 자리이며, 상한이 **있다**는 것이 값보다 중요하다.

## 4. 설계 결정 (Design Decisions)

| # | 결정 | 근거 |
|---|---|---|
| **D-1** | 무시 판정은 `check-ignore` 온디맨드 | `status --ignored` 는 큰 저장소에서 3초 폴링을 무겁게 하고 그 argv 를 고정한 테스트를 깨뜨린다. 온디맨드는 **보고 있는 겹**만 판정하므로 비용이 화면에 비례한다 (사용자 결정) |
| **D-2** | 무시된 폴더의 하위는 묻지 않는다 | `gitignore(5)`: 제외된 부모 아래의 파일은 다시 포함될 수 없다. 생략이 판정을 바꾸지 않는다 (FR-ETR-6) |
| **D-3** | `--no-index` 를 주지 않는다 | 기본 판정은 추적 중인 파일을 무시로 보지 않으며, 그것이 VS Code 의 표시와 같다 (§2.6). 요구가 "VS Code 와 동일" 이다 |
| **D-4** | 폴더 다운로드는 zip 이다 | 폴더를 구조 그대로 로컬에 쓰는 것은 File System Access API 로만 가능하고, 그것은 secure context(HTTPS/localhost)를 요구한다. 서버는 평문 HTTP 로 뜨고 접속은 Tailscale IP 이므로 조건이 성립하지 않는다. HTTPS 도입은 사용자가 보류했다 |
| **D-5** | Deflate 로 압축한다 | 원격이 Tailscale 이라 대역폭이 CPU 보다 비싸다. 소스 트리에서 3~5배가 흔하다 |
| **D-6** | 세기와 쓰기를 나눈다 | 헤더가 나간 뒤에는 오류를 보낼 자리가 없다. FR-FTR-2 가 같은 사고에서 나왔다 |
| **D-7** | zip 에 링크를 넣지 않는다 | 따라가면 순환·루트 밖 유출, 링크로 저장하면 푸는 쪽마다 결과가 갈린다 |
| **D-8** | `relPath` 는 확장이지 대체가 아니다 | 대상 `dir` 은 여전히 실재해야 한다(FR-FTR-6). "폴더를 만들지 않는다" 의 뜻은 **대상**을 만들지 않는다이지, 올리는 구조를 세우지 않는다가 아니다 |
| **D-9** | 실패는 묻는다 | 폴더 업로드에서 "첫 실패에 멈춤" 은 처음부터 다시 하라는 말이 된다 (§2.3). 파일 몇 개일 때와 수백 개일 때의 규약이 같을 수 없다 |
| **D-10** | `repo-at` 에 `source` 를 **더한다** | 폴백을 없애면 `/api/cwd` 의 소비자 넷이 함께 깨진다 (FILE_TRANSFER_SRS D-4). 판단을 호출자에게 넘기는 것이 이미 선 규약이다 |
| **D-11** | 요구 ③ 은 본 SRS 밖이다 | 원인이 확정되지 않았고 사용자가 "지금은 조사만" 을 택했다. 추측으로 코드를 고치지 않는다 |
| **D-12** | 복사는 세 단으로 내려간다 | 1단은 secure context 가 아니면 아예 없고, 2단은 사용자 제스처가 없어 거부될 수 있다. 둘 다 **환경이 정하는 것**이라 코드로 보장할 수 없다 — 마지막 단은 사용자의 클릭을 빌려 그 보장을 만든다 (§2.5) |
| **D-13** | OSC 52 **읽기**는 응답하지 않는다 | 원격의 셸에 사용자 클립보드를 넘기는 통로다. 쓰기와 달리 요구된 적이 없고, 열면 되돌리기 어렵다 |

## 6. 비목표 (Non-goals)

- **요구 ③ (간헐적 접속 불가).** 원인이 확정되지 않았다. 조사 절차와 지금까지의
  사실은 `CONNECTIVITY_INVESTIGATION.md` 에 둔다. 사용자가 "지금은 조사만" 을
  택했으므로 본 SRS 는 코드를 고치지 않는다.
- **HTTPS 도입과 File System Access API.** 폴더를 구조 그대로 로컬에 쓰는 길이지만
  사용자가 zip 을 택했다 (D-4). 나중에 열 수 있게 종단을 나눠 둔다.
- **빈 디렉터리의 업로드.** 브라우저가 목록에 주지 않는다 (FR-ETR-24).
- **전송 진행률·취소 UI.** 순차 업로드의 줄 기록과 실패 다이얼로그로 갈음한다
  (FILE_TRANSFER_SRS §6 과 같다).
- **덮어쓰기 선택지.** 탐색기의 모든 조작이 거부로 통일돼 있다 (FR-EDT-86,
  FR-FTR-16). 실패 다이얼로그의 "재시도" 도 덮어쓰지 않는다.
- **무시 표시의 실시간 갱신.** `.gitignore` 를 고치면 그 겹을 다시 읽을 때
  반영된다. 파일 감시는 탐색기 전체가 하지 않는다 (FR-EDT-67).
- **zip 이 아닌 형식.** tar.gz 는 Windows 기본 탐색기가 열지 못한다.
- **`/api/upload`·`/api/download` 의 인증.** FILE_TRANSFER_SRS §6·§7 이 남긴
  위험이며 본 SRS 가 바꾸지 않는다.

## 7. 위험 (Risks)

| 위험 | 등급 | 대응 |
|---|---|---|
| 폴더 zip 이 서버 CPU·디스크 I/O 를 오래 점유한다 | MEDIUM | 항목·크기 상한을 먼저 검사하고(FR-ETR-12) 스트리밍이라 메모리는 상수다. `--expose` 환경에서는 §6 의 인증 부재 위험과 겹친다 |
| `check-ignore` 프로세스가 겹마다 뜬다 | LOW | 겹당 한 번이고 무시된 폴더 아래로는 아예 뜨지 않는다 (FR-ETR-6) |
| 폴더 업로드가 수천 건의 요청을 만든다 | MEDIUM | 순차이므로 동시성은 1 이고, 수집에 상한이 있다 (FR-ETR-22). 파일당 한 요청인 것은 multipart 스트리밍의 성질이며 §6 의 진행률 UI 보류와 함께 남는다 |
| `--expose` 로 띄운 서버에서 폴더 다운로드가 트리 전체를 유출한다 | **HIGH** | 이미 있던 성질이다(파일 단위로도 가능했다). 루트 가드는 그대로 적용된다. 인증은 별건 (§6) |
| 무시 표시가 사용자를 "이건 못 만진다" 로 오독하게 한다 | LOW | 흐림은 표시일 뿐이고 어떤 조작도 막지 않는다 (FR-ETR-8) |
