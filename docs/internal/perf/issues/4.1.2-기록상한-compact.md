## 진행 기록

2026-11-25 (4.1.2 담당) — 구현을 마쳤다. 상태는 review. 커밋 `dcdcaec3`(pf/4.1.2).

- 바꾼 것(termstate 만): `keep: Option<usize>` 덮어쓰기와 `keep()` = `termlimit::emu_keep(rows)`. 상한은 `termlimit::emu_cap` 으로 정하고, 크기를 바꾸면(`reload_options`) 다시 계산한다. 공개 API `Screen::compact()` 를 더했다. 대체 화면에서는 아무것도 하지 않는다. 기록 전체에 `complete_lines(cut=false)` → `store.push` → `drop_oldest` → `grid_mut().truncate()` 를 하고, 걸친 꼬리는 남긴다. 4.1.3 의 compactor 는 이 API 를 cmu 잠금 안에서 그대로 부르면 된다. `settle_history` 와 compact 는 옮기는 코드(`move_oldest`)를 함께 쓴다. `resize` 는 상한 올리기 → `term.resize` → compact → `reload_options` 순서로 돈다.
- 지운 것: termstate `EMU_KEEP`(pub, 쓰는 곳은 termstate 시험뿐), 내부 `emu_cap`.
- **설계와 다르게 한 것(§4)**: 크기를 바꾸기 "앞"에서 compact 하지 않는다. 앞에서 비우면 행을 늘리거나 폭을 넓힐 때 alacritty 가 기록을 화면으로 끌어 내리지 못한다(`grow_lines`·`grow_columns`). 그러면 화면과 커서가 xterm 과 달라진다(실측: `resize-wrap-grow` 786칸 어긋남). 대신 바꾸기 앞에서 상한을 `(기록+화면)×(옛 폭/새 폭 올림 + REFLOW_CARRY_ROWS)` 까지 올린다. 그러면 좁힐 때 `shrink_columns` 가 `max_scroll_limit` 에서 자르지 않는다(좁히기 손실 방지라는 같은 목적). 바꾼 뒤 compact 는 설계대로 한다. 대체 화면에서는 상한을 올리지 않는다(올리면 대체 화면 격자에 기록이 생긴다 — 시험 `resize_in_alt_screen_leaves_alt_without_history` 로 RED 를 확인했다).
- 동작 변경: ① 이전에는 화면 위 기록이 1,000행이고 그리드가 화면 + 2,000행이었다. 이제는 rows 로 keep 을 정하고(80×24 464 / 120×40 448 / 200×50 438) 그리드는 화면 + 1,000행이다. 이유: D-49·D-52. ② 이전에는 좁히면 상한을 넘는 오래된 기록을 버렸다. 이제는 저장소로 옮겨 보존한다. ③ 이전에는 크기를 바꾼 뒤 저장 공간이 "화면 + 그때 기록 + 1,000행"이었다. 이제는 바꾼 직후 화면(+꼬리)만 남고, 다음 출력에서 한 단위를 잡는다. ④ 크기를 바꾸면 에뮬레이터 기록이 0 이 되고 기록 전체를 저장소에서 꺼낸다(D-28 폭 다시 감싸기).
- 시험(RED 먼저 확인): 처음에는 API 만 `Option` 으로 바꾸고 compact 는 빈 함수로 두었다. 그 상태에서 lib 7건(`history_keeps_emu_keep_rows`·`keep_follows_resize`·`narrowing_keeps_all_history`·compact 3건·`restore_accepts_handover_from_old_keep`)과 통합 시험 3건(120×40 짧은 줄 그리드 5,798,656 B > 상한 3,174,144 B 등)이 실패했다. 새 `src/compact_tests.rs` 14건은 다음을 본다: A, 좁히기 보존, compact 순서·꼬리·대체 화면, 앞뒤 스냅숏·text·화면 행 동일(sim-line·sim-tui·색·링크·넓은 글자·wrap), 모든 분할점에 compact 끼우기(`check_points_with`), sim 표본 분할점, 재출력, keep 1,000 인계 수용, compact 뒤 인계 왕복, 대체 화면 크기 바꾸기. 새 `tests/emu_storage.rs` 4건은 스레드별 계수 `#[global_allocator]` 로 잰다. 첫 기록 할당에서 같은 크기의 행 할당은 정확히 `ALAC_STORAGE_UNIT` 번이다(alacritty `MAX_CACHE_SIZE` 를 고정한다). 120×40·80×24·200×50 × 짧은 줄·코드 120자 색으로 2만 줄을 넣은 뒤와, 크기 바꾸기 세 쌍 뒤에 다시 2만 줄을 넣은 뒤의 그리드 상한을 본다. compact 뒤에는 꼬리만 남는다.
- 기존 시험 변경: xterm 비교 `compare` 의 기록 비교는 이제 스냅숏을 새 에뮬레이터에 넣은 행으로 본다. 크기를 바꾸면 기록이 저장소로 가서 에뮬레이터 행만으로는 볼 수 없기 때문이다. 기대값(ref)은 그대로다. `check_points_from`·`check_handover` 는 변형(`check_points_with`·`check_handover_with`)을 부르게 했다.
- 결과(hermetic): termstate lib 88 통과(2 ignored), 통합 4 통과, toolhub lib 112, termlimit 7. fmt·clippy(termstate, all-targets, -D warnings)는 경고 없음. scripts/test 95 통과·0 실패. check-*.mjs·check-*.sh 는 모두 통과했다. e2e(포트 62150, 1 worker, 최종 빌드로 다시 돌림): W2·W4·H1·S1·R1·Q1 6건 통과. W4 p95 42.2 ms(p50 32.2). 빌드 `otterminal-pf4.1.2` 는 성공했다.
- 측정: 그리드 증가분(만든 뒤, 저장소 제외)은 120×40 에서 5.80 MB → 2.89 MB, 80×24 1.93 MB, 200×50 4.81 MB 다. compact 뒤에는 약 5 KB 만 남는다. `measure_snapshot_5000_rows`(release): 앞은 sim-line x8 6,380 µs, sim-tui x8 3,018 µs(1회)이고, 뒤는 sim-line 4,757~4,943 µs, sim-tui 1,468~1,520 µs(3회)다. 크기는 같다(442,611 B·100,075 B).
- **발견(범위 밖, 4.1.3 측정에 영향)**: `Screen::new` 하나가 크기와 관계없이 살아 있는 힙 약 2.1 MB 를 잡는다. vte 0.15 `Processor` 의 동기 갱신 버퍼 `Vec::with_capacity(SYNC_BUFFER_SIZE = 2 MiB)`(`vte-0.15.0/src/ansi.rs:39,263`) 때문이다. 건드리지 않은 페이지라 RSS·footprint 에는 거의 드러나지 않을 것이다. 다만 live heap 판정(설계 §5)에서는 도구당 2 MiB 로 잡힌다. 판정 방법은 4.1.3 에서 정해야 한다.
- 남은 위험: (MED) 크기를 바꾼 직후에는 에뮬레이터 기록이 0 이므로, 기록 행이 필요한 경로(스냅숏·위로 받기)가 모두 저장소에서 다시 감싼 행을 쓴다. e2e·xterm 비교는 통과했다. (LOW) 대체 화면 안에서 좁히면 가려진 주 화면 기록은 예전처럼 상한에서 잘릴 수 있다(대체 화면은 compact 무동작, 이전과 같은 동작). (LOW) 상한을 올린 채 좁히면 재흐름 동안 잠깐 행이 크게 늘 수 있다(바로 compact·truncate 된다).
