# SRS: 설정 컨트롤의 공통 언어 (IEEE 29148 준수)

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)
설정 패널의 입력 수단을 **한 벌의 시각 언어**로 모은다. 새로 들어오는 값(가장자리 표시 세기)이
기존 항목과 따로 놀지 않게 하고, 이미 어긋나 있던 항목(슬롯 방향)을 그 언어로 되돌린다.

### 1.2 범위 (Scope)
- 포함: `web/style.css`(`.ds-switch`·`.ds-range`), `web/index.html`(슬롯 방향·표시 세기 행),
  `web/js/core/app-slots.js`(슬롯 방향 배선), `e2e/window-slots.spec.ts`(TC-WSL-27 갱신).
- 비포함: 설정 항목의 추가·삭제, 값의 의미 변경, 다른 패널(Shortcuts·Notify·Sandbox)의 재배치,
  `.ds-num`·`.ds-text`·`.sbs-select`·체크박스의 생김새.

### 1.3 정의 (Definitions)
- **스위치(`.ds-switch`)**: 값이 둘인 설정을 뒤집어 고르는 컨트롤. 흔히 보는 그 토글이다 —
  둥근 트랙 안에서 손잡이가 좌우로 옮겨 앉고, **두 값의 이름은 트랙 바깥 양쪽**에 적힌다.
- **레인지(`.ds-range`)**: 정수 눈금 위에서 정도를 고르는 컨트롤. 값이 숫자로 함께 보인다.
- **공통 언어**: 바탕 `--bg`, 테두리 1px `--border`, 반경 4px, 글자 12px, 손이 닿으면 `--accent`.
  기존 `.ds-toggle`·`.ds-num` 이 이미 쓰고 있는 규약이다.

## 2. 현황 (Current State)
1. 설정 패널의 컨트롤은 `.ds-toggle`(버튼) · `.ds-num`/`.ds-text`(입력) · `.sbs-select`(선택) ·
   맨몸 체크박스로 나뉜다. 앞의 셋은 위의 공통 언어를 지키지만 **체크박스는 브라우저 기본**이다.
2. 슬롯 방향(FR-WSL-81)은 `.ds-toggle` 하나로, **지금 값만 적어 두고 누르면 뒤집히는** 형태다.
   두 값 중 무엇이 있는지는 눌러 봐야 알고, 값이 바뀌면 버튼의 글자도 바뀐다.
3. 정도를 고르는 컨트롤은 아직 없다 — 세기 같은 값을 넣을 자리가 없다.

### 2.1 사용자 결정 (2026-09-06)
- **D-1** 가장자리 표시는 on/off 가 아니라 **0~10 레인지**로 고른다. 기본 5, **0 이면 꺼진다**.
- **D-2** 레인지는 다른 버튼·토글과 **통일된** 생김새여야 하고, 테마 색을 쓴다.
- **D-3** 슬롯 방향 토글도 같은 언어로 맞춘다.
- **D-3a**(정정) 그 토글은 **일반적인 토글 스위치**다. 값의 이름은 스위치 밖 양쪽에 **영어 글자만**
  적는다 — 그림 문자(`▐▌`·`▀▄`)는 두지 않는다.

### 2.2 설계 결정
- **D-4** 슬롯 방향은 **스위치**가 된다. 두 값의 이름이 트랙 양쪽에 늘 보이므로 "무엇을 고를 수
  있는가" 가 드러나고, 손잡이의 자리가 "지금 무엇인가" 를 말한다 — 값이 적힌 버튼 하나는 후자만 말했다.
- **D-4a** 값의 이름은 **마크업에 그대로** 둔다. JS 가 글자를 채우면 그 문자열이 코드로 들어가는데,
  이 둘은 바뀌지 않는 이름이고 화면의 자리도 고정이다.
- **D-5** 레인지의 채워진 부분은 `background` 그라데이션으로 그린다. `accent-color` 는 브라우저마다
  트랙·엄지의 크기와 여백이 달라 같은 행의 다른 컨트롤과 높이가 어긋난다.
- **D-6** 채움 비율은 JS 가 `--fill` 로 넘긴다. CSS 만으로는 `input[type=range]` 의 현재 값을 읽을 수 없다.
- **D-7** 0 은 숫자가 아니라 **`끔`** 으로 적는다. 레인지의 왼쪽 끝이 "가장 약함" 이 아니라 "없음" 이라는
  사실은 눈금이 말해 주지 않는다.

## 3. 요구사항 (Requirements)

### 3.1 기능 요구사항 (Functional)
| ID | 요구사항 | 우선 |
|----|---------|------|
| FR-SCT-1 | `.ds-switch` 는 트랙 하나와 그 안의 손잡이로 이뤄진다. 손잡이는 고른 값 쪽에 앉고, 켜진 쪽 트랙은 `--accent-active` 바탕이 된다. | 필수 |
| FR-SCT-2 | 두 값의 이름은 트랙 **바깥 양쪽**에 놓인다. 고른 쪽 이름은 `--text-bright`, 나머지는 `--text-dim` 이다. | 필수 |
| FR-SCT-3 | `.ds-switch` 컨테이너의 `data-v` 는 **지금 값**이다 — 화면 밖(테스트·다른 코드)에서 값을 읽는 자리가 하나로 남는다. | 필수 |
| FR-SCT-4 | 슬롯 방향은 `.ds-switch` 로 바뀐다. 이름은 `Horizontal`·`Vertical` 이며 마크업에 그대로 적힌다 (D-3a·D-4a). | 필수 |
| FR-SCT-5 | 스위치는 `role="switch"` 와 `aria-checked` 를 가진다. 누르면 두 값이 뒤집힌다. | 필수 |
| FR-SCT-6 | `.ds-range` 는 `input[type=range]` 와 값 표시를 한 줄에 둔다. 값 표시는 폭이 고정되어 값이 바뀌어도 행이 흔들리지 않는다. | 필수 |
| FR-SCT-7 | 레인지의 트랙은 `--border`, 지나온 부분은 `--accent` 다. 엄지는 `--accent` 이며 반경 3px 로 다른 컨트롤과 같은 각을 가진다. | 필수 |
| FR-SCT-8 | 채움 비율은 JS 가 `--fill`(백분율)로 세운다. 값이 바뀔 때마다 함께 갱신된다 (D-6). | 필수 |
| FR-SCT-9 | 레인지는 키보드로 조작할 수 있다(네이티브 `input[type=range]` 를 그대로 쓴다). 포커스 표시가 보인다. | 필수 |

### 3.2 비기능 요구사항 (Non-functional)
- NFR-1 `.ds-toggle`·`.ds-num`·`.ds-text`·`.sbs-select` 의 값은 바뀌지 않는다 — 이 작업은 **새 컨트롤 둘**과
  그중 하나를 쓰게 된 기존 항목 하나에만 닿는다.
- NFR-2 슬롯 방향의 **동작**은 그대로다: 고른 값이 곧 `slotDir` 이고, 저장·복원 경로는 손대지 않는다.
- NFR-3 두 컨트롤 모두 밝은 테마와 어두운 테마에서 같은 뜻으로 읽힌다(색을 팔레트에서만 쓴다).

### 3.3 이전 동작 / 새 동작 / 이유
| 항목 | 이전 | 새 | 이유 |
|------|------|-----|------|
| 슬롯 방향 | 지금 값이 적힌 버튼(`▐▌ 가로`), 누르면 뒤집힘 | 토글 스위치 + 바깥 양쪽에 `Horizontal`·`Vertical` | 고를 수 있는 것과 지금 값을 함께 보여준다 (D-4) |
| 정도 설정 | 없음 | `.ds-range` | 0~10 같은 값을 넣을 자리가 생긴다 |

## 5. 리스크
- LOW: 생김새와 그 배선에 한정된다. 값의 의미·저장 경로는 그대로다.
- 잔여: `input[type=range]` 의 엄지 스타일은 브라우저마다 접두사가 다르다 — WebKit·Firefox 둘 다 적는다.
