# SRS: e2e 는 공개 계약만 본다 — IEEE 29148

> **문서 상태**: 초안

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

`05-test.md TEST-6` 가 제기한 것은 이것이다.

> **e2e 가 프론트의 private 상태에 결합돼 있다.**

실측(2026-09-12): **`app._xxx` 507회 · 86파일 · 서로 다른 이름 114개.**
(로드맵이 적은 533/81 을 정정한다 — M5 가 로드맵 수치 여덟을 정정한 것과 같은
부류다.)

대가는 두 가지다.

1. **리팩터가 결함이 아니라 이름 변경으로 깨진다.** `edWindows` 를 고치려면
   33곳의 e2e 를 함께 열어야 하고, 그러면 리팩터의 diff 에서 "무엇이 바뀌었나"
   가 보이지 않는다. `DRIFT_RECLAIM_SRS §7.6` 이 세 파일을 *"손대지 않았다"* 고
   적은 이유의 일부가 이것이다.
2. **e2e 가 무엇을 계약으로 여기는지 아무도 모른다.** 114개 이름 중 어느 것이
   "이 화면의 약속" 이고 어느 것이 "마침 거기 있던 필드" 인지 구분이 없다.

본 SRS 는 그 결합을 **86파일에서 한 파일로** 옮긴다.

### 1.2 범위 (Scope)

| 묶음 | 내용 |
|---|---|
| **A** 계약 | `window.app.testing` — e2e 가 보는 **유일한** 표면. 한 파일이 정의한다 |
| **B** 이관 | e2e 507곳을 그 표면으로 옮긴다. **단정은 한 줄도 바뀌지 않는다** |
| **C** 게이트 | 스펙의 `app._xxx` 직접 접근을 grep 으로 막는다 |
| **D** 예외 | 계약으로 덮을 수 없는 것의 목록과 그 근거 |

**미포함**: e2e 의 재조직(`TEST-7`)·대기 제거(`TEST-16`)는 별도다. 본 SRS 는
**무엇을 보는가**만 바꾸고 **무엇을 단언하는가**는 바꾸지 않는다.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **계약** | `app.testing` 의 속성·함수. 이름이 바뀌면 그것은 **깨진 계약**이며 이 SRS 를 고쳐야 한다 |
| **내부** | `app._xxx`. 언제든 이름이 바뀔 수 있고, 바뀌어도 e2e 는 깨지지 않아야 한다 |
| **이관** | 호출부를 `app._x` 에서 `app.testing.x` 로 옮기는 일. 값도 타이밍도 같다 |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 가장 많이 쓰이는 열

| 이름 | 횟수 | 무엇 |
|---|---|---|
| `focusedTerminal` | 39 | 포커스 칸의 터미널 인스턴스 |
| `edOpenFile` | 38 | 편집기에서 파일 열기 |
| `edWindows` | 33 | Editor(Repo) 창 목록 |
| `_execRemote` | 21 | 원격 명령 실행 경로 |
| `_edActiveEditor` | 16 | 활성 편집기 |
| `sbTab` | 14 | 사이드바 활성 탭 |
| `gitPin` · `aw` | 12 | 핀 · 활성 창 |

### 2.2 이름의 성질이 셋으로 갈린다

- **동작** (`edOpenFile`·`gitPin`·`_mkWindow`) — 부르면 무언가 일어난다
- **조회** (`edWindows`·`aw`·`plainWindows`) — 지금 상태를 답한다
- **내부 저장소** (`editors`·`_attn`·`gitPanels`·`_gitWdAt`) — 자료구조 그 자체

셋째가 가장 위험하다. 그 자료구조의 **모양**까지 e2e 가 알고 있으므로, 모양을
바꾸는 리팩터는 e2e 를 반드시 깬다.

## 3. 요구사항 (Requirements)

### 3.1 묶음 A — 계약

**FR-ATC-1** `window.app.testing` 이 **유일한 표면**이다. e2e 는 그 밖의
`app.*` 내부에 닿지 않는다.

**FR-ATC-2** 계약은 **한 파일**이 정의한다 (`web/js/core/app-testing.js`).
내부 이름이 바뀌면 고칠 자리는 그 파일 하나다.

**FR-ATC-3** 계약의 이름은 **평평하다** — `app.testing.edOpenFile` 이다.
묶음은 **그 파일의 절**로 표현된다 (창·칸·탭 / 편집기·탐색기 / git / 도구·터미널 /
사이드바·상태바 / 주의·활동 / 전파·저장 / 그 밖). 그 절 목록이 곧 "이 화면이
무엇을 약속하는가" 의 목차다.

**중첩하지 않는 이유는 D-ATC-4 다** — 이름을 자르면 이관이 기계적이지 않게 되고,
507곳의 diff 를 사람이 검토할 수 없다. 그리고 `_attn`·`editors` 처럼 접두를
자를 수 없는 이름이 실재한다.

**FR-ATC-4** 계약의 이름은 **내부 이름에서 `_` 하나를 뗀 것**이다
(`edOpenFile` → `testing.edOpenFile`). 규칙에 예외가 없다.

**FR-ATC-5** 접근자는 **읽을 때 계산한다**(getter). 값을 미리 복사하면 그
스냅샷이 낡는다 — e2e 는 시점을 스스로 고른다. 함수는 **읽을 때 바인딩한다** —
미리 바인딩하면 나중에 갈아 끼운 구현이 계약에 닿지 않는다.

**FR-ATC-5a** 계약은 **쓸 수도 있다**(setter). e2e 12개 이름 24곳이 내부를
갈아 끼워 상태를 인공으로 세운다(`_gitWdAt`·`windowFocused`·`_echoResult` …).
읽기만 열면 그 검사들이 계약 밖에 남고, 남은 것이 곧 게이트의 구멍이 된다.

**FR-ATC-6** 계약은 **제품 동작을 바꾸지 않는다.** 새 상태를 만들지 않고, 기존
함수를 감싸기만 한다.

**FR-ATC-7** 계약은 **언제나 존재한다** — 빌드 갈래를 두지 않는다. 프로덕션에서
빼면 그 빌드는 e2e 가 검증한 것과 다른 프로그램이고, 그 순간 e2e 의 뜻이 준다.

### 3.2 묶음 B — 이관

**FR-ATC-8** 이관은 **호출부만** 바꾼다. 단정·대기·선택자·순서는 한 글자도
바뀌지 않는다.

**FR-ATC-9** 단정 총수가 유지된다.

### 3.3 묶음 C — 게이트

**FR-ATC-10** `scripts/check-e2e-private.sh` 가 `e2e/` 안의 `app._` 접근을
잡는다. 위반 0 이 통과 조건이다.

**FR-ATC-11** 게이트는 **예외 목록을 갖는다**(FR-ATC-12). 목록의 각 줄에는
근거가 붙는다 — 근거 없는 예외는 게이트를 없애는 것과 같다.

**FR-ATC-12** 예외는 **파일 단위가 아니라 이름 단위**다. 파일을 통째로 빼면 그
파일의 새 위반이 조용히 들어온다.

**FR-ATC-13** 게이트는 `make gates` 와 CI 에 등록된다.

### 3.4 묶음 D — 예외

**FR-ATC-14** 계약으로 덮지 않는 것은 **`app` 자체의 존재 확인**뿐이다
(`window.app` 이 섰는가). 그것은 부팅의 사실이지 내부가 아니다.

## 4. 설계 결정 (Design Decisions)

**D-ATC-1: `app.testing = app` 이 아니다 — 이름을 **열거**한다.**
그냥 되내보내면 결합을 이름만 바꾼 것이고, e2e 가 내일 새 내부에 닿는 것을
아무것도 막지 못한다. 열거하면 **표면이 유한해지고 그 목록이 diff 에 보인다** —
새 이름이 필요하면 계약을 먼저 고쳐야 하고, 그 커밋이 "e2e 가 내부를 하나 더
보기 시작했다" 를 말한다. 절로 나눈 덕에 **어느 축이 과하게 열려 있는지**도
보이며, 그것이 `FE-4`(계층 역전)를 다음에 닫을 때의 지도가 된다.

**D-ATC-2: 계약을 프로덕션에서 빼지 않는다.**
빌드 갈래를 두면 e2e 가 검증한 것과 사용자가 받는 것이 다른 프로그램이 된다.
노출 위험은 없다 — 이 계약은 이미 전역인 `window.app` 을 다른 이름으로 가리킬
뿐이고, 브라우저 콘솔을 여는 사람은 `app` 을 그대로 쓸 수 있다.

**D-ATC-3: 게터로 감싼다 — 값을 복사하지 않는다.**
`testing.edWindows` 가 **읽는 시점**의 배열을 주어야 한다. 미리 복사하면 e2e 가
낡은 스냅샷을 단언한다. 함수도 같다: 미리 바인딩해 두면 e2e 가 갈아 끼운 구현
(`gitReposRefresh = async()=>{}`)이 계약을 지나지 않는다.

**D-ATC-4: 이름을 기계적으로 옮긴다 (더 좋은 이름을 지어내지 않는다).**
507곳의 이관에서 이름까지 고치면 리뷰가 불가능하다 — `app._x` → `app.testing.x`
는 사람이 훑어 확인할 수 있고, `app.edOpenFile` → `app.testing.ed.openFile` 은
그렇지 않다. 이름의 개선은 이 계약이 선 뒤에 **한 파일 안에서** 할 수 있고,
그것이 이 SRS 의 목적이다.

**D-ATC-5: 자료구조를 그대로 노출하는 것을 예외가 아니라 계약으로 적는다.**
`gitPanels`·`editors` 같은 것은 e2e 가 그 모양을 알고 있어야만 재는 것이
있다. 감추는 대신 **계약에 적어** 그 사실을 드러낸다 — 감춘 결합은 없어진
결합이 아니다.
