## 3. 요구조건 (각 항목 이전/새 동작 기록, TDD)

### T-1 디렉터리 로드 규약 (#31, N2)
- T-1.1 폴더 로드는 요청 세대를 가진다. 진행 중 로드가 있을 때의 새 요청은 버리지 않고 "완료 후 한 번 더(coalesce)" 로 처리한다. 적용은 최신 세대 응답만 한다(§3A-1).
- T-1.2 여러 항목의 병렬 이동·생성·삭제 뒤 최종 화면은 서버 상태와 같다. 한 건 실패의 되돌리기가 다른 성공 건의 반영을 되돌리지 않는다 — 배치 조작은 항목별 되돌리기 대신 배치 종료 후 영향받은 부모 폴더를 재조회해 서버 상태로 수렴한다(§3A-1).

### T-2 스탬프 상태 모델 (#29, #30)
- T-2.1 폴더별 관측 상태를 "미관측 / 관측(stamp) / 실패 / 사라짐" 으로 구분한다. 실패·사라짐 상태의 폴더는 다음 폴링에서 재조회 대상이다.
- T-2.2 일시적 오류(status 0·5xx)는 멀쩡한 목록을 오류로 덮지 않는다 — 기존 목록을 유지하고 그 폴더 행에 "갱신 실패" 표식을 단다. 4xx 는 목록을 오류로 바꾼다(§3A-2).
- T-2.3 펼쳐 둔 폴더가 사라졌다 다시 생기면 새 목록을 읽는다(옛 `_kids` 폐기).

### T-3 다중 칸 관측 (#32)
- T-3.1 같은 루트를 여러 칸에 띄워도 각 칸에서 펼친 폴더가 모두 외부 변경을 따라간다. stamp 질의는 store 가 하며 대상은 그 루트의 모든 뷰의 펼친 폴더 합집합이다(§3A-2).

### T-4 실패는 보인다 (#27 ✅)
- T-4.1 삭제·이름변경·생성·이동·업로드 실패 사유가 후속 재조회(`_after`)·폴링에 지워지지 않고 사용자에게 보인다. 수명·자리는 §3A-3.

### T-5 대소문자만 다른 이름변경 (#28 ✅)
- T-5.1 대소문자를 구분하지 않는 파일시스템(macOS APFS 기본, Windows)에서 `readme.md`→`README.md` 가 성공한다. 대상이 존재할 때 **같은 부모 디렉터리 + 이름이 대소문자만 다름 + `os.SameFile`** 을 모두 만족할 때만 충돌로 보지 않는다(하드링크 두 이름을 자기 자신으로 오판하지 않는다). 대소문자 구분 FS 에서는 기존 동작 유지(§3A-4).

### T-6 낙관 반영의 되돌리기 (P2)
- T-6.1 펼쳐 둔 기존 폴더 이름으로의 변경이 거부되면 두 폴더의 펼침·캐시가 원래대로 돌아온다(키 충돌 시 덮어쓰기 금지).
- T-6.2 생성 실패 시 선택을 원래대로 되돌린다(다음 "새 파일"이 원래 폴더에 뜬다). 입력하던 이름을 보존한다.

### T-7 조작 의미 (P2)
- T-7.1 "복제"는 사용자의 클립보드(잘라내기/복사 구분 포함)를 원래대로 되돌린다(✅ `file-tree-edit.js:363` move 인자 누락).
- T-7.2 폴더를 자기 자신(또는 같은 부모) 위에 드롭하면 아무 일도 하지 않는다(오류 없음). 다중 선택 중 드롭 대상 자신은 건너뛴다.
- T-7.3 인라인 편집을 Enter/Esc 로 끝내면 키보드 포커스가 트리 목록으로 돌아온다.
- T-7.4 드래그 도중 다시 그려져도 드래그 원본·드롭 강조가 유지되고, 드래그가 끝나면(Esc·밖에 놓기·창 blur 포함) 드래그 상태가 반드시 해제된다. 남은 드래그 상태가 이후 다른 드롭(편집기 탭 등)에서 파일을 옮기지 않는다.

### T-8 성능 (P2)
- T-8.1 git 상태 폴링 응답의 `mark`(서버 관측 식별자, §3A-0 X5)가 직전 적용분과 같으면 상태 재계산·rollup·전체 재칠을 하지 않는다. 대형 폴더(수천 항목)에서 변화 없는 폴링이 전체 행 재계산을 일으키지 않음을 렌더 호출 수 계측 단위 테스트로 검증한다.

### T-9 이름변경과 편집기 (03 연계)

### §3A-1 폴더 로드·배치 조작 (T-1)
사실: `load`(`file-tree-paint.js:15-72`)는 `_busy` 면 요청을 버린다(`:16`), 세대 없음, 실패 시 `_stamps.delete(dir)`(`:43`).

| 항목 | 확정 |
|------|------|
| 세대 | 폴더별 `loadGen`. 요청은 시작 시 gen 을 기억하고, 응답은 그 gen 이 현재 gen 과 같을 때만 적용한다 |
| coalesce | 진행 중 로드가 있으면 새 요청은 "대기 1건" 으로 합친다(나중 요청의 옵션이 이긴다). 진행 중 로드가 끝나면 대기 건을 1회 실행한다 |
| 낙관 반영 | 이동·생성·삭제로 `_kids` 를 직접 고치면 그 폴더의 gen 을 올린다 — 낙관 반영 전에 출발한 응답은 적용되지 않는다 |
| 이어 받기 | 이어 받기(offset>0)는 재조회(offset=0)와 합치지 않는다. 재조회가 진행·대기 중이면 이어 받기 요청은 버린다(재조회가 적재분만큼 다시 채운다, FR-FSP-12) |
| 배치 조작 | 여러 항목 조작은 항목별 되돌리기를 하지 않는다. 배치가 끝나면(성공·실패 무관) 영향받은 부모 폴더들을 위 규약으로 재조회한다. 실패 항목은 §3A-3 으로 표시한다. 이전: 항목별 스냅샷 되돌리기가 병렬 조작 간 서로의 반영을 되돌렸다(#31) / 새: 서버 재조회로 수렴 |

### §3A-2 관측 상태·다중 칸 (T-2, T-3)
사실: 폴링 `pollStamp`(`file-tree-paint.js:431-468`)는 응답에서 빠진 겹의 stamp 를 지운다(`:458`, #30). `_stampBusy` 는 루트 공유 store 의 것(`file-tree-store.js:61-62`)인데 질의 대상 `_stampDirs()`(`file-tree-paint.js:413-419`)는 그 뷰의 펼친 폴더뿐이고, `app-editor-pane.js:24` 가 보이는 트리들을 연달아 불러 둘째 뷰는 busy 로 즉시 반환된다(#32).

| 항목 | 확정 |
|------|------|
| 상태 | 폴더 관측 상태 = `unseen` · `ok(stamp)` · `failed(code)` · `gone` |
| 전이 | load 성공 → ok, load 실패 → failed, 폴링 응답에서 빠짐 → gone(`_kids` 폐기, 펼침 상태 유지), gone 폴더가 다시 응답에 나타나거나 load 성공 → ok |
| 폴링 대상 | 펼친 폴더 중 ok·failed·gone. failed·gone 은 stamp 비교 없이 폴링 회차마다 재조회하되 연속 실패 시 `editorGitBackoffMs` 와 같은 백오프를 적용 |
| unseen | "unseen 은 재조회하지 않는다"(FR-FSL-10)는 ok 로 처음 들어온 겹에만 적용한다 |
| 일시 오류 | status 0(전송 실패)·5xx: 기존 목록 유지 + 그 폴더 행에 "갱신 실패" 표식. 4xx(권한·부재): 목록을 오류로 바꾼다. 다음 성공 시 표식 제거 |
| 다중 칸 | stamp 질의는 store 가 한다. 대상 = 그 루트의 모든 뷰의 펼친 폴더 합집합(중복 제거, 루트 먼저, `FS_STAMP_MAX` 로 자름). 뷰별 `pollStamp` 는 store 호출로 대체한다. 응답 적용은 그 폴더를 펼친 모든 뷰에 반영된다 |

### §3A-4 대소문자 이름변경 (T-5)
사실: `handlers_fs_mutate.go:103-137` 의 `Lstat(to)` 가 대소문자 비구분 FS 에서 자기 자신을 찾아 EEXIST(#28). 일반 파일은 `os.Link` 로 먼저 잡는데 대소문자만 다른 이름은 Link 도 EEXIST.

| 항목 | 확정 |
|------|------|
| 판정 | 대상이 존재할 때 ① `filepath.Dir(from)==filepath.Dir(to)` ② `strings.EqualFold(filepath.Base(from), filepath.Base(to))` 이고 두 이름이 바이트로 다름 ③ `os.SameFile(Lstat(from), Lstat(to))` — 셋 모두 참이면 대소문자 변경으로 보고 `os.Link` 를 건너뛰어 `os.Rename` 한다(디렉터리 포함) |
| 하드링크 | 대소문자 구분 FS 의 하드링크 두 이름(①·③ 참, ② 거짓) 또는 다른 디렉터리의 하드링크(① 거짓)는 위 조건에 걸리지 않으므로 기존대로 충돌이다 |
| 테스트 | 대소문자 비구분 FS 에서만 실행(런타임 감지 후 `t.Skip`). 하드링크 오판 방지 테스트는 모든 FS 에서 실행 |

### §3A-8 구현 중 정정·추적표 (구현 완료 2026-09-24)

구현 중 정정:
- 관측 식별자 함수는 `store.Mark`(`domain/git/store/mark.go`) — hub 의 `obsMark` 는 그것을 부른다.
- 세대로 **버려진** 재조회 응답은 "한 번 더" 로 다시 읽는다 — 버리기만 하면 그 폴더가 목록 없이 남는다(로드 진행 중 낙관 반영과의 경합, e2e 로 재현).
- 되돌리기 스냅샷이 "목록 없음" 이었으면(로드 진행 중) 그 사이 도착한 목록을 지우지 않고 다시 읽는다. 이름변경의 키 이동은 옮겨진 키의 양쪽 세대를 올린다. 대상 폴더를 **읽는 중**이어도 낙관 반영을 하지 않는다(T-6.1 확장).
- 단일 항목 이동은 기존처럼 낙관 반영(+실패 시 되돌리기)이고, 여러 항목은 `doMoveMany` 배치(되돌리기 없이 재조회로 수렴)다. 삭제는 여러 건이든 한 건이든 되돌리기 없이 재조회로 수렴한다.
- `edRetargetTabs` 는 `{count, conflicts}` 를 돌려준다(이전: 탭 수).
- 드래그 표식 타입 `application/x-dongminal-tree` 를 싣는다. 현재 트리 밖에서 트리 드래그를 해석하는 자리는 없다 — 앞으로 생기면 이 타입이 있을 때만 해석한다.
