## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

dongminal 에 Git 기능을 도입한다. 브라우저 기반 터미널 멀티플렉서 안에서 **GUI 만으로
일상 git 작업이 완결**되도록 하는 것이 목표다 — 변경 확인, 스테이징, 커밋, 원격 동기화,
히스토리 탐색, 브랜치·스태시 조작.

본 SRS 는 MVP 범위(P0 38개 기능)를 마일스톤 M1~M5 로 나누어 정상 요구사항으로 전개한다.

### 1.2.1 마일스톤 경계의 의미

경계는 임의가 아니다.

- **M1 에는 파괴적 동작이 하나도 없다.** `internal/git` 이 쓰기 명령을 아예 노출하지
  않는다(FR-GIT-7). 안전 정책을 세우기 전에 저장소를 건드릴 경로를 만들지 않는다.
- **M2 에서 묶음 J(안전 정책)를 먼저 세운다.** discard·amend 가 들어오는 시점과
  preflight·recovery hint 가 서는 시점이 같아야 한다.
- **M3 은 작다**(원격 3동작). M2 의 안전 정책 위에 얹히므로 독립 마일스톤으로 둔다.
- **M4·M5 는 읽기 비중이 크다.** 조작은 대부분 M2 의 정책을 재사용한다.

### 1.3 정의 (Definitions)

| 용어 | 뜻 |
|---|---|
| **리포(repo)** | `git rev-parse --show-toplevel` 로 확정된 저장소 루트 절대경로 |
| **활성 리포** | Git 창이 현재 표시 중인 리포. `⟳`(follow) 또는 `📌`(고정) 중 하나에서 온다 |
| **follow** | 포커스된 터미널 칸의 cwd 로 활성 리포를 자동 결정하는 모드 |
| **핀(pin)** | 사용자가 고정한 리포. `workspace.json` 에 영속 |
| **signature** | `.git` 상태 변화를 싸게 감지하는 값 — `HEAD` 내용 + `index` mtime + 현재 ref mtime |
| **diff 축(axis)** | 무엇과 무엇을 비교하는지. `worktree↔index`, `index↔HEAD`, `worktree↔HEAD` |
| **single-flight** | 같은 조회가 이미 진행 중이면 새로 띄우지 않고 결과를 공유하는 것 |
| **preflight** | 실행 전 차단 검사. 실패를 사후 오류가 아니라 사전 차단으로 전환한다 |
| **recovery hint** | 파괴적 동작 직전에 제시하는 복구 수단 안내(및 값 기록) |
| **파괴적 동작** | discard · 브랜치 삭제(`-D`) · stash drop · 태그 삭제 · `reset --hard` · force push · 원격 ref 삭제 (FR-GIT-89) |
| **2단계 확인** | 1단계에서 영향 범위를 보이고, 2단계에서 실행을 확인하는 절차 |
| **원격 작업** | fetch / pull / push. 네트워크·인증이 개입하고 시간이 걸리는 작업 |

## 2. 전제 (Established Facts)

M1 은 새로 만드는 것보다 **이미 있는 것을 잇는 비중이 크다.** 근거는 다음과 같다.

### 2.1 git 실행 패턴이 이미 있다

`internal/worktree/worktree.go:83` `execGit` 은 `exec.LookPath` → `CommandContext`
(타임아웃) → `CombinedOutput` 구조이며, `Runner` 주입으로 테스트가 결정론적이다.
M1 은 이 패턴을 `internal/git` 로 일반화한다.

### 2.2 cwd 가 도구별로 실시간 추적된다

`s.Tools.Cwd(toolID)` 와 `GET /api/cwd?tool=<id>` 가 이미 있고, 셸 훅
(`zdotdir/.zshrc` 의 `precmd`/`chpwd`, `bash-hook.sh` 의 `PROMPT_COMMAND`)이
OSC 777 `Cwd;<pwd>` 로 갱신한다. **리포 해석에 디스크 스캔이 필요 없다.**

### 2.3 Monaco 가 이미 로드된다

`web/js/file-editor.js:5` 가 `monaco-editor@0.56.0` 전체 번들
(`vs/editor/editor.main`)을 로드하며 `monaco.editor.createDiffEditor` 가 포함된다.
테마도 `monaco.editor.defineTheme('dongminal', …)` 로 연동돼 있다.

### 2.4 가시성 게이팅 선례가 있다

`FR-STAT-17` 이 `document.hidden` 동안 폴링을 멈추고 복귀 시 즉시 1회 수집하도록
정하고 있으며 `app.js:2311-2316` 이 그 구현이다. Git 폴링도 같은 규약을 따른다.

### 2.5 데이터 모델

`workspace.json` 은 `schemaVersion: 2` 이고 `windows[]` 의 각 원소는
`{id, name, layout}` 이다. 창에는 현재 `type` 필드가 **없다**. 탭은
`{id, name, type, toolId}` 이며 `type` 은 `terminal`·`editor` 등이다.

### 2.6 실측된 비용

| 항목 | 값 | 출처 |
|---|---|---|
| `git status --porcelain=v2 -z` | 10ms 내외 (20,000 파일에서 30ms) | GIT_INTEGRATION_ANALYSIS §4.5.2 |
| signature (2 syscall) | 0.02ms | 같은 절 |
| `core.fsmonitor` 효과 | 1.0배 (이득 없음) | 같은 절 |

## 3. 요구사항 — M1 읽기

### 3.1 묶음 A — git 실행 단일 지점 (`internal/git`)

- **FR-GIT-1** 모든 git 실행은 `internal/git` 의 단일 진입 함수를 통과한다. 다른
  패키지가 `exec.Command("git", …)` 를 직접 호출하지 않는다.
  (예외: `internal/worktree` 는 Run 격리 전용 경로로 기존대로 유지한다.)
- **FR-GIT-2** 인자는 문자열 배열로 전달한다. 셸을 경유하지 않으며 문자열 결합으로
  명령을 만들지 않는다.
- **FR-GIT-3** 모든 실행에 `exec.CommandContext` 로 타임아웃을 건다. 기본 상한은
  30초이며 호출자가 축소할 수 있다.
- **FR-GIT-4** 실행 단위는 `Runner` 로 주입 가능해야 한다 (`internal/worktree` 선례).
- **FR-GIT-5** 실행마다 `argv`·`cwd`·`exitCode`·`durationMs`·`stderr` 를 구조화해
  기록한다. M1 에서는 기록만 하고 표시하지 않는다 — Console 탭(M6)이 이 기록을 읽는다.
- **FR-GIT-6** stdout·stderr 보존량에 상한을 두고, 초과 시 잘렸음을 표시한다.
- **FR-GIT-7** 이 패키지는 M1 에서 **저장소를 변경하는 명령을 제공하지 않는다.**
  제공하는 것은 `rev-parse`·`status`·`diff`·`show`·`log`·`for-each-ref` 계열의
  읽기 명령뿐이다.
- **FR-GIT-8** git 이 없거나(`ErrGitMissing`) 대상이 저장소가 아닌 경우
  (`ErrNotRepo`) 는 구분 가능한 오류로 반환한다. 조용히 빈 결과로 낮추지 않는다.

### 3.2 묶음 B — 리포 해석과 목록

- **FR-GIT-9** 시스템은 포커스된 터미널 칸의 cwd 로부터
  `git rev-parse --show-toplevel` 로 리포를 확정한다 (follow 모드).
- **FR-GIT-10** cwd 가 저장소가 아니면 follow 항목은 "저장소 아님" 상태로 표시하고,
  마지막 유효 리포를 임의로 유지하지 않는다.
- **FR-GIT-11** 사용자는 리포를 핀할 수 있다. 핀 목록은 `workspace.json` 에 영속한다.
- **FR-GIT-12** 사용자는 경로를 직접 입력해 리포를 추가할 수 있다. 저장소가 아니면
  거부하고 사유를 표시한다.
- **FR-GIT-13** 좌측 사이드바는 GIT 섹션을 가지며 `⟳`(follow) 1개와 `📌`(핀) 목록,
  `+ Add` 진입점을 표시한다.
- **FR-GIT-14** GIT 섹션 항목은 변경 파일 수 배지를 표시한다.
- **FR-GIT-15** 항목 클릭은 Git 창을 활성화하고 활성 리포를 그 항목으로 전환한다.
- **FR-GIT-16** 활성 리포가 바뀌면 **이전 리포의 진행 중 응답이 새 화면을 덮지
  않는다.** 모든 비동기 응답은 요청 시점의 리포 식별자를 동반하며, 현재 활성 리포와
  일치하지 않으면 폐기한다. (stale 응답 가드)
- **FR-GIT-17** 사이드바 항목 수가 늘어도 WINDOWS 섹션이 사용 불가해지지 않는다 —
  각 섹션은 독립 스크롤 또는 접기를 갖는다.

### 3.3 묶음 C — 변경 감지

- **FR-GIT-18** 시스템은 세 계층으로 변경을 감지한다. 파일시스템 감시 라이브러리를
  도입하지 않는다.
  1. 즉시 신호 — 터미널 `precmd` OSC, 에이전트 hook, `POST /api/file/write`,
     브라우저 가시성·포커스 복귀
  2. signature 폴링 (기본 500ms)
  3. `git status` 폴링 (기본 1s)
- **FR-GIT-19** signature 는 `HEAD` 내용 + `index` mtime + 현재 ref mtime 으로
  구성한다. 값이 그대로면 status 재조회를 생략한다.
- **FR-GIT-20** 즉시 신호는 150ms 디바운스로 합친다. 연속 신호가 status 를 연발
  실행시키지 않아야 한다.
- **FR-GIT-21** 같은 리포의 status 조회는 single-flight 다. 진행 중 조회가 있으면
  새로 실행하지 않고 결과를 공유한다.
- **FR-GIT-22** `document.hidden` 이거나 Git 창이 비활성인 동안 클라이언트는 폴링을
  **완전히 중단**하고, 다시 보이면 즉시 1회 수집 후 정상 주기를 재개한다
  (FR-STAT-17 과 동일 규약).
- **FR-GIT-23** 폴링 주기(signature·status)는 설정으로 조정 가능하며, 0 이면 해당
  계층을 끈다.
- **FR-GIT-24** 감지는 **활성 리포 1개에 대해서만** 수행한다. 핀된 다른 리포는
  폴링하지 않는다. (GIT 섹션의 배지는 활성 리포 외에는 마지막 관측값이며, 그 사실이
  UI 에서 구분 가능해야 한다.)

- **FR-GIT-26** Git 창은 **워크스페이스 전체에 최대 1개**다. 이미 있는데 새로 열려는
  요청은 기존 창을 활성화한다.
- ~~**FR-GIT-27** Git 창은 일반 창이다 — 사용자가 그 안에서 분할해 터미널 탭을 배치할
  수 있어야 한다.~~ **폐기** — `GIT_UI_REVISION_SRS.md` FR-GIT-179 가 대체한다

- **FR-GIT-28** Git 창 내부는 고정 탭 행을 갖는다:

- **FR-GIT-29** Git 창의 활성 내부 탭과 활성 리포는 `workspace.json` 에 영속한다.
- ~~**FR-GIT-30** Git 창은 다른 창과 마찬가지로 창 목록·창 전환 단축키의 대상이다.~~

  (기존 `workspace_changed` 경로).

### 3.5 묶음 E — Changes 탭 (읽기)

- **FR-GIT-32** 헤더는 리포명, 현재 브랜치, ahead/behind 수를 표시한다.
- **FR-GIT-33** detached HEAD 와 upstream 없음은 각각 구분되는 배지로 표시한다.
- **FR-GIT-34** 변경 파일을 `staged` / `changes` / `untracked` 3그룹으로 분류해
  표시하며 각 그룹의 개수를 함께 보인다.
- **FR-GIT-35** 상태는 `git status --porcelain=v2 -z --branch` 를 파싱해 얻는다.
  `-z` 로 NUL 구분하여 공백·개행이 든 경로를 안전하게 처리한다.
- **FR-GIT-36** rename·copy 는 원본과 대상 경로를 함께 보존해 표시한다.
- **FR-GIT-37** 충돌(unmerged) 파일은 별도 표식으로 구분한다. M1 은 표시만 하며
  해결 기능은 제공하지 않는다.
- **FR-GIT-38** 파일 목록은 트리/플랫 보기를 전환할 수 있다.
- **FR-GIT-39** 상단 커밋 영역(메시지 입력·Commit 버튼)의 **자리는 M1 에서 확보하되
  비활성**이다. 파일 목록 스크롤에 영향받지 않는 고정 영역이어야 한다.
- **FR-GIT-40** 헤더의 Fetch/Pull/Push 버튼 자리는 M1 에서 확보하되 비활성이다.
- **FR-GIT-41** 파일 우클릭은 `Open Changes`(Diff 탭), `Open File`(내장 편집기),
  `Copy Path` 를 제공한다. M1 에서 저장소를 바꾸는 항목은 없다.
- **FR-GIT-42** 파일 수가 많아도 목록 렌더링이 화면을 멈추지 않아야 한다
  (가상 스크롤 또는 그에 준하는 처리).

### 3.6 묶음 F — Diff

- **FR-GIT-43** diff 는 `monaco.editor.createDiffEditor` 로 렌더링한다. 자체 diff
  하이라이트 엔진을 구현하지 않는다.
- **FR-GIT-44** 서버는 diff 축과 경로를 받아 **양쪽 전체 내용**(`original`,
  `modified`)을 반환한다. Monaco DiffEditor 가 두 모델을 요구하므로 unified diff
  텍스트를 반환하지 않는다.
  - `worktree↔index`: original = `git show :<path>`, modified = 워킹 트리 파일
  - `index↔HEAD`: original = `git show HEAD:<path>`, modified = `git show :<path>`
  - `worktree↔HEAD`: original = `git show HEAD:<path>`, modified = 워킹 트리 파일
- **FR-GIT-45** 추가·삭제된 파일은 없는 쪽을 빈 내용으로 처리하고 그 사실을 응답에
  표시한다.
- **FR-GIT-46** 바이너리 파일은 내용을 반환하지 않고 바이너리임과 크기를 반환한다.
  뷰어는 본문 대신 안내를 표시한다.
- **FR-GIT-47** Git LFS 포인터는 포인터임을 표시하고 메타만 보인다.
- **FR-GIT-48** 파일 크기 상한을 두고, 초과 시 내용을 반환하지 않고 안내한다.
- **FR-GIT-49** DiffEditor 옵션은 다음을 기본으로 한다.
  `renderSideBySide: true`, `useInlineViewWhenSpaceIsLimited: true`,
  `renderSideBySideInlineBreakpoint: 900`, `hideUnchangedRegions: {enabled:true}`,
  `ignoreTrimWhitespace: false`.
- **FR-GIT-50** `ignoreTrimWhitespace` 는 Monaco 기본값(`true`)을 뒤집는다 — git 은
  공백 변경을 변경으로 취급하기 때문이다. "공백 무시" 는 사용자 토글로 노출한다.
- **FR-GIT-51** side-by-side ↔ unified 는 사용자가 명시적으로 전환할 수 있다.
- **FR-GIT-52** Changes 탭에서 파일 단일 클릭은 우측 미리보기에, 더블클릭은 Diff 탭에
  표시한다.
- **FR-GIT-53** Diff 탭은 상단에 `‹ ›` 파일 네비게이션과 현재 위치(`2/3`)를 표시하며,
  같은 목록의 이전/다음 파일로 이동할 수 있다.
- **FR-GIT-54** diff 응답에도 FR-GIT-16 의 stale 가드를 적용한다. 식별자는
  `(리포, 축, 경로, 리비전)` 이다.
- **FR-GIT-55** Monaco 는 CDN 로드다. 로드 실패 시 diff 영역은 사유를 표시하고,
  Git 창의 나머지 기능은 계속 동작해야 한다.
- **FR-GIT-56** DiffEditor 인스턴스는 탭 전환·리포 전환 시 누수 없이 정리한다.

### 3.7 묶음 G — 상태바

- **FR-GIT-57** 상태바는 활성 리포의 브랜치와 변경 파일 수를 chip 으로 표시한다.
  기존 `STATUS_ITEMS` 체계에 편입해 사용자가 표시 여부를 끌 수 있어야 한다.
- **FR-GIT-58** chip 클릭은 Git 창을 활성화한다.
- **FR-GIT-59** 리포가 없거나 저장소가 아닌 경우 chip 은 표시하지 않는다.

### 3.8 외부 인터페이스 (API)

- **FR-GIT-60** 모든 기능은 HTTP API 를 통해 제공하며, UI 는 그 위에 선다. 프론트가
  git 실행 결과를 다른 경로로 얻지 않는다. (`dmctl git` 이 이후 같은 API 위에 얇게

## 3A. 요구사항 — M2 커밋

M2 부터 저장소를 변경한다. **묶음 J(안전 정책)는 묶음 H·I 와 같은 마일스톤에 있어야
한다** — 파괴적 경로가 열리는 시점과 방어가 서는 시점이 같아야 하기 때문이다.

### 3A.1 묶음 H — 스테이징

- **FR-GIT-64** 사용자는 파일 단위로 stage 할 수 있다 (`git add -- <path>`).
- **FR-GIT-65** 사용자는 파일 단위로 unstage 할 수 있다 (`git reset HEAD -- <path>`).
  HEAD 가 없는 저장소(초기 커밋 전)에서는 `git rm --cached` 경로를 쓴다.
- **FR-GIT-66** 사용자는 그룹 단위로 일괄 stage 할 수 있다 (changes / untracked).
- **FR-GIT-67** 사용자는 staged 그룹을 일괄 unstage 할 수 있다.
- **FR-GIT-68** 사용자는 tracked 만 / untracked 만 구분해 일괄 처리할 수 있다.
- **FR-GIT-69** 사용자는 파일을 다중 선택해 일괄 stage/unstage 할 수 있다.
- **FR-GIT-70** 일부만 staged 인 파일은 indeterminate 상태로 구분 표시한다.
- **FR-GIT-71** stage/unstage 후 상태를 즉시 재조회해 반영한다. 폴링 주기를 기다리지
  않는다.
- **FR-GIT-72** 충돌(unmerged) 파일의 stage 는 "해결됨 표시" 의 의미를 가지므로,
  실행 전 그 뜻을 사용자에게 알린다.
- **FR-GIT-73** stage/unstage 실패 시 index 와 워킹 트리를 실행 전 상태로 두고 오류를
  표면화한다. 부분 적용 상태로 조용히 남기지 않는다.

### 3A.2 묶음 I — 커밋

- **FR-GIT-74** 커밋 메시지는 멀티라인 입력이며, 입력에 따라 높이가 늘고(auto-grow)
  경계 드래그로 조정 가능하다. **파일 목록 스크롤과 독립된 고정 영역**이다(FR-GIT-39).
- **FR-GIT-75** 작성 중인 메시지는 리포별 draft 로 영속한다. 리포·창을 전환하거나
  브라우저를 새로고침해도 보존된다.
- **FR-GIT-76** 저장소에 `commit.template` 이 설정돼 있으면 초기 내용으로 채운다.
- **FR-GIT-77** Commit 버튼은 staged 내용을 커밋한다
  (`git commit --file=- --cleanup=strip`). 메시지는 stdin 으로 전달한다 — 인자로
  넘기지 않는다.
- **FR-GIT-78** `amend` 토글은 직전 커밋 메시지를 채우고 `--amend` 로 실행한다.
  토글을 끄면 채워진 메시지를 원래 draft 로 되돌린다.
- **FR-GIT-79** `Commit ▾` 드롭다운은 sign-off(`--signoff`),
  no-verify(`--no-verify`), commit all(`-a`) 을 제공한다. VSCode 의 조합 명령 20개를
  이 옵션 조합으로 대체한다.
- **FR-GIT-80** 커밋 성공 시 상태를 재조회하고 메시지 입력을 비운다.
- **FR-GIT-81** 커밋 성공 후 5초간 undo 진입점을 토스트로 제공한다.
- **FR-GIT-82** undo 는 `git reset --soft HEAD@{1}` 이다. 실행 후 상태와 메시지를
  커밋 직전으로 되돌린다.
- **FR-GIT-83** 토스트가 만료되거나 다른 커밋이 발생하면 undo 진입점은 사라진다.
  **만료된 undo 를 실행할 수 있어서는 안 된다.**
- **FR-GIT-84** 메시지가 비었거나 staged 가 없으면 Commit 을 비활성화하고 사유를
  표시한다. (`--allow-empty` 는 M2 범위 밖이다.)
- **FR-GIT-85** GPG 서명이 활성(`commit.gpgsign`)이면 그 사실을 표시한다. 서명 실패는
  커밋 실패로 취급하고 사유를 그대로 보인다.

### 3A.3 묶음 J — 안전 정책

**본 묶음은 M2 이후 모든 파괴적 동작이 따르는 공통 규약이다.**

- **FR-GIT-86** 시스템은 커밋 실행 전 다음을 검사해 차단한다 (preflight):
  `user.name`/`user.email` 미설정, 진행 중인 머지·리베이스·체리픽·리버트.
- **FR-GIT-87** detached HEAD 에서의 커밋은 차단하지 않되 그 상태와 결과(커밋이 어느
  브랜치에도 속하지 않음)를 명시적으로 경고한다.
- **FR-GIT-88** preflight 차단은 **무엇이 왜 막혔고 어떻게 푸는지**를 함께 표시한다.
  단순 실패 메시지로 끝내지 않는다.
- **FR-GIT-89** 다음을 **파괴적 동작**으로 정의한다: discard, 브랜치 삭제(`-D`),
  stash drop, 태그 삭제, `reset --hard`, force push, 원격 브랜치·태그 삭제.
- **FR-GIT-90** 파괴적 동작은 2단계 확인을 거친다. 1단계는 **영향 범위**(대상 목록·
  개수)를 보이고, 2단계는 명시적 실행 확인이다.
- **FR-GIT-91** discard 확인 화면은 폐기될 파일 목록을 보인다. 개수만 표시하지 않는다.
- **FR-GIT-92** 파괴적 동작 직전에 **recovery hint** 를 제시한다 — discard 는 stash
  대안을, ref 삭제는 삭제될 ref 값을 기록해 되살릴 명령을 안내한다.
- **FR-GIT-93** recovery hint 로 기록한 값은 세션 동안 조회 가능하다.
- **FR-GIT-94** 모바일에서는 파괴적 동작의 확인 단계를 데스크톱보다 엄격히 적용한다
  (터치 오조작 방지). 확인 버튼은 목록과 분리 배치하고 기본 포커스를 취소에 둔다.
- **FR-GIT-95** 모든 파괴적 동작은 `internal/git` 의 지정된 단일 경로를 통과하며,
  FR-GIT-5 의 실행 기록에 파괴적임이 표시된다.
- **FR-GIT-96** 실패한 동작은 stderr 마지막 N줄(기본 200)을 보존하고 복사할 수 있게
  한다.
- **FR-GIT-97** 파괴적 동작의 기본 선택지는 항상 **안전한 쪽**이다 (force 아님,
  삭제 아님, 취소가 기본 포커스).

## 3B. 요구사항 — M3 원격

### 3B.1 묶음 K — Fetch / Pull / Push

- **FR-GIT-98** Changes 탭 헤더는 Fetch / Pull / Push 버튼을 제공한다.
- **FR-GIT-99** 버튼은 **기본 동작만** 수행한다. 변형(`--prune`, `--rebase`,
  force 등)은 다이얼로그(묶음 P)로 분리한다.
- **FR-GIT-100** upstream 이 없는 브랜치에서 Push 는 Publish(`-u` 로 upstream 설정)로
  동작하며, 그 사실을 사용자에게 알린다.
- **FR-GIT-101** 원격 작업은 실행 중임을 표시하고, 같은 리포에 대해 동시 실행을
  막는다.
- **FR-GIT-102** 원격 작업에는 작업 식별자를 발급하고, 진행 중 취소할 수 있다
  (프로세스 종료 시그널). 취소는 부분 적용 가능성을 사용자에게 알린다.
- **FR-GIT-103** 원격 작업의 출력은 줄 단위로 스트리밍해 진행 상황을 보인다.
- **FR-GIT-104** 인증이 필요한 경우를 감지해 안내한다. **자격증명을 dongminal 이
  저장하거나 중계하지 않는다** — git 의 credential helper 에 위임하고, 대화형 입력이
  필요하면 터미널에서 수행하도록 안내한다.
- **FR-GIT-105** push 가 거부(non-fast-forward)되면 사유와 후속 선택지(fetch 후
  rebase/merge)를 제시한다. **force 를 기본 제안하지 않는다.**
- **FR-GIT-106** force push 는 `--force-with-lease` 를 기본으로 하고,
  `--force` 는 별도의 2단계 확인을 요구한다(FR-GIT-89·90).
- **FR-GIT-107** 작업 완료 후 ahead/behind 와 상태를 갱신한다.
- **FR-GIT-108** 네트워크·인증 실패는 stderr 를 보존해 표시한다(FR-GIT-96).
- **FR-GIT-109** Fetch 다이얼로그는 `--prune`, `--tags`/`--no-tags` 를 제공한다.
- **FR-GIT-110** Pull 다이얼로그는 rebase / ff-only / no-ff 를 제공한다.
- **FR-GIT-111** Pull 중 충돌이 발생하면 충돌 상태를 표시하고 Changes 탭으로 안내한다.
  M3 에서 충돌 해결 UI 는 제공하지 않는다(FR-GIT-37 의 표시까지).
- **FR-GIT-112** 진행 중인 원격 작업은 상태바에도 표시되어, Git 창을 보지 않아도
  알 수 있다.

## 3C. 요구사항 — M4 히스토리

### 3C.1 묶음 L — History 탭

- **FR-GIT-113** 커밋 목록은 `git log` 로 조회하며, 해시·부모 목록·author·date·
  subject 를 포함한다. 출력은 NUL 구분으로 파싱한다.
- **FR-GIT-114** 초기 300개를 로드하고, 추가 로드는 100개 단위다.
- **FR-GIT-115** 스크롤이 목록 끝에 도달하면 자동으로 추가 로드한다.
- **FR-GIT-116** 목록은 가상 스크롤로 렌더링한다. 보이지 않는 행은 DOM 에 두지 않는다.
- **FR-GIT-117** 그래프 레인은 부모 관계로부터 단일 전방 패스로 계산한다. 각 행에 대해
  커밋의 레인, 통과 레인, 부모 레인, 새 머리 여부를 산출한다.
- **FR-GIT-118** 그래프는 **행별 인라인 SVG** 로 그린다. 캔버스를 쓰지 않는다 —
  가상 스크롤과 테마 연동 때문이다.
- **FR-GIT-119** 레인 색은 **현재 테마의 팔레트에서 파생**한다. 색을 하드코딩하지
  않는다. 테마를 바꾸면 그래프 색도 따라 바뀐다.
- **FR-GIT-120** 레인 수에 상한을 두고, 초과 시 압축 표식을 표시한다.
- **FR-GIT-121** 어느 자식도 예약하지 않은 커밋(브랜치 머리)은 위쪽 진입선을 그리지
  않는다.
- **FR-GIT-122** refs 사이드바는 로컬 브랜치·원격 브랜치·태그를 그룹 트리로 보인다.
- **FR-GIT-123** refs 사이드바에서 ref 를 선택하면 그 ref 기준으로 목록을 필터한다.
  선택 해제 시 전체(`--all`)로 돌아간다.
- **FR-GIT-124** 목록 컬럼은 그래프 · 메시지(+ref 배지) · Author · Date · Commit(해시)
  이다.
- **FR-GIT-125** 폭이 좁아지면 Commit → Date → Author 순으로 컬럼을 숨긴다. 그래프와
  메시지는 항상 남는다.
- **FR-GIT-126** 커밋에 붙은 브랜치·태그는 배지로 표시하며, HEAD 위치를 구분한다.
- **FR-GIT-127** 미커밋 변경이 있으면 목록 최상단에 해당 행을 표시한다.
- **FR-GIT-128** 커밋 정렬 순서(date / author-date / topo)를 선택할 수 있다.
- **FR-GIT-129** 텍스트 검색은 **로드된 범위 검색과 저장소 전체 질의를 구분**하고,
  현재 어느 모드인지 사용자에게 표시한다. 두 결과가 다를 수 있음이 드러나야 한다.
- **FR-GIT-130** author · date · path 필터를 제공하며, 가능한 경우 git 옵션으로
  내려보낸다.
- **FR-GIT-131** 해시·브랜치·태그로 즉시 이동할 수 있다. 대상이 로드 범위 밖이면
  로드한 뒤 이동한다.
- **FR-GIT-132** 로드 실패 시 사유를 표시하고, 이미 로드된 목록을 지우지 않는다.
- **FR-GIT-133** 리포 전환 시 목록·필터·선택을 초기화하고, 이전 리포의 응답을
  폐기한다(FR-GIT-16).
- **FR-GIT-134** 그래프·목록의 렌더 성능은 스크롤 중 프레임 저하가 체감되지 않아야
  한다(§4 성능 기준).

### 3C.2 묶음 M — 커밋 상세와 액션

  브랜치·태그·스태시·파일)별로 항목 집합을 선언하면 렌더·키보드 조작·닫기가 공통
  경로를 탄다. 표면 지도 S4 의 46개 항목이 이 프레임워크 위에 선형으로 얹힌다.

- **FR-GIT-170** 조작 후 목록과 상태를 갱신한다.

### 3D.3 묶음 P — 다이얼로그 공통 규약

- **FR-GIT-171** 다이얼로그는 공통 골격을 공유한다 — 제목, 본문, 옵션, 실행/취소,

- **FR-GIT-172** 파괴적 동작의 다이얼로그는 묶음 J 의 2단계 확인을 따른다.
- **FR-GIT-173** 옵션의 기본값은 항상 안전한 쪽이다(FR-GIT-97).
- **FR-GIT-174** 실행 중에는 중복 실행을 막고 진행 상태를 보인다.
- **FR-GIT-175** 실패 시 사유와 stderr tail 을 표시하고 복사할 수 있게 한다.
- **FR-GIT-176** `Esc` 로 취소하고 `Enter` 로 기본 동작을 실행한다. **파괴적
  다이얼로그에서 `Enter` 의 기본 동작은 취소다.**
- **FR-GIT-177** 다이얼로그는 모바일 폭에서도 조작 가능해야 한다 — 옵션과 확인

- **FR-GIT-178** 다이얼로그가 열린 동안에도 폴링·감지는 계속되며, 대상 상태가 변하면

**성능 기준** (§2.6 실측 기준):

- `/api/git/status` 는 캐시 적중 시 10ms 이하로 응답한다.
- signature 조회는 1ms 이하다.
- 폴링이 도는 동안 dongminal 프로세스의 추가 CPU 점유가 활성 리포 1개 기준
  **평시 3% 를 넘지 않는다.**
- History 목록은 10,000 커밋에서도 스크롤이 매끄러워야 하며, DOM 노드 수는 로드된
  커밋 수가 아니라 **화면에 보이는 행 수에 비례**한다.
- 원격 작업은 진행 중에도 UI 를 막지 않는다.

**보안 기준**

- 자격증명(비밀번호·토큰·SSH 패스프레이즈)이 dongminal 의 로그·저장 파일·HTTP 요청
  본문·에러 메시지 어디에도 남지 않는다 (FR-GIT-104, V43).
- 리포 경로는 서버가 `rev-parse` 로 재확인한 뒤에만 파일 접근에 사용한다 (FR-GIT-62).
- git 인자는 배열로 전달하며 셸을 경유하지 않는다 (FR-GIT-2).

### 7.1 요구사항 해석 (구현 중 확정)

요구사항 문면이 두 가지로 읽히는 지점을 아래로 확정했다.

| # | FR | 해석 |
|---|---|---|
| I1 | 22 | **폴링 두 계층(signature·status)만 게이팅한다.** 즉시 신호(계층 ①)는 `document.hidden` 만 보고, Git 창이 비활성이어도 한 번은 수집한다. 근거: 즉시 신호는 사용자 행동에 1:1 이라 "폴링"이 아니고, 상태바 chip(FR-GIT-57)과 GIT 섹션 배지(FR-GIT-14)가 Git 창을 보지 않을 때도 딛는 값이다. 비용은 사용자가 명령을 실행한 순간의 10ms 한 번이다 |
| I2 | 73 | git 의 `add`/`reset`/`checkout` 은 경로별로 처리하므로 **진짜 롤백이 불가능하다.** 요구사항("부분 적용 상태로 조용히 남기지 않는다")은 실행 전후 status 를 비교해 `partial` 과 **무엇이 바뀌었는지**를 응답에 담는 것으로 만족시킨다. git 이 주지 않는 원자성을 흉내 내지 않는다 |
| I3 | 14 | 배지의 "변경 파일 수"는 그룹 개수의 합이 아니라 **서로 다른 경로의 개수**다. 한 파일이 staged 와 changes 에 동시에 들 수 있고(FR-GIT-70), 합으로 세면 파일 하나가 둘로 보인다 |
| I4 | 19 | signature 에 index 의 **크기**를 함께 넣는다. `stat` 한 번이 mtime 과 size 를 다 주므로 비용이 0 이고, mtime 해상도가 낮은 파일시스템에서 같은 초 안의 두 번째 쓰기를 놓치지 않는다 |
| I5 | 95 | 파괴적 판정은 하위 명령만으로 되지 않는다(`reset --soft` 는 안전, `--hard` 는 아니다). 호출자가 `WriteSpec.Destructive` 로 **선언**하고 그 선언이 실행 기록에 남는다 |
| I6 | 77 | 커밋 메시지는 stdin 으로 전달하고 **실행 기록에는 바이트 수만 남긴다.** 메시지를 기록에 남기면 사람이 붙여넣은 것이 무엇이든 실행 로그로 흐른다 |
| I7 | 161, 95 | `git stash list`·`stash show` 는 읽기지만 **쓰기 경로(`ExecWrite`)로 간다.** `stash` 가 `writeCommands` 에 있고 두 목록의 교집합이 비어 있어야 하기 때문이다(FR-GIT-95). FR-GIT-161 이 `git stash list` 를 못박았으므로 `log -g refs/stash` 로 바꾸지 않았다. 대가는 stash 목록 조회가 실행 기록에 쓰기로 남는 것이고, `Destructive:false` 와 argv 로 구분 가능하다. 하위 명령 수준의 목록 분리는 값어치가 확인되면 그때 한다 |
| I8 | 159 | `git check-ref-format --branch` 는 **exit 0 으로 이름을 펼친다** — `@{-1}` 은 직전 브랜치 이름을 출력하고 `git branch '@{-1}'` 은 실제로 그 브랜치를 건드린다(실측). 그래서 종료 코드만 믿지 않고 **stdout 이 입력과 같은지** 확인한다 |
| I9 | 47, 46, 48 | "메타만 보인다"는 ① 내용 대신 메타를 보인다 ② 내용을 받아오지 않는다 둘로 읽힌다. **둘 다로 확정한다** — 본문은 그리지 않고(이미 그랬다), 서버가 이미 싣는 메타(`lfsOid`·`lfsSize`)를 안내 **아래 줄**로 보인다. LFS 의 크기는 **가리키는 객체**의 크기다 — 포인터 파일 자신의 134 B 는 사용자가 묻는 것이 아니다. 함께 **FR-GIT-46·48 로 범위를 넓혔다**: 서버가 두 경우에도 `size` 를 싣는데 뷰어가 사유만 보이면 "얼마나 큰가·얼마나 넘었는가" 를 물을 자리가 없다. 메타를 만드는 곳은 한 함수(`gitBlobMetaLines`)이고 kind 로 갈린다. 양쪽 메타가 같으면 한 줄, 다르면 이전·이후로 나눈다 — 같은 값을 두 번 보이면 두 쪽이 다르다고 읽힌다 |
