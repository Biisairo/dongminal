### Go 와 다르게 한 내부 결정

- chat 의 전달 줄·Changed 알림은 goroutine 대신 std 스레드(+Condvar 신호)다. tokio 런타임 없이도 선다. mesh 는 런타임이 필요하다
- chat 의 deliver 는 상태 안에 두어 시험이 잠금 안에서 바꿀 수 있다(Go 시험의 opts.Deliver 교체 대응)
- chatsock 은 연결마다 읽기·쓰기 std 스레드, 보낼 줄은 Mutex+Condvar 큐(1024, 넘치면 끊음). close 는 막힌 accept 를 깨우려 소켓에 스스로 한 번 건다(Go 는 `ln.Close()` 가 Accept 를 깨운다)
- hello 전 연결은 지문 대신 일련번호 키로 pending 에 둔다(Go 는 net.Conn 을 키로 쓴다)
- Go `strings.EqualFold(tab,"User")` 는 "user" 의 글자 가운데 ASCII 밖으로 접히는 `ſ` 만 따로 맞춘 비교로 옮겼다
- Service 와 Mesh 가 서로를 쥔다(Arc 순환). close 로 멈추며, 둘 다 프로세스가 사는 동안 사는 객체라 해제하지 않는다
