## M6 의 목표는 "flaky 수정" 이 아니다

로드맵이 목표를 재서술했고 그 근거가 §M6 머리말에 있다. 요약하면:

  1차 감사(`TEST-5`)는 "flaky 아홉 건이 모두 관측 → 전체 재렌더 → DOM 교체라는
  동일 기전" 이라 판정했다. `11 §5` 가 9건을 코드로 매핑해 **그 판정이 절반만
  맞다**는 것을 확인했다 — 기전은 **셋**이고, **9건 중 8건이 제품 결함으로
  설명된다.** "테스트가 취약한 것" 이 아니다.

그래서 **가장 먼저 할 것은 낙관적 레이아웃 보호**다 (`_onWorkspaceChanged` 가
아직 저장되지 않은 로컬 레이아웃 변경을 덮지 않게). **flaky 5~6건이 거기서
닫힌다.** `app.js:531-556` 이 이미 rev 비교로 절반을 하고 있다.

**`fixtures.ts` 의 "재렌더는 앱의 정상 동작이므로 견디는 쪽은 테스트다" 는
근거가 없다** — git 관측은 `render()` 를 부르지 않는다(`app-git.js:610`).
탭이 사라지는 진짜 이유는 워크스페이스 재채택이고, 그것은 정상 동작이 아니다.

## 착수 순서 — 로드맵이 정했다 (§M6 내부 순서)

  ① **낙관적 레이아웃 보호** — flaky 5~6건이 여기서 닫힌다
  ② **관측 국소 수정** — `GP-2`(첫 관측) · `GP-9`+branches `_adopt` 재조회(B6) ·
     `GP-10`(쓰기 분류). 남은 flaky 2건
  ③ **`flaky > 0` 을 CI 실패로 승격** — ①② 보다 먼저 하면 CI 가 계통 결함으로
     계속 빨갛다
  ④ **갱신 수명·표시** — `GP-3`·`GP-4`·`GP-5`·`GP-6`
  ⑤ **서버 감지 2단화** — `GP-7`(`ReadSignature` 게이트) · `GP-8`(병렬화+회차 시한).
     **①~④ 이후에만.** `11 D-4` 가 "순서가 요점" 이라 못박았다

**순서를 바꾸지 마라.** ⑤ 를 먼저 하면 감지가 성기어진 상태에서 ①~④ 의 결함을
디버그하게 된다.

## M5 가 남긴 것 — 지금 쓸 수 있는 것

이번 마일스톤이 **진단 도구를 만들었다.** M6 은 그것을 처음 쓰는 마일스톤이다.

  · **요청 ID** — 응답 헤더 `X-Request-Id`. 접근 로그·핸들러 로그·데몬 RPC 로그가
    같은 ID 를 든다. **flaky 를 쫓을 때 이것이 실마리다** — 실패한 e2e 의 응답
    헤더에서 ID 를 집어 서버 로그를 보면 그 요청이 무엇을 했는지 전부 나온다
  · **`DONGMINAL_LOG_LEVEL=debug`** — 데몬 RPC 줄이 그때만 나온다. 상관관계를
    쫓을 때 켠다
  · **`GET /api/diag`** — `goroutines`·`allocMB`·게이트 거절 수·**데몬 재연결 수**.
    "도구가 가끔 멎는다" 류에서 `reconnects` 가 0 이 아니면 거기가 출발점이다
  · **`X-Error-Code`** — 모든 오류 응답의 코드. e2e 가 "실패했다" 대신
    **"무엇으로 실패했다"** 를 단언할 수 있다. 뜻은 `docs/external/errors.md`
  · **`.lastexit`** — 비정상 종료 판정. `doctor --bundle` 이 담는다
  · **`scripts/perf-probe.sh`** — `GP-7`(1초마다 `git status`)의 **before/after 를
    잴 자리**다. 예산은 `docs/internal/PERFORMANCE_BUDGET.md`
  · **`dongminal backup --out`** — 위험한 변경 전에 홈을 통째로 담는다

## M5 가 세운 게이트 — 깨뜨리지 말고 딛어라

`make gates` 에 **20종**이 있고 이번에 일곱이 늘었다. M6 에서 걸릴 만한 것:

  · `check-logging.sh` — **`log.Printf` 를 쓰지 마라.** `dmlog.Warnf(ctx, …)` 다.
    새로 쓰는 곳은 키-값(`dmlog.Warn(ctx,"msg","k",v)`)
  · `check-http-error.sh` — **`http.Error` 를 쓰지 마라.** `httpErr(w,msg,status,code)`
    이고 코드는 `apierr/codes*.go` 에 등록한다
  · `check-error-docs.sh` — 코드를 더하면 `codes_doc.go` 에 **의미와 복구 안내**를
    적어야 한다. 안 적으면 생성이 실패한다
  · `check-api-docs.sh` · `check-commands-docs.sh` · `check-shortcuts-docs.sh` —
    **표면을 더하면 그 문서를 같은 변경에서 고쳐야 한다.** 양방향이다
  · `check-srs-status.sh` — 새 SRS 는 제목 바로 아래에 상태 한 줄:
    `> **문서 상태**: 초안`. 값은 enum 이다
  · `check-decisions.sh` — SRS 의 결정을 고치면 `go run ./scripts/gen-decisions`

**생성물을 직접 고치지 마라** — `docs/external/errors.md` · `docs/internal/decisions.md`.

## 규약 (변하지 않는다)

- **로컬 전량은 `make e2e`** (CI 와 같은 8샤드 병렬, ~8분). `npx playwright test`
  한 프로세스로 돌지 마라 — CI 와 상태 누적 범위가 달라 답이 갈린다
- **출력을 자르지 마라.** `| tail -N` 은 종료코드를 `tail` 의 것으로 만든다.
  샤드 로그에는 이진 바이트가 섞이므로 **`grep -a`** 로 읽어라
- **재시동은 하지 않는다.** 안내만 낸다 — 데몬을 내리면 그 위의 PTY 가 전부 죽는다
- **이 저장소의 바이너리로 `start`/`stop` 을 부르지 마라.** 도구 셸의
  `DONGMINAL_PORT` 가 사용자의 실제 인스턴스를 가리킨다. `--isolated` 를 쓰거나
  **검사가 자기 전제를 스스로 세우게** 하라 (M5 에서 두 번 물렸다)
- 중·대 규모는 **스펙 → 테스트(RED) → 구현(GREEN)**
- **동작을 바꾸면 그 근거 문서를 같은 변경에서 고쳐라**
- 게이트를 느슨하게 만들어 통과시키지 마라. 새 게이트를 세우면 **탐침으로
  검출을 확인하고 지워라**
- 커밋 메시지에 AI 서명 금지. 커밋은 사용자 확인 후에만
