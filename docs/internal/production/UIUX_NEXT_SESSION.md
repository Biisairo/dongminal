## 2. 아직 안 될 때 — 남은 축 ②(TUI)

이 세션이 **손대지 않고 남긴** 것이다. Claude Code 같은 TUI 는 델타만 보내므로
어긋난 화면이 스스로 낫지 않는다.

넛지는 **전량 재생 + alt screen** 일 때만 걸리고, 전량 재생은 **폭이 바뀌었을

**함정이 있다.** `M11_SRS` §2.4f 가 조건을 **좁힌** 이력이 있다 — 넛지는
`SIGWINCH` 를 두 번 일으키고, *"화면을 지우지 않고 커서만 올려 덮어쓰는 앱은
그때마다 어긋난 그림을 하나씩 더 쌓는다. **claude 가 그 방식이다**"*. 넓히면
그 결함이 되살아난다.

그래서 넛지를 넓히는 대신 **되찾는 순간 전량 재생을 요청하는** 쪽이 과거 결함을

## 4. 이 세션이 값을 치르고 안 것 — 같은 값을 다시 치르지 마라

**① 시험이 먼저 빨개지지 않으면 진단을 의심하라.**
처음에 *"`_onWindowFocus` 에 `resendWindowSizes` 가 빠졌다"* 로 읽고 고쳤는데
**RED 가 나지 않았다.** `renderer-layout.js` 가 render 끝에서 이미 활성 창에
resize 를 보내고 있었다. 되돌렸다. 이번 세션에서 **두 번** 헛짚었고 둘 다 RED
확인이 잡아 줬다.

**② `render()` 는 터미널을 되돌리지 않는다.** 앱 레이아웃을 그릴 뿐이다.
터미널 내용은 PTY 크기 재전송(`0x01`) → 서버 재생으로 돌아온다.

**③ 판정을 DOM 에 되묻지 마라.** ②의 교훈과 같은 뿌리다 — 화면에 보이는 사실을
클래스로 되물어 확인하면, 그 되물음이 틀리는 순간 조용히 넘어간다.

**④ 이 저장소의 자산은 `embed` 다.** `web/` 을 고쳐도 **재빌드 전에는 반영되지
않는다.** 사용자가 "안 고쳐졌다" 고 할 때 가장 먼저 의심할 것.

**⑤ e2e 는 `devices['Desktop Chrome']` 이라 UA 가 Windows 다.** 그런데 브라우저의
**편집 명령은 호스트 OS 관습**을 따른다. 한 판에서만 참인 것을 전 판의 단정으로
적으면 CI 에서만 깨진다(실제로 겪었다).

**⑥ 모듈 크기 게이트(500줄)는 주석도 센다.** 근거 주석을 길게 쓰는 이 저장소의
문화와 부딪히면 **가르는 것이 정석**이다 — 이번에도 `app-focus.js` 를 갈랐고,
가른 자리는 그 파일 머리 주석이 이미 적어 둔 경계였다.

## 5. 변하지 않는 규약

- **SDD**: 스펙 → 테스트 → 코드. 스펙은 `docs/internal/*_SRS.md`, IEEE 29148.
- **RED 를 먼저 본다.** 고치기 전에 시험이 지는 것을 눈으로 확인한다.
- `make gates` · `make unit` · `npm run typecheck` 는 커밋 전 필수.
- 전량 e2e 는 `make e2e` (8샤드, ~7분). **격리 재실행의 "결함 0"** 까지 봐야 한다 —
  flaky 는 부하로 갈린다.
- 푸시하면 CI 둘(`verify` · `e2e`)이 돈다. `gh run watch <id>` 로 본다.
- **커밋 메시지에 AI 서명 금지.**
- 커밋은 **사용자 확인 후**에만.
