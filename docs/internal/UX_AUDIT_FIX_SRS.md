## 3. 요구사항 (Specific Requirements)

### 3.1 1묶음 — 빠른 효과

**FR-UXF-1 (D1)** — 상단바와 칸 머리글의 제목은 `창 이름 · 탭 이름` 이다. 사이드바 탭 라벨(`창`·`Repo` 등)은 앞에 붙이지 않는다.
창 이름이 비었으면 라벨을 이름 자리에 쓴다. 같은 말은 겹쳐 적지 않는다(종전 규칙).

> 이전 동작: `라벨 · 창 이름 · 탭 이름` (예: `창 · Window · Shell`).
> 새 동작: `Window · Shell`.
> 이유: 라벨은 사이드바 탭 이름이라 제목에서 정보가 없다 (진단 D1).

**FR-UXF-2 (D1)** — 제목의 구분점 `·` 은 흐린 글자(`.tt-sep`, `--text-hint`)로 그린다. `title` 속성은 전체 문자열 그대로다.

**FR-UXF-3 (D3)** — 상태바 항목의 **기본값**: 연결·cwd·인코딩만 켜짐이다. 위치(`location`)·지연(`latency`)·메모리(`memory`)는 기본
꺼짐이다. 저장된 값이 있으면 그것을 따른다 (D-1).

**FR-UXF-4 (D8)** — 포인터로 연 모달이 첫 요소에 포커스를 줄 때, 그리고 모달을 닫아 여는 단추로 포커스를 돌려줄 때 포커스 링을
그리지 않는다. 키보드로 열었거나, 그 뒤 키를 누르면 링은 종전대로 그린다. 포커스의 자리는 바뀌지 않는다 (C-3).

**FR-UXF-5 (D11)** — Changes 파일 행의 discard 단추(`[data-act="discard"]`)는 늘 위험색(`--danger-text`)이고, 앞 단추와
간격(`--ui-gap`)을 둔다. 흐림은 행 동작 공통의 투명도 규칙(FR-GIT-236)을 따른다 — 따로 낮추지 않는다.

**FR-UXF-6 (D14)** — 편집기 미리보기 단추(`.fe-render`)는 데스크톱에서도 편집기 오른쪽 아래에 선다(줄 번호와 겹치지 않는다).

**FR-UXF-7 (M3)** — 모바일 키바의 키보드 키(`data-act="kb"`)는 글자 `⌨` 대신 키보드 아이콘(`i-keyboard`)을 그린다. 켜짐
표식(`.sticky`)과 이름(`aria-label`)은 유지한다.

**FR-UXF-8 (M7)** — diff 보기 저장값(`gitDiffSideBySide`)이 없으면 모바일은 통합 보기로, 데스크톱은 나란히 보기로 시작한다.
저장값이 있으면 그것을 따른다 (D-2).

**FR-UXF-9 (M9)** — 미리보기 탭의 이름은 기울임꼴이 아니라 흐린 글자(`--text-muted`)다. 툴팁은 종전 문구(`editor.repo_preview_title`)다.

**FR-UXF-10 (X5)** — 앱 새로고침 단추(`#soft-reload-btn`)는 `rotate-ccw` 아이콘을 쓴다. `refresh-cw` 는 목록 새로고침(Activity·git)
에만 남는다.

#### 3.10.1 diff 도구 줄 (D13·M8, D-29)

**FR-UXF-80** — 데스크톱 diff 도구 줄(`.git-diff-bar`)의 단추는 한 문법이다: `‹ ›`(`.git-diff-nav`)는 아이콘 고스트 단추
(`ui-btn-ghost ui-btn-icon`, 아이콘 `chevron-left`·`chevron-right`), `Blame`(`.git-diff-blame`)은 고스트 토글(`aria-pressed`),
공백 무시·접기(`.git-diff-ws`·`.git-diff-fold`)는 같은 높이의 고스트 토글 모양(라벨 `ui-btn ui-btn-ghost ui-btn-sm`, 안의 체크박스는
남긴다 — 기존 시험·키보드 경로가 그 `input` 위에 서 있다). 나란히/통합은 분할 단추(`ui-segment`) 하나로 남는다.

**FR-UXF-81** — 모바일 도구 줄은 한 줄이다: `‹ ›` · 파일명(말줄임) · 나란히/통합 · `⋯`(`.git-diff-more`, 툴팁 `More diff options`).
축(`.git-diff-axis`)·위치(`.git-diff-pos`)는 모바일에서 숨기고 파일명의 `title` 에 `축 · 위치` 를 싣는다. `⋯` 메뉴의 항목은
`Blame`·`공백 무시`·`변경 없는 줄 접기` 셋이고, 켜진 항목은 체크 표시(`cur`)다. 메뉴 항목은 데스크톱 단추와 같은 동작을 부른다.
모바일에서 Blame 단추와 체크박스 라벨은 줄에 서지 않는다.

> 이전 동작: 상자 단추·분할 단추·체크박스가 섞였고, 모바일은 두세 줄로 꺾였다(`style-git-views.css` FR-MUX-41). / 이유: 진단 D13·M8, D-29.

#### 3.10.2 LSP 설치 제안 띠 (D15)

**FR-UXF-82** — 제안 띠(`.fe-offer`)는 한 언어(서버 id)에 **처음 한 번** 선다. 닫는 길은 둘이다: `받기`(받을 수 없으면 `설정`)와
`나중에`(`.fe-offer-no`). `×`(`.fe-offer-x`)는 없다. 띠가 한 번 섰으면(어느 길로 닫았든, 닫지 않고 파일을 떠났든) 그 언어는
"제안함" 으로 기억한다(`LSP_OFFER_KEY`, 기기별 — 종전 `다시 보지 않기` 의 기록도 "제안함" 으로 읽는다).

**FR-UXF-83** — "제안함" 인 언어의 파일이 포커스 편집기이고 그 서버가 아직 없으면, 상태바에 작은 표식(`.sb-lsp-offer`, 글자 `LSP`,
툴팁 `Language server for <id> is not installed — click to set up`)이 선다. 누르면 그 편집기에 제안 띠를 다시 연다. 서버가 생기면
(`_lspStatusInvalidate` 뒤 다시 읽어 `found`) 표식은 사라진다. 이 표식은 상태바 설정의 켜고 끄는 항목이 아니다(`#bg-btn`·갱신 알림과
같은 상황 표식).

> 이전 동작: md 파일을 열 때마다 띠가 섰고 닫는 길이 셋(받기·다시 보지 않기·×)이었다. / 이유: 진단 D15.

#### 3.10.3 메뉴의 단축키 (D18)

**FR-UXF-84** — 메뉴 키트(`UIKit.menu`)의 항목은 선택 필드 `key`(단축키 동작 이름, 예 `closeTab`)를 받는다. 값이 있고 그 동작에 지금
바인딩이 있으면 항목 오른쪽 끝에 작은 키캡(`.ui-menu-key`, 글자는 단축키 표시 함수와 같은 표기)이 선다. 바인딩이 없으면 아무것도 서지 않는다.
글자 크기는 `--fs-sm`, 색은 `--text-hint` 다.

**FR-UXF-85** — 키캡을 다는 자리: 칸 탭 메뉴(`renderer-pane-wire.js` — 새 탭·닫기·이름 바꾸기 등 단축키가 있는 항목), 사이드바 창 행 메뉴,
편집기 탭 메뉴. 단축키가 없는 항목은 그대로다.

> **구현 메모 (스펙·코드 어긋남, 2026-11-20)**: 코드에는 **사이드바 창 행 메뉴가 없다**(`sidebar-list.js` 에 `contextmenu` 가 없다).
> 편집기 탭은 따로 메뉴가 없고 칸 탭 메뉴(`renderer-pane-wire.js`)를 함께 쓴다. 그래서 키캡은 칸 탭 메뉴(`new`→`newTab`,
> `close`→`closeTab`)와 `+` 단추의 메뉴(`new`)에만 달렸고, 그것으로 편집기 탭도 덮인다. `이름 바꾸기`에는 단축키가 없어 키캡이 없다.
> 창 행 메뉴를 새로 만드는 일은 이 묶음의 범위가 아니다.

> 이전 동작: 메뉴에 단축키 표시가 없었다. / 이유: 진단 D18.

### 3.12 패널 탭의 아이콘과 라벨 (D-35)

> 상태: **스펙(2026-11-20, 6차 세션).** 7묶음 도중 사용자 지시로 먼저 한다.

**FR-UXF-98** — 두 패널(메인 패널 `#sb-tabs`, 작업 패널 `#agents-head` 의 탭 줄)의 펼친 탭은 **아이콘을 늘 보인다.** 탭 줄에
모든 탭의 라벨이 잘리지 않고 들어가면 탭 줄에 `labeled` 가 서고 라벨이 아이콘 옆에 선다. 하나라도 잘리면 라벨은 모두 숨고 이름은
툴팁이 말한다. "넓다" 의 기준은 고정 폭이 아니라 **실제로 들어가는가**다 — 라벨 길이가 로케일마다, 배지 수가 때마다 다르기 때문이다.
판정(`panelTabsFit`)은 탭 줄의 폭이 바뀔 때와 탭을 다시 그릴 때 한다. 판정은 라벨을 세운 상태에서 재므로 같은 폭에서는 늘 같은 답이다.

**FR-UXF-99** — 라벨이 서도 탭은 **같은 폭**(`flex:1 1 0`)이다 — 메인 패널의 배지는 고르지 않은 탭에만 서므로(FR-SBT-12) 내용 폭을
따르면 탭을 바꿀 때 줄이 출렁인다(FR-PCH-80 의 뜻). 그래서 "들어가는가" 는 탭마다 제 몫의 폭 안에서 잰다. 레일(접힌 패널)은 종전 그대로 아이콘만이다.
모바일 시트도 같은 규칙이다(화면이 넓으면 아이콘 + 라벨).
기본 폭에서의 결과(2026-11-20 실측, 사용자 확인): 메인 패널 200px 은 아이콘만(`저장소` 가 6px 모자람, 약 220px 부터 라벨), 작업 패널 260px 도 아이콘만(약 340px 부터).

> 이전 동작: 메인 패널은 넓으면 라벨만(아이콘 숨김), 머리 폭 180px 미만이면 아이콘만이었다(CHAT_WINDOW_SRS FR-CW-24).
> 작업 패널은 폭과 상관없이 아이콘만이었다(PEER_CHAT_SRS FR-PCH-80). / 이유: 사용자 지시 D-35.

#### 3.11.2 키바 구성과 매크로 (M4·O7, D-31)

**FR-UXF-93** — 키바 구성은 설정 키 `keybar`(객체, 서버 설정)다: `{order:[id…], off:[id…], macros:[{id,label,key,ctrl,alt,shift}…]}`.
기본 키는 고정 id 를 갖는다(`esc`·`tab`·`enter`·`ctrl`·`ctrlc`·`alt`·`up`·`down`·`left`·`right`·`pipe`·`tilde`·`slash`·`hyphen`·`home`·`end`·`pgup`·`pgdn`).
키바에 서는 순서는 다음으로 정한다(`keybarResolve`):
1. `⌨` 가 늘 맨 왼쪽이다. 구성 대상이 아니다
2. `order` 에 적힌 id 를 그 순서로 세우고, 적히지 않은 기본 키는 기본 순서대로, 적히지 않은 매크로는 만든 순서대로 끝에 붙는다
3. `off` 에 든 id 는 서지 않는다. 알 수 없는 id 는 버린다
4. 값이 없거나 객체가 아니면 지금 키바와 같다(기본 18개, 기본 순서)

**FR-UXF-94** — 매크로는 키 조합 하나다. `ctrl`·`alt`·`shift` 중 **하나 이상**이 켜져 있어야 한다. `key` 는
`a`–`z`·`0`–`9`·`space`·`esc`·`tab`·`enter`·`backspace`·`up`·`down`·`left`·`right`·`home`·`end`·`pgup`·`pgdn`·`[`·`]`·`\`·`/` 중 하나다.
보내는 바이트(`mkbComboBytes`, 순수 함수):

| key | 규칙 |
|---|---|
| 글자·숫자·`[ ] \ /`·`space` | Shift 면 글자를 대문자로. Ctrl 이면 `@`–`~`·`space`·`/` 를 제어 문자로(`code & 0x1f`, `space`→`0x00`, `/`→`0x1f`). Alt 면 앞에 `ESC` |
| `esc`·`enter`(`\r`)·`tab`(`\t`)·`backspace`(`0x7f`) | Shift+`tab` 은 `ESC [ Z`, Ctrl+`backspace` 는 `0x08`. 그 밖의 Ctrl·Shift 는 바이트를 바꾸지 않는다. Alt 면 앞에 `ESC` |
| `up`·`down`·`right`·`left`·`home`·`end` | 수식 값 `m = 1 + Shift(1) + Alt(2) + Ctrl(4)` 로 `ESC [ 1 ; m A/B/C/D/H/F` |
| `pgup`·`pgdn` | `ESC [ 5 ; m ~` · `ESC [ 6 ; m ~` |

누르면 키바의 Ctrl·Alt 상태를 읽지도 바꾸지도 않고 곧바로 보낸다(`^C` 와 같은 길, FR-MKB-10).
라벨의 기본값은 `^`(Ctrl)·`⌥`(Alt)·`⇧`(Shift) 다음에 키 표기(글자는 대문자, 방향은 `↑↓←→`)다 — 예 `^D`·`⌥B`·`^⇧↑`. 사용자가 고칠 수 있고 1~8자다.
길게 누르면 뜨는 이름은 `Macro: Ctrl+D` 꼴(영어)이다.

**FR-UXF-95** — 설정의 `터미널` 탭에 `모바일 키바` 구역이 선다(데스크톱에서도 고칠 수 있다). 행마다 키 라벨·이름·켜기 스위치·위·아래
단추가 있고, 매크로 행에는 지우기 단추가 더 있다. `⌨` 는 행이 없다. 아래에 매크로 추가 줄(Ctrl·Alt·Shift 체크, 키 선택, 라벨, `추가`)과
`기본값으로` 단추가 있다. `기본값으로` 는 순서와 켜기만 되돌리고 매크로는 남긴다. 구역의 변경은 **바로 적용되고 저장된다**(같은 탭의 스위치와
같은 규약) — 키바가 곧바로 다시 그려진다. 수식이 하나도 없으면 `추가` 는 비활성이다.

> 이전 동작: 키바는 코드에 고정된 18개(`MKB_KEYS`)였고 설정이 없었다. / 이유: 진단 M4·O7, D-31.

#### 3.11.3 서랍 단추 한 줄 (M10, D-32)

**FR-UXF-96** — 모바일 서랍 `창` 패널의 단추 줄(`#sb-panel-windows .sb-actions`)은 한 줄이다. 보이는 단추가 줄에 다 들어간다 — 넘치면 줄을 넘기지
않고 각 단추가 줄어 라벨을 말줄임한다. 단추 높이는 터치 하한(`--touch-min`)이다. 데스크톱은 바뀌지 않는다.
