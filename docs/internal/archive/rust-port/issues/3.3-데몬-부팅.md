  **`dm-daemon-boot` 공개 API**
  - `run(home: &str, version: &str, daemon_build: &str, handover_fd: i64)` — Go `boot.Run`. 안에서 tokio multi-thread 런타임을 만들고, 주 스레드가 accept 루프를 돈다. 종료 신호(platform `shutdown_signals`)를 받으면 edge·채팅을 닫고 `ps.close()` → 도구 저장 뒤 돌아온다. 기동 실패(runtime install, listen)는 Go 처럼 `process::exit(1)`. 7.x 의 `cmd/dongminal` 은 `d` 분기에서 `handover::parse_daemon_args` → `--handover-version` 이면 `handover::VERSION` 출력, 아니면 이 함수를 부르면 된다(`tests/daemon.rs` 의 `daemon_main` 이 그 모양이다).
  - `referenced_tools(&Path) -> HashSet<String>` — workspace.json 의 탭이 가리키는 도구 id(없음·해석 실패는 빈 집합, 로그 문구 Go 와 같음).
  - `start_edge(home, &PanedServer, &Arc<ToolManager>) -> Box<dyn FnOnce()+Send>` — 노드·노드 소켓·간선 계층·채팅·채팅 소켓·도우미 감시(30초, 연속 3번 실패에 키 비움)를 세우고 닫는 함수를 준다. tokio 런타임 안에서 부른다.
  - 내부: `sys.rs`(신호, `execve`(nix), `self_exe`=current_exe+gocompat `eval_symlinks`, euid, 인계 fd → File).

  **Go 와 다르게 한 결정**
  - `run` 이 자기 tokio 런타임을 만들고 끝에 `shutdown_background()` 한다(Go 의 main 이 돌아오면 goroutine 이 함께 끝나는 것과 같게).
  - 인계 fd 를 File 로 받는 자리(`sys::handover_file`)에 `unsafe`(fcntl F_GETFD 확인 + from_raw_fd)를 썼다 — fd 전달 코드라 AGENT_RULES 4절 범위로 보았다. 닫힌 fd 면 Go 가 읽을 때 내는 것과 같은 `인계 상태 읽기: read handover: bad file descriptor` 를 낸다.
  - 도우미 감시는 tokio interval(첫 틱 30초 뒤, 밀린 틱은 건너뜀 = Go Ticker)과 spawn_blocking 의 `info` 다.
  - 채팅 소켓 서버를 `ChatUser`(ipc trait)에 거는 어댑터 `ChatUserOf` 를 boot 에 두었다(chatsock 이 ipc 를 모르므로).
  - `edge::Listener::new` 는 Rust 에서만 실패할 수 있다(rustls 설정). 실패하면 `edge listener: <오류>` 를 남기고 노드 소켓 없이 간다(Go 에는 없는 경로).

  **남은 위험**
  - edge 리스너 닫기가 Rust 에서는 비동기다(edge·edgerelay crate 가 리스너 태스크에 알리고 태스크가 소켓을 놓는다). Go 는 `ln.Close()` 가 돌아오면 바로 닫혀 있다. 시험은 2초 안에 닫히기를 기다린다. 데몬 종료 경로에서는 곧 프로세스가 끝나 관측 차이가 없다.
  - boot 는 edgenode→rustls→ring 을 끌어와 windows·linux 교차 clippy 를 건너뛰었다(8.3). windows 분기(`listen_signal`=ctrl_c·ctrl_break, `exec`·`handover_file` 은 Unsupported)는 컴파일 검사를 받지 않았다.
  - 실제 프로세스 시험은 /tmp 짧은 경로, `/bin/zsh` 류 기본 셸, 프로세스 표에 기댄다. 시간 시한 20초.
  - windows `hostname` 은 cargo clippy 로 컴파일만 확인했고 실행 확인은 못 했다.
