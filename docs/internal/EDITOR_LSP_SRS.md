# SRS: 편집기의 코드 탐색 (LSP) — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

접수한 요구는 한 줄이다.

> **"editor 에서 코드 레퍼런스 이동같은 기능"**

지금 Editor 창의 편집기는 **글자만 안다.** 문법 색칠은 Monaco 의 정적 문법이고,
`needle` 이 함수인지 변수인지 어디서 정의됐는지는 아무도 모른다. 파일 내 찾기와
전체 grep 이 있지만 그것은 **글자 찾기**다 — 같은 이름의 다른 심볼을 가리지 못한다.

요구는 편집기가 **코드를 알게** 하는 것이다. 그 앎의 표준 공급원이 LSP 다.

### 1.2 범위 (Scope)

**포함**

| 묶음 | 내용 |
|---|---|
| **A** 확보 | 서버 실행 파일을 찾고, 없으면 사용자 기계의 패키지 매니저로 받는다 |
| **B** 수명 | 루트·언어마다 프로세스 하나. lazy 기동, idle 종료, 서버 종료 시 정리 |
| **C** 이동 | 정의로 이동 · 참조 찾기 · 뒤로 가기 |
| **D** 호버 | 심볼의 타입과 문서 |
| **E** 진단 | 에러·경고 밑줄 (서버가 밀어 주는 알림) |
| **F** 연동 | Monaco 의 provider 로 붙이는 클라이언트 쪽 |
| **G** 설치 UI | 파일을 열 때의 설치 제안과 설정창의 상태·경로 |
| **H** 경계 | 루트 가드·셸 미경유·자원 상한 |

**미포함:** §6 비목표. 특히 **자동완성은 이 작업에 없다** (§1.5 I-2).

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **LSP** | Language Server Protocol. 편집기와 언어 서버가 JSON-RPC 로 주고받는 규약 |
| **언어 서버** | `gopls`·`typescript-language-server`·`pyright-langserver` 같은 별도 프로세스 |
| **세션** | (루트, 언어) 한 쌍에 딸린 언어 서버 프로세스와 그 상태 |
| **전용 디렉터리** | `<홈>/lsp/`. 우리가 받은 서버가 사는 곳. 시스템을 오염시키지 않는다 |
| **진단** | 서버가 요청 없이 밀어 주는 에러·경고 목록 (`publishDiagnostics`) |
| **홈** | `$DONGMINAL_HOME`, 기본 `~/.dongminal` (`dmenv.DefaultHomeDir`) |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 편집기는 CDN 에서 오는 Monaco UMD 다

`file-editor.js` 는 `https://cdn.jsdelivr.net/npm/monaco-editor@0.56.0/min/vs` 를
AMD loader 로 받는다. 번들러가 없다.

그러므로 **`monaco-languageclient` 를 쓸 수 없다.** 그것과 `vscode-jsonrpc` 는 ESM·
번들러를 전제하며 UMD 전역 빌드를 내지 않는다. LSP 를 브라우저까지 그대로 프록시하는
표준 경로가 이 구조에서는 막혀 있다 — **서버가 LSP 를 말하고, 화면에는 우리 종단이
간다** (D-1).

### 2.2 외부 도구를 PATH 에서 찾는 선례가 있다

`handlers_fs_search.go:202`:

```go
func lookRipgrep() string {
	p, err := exec.LookPath("rg")
	if err != nil { return "" }
	return p
}
```

그리고 어느 구현으로 훑었는지를 **응답에 실어** 사용자가 결과 차이를 설명할 수 있게
한다 (FR-EGS-3). 언어 서버의 확보도 같은 모양이어야 한다.

### 2.3 셸을 거치지 않는 규약이 이미 있다

같은 파일의 `grepWithRipgrep` 주석: *"질의는 **인자로만** 넘어간다 (FR-EGS-9, D-4).
셸을 거치지 않으므로 질의에 든 메타문자가 명령이 되지 않는다."*

설치 명령은 **패키지 이름과 버전이 인자로 가는 자리**이므로 이 규약이 그대로 걸린다.

### 2.4 서버에서 화면으로 밀어 주는 길이 이미 있다

`/api/commands/sse` (`server.go:167`). RELOAD_CONTINUITY_SRS FR-RLC-20 이 그 위에
"서버의 인사"를 얹었다. **진단은 요청 없이 오는 것이므로 이 길이 필요하다** — 폴링으로
바꾸면 타이핑을 멈춘 뒤 밑줄이 늦게 서거나, 멈추지 않았는데도 계속 묻게 된다.

### 2.5 의존성은 인터페이스로 주입된다

`deps.go` 의 `Deps` 가 그 자리이며, `SandboxReaper` 주석이 이유를 적고 있다 —
*"인터페이스인 것은 방향 때문이다 — httpapi 는 컨테이너 런타임을 알지 않는다."*

**`httpapi` 는 LSP 도 알지 않아야 한다.** 프로세스·프로토콜은 도메인 패키지의 것이다.

### 2.6 홈과 그 아래 자리는 `dmenv` 가 정한다

`dmenv.EnvHome` / `dmenv.DefaultHomeDir`(`.dongminal`). 헬퍼가 `<홈>/bin` 에 서고
데이터가 `<홈>` 아래 산다. 전용 디렉터리는 그 규약을 따라 `<홈>/lsp/` 다.

### 2.7 루트 가드가 이미 있다

`fsRoot(w, raw)` 가 Editor 목록에 등록된 루트만 통과시킨다 (`handlers_fs.go`).
LSP 종단도 **새로 쓰지 않고 그것을 딛는다** — 가드가 두 벌이 되면 한쪽만 고쳐진다.

### 2.8 편집 중 내용은 서버에 없다

저장은 `POST /api/file/write` 이며, 그 전의 편집은 **브라우저 안에만** 있다. Monaco
모델이 진실이고 디스크는 낡았다.

언어 서버가 디스크만 본다면 **저장하지 않은 편집에서 정의로 이동이 어긋난다** — 방금
쓴 함수로 갈 수 없고, 지운 줄로 간다. 그래서 요청은 그 파일의 **현재 텍스트를 함께
싣는다** (D-3).

### 2.9 언어 서버는 독립 바이너리를 릴리스하지 않는다

| 서버 | 확보 경로 | 독립 바이너리 |
|---|---|---|
| `gopls` | `go install golang.org/x/tools/gopls@latest` | **없다** (GitHub 릴리스에 첨부물이 없다) |
| `typescript-language-server` | `npm i typescript-language-server typescript` | 없다 (npm 패키지) |
| `pyright-langserver` | `npm i pyright` | 없다 (npm 패키지) |

그러므로 I-4 의 "인터넷에서 받는다" 는 **사용자 기계의 패키지 매니저(go·npm)를
호출한다** 는 뜻이다. 우리가 tarball 을 내려받아 풀 수 있는 대상이 아니다.

이것이 뜻하는 바: **툴체인이 없는 기계에서는 설치가 불가능하며, 그 사실을 알려야
한다.** 조용히 실패하면 사용자는 우리 버그로 읽는다.

### 2.10 진단·호버·이동은 Monaco 가 이미 그릴 줄 안다

| 얻는 것 | Monaco 의 자리 |
|---|---|
| 정의로 이동 | `monaco.languages.registerDefinitionProvider` |
| 참조 찾기 | `registerReferenceProvider` (peek 목록까지 Monaco 가 그린다) |
| 호버 | `registerHoverProvider` |
| 진단 밑줄 | `monaco.editor.setModelMarkers(model, owner, markers)` |

**그러므로 우리가 만드는 것은 UI 가 아니라 그 provider 의 속이다** — 찾기 패널에서
검색기를 Monaco 에게 맡긴 것과 같은 판단이다 (EDITOR_FIND_PANEL_SRS D-2).

### 2.11 Monaco 의 peek 은 **다른 파일**에서 우리 탭 시스템을 모른다

§2.10 은 "정의로 이동·참조 찾기의 UI 를 Monaco 가 그릴 줄 안다" 였다. 절반만 맞다.

같은 파일 안의 이동은 Monaco 가 스스로 한다. 그러나 **다른 파일**로 가려면 그 모델을
편집기에 올려야 하고, Monaco 는 그 일을 `ICodeEditorService.openCodeEditor` 에게
시킨다. standalone(UMD) 빌드의 기본 구현은 **이미 그 편집기에 올라와 있는 모델만**
연다 — 우리 탭 시스템을 모르므로, 열려 있지 않은 파일의 정의로는 아무 일도 일어나지
않는다.

갈아 끼우는 길이 없지는 않다 (`monaco.editor.create` 의 override services). 그러나
그것은 **문서화되지 않은 내부 서비스에 의존하는 일**이고 Monaco 판이 오르면 깨진다.

그리고 그렇게 얻을 것이 우리에게는 이미 있다:

| 필요한 것 | 이미 있는 것 |
|---|---|
| 다른 파일을 탭으로 열고 그 줄로 가기 | `_edOpenFile(path, {line, col})` (FR-EQO-7 · FR-EGS-10) |
| 그 파일을 탐색기에서 보이게 하기 | `revealPath` (FR-EKB-6) |
| 자리 목록을 고르게 하기 | 찾기 패널의 껍데기 — 경로·줄·본문 한 줄씩, `↑↓`·`Enter` (FR-EGS-*) |

그래서 **정의 이동과 참조 목록은 우리가 처리한다** (D-8b). 호버는 다르다 — 그것은
같은 자리에 말풍선을 띄우는 일이므로 provider 가 맞다 (M3).

### 2.11c 그 기각 근거는 낡았다 — `registerEditorOpener` 는 **공개 API 다** (2026-09-11, U-1)

§2.11 은 "갈아 끼우려면 문서화되지 않은 내부 서비스(`ICodeEditorService`)에 의존해야
한다" 를 근거로 provider 경로를 기각했다. **그 문장은 지금의 Monaco 에 맞지 않는다.**

실측: 벤더링된 판(`web/vendor/monaco/vs/editor-*.js.gz`)에
**`monaco.editor.registerEditorOpener` 가 있다.** 이것은 override services 가 아니라
`monaco.editor` 표면의 공개 함수이며, "다른 파일로 가려 할 때 무엇을 할지" 를
우리가 정하는 자리다. 즉 §2.11 이 우려한 것(peek 이 우리 탭 시스템을 모른다)을
**문서화된 자리 하나로** 채울 수 있다.

그리고 사용자가 그것을 요구했다 (2026-09-11 증언):

> *"파일 연결이 전혀 안 되어 있다. import 한 객체를 커맨드클릭 해도 이동하지 않는다."*

**커맨드클릭은 지금까지 요구사항이 아니었다.** `D-10` 은 `F12` 를 기본 키로 두었고
`D-8b` 는 "키도 우리가 잡는다" 였다. 그러나 Cmd/Ctrl+클릭은 이 동작의 **관용**이며
(VS Code·IntelliJ·vscode.dev 가 같다), 관용을 따르지 않으면 사용자는 그 기능이
있는지를 알 방법이 없다 — `D-10` 이 `F12` 를 고른 것과 **정확히 같은 논리**다.

> **⚠ 앞선 조사 기록의 정정.** 6차 세션의 U-1 조사는 *"§2.10:159 가 정의로 이동을
> `registerDefinitionProvider` 로 규정했는데 등록이 한 자리도 없다 → 요구 미달"*
> 로 적었다. **틀렸다.** `:159` 는 §2.10 의 **조사 표**(Monaco 가 할 줄 아는 것의
> 목록)이고, 바로 다음 절 §2.11 과 `D-8b` 가 그 경로를 **의도적으로 기각**했다.
> 그러므로 이것은 "구현이 빠진 요구" 가 아니라 **새 요구이며 기각의 재검토**다.
> 이 저장소의 교훈 그대로다 — *"기각된 것이 정확히 무엇인지 읽어라."*

### 2.11b `refresh()` 의 `setValue` 가 방금 옮긴 커서를 앗아간다 (기존 결함)

`_edOpenFile` 은 이미 열려 있는 탭에도 좌표를 적용한다 — 주석이 그 뜻을 적고 있다:
*"이미 열려 있던 탭이어도 옮긴다 — 사용자가 고른 것은 파일이 아니라 그 줄이다"*
(FR-EGS-10).

그런데 순서가 이렇게 흐른다.

1. `addTab` 의 editor 분기가 이미 있는 탭에 `refresh()` 를 부른다 — **비동기** fetch 가
   시작된다
2. `revealLine(4, 3)` 이 커서를 그 줄로 옮긴다
3. fetch 가 끝나고 `refresh()` 가 `this._editor.setValue(content)` 를 부른다 —
   **`setValue` 는 커서를 1,1 로 되돌리고 undo 스택을 버린다**

관측으로 확정했다: `revealLine` 이 `4,3` 으로 불렸고(`has-editor`) 최종 위치는 `1,1`
이었다.

**이것은 이번 작업이 만든 결함이 아니다.** `editor-git-ux.spec.ts` 의 `V-EGS-10`
(검색 결과를 고르면 그 줄로 열린다)이 이 저장소에서 이미 실패하고 있었고, 그 원인이
이것이다 — 전체 검색으로 **이미 열어 둔** 파일을 고르면 그 줄로 가지 않는다.

고칠 자리는 `refresh()` 다: **내용이 같으면 `setValue` 를 하지 않는다.** 같은 내용을
다시 넣는 일은 화면에 아무것도 바꾸지 않으면서 커서와 undo 스택만 버린다.

### 2.12 앞선 작업이 편집기 안의 키를 capture 로 잡는다

EDITOR_FIND_PANEL_SRS FR-EFP-1 이 `el` 의 keydown 을 capture 로 옮겼다. 정의로
이동(`F12`)의 키가 그 판정을 지나므로, 새 키를 더할 자리는 이미 정해져 있다.

### 2.13 판(`?v=`)은 서버가 계산한다

`index.html` 은 `?v=__ASSETV__` 자리표시자만 적는다. 손으로 올릴 값이 없다.

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 묶음 A — 서버 확보 (FR-LSP-1~12)

- **FR-LSP-1** **서술자**가 있다: 식별자, 그것이 덮는 Monaco 언어 id 들, 대응 확장자,
  실행 파일 이름, 기동 인자, 설치 방법(패키지 매니저·패키지 이름). 서술자는 **한
  자리**에 산다.

  **단위가 언어가 아니라 서술자인 것이 규칙이다.** `typescript-language-server`
  하나가 TypeScript 와 JavaScript 를 함께 덮으므로, 언어를 단위로 삼으면 같은
  프로세스가 둘로 세어져 두 번 기동된다.
- **FR-LSP-2** 기본 서술자는 셋이다 — Go(`gopls`) · TypeScript·JavaScript
  (`typescript-language-server`) · Python(`pyright-langserver`) (I-3).
- **FR-LSP-3** 사용자는 **서술자를 설정으로 더하거나 덮을 수 있다** (I-3). 확장자와
  실행 명령을 짝지어 적는 표이며, 기본 셋도 그 표에서 덮인다.
- **FR-LSP-4** 실행 파일 탐색의 순서는 셋이다: ① 사용자가 설정에 적은 절대경로
  ② `PATH` ③ 전용 디렉터리(`<홈>/lsp/bin`). 먼저 찾은 것을 쓴다.
- **FR-LSP-4b** 설정이 적은 절대경로(FR-LSP-4 ①)는 **요청이 싣는다.** 설정 블롭은
  서버가 해석하지 않으므로(PAGE_TITLE_SRS §2.2) 서버가 그것을 읽을 자리가 없다 —
  화면이 자기 설정을 실어 보내고, 서버는 그 표로 탐색한다.
- **FR-LSP-5** 어느 경로에서 찾았는지는 **상태 조회에 실린다** (FR-EGS-3 의 `engine`
  과 같은 근거) — 사용자가 "왜 저 서버가 쓰이는가" 를 설명할 수 있어야 한다.
- **FR-LSP-6** 찾지 못하면 **설치할 수 있는지**를 함께 알린다: 그 언어의 패키지
  매니저(`go`·`npm`)가 PATH 에 있는가.
- **FR-LSP-7** 설치는 전용 디렉터리로 **격리된다.** `go install` 은 `GOBIN` 을,
  `npm` 은 `--prefix` 를 그 디렉터리로 받는다. **시스템·사용자 전역을 건드리지
  않으며**, 디렉터리를 지우면 원상복구된다.
- **FR-LSP-7b** 전용 디렉터리 **안의 자리는 도구마다 다르다** — `GOBIN` 은
  `<lsp>/bin/` 에 놓고 `npm --prefix` 는 `<lsp>/node_modules/.bin/` 에 놓는다.
  탐색(FR-LSP-4 ③)은 그 서술자의 설치 도구에 맞는 자리를 본다. 한 자리만 보면
  npm 으로 받은 서버를 우리가 받아 두고도 못 찾는다.
- **FR-LSP-8** 설치는 **사용자가 눌러야** 일어난다 (I-5). 서버가 스스로 네트워크를
  쓰거나 남의 기계에 파일을 쓰지 않는다.
- **FR-LSP-9** 설치 명령은 **셸을 거치지 않는다** (§2.3). 패키지 이름은 서술자에서
  오며 사용자 입력이 그 자리에 닿지 않는다.
- **FR-LSP-10** 설치의 진행과 결과(성공·실패 사유·`stderr` 요약)가 화면에 보인다.
  **조용히 실패하지 않는다** (§2.9).
- **FR-LSP-11** 패키지 매니저가 없으면 그 사실을 이름으로 알린다 — "go 가 없어
  gopls 를 받을 수 없습니다" 는 사용자가 다음에 할 일을 아는 문장이고, "설치
  실패" 는 아니다.
- **FR-LSP-12** 설치에는 시간 상한이 있다. 넘으면 중단하고 그 사실을 알린다.

### 3.2 묶음 B — 세션 수명 (FR-LSP-13~20)

- **FR-LSP-13** 세션은 **(루트, 서술자) 한 쌍마다 하나**다 (FR-LSP-1 의 단위).
  같은 루트의 `.go` 파일 여럿이 한 `gopls` 를 공유하고, `.ts` 와 `.js` 도 한
  `typescript-language-server` 를 공유한다.
- **FR-LSP-14** 세션은 **필요할 때 선다** (lazy). 파일을 열지 않은 언어의 서버는
  기동하지 않는다.
- **FR-LSP-15** 기동은 LSP 의 `initialize`·`initialized` 를 마쳐야 끝난다. 그 전에
  온 요청은 **기다린다** (버리지 않는다) — 파일을 열자마자 누른 `F12` 가 죽으면
  사용자는 기능이 없는 줄로 읽는다.
- **FR-LSP-16** 기동 실패는 그 세션에 **기억된다.** 매 요청마다 같은 실패를 되풀이해
  프로세스를 띄우지 않는다. 설정이나 설치가 바뀌면 그 기억은 지워진다.
- **FR-LSP-17** 일정 시간 쓰이지 않은 세션은 **정지한다.** 언어 서버는 큰 저장소에서
  수백 MB 를 쓴다.
- **FR-LSP-18** 서버가 내려갈 때 모든 세션을 정지한다 (FR-SBX-44 와 같은 근거).
- **FR-LSP-19** 세션 수에 상한이 있다. 넘으면 가장 오래 쓰이지 않은 것을 정지한다.
- **FR-LSP-20** 언어 서버의 죽음(크래시)은 **그 세션만** 무너뜨린다. 다음 요청이
  다시 세운다.

### 3.3 묶음 C — 정의·참조 (FR-LSP-21~28)

- **FR-LSP-21** `POST /api/lsp/definition` 은 (루트, 경로, 줄, 열)에 대한 정의의
  자리 목록을 돌려준다. 각 자리는 절대경로·줄·열이다.
- **FR-LSP-22** `POST /api/lsp/references` 는 같은 입력에 대한 참조 목록을 돌려준다.
  선언 자신을 포함할지는 요청이 정한다.
- **FR-LSP-23** 두 종단은 **그 파일의 현재 텍스트를 함께 받는다** (§2.8 / D-3).
  서버는 그것을 `didOpen`/`didChange` 로 언어 서버에 알린 뒤 묻는다.
- **FR-LSP-24** 두 종단은 `fsRoot` 가드를 딛는다 (§2.7). 루트 밖의 경로는 거절된다.
- **FR-LSP-25** 정의가 **하나면 그 자리로 옮긴다.** 여럿이면, 그리고 참조 목록은
  **이미 있는 찾기 패널의 껍데기**로 고르게 한다 (§2.11).

  ~~여럿이면 Monaco 가 고르게 한다 (peek) — 우리가 목록 UI 를 만들지 않는다.~~
  **개정됨** — 그 판단은 §2.11 을 알기 전의 것이다. peek 으로 **다른 파일**을 열려면
  문서화되지 않은 내부 서비스를 갈아 끼워야 하고, 우리는 이미 그 일을 하는 길과
  목록의 껍데기를 갖고 있다.
- **FR-LSP-26** 옮겨간 자리가 **다른 파일이면 그 파일을 탭으로 연다.** 열린 파일이면
  그 탭으로 옮긴다. 두 경우 모두 탐색기에서 그 파일이 보인다 (FR-EKB-6 을 딛는다).
- **FR-LSP-26b** 이미 열려 있는 탭으로 옮길 때도 **그 줄로 간다.** 그러려면 `refresh()`
  가 같은 내용을 다시 넣지 않아야 한다 (§2.11b) — 이 저장소에 이미 있던 결함이며
  `V-EGS-10` 이 그것을 잡고 있었다.
- **FR-LSP-27** **뒤로 가기**가 있다. 정의로 뛴 자리에서 돌아올 수 없으면 그 이동은
  길을 잃는 일이 된다.
- **FR-LSP-28** 서버가 답하지 못하면(세션 없음·시간 초과·빈 결과) **아무 일도 일어나지
  않는 것이 아니라** 그 사실이 보인다. 침묵은 고장과 구별되지 않는다.

### 3.4 묶음 D — 호버 (FR-LSP-29~31)

- **FR-LSP-29** `POST /api/lsp/hover` 는 그 자리 심볼의 타입·문서를 돌려준다.
- **FR-LSP-30** 호버는 **정의 이동과 같은 세션·같은 텍스트 동기화**를 쓴다. 두 벌로
  두면 한쪽만 낡는다.
- **FR-LSP-31** 호버는 **자주 발화한다.** 요청은 마우스가 멈춘 뒤에 나가고, 앞선
  요청은 취소된다.

### 3.5 묶음 E — 진단 (FR-LSP-32~37)

- **FR-LSP-32** 진단은 언어 서버가 요청 없이 밀어 주는 것이며, 우리도 화면에
  **밀어 준다** — SSE 를 쓴다 (§2.4).
- **FR-LSP-33** 진단은 파일 단위로 온다. 화면은 그 파일의 모델에
  `setModelMarkers` 로 얹는다 (§2.10).
- **FR-LSP-34** 진단의 owner 는 우리 것 하나다. 그래야 갱신이 앞선 것을 덮고
  **밑줄이 겹쳐 남지 않는다.**
- **FR-LSP-35** 탭을 닫으면 그 파일의 진단을 걷는다.
- **FR-LSP-36** 진단은 **켜고 끌 수 있다.** 큰 저장소에서 저장하지 않은 파일마다
  경고가 서는 것을 원하지 않는 사용자가 있다.
- **FR-LSP-37** 진단이 오지 않는 것과 진단이 없는 것은 다르다. 세션이 서지 않았으면
  그 사실이 보인다 (FR-LSP-28 과 같은 근거).

### 3.6 묶음 F — 클라이언트 연동 (FR-LSP-38~43)

- **FR-LSP-38** 붙이는 자리는 Monaco 의 provider 셋이다 (§2.10). 우리는 그 **속만**
  채운다.
- **FR-LSP-39** provider 는 **언어마다 한 번** 등록된다. 편집기를 여럿 세워도 등록이
  늘지 않는다.
- **FR-LSP-40** 정의 이동·참조 찾기의 키는 **설정에서 바꿀 수 있다** (FR-EKB-5 와 같은
  체계). 기본값은 `F12`·`Shift+F12`, 뒤로 가기는 `Mod+Alt+-` 다.

  **`F12` 를 기본으로 두는 대가가 있다** (D-10): 그것은 브라우저 개발자 도구의 키이며
  우리 키 차단의 예외 목록(`KEY_BLOCK_EXEMPT_BARE`)에 들어 있다. 편집기 안에서 그
  키는 이제 정의 이동이므로 **편집기에 포커스가 있는 동안 개발자 도구가 그 키로
  열리지 않는다.** 편집기 밖에서는 종전대로다.
- **FR-LSP-40b** 세 키는 **편집기가 선 탭에서만** 동작하며, 그렇지 않으면 삼키지
  않는다 (FR-EFP-13 과 같은 근거). 뒤로 갈 자리가 없을 때의 뒤로 가기도 삼키지
  않는다 — 삼키면 그 조합을 다른 데 쓸 수 없게 된다.
- **FR-LSP-41** 그 키의 판정은 편집기 안의 **capture 리스너**를 지난다 (§2.12).
- **FR-LSP-42** LSP 가 없는 언어의 파일에서는 그 키가 **아무것도 삼키지 않는다**
  (FR-EFP-13 과 같은 근거).
- **FR-LSP-43** 요청이 오래 걸리면 진행 중임이 보인다. 그리고 취소할 수 있다.

### 3.7 묶음 G — 설치 제안·설정 (FR-LSP-44~48)

- **FR-LSP-44** 언어 서버가 없는 파일을 **처음 열 때** 배너가 뜬다 (I-5): 무엇을
  설치하면 무엇이 되는지, 그리고 설치 버튼.
- **FR-LSP-44a** (2026-09-08 접수) 배너가 서면 그 자리를 이미 쓰고 있던 것들
  (찾기 줄 · 알림 줄)이 **배너가 실제로 먹은 높이만큼** 내려 앉는다. 고정값이 아니다.

  > **개정 (U-2, 2026-09-11).** 목록에서 **미리보기 손잡이가 빠졌다.** 그 손잡이는
  > 좌하단으로 내려가(`FR-DRB-3`) 배너와 자리를 다투지 않는다 — 내려 앉힐 이유가
  > 없어졌고, 그것을 위해 있던 표식(`fe-offered`)도 함께 걷었다. 배너가 두 줄로
  > 접혀도 좌하단은 그 아래이므로 V-LSP-23 의 뜻은 그대로 지켜진다.

  종전에는 `38px` 이 박혀 있었고, 그것은 **배너가 한 줄이라는 가정**이었다. 390px
  폭에서는 안내 문장이 두세 줄로 접혀 배너가 그보다 커지고, 그러면 손잡이는 배너
  아래가 아니라 배너 **안**에 놓인다 — 눌러도 배너가 클릭을 먹으므로 사용자에게는
  "미리보기가 동작하지 않는다" 로 보인다. CI 의 ubuntu 러너가 이것을 잡았다(그
  러너에는 markdown 서버가 없어 배너가 늘 선다).

  높이는 JS 가 재어 `--fe-offer-h` 로 넘긴다. 폭이 바뀌면 줄 수도 바뀌므로 한 번
  재는 것으로는 모자라고, 관측(`ResizeObserver`)을 배너와 **같은 수명**으로 둔다.

- **FR-LSP-45** 그 배너는 **닫을 수 있고, 닫으면 그 언어에 대해 다시 뜨지 않는다.**
  파일마다 뜨면 그것이 곧 고장이다.
- **FR-LSP-46** 설정에 **Editor ▸ 코드 탐색** 자리가 있다: 언어별 상태(있음·없음·
  경로·어디서 찾았는지), 설치 버튼, 진단 토글, 그리고 서술자 표(FR-LSP-3).
- **FR-LSP-47** 설정에서 지운 전용 디렉터리의 서버는 다시 "없음" 이 된다 — 상태는
  **캐시가 아니라 관측**이다.
- **FR-LSP-48** 설치 중에는 그 언어의 버튼이 다시 눌리지 않는다. **판정은 서버가
  한다** — 화면의 비활성만으로는 다른 탭·다른 기기에서 누른 두 번째 설치를 막지
  못한다. 그래서 "설치 중" 은 상태 조회에 실리고, 두 번째 요청은 거절된다.

### 3.8 묶음 H — 경계 (FR-LSP-49~53)

- **FR-LSP-49** 모든 종단이 `fsRoot` 가드를 딛는다 (§2.7).
- **FR-LSP-50** 언어 서버 프로세스는 **그 루트를 작업 디렉터리로** 받는다. 루트 밖을
  읽는 것을 우리가 막지는 못하지만(그것은 언어 서버의 일이다), 우리가 그 밖을
  가리키지도 않는다.
- **FR-LSP-51** 어떤 명령도 셸을 거치지 않는다 (§2.3).
- **FR-LSP-52** 요청에는 시간 상한이 있다. 언어 서버가 답하지 않아도 종단이 멎지
  않는다.
- **FR-LSP-53** 요청이 싣는 텍스트에 크기 상한이 있다. 넘으면 거절하고 그 사실을
  알린다.

### 3.9 묶음 I — 커맨드클릭으로 정의로 (FR-LSP-60~65) — **U-1, 2026-09-11 신설**

근거는 §2.11c 와 `D-8c` 다. 사용자 증언: *"import 한 객체를 커맨드클릭 해도
이동하지 않는다."*

- **FR-LSP-60** Cmd/Ctrl+클릭으로 **그 심볼의 정의로 이동한다.** 링크 밑줄도
  Monaco 가 그린다 — 누를 수 있다는 표시가 없으면 기능이 있는지 알 수 없다.
- **FR-LSP-61** 구현은 `monaco.languages.registerDefinitionProvider` 이며, 그
  속은 이미 있는 종단(`/api/lsp/definition`)이다. **새 종단도 새 상태도 만들지
  않는다.**
- **FR-LSP-62** 등록은 **언어마다 한 번**이고 언어 목록은 `/api/lsp/status` 의
  선언에서 온다 — 호버(`FR-LSP-39`)와 **같은 자리·같은 규약**이다. 표를 두 벌로
  두면 언어를 더할 때 한쪽만 고쳐진다.
- **FR-LSP-63** **다른 파일로 가는 일은 `monaco.editor.registerEditorOpener` 가
  받아 우리 탭 시스템으로 넘긴다** — `_edOpenFile(path,{line,col})`. 그것이 조상
  폴더 펼치기까지 한다 (`FR-EKB-6`). 같은 파일 안의 이동은 Monaco 에 맡긴다.
- **FR-LSP-64** 그 이동도 **뒤로 가기 스택에 쌓인다** (`FR-LSP-27`). 계기가
  둘이므로(키·클릭) 한쪽만 쌓으면 돌아올 수 있고 없고가 어떻게 뛰었는지에 따라
  갈린다.
- **FR-LSP-65** provider 가 답하지 못하면 **Monaco 의 관용대로** 조용하다(링크가
  서지 않는다). 알림 줄에 사유를 쓰는 것은 `F12` 경로의 것이며(`D-9`), 마우스가
  지나갈 때마다 뜨는 알림은 호버가 이미 기각한 것이다.
- **FR-LSP-67** Cmd/Ctrl+클릭의 **계기는 우리가 잡는다** (`onMouseUp`). 판정은
  `Mod` 규약 그대로 — Ctrl 과 Meta 중 **정확히 하나**이며(`helpers.js`), Alt·Shift
  가 섞이면 우리 것이 아니다. 드래그로 끝난 클릭(선택이 남은 경우)은 자리를 고른
  것이 아니므로 무시한다. 그 뒤는 `F12` 와 같은 경로다.
- **FR-LSP-66** provider 를 걸면 Monaco 의 **기본 키**(`F12`·`Alt+F12`·`Shift+F12`)도
  함께 살아난다. 그 키바인딩은 **편집기마다 죽인다** — 그러지 않으면 설정에서 키를
  바꿔도 옛 키가 계속 듣고, `FR-LSP-40`(키는 설정의 것)이 깨진다.

  > **기존 검사가 이것을 잡았다** — *"설정에서 바꾼 키로 정의 이동이 된다"* 가
  > provider 를 걸자마자 실패했다(옛 `F12` 가 여전히 이동했다). 관용을 하나 더하는
  > 일이 이미 있던 계약을 **다른 자리에서** 깨뜨린 것이며, 이 저장소가 U-15 에서
  > 배운 것과 같은 부류다.
  >
  > 그래서 계기를 가른다: **키는 우리 것 · 마우스 제스처는 Monaco 것.** 제스처는
  > 키바인딩이 아니므로 이 조치에 걸리지 않는다. `Alt+F12`(peek)는 **채택하지
  > 않는다** — 다른 파일의 peek 은 그 모델이 없어 빈 창이 되고, 우리에게는 목록
  > 껍데기가 이미 있다 (`FR-LSP-25`).

## 5. 확정 결정 (Decisions)

- **D-1 서버가 LSP 를 말하고, 화면에는 우리 종단이 간다.** 브라우저까지 LSP 를 그대로
  프록시하는 표준 경로(`monaco-languageclient`)는 번들러를 전제하며 우리는 CDN UMD 를
  쓴다 (§2.1). 종단을 우리가 정하면 요청·응답이 우리 가드(`fsRoot`)와 우리 상한을
  그대로 지난다.
- **D-2 요청·응답은 HTTP, 진단은 SSE.** 진단만 성질이 다르다 — 요청 없이 오기
  때문이다 (§2.4). 둘을 하나로 합치려 WebSocket 을 새로 열지 않는다: 이미 있는 두 길로
  덮인다.
- **D-3 요청이 현재 텍스트를 싣는다.** 저장 전 편집이 브라우저에만 있으므로(§2.8),
  디스크만 보는 서버는 방금 쓴 함수를 모른다. 대안은 저장을 강제하는 것이었으나,
  그것은 "정의를 보려면 저장하라" 가 되어 요구를 이루지 못한다.
- **D-4 프로세스·프로토콜은 도메인 패키지의 것이다.** `httpapi` 는 LSP 를 알지 않고
  인터페이스만 받는다 (§2.5).
- **D-5 서버 실행 파일을 배포물에 넣지 않는다.** 사용자가 명시한 제약이며(I-4), 애초에
  대상들이 독립 바이너리를 내지 않는다 (§2.9).
- **D-6 설치는 패키지 매니저 경유이며 전용 디렉터리로 격리된다.** `go install` 에
  `GOBIN`, `npm` 에 `--prefix` 를 준다 (FR-LSP-7). 전역에 쓰면 우리가 남의 기계를
  바꾸는 일이 되고, 되돌릴 방법도 우리 손에 없다.
- **D-7 자동완성은 넣지 않는다.** I-2 다. 타이핑마다 왕복이 나고 원거리 접속에서
  가장 먼저 무너지는 기능이며, 그 실패는 "편집기가 느리다" 로 보인다.
- **D-8 UI 는 Monaco 의 것을 쓴다 — 그것이 우리 탭 시스템을 알 필요가 없을 때만.**
  호버·진단이 그렇다 (§2.10): 말풍선과 밑줄은 같은 파일 안의 일이다.
- **D-8b 정의 이동과 참조 목록은 우리가 처리한다.** §2.11 — Monaco 의 peek 은 다른
  파일에서 우리 탭 시스템을 모르고, 갈아 끼우려면 문서화되지 않은 내부 서비스에
  의존해야 한다. 그리고 그렇게 얻을 것(파일 열기·조상 펼치기·목록 껍데기)을 우리는
  이미 갖고 있다. **키도 우리가 잡는다** — 이미 capture 리스너가 그 자리에 있다
  (§2.12).
- **D-8c (2026-09-11) 커맨드클릭을 위해 `D-8b` 를 절반 되돌린다.** `D-8b` 는
  provider 경로 전체를 기각했으나 그 근거(내부 서비스 의존)가 낡았다(§2.11c).
  이제 이렇게 가른다:

  | 계기 | 누가 그리나 | 왜 |
  |---|---|---|
  | Cmd/Ctrl+**클릭** | **우리** — `onMouseUp` → `_lspJump('def')` (`FR-LSP-67`) | 실측: 이 판의 Monaco 는 링크 제스처 기여가 서 있어도 **provider 를 묻지 않는다**(아래 상자) |
  | 우클릭 메뉴 · `revealDefinition` 명령 | **Monaco** — `registerDefinitionProvider` + `registerEditorOpener` | 그 경로는 provider 를 실제로 묻는다(검증 `V-LSP-60`). 다른 파일은 opener 가 우리 탭으로 되돌린다 |

  > **⚠ 실측이 절반을 되돌렸다 (2026-09-11).** 처음 설계는 "제스처도 Monaco 가
  > 그린다" 였다. 그런데 e2e 로 제스처를 그대로 재 보니 **정의 요청이 0건**이었다 —
  > `getContribution('editor.contrib.gotodefinitionatposition')` 은 참이고,
  > DOM 이벤트에 수정 키도 실려 있었다(`metaKey:true`, mousemove 3회). 그런데도
  > 묻지 않았다. 벤더링된 판의 기여가 우리 편집기 설정에서 어떤 조건을 만족하지
  > 못하는 것으로 보이나 **원인을 단정하지 않는다.**
  >
  > 그래서 제스처는 우리가 잡고 `F12` 와 **같은 경로**를 태운다. 얻는 것이 있다 —
  > 알림 줄의 사유·목록·뒤로 가기가 계기와 무관하게 하나다. 잃는 것은 링크 밑줄
  > 이며, 그것은 Monaco 의 기여가 살아나야 생긴다.
  | `F12` · `Shift+F12` | **우리** — `_lspJump` 그대로 | 알림 줄(사유)·목록 껍데기·뒤로 가기 스택이 이미 그 경로에 있다 (`D-9`) |

  **두 벌 구현이 아니다** — 같은 종단(`/api/lsp/definition`)의 두 계기다. 그리고
  뒤로 가기 스택은 **둘 다** 쌓는다(`FR-LSP-44`): 한쪽만 쌓으면 사용자가 어떻게
  뛰었는지에 따라 돌아올 수 있고 없고가 갈린다.

- **D-10 기본 키는 `F12` 다 — 개발자 도구를 포기하고서.** 그것이 이 동작의 관용이고
  (VS Code·IntelliJ·vscode.dev 가 같다), 관용을 버리면 사용자가 그 기능이 있는지를
  알 방법이 없다. 대가는 편집기 안에서 그 키로 개발자 도구가 열리지 않는 것이며,
  그 사실을 사용자 문서에 밝히고 설정에서 바꿀 수 있게 한다 (FR-LSP-40).
- **D-9 없음과 고장을 가른다.** LSP 는 "안 되는 경우" 가 많다 — 서버 없음, 툴체인
  없음, 기동 실패, 시간 초과, 결과 없음. 그 다섯이 모두 "아무 일도 안 일어남" 으로
  보이면 사용자는 전부 우리 버그로 읽는다 (FR-LSP-11·28·37).

## 6. 비목표 (Non-goals)

1. **자동완성** (D-7 / I-2).
2. 이름 바꾸기·코드 액션·서식 정리 — LSP 가 줄 수 있지만 이 요구의 대상이 아니다.

   않았다.
8. 자동완성이 아닌 것이라도 **타이핑마다 왕복하는** 어떤 기능도 넣지 않는다.
