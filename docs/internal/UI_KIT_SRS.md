## 1. 개요

### 1.1 목적

접수한 말은 셋이다.

> ⑤ **"전반적으로 아이콘들이 작아서 잘 안보인다.. 각 버튼을 꽉 채우도록한다."**
>
> ⑥ **"버튼, 탭 등 모든 ui 요소들 같은것 중복으로 되어있는거 찾아서 공통화하도록
> 리팩토링. 일종의 인터페이스 만들어서 재사용하도록한다."**
>
> ⑧ **"어느 핸들이든 크기조절 핸들을 잡고 움직일 때 해당 선 양쪽의 크기를
> 가시적으로, 실시간으로 보여주도록 한다."**

셋은 한 문서에 있다. ⑤와 ⑥이 **같은 자리**를 고치기 때문이다 — 아이콘을 키우려면
"이 버튼은 아이콘 버튼이다" 라는 구분이 있어야 하고, 그 구분은 ⑥이 세우는 종류
체계 없이는 11개 클래스에 열한 번 적히게 된다. ⑧이 여기 있는 이유는 그 표시가
**여섯 개 핸들에 같은 모양으로** 붙어야 하고, 그것이 곧 공통화이기 때문이다.

### 1.2 범위

**포함**
- 버튼·탭·모달/다이얼로그/확인창·드롭다운/컨텍스트 메뉴·입력기/토글/레인지/배지의
  공통 토큰·기본 클래스·생성 팩토리 (사용자 결정 D-2)
- 유니코드 문자 아이콘 → SVG 아이콘 전면 교체 (D-3)
- 아이콘 크기가 버튼 크기에서 파생하는 규칙
- 리사이즈 핸들 6종의 실시간 크기 표시

**비포함**
- 색 팔레트·테마 44종의 값 (`themes.js`) — 키트는 기존 CSS 변수를 딛는다
- 레이아웃 규약(사이드바 폭·분할 비율·슬롯) — 핸들이 **무엇을 바꾸는지**는 그대로다
- git 상태 문자(`M A D R C ? U`)·lane 그래프·diff 기호 — 아이콘이 아니라 **git 의
  어휘**다 (§6 비목표 #3)
- 터미널 안(xterm)의 어떤 것도

### 1.3 정의

| 용어 | 정의 |
|------|------|
| **키트(kit)** | 이 문서가 세우는 공통 토큰 + 기본 클래스 + 생성 팩토리의 총칭 |
| **종류(kind)** | 버튼이 무엇인가 — `default` · `icon` · `primary` · `danger` · `ghost` |
| **아이콘 버튼** | 내용이 아이콘 하나뿐인 버튼. 크기 규칙이 여기에만 붙는다 |
| **스프라이트** | 문서에 한 번 심는 `<svg><symbol>` 묶음. 쓰는 자리는 `<use>` 로 참조한다 |
| **핸들** | 잡고 끌어 두 영역의 크기를 바꾸는 요소 (6종, §2.7) |

## 2. 현재 상태 (조사로 확정한 사실)

### 2.1 버튼이 열한 종이다

| 클래스 | 정의 | 쓰는 곳 |
|---|---|---|
| `.tbtn` | `style.css:284` | 상단바 (`index.html`), `runs-panel.js`, `app-statusbar.js` |
| `.mtbtn` | `style.css:928` | 상단바 모바일 (`index.html`) |
| `.ds-toggle` | `style.css:836` | 설정 모달 (`index.html`) |
| `.preset-btn` | `style.css:773` | 프리셋 목록 |
| `.mkb-btn` | `style.css:994` | 모바일 키바 (`app-mobile.js`) |
| `.ed-head-btn` | `style-editor.css:112` | 편집기 머리 |
| `.git-remote-btn`·`.git-commit-btn`·`.git-files-mode` | `style-git.css:79` (**셋이 한 줄에 묶여 있다**) | git 패널 |
| `.git-init-btn` | `style-git.css:517` | git 없는 폴더 |
| `.git-undo-btn` | `style-git.css:367` | 되돌리기 알림 |

`style-git.css:79` 이 이미 셋을 한 줄에 묶었다는 사실이 이 문서의 논거다 — **같은
것을 같이 적으려는 시도가 이미 있었고, 파일 경계에서 멈췄다.**

### 2.2 탭이 다섯 종이다

`.pn-tab`(분할 칸) · `.sb-tab`(사이드바) · `.mtab`(설정 모달) · `.ed-side-tab`(편집기
사이드) · `.pv-tab`(미리보기). 활성 표시가 넷은 밑줄, 하나는 왼쪽 선이고, 배지는
`.sb-tab-badge` 한 곳에만 있다.

### 2.3 상자가 셋이다

`.modal-*`(설정) · `.confirm-*`(확인창) · `.gc-*`·`.git-dialog-*`(git 다이얼로그).
셋 다 오버레이 + 상자 + 머리 + 본문 + 버튼줄이며, 셋 다 자기 것을 따로 그린다.

### 2.4 메뉴는 하나뿐이지만 곧 둘이 된다

지금은 `.git-menu`(`style-git.css:590`) 하나다. 묶음 B의 요구 ⑨가 History 상단에
필터·옵션 드롭다운을 요구하므로, 이 문서가 규약을 세우지 않으면 그때 두 벌이 된다.

### 2.5 컨트롤은 설정 모달 안에만 산다

`.ds-row`·`.ds-text`·`.ds-num`·`.ds-toggle`·`.ds-switch`·`.ds-range`·`.sbs-select`.
`ds` 는 display settings 의 약자이고, 그래서 git·편집기 쪽 입력기는 이 생김새를
쓰지 못한 채 각자 그려졌다.

### 2.6 아이콘은 전부 유니코드 문자다

실측(`web/js`·`index.html`, vendor 제외):

```
●  23    ×  21    ↑  19    ↓  18    ✕   9    ‹ ›  7+7
★   6    ✓   4    ☰   4    ⟳   3    ▣   3    ↗   3    ↺   3    ⌨   3
⎇   2    −   2    ⧉   2    🔔  2    ↻   1    ⚙   1    ✏   1    ⌕   1    🔍  1
```

크기 규칙은 **한 자리에만** 있다 — `html.sb-collapsed … .sb-tab-icon{font-size:14px}`
(`style.css:230`). 나머지는 버튼의 상속 글자 크기(11~13px)를 그대로 받는다. 그래서
28px 버튼 안에 12px 글자가 앉아 있고, 그것이 접수한 "작아서 안 보인다" 다.

이모지 둘(🔔·🔍)은 **폰트가 색을 정한다** — 테마 색을 따르지 않는 유일한 아이콘이다.

### 2.7 핸들이 여섯이고 표시가 하나도 없다

| 핸들 | 구현 | 무엇을 바꾸나 |
|---|---|---|
| `#sb-handle` | `input-binding.js:45~81` | 사이드바 폭 (px, 100~400. 끝까지 끌면 접힘) |
| `#agents-handle` | `input-binding.js:15~21` | Agents 패널 폭 (px) |
| `.sh` | `renderer.js:779·784~806` | 분할 칸 비율 (%) |
| `.slot-handle` | `renderer.js:272`, `app-slots.js:575~600` | 슬롯 비율 (%) |
| `.ed-ex-handle` | `renderer.js:454·560~573` | 탐색기 폭 (px) |
| `.git-commit-resize` | `commit.js:62·85·207~212` | 커밋 입력 높이 (px) |

여섯이 각자 `mousedown`→`mousemove`→`mouseup` 을 쓰고, 여섯 중 어느 것도 끄는
동안 수치를 보이지 않는다. 사용자는 놓아 봐야 결과를 안다.

### 2.8 사용자 결정 (2026-09-08 인터뷰)

- **D-1** 문서는 셋으로 나눈다. 이 문서가 그중 형태를 맡는다.
- **D-2** 공통화는 **JS 팩토리까지** 간다. 대상은 버튼·탭 + 모달/다이얼로그/확인창
  + 드롭다운/컨텍스트 메뉴 + 입력기/토글/레인지/배지.
- **D-3** 아이콘은 **크기 토큰 규칙과 SVG 교체를 함께** 한다. 출처는 **Lucide(MIT)**
  이며 **모든 아이콘을 교체한다**.
- **D-4** 핸들의 표시는 **px + 터미널 칸일 때 cols×rows + 비율(%)** 이고, **세로로
  하나씩 순서대로** 쌓아 보인다 (가로로 늘어놓으면 좁은 핸들 옆에서 길어진다).

### 2.9 설계 결정

- **D-5 기존 클래스를 지우지 않는다.** 공통 클래스를 **함께** 붙인다 —
  `class="ui-btn ui-btn-icon tbtn"`. 근거는 `SidebarList` 가 `.sbl-*` 를 도입할 때
  세운 것과 같다(FR-BLP-6·7): e2e 131개와 CSS 캐스케이드가 기존 이름 위에 서 있고,
  그것을 갈아치우는 것은 리팩터가 아니라 파괴적 변경이다.
- **D-6 파일은 새로 만든다** — `web/style-kit.css` 와 `web/js/ui/ui-kit.js`.
  `style.css` 는 이미 1206줄이고 캐스케이드 순서가 곧 의미다(§아키텍처). 키트는
  **가장 먼저** 와야 기존 규칙이 그것을 덮을 수 있다: `<link>` 는 `xterm.css` 뒤,
  `style.css` **앞**이다.
- **D-7 아이콘 크기는 버튼 높이에서 파생한다.** `--ui-btn-h` 하나가 진실이고
  아이콘 변은 `calc(var(--ui-btn-h) * var(--ui-icon-ratio))` 다. 두 값을 따로 적으면
  버튼 높이를 바꿀 때 아이콘만 남는다.
- **D-8 SVG 는 스프라이트 하나다.** `<symbol id="i-close">…` 를 `index.html` 에
  한 번 심고 쓰는 자리는 `<use href="#i-close">` 다. 아이콘마다 인라인 마크업을
  넣으면 같은 경로 데이터가 파일 수십 곳에 복제된다. `fill:none; stroke:currentColor`
  이므로 44개 테마가 색을 그대로 준다.
- **D-9 팩토리는 DOM 을 만들 뿐 상태를 갖지 않는다.** `UIKit.button({...})` 는
  `HTMLButtonElement` 를 돌려주고 끝난다 — 어떤 레지스트리에도 등록하지 않는다.
  근거는 `reconcileList`(FR-RPT-3)다: 목록은 요소를 **다시 만들지 않는** 것이 규약인데
  팩토리가 상태를 들면 재사용된 요소와 팩토리의 기억이 어긋난다.
- **D-10 핸들 표시는 요소 하나를 재사용한다.** 끌 때마다 만들고 지우면 6종에
  같은 코드가 여섯 벌 생기고, 끄는 동안(초당 60회) DOM 을 만든다. 문서에 하나
  두고 위치·문구만 고친다 — `#focus-edge` 가 정적 마크업인 것과 같은 근거(FR-UFE-8).
- **D-11 핸들 표시를 낳는 것은 `UIKit.drag()` 다.** 여섯 곳의 `mousedown`→
  `mousemove`→`mouseup` 이 이미 같은 골격이므로, 표시를 붙일 자리도 하나다.
  각 자리가 주는 것은 **무엇이 바뀌는가**(축·양쪽 요소·단위)뿐이다.

### 4.2 아이콘 치수는 눈으로 보이지 않는다 (2026-09-08)

V-1 은 **e2e 로 구현된 적이 없었다.** 상단바를 옮길 때 실측으로 한 번 확인하고
지나갔고, 그 뒤 병기한 자리들은 아무도 재지 않았다. 실제로 위반이 둘 있었다:

| 자리 | 버튼 높이 | 아이콘 | 비율 | 왜 |
|---|---|---|---|---|
| `.ed-side-act` (git 뷰 탭 여섯) | 30px | 17.7px | **0.59** | `--git-hit`(30px)이 키트의 `--ui-btn-h`(26px)보다 크다 |
| `.modal-close` (설정 닫기) | 24px | 17.7px | **0.74** | 반대 방향 — 자기 치수가 26px보다 **작다** |

**둘 다 눈으로는 멀쩡하다.** 아이콘은 제대로 그려지고 조금 작거나 클 뿐이라,
자리마다 사람이 세는 방식으로는 잡히지 않는다. `ui-kit-icons.spec.ts` 가 **화면에
있는 아이콘 버튼 전부**를 돌아 재므로 새 표면을 옮길 때 그 자리가 자동으로 검사에
든다 (UIK5 는 같은 방식으로 이름 없는 아이콘 버튼을 찾는다 — FR-GLY-6).

고치는 방법은 하나다: **그 버튼의 실제 높이에서 다시 파생시킨다.** px 를 적지
않는 것이 요점이며(FR-GLY-5), `.modal-close` 는 높이와 아이콘이 같은 토큰을
딛도록 `--modal-close-h` 를 세웠다 — 한쪽만 고쳐지는 일이 없어야 한다.

## 4.1 ⑧ 의 구현이 남긴 자리 (2026-09-08)

검증은 `handle-size-hud.spec.ts` 아홉이다. **핸들 목록을 데이터로 두었다**
(`HANDLES`) — 새 핸들이 생기면 그 배열에 한 줄을 더하는 것으로 끝나고, 검사를
복사하지 않는다 (FR-HSZ-10 이 요구하는 "하나라도 예외면 깨진다" 를 구조로 지킨다).
목록에는 여섯 핸들과 **세로 축의 자리 하나**가 있다: 가로만 재면 `rows` 갈래가
검사를 벗어난다.

구현이 밝힌 것 넷:

- **시작 좌표는 골격의 것이다.** 여섯 자리가 저마다 `const sx=e.clientX` 를 다시
  적고 있었고, `sides` 도 그 값을 기준으로 변화량을 낸다. `UIKit.drag` 이
  `ctx.sx0`·`ctx.sy0` 를 채운다.
- **`C×R` 은 fit 전 값으로 계산할 수 없다.** `.xterm-screen` 은 fit 이 돌기
  전까지 옛 크기이므로(끄는 동안 fit 을 돌리지 않는다 — FR-HSZ-9), 그 크기에 그
  칸이 **얻거나 잃을 양**을 더해서 나눈다. 셀 크기 자체는 폭·높이와 무관해 지금
  값이 그대로 유효하다.
- **"이 영역이 터미널인가" 는 한 자리여야 한다** (`app._termIn`). 판정을 각
  핸들이 따로 하면 여섯 벌이 되고, `vis` 를 함께 보는 것을 한 곳이라도 빠뜨리면
  숨은 도구의 격자를 보이는 칸의 값으로 적는다.
- **분할 칸 핸들만 양쪽이 둘 다 터미널이다.** 나머지 다섯은 한쪽 또는 양쪽이
  터미널이 아니고, 그때 격자 줄이 붙지 않는 것을 `terms` 목록이 자리마다 잰다.

- **HIGH — 이전 중의 회귀.** 열한 종 버튼을 옮기는 동안 특이성이 뒤집혀 생김새가
  달라질 수 있다. 완화: D-5(병기)·FR-UIK-11(약한 규칙)·FR-UIK-29(표면 단위 이전과
  그때마다의 e2e).
- **MEDIUM — 아이콘 전면 교체의 폭.** 자리가 수십 곳이고 각각 `title` 을 요구한다
  (FR-GLY-6). 완화: 사상표(FR-GLY-4)를 먼저 확정하고 문자 인벤토리 스크립트로
  잔여를 기계 검사한다(V-4).
- **MEDIUM — 다른 세션과의 충돌.** 지금 git 쪽 파일 15개가 다른 세션에서 수정
  중이다(`app-git.js`·`panel-poll.js`·`gitapi/*` 등). git 표면의 이전은 그 작업이
  끝난 뒤에 손댄다 — §7 의 순서가 그 이유다.
- **LOW — Lucide 라이선스.** MIT 이며 고지를 스프라이트 머리에 남긴다(FR-GLY-3).

## 6. 비목표

1. 테마 팔레트·색 체계 변경. 키트는 색을 만들지 않는다.
2. 기존 클래스 이름의 제거·개명. 이 문서는 **더하기만** 한다.
3. git 상태 문자·lane 그래프·diff 기호·키바의 문자 키를 아이콘으로 바꾸는 것.
4. 레이아웃 규약(무엇이 어떤 단위로 저장되는가)의 변경. ⑧은 **보이기만** 한다.
5. 터미널(xterm) 내부의 폰트·크기.

## 7. 이전 순서 (FR-UIK-30 의 자리)

git 표면이 마지막인 것은 §5 의 충돌 위험 때문이다.

| 순서 | 표면 | 상태 |
|---|---|---|
| 1 | 키트 파일·토큰·스프라이트 신설 | **완료** — `web/style-kit.css`(10.1KB) · `web/js/ui/ui-kit.js` · 스프라이트 32종 |
| 2 | 상단바 (`.tbtn`·`.mtbtn`) | **완료** — 알림 배지·슬롯 ±·모바일 넷·검색 바 |
| 3 | 사이드바 탭·목록 | **완료** — `SidebarTabs.build` → `UIKit.tab`, 행의 `×` → 아이콘. **레일 목록은 묶음 B(FR-RAL)** |
| 4 | 설정 모달 | **완료** — 닫기·프리셋 셋·단축키 초기화·마운트 제거 + 크기 고정(FR-UIK-12·13) |
| 5 | 확인창·다이얼로그 | **완료** — 문자 아이콘이 **없던** 표면이다. 한 일은 `.ui-btn` 병기와 등급(`-primary`·`-danger`·`-sm`) 부여 |
| 6 | 편집기·탐색기 | **완료** — 찾기 바(`↑↓✕`) · 제안 닫기(`✕`) · dirty diff 미리보기 닫기(`✕`) |
| 7 | Runs·Agents 패널 | **완료** — Agents 머리의 `↻`·`✕`. Runs 패널에는 문자 아이콘이 없었다 |
| 8 | 모바일 키바 | **이전하지 않는다** (아래 개정) |
| 9 | git 패널 전체 | **완료** — 앞서 옮긴 fetch·pull·push·행 동작에 더해 **본문 뷰 진입점 여섯**(`⏲⎇≣›⧉⊞`)을 옮겼다. 그 여섯이 "git 패널 아이콘 완료" 에서 빠져 있었다 |
| 10 | 핸들 6종 → `UIKit.drag` + HUD | **완료** — §4.1 |

> **8 을 이전하지 않는 근거** (2026-09-08). FR-GLY-4 는 `⌨`→`keyboard`,
> `↑↓`→`arrow-up/down` 을 교체 대상에 넣었지만, 키바는 **문자 키의 판**이다.
> 열여덟 중 SVG 가 될 수 있는 것은 다섯(`⌨ ↑↓←→`)뿐이고 나머지 열셋
> (`Esc Tab Ctrl ^C Alt | ~ / - Home End PgUp PgDn`)은 글자다. 다섯만 바꾸면 한
> 판 안에 두 어휘가 섞인다. 그리고 접수한 말 "모든 버튼안에는 아이콘이 꽉 차야
> 한다" 의 대상은 **아이콘 버튼**이며, `Esc`·`Home` 은 아이콘이 아니라 레이블이라
> 꽉 차면 안 된다. FR-GLY-8 이 이미 "키바의 문자 키는 그대로 둔다" 는 예외를
> 인정했고, 이 판단은 그 예외를 같은 판의 나머지 다섯까지 넓힌 것이다.
> `.ui-btn` 병기도 하지 않는다 — 키바는 `--m-kb-h` 파생이라는 자기 치수 규약을
>갖고(TC-B2 가 그것을 잰다), 키트의 26px 높이가 그것을 흔든다.
> 키바 안이 아닌 모바일 드로어의 닫기(`✕`)는 이 예외 밖이므로 옮겼다.

### 7.1 git 패널의 아이콘 상수 — 소비 지점 (조사 완료)

문자 라벨을 아이콘 이름으로 바꾸고 소비 지점에서 `UIKit.icon()` 을 붙이면 된다.
**여섯 상수의 소비 지점이 일곱 줄뿐이다** — 표를 고치는 비용이 작다.

| 상수 | 값 | 소비 지점 |
|---|---|---|
| `GIT_REFRESH_LABEL` | `⟳` | `renderer.js:515` |
| `GIT_FILES_MODE_ICON` | `{tree:'⊟',flat:'☰'}` | `panel-changes.js:267` |
| `GIT_ACT_LABEL` | `{openFile:'↗',stage:'+',unstage:'−',discard:'↺',…}` | `panel-changes.js:257·522·591` |
| `GIT_BR_FAV_MARK` | `★` | `branches.js:278` |
| `GIT_BR_CURRENT_MARK` | `✓` | `branches.js:289` |
| `GIT_REMOTE_ICON` | `{fetch:'⤓',pull:'↓',push:'↑'}` | `panel-changes.js:117` |

`ours`·`theirs` 는 글자로 남는다 (FR-GLY-8: 어휘이지 아이콘이 아니다).
