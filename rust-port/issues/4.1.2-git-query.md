#### Go 와 다르게 한 내부 결정

- core 에 `rel_path_detail(p) -> Result<String, String>` 을 더했다(4.1.1 공개 API 추가). Go `RelPath(p, kind)` 는 kind 가 query 의 `ErrDiffPath` 라 core Kind 로 표현할 수 없다
- 파싱은 stdout 을 lossy UTF-8 로 읽는다. diff 본문(`DiffSide.body`)·`side_bytes`·`hunk_diff_id`(sha256)는 바이트 그대로다
- Go nil slice 는 `Vec` + `serialize_with = nil_if_empty`(비면 `null`)로 냈다 — append 로만 채우는 필드(Status 그룹, FileDiff.hunks, Hunk.lines). 늘 non-nil 인 필드는 `[]`
- `CommitDetail` 은 Go 임베드 순서를 맞추려고 직렬화를 손으로 썼다(serde flatten 은 gocompat 에서 키가 정렬된다 — 다른 이슈도 조심할 것)
- `os.ReadDir` 정렬·`fnv64a`·`UnixNano` 를 직접 구현(signature)
- gittest·testpath 는 4.1.1 과 같이 시험 안 임시 보조

#### 남은 위험

- 비 UTF-8 경로(status·log 의 경로)는 lossy 변환으로 바뀐다. Go 는 바이트를 그대로 git 에 되돌려 줄 수 있다
- 오류 문구 대조는 시험에 넣은 것(status·log·diff·blame·remote·branch 일부)만 했다
- preflight 실제 git 시험의 identity 분기는 전역 user.name 이 없는 환경(hermetic HOME)에서만 판정한다
