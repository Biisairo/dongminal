# SRS: 노드 역할의 데몬 이관 (Peer Daemon) — IEEE 29148

> **문서 상태**: 승인·구현중
> **남은 것**: 단계 2~5 (FR-PDM-2·10~53). 단계 1(FR-PDM-1 패키지 이동)은 끝났다.
> **입력**: 2026-11-17 대화. 사용자 결정은 다섯이다.
> - D-PDM-1 노드는 서버가 아니라 **데몬**이다. 연결의 주체도 데몬이다
> - D-PDM-2 서버는 **망이 통하게만** 한다. 들어오는 연결과 나가는 연결 모두 서버를 거치지만, 서버는 내용을 보지 않는다
> - D-PDM-3 일을 둘로 나눈다. 먼저 이 SRS 로 기존 peer 를 데몬으로 옮기고, 채팅은 `PEER_CHAT_SRS` 에서 그 위에 얹는다
> - D-PDM-4 이 SRS 는 **옮기기만 한다.** 사용자가 보는 동작은 바꾸지 않는다
> - D-PDM-5 디스크에 저장하는 내용을 늘리지 않는다

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

지금 peer 기능(`PEER_NETWORK_SRS`)은 웹서버 프로세스 안에 있다. 노드 신원, 짝 목록, 노드 포트, TLS, 프로토콜 명령을 모두 서버가 처리한다.

그런데 터미널과 에이전트는 데몬(`dongminald`)이 들고 있고, 서버는 업데이트할 때마다 다시 뜬다. 그래서 "이 노드에 무엇이 있는가"를 말하는 주체(서버)와 실제로 그것을 가진 주체(데몬)가 다르다. 다음 SRS(`PEER_CHAT_SRS`)의 채팅 상태는 세션과 수명이 같아야 하므로, 노드의 주체가 데몬이어야 한다.

이 SRS 는 노드 역할을 데몬으로 옮긴다. 서버에는 바이트를 잇는 통로와 화면만 남긴다.

### 1.2 범위 (Scope)

| 단계 | 묶음 | 내용 |
|---|---|---|
| 1 | M | peer 도메인 패키지를 공유 계층으로 옮긴다. 동작 변경 없음 |
| 2 | L | 서버의 바이트 통로(들어오는 연결 전달, 나가는 연결 대행)와 데몬의 노드 소켓 |
| 3 | N | 데몬이 신원·짝 목록·짝맞춤·TLS·프로토콜 명령을 처리한다 |
| 4 | U | 서버가 로컬 API·dmctl·화면 요청을 데몬에 넘기고, 데몬의 화면 요청(창 배치 등)을 처리한다 |
| 5 | X | 서버 쪽 옛 노드 코드 제거, 문서 |

**미포함:** §6 비목표.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|---|---|
| **노드** | 짝맺기와 프로토콜 명령의 주체. 데몬 모드에서는 데몬, 직접 모드에서는 서버 프로세스다 (D-PDM-11) |
| **노드 포트** | 다른 노드가 접속하는 TCP 포트. 기본 58147. 서버가 연다 |
| **노드 소켓** | 데몬이 여는 로컬 소켓 `node.sock`. 서버가 노드 포트로 받은 연결을 이 소켓으로 넘긴다 |
| **발신 소켓** | 서버가 여는 로컬 소켓 `dial.sock`. 데몬이 다른 노드에 연결할 때 서버에 TCP 연결을 부탁하는 자리다 |
| **바이트 통로** | 노드 포트 ↔ 노드 소켓, 발신 소켓 ↔ 원격 TCP 사이에서 바이트를 그대로 옮기는 서버의 기능. TLS 를 끝내지 않는다 |
| **화면 요청** | 데몬이 서버에 부탁하는 일. 창·탭 배치, 탭 닫기 방송, 창·탭 이름 조회 |

## 2. 현황 (Identified Issue)

### 2.1 노드 역할이 서버에 있다

| 구성 | 지금 자리 |
|---|---|
| 신원(`node-cert.pem`·`node-key.pem`), 짝 목록(`peers.json`) | `httpapi/peer_node.go:40-58` → `domain/peer/identity.go`·`config.go` |
| 노드 포트, TLS 1.3, 지문 판정(`Admission`) | `domain/peer/listener.go:88-178`, 판정 클로저 `peer_node.go:61-78` |
| 짝맞춤 상태, 속도 제한, 마지막 응답 시각 | `domain/peer/pairing.go`·`limit.go` |
| 프로토콜 명령 6개와 짝맞춤 경로 | `httpapi/peer_commands.go`·`peer_spawn.go`·`peer_node.go:143-222` |
| 발신 클라이언트(지문 고정) | `domain/peer/client.go:82-148`. `/api/peers/call`·`add`·`approve` 가 쓴다 |
| 원격 기동 기록 | `peer-spawns.json` (`domain/peer/spawnlog.go`) |
| 화면 갱신 | SSE `peers_changed` (`peer_api.go:89-98`) |

### 2.2 명령이 기대는 서버 전용 상태

| 명령 | 서버 전용 의존 |
|---|---|
| `agents.list` | 창·탭 이름(`WorkIndex.Entries`), 활동 상태(서버 `AttnTracker` 거울) |
| `message.send` | 주소 해석(`WorkIndex.ResolveStrict`) |
| `agent.spawn` | 창 배치(`Commands.BroadcastAndAwait("newWindow")`, `Focus`), 탭 배치(`restoreTool`·`renameTab` 방송, `awaitTab`), 첫 프롬프트 준비 신호(`activityChanged`) |
| `agent.status` | 활동 상태(서버 거울) |
| `agent.close` | `closeTab` 방송 |
| 짝맞춤 | `peers_changed` 방송 |

나머지(도구 목록·전경·busy·cwd·생성·삭제·붙여넣기, 에이전트 등록부)는 데몬에 이미 있다. 활동 상태도 ARD 이후 데몬의 `Tool` 이 들고 있다(`daemon/ipc/report.go:115-127`).

### 2.3 데몬의 제약

- 데몬은 서버 연결을 **하나씩** 받는다(IPC-24). 다른 클라이언트는 별도 소켓이 필요하다(보고 소켓 선례).
- 느린 요청은 `goSlow` 로 따로 돌려 다른 요청을 막지 않는다(`paned.go:170-183`).
- 데몬에는 TCP 리스너와 `crypto/tls` 사용이 없다.
- 데몬 코드를 바꾸면 적용할 때 데몬을 다시 띄워야 하고, 그때 모든 터미널 세션이 끊긴다.

## 3. 요구 (Requirements)

### 3.1 묶음 M — 패키지 이동

- **FR-PDM-1** `internal/webserver/domain/peer` 를 `internal/shared/peer` 로 옮긴다. 데몬과 서버가 함께 쓸 수 있어야 하기 때문이다. 동작과 시험은 그대로다.
- **FR-PDM-2** 서버 전용 의존이 없는 명령 로직(`peerGate`, `peerEnvelope`, `stripControl`, 명령 디스패치 표, 명령별 판정)을 `internal/shared/peernode` 로 옮긴다. 서버 전용 의존은 인터페이스(§3.4 화면 요청)로 받는다.

### 3.2 묶음 L — 바이트 통로

- **FR-PDM-10** 서버는 노드 설정의 `enabled`·`bind`·`port` 대로 노드 포트를 연다. 연결을 받으면 데몬의 노드 소켓에 연결하고, 출발지 주소 한 줄(프리앰블)을 보낸 뒤 양쪽 바이트를 그대로 잇는다. 서버는 TLS 를 끝내지 않고 내용을 읽지 않는다.
- **FR-PDM-11** 데몬은 노드 소켓 `node.sock` 을 홈에 연다. 권한은 소유자만이다. 연결을 여럿 동시에 받는다. 프리앰블의 출발지 주소는 짝맞춤에서 상대가 주소를 알리지 않았을 때 쓴다(PEER_NETWORK I-4).
- **FR-PDM-12** 서버는 발신 소켓 `dial.sock` 을 홈에 연다. 권한은 소유자만이다. 데몬이 `{addr, port}` 를 보내면 서버가 연결 시간 한도(FR-PNW-44, 5초) 안에 TCP 로 연결하고, 성공을 알린 뒤 양쪽 바이트를 그대로 잇는다. 실패하면 사유를 돌려주고 닫는다.
- **FR-PDM-13** 서버가 꺼져 있으면 노드 포트와 발신 소켓이 없다. 이때 다른 노드는 이 노드에 닿지 못하고, 데몬의 발신은 `peer_unreachable` 로 끝난다. 데몬의 짝 목록·짝맞춤 상태·기동 기록은 그대로 남는다.
- **FR-PDM-14** 노드 포트를 열지 못하면(포트 사용 중 등) 서버는 계속 동작하고, 그 사유를 데몬에 알린다. 데몬은 그 사유를 노드 상태에 실어 화면과 `dmctl peers` 에 보인다(FR-PNW-9).

### 3.3 묶음 N — 데몬의 노드 처리

- **FR-PDM-20** 데몬이 신원 파일과 `peers.json` 을 읽고 쓴다. 서버는 이 파일을 읽지도 쓰지도 않는다. 파일의 자리와 형식은 바꾸지 않는다.
- **FR-PDM-21** 데몬이 노드 소켓으로 들어온 연결의 TLS 를 끝내고, 지문 판정(`Admission`)·경로 판정·짝맞춤 경로·프로토콜 명령을 처리한다. 판정 규칙은 FR-PNW-5~7·24·41 그대로다.
- **FR-PDM-22** 데몬이 발신 클라이언트를 갖는다. 발신 소켓으로 얻은 연결 위에서 TLS 를 맺고 상대 지문을 고정한다(FR-PNW-22, 지금의 `client.go` 규칙).
- **FR-PDM-23** `agents.list`·`agent.status`·`agent.spawn` 의 첫 프롬프트 준비 판정은 **데몬 `Tool` 의 활동 상태**를 쓴다. 서버의 활동 거울을 쓰지 않는다. 값의 어휘는 바꾸지 않는다(I-14·I-21).
- **FR-PDM-24** `message.send` 의 `to`·`from` 은 도구 uuid 로 데몬의 도구 목록에서 찾는다. 좌표 라벨을 받지 않는 규칙(FR-IDU)과 오류 코드는 그대로다.
- **FR-PDM-25** 원격 기동 기록(도구 id → 짝 지문)은 **데몬 메모리**에 둔다. `peer-spawns.json` 은 쓰지 않는다. 데몬이 끝나면 그 도구들도 함께 끝나므로, 기록이 도구보다 오래 살 필요가 없다. 처음 시작할 때 남아 있는 `peer-spawns.json` 은 지운다.
- **FR-PDM-26** 감사 로그(`peer audit`, FR-PNW-94)는 데몬 로그에 남긴다. 항목과 "본문을 남기지 않는다" 규칙은 그대로다.
- **FR-PDM-27** 짝·초대·승인 대기가 바뀌면 데몬이 push `peers` 를 보낸다. 본문은 지금의 `peers_changed` 와 같다(`paired` 선택 인자 포함). 서버는 받은 그대로 SSE 로 방송한다.

### 3.4 묶음 U — 서버와 데몬 사이

서버 → 데몬

- **FR-PDM-30** 로컬 API(`/api/peers/*`, FR-PNW-70)와 그 응답 모양은 바꾸지 않는다. 서버는 요청을 새 IPC 메서드 `peer`(`{op, args}`)로 데몬에 넘기고, 데몬의 답을 그대로 돌려준다. `dmctl` 은 바꾸지 않는다.
- **FR-PDM-31** `peer` 메서드는 느린 요청으로 처리한다(`goSlow`). 원격 호출이 걸리는 동안 같은 연결의 입력·목록을 막지 않는다.
- **FR-PDM-32** `/api/peers/call` 의 `from`(호출한 도구)은 지금처럼 서버가 `DONGMINAL_TOOL_ID` 로 채워 넘긴다(FR-PNW-72).
- **FR-PDM-33** 서버가 데몬에 (다시) 붙으면 `peer` 의 조회(`get`)로 노드 상태를 받아 화면을 갱신한다.

데몬 → 서버 (화면 요청)

- **FR-PDM-40** 데몬은 화면 요청을 push `peerui` 로 보낸다. 본문은 `{id, kind, args}` 다. 서버는 처리한 결과를 IPC 메서드 `peeruidone`(`{id, result}`)로 돌려준다.
- **FR-PDM-41** 화면 요청의 종류는 넷이다.

  | kind | 하는 일 | 지금 코드 |
  |---|---|---|
  | `names` | 도구 uuid 목록의 창·탭 이름을 돌려준다 | `WorkIndex.Entries` |
  | `window` | 새 창을 만들고 그 첫 탭에 도구를 붙인다 | `newWindow` 방송, `Focus` |
  | `tab` | 기준 도구의 칸에 도구를 탭으로 붙이고 이름을 정한다 | `restoreTool`·`renameTab` 방송, `awaitTab` |
  | `closeTab` | 도구의 탭을 닫는다 | `closeTab` 방송 |

- **FR-PDM-42** 서버가 붙어 있지 않거나 시간 한도 안에 답하지 않으면 데몬은 다음처럼 처리한다. 모두 지금 "브라우저가 없을 때"의 동작과 같다.

  | kind | 답이 없을 때 |
  |---|---|
  | `names` | 이름을 비워 둔다 |
  | `window`·`tab` | 헤드리스로 두고 `headless:true` 를 돌려준다(FR-PNW-61) |
  | `closeTab` | 도구만 지운다. 서버가 다시 붙으면 도구 목록에 없는 탭을 지금의 재연결 처리로 정리한다 |

- **FR-PDM-43** 화면 요청의 시간 한도는 `agent.spawn` 이 보내는 쪽 요청 한도(15초, FR-PNW-44) 안에 답할 수 있게 정한다.

### 3.5 묶음 X — 호환과 정리

- **FR-PDM-50** 데몬은 `hello` 의 기능 목록에 `peer` 를 싣는다. 서버는 `peer` 를 말하는 데몬과만 노드 기능을 켠다.
- **FR-PDM-51** 데몬이 `peer` 를 말하지 않으면(옛 데몬) 서버는 노드 포트를 열지 않는다. 로컬 API 는 409 `peer_daemon_restart` 로 답하고, 화면과 `dmctl peers` 는 "데몬을 다시 시작해야 노드 기능을 쓸 수 있다"고 알린다. 서버가 노드 역할을 대신하지 않는다.
- **FR-PDM-52** 직접 모드(데몬 없음)에서는 서버 프로세스가 노드다. 같은 `peernode` 코드를 쓰고, 바이트 통로 대신 지금처럼 노드 포트를 직접 처리한다. 화면 요청은 함수 호출로 처리한다.
- **FR-PDM-53** 묶음 N·U 가 끝나면 서버의 옛 노드 코드(`httpapi/peer_node.go`·`peer_commands.go`·`peer_spawn.go` 의 노드 처리)를 지운다. 같은 판정을 두 곳에 두지 않는다(D-ARD-8 과 같은 근거).

### 3.6 비기능 (Non-functional)

- **NFR-PDM-1** `PEER_NETWORK_SRS` 의 시험이 모두 그대로 통과해야 한다. 시험이 서버 내부를 직접 부르던 곳은 같은 동작을 데몬 쪽에서 확인하도록 옮긴다.
- **NFR-PDM-2** 짝맞춤과 프로토콜은 한 머신에서 노드 둘(서로 다른 홈, 서버+데몬 한 쌍씩)로 검증한다(NFR-PNW-3 승계).
- **NFR-PDM-3** 새 외부 의존성을 들이지 않는다(NFR-PNW-2 승계).
- **NFR-PDM-4** 디스크에 새로 쓰는 파일은 소켓 둘(`node.sock`·`dial.sock`)뿐이다. `peer-spawns.json` 은 없어진다(D-PDM-5).
- **NFR-PDM-5** 데몬을 다시 띄워야 하는 단계는 커밋 메시지와 보고에 그 사실을 적는다(NFR-ARD-5 와 같다).

## 4. 결정 (Decisions)

| ID | 결정 | 이유 |
|---|---|---|
| D-PDM-1 | 노드는 데몬이다 | 사용자 결정 (2026-11-17). 터미널과 에이전트를 가진 것이 데몬이다 |
| D-PDM-2 | 서버는 바이트 통로다. TLS 는 데몬이 끝낸다 | 사용자 결정. 서버가 TLS 를 끝내고 지문을 데몬에 알리면, 그 알림을 꾸밀 수 있는 자리가 하나 더 생긴다 |
| D-PDM-3 | peer 이관과 채팅을 SRS 둘로 나눈다 | 사용자 결정. 옮기기와 기능 추가가 섞이면 문제의 원인을 가르기 어렵다 |
| D-PDM-4 | 사용자가 보는 동작은 바꾸지 않는다 | 사용자 결정. 예외는 §4.1 에 적는다 |
| D-PDM-5 | 디스크 저장을 늘리지 않는다 | 사용자 결정 |
| D-PDM-6 | 나가는 연결도 서버가 대행한다(`dial.sock`) | D-PDM-2 의 "연결도 서버를 통한다". 서버가 꺼져 있으면 노드는 들어오지도 나가지도 않는다는 한 규칙이 된다 |
| D-PDM-7 | 들어오는 연결은 데몬의 별도 소켓으로 받는다 | 서버 연결 소켓은 하나만 받는다(IPC-24). 원격 연결은 여럿이 동시에 온다 |
| D-PDM-8 | 활동 상태의 원천은 데몬 `Tool` 이다 | 데몬이 이미 갖고 있다(ARD). 서버 거울을 물으면 서버가 꺼졌을 때 답하지 못한다 |
| D-PDM-9 | 원격 기동 기록은 데몬 메모리에 둔다 | 기록과 도구의 수명이 같아졌다. 파일이 하나 줄어든다(D-PDM-5) |
| D-PDM-10 | 옛 데몬과는 노드 기능을 끈다. 서버가 대신하지 않는다 | 서버에 노드 코드를 남기면 같은 판정이 두 벌이 된다 |
| D-PDM-11 | 직접 모드에서는 서버 프로세스가 노드다 | 직접 모드에서는 서버가 곧 도구를 가진 프로세스다. 같은 `peernode` 코드를 쓴다 |
| D-PDM-12 | 화면 요청은 데몬 → 서버 push 와 응답 메서드로 한다 | 창·탭 배치는 화면만 할 수 있다. 서버가 없을 때는 지금의 "브라우저 없음" 동작으로 떨어진다 |

### 4.1 동작 변경 (D-PDM-4 의 예외)

| 항목 | 이전 | 새 동작 | 이유 |
|---|---|---|---|
| 감사 로그 자리 | `server.log` 의 `peer audit` 줄 | 데몬 로그의 같은 줄 | 프로토콜을 처리하는 프로세스가 데몬이다. 서버가 꺼져 있어도 남는다 |
| `peer-spawns.json` | 홈에 파일로 남는다 | 없다. 데몬 메모리에 둔다 | D-PDM-9 |
| 서버만 다시 뜰 때 | 노드도 함께 내려갔다 올라온다. 짝맞춤 대기(메모리)가 사라진다 | 노드 포트만 잠깐 닫힌다. 짝맞춤 대기·속도 제한·마지막 응답 시각이 그대로 남는다 | D-PDM-1 |
| 옛 데몬과 새 서버 | 노드 기능이 동작한다 | 데몬을 다시 시작할 때까지 노드 기능이 꺼진다 | D-PDM-10 |

## 6. 비목표 (Non-goals)

1. 채팅, 망 이웃, 사람 확인 도우미. `PEER_CHAT_SRS` 에서 다룬다 (D-PDM-3).
2. 프로토콜 명령·로컬 API·dmctl·화면의 동작 변경 (D-PDM-4).
3. 데몬을 다시 띄우지 않고 이 변경을 적용하는 방법.
4. 서버가 꺼져 있는 동안 원격 연결을 받는 방법(데몬이 노드 포트를 직접 여는 방식).

## 7. 위험 (Risks)

| 위험 | 등급 | 대응 |
|---|---|---|
| peer·채팅 코드를 고칠 때마다 데몬을 다시 띄워야 하고, 그때 모든 터미널 세션이 끊긴다 | MEDIUM | 사용자가 받아들인 대가(D-PDM-1). 단계마다 보고에 적는다(NFR-PDM-5) |
| 서버가 꺼져 있는 동안 노드에 닿을 수 없다 | LOW | D-PDM-2·6 의 결과. 데몬의 상태는 남으므로 서버가 돌아오면 바로 이어진다 |
| 서버 없이 데몬이 도구만 지운 탭이 화면에 남는다 | MEDIUM | 재연결 때 도구 목록에 없는 탭을 지우는 기존 처리로 정리되는지 시험한다(TC-PDM-8). 안 되면 멈추고 알린다 |
| 같은 사용자의 다른 프로세스가 `node.sock` 에 붙어 프리앰블의 출발지 주소를 꾸민다 | LOW | 프리앰블은 주소 기본값에만 쓴다. 신원 판정은 TLS 클라이언트 인증서로만 한다 |
| 같은 사용자의 다른 프로세스가 `dial.sock` 으로 임의 TCP 연결을 연다 | LOW | 그 프로세스가 스스로 열 수 있는 연결과 같다. 권한이 늘지 않는다 |
| 화면 요청이 걸리는 동안 `agent.spawn` 이 보내는 쪽 시간 한도를 넘는다 | LOW | FR-PDM-43 의 한도. 넘으면 헤드리스로 떨어진다 |
