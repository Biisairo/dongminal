### ERR_INVALID_HTTP_RESPONSE (V-24·V-OPL-1)

- **판정: 제품 결함이 아니다. Go·Rust 공통이고, e2e 하네스의 접속 주소 문제다.**
- **원인**:
  - 서버는 `127.0.0.1` 에만 바인드한다. 실측: Rust `127.0.0.1:61200`, Go 기준선(go1.27.2, `127ff7d9` 격리 빌드) `127.0.0.1:61201`.
  - e2e 는 `http://localhost:<port>` 로 붙고, 브라우저는 `localhost` 로 `::1` 을 고를 수 있다.
  - 그 포트의 `[::1]` 을 다른 프로세스가 쥐면 브라우저가 그쪽으로 간다. 그 프로세스가 HTTP 가 아닌 것(예: TLS)을 말하면 Chromium 은 `net::ERR_INVALID_HTTP_RESPONSE`, curl 은 `HTTP/0.9` 를 낸다.
  - 격리 서버 + `[::1]` 가짜 리스너로 같은 문구를 재현했다. 두 워커가 같은 순간 함께 무너진 것과 맞는다.
- **그 시각에 `[::1]:61000·61001` 을 쥔 프로세스는 특정하지 못했다**. 그때 다른 에이전트들이 시험을 돌리고 있었다. 참고로 같은 범위를 쓰는 시험이 있다:
  - `127.0.0.1` 직접 바인드: `httpapi/tests/telegram.rs`(61000+pid%2000 부터 훑음), `domain/ext/tests/wire.rs`(60147..61147), edge 계열 free_port(60147..64999 무작위).
  - std·tokio 의 `TcpListener::bind` 는 Unix 에서 SO_REUSEADDR 를 켠다. 다만 서버가 같은 `127.0.0.1` 을 쥐고 있으면 그 주소는 바인드할 수 없음을 실측으로 확인했다(Errno 48). 그래서 새는 길은 `::1` 쪽이다.
- **고침(e2e 만)**: `playwright.config.ts` 에 `E2E_HOST = '127.0.0.1'` 을 두고, 기본 baseURL·워커 픽스처의 ping·baseURL·edges-settings 의 상대 노드를 모두 이 상수로 붙인다. 남은 `localhost` 는 뷰어 URL 재작성 시험의 의도된 값과 진단의 Host 헤더뿐이다.
- **RED→GREEN**: 회귀 `e2e/harness-loopback.spec.ts`. 워커 포트의 `[::1]` 을 HTTP 가 아닌 리스너로 쥐고 `page.goto('/')` 를 부른다.
  - 고치기 전: `net::ERR_INVALID_HTTP_RESPONSE at http://localhost:61100/`
  - 고친 뒤: 통과
- **영향 확인**(Rust·Go 각각, 워커 2, `--retries=0`):
  - 주소·origin 에 매인 spec 과 원래 실패한 두 spec 14개 파일: Rust 77/77, Go 77/77.
  - 클립보드(보안 컨텍스트) spec 7개 파일, 모바일 터치 포함: Rust 74/74.
- **진단 수단(`abcd22f5`)**:
  - 워커 서버의 stdout·stderr 전부를 워커 홈의 `server.log` 에 쓴다.
  - 테스트가 실패하면 그 순간의 날 응답 첫 512바이트와 포트 소유(`lsof`)를 그 로그에 적는다.
  - `DM_E2E_KEEP_HOME=1` 이면 teardown 이 홈을 남긴다(데몬은 세운다).
  - 11.10 전량에서 흔들림이 나면 근거로 쓴다.
