# 3.4.2 서버 묶음 서빙 (D-29·D-33)

## 목표

- 묶음 정의 파일 한 자리(`web/bundles.json` 가칭): 묶음 이름 → 파일 목록(순서가 곧 로드 순서) → CSS 목록. `boot` 묶음 포함.
- 서버(`StaticAssets`)가 시작할 때 정의대로 이어 붙여 `/b/<name>.js` 로 낸다. 파일 사이에 `/* ==== js/… ==== */` 경계, ETag·gz, 판 해시에 정의 포함, 줄 오프셋 소스맵.
- index.html 은 vendor·head 인라인·언어 파일·`b/boot.js` 만 남긴다. `error-log.js` 는 맨 앞을 지킨다.
- `scripts/check-load-order.mjs` 가 index.html 대신 정의 파일을 읽는다. 하네스(`harness.mjs`)는 고치지 않는다.
- 설계: `perf/M3_DESIGN.md` §3.4, D-M3-1·5.

## 완료 조건

- RED(Rust 단위): 묶음 바이트 = 정의 순서대로 이은 파일 + 경계 줄. 정의에 없는 이름은 404. 묶음 안 파일 하나가 바뀌면 판이 바뀐다. gz 를 받는 클라이언트에 `Content-Encoding: gzip`.
- e2e: 부팅이 `b/boot.js` 를 싣고 첫 터미널이 뜬다(기존 부팅 스펙 한두 개).
- `check-load-order` 통과. 전체 시험 금지.
- 동작을 바꿨으면 이전 동작 / 새 동작 / 이유를 진행 기록과 커밋 메시지에 적는다.
