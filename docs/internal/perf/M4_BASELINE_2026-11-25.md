## 1. 시나리오

| 항목 | 값 |
|---|---|
| 창·탭 | 창 5개 × 탭 3개 = 15개. 보이는 에이전트 2개, 숨은 에이전트 6개 |
| 단계 | `idle` 60초 → `idle-git` 60초 → `idle-closed` 60초 (`--only idle,idle-git,idle-closed --phase-s 60 --idle-s 60`) |
| idle | 출력 없음, 셸 프롬프트 상태. 입력 지연을 잰다 |
| idle-git | Repo 창의 Git Changes 와 편집기 탭(파일 하나)을 보이게 둔다. 입력 지연을 재지 않는다 |
| idle-closed | 페이지를 닫는다. 서버·데몬 지표만 잰다 |
| 기본 3회 | 에이전트 탭의 전경이 셸이다 |
| `--idle-fg` 3회 | 유휴 단계 동안 에이전트 탭의 전경에서 `sleep 86400` 을 돌린다. 입력을 기다리는 에이전트를 흉내 낸다 |

명령(회마다 포트만 다르다):

```
node scripts/perf/scenario.mjs --port 60210 --bin ./otterminal-pf4.4 --windows 5 --tabs 3 \
  --phase-s 60 --idle-s 60 --only idle,idle-git,idle-closed --out run0.json [--idle-fg 'sleep 86400']
```

## 2. 측정 방법

- **외부 프로세스**: 격리 인스턴스의 PATH 앞에 감싸개를 둔다(`ps`·`lsof`·`pgrep`·`git`·`rg`). 감싸개는 호출될 때 `시각 PPID 이름 인자` 를 한 줄 적고 진짜 실행 파일로 넘긴다. 단계 구간 안에서 PPID 가 서버나 데몬인 줄만 센다.
- **CPU %**: `ps -o time=` 를 단계 처음과 끝에 읽고 그 차이를 벽시계 시간으로 나눈다. `ps` 의 시간 단위는 10ms 라서, 60초 구간의 값은 0.0167% 단위로 끊긴다.
- **깨어남**: `top -l 2 -s 30 -stats pid,cpu,idlew,csw` 두 표본의 차이를 쓴다.
  - IDLEW·CSW 는 누적값이다. 그래서 두 표본의 차이를 쓴다.
  - IDLEW 는 코어를 유휴 상태에서 깨운 횟수만 센다. 기계가 바쁘면 코어가 유휴 상태로 가지 않으므로 0에 가깝게 나온다. 이번 측정이 그랬다. 그래서 깨어남 비교에는 CSW(문맥 전환 수)를 주 지표로 쓴다.
  - 설계는 `-stats pid,cpu,idlew` 였다. 위 이유로 `csw` 열을 더했다.

## 5. 발견

1. **서버가 Git 창을 연 뒤 `git` 을 60초에 17번 띄운다.** 약 3.5초마다 한 번이다. 6회 모두 17번으로 같았다. 페이지를 닫은 뒤(`idle-closed`)에도 줄지 않았다. 설계 §0.3 의 gitwatch 동작과 맞는다. 목표는 0이다(4.9).
2. **데몬은 탭의 전경이 셸이 아닐 때만 `ps` 를 띄운다.** 전경이 셸이면 0번, `sleep` 이면 60초에 17~21번이다. 페이지를 닫아도 줄지 않았다. 설계 §0.1 의 "유휴에도 2초마다 ps" 는 전경 프로그램이 있을 때만 맞다. 목표는 0이다(4.6).
3. **`lsof`·`pgrep`·`rg` 는 한 번도 잡히지 않았다.**
4. **유휴 CPU 는 이미 목표(0.1% 이하) 안팎이다.** 서버는 `idle-git` 에서 평균 0.10% 로 목표 경계에 있다. 나머지 단계는 0.02~0.09% 다.
5. **서버·데몬은 아무 일이 없어도 초당 9~16번 문맥을 전환한다.** 페이지를 닫아도 거의 같다. 1초 주기 스위퍼·유휴 판정과 2초 전경 poll(설계 §0 항목 4)이 남아 있는 것과 맞는다. 4.5·4.8 뒤 4.14 에서 이 값이 줄어야 한다.
6. **브라우저 쪽 유휴 부하는 작다.** 요청 0건/분, WS 메시지 약 1.3건/초(idle), 메인 스레드 사용률 0.4% 이하다.
