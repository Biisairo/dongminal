# 인계 — UI/UX 남은 일 (6묶음부터) + 코드 리팩터링

> 넘긴 날: 2026-11-20. 넘긴 까닭: 맥락 사용률이 기준(60%)에 다가갔다. 같은 일을 이어 간다.

## 착수 블록 — 이번 세션의 지시 전부

처음 받은 사용자 지시(그대로, 여전히 유효): *"uiux 관련은 전부 진행. 추가로 코드레벨에서도 리팩토링 대상(중복제거, 함수분리, 상수화 등등)이 있으면 확인하여 전부 진행"*
이 세션에서 더한 사용자 지시: *"테스트는 최소한, 지금 수정 관련된거만 하고 커밋 후 남은 일 전체 하나씩 진행."* — **e2e 전량을 묶음마다 돌리지 않는다.** 관련 e2e 만 돌린다.

1. **6묶음을 구현한다.** 스펙은 이미 있다 — `UX_AUDIT_FIX_SRS.md` §3.10(FR-UXF-80~85, TC-UXF-80~84), 결정 D-29. **시험(RED)부터** 쓴다(5묶음·채팅 창은 구현을 먼저 해 RED 를 확인하지 못했다 — 되풀이하지 않는다)
2. 그 뒤 순서: 7묶음(모바일 M1·M4·O7·M10·O6·D9) → O3·O5(각자 새 SRS, 인터뷰부터) → 코드 리팩터링(조사 → 목록 문서 → 진행) → 문서·코드 어긋남(사용자가 고른다) → 받아들인 한계 목록을 다시 보이고 바꿀지 묻기
3. 묶음마다: 스펙(IEEE 29148, 갈림길은 먼저 묻는다) → 시험 RED → 구현 → `make gates`·`npm run -s unit`·`npm run -s typecheck`·관련 e2e → 화면 확인(스크린샷) → 문서 개정 → **커밋 메시지 미리보기를 보이고 사용자 확인 뒤 커밋**
4. **푸시는 하지 않았다.** main 은 origin 보다 **6커밋 앞서 있다**(`769a27c5` 4묶음 … `02aaee58` 채팅 창 + 이 인계 커밋). 푸시 전 e2e 전량을 돌릴지·언제 푸시할지는 사용자에게 묻는다 — 사용자는 e2e 전량을 "문서만 바꿨는데 왜 돌리냐"며 멈추게 했다(실은 4묶음 코드 검증이었다). 묻지 않고 전량을 시작하지 않는다
5. 결정이 필요한 갈림길은 **하나씩**, 선택지마다 **결과(무엇이 어떻게 보이고 바뀌는가)** 를 적어 묻는다. 화면 낱말이 섞이면 ASCII 미리보기(`preview`)를 붙인다 — 사용자가 O8 질문에 "뭘 말하는건지 모르겠어"라고 답했고, 미리보기로 다시 물어 풀렸다
6. 끝났다고 보고하기 전에 **스스로 점검한다**(diff 다시 읽기, 바뀐 값을 쓰는 다른 자리 추적, 화면 확인). 사용자가 "진짜 된거야? 더 할거없어?" 라고 물었다 — 남은 것을 정직하게 나눠 보고했다

## 4. 값을 치르고 배운 것 (이 세션)

- **패널의 자리는 언제든 바뀐다(사용자 지시).** 안내문에 `왼쪽`·`오른쪽` 같은 자리 말을 쓰지 않는다 — `CHAT_WINDOW_SRS` C-4. 두 패널은 `setPanelDock({left:[...],right:[...]})`(`DOCK_PANELS=['sidebar','activity']`)로 바뀐다 — 화면 확인 때 오른쪽 배치도 찍는다
- **창 종류 판정은 `isKindWin(s)`(Git·Repo·채팅) 하나다.** `isGitWin||isEditorWin` 두 개로 적힌 자리가 60곳이었다 — 새 자리는 `isKindWin`·`isChatWin` 을 쓴다. `plainWindows` 가 일반 창의 기준이다
- **빈 창의 안내 원소는 `LAYOUT_CLASSES`(`renderer.js`)에 이름이 있어야 거둬진다.** 없으면 칸이 생긴 뒤에도 안내가 본문 위에 남아 클릭을 먹는다(채팅 창에서 실제로 났다 — e2e 가 hover 를 못 해 잡혔다)
- **모바일에서 사이드바 탭의 `onActivate` 가 창을 바꾸면 `switchWindow` 가 서랍을 닫는다** — 목록을 보여야 하는 탭은 모바일에서 창을 바꾸지 않는다(채팅 탭)
- **ui/ 계층 파일은 App 의 `_` 이름에 닿지 못한다**(게이트 FR-FMB-40) — 필요하면 `_` 를 떼어 승격한다(`chatUnreadTotal`)
- **사이드바 탭 서술자는 `sidebar-tabs.js` 가 로드될 때 직행 키를 파생한다** — 새 탭 서술자는 그 파일 **앞**에 로드되는 파일에 두고 배열에 넣는다(`sidebar-tab-chat.js`). App 프로토타입 확장은 core 쪽 파일(앱 뒤 로드)에 둔다
- **모듈 크기 게이트**: 500 초과 파일 수와 **최대 줄(975, `app-layout.js`)** 이 기준선이다. `app-layout.js` 에 줄을 더하면 진다 — 주석을 같은 줄로 붙여 맞췄다. 새 모듈은 `index.html` 의 로드 순서 주석과 함께 넣는다
- **새 SRS 는 머리에 `> **문서 상태**: …` 와 `> **남은 것**: …` 두 줄이 있어야 게이트를 지난다.** 결정 표를 바꾸면 `go run ./scripts/gen-decisions`
- **스크롤 표면은 킷 클래스(`ui-scroll`)를 만드는 자리에서 단다**(게이트 FR-KIT-20)
- **임시 화면 시험(`e2e/zz-tmp-shot.spec.ts`)은 찍은 명령 안에서 바로 지운다** — 한 번 남겨 두어 게이트(TEST-16 고정 대기)가 졌다
- 단위 하네스: 가짜 원소에 `setAttribute`·`getAttribute` 를 더했다(`harness.mjs`). 가짜 `PrefStore.local` 에 `bool`·`setBool` 이 필요한 시험이 있다. `newEntityId` 는 `crypto.randomUUID` 대역이 있어야 돈다
- 컨테이너 쿼리 조건에는 변수를 쓸 수 없다 — 값(480px·180px)을 쓰고 스펙에 이유를 적었다
- 질문 글에 오타(`좁으면`→`좋으면`)가 있었다 — 고르기 전에 다시 읽는다
- V-LAY-1 은 다른 시험과 병렬로 돌면 한 번 실패하고 단독으로는 통과했다(`git:history` 행 키가 흔들림) — 실패하면 단독으로 먼저 가린다

## 5. 변하지 않는 규약

`UX_5_HANDOFF.md` 5절 그대로. 요약: 스펙 → RED → 구현 → 게이트·단위·타입·관련 e2e → 화면 → 문서 개정 → 확인 뒤 커밋. 동작이 바뀌면 SRS·주석·기존 시험에 이전/새/이유. 커밋 메시지에 AI 서명 금지. 툴팁·`aria-label` 은 영어, 보이는 글자는 로케일. 모서리 토큰 넷, 글자 `--fs-*`. `features.md`·`CHANGELOG [Unreleased]`·필요하면 `shortcuts.md` 를 함께 고친다.
