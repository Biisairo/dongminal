# SRS: 접속 허용 목록 (Access Allowlist) — IEEE 29148

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

`dongminal start --expose` 는 `0.0.0.0` 에 바인드하는 것이 전부다
(`internal/ctl/cli/start.go:40`, `options.go:44`). 그 뒤에 어떤 접근 제어도 없다.
그런데 이 서버가 여는 표면은 PTY 터미널·파일 읽기/쓰기/zip·명령 실행이다 —
**`--expose` 는 인증 없는 원격 코드 실행 종단을 네트워크에 여는 것과 같다.**

본 SRS 는 서버가 **출발지 기준 허용 목록**을 소유하고, 목록에 없는 출발지의 요청을
HTTP·WebSocket 을 통틀어 거절하게 한다. 목록과 그 적용 여부는 설정 화면에서
추가·제거·수정한다.

### 1.2 범위 (Scope)

**포함:**

| 묶음 | 내용 |
|---|---|
| S | 서버 소유 저장소 `access.json` — 적용 토글 + 항목 목록. 부팅 시 로드, 원자적 저장 |
| G | 요청 경로의 게이트 미들웨어. 정적 자산·`/api/*`·`/ws` 전부를 한 자리에서 덮는다 |
| N | 호스트명 항목의 **정방향** 해석기. 요청 경로 밖에서 주기적으로 돌며 IP 집합을 캐시한다 |
| E | 종단 `GET/PUT /api/access` 와 설정 화면의 편집 UI |

**미포함:** §5 비목표. 특히 **인증(토큰·비밀번호)·TLS·Host 헤더 검증은 본 SRS 가 하지
않는다.** 허용 목록은 "어느 기기"만 판정하며 "누구"는 판정하지 못한다.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|------|------|
| **출발지 (origin address)** | `http.Request.RemoteAddr` 에서 뽑은 IP. 프록시 헤더는 보지 않는다 (FR-ACL-6) |
| **항목 (entry)** | 허용 목록의 한 줄. IP 리터럴·CIDR·호스트명 중 하나와 이름표를 갖는다 |
| **적용 토글 (enforcement toggle)** | 목록을 실제로 적용할지의 단일 불리언. 끄면 게이트가 모두 통과시킨다 |
| **게이트 (gate)** | 출발지를 목록과 대조해 통과·거절을 판정하는 미들웨어 |
| **자기 주소 (self address)** | loopback(`127.0.0.0/8`·`::1`) + 이 서버 머신이 가진 모든 로컬 인터페이스 주소. 목록·토글과 무관하게 항상 통과한다 (FR-ACL-5) |
| **해석 캐시** | 호스트명 항목을 정방향 해석해 얻은 IP 집합. 게이트는 이것만 읽는다 |

## 2. 실측된 현황 (Current State)

### 2.1 미들웨어 체인에 게이트 자리가 이미 있다

```go
// server.go:200
return loggingMiddlewareFor(s, recoverMiddleware(mux))
```

정적 핸들러·`/ws`·`/api/*` 가 모두 이 `mux` 아래다. 한 겹만 끼우면 전 표면이 덮인다.
따로 핸들러마다 검사를 뿌릴 이유가 없고, 뿌리면 새 종단이 추가될 때마다 빠뜨린다.

### 2.2 `settings.json` 은 이 규칙을 담을 자리가 아니다

`handlers_settings.go:14` 의 규약은 명시적이다 — **"브라우저 설정은 서버가 해석하지 않는
JSON blob"**. 방송 페이로드에 본문을 싣지 않는 이유도 같다(같은 파일 :80). 접근 제어는
서버가 해석해야 하는 값이므로 그 blob 에 넣으면 규약을 깨뜨린다. 저장소를 분리한다.

### 2.3 출발지 이름은 요청에 실려 오지 않는다

요청이 가진 것은 IP 뿐이다. "특정 도메인만 허용" 을 판정하려면 이름과 IP 를 잇는 단계가
따로 있어야 한다. 역방향(PTR) 해석은 요청마다 DNS 왕복이 붙고 대개 레코드가 없거나
신뢰할 수 없다 — 본 SRS 는 **정방향** 해석만 쓴다(묶음 N).

### 2.4 이름 해석은 이 환경에서 실제로 동작한다 (실측)

Tailscale MagicDNS 가 켜진 macOS 에서 `net.LookupHost` 를 직접 돌린 결과다.
`CGO_ENABLED=0` (pure-Go resolver) 에서도 같았다 — tailscaled 가 `/etc/resolv.conf`
에도 MagicDNS 서버(`100.100.100.100`)와 search domain 을 써 두기 때문이다.

| 입력 | 결과 |
|---|---|
| `macmini` | `100.117.248.111` |
| `macmini.tail5da9ae.ts.net` | `100.117.248.111` |
| `macmini-office` | `100.89.214.106` |
| `macmini.local` | **실패** (`no such host`) |

두 가지가 따라 나온다: (i) MagicDNS 짧은 이름·FQDN 모두 묶음 N 으로 판정 가능하다,
(ii) mDNS 이름은 불가능하다 (FR-ACL-14a).

## 3. 요구사항 (Requirements)

### 3.1 묶음 S — 저장소

**FR-ACL-1.** 서버는 `<DataDir>/access.json` 을 소유한다. 모양은:

```json
{
  "enabled": false,
  "entries": [
    { "id": "<uuid>", "value": "100.101.102.103", "label": "macmini", "enabled": true }
  ]
}
```

**FR-ACL-2.** 파일이 없거나 읽지 못하면 `enabled=false`, 빈 목록으로 선다 — 즉
**읽기 실패가 서버를 잠그지 않는다.** 실패는 로그에 남긴다.

**FR-ACL-3.** 저장은 `platform.WriteFileAtomic` 으로 한다 (`handlers_settings.go:55` 와
같은 근거 — 사용자가 손으로 만든 값이고 잘리면 되돌릴 수 없다).

**FR-ACL-4.** 저장은 메모리 상태에 **즉시** 반영된다. 서버 재시작을 요구하지 않는다.

### 3.2 묶음 G — 게이트

**FR-ACL-5.** **자기 주소**에서 온 요청은 목록·토글과 무관하게 항상 통과한다. 오설정으로
자기 자신이 잠기는 일이 구조적으로 불가능해야 한다.

자기 주소는 loopback 만으로는 부족하다. 서버를 띄운 그 컴퓨터에서 브라우저가
`http://macmini-office:8080` 처럼 **자기 이름**으로 붙으면 출발지는 `127.0.0.1` 이
아니라 그 인터페이스의 주소(`100.89.214.106`)다 — loopback 예외에 걸리지 않아
"내 컴퓨터인데 내 서버에 막히는" 상태가 된다. 자기 이름으로 붙는 것은 흔한 습관이므로
(북마크·MagicDNS) 이 경우를 예외에 포함한다.

**이것이 목록을 약하게 만들지 않는다.** 출발지가 서버 자신의 주소인 TCP 연결은 자기
자신뿐이다. 남이 그 주소를 위조하면 응답 패킷이 위조된 주소(=서버 자신)로 가므로
핸드셰이크가 성립하지 않는다.

**FR-ACL-5a.** 로컬 인터페이스 주소 집합은 부팅 시 수집하고, 호스트명 해석과 같은
주기로 갱신한다 (인터페이스는 VPN 접속·네트워크 전환으로 바뀐다). 수집에 실패해도
loopback 예외는 남는다 — 최후의 탈출구가 사라지면 안 된다.

**FR-ACL-5b.** SSH 포트 포워딩(`ssh -L`)은 출발지가 서버 쪽 loopback 이므로 목록을
지나간다. 이는 의도된 성질이다 — 그 터널을 세울 수 있는 사람은 이미 셸 권한을 가졌고,
목록이 막을 수 있는 것이 아니다.

**FR-ACL-6.** 출발지는 `RemoteAddr` 에서만 뽑는다. `X-Forwarded-For`·`X-Real-IP` 등
클라이언트가 쓸 수 있는 헤더는 **신뢰하지 않는다.** 신뢰하면 목록이 헤더 한 줄로 무력화된다.

**FR-ACL-7.** 적용 토글이 꺼져 있으면 게이트는 모든 요청을 통과시킨다 — 현행 동작과 같다.

**FR-ACL-8.** 토글이 켜져 있고 출발지가 어느 활성 항목과도 맞지 않으면 `403` 으로 끊는다.
본문은 최소한으로 하고 목록 내용을 응답에 싣지 않는다.

**FR-ACL-9.** 토글이 켜져 있고 목록이 비어 있으면 **자기 주소만** 통과한다 (FR-ACL-5 의 귀결).

**FR-ACL-10.** 게이트는 `loggingMiddlewareFor` **안쪽**, `recoverMiddleware` **바깥쪽**에
선다. 로깅 안쪽이어야 거절이 접근 로그에 남는다.

**FR-ACL-11.** 게이트는 정적 자산·`/api/*`·`/ws` 를 구분하지 않는다. 예외 경로는 없다.

**FR-ACL-12.** 이미 수립된 WebSocket 연결은 목록 변경으로 끊지 않는다. 게이트는 **연결
수립 시점**에만 판정한다.

**FR-ACL-13.** 거절은 로그에 출발지와 경로를 남긴다. 목록이 켜졌는데 접속이 안 되는
상황에서 이유를 찾을 수 있는 유일한 근거다.

### 3.3 묶음 N — 항목 해석

**FR-ACL-14.** 항목 `value` 는 세 형태를 받는다:

| 형태 | 예 | 판정 |
|---|---|---|
| IP 리터럴 | `100.101.102.103`, `fd7a::1` | 출발지와 같은가 |
| CIDR | `192.168.0.0/24`, `100.64.0.0/10` | 출발지를 포함하는가 |
| 호스트명 | `macmini`, `macmini.tail5da9ae.ts.net` | 해석 캐시의 IP 집합에 출발지가 있는가 |

**FR-ACL-14a.** 호스트명은 **표준 DNS 로 풀리는 이름만** 지원한다. mDNS(`*.local`)는
지원하지 않는다 — Go 의 `net.LookupHost` 로 풀리지 않는다(§2.4 실측). 그런 값은
FR-ACL-16 에 따라 "해석 실패" 로 드러난다.

**FR-ACL-15.** 호스트명 해석은 **요청 경로에서 하지 않는다.** 부팅 시 1회, 이후 주기적으로
백그라운드에서 돌며 캐시를 갱신한다. 게이트는 캐시만 읽는다.

**FR-ACL-16.** 해석에 실패한 호스트명 항목은 아무 출발지와도 맞지 않는다(= 통과시키지
않는다). 실패는 로그와 `GET /api/access` 응답에 상태로 드러난다.

**FR-ACL-17.** `enabled=false` 인 항목은 판정에서 빠진다 — 지우지 않고 잠시 끌 수 있어야 한다.

**FR-ACL-18.** 형식이 유효하지 않은 `value` 는 저장 시점에 거절한다(`400`). 저장된 뒤에
조용히 무시되면 사용자는 규칙이 걸린 줄 안다.

### 3.4 묶음 E — 종단과 UI

**FR-ACL-19.** `GET /api/access` 는 현재 토글·항목·항목별 해석 상태를 돌려준다.

**FR-ACL-20.** `PUT /api/access` 는 토글과 목록 전체를 교체 저장한다. 저장 뒤 설정 변경
방송을 낸다 (`settingsChangedPayload` 와 같은 규약 — 본문 없이 "다시 받으라").

**FR-ACL-21.** 두 종단은 게이트 **뒤**에 있다. 즉 허용된 출발지는 목록을 고칠 수 있다.
근거: 허용된 기기는 이미 PTY 전권을 갖고 있어 `access.json` 을 직접 고칠 수 있다 —
종단만 막는 것은 실질 방어가 아니면서 원격 관리를 불가능하게 만든다.

**FR-ACL-22.** 설정 화면에 전용 탭을 둔다. 적용 토글 1개, 항목 목록(추가·제거·값 수정·
이름표·항목별 on/off), 저장 버튼.

**FR-ACL-23.** UI 는 화면을 열 때 **현재 접속 중인 출발지**를 보여준다. 무엇을 목록에
넣어야 하는지 사용자가 알 방법이 달리 없다.

**FR-ACL-24.** 저장하려는 목록이 **현재 자기 출발지를 통과시키지 못하면** UI 가 경고하고
확인을 받는다. 서버는 그 저장을 막지 않는다 — 서버 머신에서 언제나 되돌릴 수 있다(FR-ACL-5).

## 4. 검증 (Verification)

| 요구 | 검증 |
|---|---|
| FR-ACL-1·3 | 단위: 저장 후 재로드가 같은 값을 낸다. 원자적 쓰기 경로를 탄다 |
| FR-ACL-2 | 단위: 없는 파일·깨진 JSON → `enabled=false`, 빈 목록, 에러 없음 |
| FR-ACL-5 | 단위: 토글 on + 빈 목록에서 `127.0.0.1` **과** 가짜 로컬 인터페이스 주소가 모두 200 |
| FR-ACL-5a | 단위: 인터페이스 수집이 실패해도 `127.0.0.1` 이 200 |
| FR-ACL-6 | 단위: 목록에 없는 출발지가 `X-Forwarded-For: <허용 IP>` 를 붙여도 403 |
| FR-ACL-7 | 단위: 토글 off + 빈 목록에서 외부 출발지가 200 |
| FR-ACL-8·9 | 단위: 토글 on + 비허용 출발지 → 403, 본문에 목록 내용 없음 |
| FR-ACL-11 | 단위: `/`·`/api/state`·`/ws` 세 경로 모두 403 |
| FR-ACL-12 | 단위: 연결 수립 후 목록을 비워도 기존 연결이 살아 있다 |
| FR-ACL-14 | 단위: IP·CIDR·호스트명 각각의 매칭/비매칭 경계 |
| FR-ACL-15 | 단위: 게이트 판정 중 DNS 해석기가 호출되지 않는다(가짜 해석기 호출 수 0) |
| FR-ACL-16 | 단위: 해석 실패 항목이 어떤 출발지도 통과시키지 않는다 |
| FR-ACL-18 | 단위: `PUT` 에 `not an ip/cidr/host` → 400, 저장되지 않음 |
| FR-ACL-19·20 | 단위: GET→PUT→GET 왕복. PUT 뒤 방송 1회 |
| FR-ACL-22 | e2e: 항목 추가 → 저장 → 탭 재진입에서 값이 남는다 |
| FR-ACL-23 | e2e: `#acl-you` 가 채워진다 |
| FR-ACL-24 | e2e: 자기를 자르는 목록에 확인 대화가 뜨고, 취소하면 저장되지 않는다. 토글이 꺼져 있으면 확인 없이 저장된다 |

## 5. 비목표 (Non-goals)

1. **인증.** 토큰·비밀번호·사용자 개념을 만들지 않는다. 허용된 출발지 뒤의 사람이
   누구인지 서버는 모른다.
2. **TLS.** 평문 HTTP 그대로다. 같은 네트워크에서 트래픽은 읽힌다.
3. **Host 헤더 검증.** "어느 이름으로 들어왔는가" 는 클라이언트가 정하는 값이라 접근
   제어가 되지 않는다. DNS rebinding 방어가 필요해지면 별도 SRS 로 다룬다.
4. **역방향 DNS(PTR) 기반 판정.** §2.3.
5. **속도 제한·차단 이력·잠금.** 반복 거절을 세거나 막지 않는다.
6. **`--expose` 의 기본 동작 변경.** 토글 기본값은 꺼짐이며, 기존 사용자의 동작은 그대로다.
