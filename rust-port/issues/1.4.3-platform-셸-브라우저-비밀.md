# 1.4.3 platform 셸·브라우저·opener·비밀

## 목표

대화형 셸 선택과 훅 주입, 셸 인용, frameless 브라우저·일반 브라우저 명령 조립, macOS 키체인(security CLI) 비밀 저장소를 옮긴다. 공개 API 는 부모 이슈 1.4 의 진행 기록 "공개 API 안" 을 따른다. 바꿔야 하면 조정자에게 먼저 알린다.

## 대상 Go 코드

- `internal/shared/platform/shell.go`, `browser.go`, `opener.go`, `secrets.go` (약 680줄)

## 완료 조건

- 대상 Go 코드의 관측 동작을 Rust 가 동등하게 제공한다 (FR-RSP-1·3)
- 관측 동작을 검증하는 Go 테스트가 Rust 테스트로 옮겨져 통과한다 (V-RSP-1)
- `cargo fmt --check`, `cargo clippy -D warnings`, 격리 실행 `cargo test` 통과 (NFR-RSP-4)
- OS 의존 코드가 있으면 windows·linux 대상 `cargo check` 통과 (NFR-RSP-5)
- 작업 전후 `rust/scripts/prod-pids.sh` 출력이 같다 (V-RSP-5)
- 진행 기록에 공개 API 요약과 Go 와 다르게 한 내부 결정이 있다

  **공개 API** (1.4.2 가 고정한 trait 그대로, 구현만 채웠다)
  - `current().shell: &dyn ShellProvider` — unix 는 posix 셸(`$SHELL`→`/bin/bash`→`/bin/sh`, `-l`, LANG·LC_*·`SHELL_SESSIONS_DISABLE=1`·`SHELL=`; zsh 는 `ZDOTDIR=<bin>/zdotdir`, bash 는 `--rcfile <bin>/bash-hook.sh`; 상대경로 bin 은 훅 없음), windows 는 `DONGMINAL_SHELL`→pwsh.exe→powershell.exe→cmd.exe(PowerShell 이면 `-NoLogo -NoExit -ExecutionPolicy Bypass -Command ". '<bin>\powershell-hook.ps1'"`). `quote` 는 posix `'\''`, PowerShell `''`.
  - `current().browser.frameless_command(url)`, `current().opener.open_command(url)` → `io::Result<(name, args)>`. 실패 문구(`io::Error` Display)는 Go hint 와 바이트가 같다(리눅스만 실패할 수 있다).
  - `current().secrets` — macOS 는 `/usr/bin/security` 키체인(5초 기한, rc 44 = 없음, `security -i` 한 줄 4032 바이트 상한, hex 값), 그 밖은 `NoSecrets`. 오류 문구: `keychain read|write|delete: <Go 오류>`, `keychain read|write|delete failed (rc=N)`, `SecretsError::TooLong`, `SecretsError::Unavailable`.
  - crate 내부(`pub(crate)`): `shell::gopath::Conv::{Unix,Windows,HOST}` 의 `join/clean/base/is_abs/split_list`(Go `path/filepath` go1.27.2 그대로), `shell::lookpath::look_path`(Go `exec.LookPath`, unix·windows, ErrDot 규칙 포함). 1.4.4~1.4.6 이 Go `filepath.Join`·`LookPath` 가 필요하면 이것을 쓰면 된다.

  **옮긴 테스트**: Go shell·shell_bash·browser·opener·secrets 테스트 전부(관측 동작 검사) + Go `path/filepath` 의 Clean·Join·Base·IsAbs 표(unix·windows) + LookPath 규칙 + 실제 프로세스로 실행기 계약(cat·sh, security 는 부르지 않음). 이 이슈로 늘어난 테스트 약 75개, crate 전체 128개 통과.

  **Go 와 다르게 한 내부 결정**
  - Go `filepath.Join/Clean/Base`·`exec.LookPath` 는 Rust std 에 대응물이 없어 `shell/gopath.rs`·`shell/lookpath.rs` 로 그대로 옮겼다(lazybuf·postClean 모양까지). 원래 dm-gocompat 에 둘 성격이지만 "다른 이슈 crate 를 고치지 않는다" 규칙 때문에 platform 안에 `pub(crate)` 로 두었다. 조정자가 원하면 gocompat 로 옮길 수 있다.
  - unix `findExecutable` 의 `Eaccess` 를 `libc::faccessat(AT_EACCESS)` 로 불렀다(unsafe 1곳, SAFETY 주석). 그래서 `Cargo.toml` 의 `[target.'cfg(unix)'.dependencies]` 에 `libc` 를 더했다. **1.4.4·1.4.5 도 같은 줄을 더하면 병합 충돌이 날 수 있다**(같은 내용이면 하나만 남기면 된다).
  - 키체인 실행기의 5초 기한은 `try_wait` 폴링(5ms)으로 잰다. 기한이 지나면 kill 하고 Go 와 같은 `signal: killed` 문구를 낸다. 실행 실패는 `fork/exec <path>: <errno>`(gocompat oserr).
  - 키체인 값과 env 값은 `String` 이다(1.4.2 의 trait 모양). UTF-8 이 아닌 바이트는 lossy 로 바뀐다. Claude 자격증명은 JSON 이라 관측 차이는 없다고 본다.
  - windows LookPath 의 `os.SameFile` 은 1.4.2 의 `paths::file_id`(심볼릭 링크를 따라간다)를 쓴다. Go 는 Lstat 이다. 실행 파일이 심볼릭 링크이고 cwd 에도 있는 드문 경우만 갈린다.

  **남은 위험**: windows·linux 는 cargo clippy(check 포함)만 통과했고 실행 검증은 없다(셸·브라우저 선택 로직은 가짜 환경으로 호스트에서 검증됨).
