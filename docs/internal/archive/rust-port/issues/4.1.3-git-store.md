#### 공개 API (dm_webserver_domain_git_store)

- `Store::new(Arc<core::Service>, StoreOptions) -> Arc<Store>`. `StoreOptions::default().status_ttl(d).root(ctx).clock(Clock)` (`Clock = Arc<dyn Fn() -> SystemTime + Send + Sync>`)
- `Arc<Store>` 메서드: `status(&ctx, repo) -> (Result<Observation, query::Error>, bool /*캐시·합류*/)`, `repo_root`, `common_dir`, `signature`(async) / `invalidate`, `observed`, `forget_root`, `service() -> &Arc<Service>`, `root() -> &Ctx`
- `Observation { status, signature, observed_at_unix_ms }`(serde), `mark(&Observation) -> String`, 상수 `DEFAULT_STATUS_TTL`·`DEFAULT_REPO_ROOT_TTL`·`DEFAULT_GIT_DIRS_TTL`·`DEFAULT_OBSERVED_CAP`
- 오류는 모두 `query::Error`(core 오류는 `is_core(Kind)`). ctx 가 먼저 끝나면 `"git_canceled|git_timeout: <무엇> 를 기다리는 중: context …"`

#### 옮긴 시험: 15개 (store·cache·flight 시험 전부). `mark` 는 go1.27.2 실측 두 값과 바이트 대조(`1dyuxhts8py4v`, `11scdfklsagxi`)

#### Go 와 다르게 한 내부 결정

- Go 고루틴 flight 는 `tokio::spawn` + `Notify`/`OnceLock` 결과 칸. 호출자 ctx 가 끝나도 비행은 서버 수명(root ctx)으로 계속 돈다(Go 와 같다)
- repoState 포인터 동일성은 생성 때 받은 고유 번호(`id`)로, flight 동일성은 `Arc::ptr_eq` 로 판정
- 시각은 `SystemTime`(Go time.Time). 무효화의 "zero time" 은 `None`
- LRU 는 Vec(상한 64, 이동 O(n))
- edition 2024 예약어라 `gen` 대신 `generation`

#### 남은 위험

- 시계를 뒤로 돌리면(`now < at`) Go 는 음수 경과로 "신선"하다고 보고, Rust 는 0 으로 보아 역시 신선하다 — 같은 결과지만 정의가 다르다
- 4.1 전체(4.1.1~4.1.3) 완료. 4.2 jobs 가 쓸 core API(`Ctx`·`command`·`spawn`·`vanished_bin`·`record_unguarded`·`KILL_GRACE`·`JOB_CEILING`)는 4.1.1 진행 기록 참고
