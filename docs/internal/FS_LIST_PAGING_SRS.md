# SRS: 잘린 폴더의 나머지에 닿는 길 — IEEE 29148

> **문서 상태**: 초안
>
> 로드맵 §M6 (나) `FUI-10` 의 스펙이다. 요구 번호 접두어는 **`FR-FSP`**
> (FileSystem list Paging).

## 1. 개요 (Introduction)

### 1.1 목적 (Purpose)

감사 `12-func-ui.md` **FUI-10**:

> 잘린 폴더(10,000 초과)의 나머지에 닿는 길이 없다. `FR-EDT-65` 가 잘림
> **표기**는 정했지만 "더 보기"·필터·정렬 전환은 없어 **10,001번째 이후 파일은
> UI 로 열 수 없다** (터미널 `edit` 로만).

**지금은 사실만 말하고 끝난다.** `file-tree-paint.js` 가 `{t:'more'}` 행을
세워 *"잘림. N개 표시"* 를 보이는데, 그것은 사용자가 이미 짐작한 것이고 알고
싶은 것은 **나머지를 어떻게 보는가**다. 이 저장소가 `GIT_INIT_NOT_REPO` 에서
내린 것과 같은 판단이다 — *"사실만 말하고 끝내지 않는다"* (FR-RTU-25·26).

### 1.2 범위 (Scope)

| | 대상 |
|---|---|
| 서버 | `internal/webserver/httpapi/handlers_fs.go` — `fsListDir` · `apiFSList` |
| 클라 | `web/js/ui/file-tree-paint.js` — 적재·`more` 행 · `file-tree.js` 의 `_kids` |
| 문서 | `docs/external/api.md` (게이트가 강제) |
| 검사 | 서버 단위 · e2e |

**비포함** (§5):

- 행 안 필터·정렬 전환. 사용자 결정으로 **페이징을 골랐다** (2026-09-12).
- `fsListMax` 값의 변경. 한 요청의 상한은 그대로 10,000 이다.

### 1.3 정의 (Definitions)

| 용어 | 정의 |
|---|---|
| **쪽(page)** | 한 번의 `/api/fs/list` 가 돌려주는 최대 `fsListMax`(10,000)개의 이어진 구간 |
| **적재분(loaded)** | 그 폴더에 대해 클라가 지금까지 받은 쪽의 합. 언제나 **앞에서부터 이어진다** |
| **총수(total)** | 그 폴더의 항목 수. `os.ReadDir` 이 이미 전부 읽으므로 **세는 비용이 0** 이다 |

### 1.4 참고 (References)

- `FR-EDT-59`·`61`·`65` (`EDITOR_TAB_SRS`) — 한 겹 조회 · **서버가 정하는 순서** · 잘림 표기
- `NOTES_LIVE_EXPLORER_SRS` `FR-FSL-10` — 목록과 같은 관측의 `stamp`
- `docs/internal/production/12-func-ui.md` FUI-10 — 원본 감사

## 2. 전체 기술 (Overall Description)

### 2.1 왜 페이징이 성립하는가

**순서가 이미 서버의 것이기 때문이다.** `FR-EDT-61` 이 *"잘림의 경계가 요청마다
달라지지 않으려면 순서가 서버에서 결정돼야 한다"* 로 정렬(폴더 먼저, 이름
오름차순, 대소문자 무시)을 못박았고 `fsListDir` 이 그것을 지킨다.

그래서 `offset` 은 **뜻이 있는 좌표**다 — 같은 폴더에 대해 같은 `offset` 은
(그 사이에 파일이 생기거나 사라지지 않는 한) 같은 자리를 가리킨다.

### 2.2 제약 (Constraints)

| # | 제약 | 출처 |
|---|---|---|
| C-1 | 한 요청의 상한은 `fsListMax`(10,000) 그대로다. 응답 크기를 키우지 않는다 | `handlers_fs.go:55` |
| C-2 | 정렬을 클라가 다시 하지 않는다 — 하면 쪽의 경계가 흐트러진다 | `FR-EDT-61` · `file-tree-paint.js:29` 주석 |
| C-3 | 폴링이 같은 폴더를 다시 읽을 때 **적재분을 잃지 않는다**. 잃으면 폴링 한 번이 사용자의 "더 보기" 를 되돌린다 | `FR-FSL-10` |
| C-4 | API 표면을 더하면 `docs/external/api.md` 를 같은 변경에서 고친다 | `scripts/check-api-docs.sh` |

## 3. 상세 요구사항 (Specific Requirements)

### 3.1 서버

**FR-FSP-1** `GET /api/fs/list` 가 `offset` 질의를 받는다. 없으면 `0` 이다.
음수·정수 아님은 `0` 으로 떨어진다 — 손으로 고친 URL 하나가 오류 화면이 되지
않아야 한다 (`pollValue` 와 같은 규약).

**FR-FSP-2** 응답에 **`offset` 과 `total`** 이 실린다.

    { path, entries, offset, total, truncated, stamp }

`truncated` 의 뜻은 **바뀌지 않는다** — *"이 응답 뒤에 더 있다"* 이다. 다만 이제
그 기준이 `offset + len(entries) < total` 이다.

**FR-FSP-3** `offset` 이 `total` 이상이면 `entries` 는 **빈 배열**이고
`truncated` 는 거짓이다. 오류가 아니다 — 폴더가 줄어든 뒤의 요청이 그 꼴이고,
그때 사용자가 볼 것은 오류가 아니라 "더는 없다" 이다.

**FR-FSP-4** `total` 은 **정렬 전 전체 수**다. `os.ReadDir` 이 이미 전부
읽으므로 세는 비용이 없다 (§1.3).

**FR-FSP-5** `stamp` 는 그대로 **그 조회와 같은 관측**의 것이다 (`FR-FSL-10`).
쪽마다 달라질 수 있으므로 클라는 **마지막으로 받은 쪽의 stamp** 를 쓴다.

### 3.2 클라이언트

**FR-FSP-10** `_kids` 의 항목이 `total` 과 `loaded`(= `entries.length`)를
갖는다. `truncated` 는 그대로 둔다 — 그리는 쪽이 읽는 값이다.

**FR-FSP-11** 잘림 행(`{t:'more'}`)이 **누를 수 있는 것**이 된다. 문구는 사실
둘을 함께 말한다: **보이는 수와 전체 수**.

    10,000 / 37,412 — 더 보기

**FR-FSP-12** 누르면 `offset = loaded` 로 다음 쪽을 받아 **이어 붙인다.**
받는 동안 그 행이 진행을 보이고, 그 사이의 다시 누름은 무시된다 (요청이 두 벌로
나가면 같은 구간을 두 번 받는다).

**FR-FSP-13** 실패하면 그 행이 사유를 보이고 **적재분은 그대로다.** 다시 누를 수
있다. 조회 실패를 목록 전체의 실패로 바꾸지 않는다 (`EDITOR_TREE_ERR` 과 같은
규약).

**FR-FSP-14** **폴링·재조회는 적재분을 유지한다** (C-3). 그 폴더를 다시 읽을 때
클라는 **받아 둔 쪽 수만큼** 이어 요청한다. 첫 쪽만 받고 나머지를 버리면 폴링
한 번이 사용자의 "더 보기" 를 되돌린다.

**FR-FSP-15** 폴더를 **접으면 적재분을 버린다.** 다시 펴면 첫 쪽부터다 —
접는 것은 "이제 안 본다" 는 말이고, 그 상태를 무한히 들고 있을 이유가 없다.

**FR-FSP-16** 이름 변경·삭제·생성의 낙관적 반영은 **적재분 안에서만** 한다.
적재분 밖의 항목은 클라가 모르며, 아는 척하지 않는다.

### 3.3 비기능

**FR-FSP-20** 쪽을 더 받아도 **정렬을 다시 하지 않는다** (C-2). 서버가 준
순서대로 뒤에 잇는다.

**FR-FSP-21** `docs/external/api.md` 의 `/api/fs/list` 항목에 `offset` 과 새 응답
필드를 적는다 (C-4).

## 4. 검증 (Verification)

### 4.1 서버 단위 (`handlers_fs_test.go`)

| ID | 확인 |
|---|---|
| TC-FSP-1 | `offset` 없으면 0 쪽. `total` 이 실린다 |
| TC-FSP-2 | `offset=10000` 이 그 다음 구간을 준다 — 첫 쪽과 **겹치지 않고 빠뜨리지 않는다** |
| TC-FSP-3 | `offset >= total` 은 빈 배열 · `truncated:false` · **200** |
| TC-FSP-4 | 음수·정수 아님은 0 으로 떨어진다 |
| TC-FSP-5 | 쪽을 이어 붙이면 **한 번에 다 읽은 것과 순서까지 같다** |

### 4.2 e2e (`editor-explorer.spec.ts` 또는 신설)

| ID | 확인 |
|---|---|
| V-FSP-1 | 10,000 을 넘는 폴더에서 "보이는 수 / 전체 수" 가 보인다 |
| V-FSP-2 | 더 보기를 누르면 행이 늘고 그 행의 문구가 따라간다 |
| V-FSP-3 | 전부 받으면 그 행이 **사라진다** |
| V-FSP-4 | 더 보기 뒤 폴링이 한 번 돌아도 적재분이 줄지 않는다 (FR-FSP-14) |
| V-FSP-5 | 접었다 펴면 첫 쪽이다 (FR-FSP-15) |

## 5. 비목표 (Non-Goals)

| # | 하지 않는 것 | 사유 |
|---|---|---|
| N1 | 행 안 필터·정렬 전환 | 사용자가 페이징을 골랐다 (2026-09-12). 필터는 "이름을 아는 경우" 만 돕고, 이 요구는 **나머지에 닿는 길**이다 |
| N2 | `fsListMax` 값 변경 | 한 요청의 상한은 응답 크기의 보호막이다. 페이징은 그 상한을 없애는 것이 아니라 **넘어가는 길**을 내는 것이다 |
| N3 | 무한 스크롤 | 폴더 목록은 History 와 달리 **행 높이가 같고 접힘이 있다.** 스크롤 위치로 적재를 유발하면 접은 폴더가 그 판단을 흐린다. 누름이 명시적이고 싸다 |
| N4 | `offset` 의 안정성 보장 | 그 사이에 파일이 생기거나 사라지면 경계가 밀린다. 폴더 목록에서 그것은 **받아들이는 부정확**이다 — 다음 폴링이 바로잡는다 |
