  - **Go 와 다르게 한 내부 결정**
    - Engine 은 async(tokio)다. `busy` 는 tokio Mutex, 행·상태는 std Mutex(await 를 넘기지 않는다). Go ctx 는 회차의 틈(`pause`)에만 `CancellationToken` 으로 받는다. 나머지 취소는 future drop 이다. `switch` 의 전략 조회는 끊는 토큰 없이 돈다(호출부가 future 를 버리면 멈춘다).
    - `refresh` 는 실패 때 그때의 자격증명을 함께 준다(`Err((cred, err))`) — Go 의 `(cur, err)` 반환과 같은 뜻(AuthDeadFP 지문에 쓴다). 활성 갱신의 6초 시한은 tokio timeout 이고 문구는 `context deadline exceeded`.
    - 시험 이음매 `writeUsageFile`·`readStoreFile` 은 쓰기·읽기 횟수 카운터(`Engine::writes`·`Store::reads`)다.
    - `Run` 의 남은 시간은 Go 처럼 실제 시계(`OffsetDateTime::now_utc`)로 잰다. 음수는 0 이고 하한 1초가 덮는다.
    - AccountView 는 Account 임베드를 같은 순서의 와이어 구조체로 직접 직렬화한다. WindowView·ScopedWindowView 는 필드를 펼쳤다. `PaceView.scoped` 는 BTreeMap(Go map 의 JSON 도 키 정렬이라 같다).
    - `Credential::expired` 는 ms 값을 받는다(시계는 OffsetDateTime).
  - **남은 위험**: 디렉터리 락(최대 9초 대기)·파일 락·키체인 호출이 async 안에서 블로킹이다(Go 와 같은 구조, MEDIUM — 운영 런타임은 멀티스레드여야 한다. 5.5 httpapi 가 이 전제를 지켜야 한다). 실제 Anthropic 응답과의 호환은 가짜 API 로만 봤다.
