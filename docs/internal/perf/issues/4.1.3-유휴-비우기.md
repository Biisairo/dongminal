- 바꾼 것: toolhub `Tool` 의 `Cmu` 에 `fed_at`·`dirty` 를 두고, 넣기·크기 바꾸기·`adopt_screen` 이 잠금 안에서 적는다(`touch`). dirty 가 거짓→참일 때만 등록부의 `Notify` 를 깨운다. 등록부는 `create`·`restore`·`adopt`·`adopt_handover` 에서 깨우개를 건다(`enroll`). 이미 바뀐 화면은 거는 순간 깨운다. 그래서 인계 받은 도구는 dirty 로 시작한다. `ToolManager::spawn_screen_compactor` 는 가장 이른 `fed_at + 유휴 시간` 까지 자고, dirty 도구가 없으면 `notified()` 만 기다린다. 깨면 잠금 안에서 다시 확인하고 `spawn_blocking` 안에서 `Screen::compact` 를 부른다. `daemon/boot` 가 1초 sweeper 와 따로 띄운다. 유휴 시간은 `termlimit::SCREEN_IDLE_COMPACT`, 검사용 덮어쓰기는 `OTTERMINAL_SCREEN_IDLE_COMPACT_MS`(`otterenv/src/names.rs`, getting-started 환경변수 표에 한 줄 — `check-env-docs` 게이트). 비울 때 debug 로그 `[tool <id>] 유휴 기록 비움`.

- 측정(NFR-PRF-10, D-55·D-57): 판정은 **충족**이다. 격리 인스턴스, 탭 16개, 숨은 120×40 탭 12개에 25,000줄을 채운 뒤 agent-sim 60줄/초, footprint 30초 표본. 유휴 시간은 환경변수로 60초로 당겼다. 터미널당 (footprint − 기준) ÷ 12 는 다음과 같다. 출력 중: 짧은 줄 5.09 MB, 코드 120자 6.53 MB. 비운 뒤: 4.03·5.56 MB. 크기 바꾼 뒤(165×47): 2.26·3.77 MB. 5만 줄(참고) 출력 중: 6.07·8.67 MB. 살아 있는 힙은 출력 중 4.61·5.35 MB, 비운 뒤 1.52·2.27 MB 다. 비교 표와 방법은 SRS §7.4 에 있다. 4.1 분석과 다른 점이 하나 있다. 출력 터미널 12개를 모두 숨은 120×40 탭으로 했다(4.1 은 보이는 16열 칸 3개를 섞었다).
- 남은 위험: (MED) 비운 뒤 물리 사용량이 1~1.2 MB/도구만 준다. macOS malloc 이 놓은 작은 블록의 페이지를 곧바로 돌려주지 않기 때문이다(코드 인스턴스 끝: `Malloc Small` 더러운 페이지 124 MB, 살아 있는 힙 64 MB). 그래서 넓은 터미널(165×47)에서 코드 출력을 다시 채우면 터미널당 9.49 MB 까지 간다(D-55 로 판정 밖). 2·3회째는 같은 수준이라 계속 늘지는 않는다. 줄이려면 비운 뒤 `malloc_zone_pressure_relief` 를 부르거나 할당자를 바꿔야 한다. 이는 범위 밖이므로 결정이 필요하다. (LOW) 비우기는 cmu 잠금 안에서 도구 하나씩 돈다. 120×40 도구 하나는 수 ms 다. 그동안 그 도구의 넣기는 기다린다. (LOW) compactor 는 깰 때마다 등록부 전체를 훑는다(도구 수 상한 256).
- 측정 중 본 것(범위 밖): 5만 줄 짧은 줄 인스턴스에서 `otterctl split-h` 한 번이 빠졌다(탭 15개). 4.2(생성 명령 uuid 등록 경합)와 같은 현상으로 보인다.
