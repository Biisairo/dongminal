## 2. 배운 것

### 2-1. 접수한 사람의 가설을 그대로 쓰지 않는다 — **누적이 아니었다**

사용자가 *"300% 넘게 나온다"* 와 함께 **원인의 가설**을 주었다: *"누적과 순간이 섞였는지
부터 의심하라."* 합리적인 가설이고, 나도 코드를 읽고 같은 결론에 먼저 닿았다 —
`result.usage` 를 합산해 쓰는 자리가 분명히 있었다.

**재어 보니 틀렸다.** 실제 claude 에 프롬프트 둘을 넣고 사용량 프레임을 전수로 셌다.

```
턴1  message_start  in=2  cw=25698  cr=0      → 25700
     result         in=2  cw=25698  cr=0      → 25700   (누적 아님)
턴2  message_start  in=2  cw=34     cr=25698  → 25734
     result         in=2  cw=34     cr=25698  → 25734   (누적 아님)
```

**분자는 옳았다.** 틀린 것은 **분모**다 — `modelUsage` 에 항목이 **둘**이고
(`claude-haiku-4-5`(창 200k) · `claude-opus-5[1m]`(창 1M)), 고르는 코드가 사전순 첫
항목을 집었다(`h` < `o`). opus 대화의 토큰을 haiku 의 창으로 나눈 것이 300% 다.

그 함수의 주석은 *"보통 하나다"* 였다. **추정이 주석으로 굳어 있었다.**

*이 저장소는 같은 것을 여러 번 겪었다 (`M11_PROGRESS` §2-12: "에이전트가 안 해 준다"
는 재기 전에는 가설이다). 이번에는 **사용자의 가설**이 그 자리에 있었다.*

### 2-2. 값이 없는 것과 값을 안 읽는 것은 다르다 — 주석이 거짓말을 하고 있었다

`ompCommandsStatus` 의 주석은 이랬다.

> *"omp 의 명령 목록은 **이름뿐**이다 (실측한 프레임에 설명·인자 문법이 없다).
> 없는 것을 지어내지 않는다."*

문장의 모양이 옳다 — `FR-CBG-5` 를 근거로 들고, 실측을 인용한다. **그런데 사실이
아니었다.** omp 17.4.0 을 띄워 `available_commands_update` 를 받으니 명령 56개 전부가
`description` 과 `input.hint` 를 싣는다.

```json
{"name":"fast","description":"Toggle fast mode","input":{"hint":"[on|off|status]"}, …}
```

그래서 `M9_SRS FR-M9-45` 가 claude 에서 푼 문제(*"무엇을 보낼지 알 길이 없다"*)가
**omp 에만 그대로 남아** 있었고, 아무도 그것을 결함으로 읽지 않았다 — 주석이 *"없다"*
고 단언했기 때문이다.

**교훈**: `FR-CBG-5`("모른다 ≠ 0")를 인용한 주석일수록 **그 '모른다' 가 실측인지**를
다시 봐야 한다. 그 조항은 지어내기를 막는 손인데, 재지 않은 단정에 붙으면 **안 읽기를
정당화하는 손**이 된다.

### 2-3. 누수는 틀린 답보다 **우연히 맞은 답**으로 더 오래 산다

화면의 `agentDetail(tool, input)` 은 `command` → `file_path` 순으로 도구 인자를 찾았다.
**claude 의 입력 키**다. 고침을 무력화하고 셋을 다시 재니:

```
codex   떨어졌다   — tool_use 블록을 아예 내지 않는다. 어떤 길도 없었다
omp     통과했다   — shell 도구의 arguments 가 마침 `command` 라 맞았다
```

omp 는 **맞은 것이지 안 것이 아니다.** `ompArgsDetail` 의 둘째 키는 `path` 인데 화면은
`file_path` 를 찾았으므로, 경로를 인자로 받는 omp 도구는 카드에 JSON 원문이 섰다.

그 우연한 일치가 *"omp 는 잘 되는데"* 를 만들고, 그것이 누수를 결함이 아닌 것으로
보이게 했다. **프로브를 세 판 모두에 돌리지 않았으면 여기서 멈췄다.**

### 2-4. "조용한 성공" 은 없는 기능보다 나쁘다 — 인계가 두 번 사라졌다

이 단계를 낳은 인계 자체가 증거다. `dmctl msg --to <gui toolId>` 를 두 번 보냈고 둘 다
*"전송 완료"* 를 냈는데 `/api/agent/events` 에는 아무것도 없었다.

```
apiToolMessage → ToolIO.SendPaste(toolID, …)
                       └─ if p.Kind == KindAgent { return nil }    ← 성공으로 답하고 버린다
```

**그 무동작 자체는 옳다** (FR-AGT-2: 프레임 아닌 바이트는 에이전트를 깨뜨린다). 틀린
것은 **부르는 쪽이 그것을 성공으로 읽은 것**이다. 그 자리의 주석은 *"입력은 해석층의
프롬프트 경로로 간다"* 라 적혀 있었는데 — **그 경로로 보내는 코드가 없었다.**

주석이 **의도**를 적고 구현이 그것을 따르지 않은 자리이며, 오류를 냈다면 첫날 잡혔다.

**고친 모양**: 문을 하나로 모았다 (`Server.deliverToTool`). 다섯 자리가 각자
`SendPaste` 를 부르고 있었고, 갈래를 다섯 벌 두면 한쪽만 고쳐진다.

### 2-5. 선언이 없으면 앎은 **이름**으로 적힌다

누수 열둘이 두 종류였고, 그 구분이 고치는 법을 갈랐다 (D-M12-1).

| 종류 | 예 | 왜 화면에 갔나 |
|---|---|---|
| 값이 계약에 없다 | `agentDetail`·`_mkDiff`·`_isBackground` | 옮길 어휘가 없어 **원문을 파싱**했다 |
| 능력이 선언되지 않았다 | `AGENT_PICK_CMD_RE`·`_openConfigPick`·`_abandon` | 적을 자리가 없어 **이름과 형식**으로 적혔다 |

`/model`·`/config` 가 브라우저의 정규식에 박힌 것은 게으름이 아니라 **적을 자리가
없었기 때문**이다. `ProtoCommand.Form` 을 만들자 이름이 갈 곳이 생겼고 정규식이 사라졌다.

같은 부류의 자리 하나가 더 있었다: `_abandon()` 이 언제나 거절을 보냈고 그 근거가
*"claude 에는 답 없이 닫는 프레임이 없다"* 였다. **`ompProto.Cancel` 은 있는데 부르는
곳이 없었다** — claude 의 사정이 세 에이전트의 동작이 된 자리다.

### 2-6. 흉내가 원본보다 적으면 검사가 헛돈다

`/config` 를 선언으로 옮기자 `V-M11-66` 이 떨어졌다. 까닭은 코드가 아니라 **fakeagent**
였다 — 그 흉내의 명령 목록에 `config` 가 없었다. 종전에는 화면이 이름을 정규식으로
알았으므로 **목록에 없어도 폼이 섰다.**

즉 그 검사는 여태 *"화면이 `/config` 라는 글자를 안다"* 를 재고 있었지 *"그 명령이
있다"* 를 재지 않았다. 흉내를 원본에 가깝게 고치자 재는 대상이 제자리로 왔다.

**같은 자리에서 반대 방향의 것도 하나 나왔다**: `TestFake_PongTurn` 이 명령 **수**(3)를
박아 두어, 흉내가 원본에 가까워지자 떨어졌다. 수 대신 **선언이 달리는가**를 재게 고쳤다.

### 2-7. 동작을 바꾸면 기존 검사가 떨어진다 — 이번엔 셋

`D-M11-7` 그대로다. 같은 변경에서 고쳤고, 무엇이 왜 바뀌었는지를 검사 안에 적었다.

| 검사 | 왜 떨어졌나 | 어떻게 고쳤나 |
|---|---|---|
| `V-M11-65` | 고른 모델이 프롬프트 문자열이 아니라 **제어**로 나간다 (L7) | **나가는 요청**을 잰다 (`/api/agent/control`). 화면에는 아무것도 서지 않는 것이 새 계약이라 화면으로는 가를 수 없다 |
| `V-M11-66` 계열 | 흉내에 `config` 가 없었다 (§2-6) | 흉내를 실측에 맞췄다 |
| `TestFake_PongTurn` | 명령 수를 박았다 | 선언의 유무를 재게 바꿨다 |

### 2-8. 같은 잘못을 **두 번** 했다 — "프로토콜이 주지 않는다" 는 단정

`D-M12-2` 를 세울 때는 omp 의 명령 설명(L8) 하나인 줄 알았다. 사용자가 *"여전히 '알 수
없는 프레임'이 나온다"* 라 접수해 세어 보니 **같은 부류가 하나 더** 있었다.

| 자리 | 그때 적은 것 | 실제 |
|---|---|---|
| `omp_decode.go` | *"명령 목록은 이름뿐이다 — 설명·인자 문법이 없다"* | `description`·`input.hint` 가 **온다** |
| `M11_SRS` §7 | *"백그라운드의 진행을 **구조로 주지 않는다** — ID·경로가 문장 안에 있다"* | `task_notification` 이 `status`·`output_file`·`summary` 를 **필드로** 준다 |

둘 다 `FR-CBG-5`("모른다 ≠ 0")를 근거로 들었고, 둘 다 **재지 않은 단정**이었다.
그 조항은 **지어내기를 막는 손**인데 이렇게 쓰면 **안 읽기를 정당화하는 손**이 된다.

**그래서 `D-M11-4` 의 문장을 늘렸다**: *주지 않는 값은 옮기지 않는다* — **다만 주는
값은 버리지 않는다.** 앞 절반만 인용하면 뒤 절반이 사라진다.

### 2-9. 실측의 **표본**이 현상을 담는지 물어라

`result.usage` 가 누적인지를 두 턴으로 쟀고 *"누적이 아니다"* 라 결론했다. 틀렸다 —
**그 두 턴이 도구를 쓰지 않아 API 요청이 하나뿐**이었고, 그때는 합과 순간이 같은 수다.

재야 했던 것은 턴의 **수**가 아니라 턴 안의 **요청 수**였다. 도구 셋을 쓰는 턴 하나가
곧바로 갈랐다 (103574 vs 26051).

**표본을 늘린 방향이 틀렸던 것이다** — 턴을 둘로 늘렸으나 현상은 턴 **안**에 있었다.

### 2-10. 한 수치가 **둘 이상의 결함**을 가질 수 있다

창(200k→1M)을 고치고도 화면이 462% 였다. 그때 든 의심이 *"고침이 안 들어갔나"* 였고,
바이너리를 뒤져 고침이 들어 있음을 확인하고서야 **분자도 따로 틀렸다**를 보았다.

라이브 상태 한 줄이 그것을 갈랐다:

    usage: {"tokens": 489801, "contextWindow": 1000000, "model": "claude-opus-5"}

분모는 고쳐져 있었다. **첫 고침 뒤 증상이 남으면 "안 고쳐졌다"가 아니라 "둘이었다"를
먼저 의심한다.**

### 2-11. 흉내가 원본보다 **빠르면** 검사가 헛돈다

`FR-M12-12`(끊김이 큐보다 먼저 선다)의 검사가 **처음에 초록이었다.** fake 가
`control_response` 와 `result` 를 같은 순간에 내어, 접수한 순서 뒤집힘이 재현되지
않았기 때문이다. 실제 claude 는 그 사이에 시간이 걸린다.

fake 에 300ms 를 넣자 검사가 떨어졌다 — 그때서야 고칠 것이 보였다.

§2-6 은 *"흉내가 원본보다 **적으면**"* 이었고 이것은 *"**빠르면**"* 이다. 같은 뿌리다:
**흉내의 어느 축이든 원본보다 무르면 그 축을 재는 검사가 헛돈다.**

## 3. 재는 손 (다음 사람을 위해)

**claude 의 사용량을 재려면** — 두 턴을 넣어야 누적/순간이 갈린다:

    { print -r -- '{"type":"user","message":{"role":"user","content":[{"type":"text","text":"Say A."}]}}'
      sleep 25
      print -r -- '{"type":"user","message":{"role":"user","content":[{"type":"text","text":"Say B."}]}}'
      sleep 25
    } | claude -p --output-format stream-json --input-format stream-json \
          --include-partial-messages --verbose --permission-mode bypassPermissions > raw.jsonl

    jq -c 'select(.type=="result") | {usage, modelUsage}' raw.jsonl

**omp 를 재려면** — 프레임은 `{"id":…,"type":"<command>",…}` 다 (`command` 라는 필드가
아니다. 그것으로 두 번 헛돌았다):

    { print -r -- '{"id":"dm-1","type":"get_state"}'; sleep 3
      print -r -- '{"id":"dm-2","type":"prompt","message":"…"}'; sleep 60
    } | omp --mode rpc-ui --approval-mode always-ask > raw.jsonl

**codex 는 이 기계에 없다** — 어댑터 소스와 JSON 스키마가 근거이고 **실측이 아니다**
(`M12_SRS` §7 의 갭).
