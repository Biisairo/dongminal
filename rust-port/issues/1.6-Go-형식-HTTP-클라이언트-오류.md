# 1.6 Go 형식 HTTP 클라이언트 오류

## 목표

Go `net/http` 클라이언트의 전송 오류는 `*url.Error` 로 감싸져 `Get "https://x/y": dial tcp 127.0.0.1:1: connect: connection refused` 꼴로 드러난다(`update --check` stderr, 로그, HTTP 오류 본문). reqwest 의 오류 문구는 이와 다르다. Go 와 같은 문구를 만드는 공통 도구를 `dm-gocompat`(새 파일 `src/neturl_err.rs` 등, 기존 파일은 고치지 않는다)에 두고, 1.3 의 `release` 를 첫 소비자로 바꾼다.

- 범위: 연결 거부·이름 해석 실패·시간 초과·TLS 실패·리다이렉트 초과·본문 읽기 오류·상태 코드 오류 등, 저장소의 HTTP 클라이언트(release·updatecheck·telegram·claudeacct·ext·edge·toolclient 등)가 실제로 문구를 드러내는 경우. 저장소 전체를 grep 으로 조사해 범위를 확정한다.
- 기준: go1.27.2 실측(로컬 가짜 서버·닫힌 포트·잘못된 호스트). 외부 네트워크에 나가지 않는다.
- reqwest 가 원인 정보를 감추는 경우는 원인 사슬(source)을 따라가 io::Error·hyper 오류에서 가른다. 가를 수 없으면 진행 기록에 남은 위험으로 적는다.
